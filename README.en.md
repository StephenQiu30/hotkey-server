# HotKey

A personal, noncommercial learning project for social-media monitoring. The only server stack is Python, FastAPI, SQLAlchemy 2, PostgreSQL, Alembic, Celery and RabbitMQ. The workspace uses React, TypeScript and Vite. Business operations use the single `/api/*` root without a numeric URL version or a legacy compatibility route.

Implemented: single-owner initialization, revocable cookie sessions, CSRF protection, versioned monitor drafts, and idempotent diagnostic jobs through a transactional Outbox and a real prefork worker. An active monitor can start collection from the workspace. The generated UmiOpenAPI client sends only the current version and idempotency key; the backend shares one batch orchestration path with the scheduler, derives sources, queries, window, policy and retention from the active snapshot, and reserves the complete first-page batch atomically. While the page is visible, the workspace polls generated Job and CollectionRun clients every two seconds only when queued or running work exists. It cancels polling when hidden, performs one complete refresh after both resources become terminal, and then stops. Active collection runs expose a cancel action that calls the generated Job cancellation client and then reloads the persisted terminal state.

Bounded source probes, persistent page collection foundations, manual event grouping, platform trends, notifications, frozen comment samples, manual viewpoint analysis, and cited knowledge snapshots are implemented. Source 429 responses create a new job epoch at Retry-After, transient failures use bounded backoff, and every later attempt reserves the daily request budget again; permanent failures and exhausted retry limits settle the collection run and job together. Final-page evidence, content, checkpoint, collection run and job now settle in one transaction, so message redelivery after commit cannot fetch the source again. User cancellation settles the job and collection run atomically. A page cannot commit after cancellation during a source request or object upload; a rejected upload is deleted exactly or recorded for reconciliation. Knowledge supports exact and semantic search, controlled comment statistics, deterministic cited answers, and an online withdrawal barrier; the recoverable semantic index uses self-hosted Ollama and pgvector. A synthetic lifecycle now covers withdrawal manifests, conservative shared-page removal, exact-key MinIO version deletion, and post-restore replay. **The existing MinIO instance and real sources are not admitted yet; real-content evaluation, automatic model labeling, production backup restore, and old-application rollback remain open.** Saving a draft does not start collection. Diagnostic jobs do not produce social data.

The September 15 replanning defines **monitors → discovery inbox → comment tracking → event records → analysis and knowledge retrieval**. From the repository root, with Docker Compose v2.24.4+:

```sh
docker compose up -d --build
docker compose exec backend python -m cli owner-init learner
```

Enter a password of at least 12 characters interactively and visit http://localhost:8010. No default owner exists. Ports bind to loopback only. Use the production override behind HTTPS for a production-like experiment.

See the [Chinese README](README.md), [design and source research](docs/design/006-社交媒体关键词监控与评论分析设计.md), [implementation plan](docs/plans/006-社交媒体关键词监控与评论分析计划.md), and [operations](docs/operations/006-Python运行与验证.md). FastAPI generates the runtime OpenAPI document and Swagger UI. Its reproducible snapshot is `docs/openapi/openapi.json`; `@umijs/openapi` generates all frontend endpoint functions and types under `frontend/src/api/`, while Axios is confined to `frontend/src/request.ts`.

The previous implementation and contracts exist only in Git history. No legacy endpoints, accounts or databases are silently reused. Existing persistent volumes are preserved.

Backend application code lives in `backend/src/`, with separate `worker/` and `cli/` directories. Tests and verification scripts stay in `backend/tests/` and `backend/scripts/`. See the [backend layout and commands](backend/README.md).

Operators can export a private withdrawal manifest with `python -m cli deletion-export <path>`, replay it after an isolated restore with `deletion-replay <path>`, and run bounded object cleanup with `evidence-reconcile --limit 20`. CI exercises the restore order with a real custom-format `pg_dump`, `pg_restore`, and two manifest replays in disposable Compose. Cleanup requires complete `HOTKEY_S3_*` settings. The application does not create buckets or change object-lock and lifecycle policy; production deletion and disaster recovery remain unverified until the existing instance's TLS path, delete permissions, version history, incomplete multipart lifecycle, backup retention, and off-host restore are checked.
