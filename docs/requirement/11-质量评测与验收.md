# 11 质量评测与验收

需求编号：`REQ-11`。本文定义判据，不表示已通过，进度只在BACKLOG。

## 用户任务

判断能力是否在真实数据与自然时间下可用。

## 功能与约束

| 维度 | 必须记录 | 验收解释 |
|---|---|---|
| 搜索与增量 | 同账号/来源/查询/排序/窗口的对照、返回与新增/重复/更新数量、游标和停止原因 | 至少两轮真实采集，不用旧数据替代本轮；可见集合覆盖不扩大成全网召回率 |
| 相关性与事件 | 按语言/来源/查询分层的真实标注，TP/FP、误合并/漏合并与边界案例 | 校准与验收样本分开；正式评测前固定样本方法和质量阈值，再以保留样本复核，不只展示成功案例 |
| 趋势与时效 | 窗口边界、来源/规则版本、统计集合；发布时间、首次可检索、采集与识别时间 | 首次可检索时间未知就标未知；断采、规则/覆盖变化不制造上升或降温结论，数值缺失不造曲线 |
| 持续运行 | 至少连续七个自然日的应执行/静默窗口、成功/部分/失败/漏轮、延迟、人工干预和恢复 | 至少包含两轮自然调度的成功采集和事件更新；每个应执行窗口有回执或漏轮原因。正式观察前固定运行成功率/延迟阈值，全部失败或只有人工触发不能通过 |
| 提醒 | 条件与规则版本、冷却与事件去重、评估/发送/实际送达、重复与噪声 | 至少一个真实条件达标事件沿完整链路到本人接收；无自然触发则继续观察，模拟触发只证明代码路径 |
| 硬门槛 | 准入、预算、owner 隔离、证据可读、身份去重、停止与恢复 | 未获准请求、超预算新请求、身份误去重、停止后新请求或数据泄漏均阻止能力验收；修复后重验受影响阶段 |

准确率、容量和时延先测基线再冻结验收阈值；阈值与实际结果只在对应 BACKLOG 待办中保留必要证据，不编造固定目标。七日是最低观察长度，不能被解释为已经验证长期稳定或达到 SLA。


### 页面与性能

1440px/390px覆盖正常、空、加载、错误、无权限和键盘；200%缩放、减少动态效果下动作可达。静态说明无远程数据的状态写不适用。先在同构建、浏览器、硬件和网络下测正常/失败基线，再优化无用请求、复用/并行、有界分页及必要索引，不预建百万级平台。

## 验收标准

首版需完成两轮真实采集、相关性和事件人工评测，以及至少连续七个自然日的监测观察。观察记录应执行/静默窗口、漏轮、延迟、人工干预及实际发生的来源故障与恢复，不用人工反复触发代替调度。自然期未出现的异常恢复场景仍须受控验证，分别标注证据，不能伪造自然故障。七日是最低观察长度，不是已达到的 SLA；中途发生验收门槛失败时，修复后重验受影响环节，必要时延长观察。阶段门槛见[持续监测计划](../plan/06-持续监测与恢复.md)。

源码、受控样本、独立环境、真实平台、自然时间、用户体验和独立审查分别报告；未验证项保留在BACKLOG。
