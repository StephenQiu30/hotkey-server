# 来源授权与故障处置

## 已实现准入矩阵

只有下列七类 `source_type` 可以创建。搜狗与 DuckDuckGo 是已验收的不可接入边界，不得通过抓网页、Cookie、浏览器会话或第三方代理绕过。

| 类型 | 授权 | 启用前必检 |
| --- | --- | --- |
| `rss` | 无 | HTTPS/受控 HTTP Feed、SSRF 校验、分页与存储策略 |
| `hacker_news` | 无 | 固定官方 Firebase API、分页上限 |
| `x` | Bearer | X Recent Search 授权、配额与条款 |
| `bing_grounding` | Bearer | Microsoft Foundry Grounding 能力、数据边界批准、单页限制 |
| `bilibili` | OAuth2 | Open Platform scope、Open ID、删除同步、归属与 Webhook 密钥 |
| `weibo` | Bearer | 官方 CLI 授权、套餐/额度、删除同步与开发者协议 |
| `google_agent_search` | Bearer | Discovery Engine IAM、区域和完整 ServingConfig 资源名 |

## 新增或轮换授权

1. 在变更单保存业务目的、数据类别、条款链接、保留天数、配额、责任人和撤销方法。
2. 在密钥管理系统创建新版本；HotKey 仅保存 `credential_ref`，不得把 Token 粘贴到名称、URL、日志、任务参数或工单正文。
3. 由 Admin 创建停用状态的连接，配置固定官方端点和最小权限。
4. 执行“测试连接”；只有健康状态为 `healthy` 且合规字段完整时才能启用需授权来源。
5. 用一个受控监控运行一次采集，核对 `collection_runs`、内容归属、原始证据、配额和审计，再扩大范围。

## 故障分级与处置

| 现象 | 首要证据 | 操作 |
| --- | --- | --- |
| `401/403` 或探测不健康 | 来源健康状态、稳定诊断码 | 立即停用；核对 scope、过期和撤销状态；按轮换流程换新凭据 |
| `429`、配额临界 | `hotkey_quota_limit`、来源运行和 Provider 控制台 | 保持事实不变；降低监控频率或停用来源，等待窗口恢复，不并发重放 |
| `5xx`、超时、DNS/TLS | 采集失败率、耗时、稳定失败码、请求 ID | 验证官方状态和出口；保留有界重试，持续超阈值则停用 |
| 内容格式不合法 | 采集诊断码、原始证据引用 | 隔离该条，禁止放宽安全解析；提交兼容性修复和回归 fixture |
| 删除/授权撤销事件 | Webhook receipt、审计 | 验签、幂等处理、停用连接并执行删除同步；不得继续采集 |
| 疑似凭据或内容泄露 | 日志/指标/任务安全投影 | 停止相关角色，撤销凭据，保全审计；按安全响应处理后再恢复 |

## 恢复条件

- 新凭据已通过测试连接，旧凭据已撤销或处于明确回滚窗口。
- 最近一次受控采集成功，失败码不含上游原文，指标标签不含查询、URL、账号、凭据或资源 ID。
- 配额足够覆盖下一调度窗口；数据存储、归属、删除同步和条款仍有效。
- 操作人与复核人在审计记录中明确批准启用。

恢复时只启用一个连接，观察两个调度周期，再逐步恢复同类型来源。禁止批量重试所有失败任务；只在治理界面对明确的 `discarded` 或 `cancelled` 任务执行有确认的单任务重试。

## 证据保留

故障单保存时间窗、`source_type`、来源 ID、CollectionRun ID、任务 ID、请求 ID、稳定原因码、配额窗口和处置结论。不得保存查询文本、上游响应正文、Token 或任务原始参数；需要核查原始证据时通过受控对象引用读取。
