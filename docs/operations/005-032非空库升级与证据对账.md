# 032 非空库升级与证据对账

## 状态与适用边界

本文是 032 实现必须满足的运维契约。v1.2 已在 2026-08-10 完成独立恢复库的 PostgreSQL+MinIO+Vault 全流程演练，因此状态升为 `active`。这只表示流程可重复执行，不授权在生产或唯一一份数据上直接操作；每次执行仍必须建立新的一致备份、独立恢复环境、双人复核和回滚窗口。备份、独立恢复和密钥处理继续遵循 [Operations 002](002-备份恢复与密钥轮换.md)，部署切换遵循 [Operations 001](001-部署升级与回滚.md)。

`backend/db/schema.sql` 是唯一结构事实源。升级命令只能读取编译进目标二进制的 canonical Schema，不得创建 `db/migrations/`、临时结构 SQL、文档 SQL、代码内 DDL 字符串或另一份 Schema。本文只规定操作顺序、命令契约和数据处置，不复制任何表结构。

## 冻结不变量

- Source 自有 `RawEvidenceStore`/MinIO adapter；一份 EvidenceSnapshot 可关联多个 SourceObservation，一个 observation 也可关联多份 snapshot，关联必须带可校验 locator。
- Vault 路径只允许 `documents/{document_id}/{document_version_id}/{artifact_type}/{transformer_profile_sha256}.{md|txt}`。唯一幂等身份为 `(document_version_id, artifact_type, transformer_profile_sha256)`；同路径不同字节拒绝覆盖并隔离。
- 共享 LifecycleState 枚举只允许 `policy_pending`、`policy_blocked`、`raw_pending`、`raw_available`、`raw_failed`、`derive_pending`、`derived_available`、`derive_failed`、`readable`、`retention_blocked`、`quarantined`、`tombstoned`；EvidenceSnapshot、DerivedArtifact、DocumentVersion 分别受 Design 定义的实体子集约束，跨存储推进是跨行 saga，不要求单行经历全部状态。
- 旧 MinIO Markdown/text、`contents.excerpt`、AI 摘要或 JSONB captured payload 不能被声明为 raw EvidenceSnapshot。无法证明来源、权利、正文类型或谱系时必须保守降级，不能猜测。
- 旧 credibility、claim confidence、heat/radar、event/claim 状态都处于 `legacy_quarantined`；不得回填成 HeatProfile v2 或 EvidenceStateProfile v2 的输入。
- 升级、回填、对账和回滚都不得覆盖不可变 SourceObservation、EvidenceSnapshot、DocumentVersion、RightsDecision、Decision 或 Citation。

## 激活前门禁

只有同时满足以下条件，本文才可从 `planned` 改为 `active`：

1. 032 Design 为 `accepted`、PRD 为 `approved`，对应代码和 canonical Schema 已评审。
2. 空库初始化、与生产同版本的非空恢复库升级、重复执行和失败事务测试均通过。
3. `db upgrade`、`backfill-evidence-lineage`、`reconcile-evidence-lineage` 的 dry-run、apply、防误操作、批次、断点续跑和审计测试通过。
4. 按 Operations 002 对 PostgreSQL、MinIO、Vault 和配置版本完成一致备份，并在独立 Compose 项目/新卷恢复成功。
5. 记录旧 Git commit、镜像 ID、catalog fingerprint、各事实表行数、MinIO/Vault 清单哈希、活跃 producer 和回滚窗口。
6. API/worker 共享同一受控 Vault，只有 Knowledge `ProjectionService` 写入；readiness 已验证单 writer、POSIX 原子 hard-link 或 rename-no-replace/locking、目录 fsync 和 API 只读。

## 命令契约

当前二进制已提供以下接口；示例中的身份与摘要必须替换为恢复演练产生的真实、非敏感记录：

```bash
cd backend

go run ./cmd/hotkey db upgrade --target 032 --dry-run
go run ./cmd/hotkey db upgrade --target 032 --apply-schema --confirm-non-empty

go run ./cmd/hotkey maintenance backfill-evidence-lineage \
  --phase source --batch-size 200 --dry-run
go run ./cmd/hotkey maintenance backfill-evidence-lineage \
  --phase source --batch-size 200 --apply --confirm-non-empty \
  --operator-id '<operator_record_id>' --reviewer-id '<reviewer_record_id>' \
  --backup-evidence-sha256 '<backup_sha256>' \
  --rehearsal-evidence-sha256 '<rehearsal_sha256>'
go run ./cmd/hotkey maintenance backfill-evidence-lineage \
  --phase source --batch-size 200 --run-id '<migration_run_id>' --resume \
  --apply --confirm-non-empty \
  --operator-id '<operator_record_id>' --reviewer-id '<reviewer_record_id>' \
  --backup-evidence-sha256 '<backup_sha256>' \
  --rehearsal-evidence-sha256 '<rehearsal_sha256>'

go run ./cmd/hotkey maintenance reconcile-evidence-lineage \
  --scope all --batch-size 200 --grace-period-hours 24 --dry-run
go run ./cmd/hotkey maintenance reconcile-evidence-lineage \
  --scope all --batch-size 200 --grace-period-hours 24 \
  --apply --confirm-non-empty \
  --operator-id '<operator_record_id>' --reviewer-id '<reviewer_record_id>' \
  --backup-evidence-sha256 '<backup_sha256>' \
  --rehearsal-evidence-sha256 '<rehearsal_sha256>'
go run ./cmd/hotkey maintenance reconcile-evidence-lineage \
  --scope all --batch-size 200 --grace-period-hours 24 \
  --run-id '<reconciliation_run_id>' --resume --apply --confirm-non-empty \
  --operator-id '<operator_record_id>' --reviewer-id '<reviewer_record_id>' \
  --backup-evidence-sha256 '<backup_sha256>' \
  --rehearsal-evidence-sha256 '<rehearsal_sha256>'
```

未显式提供 apply 与 confirm 参数时，命令必须只读且不得修改 PostgreSQL、MinIO、Vault、任务队列或切换 profile。所有命令默认拒绝未知 target/phase/scope、Schema 指纹不匹配、producer 未停、备份/演练证据缺失或运行中同 scope 写任务。日志只输出 ID、计数、哈希、状态和安全 reason code，不输出正文、raw bytes、对象凭据或完整路径中的用户输入。

`db upgrade --dry-run` 输出当前/目标 catalog fingerprint、缺失/意外表与索引数、估算行数、当前表/索引字节、版本化索引工作空间估计、`access_exclusive_transactional` 锁风险、pg_trgm/vector 版本和阻断项。估计值用于预留空间，不是承诺的峰值；apply 在 advisory lock 保护的单一事务内执行 embedded canonical Schema 并在提交前完整验证，失败不会留下 partial fingerprint，重复 apply 必须无变化成功。

## 正式升级顺序

1. **建立变更记录**：分配 `migration_run_id`，固定 Git commit、二进制 SHA-256、canonical Schema SHA-256、操作人、复核人、备份证据、开始时间和回滚窗口。
2. **恢复库预演**：只在独立 Compose 项目与新卷恢复最近一致备份；先完成所有 dry-run、批次回填、对账、切换和读路径验收。生产不作为首次演练环境。
3. **停止相关 producer**：停止采集、raw/derived 转换、embedding、匹配、事件和通知 v1/v2 写入，等待 running job 归零；保留旧稳定只读路径。
4. **Schema dry-run**：核对 catalog diff、锁、空间和预计时间。发现未知 DDL、不可收敛改名、向量非 1024 维或同义事实表时停止。
5. **Canonical Schema apply**：显式执行 `--apply-schema --confirm-non-empty`，随后验证目标 fingerprint、约束、索引和重复 apply；不得执行手工 SQL 修补。
6. **分 phase 回填**：严格按 `source → evidence_metadata → document → match → family_event → evidence_state` 执行。只有相应 P0/P1 能力、Schema 和验收 fixture 已实现时才能运行该 phase，不能为追赶进度提前制造占位事实。
7. **全量对账**：比较 PostgreSQL 清单、MinIO HEAD/摘要和 Vault 文件/摘要，并复核权利、保留期、active artifact 与 lineage；先 dry-run、复核差异，再显式 apply 可恢复动作。
8. **影子和切流**：依次使用 `legacy → shadow → allowlist → default → rollback_expired`。每次变化保存操作人、Monitor allowlist、profile/version、指标、时间和回滚点；不得长期双写同一业务事实。
9. **恢复 producer**：按 Source raw → Document projection → embedding/match → event/evidence → notification 顺序逐级恢复，并观察失败率、积压和三存储差异。

## 批次、重入与历史映射

回填使用稳定主键游标，不使用 OFFSET；默认批次 200，可按锁等待、对象存储吞吐和事务时间下调。每个 item 保存 `migration_run_id`、phase、legacy source type/id、目标 ID、输入 SHA-256、attempt、状态、reason code、开始/完成时间。唯一约束必须保证同一 phase、源身份和输入哈希重复执行返回原目标；输入变化创建新 item，不能改写成功历史。

运行中断后只允许以同一 `migration_run_id` 和冻结配置 `--resume`。恢复时先验证二进制、Schema、profile、RightsPolicy 和配置哈希未变化；变化时终止旧 run 并创建新 run，禁止在一个 run 内混用语义。单条永久失败不阻塞已提交批次，但 phase 在 unresolved blocker 未清零前不能标为 complete，也不能进入依赖它的切流状态。

各 phase 的保守规则：

| phase | 输入与目标 | 必须降级/拒绝的情形 |
|---|---|---|
| `source` | 旧连接、游标、采集运行 → SourceEndpoint/Checkpoint/ProcessingRun/Observation | external ID、上游版本或主体不可证明时保留独立 observation，不按 canonical URL 合并 |
| `evidence_metadata` | 旧对象清单 → legacy derived 或可证明的 raw snapshot 清单 | Markdown/text/摘要不得伪装为 raw；缺 RightsDecision 时 `policy_blocked` |
| `document` | 允许的 observation+snapshot+locator → immutable DocumentVersion/DerivedArtifact | 无 raw、locator/hash 不符或正文类型不明时 `metadata_only`/`quarantined`，不补写正文 |
| `match` | 旧匹配 → v2 影子输入或新决策 | 旧向量、credibility 和可变 monitor 身份不得直接成为 active v2 决策 |
| `family_event` | 可重建版本 → ContentFamily/MicroEvent/Storyline | 无可证明谱系时不合并；旧 Event/Topic 不直接等同新模型 |
| `evidence_state` | 可引用版本、locator、lineage root → ClaimEvidence/EvidenceState v2 | 旧 verified/unverified/corroborated/confidence 不映射；无法回到原文时 `no_citable_body` |

## PostgreSQL、MinIO 与 Vault 对账

`reconcile-evidence-lineage` 至少支持 `pg-minio`、`pg-vault`、`rights-retention` 和 `all` scope。扫描以清单 ID/稳定游标分批，HEAD/文件读取受并发与速率限制；报告按 `missing`、`orphan_within_grace`、`orphan_expired`、`digest_mismatch`、`policy_blocked`、`retention_blocked`、`active_pointer_invalid`、`healthy` 分类。

| 差异 | dry-run 结论 | apply 动作 |
|---|---|---|
| PG `raw_pending`、MinIO 无对象 | 可重试或超过上限 | 幂等重试；超过策略上限转 `raw_failed` |
| MinIO 有对象、PG 无清单 | 宽限期孤儿 | 宽限期内不动；当前命令到期后仍只追加 `orphan_expired` 审计，删除/隔离必须由另行批准的 Source-scoped 任务执行 |
| snapshot/locator 摘要不符 | 完整性失败 | 停止下游读取并转 `quarantined`，不得修正哈希掩盖差异 |
| PG derived 清单、Vault 缺失 | 可从 raw 重建或不可恢复 | 先停止展示，转 `derive_failed`；仅在权利允许且 raw 健康时重建 |
| Vault 同路径不同字节 | 非法覆盖/人工修改 | 拒绝覆盖、隔离文件和版本；保留审计证据 |
| Vault 有文件、PG 无引用 | 宽限期孤儿 | 当前命令只追加宽限期/过期审计，不自动采纳、移动或删除；人工确认后由独立清理变更处置 |
| active artifact 指向旧/缺失 profile | 投影漂移 | 指向已登记且健康的目标 profile；保留旧产物，不覆盖 |
| 许可撤回/保留到期 | 先阻断读取 | 转 `retention_blocked`，执行受审计删除/墓碑任务；失败只追加任务状态 |

对账 apply 不能把未知资产自动变为可读，不能自动放宽 RightsDecision，也不能跨 Source scope 删除对象。每批操作保存 before/after 状态、对象/文件摘要、decision/profile 版本和 reason code；修复后立即对同一 scope 重跑 dry-run，差异未收敛则保持不可读并升级人工复核。

## 切流验收与回滚

进入 `allowlist` 前至少验证：P0 Citation/Document API 的 exact DocumentVersion 与强 ETag、390px 移动 Markdown、安全失败投影、人工 match review、异步 expansion/preview、1024 维 embedding、逐 action 不可变 RightsDecision 及其只读矩阵、三存储故障注入和 OpenAPI Client。P1/P2 只能在各自依赖和质量门槛通过后扩展，Web Push 虽为 P2 必交付能力，仍必须逐用户/设备 opt-in。

出现 catalog 指纹异常、不可变事实被覆盖、raw/derived 哈希差异、越权展示、legacy/v2 语义混读、任务持续积压或质量门槛回归时：

1. 停止受影响 v2 producer、通知和新 allowlist 扩容；把受影响版本转不可读。
2. 将 active read/write/profile 切回上一个已审计状态；不逆向删除 additive Schema。
3. 保留所有新 Observation、Snapshot、DocumentVersion、Decision、对象和 Vault 文件，按原权利/保留策略管理；回滚不是批量删除授权。
4. 以新 reconciliation/migration run 修复或重放，不复用已完成 run，也不覆盖历史。
5. 若旧版本无法安全读取新事实，在独立环境恢复发布前一致备份并评审切流；禁止覆盖现有生产卷。

`rollback_expired` 只有在回滚窗口结束、所有 producer 已停止 legacy 写入、对账零未解决阻断项、Acceptance 完成且单独的破坏性清理评审通过后才能进入。032 本身不删除旧列、旧表、MinIO 对象或 Vault 文件。

## 运维记录与完成证据

每次演练或执行必须留存：命令和安全参数摘要、Git/镜像/Schema/profile 哈希、migration/reconciliation run ID、phase/scope、批次计数、失败 reason codes、三存储前后清单摘要、切流状态、指标、操作人/复核人、开始/结束时间和回滚结论。正文、raw bytes、Secrets、Authorization/Cookie 和预签名地址不得进入记录。

只有恢复库全流程、生产等价 dry-run、幂等重入、失败注入、回滚和对账均有可重复证据时，才将结果写入 032 Acceptance 并保持本文 `active`。
