# 备份、恢复与密钥轮换

## 备份范围与保管

一次可恢复备份必须同时包含 PostgreSQL、自管 MinIO Bucket、Vault 卷、Git 提交、镜像 ID 和配置键名清单。Redis 只保存验证码、限流和短期票据，不作为业务事实备份。UI 托管来源的数据库密文还依赖同版本 `HOTKEY_SOURCE_CREDENTIAL_MASTER_KEY`；清单只记录其受控密钥库版本或指纹，密钥值必须与数据库分开保管。备份不得包含明文 `.env.prod`；备份目标需加密、限制访问并按组织策略保留。

先设置一个明确且已存在于受控磁盘的目录，然后验证目标不是根目录或用户主目录：

```bash
HOTKEY_BACKUP_DIR='/srv/hotkey-backups/2026-08-08T1700Z'
test -n "$HOTKEY_BACKUP_DIR"
test "$HOTKEY_BACKUP_DIR" != "/"
test -d "$HOTKEY_BACKUP_DIR"
```

## 创建一致备份

1. 在治理界面停用来源，等待 `running_jobs` 归零；保持 Web 只读窗口。
2. 记录提交和镜像：

```bash
git rev-parse HEAD > "$HOTKEY_BACKUP_DIR/git-commit.txt"
docker compose --env-file .env.prod -f docker-compose-prod.yml images > "$HOTKEY_BACKUP_DIR/images.txt"
```

3. 导出 PostgreSQL：

```bash
docker compose --env-file .env.prod -f docker-compose-prod.yml exec -T postgres \
  pg_dump --username hotkey --dbname hotkey --format=custom \
  > "$HOTKEY_BACKUP_DIR/postgres.dump"
test -s "$HOTKEY_BACKUP_DIR/postgres.dump"
```

4. 通过生产网络内的一次性 `mc` 容器导出 MinIO；凭据只从 `.env.prod` 注入，不写入命令历史或备份：

```bash
mkdir -p "$HOTKEY_BACKUP_DIR/minio"
docker run --rm --network hotkey-prod_default --env-file .env.prod \
  --volume "$HOTKEY_BACKUP_DIR/minio:/backup" --entrypoint /bin/sh minio/mc:latest -ec \
  'mc alias set source http://minio:9000 "$MINIO_ROOT_USER" "$MINIO_ROOT_PASSWORD" >/dev/null && mc mirror --overwrite "source/${HOTKEY_MINIO_BUCKET:-hotkey-evidence}" /backup'
```

5. 只读归档 Vault 卷：

```bash
docker volume inspect hotkey-prod_vault_data >/dev/null
docker run --rm --volume hotkey-prod_vault_data:/source:ro \
  --volume "$HOTKEY_BACKUP_DIR:/backup" alpine:3.22 \
  tar -C /source -czf /backup/vault.tar.gz .
test -s "$HOTKEY_BACKUP_DIR/vault.tar.gz"
```

6. 对备份文件计算哈希并把清单保存到独立审计位置：

```bash
find "$HOTKEY_BACKUP_DIR" -maxdepth 2 -type f -exec sha256sum {} \; \
  > "$HOTKEY_BACKUP_DIR/SHA256SUMS"
```

## 独立恢复演练

恢复必须使用新项目 `hotkey-restore` 和新卷。先确认不存在同名运行资源；如果存在，停止并选择新的演练名，不得删除未知资源。

```bash
test -s "$HOTKEY_BACKUP_DIR/postgres.dump"
test -s "$HOTKEY_BACKUP_DIR/vault.tar.gz"
docker compose -p hotkey-restore --env-file .env.prod -f docker-compose-prod.yml ps --all
docker compose -p hotkey-restore --env-file .env.prod -f docker-compose-prod.yml up --detach --wait postgres redis minio
```

将数据库恢复到新项目的空数据库：

```bash
docker compose -p hotkey-restore --env-file .env.prod -f docker-compose-prod.yml exec -T postgres \
  pg_restore --username hotkey --dbname hotkey --clean --if-exists \
  < "$HOTKEY_BACKUP_DIR/postgres.dump"
```

将对象与 Vault 恢复到新卷，再启动其余服务：

```bash
docker run --rm --network hotkey-restore_default --env-file .env.prod \
  --volume "$HOTKEY_BACKUP_DIR/minio:/backup:ro" --entrypoint /bin/sh minio/mc:latest -ec \
  'mc alias set target http://minio:9000 "$MINIO_ROOT_USER" "$MINIO_ROOT_PASSWORD" >/dev/null && mc mb --ignore-existing "target/${HOTKEY_MINIO_BUCKET:-hotkey-evidence}" && mc mirror --overwrite /backup "target/${HOTKEY_MINIO_BUCKET:-hotkey-evidence}"'
docker volume create hotkey-restore_vault_data
docker run --rm --volume hotkey-restore_vault_data:/target \
  --volume "$HOTKEY_BACKUP_DIR:/backup:ro" alpine:3.22 \
  tar -C /target -xzf /backup/vault.tar.gz
docker compose -p hotkey-restore --env-file .env.prod -f docker-compose-prod.yml up --detach --wait --wait-timeout 240
```

验收 `/readyz`、登录、事实数量、随机证据对象、报告文件和审计记录。演练资源仅在复核具体项目名与卷名后清理；生产项目和卷永不作为清理目标。

## 密钥轮换

一次只轮换一类密钥，保留可回滚旧值直到验证完成，并在变更单记录密钥版本而非明文。

| 密钥 | 影响 | 顺序 |
| --- | --- | --- |
| 来源、AI、SMTP Token | 单连接或单 Provider | 停用能力 → 更新 Secret → 探测 → 启用 |
| `HOTKEY_SOURCE_CREDENTIAL_MASTER_KEY` | 所有 UI 托管来源 | 预先取得各来源替换凭据 → 停用托管来源 → 替换主密钥并重启 API/Worker → 在 UI 逐一替换凭据 → 探测 → 启用；完成前保留旧主密钥以便回滚 |
| MinIO 凭据 | 所有证据读写 | 新建凭据 → 更新服务 → 验证对象读写 → 撤销旧凭据 |
| `HOTKEY_JWT_SECRET` | 所有访问令牌 | 公告会话失效 → 替换 → 重启 API → 重新登录 → 撤销旧值 |
| `HOTKEY_VERIFICATION_HMAC_SECRET` | 未使用的验证/重置票据 | 确认可接受旧票据失效 → 替换 → 重启 API → 重新发起流程 |

轮换后必须通过 readiness、登录、来源探测、一次证据写读和审计检查。任何一步失败时恢复旧值、重启受影响服务并保持对应来源停用。
