# 部署、升级与回滚

## 适用边界

本手册面向当前模块化单体部署：PostgreSQL、Redis、MinIO、Go Server/Worker 与 Next.js Web。它不包含 Kafka、Temporal、Elasticsearch、Keycloak、Python 服务或 Kubernetes 高可用拓扑。

在 `status` 改为 `active` 前，必须完成空库与非空库升级、回滚和恢复演练，并将证据写入 Acceptance 005。

## 发布前门禁

- 工作区只包含本次发布变更，无密钥、个人数据或临时产物；
- `backend/db/schema.sql`、后端生成 OpenAPI、发布 Swagger 和前端客户端一致；
- 日常与生产 Compose 均通过配置校验；
- 数据备份可读取且恢复点满足 RPO；
- 当前镜像、配置、Schema 兼容版本和回滚目标已登记；
- 变更具备前向兼容顺序，不要求删除事实或覆盖持久卷；
- 相关 Acceptance、回滚责任人和观察窗口已经确认。

## 发布顺序

1. 冻结变更并记录发布版本、配置摘要和数据库兼容版本；
2. 在隔离环境使用生产备份副本完成初始化/兼容性验证；
3. 构建并扫描后端、前端镜像；
4. 先部署向后兼容的 Schema 与后端；
5. 验证 readiness、关键 API、Worker 队列和证据存储；
6. 部署前端并验证登录、Monitor、事件、通知与搜索主路径；
7. 观察错误率、延迟、队列积压、数据库连接和对象存储失败；
8. 观察窗口结束后记录结果，不自动删除旧字段或旧镜像。

## 成功判据

- 所有容器健康且无持续重启；
- API Result 仍为 `code/message/data`，成功业务码为 `0`；
- 新旧前端在兼容窗口内均可消费 OpenAPI；
- 任务可领取、重试和恢复，无重复业务副作用；
- PostgreSQL、MinIO 与 Vault 的写入/读取均通过；
- 关键 SLO 未出现持续退化，日志无凭据和原始敏感正文。

## 停止与回滚

出现以下任一情况立即停止扩大发布：数据约束失败、权限越权、证据不可回读、队列重复副作用、错误率持续超阈值或无法确认回滚目标。

回滚遵循“代码回退、数据前向兼容”：

1. 停止新流量和新任务领取，保留正在运行任务的可恢复状态；
2. 回退到兼容旧 Schema 的上一应用版本；
3. 不删除新表、事实、任务、审计、对象或卷；
4. 若数据已损坏，转入 [备份、恢复与重建](002-备份恢复与重建.md)，不得用应用回滚替代恢复；
5. 验证旧版本关键路径并记录事件时间线和残余影响。

## 演练证据

- 发布版本与配置哈希；
- Compose 配置校验和应用质量命令结果；
- 空库/非空库兼容验证摘要；
- Smoke、回滚 Smoke 和数据对账结果；
- 发布前后指标、事件记录与责任人签字。

## 演练频率

- 每个重大 Schema、OpenAPI、运行入口或持久任务兼容变更在发布前至少演练一次；
- 常规发布与应用回滚至少每季度抽取一个候选版本演练一次；
- 任一演练失败或回滚路径变化后，修订手册并在下次发布前复演。
