# 备份、恢复与重建

## 适用环境与成功判据

本手册只在隔离的恢复环境、独立 Compose Project、新卷和无生产来源/通知出口的网络边界中执行，不得覆盖生产数据库、对象或 Vault。成功要求 PostgreSQL 兼容、MinIO 对象清单全量闭合且内容哈希按批准口径校验、Vault 人工区域完整、River 任务可安全恢复、派生投影可重建、权限隔离有效，并产出可复测的实际 RPO/RTO 与差异清单。

## 恢复目标

- 候选 RPO：15 分钟；
- 候选 RTO：2 小时；
- 业务事实、证据和人工知识优先于缓存、搜索投影和运行时临时状态；
- 候选数字只有在固定数据规模、硬件和演练窗口下通过后才成为承诺。

## 数据分级

| 资产 | 权威性 | 备份与恢复 |
|---|---|---|
| PostgreSQL | 业务事实与审计事实源 | 全量备份 + 可验证的增量/日志恢复策略 |
| MinIO | 原始证据和大对象 | 版本/复制或独立备份；按对象哈希校验 |
| Obsidian Vault | 人工长期知识 | 文件备份；启用 Git 时保留可审阅历史 |
| Redis | 缓存、验证码、短期票据、限流 | 原则上可丢弃重建；不得当作业务事实恢复 |
| 加密配置元数据 | Key ID、算法/版本、配置指纹，不含明文 Secret | 与数据备份分开保存；恢复前验证目标环境具备批准的解密能力 |
| River 任务事实 | Job、Attempt、终态及外部副作用关联 | 随 PostgreSQL 恢复；隔离 running/leased 任务并对账后再分批重领 |
| OpenAPI/客户端 | 代码生成物 | 从同一 Git revision 重新生成并校验 |
| 全文检索投影 | 可重建派生数据 | 从 PostgreSQL 与 Vault 全量重建并原子切换 |

## 备份前检查

- 记录代码版本、Schema 哈希、对象存储版本和 Vault revision；
- 校验备份目的地权限、加密和可用容量；
- 数据库备份、对象备份和密钥材料分离保存；
- 不把真实密钥、DSN 或个人绝对路径写入日志和文档；
- 为删除/撤权数据保留策略定义备份侧的到期处理。

## 一致性清单

每个可恢复点必须生成同一时间围栏内的清单，至少包含：Git revision、应用/上游镜像解析 ID、Schema Hash、OpenAPI Hash、PostgreSQL 恢复点与完成时间、MinIO Object Key/大小/版本/Hash 清单、Vault revision 与目录 Hash、配置指纹/Key ID、River 未终态 Job/Attempt 摘要、Retention/Rights 策略版本和通知出口禁用标识。任一资产不在同一围栏或清单缺失时，停止并重新取得恢复点。

## 隔离恢复流程

1. 创建独立 Compose 项目、网络、数据库、对象存储和 Vault 目录，并在网络/配置层禁用生产来源、邮件、Web Push 和用户通知出口；
2. 验证一致性清单、备份完整性、目标容量、配置指纹、Key ID 与解密能力；API/Worker 保持停止；
3. 恢复 PostgreSQL，运行只读 Schema/约束/OpenAPI 兼容检查，并识别 River 的 running/leased/retry_wait/终态 Job 与 Attempt；
4. 恢复 MinIO，对 Object Key、大小和版本清单做 100% 对账；内容 SHA-256 使用全量校验，若数据规模要求抽样，必须先批准比例、分层方法、风险声明和失败阈值，不能称为全量哈希对账；
5. 恢复 Vault，校验 Stable ID、Revision、目录 Hash、自动区域和人工区域；人工区域不能由 PostgreSQL 生成；
6. 对 River 未终态任务及已发生的外部副作用做隔离和幂等对账，在证据闭合前不得重领；
7. 重建全文检索、知识自动区域和其他可丢弃投影；不得清空 Notification/User Notification/已读事实或 Vault 人工区域；
8. 先以只读/不领取任务模式启动 API，执行登录、Monitor、内容、事件、报告、知识和通知只读 Smoke；
9. 分批恢复 Worker，验证租约重领、Attempt 追加和外部副作用零重复，再逐步开放非生产出口；
10. 计算实际 RPO/RTO，保存全量清单差异、哈希结果、任务恢复结果和未恢复项。

## M4 通知、Vault 与搜索投影恢复入口

`recover-projections` 是隔离恢复环境中的保守预检和重新排队入口。它不删除 Notification Outbox、User Notification、Notification Read Receipt 或 Delivery Attempt，也不接受正文、收件人列表、Vault 绝对路径或凭据参数。它对四类追加事实的全部行计算规范化 SHA-256，并记录通知、已读与 Attempt 的最大 ID；Vault 只输出经过当前文件或受保护 Revision 验证的人工区域 SHA-256。

先在 API、Worker、来源连接器和通知出口均停止的恢复环境执行只读预检：

```bash
cd backend
go run ./cmd/hotkey maintenance recover-projections --dry-run
```

预检只把 `dispatch_started_at IS NULL` 的 Delivery Claim 识别为可丢弃协调状态。任何已开始派发的 Claim 都返回 `started_delivery_claim_requires_provider_reconciliation`，必须先依据 Provider 幂等键/回执完成对账；既有 `unknown` Attempt 保留且不自动重发。Vault 当前文件冲突、受保护 Revision 缺失或一个文档对应多个 `document_source` Evidence 同样阻断执行，不能猜测修复。

执行模式还要求非生产配置、SMTP 关闭、网络层禁用生产来源/通知出口、独立操作人与复核人，以及不可变恢复运行、备份、演练证据摘要。事务成功时系统同步追加一条 `projection_recovery_runs` 不可变恢复运行记录，只保存安全运行 ID、双人身份、证据摘要、事实/人工区前后指纹、稳定游标和任务计数；该记录禁止更新或删除，不保存正文、收件人、Vault 路径、凭据或连接串：

```bash
cd backend
go run ./cmd/hotkey maintenance recover-projections \
  --apply \
  --confirm-isolated \
  --production-egress-disabled \
  --operator-id '<operator-record-id>' \
  --reviewer-id '<independent-reviewer-record-id>' \
  --run-sha256 '<64-lowercase-hex>' \
  --backup-evidence-sha256 '<64-lowercase-hex>' \
  --rehearsal-evidence-sha256 '<64-lowercase-hex>'
```

该事务重新读取并锁定恢复目录，只清理尚未开始外部派发的 Delivery Claim；随后以恢复运行摘要生成稳定 River Key，为缺失的知识文件排入 `project_knowledge`，为当前可读但缺少授权搜索投影的唯一 Source Evidence 排入 `generate_source_document`。队列参数只有稳定业务 ID、版本和 Hash；Vault 文件正文从 PostgreSQL 与受保护 Revision 读取，搜索正文从 Source Evidence/Vault 投影重新读取。事务提交前再次验证四类通知事实与 Vault 人工区域指纹不变，否则全部回滚。

Redis、WebSocket 会话、浏览器客户端缓存必须通过隔离环境的实例/卷生命周期清理，不能由该数据库命令删除。敏感搜索投影遵守数据库 Tombstone/撤权约束；演练应从不含可丢弃投影的恢复副本开始，禁止在在线库绕过触发器删除。Worker 完成后重新运行 `--dry-run`，要求 `vault_missing=0`、`search_missing=0`、`blockers=`，再执行 PostgreSQL–Vault/MinIO 对账并保存前后事实指纹、人工区域指纹、River Job/Attempt 和差异清单。

仓库内的可复现独立副本门禁使用当前已安装的 Go、`pg_dump`、`pg_restore`，以及隔离 PostgreSQL、Redis DB 15 和 MinIO Bucket；它不启动或重启业务项目，也不访问外部 Provider：

```bash
cd backend
HOTKEY_M4_PROJECTION_RECOVERY_OUTPUT='<new-private-report-path>' \
HOTKEY_M4_PROJECTION_RECOVERY_ENVIRONMENT='<isolated-environment-label>' \
HOTKEY_M4_PROJECTION_RECOVERY_HARDWARE='<fixed-hardware-label>' \
HOTKEY_M4_PROJECTION_RECOVERY_GIT_REVISION='<40-char-commit-sha>' \
HOTKEY_M4_PROJECTION_RECOVERY_PRODUCTION_EGRESS_DISABLED=true \
make m4-fault-recovery-acceptance
```

门禁先从完整源库生成 Custom Dump，但明确不把 `document_version_search_indexes` 的可丢弃数据写入恢复包；源库和源 Vault 保持不变。它把其余 Schema/事实恢复到独立 PostgreSQL，把受保护 Revision 复制到独立 MinIO Bucket，把 Vault 复制到独立目录后只移除目标知识投影，并通过隔离 Redis DB 生命周期清除 WebSocket/客户端缓存 Fixture。受控命令只移除尚未开始的 Delivery Claim，随后正式 `project_knowledge` 与 `generate_source_document` Worker 必须使二次预检归零。输出采用 `O_EXCL` 和 `0600`，只记录事实 ID/游标/指纹、人工区哈希、作业计数、`unknown` Attempt 的人工处置、撤权可见延迟和差异数组；不记录正文、邮件地址、对象键、Vault/宿主路径、连接串或凭据。该自动化 Fixture 不等同于生产操作者/复核人批准。

Python Agent 不参与恢复编排、通知交付、事实存储或 Vault/搜索写入；`agent/` 仍只负责内部 Python 数据分析与模型编排，恢复状态与作业事实由 Go/PostgreSQL/River 持有。

## 失败停止条件

- Schema 与应用版本不兼容；
- 证据哈希不一致或对象缺失率超过已批准阈值；
- Vault 人工区域丢失或 Stable ID 冲突；
- 恢复环境意外连接生产来源、邮件或用户通知；
- 权限隔离、审计链或备份密钥无法验证。
- River 未终态任务的租约、Attempt 或外部副作用无法对账；
- 任一 Notification/User Notification/已读事实或 Vault 人工区域被重建流程清空。

失败后保留恢复环境、只读日志和对账结果用于调查；停止继续写入或切流，销毁前先登记证据。恢复演练不修改生产事实，因此不以“回滚生产数据”收尾；需要重试时创建新的隔离目标并从已验证恢复点重新开始。

## 演练频率与证据

- 重大 Schema/存储变更发布前执行一次；
- 常规恢复演练至少每季度一次；
- 证据包含一致性清单、版本、数据规模、起止时间、RPO/RTO、对象清单全量对账、内容 Hash 全量或已批准抽样口径、River 租约/Attempt/副作用结果、Smoke、差异、失败与改进项；
- 只有真实恢复演练通过后，本手册和相关 SLO 才能改为 `active`。

### 001 联合恢复证据校验

仓库的可执行联合演练器会在当次进程中创建两个随机命名的可丢弃 PostgreSQL 数据库、两个开启版本的 MinIO Bucket 和三个临时 Vault 目录。它先建立业务事实、对象证据、含人工字节的 Vault 文件与 River Job/Attempt Fixture，再真实执行 `pg_dump`/`pg_restore`、MinIO 对象备份/回写和 Vault 文件备份/回写，最后对五类资产的计数与规范化 SHA-256 做零差异对账。`HOTKEY_TEST_DSN` 只作为创建随机数据库的维护连接，演练器绝不向该 DSN 指向的数据库写入或恢复；它不启动 API/Worker，且必须显式声明生产出口已禁用。完成后删除当次数据库、Bucket 和临时文件。

```bash
cd backend
export HOTKEY_TEST_DSN='<isolated-postgresql-maintenance-dsn>'
export HOTKEY_TEST_REDIS_URL='<isolated-redis-url>'
export HOTKEY_TEST_MINIO_ENDPOINT='<isolated-minio-host:port>'
export HOTKEY_TEST_MINIO_ACCESS_KEY='<isolated-access-key>'
export HOTKEY_TEST_MINIO_SECRET_KEY='<isolated-secret-key>'
export HOTKEY_TEST_MINIO_BUCKET='hotkey-joint-recovery'
export HOTKEY_JOINT_RECOVERY_OUTPUT='<new-evidence-directory>/joint-recovery.json'
export HOTKEY_JOINT_RECOVERY_ENVIRONMENT='isolated-recovery-runner-identifier'
export HOTKEY_JOINT_RECOVERY_HARDWARE='cpu/memory/disk/network exact description'
export HOTKEY_JOINT_RECOVERY_GIT_REVISION='<40-character-lowercase-commit-sha>'
export HOTKEY_JOINT_RECOVERY_PRODUCTION_EGRESS_DISABLED='true'
make joint-recovery-acceptance
```

输出版本为 `hotkey-joint-recovery-v1`，使用独占创建且拒绝覆盖；报告保留五类资产的预期/实际计数、Hash、MinIO 版本化对象数、实际时间线、毫秒级 RPO/RTO、候选目标是否命中与排除项。该命令是仓库的固定合成 Fixture；发布候选仍应在目标部署同构环境从已批准备份再执行一次，不得把合成数据的命中数字升级为无条件 SLA。

恢复演练在全部读取和对账命令完成后生成一份独立 JSON manifest。清单必须使用固定的 `hotkey-recovery-manifest-v1` 结构，且至少含一个 Vault 人工区域 Fixture：

```json
{
  "version": "hotkey-recovery-manifest-v1",
  "git_revision": "<40-character-lowercase-commit-sha>",
  "environment": "isolated-recovery-runner-identifier",
  "isolated": true,
  "production_egress_disabled": true,
  "incident_cutoff_at": "2026-08-27T08:00:00Z",
  "recovery_point_at": "2026-08-27T07:50:00Z",
  "drill_started_at": "2026-08-27T08:05:00Z",
  "services_readable_at": "2026-08-27T09:35:00Z",
  "reconciliation_completed_at": "2026-08-27T09:45:00Z",
  "assets": [
    {"name":"postgres_facts","expected_count":1,"actual_count":1,"expected_sha256":"<sha256>","actual_sha256":"<sha256>"},
    {"name":"minio_evidence","expected_count":1,"actual_count":1,"expected_sha256":"<sha256>","actual_sha256":"<sha256>"},
    {"name":"vault_all_files","expected_count":1,"actual_count":1,"expected_sha256":"<sha256>","actual_sha256":"<sha256>"},
    {"name":"vault_manual_regions","expected_count":1,"actual_count":1,"expected_sha256":"<sha256>","actual_sha256":"<sha256>"},
    {"name":"river_jobs_attempts","expected_count":1,"actual_count":1,"expected_sha256":"<sha256>","actual_sha256":"<sha256>"}
  ],
  "differences": []
}
```

每类 SHA-256 都针对该类资产按稳定业务 ID 排序后的规范化清单计算，而不是针对命令输出或含绝对路径的临时文本计算。`vault_manual_regions` 的 expected/actual 清单必须保留人工字节的 Hash；`river_jobs_attempts` 必须包含未终态 Job、Attempt 和已知外部副作用身份。

```bash
cd backend
export HOTKEY_RECOVERY_MANIFEST='<immutable-drill-directory>/manifest.json'
export HOTKEY_RECOVERY_OUTPUT='<immutable-drill-directory>/verification.json'
make recovery-evidence
```

校验工具使用 `incident_cutoff_at - recovery_point_at` 计算实际 RPO，使用 `services_readable_at - drill_started_at` 计算实际 RTO，并独立输出候选 15 分钟/2 小时是否命中。未达候选值不会伪造对账失败，但也不会被隐藏；资产缺失、计数/Hash 不同、未解释差异、非隔离环境或已有输出文件会直接失败。该命令只验证已采集证据，不替代本手册的真实备份、恢复和对账命令。
