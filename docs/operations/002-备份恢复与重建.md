# 备份、恢复与重建

## 适用环境与成功判据

本手册只在隔离的恢复环境、独立 Compose Project、新卷和无生产来源/通知出口的网络边界中执行，不得覆盖生产数据库、对象或 Vault。成功要求 PostgreSQL 兼容、MinIO 对象清单全量闭合且内容哈希按批准口径校验、Vault 人工区域完整、River 任务可安全恢复、派生投影可重建、权限隔离有效，并产出可复测的实际 RPO/RTO 与差异清单。

## 恢复目标

- 候选 RPO：15 分钟；
- 候选 RTO：2 小时；
- 业务事实、证据和人工知识优先于缓存、搜索投影和运行时临时状态；
- 候选数字只有在固定数据规模、硬件和演练窗口下通过后才成为承诺。

## 数据分级

| 资产 | 权威性 | 备份与恢复 |
|---|---|---|
| PostgreSQL | 业务事实与审计事实源 | 全量备份 + 可验证的增量/日志恢复策略 |
| MinIO | 原始证据和大对象 | 版本/复制或独立备份；按对象哈希校验 |
| Obsidian Vault | 人工长期知识 | 文件备份；启用 Git 时保留可审阅历史 |
| Redis | 缓存、验证码、短期票据、限流 | 原则上可丢弃重建；不得当作业务事实恢复 |
| 加密配置元数据 | Key ID、算法/版本、配置指纹，不含明文 Secret | 与数据备份分开保存；恢复前验证目标环境具备批准的解密能力 |
| River 任务事实 | Job、Attempt、终态及外部副作用关联 | 随 PostgreSQL 恢复；隔离 running/leased 任务并对账后再分批重领 |
| OpenAPI/客户端 | 代码生成物 | 从同一 Git revision 重新生成并校验 |
| 全文检索投影 | 可重建派生数据 | 从 PostgreSQL 与 Vault 全量重建并原子切换 |

## 备份前检查

- 记录代码版本、Schema 哈希、对象存储版本和 Vault revision；
- 校验备份目的地权限、加密和可用容量；
- 数据库备份、对象备份和密钥材料分离保存；
- 不把真实密钥、DSN 或个人绝对路径写入日志和文档；
- 为删除/撤权数据保留策略定义备份侧的到期处理。

## 一致性清单

每个可恢复点必须生成同一时间围栏内的清单，至少包含：Git revision、应用/上游镜像解析 ID、Schema Hash、OpenAPI Hash、PostgreSQL 恢复点与完成时间、MinIO Object Key/大小/版本/Hash 清单、Vault revision 与目录 Hash、配置指纹/Key ID、River 未终态 Job/Attempt 摘要、Retention/Rights 策略版本和通知出口禁用标识。任一资产不在同一围栏或清单缺失时，停止并重新取得恢复点。

## 隔离恢复流程

1. 创建独立 Compose 项目、网络、数据库、对象存储和 Vault 目录，并在网络/配置层禁用生产来源、邮件、Web Push 和用户通知出口；
2. 验证一致性清单、备份完整性、目标容量、配置指纹、Key ID 与解密能力；API/Worker 保持停止；
3. 恢复 PostgreSQL，运行只读 Schema/约束/OpenAPI 兼容检查，并识别 River 的 running/leased/retry_wait/终态 Job 与 Attempt；
4. 恢复 MinIO，对 Object Key、大小和版本清单做 100% 对账；内容 SHA-256 使用全量校验，若数据规模要求抽样，必须先批准比例、分层方法、风险声明和失败阈值，不能称为全量哈希对账；
5. 恢复 Vault，校验 Stable ID、Revision、目录 Hash、自动区域和人工区域；人工区域不能由 PostgreSQL 生成；
6. 对 River 未终态任务及已发生的外部副作用做隔离和幂等对账，在证据闭合前不得重领；
7. 重建全文检索、知识自动区域和其他可丢弃投影；不得清空 Notification/User Notification/已读事实或 Vault 人工区域；
8. 先以只读/不领取任务模式启动 API，执行登录、Monitor、内容、事件、报告、知识和通知只读 Smoke；
9. 分批恢复 Worker，验证租约重领、Attempt 追加和外部副作用零重复，再逐步开放非生产出口；
10. 计算实际 RPO/RTO，保存全量清单差异、哈希结果、任务恢复结果和未恢复项。

## 失败停止条件

- Schema 与应用版本不兼容；
- 证据哈希不一致或对象缺失率超过已批准阈值；
- Vault 人工区域丢失或 Stable ID 冲突；
- 恢复环境意外连接生产来源、邮件或用户通知；
- 权限隔离、审计链或备份密钥无法验证。
- River 未终态任务的租约、Attempt 或外部副作用无法对账；
- 任一 Notification/User Notification/已读事实或 Vault 人工区域被重建流程清空。

失败后保留恢复环境、只读日志和对账结果用于调查；停止继续写入或切流，销毁前先登记证据。恢复演练不修改生产事实，因此不以“回滚生产数据”收尾；需要重试时创建新的隔离目标并从已验证恢复点重新开始。

## 演练频率与证据

- 重大 Schema/存储变更发布前执行一次；
- 常规恢复演练至少每季度一次；
- 证据包含一致性清单、版本、数据规模、起止时间、RPO/RTO、对象清单全量对账、内容 Hash 全量或已批准抽样口径、River 租约/Attempt/副作用结果、Smoke、差异、失败与改进项；
- 只有真实恢复演练通过后，本手册和相关 SLO 才能改为 `active`。
