# 来源授权、预算与故障处置

## 适用环境与前置检查

适用于开发、验收和生产中的官方 API、RSS、Atom 或明确授权 Feed；首次启用、授权/套餐变化、凭据轮换、持续 401/403/429、解析契约变化或恢复停用连接时执行。开始前确认操作者具有 Admin 权限，Rights/Policy 责任人、授权到期日、预算上限、脱敏审计和回滚到“禁用连接”的路径均已登记。

## 原则

只使用官方 API、RSS、Atom 或明确授权 Feed。不得绕过登录、验证码、设备指纹、反爬或平台访问限制；不得采集私密账号、封闭群组或未获许可的评论。

每次来源调用必须依次通过：

```text
Capability → Rights/Policy → Credential → Budget → Rate Limit → Endpoint/SSRF Policy → Request
```

其中 Credential 门禁只验证凭据引用、状态、用途与授权关联；只有 Endpoint/SSRF Policy 已验证最终目标（含重定向）后，执行器才可在请求边界解密并附加凭据。任何早期探测、解析或重定向检查均不得携带 Secret。

## 启用来源

1. 登记平台、用途、数据类型、允许动作、保留限制和授权到期日；
2. 记录 Capability：发现、Lookup、会话、指标、历史窗口和分页上限；
3. 使用凭据引用，不在数据库普通字段、日志或文档中保存明文；
4. 配置每分钟/每日请求、每轮条目/页数/字节、墙钟时间和重试预算；
5. 用非生产 Monitor 执行健康、分页、Checkpoint、证据和限流测试；
6. 通过权限与数据最小化审查后才允许生产启用。

## 故障分类

| 信号 | 判断 | 默认动作 |
|---|---|---|
| 401 | 凭据失效或时钟/签名错误 | 停止重试，禁用连接，通知管理员 |
| 403 | 权利、套餐或策略拒绝 | 停止采集，重新做 Rights 决策 |
| 429 | 配额或速率限制 | 遵守 Retry-After，退避并消耗重试预算 |
| 5xx/超时 | 上游暂时故障 | 有界退避；超过预算标记部分失败 |
| 解析失败 | 契约或 Feed 格式变化 | 保存脱敏证据，隔离样本，不无限重试 |
| 权利到期 | 授权不可继续 | 停止新采集，按策略删除/去标识并审计 |

单来源失败不得阻塞其他来源；整轮运行应给出 `partial_success` 或等价明确状态，并保留每个来源的结果、错误类别和重试决定。

## 恢复

1. 确认授权、凭据、Endpoint 和预算均有效；
2. 在隔离 Monitor 上执行 Health 与单页采集；
3. 验证 Checkpoint 不倒退，重试不创建重复 Observation/Document；
4. 验证原始证据、发布时间和来源身份正确；
5. 小流量恢复，观察 401/403/429、解析成功率和延迟；
6. 记录停机窗口、丢失窗口、回填决定和审批人。

## 成功与停止判据

成功要求 Capability 与 Rights 一致、健康请求通过、Checkpoint 不倒退、重复执行不产生重复当前事实、证据哈希可验证、预算/限流生效且普通日志无凭据或完整敏感正文。出现授权不明、凭据异常、SSRF/重定向策略失败、预算不可控、证据无法验证、重复副作用或日志泄密时立即停止；禁用该连接和新任务，保留已提交事实与审计，不影响其他来源。

## 三来源真实授权冒烟

`backend/` 下的 `make source-live-smoke` 是受信任环境专用入口，普通 CI 不执行。它通过正在运行的 Go API 依次读取三个已配置来源、执行管理员 Health，再对 RSS、Hacker News、X 发起一次有界即时搜索，因此不会绕过 Application 准入、Connector Endpoint/SSRF、预算或凭据边界。执行前必须已经完成本节的授权登记、当前 `fetch` Rights 决策、来源配置和 X 托管凭据写入。

调用方通过受信任 Secret 注入提供以下环境变量，不得把值写入仓库、命令历史、日志或报告：

| 变量 | 要求 |
|---|---|
| `HOTKEY_SOURCE_LIVE_SMOKE_CONFIRM` | 必须精确为 `I_CONFIRM_AUTHORIZED_P0_SOURCES`，表示操作者已确认三个来源均获授权 |
| `HOTKEY_SOURCE_LIVE_SMOKE_BASE_URL` | 运行中 API 的 HTTPS Origin；本机只允许 loopback HTTP |
| `HOTKEY_SOURCE_LIVE_SMOKE_ADMIN_TOKEN` | 临时 Admin Bearer Token，只通过受信任运行时注入 |
| `HOTKEY_SOURCE_LIVE_SMOKE_RSS_ID` / `HOTKEY_SOURCE_LIVE_SMOKE_HN_ID` / `HOTKEY_SOURCE_LIVE_SMOKE_X_ID` | 三个互不相同、已启用的真实 Source Connection ID |
| `HOTKEY_SOURCE_LIVE_SMOKE_QUERY` | 已批准且能在三来源返回公开数据的查询，最多 200 字符；原文不写入报告 |
| `HOTKEY_SOURCE_LIVE_SMOKE_ENVIRONMENT` | 不含秘密的受信任环境标识 |
| `HOTKEY_SOURCE_LIVE_SMOKE_REVISION` | 被验收代码的完整 40 位小写 Commit SHA |
| `HOTKEY_SOURCE_LIVE_SMOKE_OUTPUT` | 新的 `.json` 证据路径；工具拒绝覆盖已有文件 |

在 `backend/` 运行 `make source-live-smoke`。成功要求三个 ID 的类型匹配、连接启用、X 凭据状态就绪、三个 Health 均健康，并且即时搜索对每种来源只返回一个 `success` 状态且结果数大于零。报告版本为 `hotkey-source-live-smoke-v1`，只包含环境标识、Revision、时间、查询字节数，以及来源类型/ID、启用和凭据状态、健康/搜索状态、结果计数、耗时与允许列表错误码；不保存 Base URL、Token、查询原文、来源名称、Endpoint 或结果正文。失败仍生成脱敏报告并返回非零状态；缺少确认、输入不合法或输出已存在时在触网和写文件前失败关闭。

## 证据与审计

- Rights/Policy 决策及到期日；
- Capability 快照与凭据轮换时间，不含密钥；
- 预算、限流、Health 和来源成功率；
- 故障分类、重试次数、停用/恢复操作；
- 受影响 Monitor、时间窗、数据和回填结果。

## 演练频率

- 新来源、授权或凭据类型上线前执行完整启用与停用演练；
- 每月复核授权到期、配额与持续错误，每季度至少演练一次限流、授权失效和解析失败；
- 权利、接口契约或保留政策变化后立即复核并在生产恢复前完成小流量复演。
