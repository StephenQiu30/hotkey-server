# 保留、删除与撤权处置

## 适用边界

适用于数据到期、来源 Rights 变化、用户/管理员批准删除及错误数据隔离。`CHK-005-G5-002` 的自动化隔离合成复演已经完成；本手册仍为 `planned` 契约，在 `CHK-005-G5-007`、G6 与生产审批完成前不得用于生产删除。

操作目标必须是明确的 Workspace、来源、数据类别、对象 ID 集合、时间窗和策略版本。禁止使用宽泛路径、未解析变量或直接对象存储前缀作为删除范围。

## 必需参数与责任

| 参数 | 要求 |
|---|---|
| `retention_run_id` | 服务端生成的稳定运行身份 |
| 策略版本 | 已批准且在执行期间冻结 |
| 作用范围 | Workspace、来源、数据类型、ID/时间窗和预计数量 |
| Rights 决策 | 当前版本、到期/撤权时间和允许的 retain/delete 行为 |
| 审批 | 操作者、审批者、理由、备份侧到期策略和回滚边界 |
| 停止阈值 | 未批准对象、策略漂移、仍可读、数量/Hash 差异和错误上限 |

高风险批次由 Admin 发起，并使用双人或等价独立审批。任何角色都不能通过普通 API 读取被删除对象、密钥或对象存储路径。

## 当前已验证的隔离能力

当前代码已为固定七类 PostgreSQL 运维数据提供 `POST /api/v1/operations/retention-policies/:id/preview`、`POST /api/v1/operations/retention-runs/:id/approve` 和 `POST /api/v1/operations/retention-runs/:id/execute`。Preview 将策略 ID/Version、数据类别、Cutoff、Batch Size 与有序候选 ID 固化到只追加 `retention_runs` / `retention_run_items` 并计算 SHA-256；发起者不能批准自己的 Run，Execute 只接受同一 Run 的已批准精确 Hash，并在删除前重新验证策略和候选集。策略或候选漂移会把运行冻结为 `blocked`，写入稳定失败码和净化审计，不继续删除；可重试失败可沿同一 Run、候选 Hash 和未完成 Item 幂等续跑。Delivery Attempt 与 Audit Log 已作为受保护类别停用清理。

当前 Source Rights 拒绝后，内容、热点、文档、事件列表/详情/Evidence、搜索、通知深链与缓存读取均失败关闭，HTTP 响应使用 `private, no-store`。`hotkey maintenance expire-raw-evidence` 按 PostgreSQL 当前 Rights 与不可变血缘删除精确 MinIO 对象并追加删除审计；`hotkey maintenance expire-derived-artifacts` 只处理 `documents/...` 自动投影，在校验相对路径、SHA-256、大小和普通文件身份后删除精确 Vault 文件，保留 Artifact/Document 墓碑与血缘。Notification Outbox、User Notification、Notification Read Receipt、Delivery Attempt 和 Vault 人工区域均不属于删除能力的目标。

`reconcile-evidence-lineage` 已使用数据库生成的 Run 开始时间作为固定围栏；Rights、Retention、删除审计、备份运行和备份处置事实均按该围栏读取。Apply 必须绑定已登记的成功备份摘要；围栏内成功删除之前的每个成功备份都必须先有只追加的 `backup_retention_dispositions` 处置事实，否则 Run 不创建。完成回执固定输出 Run ID、围栏、备份摘要、已验证备份处置数、演练摘要和对象 Finding 计数。

提交 `f13080db` 已将上述能力收敛到同一份 `hotkey-retention-rights-rehearsal-v1` 附件：隔离 Fixture 在同一数据库围栏内重复两次验证 API/通知深链 `200→404`、检索 `1→0`、Redis 可丢弃缓存存在→不存在、真实 MinIO 原始对象与两份 Vault 自动投影物理删除、隔离外部 TAR 副本由可读变为不可读、受保护通知事实指纹和 Vault 人工文件 Hash 前后不变，最终系谱对账 3/3 健康且 `differences=[]`。远端运行 [33288799039](https://github.com/StephenQiu30/hotkey-server/actions/runs/33288799039) 全绿，净化报告见 [`retention-rights-rehearsal-github-ubuntu-f13080db.json`](../acceptance/evidence/005/retention-rights-rehearsal-github-ubuntu-f13080db.json)。因此 `CHK-005-G5-002` 已通过。

该报告只证明固定隔离合成数据和隔离文件系统执行器；TAR 副本不是生产备份，报告也不是生产删除批准。真实生产介质必须由目标环境的备份执行器逐一处置并经独立复核；本手册在 `CHK-005-G5-007` 与 G6 完成前继续保持 `planned`。

## Dry Run

1. 冻结策略版本、时间围栏和目标范围，记录当前代码/Schema/配置版本；
2. 从 PostgreSQL Rights 与系谱事实计算候选集，不从 MinIO/Vault 目录反向推断业务范围；
3. 输出各数据类别、对象数、字节、关联通知/报告/知识、备份侧影响和无法处理项；
4. 验证候选集不含未批准 Workspace、长期 Evidence 例外、法律/审计保留或活跃报告引用；
5. 重复 Dry Run，结果 Hash 必须一致；策略或事实变化时原审批失效。

## 执行顺序

1. 重新验证审批、策略、Rights、候选 Hash 和停止阈值；
2. 在 PostgreSQL 写入不可变执行批次与对象清单；
3. 先阻断 API、搜索、深链、预签名 URL 和缓存读取，验证不同角色均不可见；
4. 更新/移除可重建的检索、知识自动投影及 Delivery Claim/租约、WebSocket 会话、客户端缓存；不得删除 Notification Outbox、User Notification、Notification Read Receipt、Delivery Attempt 或 Vault 人工区域；
5. 按批准清单处理 MinIO 对象和可删除 Vault 自动文件/区域，保留必要 Hash、系谱、策略版本和删除审计；
6. 执行 PostgreSQL 当前视图/敏感派生值的到期或 tombstone 动作，不静默改写追加事实；
7. 对 API、MinIO、Vault、通知、检索、缓存和备份侧到期处理做对账；
8. 批次成功后冻结结果；部分失败保持可重入，不跳过未解释差异继续下一批。

隔离目标完成读取阻断与候选复核后，实体对象切片使用以下显式确认入口。命令不接受任意 MinIO 前缀或 Vault 路径；操作者仍须先固定数据库身份、代码版本、时间围栏和前后对象清单：

```bash
hotkey maintenance expire-raw-evidence --batch-size 25 --apply --confirm-delete
hotkey maintenance expire-derived-artifacts --batch-size 25 --apply --confirm-delete
```

## 备份侧到期与统一对账入口

物理删除完成后，先从受控备份目录按 `backup_runs` 身份找出恢复点早于最新成功删除审计的全部成功副本。备份执行器必须逐个销毁这些副本并验证其不可再读取，然后由与删除操作者独立的复核人签署一份严格清单。`record-backup-retention-disposition` **只登记外部销毁结果，不执行或替代备份删除**；不得在副本仍可读取时生成清单。

```json
{
  "version": "hotkey-backup-retention-disposition-v1",
  "disposition_sha256": "<64-lowercase-hex-stable-disposition-id>",
  "backup_run_sha256": "<recorded-successful-backup-run-sha256>",
  "deletion_evidence_sha256": "<immutable-deletion-report-sha256>",
  "reason_code": "rights_revoked",
  "operator_record_id": "<backup-disposal-operator-record-id>",
  "reviewer_record_id": "<independent-reviewer-record-id>",
  "disposed_at": "<RFC3339-timestamp>"
}
```

`reason_code` 只允许 `rights_revoked` 或 `retention_expired`。清单必须是非符号链接的普通文件、不超过 64 KiB；未知字段、未知/失败 Backup Run、自审、未来时间、重复 Backup 对应不同清单或任意路径/错误详情均失败停止。登记后事实不可更新或删除：

```bash
hotkey maintenance record-backup-retention-disposition \
  --manifest '<immutable-disposition-directory>/run.json'
```

所有受影响备份均登记后，先执行只读检查；Apply 使用独立操作者/复核人，并绑定已登记的成功备份与隔离恢复演练摘要：

```bash
hotkey maintenance reconcile-evidence-lineage \
  --scope all --batch-size 200 --grace-period-hours 24 --dry-run

hotkey maintenance reconcile-evidence-lineage \
  --scope all --batch-size 200 --grace-period-hours 24 \
  --apply --confirm-non-empty \
  --operator-id '<operator-record-id>' \
  --reviewer-id '<independent-reviewer-record-id>' \
  --backup-evidence-sha256 '<recorded-successful-backup-run-sha256>' \
  --rehearsal-evidence-sha256 '<isolated-rehearsal-sha256>'
```

Run 开始后新增或回填的 Rights、Retention、删除审计、备份运行及备份处置事实不能改变本次结论；应重新运行而不是修改原 Run。删除审计存在但 MinIO 对象/Vault 文件仍存在时保留 `policy_blocked` Finding；审计在围栏后写入时保留 `*_deletion_not_verified_at_fence` Finding，不倒退墓碑状态。

## 停止、恢复与回滚

命中未批准对象、策略漂移、候选 Hash 变化、读取仍可见、对象/系谱不一致、人工 Vault 区域可能受影响或审计写入失败时立即停止。读取阻断在撤权期间保持生效；修复原因后以同运行/批次身份幂等续跑。

删除已过不可逆点后不能用“重新显示”伪装回滚；只可从仍在批准保留期内的合法备份恢复，并重新评估 Rights。误阻断但尚未删除时，必须由独立审批解除读取阻断并记录时间线。

## 证据血缘抽样与保留例外

证据对账必须从 Event 或 Document Version 沿不可变关系回溯到 Source Observation、Evidence Reference 和 Evidence Snapshot，再核对对象存储中的实际 SHA-256、大小、生命周期以及当前 `store_raw`/`retain` 授权。禁止只凭数据库存在记录或历史授权回执把证据标记为有效；当前授权拒绝、对象缺失或 Hash 不一致都必须产生可审计 Finding，并在 Apply 模式进入阻断或隔离状态。

保留期已过的原始对象只有在存在已生效、未撤销且未过期的 `evidence_retention_exceptions` 审批时才可继续保持可用。例外只能豁免时间到期，不能覆盖当前 Rights 拒绝；对账结果必须记录 `approved_retention_exception`，并能关联审批人、批准依据、批准时间、有效期和撤销状态。前端必须把该状态显示为“经批准长期保留”，不得误报为普通可用或已过期。

隔离环境的统一最小回归入口如下；运行结果应与运行 ID、代码版本和测试数据库身份一起保存，且不得包含对象内容或凭据：

```bash
HOTKEY_TEST_DSN='<isolated-postgres-dsn>' \

HOTKEY_TEST_MINIO_ENDPOINT='<isolated-minio-endpoint>' \

HOTKEY_RETENTION_REHEARSAL_OUTPUT='<exclusive-private-output.json>' \
make retention-rehearsal-acceptance
```


## 成功判据与证据

- Dry Run 与执行范围/Hash 一致，零未批准对象；
- 撤权对象在 API、搜索、Vault 投影、MinIO URL 和缓存均不可读；
- Notification Outbox、User Notification、Notification Read Receipt、Delivery Attempt 和 Vault 人工区域未被误删；
- MinIO/Vault/PostgreSQL/投影/备份侧差异为零或全部有批准解释；
- 对账 Run 的 `backup_dispositions_verified` 等于围栏内所有受影响成功备份数，且每个处置清单对应的外部副本确已不可读；
- 证据保存策略、Rights、运行/批次 ID、审批、计数/字节、前后 Hash、失败重入、审计和已知残余。

## 演练频率

- 新数据类别、Rights 策略或删除实现上线前执行完整隔离演练；
- 每季度至少演练到期、撤权、部分失败和中断重入；
- 任一误删、仍可读或对账差异后立即停用生产批次，修订手册并复演。
