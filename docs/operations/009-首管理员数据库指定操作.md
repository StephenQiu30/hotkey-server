# 首管理员数据库指定操作

## 升级前清理

升级代码前后都不得保留旧引导凭据。删除本机 `.env`、存在时的 `.env.prod`、GoLand Run Configuration、容器/主机部署环境以及 Secret Store 中的 `HOTKEY_BOOTSTRAP_ADMIN_EMAIL` 和 `HOTKEY_BOOTSTRAP_ADMIN_PASSWORD`；如凭据曾进入受版本控制文件、共享日志或工单，应按对应平台流程撤销或轮换该密码并清理历史暴露。完成后以平台自身的变量/Secret 清单和仓库防回流测试复核，不在命令输出或验收文档中复制真实值。

代码升级后这两个键已不再读取；仅“代码忽略它们”不等于凭据已安全清理。

仅在新数据库已有一个正常注册、active、未删除用户，且不存在 active 管理员时执行。把 SQL 中 `admin@example.com` 替换为目标邮箱；不要在 SQL 中填写密码、验证码或 Token。

```sql
BEGIN;

DO $$
DECLARE
    target_email CONSTANT text := 'admin@example.com';
    change_ticket CONSTANT text := 'CHANGE-TICKET-ID';
    target_id bigint;
BEGIN
    PERFORM pg_advisory_xact_lock(hashtext('hotkey-identity-initial-admin-v1'));

    IF change_ticket = concat('CHANGE-', 'TICKET-ID') OR btrim(change_ticket) = '' THEN
        RAISE EXCEPTION 'a real change ticket is required';
    END IF;

    UPDATE users
    SET role = 'admin', version = version + 1, updated_at = now()
    WHERE lower(email) = lower(target_email)
      AND role = 'viewer'
      AND status = 'active'
      AND deleted_at IS NULL
      AND NOT EXISTS (
          SELECT 1 FROM users
          WHERE role = 'admin' AND status = 'active' AND deleted_at IS NULL
      )
    RETURNING id INTO target_id;

    IF target_id IS NULL THEN
        RAISE EXCEPTION 'initial administrator designation refused';
    END IF;

    INSERT INTO audit_logs (
        actor_type, action, resource_type, resource_id, request_id,
        before_data, after_data, result
    ) VALUES (
        'database_operator', 'identity.initial_admin.designated', 'user', target_id, change_ticket,
        jsonb_build_object('role', 'viewer'),
        jsonb_build_object('role', 'admin', 'database_principal', current_user),
        'success'
    );
END
$$;

SELECT id, email, role, status, version
FROM users
WHERE lower(email) = lower('admin@example.com')
  AND role = 'admin'
  AND status = 'active'
  AND deleted_at IS NULL;

COMMIT;
```

执行前必须同时替换邮箱和 `CHANGE-TICKET-ID`。`DO` 必须成功，最后查询必须且只能返回一行 `active/admin`。邮箱错误、目标状态错误或已经存在管理员时，`RAISE EXCEPTION` 会使整个事务失败，不得删除保护条件后重试。首次管理员存在后，后续角色操作使用管理员 API。

## Break-glass：纠正误指定

数据库操作员无需知道错误管理员密码。仅当当前恰好一个 active admin 且它就是误指定用户时，执行以下原子纠正；替换两个邮箱和变更单号：

```sql
BEGIN;

DO $$
DECLARE
    mistaken_email CONSTANT text := 'wrong-admin@example.com';
    correct_email CONSTANT text := 'correct-admin@example.com';
    change_ticket CONSTANT text := 'CHANGE-TICKET-ID';
    mistaken_id bigint;
    correct_id bigint;
BEGIN
    PERFORM pg_advisory_xact_lock(hashtext('hotkey-identity-initial-admin-v1'));

    IF change_ticket = concat('CHANGE-', 'TICKET-ID') OR btrim(change_ticket) = '' THEN
        RAISE EXCEPTION 'a real change ticket is required';
    END IF;
    IF (SELECT count(*) FROM users WHERE role = 'admin' AND status = 'active' AND deleted_at IS NULL) <> 1 THEN
        RAISE EXCEPTION 'break-glass requires exactly one active administrator';
    END IF;

    SELECT id INTO mistaken_id FROM users
    WHERE lower(email) = lower(mistaken_email)
      AND role = 'admin' AND status = 'active' AND deleted_at IS NULL
    FOR UPDATE;
    SELECT id INTO correct_id FROM users
    WHERE lower(email) = lower(correct_email)
      AND role = 'viewer' AND status = 'active' AND deleted_at IS NULL
    FOR UPDATE;
    IF mistaken_id IS NULL OR correct_id IS NULL OR mistaken_id = correct_id THEN
        RAISE EXCEPTION 'break-glass target validation failed';
    END IF;

    UPDATE users SET role = 'admin', version = version + 1, updated_at = now() WHERE id = correct_id;
    UPDATE users SET role = 'viewer', version = version + 1, updated_at = now() WHERE id = mistaken_id;

    INSERT INTO audit_logs (actor_type, action, resource_type, resource_id, request_id, before_data, after_data, result)
    VALUES
      ('database_operator', 'identity.initial_admin.corrected', 'user', correct_id, change_ticket,
       jsonb_build_object('role', 'viewer'), jsonb_build_object('role', 'admin', 'database_principal', current_user), 'success'),
      ('database_operator', 'identity.initial_admin.corrected', 'user', mistaken_id, change_ticket,
       jsonb_build_object('role', 'admin'), jsonb_build_object('role', 'viewer', 'database_principal', current_user), 'success');
END
$$;

SELECT id, email, role, status
FROM users
WHERE lower(email) IN (lower('wrong-admin@example.com'), lower('correct-admin@example.com'))
  AND status = 'active' AND deleted_at IS NULL
ORDER BY email;

COMMIT;
```

必须返回正确用户为 admin、错误用户为 viewer；任一异常都会使两次角色更新和两条审计全部回滚。不得用该流程处理日常管理员变更。
