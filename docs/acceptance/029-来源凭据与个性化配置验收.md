# 来源凭据与个性化配置验收

## 验收结论

029 于 2026-08-09 通过验收。管理员现在可在登录后的来源管理页直接填写和轮换 API Key、Token 或 OAuth 凭据包；来源参数与认证密文以 PostgreSQL 为工作区事实源。部署环境只新增独立的来源凭据主密钥，旧 `env:NAME` 来源继续兼容。任何读取响应、页面、审计和安全错误均不返回凭据明文。

| 标准 | 结果 | 证据 |
|---|---|---|
| AC-029-1 | passed | 隔离全栈环境中，Admin 从“新增来源”直接提交凭据并创建来源；页面只显示“凭据已配置”。 |
| AC-029-2 | passed | “替换凭据”表单初始为空，提交新值后来源版本从 1 变为 2、健康状态重置为 `unknown`；集成测试覆盖旧版本并发写入拒绝。 |

```bash
cd backend
make openapi-validate

  make database-runtime-verify lint test build validate schema-verify

cd ../frontend
npm run openapi:check
npm run typecheck
npm run test:unit

```

OpenAPI 连续生成前后哈希一致且契约测试通过。后端数据库空库初始化、目录一致性、vet、全部 Go 包、构建、架构、Repository 和 Schema 门禁通过。前端 OpenAPI Client、TypeScript、47 个测试文件共 201 项测试和 20 个生产路由构建通过。

## 浏览器与密文证据

在独立 PostgreSQL 数据库、独立 API 端口和独立 Web 端口完成 Admin 主故事：登录、打开来源管理、直接填写凭据创建 RSS 来源、确认旧值不回显、替换凭据并看到重新探测提示。浏览器控制台无 error/warn。

数据库证据为 `managed:v1 | key_version=1 | nonce=12`，密文中不包含新旧测试明文；轮换后来源版本为 2、健康状态为 `unknown`。后端请求日志只记录路由、状态和请求 ID。验收结束后临时服务和临时数据库已删除，主数据库、现有 3000/8080 服务及 localhost 登录 Cookie 未修改。

## 限制与回滚

- MVP 仍以单工作区共享来源为事实模型，不引入个人私有来源或多租户。
- 主密钥不存入数据库；丢失时密文不可恢复，只能重新录入。轮换步骤见 Operations 002。
- 回滚先停用托管来源并恢复支持 029 的应用或旧主密钥；不得删除来源、密文、采集事实或审计。旧 env 引用来源不受影响。
