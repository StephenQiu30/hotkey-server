# 多源 AI 热点监控首版收敛验收

## 结果

035 于 2026-08-12 通过验收。产品主线已从错误的 X-only 假设恢复为“七来源采集—查询扩展—相关性决策—MicroEvent—Heat/EvidenceState—WebSocket/邮件通知”，并从默认启动图、OpenAPI 和工作台卸载报告、知识库、Agent、legacy Event/Radar/Alert 产品入口。后续收敛将来源配置、用户与权限、治理统一为 Admin 路由，非管理员不再看到入口或权限说明页；个人版来源创建默认只显示连接必填信息，手动搜索不再受任意的每日 20 次产品配额阻断。评论正文、评论树和通用浏览器爬虫没有混入本次实现，继续由 036 独立评审。

## 参考仓库调研结论

调研基于 `liyupi/yupi-hot-monitor` 提交 `cd48b0885bfa8ae9c8043cf78ef6cfd045530bdb` 的 README、REQUIREMENTS、采集任务、AI 分析、筛选和 Socket.io 代码。采用的是其“多源发现、AI 扩词、AI 降噪、实时通知、多维筛选”的产品闭环，没有复制以下实现约束：第三方 Twitter 聚合 API、单次 LLM `isReal`、进程内扩词缓存、内存全量排序、无持久游标广播和命中 URL 后停止指标观测。

本项目最终边界为：Go 模块化单体继续承载控制面、调度、持久事实、AI 编排、查询和通知；PostgreSQL 是 MicroEvent/UserNotification 的事实源；X 使用官方 Recent Search/Post Lookup；七类来源独立失败；可信度只表达可引用证据覆盖、冲突、更正和撤回，不把模型分数称为事实概率。

## 浏览器与运行时证据

使用 `agent-browser` 访问隔离 Compose 的真实 Next.js 生产构建和 Go 后端，没有注入 API Mock：

1. 原 035 真实 Admin 登录验收中导航包含概览、监控、来源、内容、热点事件和通知；本次匿名深链实测会安全进入带原目标的登录页。当前浏览器没有可复用的 Viewer 登录态，因此未伪造会话；Viewer/Editor 的入口隐藏、空渲染、零目标请求和概览 replace 由路由/导航专项测试及全量回归覆盖。
2. 来源表单明确展示七种来源，并以 `https://example.com/feed.xml` 成功创建无凭据 RSS 连接；未点击探测或采集，避免把外部网络结果冒充连接器验收。
3. 事件页展示 heat/relevance/latest 三种排序，以及状态、Monitor、来源、EvidenceState、开始/结束时间筛选；相关性排序切换成功。当前本机开发服务复验确认页面使用统一 `app-page`（最大宽度 1440px）、共享页头与筛选卡片；390px 无水平溢出，空状态无上一页/下一页按钮，Next.js 错误浮层为 0。
4. WebSocket 首轮在反向代理 Host 与前端 Origin 不同的场景暴露 403。修复后只允许 `HOTKEY_CORS_ALLOWED_ORIGINS` 中的精确 Origin，不使用全开放选项；不受信任 Origin 单元测试仍为 403。浏览器显示“实时”，服务端记录 101。
5. 1440×1000 和 390×844 页面均无水平溢出；390px 事件页 axe-core WCAG 2A/2AA 为 0 violations、23 passes。
6. 本机登录态浏览器复验中，RSS 新增来源首屏只有来源类型、名称、Feed 地址和折叠的高级设置；展开后弹窗高度 714px、外层无溢出并保留内部滚动。监控页 DOM 中“手动搜索配额”数量为 0，页面和应用自身没有新增控制台错误。

## 过度设计清理

- 删除默认前端的报告、知识归档、Agent Token、订阅/旧告警页面、对应生成 Client 和单元测试，不再宣传首版不提供的能力。
- 删除默认 Go 启动图中的 legacy route/producer，并移除已经没有调用方的 report automation adapter 与生命周期接口。
- 保留历史模块和数据库不可变事实，便于审计与回滚；没有执行删表或破坏性数据迁移。保留 Rights、EvidenceState、通知、审计、配额和安全基础设施，因为它们仍服务于首版主链。
- 删除监控页每日手动搜索余额条、UTC 重置提示和第 21 次请求的产品 429；保留手动搜索事实账本、冷却/幂等和真实来源限流。来源弹窗将非必填运维字段收进高级设置，未删除后端安全默认值。

## 已知限制与未通过范围

- 本轮没有使用真实 X/Bing/Bilibili/Weibo/Google 凭据，也没有触发计费或公开网络采集；连接器验收使用官方响应契约夹具、Registry/HTTP/数据库集成测试。上线前仍需在各自受控凭据和条款下做非破坏性 smoke test。
- 浏览器验收没有发送真实外部邮件；邮件内容、权限、重试和持久化生命周期由单元与 PostgreSQL 集成测试覆盖。SMTP 上线 smoke 需由持有测试收件箱和服务端凭据的操作者执行。
- `npm audit` 报告 3 个 high，均来自开发期 `@umijs/openapi -> mockjs/js-yaml` 链且 `npm audit --omit=dev` 为 0；当前上游没有为整条链提供可用自动修复，记录为构建供应链风险，不以强制升级破坏生成链。
- 评论/回复、评论树、浏览器 Cookie、Playwright 登录态抓取和 Bilibili 页面爬虫均未实现。036 仍为 `proposed/planned`；没有书面授权、平台条款和来源级 RightsDecision 前不得进入生产采集。

## Go 与后续评论采集结论

Go 仍适合作为核心框架。评论功能首先需要补齐 `parent_external_id`、`root_external_id`、`relation_type`、分页游标和独立速率/保留策略，再接入各平台官方评论 API；这些是领域模型与合规问题，不是语言瓶颈。只有确有官方 API 无法覆盖、已获得书面授权且需要浏览器执行的单一平台，才考虑把 TypeScript/Playwright 作为隔离采集适配器，通过受限任务契约返回标准化结果；不得把浏览器运行时并入 Go 主进程或让它直接写业务事实表。

## 回滚

可关闭 WebSocket 并继续使用 SSE/REST；可停用自动 Claim/Evidence 或 X 指标刷新消费者而不回滚 MicroEvent；新增查询参数向后兼容，旧客户端仍使用默认 heat 排序。若需恢复历史只读入口，应单独评审并重新接回 route，不通过覆盖、删除或重解释既有 Evidence、Document、MicroEvent、Notification 和 DeliveryAttempt 事实完成回滚。
