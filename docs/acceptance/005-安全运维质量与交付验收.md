## Schema、API、配置与部署影响

- Schema 在既有只追加 `backup_runs` 之外新增 `retention_runs`、`retention_run_items`、`derived_artifact_deletion_audits` 与 `backup_retention_dispositions`，并为 `evidence_lineage_reconciliation_runs` 固定已验证备份处置数；保存策略/候选边界、不可变 Vault 路径/Hash/大小、运行状态、独立操作/复核者、计数、时间和稳定失败码；触发器禁止删除、候选项/审计/备份处置改写及非法终态迁移；
- 新增 `hotkey maintenance expire-derived-artifacts --batch-size <n> --apply --confirm-delete`，且既有 `expire-raw-evidence` 同样从 PostgreSQL 当前 Rights 与不可变血缘计算候选，不接受任意对象前缀或 Vault 路径；
- 新增 `hotkey maintenance record-backup --manifest <path>` 与 `record-backup-retention-disposition --manifest <path>`，只读取不可变严格清单，不执行备份或备份删除本身；
- Runtime Overview 复用现有安全 DTO；Retention API 由旧直接执行入口收敛为 Preview、Approve、Execute 三段式路径，OpenAPI 与前端生成客户端已同步且无漂移；
- 运维请求边界升级为 `p0-request-boundaries-v2`，覆盖全部三段 Retention 路径；
- 不新增密钥、外部服务、宿主端口或环境变量；Python `agent/` 的数据分析边界未改变；
- 正式项目继续由 Docker Compose 运行，本轮只用本机已安装环境运行测试，没有为验证重复重启项目。
