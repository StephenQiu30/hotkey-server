# 用户角色与权限管理验收

## 验收结论

004 通过验收。管理员可在统一工作台读取、搜索和筛选用户，调整固定角色与账户状态，并执行会话立即失效的软删除及恢复；非管理员既看不到管理入口，也无法绕过服务端权限边界。最后管理员约束在真实 PostgreSQL 并发竞争下成立，敏感生命周期操作保存完整审计事实。

## 验收标准

| 标准 | 结果 | 证据 |
|---|---|---|
| AC-004-1 | passed | 平台中间件测试覆盖 viewer/editor 访问管理员路由均为 403；真实浏览器 API 验证 editor 读取 `/api/v1/users` 为 403、viewer 写入 `/api/v1/monitors` 为 403。编辑者页面不请求用户列表并隐藏“用户与权限”入口。 |
| AC-004-2 | passed | PostgreSQL 并发测试令两个活跃管理员同时降级，结果严格为一次成功、一次 `LAST_ACTIVE_ADMIN`，提交后仅保留一名活跃管理员；浏览器尝试降级最后管理员得到明确中文错误且数据未变。 |
| AC-004-3 | passed | `agent-browser` 验证 1440 × 900 与 390 × 844 页面、搜索与筛选、角色与状态变更、删除确认、恢复、空态、权限态、Escape 关闭和 Tab/Enter 确认；移动端无整页横向溢出，两种稳定页面 axe 扫描均为 0 violations。 |

## 功能与审计证据

- 页面复用 shadcn/ui 的 Card、Table、Select、Badge、Alert、Skeleton、Empty、Button 和 AlertDialog，提供正常、加载、空、错误、确认和权限不足状态。
- 用户列表按后端稳定 ID 顺序读取；MVP 在前端完成邮箱/显示名称、角色、状态筛选与每页 10 条分页，不新增第二套 API 或 DTO。
- 角色、状态、删除与恢复全部调用 OpenAPI 生成客户端；软删除和禁用会撤销目标活动会话，恢复后保持禁用，需管理员显式启用。
- 成功更新在与业务变更相同的事务和锁顺序内保存 actor、resource、request_id、result 及精确 `role/status` 前后值；失败的最后管理员操作在业务事务回滚后另行保存脱敏失败审计。

## 浏览器验收

使用 `agent-browser` 连接真实 Next.js、Go、PostgreSQL 与 Redis：

- 管理员从账户菜单进入用户工作台，完成角色筛选、角色变更、禁用/启用、软删除、恢复和最后管理员拒绝场景。
- 删除对话框初始焦点位于“取消”，Escape 可关闭；重新打开后 Tab 聚焦“确认删除”，Enter 成功执行。
- 390px 视口下筛选器纵向排列，宽表仅在卡片内部滚动，`document.body` 与根节点宽度均保持 390px。
- 编辑者直达页面只看到权限说明，不发起 `/api/v1/users` 请求；账户菜单不显示管理员入口。
- 管理员桌面与移动页面、关闭弹层后的权限状态页面 axe 均为 0 violations；浏览器无应用 JavaScript 异常。

截图证据保存在本地 `/tmp/hotkey-004-desktop-users.png` 与 `/tmp/hotkey-004-mobile-users.png`，不作为仓库事实源提交。

## 失败、降级与回滚

- 列表加载失败显示可重试错误态；写入失败保留当前行数据并显示服务端安全消息。
- 最后管理员、重复恢复、邮箱冲突与非管理员访问均由服务端拒绝，前端可见性控制不作为安全边界。
- 本条未修改 Schema 或 OpenAPI 契约。回滚管理页面与导航入口后，既有角色、状态、会话和审计事实仍保持可用，不删除历史数据。
