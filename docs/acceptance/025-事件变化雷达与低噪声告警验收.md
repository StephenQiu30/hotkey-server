# 事件变化雷达与低噪声告警验收

- 当前阶段：最终验收完成。
- 准确提交：治理基线 `bf6837d`，初始 RED 契约 `d005a24`，功能与硬化实现 `aab80c8`，最终 Schema 门禁同步 `ae921a0299b007cb591c98f99226da814ff49a8a`。
- 最终结论：`accepted`；服务端 EventUpdate、Radar、Alert 与自动任务闭环满足 PRD-025，前端不在本次范围。

## RED 证据

- `d005a24` 在生产实现前固定 EventUpdate/Radar/Alert 领域、Repository、Worker、HTTP 与 OpenAPI 契约；当时缺少对应表、模块、任务和 API，现有 `GET /api/v1/events` 仅按 ID 升序，无法满足这些测试。
- 实现独立复审确认额外 RED：Radar 仅携带 `as_of` 时可被首屏后的可变投影重排；Radar/Alert 无签名 base64 JSON 游标可被篡改；乱序 occurrence 可覆盖最新线程快照/冷却并使时间倒退；RecordOccurrence 未完整拒绝非法阈值/severity；Alert 详情跨提交读取可能拼接不一致结果。
- 硬化测试先于 GREEN 执行：`TestRadarQueryAndCursorBindSemanticShapeButAllowLimitChanges`、`TestRadarCursorRejectsExpiredOrMalformedFrozenPositions` 首先因缺少冻结位置/过期字段失败；Radar integration 首先因缺少生产签名构造器失败。`TestRecordOccurrenceCommandEnforcesEligibleConsistentScoreFacts` 首先在 NaN threshold、低于阈值与 severity 不一致分支失败；Alert integration 首先因缺少签名构造器失败。
- 最终实现复审又以 `CHANGES_REQUESTED` 暴露唯一 occurrence 修改 count/version 却未使用实际写入时刻推进 `updated_at`；修复测试随后要求 `updated_at >= writeStartedAt`。这些失败均准确证明缺口，没有以既有 GREEN 替代 RED。

  - `go run ./test/runner test -tags=integration ./internal/modules/alert/infrastructure/postgres -count=1`：PASS，覆盖并发幂等、事务回滚、乱序全序、强密钥、签名游标和 REPEATABLE READ。
  - API/Worker/all 三种配置的 bootstrap 启停与路由装配定向测试：PASS；纯 Worker 不依赖 API JWT，API/all 使用强 JWT 派生游标密钥。
- `make openapi-validate`：PASS；生成文档包含 87 条路径，并固定 Radar/Alert enum、范围、BearerAuth、`expected_version >= 1` 与安全公开 DTO。

## 降级与运行时证据

- `TestEventSummaryServiceReturnsRepresentativeFallback` 与 `TestEventSummaryServiceFallsBackAfterSafeProviderFailures` 覆盖空 Registry 及 Provider unavailable/transient/timeout；确定性 EventUpdate、Radar 和 Alert 不调用 LLM，summary 使用安全 reason code 降级。
- `TestHeatHandlerFansOutActionableUpdateBeforeSummary`、`TestHeatHandlerOnlyEnqueuesSummaryWithoutActionableUpdate`、`TestHeatHandlerRetryCompletesFanOutWithoutDuplicateFacts` 证明 Alert/Summary fan-out、失败重放与稳定任务键。
- Fixture 强制要求独立 `HOTKEY_TEST_DSN`/`HOTKEY_TEST_REDIS_URL`，并拒绝与运行目标相同的 PostgreSQL/Redis；本次只使用上述可丢弃实例，未连接或修改开发数据库。

## 协议与失败证据

- `TestRadarRepositoryFiltersAndUsesAllFiveDeterministicOrders` 与领域公式测试证明五种排序、可解释维度及 insufficient=`null`；`TestRadarRepositoryCursorFreezesAsOfAndRejectsAnotherShape` 在首屏后修改 Event/Metric/MonitorEvent/Claim 并插入新事件，后续页仍无遗漏、重复或重排。
- `TestRadarRepositoryRejectsEverySignedCursorPayloadMutationAndExpiry`、`TestRadarRepositoryProductionConstructorUsesAContextDerivedSecret` 与 Top-100 测试证明 HMAC-SHA256、用途隔离、15 分钟过期、形状绑定和冻结上限。
- Alert transport 测试证明 viewer 可 acknowledge/resolve、不可 suppress，editor/admin 可执行三种动作；旧 version、非法状态、未授权与依赖错误映射为稳定 Result，响应不泄露内部原因。
- `TestOutOfOrderOccurrenceOnlyAdvancesCountAndCannotReopen`、`TestRecordOccurrenceCommandEnforcesEligibleConsistentScoreFacts` 与原子回滚测试证明全序推进、实际写入时间、阈值/severity 不变量和失败无部分写入。
- `TestRepositoryUsesCASAuditAndStableListDetailReads` 与 `TestGetReadsThreadOccurrencesAndAuditsFromOneRepeatableReadSnapshot` 证明 Alert 签名游标、CAS/Audit、最近 50 条 occurrence 和详情一致性快照；公开 DTO 不含 Monitor 配置、正文、SQL、fingerprint 或任务 payload。
