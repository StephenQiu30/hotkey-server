## 验收范围与提交

- 当前阶段：实施前验收标准审核。
- 准确提交 SHA：待实现。
- 最终结论：pending。

## RED 证据

- EventUpdate、Radar、Alert 表、模块、任务和 API 当前不存在。
- 现有 `GET /api/v1/events` 只按 ID 升序，不能证明热点或变化排序。
- 具体 RED 命令和失败测试名在 PLAN-025 开工后记录。

## GREEN 证据

- 待记录定向领域、Repository、Worker、Transport、Schema 和 OpenAPI 测试。
- 待记录隔离 PostgreSQL/Redis 的 `make ci`、`git diff --check`、`make clean`。

## 降级与运行时证据

- 待以空 AI Registry Fixture 证明 Radar、EventUpdate 与 Alert 不依赖 AI。
- 当前开发库保持只读，不作为测试 DSN；Fixture 使用可丢弃数据库。

## 协议与失败证据

- 待证明 Radar 公式、`as_of` 冻结、五种排序与跨查询游标拒绝；insufficient confirmation 保持 `null` 分数。
- 待证明 viewer 的 suppress 返回 403，而 acknowledge/resolve 成功；旧 expected version、非法状态、审计失败均为 409/503 且无部分写入。
- 待证明 Alert 详情限制 occurrence 为最近 50 条、audit 完整，响应中无 Monitor 配置、正文、SQL 或任务 payload。
- 待证明 Heat fan-out 对 actionable Update 产生一个 Alert job 和一个 Summary job；cooling/非实质变化只产生 Summary。任一步入队失败重放后仍各至多一个，Alert Worker 终态失败不阻塞 Summary。
- 待记录 occurrence 已插入但 thread/audit 故障的事务回滚、Provider unavailable/transient/timeout fallback，以及 PostgreSQL/Redis 测试目标防误连结果。

## 独立复审

- Plan readiness：独立 Reviewer 已确认 `APPROVED`，无剩余 P0/P1/P2；Heat fan-out 增量再次复核通过。
- 实现复审：待完成。

## 证据落盘门禁

- RED 必须记录准确提交 SHA、命令、失败测试名和能证明缺口的失败信号。
- GREEN 必须记录准确提交 SHA、定向/完整命令摘要、隔离 DSN 与运行 DSN 不同的安全证明、自动创建/清理数据库结果、并发与故障注入结论。
- `make openapi-check`、`make ci`、`git diff --check`、`make clean` 和兼容性回滚演练结果缺一不可；未记录时不得把 Plan/PRD/Acceptance 标记 done/accepted。

## 残余风险

- 多租户、外部告警投递、Signal Snapshot/Evidence 冻结和自动 Analysis 不在本次范围。
