# 微博开放平台关键词来源适配验收

## 验收结论

014 于 2026-08-07 通过验收。HotKey 通过微博官方 CLI API 的固定 `search statuses/limited` 命令采集关键词结果；来源是否可用由当前 Token 的 whoami、开发者/套餐状态和 available 命令目录动态决定。实现没有网页、热搜页、移动接口、Cookie、验证码或私有接口回退。账号时间线未被官方公开示例稳定命名，因此不在本条 MVP 中猜测实现。

## 验收标准

| 标准 | 结果 | 证据 |
|---|---|---|
| AC-014-1 | passed | 新来源强制 disabled；健康探测先验证 whoami，再从 `group=search&access=available` 确认 `statuses/limited`。Token 缺失、401/403/402 或命令锁定均不能启用和采集。 |
| AC-014-2 | passed | Connector fixture 验证固定 invoke 请求、关键词规范化、count/page、数字与字符串 ID、微博时间、作者、转发父 ID、官方链接及点赞/评论/转发指标；游标绑定查询签名，既有内容唯一键保证重试幂等。 |

## 官方依据与已知限制

- [微博开放平台 CLI](https://open.weibo.com/cli/index)说明 OAuth、开发者认证、套餐/额度以及关键词、用户、检索和趋势能力。
- [微博 CLI 使用手册](https://open.weibo.com/cli/manual)说明认证、套餐/试用、命令发现和本地凭据保护。
- [官方 npm 包 @weibo-ai/weibo-cli 0.9.0](https://www.npmjs.com/package/@weibo-ai/weibo-cli)公开生产 API 基址、Bearer 请求、whoami、commands、invoke 契约和 `search statuses/limited --q` 示例。
- [微博开放平台开发者协议](https://open.weibo.com/wiki/开发者协议)是界面固定条款入口。
- 仓库和验收环境没有运营方微博开发者账号、订阅或真实 Token，因此不会对官方生产接口产生计费调用。发布前管理员必须完成认证/套餐/OAuth，设置 env Token，并让健康探测真实通过；fixture 只验证官方公开的请求与响应契约，不能代替运营资质。
- 搜索结果缺失不能证明历史微博已删除；只有上游明确返回删除/不可见提示时才抑制正文。Token 撤销或套餐到期后，下一次健康探测/采集会安全失败，管理员应停用来源。

## 回滚

回滚时先停用所有 `weibo` 来源和调度，再回退应用。Schema 只扩展受控枚举与约束，没有新增表；历史 Content、指标、检查点和 CollectionRun 保留，不通过删除事实回滚。
