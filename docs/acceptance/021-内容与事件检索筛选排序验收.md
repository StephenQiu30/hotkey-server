# 内容与事件检索筛选排序验收

## 验收结论

## 浏览器验收

按用户指定的 `$agent-browser` 连接真实 Next.js、Go、PostgreSQL、Redis 与 MinIO，并使用隔离数据库和合成事实验收：

- Admin 使用关键词、来源、Monitor、最新决定、时间与相关性组合筛选 Content，结果只含符合条件的数据并显示 99/95/93/89 分、已接受与 Event 归属。
- Radar 使用关键词、Monitor、窗口、生命周期、趋势、确认状态、最低 Heat 和五种排序；10 条首页进入冻结第 2 页后只返回剩余 2 条，后退恢复同一 Cursor URL。
- 真实浏览器发现并修复 Axios 将 OpenAPI CSV 数组错误编码为方括号参数的问题；回归测试和资源请求确认最终为 `lifecycle=active&trend=rising`。
- 不存在的关键词显示可清除空态；无效 Cursor 显示本地化参数错误且不清空页面外区域。Viewer 可检索但没有删除或治理控件；匿名访问跳转带安全 redirect 的登录页。
- 1440×900 与 390×844 均无横向溢出；事件桌面、事件移动和内容移动的 axe-core 4.12.1 均为 0 violations、0 incomplete，稳定页无浏览器错误。

## 安全与产品边界

- 搜索仅返回 active、未删除的安全 DTO；不返回 excerpt、正文、对象键、内部解释、SQL 或删除事实。
- Monitor Match 使用每个 Monitor/Content 最新快照；相关性失败不伪装为 latest，Event 归属读取失败只清空可选归属字段。
- `attention` 继续是 Event 重要性/热度；Content 不新增重要性分数，两个范围不伪造成统一混排结果。

## 回滚

先移除页面筛选控件和新增查询参数，再停止相关性/归属投影；保留兼容索引。旧客户端不传参数时仍按 latest 返回 Content、按 momentum 返回 Radar，无需删除或回填业务事实。
