## Schema、API、配置与部署影响

- PostgreSQL 保留 Notification Outbox、User Notification、Read Receipt、Delivery Attempt、Report Revision/ClaimEvidence、Knowledge Revision/Projection 与 Search 投影等稳定事实；
- Vault 自动区域可重建，人工区域只从现存 Vault、Knowledge Revision 或备份恢复；冲突进入 Proposal/Inbox，不静默覆盖；
- 通知、报告、知识和搜索 API 使用统一 Result、生成 OpenAPI 与服务端权限，错误/审计不输出正文、邮件列表、路径、对象键或凭据；
- P0 搜索固定使用 PostgreSQL FTS/Trigram，不新增 Elasticsearch、Embedding、向量或 RAG 依赖；正式项目继续由 Docker Compose 运行。

## 已知限制与停止条件

- `CHK-004-G5-002` 保持未勾选，目标环境资源/积压和批准闭合前 `AC-004-008` 不得改为 `passed`；
- `unknown` 外部交付必须告警并由 Provider 回执对账或批准的人工处置，普通重放不得自动发送；
- 固定 GitHub Runner 的 warm-cache 候选测量不能替代冷缓存、生产同构硬件、流量和外部 Provider 验收。

## 回滚验证

- 应用可回滚到兼容版本，但不得删除通知事实/游标/Attempt、批准 Report Revision、Knowledge Revision、Vault 人工区域或搜索拥有模块事实；
- 自动 Vault 区域和检索投影可从 PostgreSQL 重建，`unknown` Attempt 不得转为未发送或盲重发；
- 回滚后重新执行 Schema/OpenAPI、通知收敛、逐句引用、Vault 对账、搜索权限和真实浏览器主故事。
