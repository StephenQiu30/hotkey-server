## 自动化证据

- Queue 激活测试证明 available 可提前，discarded/cancelled 保留 attempt 与 `river_job_attempt`，只增加一次 max attempt；running/completed/缺失均拒绝。
- `TestCollectionControlRetryAtomicallyRestoresCheckpointAndJob` 使用真实 PostgreSQL、River Store 和 `Worker.RunOnce`，验证 checkpoint 恢复、job available、历史保留及 retry run 最终 succeeded。
- advanced checkpoint、任意较新 run、完整 eligible target 集合、hook 失败均验证整笔事务回滚。
- 两个并发 Retry 只有一个成功。
- `TestCollectionClaimSerializesRetryAndNewerWorker` 从失败后真实 checkpoint 构造 newer request，并通过隔离测试库 `pg_locks` 中未授予 advisory lock 证明竞争已发生；Retry 先赢时无 phantom run，Worker 先赢时新窗口成功且旧 Retry 冲突。连续运行 5 次通过。
- Published Target Reader 在调用者事务内读取未提交的 checkpoint 恢复值；Operations 的按 job ID 重试仍保持 attempt 归零的独立治理语义。
- `make lint`、带隔离 PostgreSQL/Redis 的 `make test`、`make build`、`make validate`、`git diff --check` 和 `make clean` 均通过。

## 浏览器与运行时证据

真实页面点击失效目标的失败批次重试，`POST /api/v1/collection-runs/1/retry` 返回 409，并展示“采集任务状态已发生变化，请刷新后重试”。随后数据库仍保持 run=`failed`、target=`failed`、River job=`discarded` 且 attempt/max_attempts 不变，证明失败路径没有部分提交。产品级截图与完整页面验收记录位于仓库外 QA 交付目录 `qa-output/2026-08-01-hotkey/`。

## 独立复审

独立 Reviewer 首轮识别多目标 run 只验证“至少一个 target 有效”的 P1 孤儿批次风险，并要求移除可绕过队列激活的旧入口；修复后再次指出 newer Worker 测试不够确定。最终实现以完整目标身份集合比较、nil hook 拒绝和双向真实 advisory lock 竞争测试关闭全部问题，结论 `APPROVED`，无剩余 P0/P1/P2。

## 最终结论

`accepted`。PRD-024 的原子性、幂等、并发、恢复、失败回滚和 Worker 可执行性均有自动化或真实页面证据；River 终态任务若已被保留策略清理仍按稳定冲突返回，这是设计内明确残余风险，不重建丢失任务。
