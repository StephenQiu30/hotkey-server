## 浏览器验收

按用户指定的 `$agent-browser` 连接真实 Next.js、Go、PostgreSQL 与 Redis，并使用隔离数据验收：

- Admin 在事件页看到 Heat 88、趋势 32/rising、六维组成和“互动不可用且未按 0 分处理”的解释；Update、Intelligence、Heat、Members 四个请求均返回 200。
- 真实成员锁定请求成功并更新成员状态；`closed → archived` 成功，Archived、Rejected、Merged 终态不再提供治理操作。
- 真实拆分后数据库与页面均只保留未拆成员；真实合并后源事件为 Merged、成员迁移到目标事件，目标选择不包含 Archived、Rejected 或 Merged 事件。
- Viewer 能读取成员事实但没有锁定或 Admin 操作；匿名访问跳转 `/login?redirect=%2Fdashboard%2Fevents`。
- 桌面 1440px 与移动 390×844 均无横向溢出；正常态、空态、Radar 局部错误态的 axe-core 4.12.1 均为 0 violations、0 incomplete，页面错误日志为空。

桌面、移动、空态、错误态和治理截图保存在本地 `/tmp/hotkey-020-acceptance/`，不进入仓库。

## 安全与产品边界

- 生命周期、趋势和 Heat 六维各自使用后端事实；前端不重算分数，也不把缺失指标解释为 0。
- 所有治理写操作使用生成 Client、expected version、RBAC 和确认门禁；失败不乐观伪造成功状态。
- 页面不暴露原始指标序列、Provider payload、对象键、凭据、内部 SQL 或审计 metadata。

## 回滚

回滚先移除事件页治理与 Heat 组成投影，再停止写入 `component_scores`；兼容列及历史 JSON 保留，无需删除或回填事件、成员、快照、更新和审计事实。`closed → archived` 生命周期边可独立回退。
