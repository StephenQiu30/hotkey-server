# 定时监听、手动搜索与失败重试验收

## 验收结论

017 于 2026-08-07 通过验收。HotKey 保留既有自动调度主链路，并为 active published 监控补齐 Editor/Admin“立即搜索”：请求只按服务端事实提交 `collect_source` 持久任务，同一来源/查询在五分钟 UTC 桶内原子复用。手动 Worker 重读当前发布目标，运行事实保存 `trigger_type=manual`，成功后进入现有 `normalize_content` 链路。Editor/Admin 可查看批次，仅 Admin 可原子重试仍有效的失败窗口。

## 浏览器验收

使用用户指定的 `$agent-browser` 连接真实 Next.js、Go、PostgreSQL、Redis 与 MinIO，全程使用本地验收数据和 fake Connector 自动化，不执行真实第三方采集：

- Admin 发布 active 监控后出现“立即搜索”；第一次返回新建 1、复用 0，第二次返回新建 0、复用 1，并显示冷却时间。
- Editor 同样可触发并查看批次，但失败运行没有重试按钮；Viewer 只可查看监控详情，不出现手动搜索或批次控制操作。
- Admin 对具备原持久任务的 failed 批次执行重试，API 返回 200，运行恢复为 queued 且类型为 retry；不再符合条件的历史窗口返回 409，不污染新配置。
- 未认证访问 `/dashboard/settings` 跳转到带 redirect 的登录页。
- 390×844 下 `scrollWidth=clientWidth=390`，无横向溢出。
- 浏览器验收发现失败错误码的 `text-red-400` 对比度不足；改为语义化 `text-destructive` 后，相关 Admin、Editor、Viewer、匿名和移动页面 axe-core 4.12.1 均为 0 violations、0 incomplete。
- 页面错误为空；控制台只有 Next.js 开发环境的 React DevTools 与 HMR 信息。

截图、视频和 dogfood 报告保存在本地 `/tmp/hotkey-017-acceptance/`，不作为仓库事实源提交。

## 安全与数据边界

- 手动 API 只接受监控 ID，不接受 URL、查询正文、来源、窗口、游标或 Connector 参数。
- 队列仍是有界的 ID/版本/哈希信封，只增加固定枚举 trigger type；响应只返回数量和冷却时间。
- 数据库唯一约束负责并发幂等，前端禁用态和事务 advisory lock 不替代事实约束。
- 测试账号、临时端口、浏览器状态、截图、视频和验收数据库均未进入提交。

## 回滚

回滚先隐藏“立即搜索”和 Editor 批次入口，撤销手动路由，再回退 Worker 对可选 trigger type 的处理。该条不新增表或迁移；既有自动任务、检查点、CollectionRun、内容和管理员重试数据可继续保留。
