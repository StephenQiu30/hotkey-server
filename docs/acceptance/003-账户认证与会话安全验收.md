# 账户认证与会话安全验收

## 验收结论

003 通过验收。注册、邮箱验证、登录、找回与修改密码、短期访问令牌、刷新令牌轮换、会话撤销和退出已形成完整闭环。前端访问令牌与身份信息只保存在运行内存，页面重载与浏览器重启只通过服务端管理的持久 HttpOnly 刷新 Cookie 恢复；Access Token 会在到期前续期，同一浏览器的多标签页刷新通过 Web Locks 串行执行。未认证与过期会话保留经过白名单校验的控制台回跳地址。

## 验收标准

| 标准 | 结果 | 证据 |
|---|---|---|
| AC-003-1 | passed | 真实登录响应设置路径为 `/api/v1/auth`、`Max-Age=604800`、`HttpOnly`、`SameSite=Strict` 的刷新 Cookie；浏览器中 `document.cookie`、localStorage 和 sessionStorage 均不含认证数据，页面重载与浏览器重启仍可通过 Cookie 恢复。生产配置拒绝未启用 Secure 的刷新 Cookie。 |
| AC-003-2 | passed | Redis 验证存储测试覆盖 HMAC 摘要、过期、单次消费、重复验证码和并发消费；PostgreSQL 会话测试覆盖单赢家轮换、重放后整族撤销、并发重放与绝对过期；应用集成测试确认旧访问令牌同步失效。 |
| AC-003-3 | passed | 未登录访问 `/dashboard/events?status=active` 被送往编码后的登录回跳地址，登录后返回原页面和查询参数；绝对 URL、协议相对 URL、反斜杠路径及非控制台路径均回落 `/dashboard`。 |

身份模块专项测试覆盖 domain、application、PostgreSQL、Redis、密码/JWT、SMTP、HTTP Transport 和平台认证中间件。前端新增内存令牌、Cookie 恢复、安全回跳、外链拒绝和 AuthGuard 行为测试；完整前端测试共 35 个文件、119 个用例，Next.js 生产构建产出 19 个路由。

## 浏览器验收

使用 `agent-browser` 对真实 Next.js、Go、PostgreSQL 与 Redis 链路完成桌面和 390 × 844 移动验收：

- 未认证访问事件页会保留路径及查询参数，成功登录后准确回跳。
- 登录 Cookie 在匹配的 API 路径可见为 `HttpOnly=true`、`SameSite=Strict`、`Max-Age=604800`；开发 HTTP 环境按配置使用 `Secure=false`，生产环境由启动校验强制 `Secure=true`。
- `document.cookie`、localStorage 与 sessionStorage 均为空；重载页面后身份通过刷新 Cookie 恢复。
- 恶意外部回跳地址登录后只进入 `/dashboard`，未发生开放重定向。
- 退出后返回登录页且刷新 Cookie 被清除。
- 登录页与恢复后的事件页执行 WCAG 2 A/AA axe 扫描均为 0 violations；浏览器无应用 JavaScript 异常。

## 失败、降级与回滚

- Redis 或数据库不可用时，认证接口返回稳定服务不可用错误，不把基础设施故障伪装成无效凭据。
- 刷新失败会清除内存令牌并跳转登录，同时保留安全控制台回跳；单标签页并发请求共享一次刷新，多标签页通过浏览器级互斥锁串行轮换刷新 Cookie。
- 本条未修改 Schema 或 OpenAPI。回滚前端内存会话与安全回跳变更即可；既有数据库会话、验证记录和审计事实无需迁移或删除。
