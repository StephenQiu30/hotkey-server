# 实时事件流与站内通知设计

## 现状

参考项目使用 Socket.io 推送新热点；当前 HotKey 有持久告警事实和通知页面，但主要依赖请求刷新，没有统一实时传输通道。

## 目标

当采集运行、事件更新、告警或报告状态变化时，已登录用户无需刷新即可收到可恢复的站内更新。

## 非目标

不在本条复制相邻领域的数据或服务，不以纯前端假数据宣称功能完成，也不引入第二套事实源。

## 核心决策

- MVP 使用单向 authenticated SSE，而非引入 Socket.io/双向 WebSocket；所有业务动作仍走普通 HTTP API。
- 事件从持久 outbox/audit fact 投影，包含 event_id、type、resource_id、occurred_at 和最小展示 payload。
- 客户端保存 Last-Event-ID，断线指数退避并补拉缺口；实时消息只提示变化，详情仍从正式 API 获取。
- 按用户角色和资源范围过滤；心跳不包含业务数据，代理缓冲和连接上限可配置。

## 数据、接口与交互

- 认证 SSE 端点
- 事件类型与持久游标
- 客户端重连、补拉和 Toast/徽标
- 采集、事件、告警、报告通知

所有状态变化保存明确版本、时间和操作者；跨端字段由 Schema、后端 DTO 和生成 OpenAPI 驱动，前端不得手写重复类型。

## 安全、失败与降级

直接从内存广播会在多实例或重启时丢事件；必须由持久事实恢复。

外部 AI、邮件、实时连接或归档不可用时，业务事实先可靠落库，异步重试或降级读取，不在请求链路丢失结果。

## 设计验收边界

- 断线重连后不漏关键通知且允许幂等重复
- viewer 收不到管理员运行诊断
- SSE 不可用时轮询降级保持功能可用
