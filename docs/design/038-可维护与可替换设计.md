# 可维护与可替换设计

日期：2026-09-21。本版只冻结 038 S00—S01：建立不依赖平台 SDK、ORM、HTTP 或 Worker 的来源能力契约，供 X 和国内来源后续适配。本版不实现真实适配器、版本/许可登记、固定样本仓库、真实探针或替换回退。

## 1. 当前事实与问题

- 当前仓库尚无 `sources/` 领域或真实来源适配器；`evidence` 已持久化来源准入政策，但其 `SourceCapability` 枚举不应继续成为来源契约的事实源。
- 001 Design 已确定 `sources` 只拥有纯能力契约和平台适配器，无 ORM，不决定事件归属或持久业务事实。
- 如果各适配器自行解释缺失数值、父评论、空结果和限流，上游字段改名会被静默转成错误业务事实。

## 2. 目标与非目标

### 2.1 S01 目标

1. 以一个纯 Python 契约包统一 `search`、`author_posts`、`comments`、`replies` 四种请求。
2. 作品与评论统一输出稳定外部 ID、作者、发布时间、正文、互动计数和父子关系；缺失值必须显式为 `None`，不补 0。
3. 分页结果明确区分继续、完成、空结果、部分结果和停止，并保留稳定停止原因。
4. 适配器通过 Python `Protocol` 满足结构化静态类型，不要求继承框架基类。

### 2.2 非目标

- 不实现通用插件注册器、动态代码加载、适配器工厂或全局 repository。
- 不把 ActivityStreams 全量词汇复制进产品；只借用稳定 ID、`attributedTo`、`published` 和 `inReplyTo` 的最小语义。
- 不实现网络请求、持久化、任务派发、预算扣减、删除传播、HTTP 或界面。

## 3. 选型与核心决策

| 决策 | 结论 | 理由 |
|---|---|---|
| DTO | 复用已锁定的 Pydantic 2，使用 `extra="forbid"`、`frozen=True`、`strict=True` | 同时提供运行时边界验证和 mypy 类型，不新增序列化/验证库。Pydantic 官方将 `extra` 和 `frozen` 作为 `ConfigDict` 能力提供：[Config](https://docs.pydantic.dev/latest/api/config/)。 |
| 适配器端口 | 非 `runtime_checkable` 的 `typing.Protocol` | Python 官方说明 `Protocol` 支持结构子类；运行时检查只检查成员存在，不检查签名，因此本项使用 mypy 与行为测试：[typing.Protocol](https://docs.python.org/3/library/typing.html#typing.Protocol)。 |
| 请求 | 四种能力使用受判别联合，共享显式有界 `page_size`、可选 `page_token` 与 `watermark` | 避免一个含多个可选目标的模糊请求；后续页必须保持 token 以外的查询语义。 |
| 分页 | token 对业务层不透明、URL-safe，空 token 不允许；只表示继续位置，不承载授权 | Google AIP-158 要求 page token 不透明且不用作授权，结束时不返回 next token：[Pagination](https://google.aip.dev/158)。 |
| 社交对象 | 只定义 `post` 与 `comment`；评论显式持有作品 ID 及可空父评论 ID | W3C ActivityStreams 将 ID、`attributedTo`、`published` 和 `inReplyTo` 定义为通用社交对象语义：[Activity Vocabulary](https://www.w3.org/TR/activitystreams-vocabulary/)。 |

## 4. 契约与不变式

### 4.1 能力请求

| 能力 | 必需输入 | 语义 |
|---|---|---|
| `search` | `query` | 来源支持的公开搜索条件，不在契约层拆分或改写用户语义。 |
| `author_posts` | `author_external_id` | 指定来源作者的作品集合。 |
| `comments` | `post_external_id` | 指定作品的顶层评论或平台返回的评论页。 |
| `replies` | `comment_external_id` | 指定父评论的回复集合。 |

所有请求必须显式给出 `source_key` 和 1—100 的 `page_size`。`page_token` 与 `watermark` 只是来源适配器生成的不透明继续标记；用户输入、凭据、Cookie 和正文不得编码进 token。

### 4.2 统一对象

- `SourcePost`：显式包含来源、稳定作品 ID、可空作者 ID/发布时间/正文，以及必须显式给出的可空点赞、评论和转发数。
- `SourceComment`：显式包含来源、稳定评论 ID、所属作品 ID、必须显式给出的可空父评论 ID，以及可空作者/时间/正文/点赞数。
- 所有可空字段都是“已映射但来源未提供”；字段缺席是契约错误。这使上游将 `like_count` 或父评论字段改名时不会被 Pydantic 默认值静默掩盖。
- 时间如果存在必须带时区；计数如果存在必须非负；稳定 ID 不接受空白、首尾空格或控制字符。

### 4.3 页状态

| 状态 | 不变式 |
|---|---|
| `more` | 必须有 `next_page_token`，不得有停止原因；来源可返回暂时空页。 |
| `complete` | 必须有至少一项，无 next token，原因固定为 `end_of_results`。 |
| `empty` | 必须无项、无 next token，原因固定为 `source_empty`。 |
| `partial` | 必须保留至少一项，并明示限流、预算耗尽、上游错误或协议错误；可有可继续 token。 |
| `stopped` | 必须无项、无 next token，并明示无权、未支持、取消、限流、预算耗尽、上游错误或协议错误。 |

`watermark` 与 `next_page_token` 分离：前者表示增量边界，后者只表示同一次查询的下一页。结果的 `observed_at` 必须带时区。
每页同时声明 `source_key` 与 `capability`，页内项必须属于同一来源；`search`/`author_posts` 只返回作品，`comments`/`replies` 只返回评论。不同来源或错误对象类型不能在后续业务层被默默接受。

## 5. 模块与依赖方向

```text
evidence / future content / future jobs
                 │
                 ▼
        sources/contracts.py
                 ▲
                 │
     future sources/adapters/*
```

- `backend/app/sources/contracts.py` 是能力枚举、请求、统一对象、页结果与适配器端口的唯一事实源。
- `sources` 只可依赖标准库与 Pydantic；不依赖 `api`、`db`、`evidence`、`jobs`、`worker`、SQLAlchemy、FastAPI、HTTPX 或平台 SDK。
- `evidence.schemas` 改为从 `sources.contracts` 导入 `SourceCapability`，不保留平行枚举。
- S01 不创建 `sources/adapters/` 空目录；首个真实适配器只在其所属切片证明职责后落地。

## 6. API、任务、持久化与界面

S01 没有 HTTP/OpenAPI、Worker/Kafka、Redis、PostgreSQL/schema.sql、MinIO、Web 或 Flutter 变更。适配器端口是内部同步调用契约；真实执行必须由后续 Worker 用例在预算、撤权、删除和取消门禁后调用，不从浏览页面直接发网络。

## 7. 安全、失败与兼容

- DTO 不承载 owner、凭据、Cookie、授权头或原始异常；这些由后续装配层按运行边界处理。
- 未支持能力、需重新认证、无权、目标不存在、限流、预算耗尽、取消、上游错误和协议错误使用稳定枚举，不把 SDK 异常文本当业务状态。
- 新增可选字段可按兼容规则评审；删除/改义现有字段、改变缺失值或停止状态是不兼容变更，必须更新 Design 与固定样本。
- S01 无数据迁移和运行启用项；回退本提交只移除新契约并恢复 `evidence` 枚举定义，不影响持久数据。

## 8. 验证和证据边界

S01 使用单元测试覆盖：四种请求的必需输入、不透明 token、显式 `None` 而非缺席/补 0、父评论关系、时区/计数、五类页状态和结构化适配器。架构测试强制 `sources` 纯依赖边界；Ruff、mypy 和后端全量 pytest 防止回归。

S01 不涉及真实依赖，因此 PostgreSQL/Redis/Kafka/MinIO 专项集成测试 N/A；仍使用现有 `.env` 执行后端全量回归，但不用该回归冒充真实来源证据。无 HTTP/UI 变更，OpenAPI 生成和浏览器验证 N/A。

S01 通过只能证明内部契约可表达且拒绝部分静默语义偏移。它不证明任一适配器已实现、任一来源可访问、样本契约已通过、版本/许可已核查、可回退或任一产品 AC 已通过。038 保持 `in_progress`，不创建 Acceptance。

## 9. 待后续切片关闭

`OPEN-038-001` 在 S01 只关闭统一 DTO 和分页/停止契约部分。首批组件、固定版本/提交、许可范围、脱敏样本文件格式、合法真实探针和维护责任人仍由 S02 在实际候选和授权条件到位后冻结；升级/回退与替换演练留在 S03。
