# 29 登录与验证注册

对应 [29-登录与验证注册](../requirement/29-登录与验证注册.md)；实施拆分见 [29-登录与验证注册](../plan/29-登录与验证注册.md)。需求为范围依据，本文件不表示功能已实现；进度只在仓库根目录BACKLOG。

## 设计目标

登录后进入个人监控工作区，已登录用户返回安全的目标页面。

## 结构与交互

- 登录通过同一Dialog覆盖当前页面；直接/login以首页为背景，安全目标在成功后继续；保留Figma表单内容，不恢复独立整页跳转。
- 保留已有账号密码登录，仅展示服务器公布已配置的方式（密码、邮箱验证码、GitHub）；注册先验证邮箱或GitHub身份，再建立用户名密码；OAuth返回白名单，失败保留输入但不持久存密码。

### 区域与显示边界

下面保留需求定义的区域和数量；必需字段、操作语义和业务约束以同编号需求表为准，不另建字段字典。

|---|---|

| 账号登录 | 一次提交 |
| 邮箱验证 | 一次challenge |
| GitHub | 仅配置启用时出现 |

## 数据与复用边界

先核对现有入口：[frontend/src/components/auth](../../frontend/src/components/auth)、[backend/app/api/routers/identity.py](../../backend/app/api/routers/identity.py)。入口存在只代表可核对，不能据此宣称真实能力已验收。

优先复用现有业务身份、版本、服务与组件；展示派生值、本机阅读状态和持久事实分别处理。新字段仅在同编号需求有实际消费路径时补齐，接口/数据库的唯一合同仍在代码及schema。

## 状态与核对重点

Esc/遮罩关闭、焦点和滚动恢复、恶意return目标、验证前注册拒绝及会话故障。

读写状态使用真实回执；已有数据刷新失败保留可读内容并标过期，未知写入先核对结果。正常、空、加载、错误、无权限以及键盘行为按实际交互覆盖；静态内容无远程状态时标不适用。

视觉、组件与响应式沿用 [00-产品目标与边界](../design/00-产品目标与边界.md)；跨页状态沿用 [11-质量评测与验收](../design/11-质量评测与验收.md)；权限、安全渲染和许可沿用 [10-权限与数据生命周期](../design/10-权限与数据生命周期.md)。

## 登录弹窗与配置入口

首页、侧栏及手机导航中明确提供设置关键词和平台接入。登录以Dialog覆盖当前页面，关闭、Esc与遮罩可继续阅读，恢复触发焦点，不清空筛选或滚动位置。/login兼容外部跳转与会话恢复，以首页为背景展示同一弹窗；登录成功继续安全目标。平台选择只依据实际搜索能力与连接状态，保留不可选原因及接入入口。
