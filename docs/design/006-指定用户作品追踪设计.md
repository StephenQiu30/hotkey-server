# 指定用户作品追踪设计

日期：2026-09-23。本版只接受 S00 与 S01 的 X 身份解析离线子片；关注关系、持久追踪、HTTP/Web、调度、真实来源及 AC-006-001—006 均未完成。没有开发者 App/Token 和用户指定的账期美元上限时，任何 X 请求都不得发出。

## 1. 现状、目标与非目标

- 002 的 `XApiAdapter` 已用 `httpx.MockTransport` 离线验证按稳定作者 ID 获取作品及引用/转帖目标 ID；它未注册真实 X 处理器。007 已持久化作品的 `author_external_id`，并将 quote/repost 目标关系与当前作品作者分开。004/009/037 已有连接、任务和免费预算的内部先行输出，但 037 的 X 唯一付费例外及账期金额门禁尚未装配。
- 本片先固定“输入主页或 @handle → 官方 User Lookup 的稳定 user ID → 用户显式确认”的身份边界。用户名、展示名、粉丝数和主页 URL 只作候选证据与可变别名；未来关注主键必须包含 owner、source_key 与稳定 user ID，不因改名或同名自动改绑。
- 本次只实现 X 的严格本地输入解析、官方单用户 Lookup 的模拟传输和结果校验，不创建关注表、任务、API、UI、凭据文件、代理规则或第二套依赖。其他平台身份解析仍待各自来源准入；X 账号页及跨来源候选不是本片承诺。

## 2. 一手依据与复用

| 依据 | 本片结论 |
|---|---|
| [X User Lookup](https://docs.x.com/x-api/users/lookup/introduction) 与 [单用户名端点](https://docs.x.com/x-api/users/get-user-by-username) | 官方 `GET /2/users/by/username/{username}` 可返回 `id`、`username`、`name`。只取这三个身份字段；不请求粉丝数或简介，不用展示名代替 ID。 |
| [X 用户名规则](https://help.x.com/en/managing-your-account/change-x-handle) | 公开用户名由字母、数字与下划线组成，最长 15 个字符；展示名独立且可变。输入允许短于现行新建下限的历史账号，最终以官方 Lookup 结果为准。 |
| [X API 费用](https://docs.x.com/x-api/getting-started/pricing) | User Read 属按返回资源计费，当前公开标价不能代替 Developer Console 的实际费率。即使只是“解析主页”，真实调用也必须先经 037 的按请求及最坏 1 个 User 资源预留、账期硬上限与费用核对。 |
| [002 官方 API 适配器](002-X免费采集与热点监控设计.md)、[007 作品设计](007-作品资料与上下文设计.md) | 复用现有 `sources` 纯适配器边界、`SourceStopReason`、作品作者字段与关系模型；不另建 User 数据库或复制作品作者。 |

## 3. 身份及离线契约

本地只接受 `@handle`、裸 handle 或 `https://x.com/handle`（含 `www` 与末尾 `/`）。URL 必须 HTTPS、X 官方域名、单一路径段，无 userinfo、非默认端口、query 或 fragment；不跟随跳转，也不请求主页。handle 为 1—15 个 ASCII 字母、数字或下划线，拒绝 X 站内导航路径。若 X 改变用户名规则，需先更新依据和测试，不能静默截断或猜测。输入不记录到日志。

离线 Lookup 只接受 `MockTransport` 和测试用 Bearer 值；一次调用最多一次 GET、最多返回一个 User。不提供传入任意 URL 或生产 HTTP transport 的构造路径。调用方必须在请求前批准 1 次请求和最坏 1 个 User 返回，有效成功后按 1 个 User 结算；响应/传输异常按未知用量保守结算。拒绝预算时零请求。保留 `not_found`、认证/权限/限流、上游/协议失败的明确停止原因；无 User 的响应不是已确认身份。限流不自动重试。响应上限、超时及不跟随重定向沿用 002 的保守边界。

候选结果只包含 `source_key=x`、官方稳定 user ID、官方 username 与展示 name；上游额外字段忽略且不持久化。返回 ID 必须为 X 数字字符串，username 必须为安全 handle；用户名和 URL 的大小写只用于展示/查询，不作为身份相等的依据。响应中 `errors`、缺失/不合法身份、非单对象或重定向都不能冒充成功。X 官方用户名 Lookup 不是模糊搜索：相同展示名候选的选择流程留待完整 S01，不能把 Lookup 的唯一返回解释为已获用户确认。

## 4. 后续领域与交互边界

完整 S01 需要在 `monitors` 管 owner 下 `(source_key, stable_user_id)` 的关注关系与别名历史，API 依现有会话/CSRF/046 错误及运行时 OpenAPI 装配，前端 `app/accounts/` 用生成客户端展示候选并显式确认。输入解析和 Lookup 属来源调用；保存关注属于 `monitors` 事务，不能由 `sources` 写 ORM。未完成来源/费用门禁前不提供会使用户误以为可运行的按钮、路由或 Worker 注册。默认关键词关闭；评论开关只创建后续 008 的合法任务，不隐式外采。

按已确认稳定 ID 请求作者作品；`SourcePost.author_external_id` 是当前作品作者，`quote_external_id`/`repost_external_id` 是目标作品 ID，目标作者只能来自其自身来源证据，不能从目标关系反推。当前作品作者不等于关注 ID 时拒绝归为该账号的新作。无关键词新作先属于账号列表；事件关联归其他计划。置顶、旧帖重排与改名不得凭观察顺序推进“新作”水位；首次回填与新作按 010 的 `scan_kind`/已证实范围区分。S02/S03 仍待真实端点和产品切片设计。

## 5. 冻结样本、验证与停止条件

S01 离线样本 v1：`@small` 与 `https://x.com/small/` 指向相同 ID；相同展示名的两个不同 ID 不可自动互换；同一 ID 改用户名保持身份；无数据、401、403、404、429、500、302、错误结构/超大正文；预算拒绝零请求、成功 1 User 和异常未知结算。测试仅使用 MockTransport，断言请求仅访问官方固定主机、无跟随跳转、无附加 `user.fields`、不泄漏 token/原始输入。后续 S01/S02 再加引用/转帖、无词新作、置顶/回填与 owner/版本/停用的真实 PostgreSQL/浏览器样本。

文件：`backend/app/sources/adapters/x_user_lookup.py` 仅 X 解析与纯适配；`backend/tests/unit/test_x_user_lookup.py` 为红绿证据；本次不改 schema.sql、OpenAPI、Web 或 Compose。执行 `uv run pytest tests/unit/test_x_user_lookup.py`、后端全量 pytest、Ruff、format、mypy 与架构测试。无数据库/消息/浏览器变更，相关门禁本片不适用；不能以模拟通过填产品 AC。

`OPEN-006-001` 的“首轮 50 件、7 天、60 分钟”仍是 PRD 建议：无已授权真实作者样本、端点可用性和已确认费用上限时不设产品默认，也不自动启动首次回填。后续真实解析/采集必须先完成 002 S01b、037 paid 门禁和 004 连接状态，核对 Developer Console 当期费率/权限并做逐能力实测；未通过则维持 `not_connected`。本片零持久变更，无迁移；回退只撤销未接线的纯适配器。日志、错误和审计不可写入 handle、URL、Token 或平台响应正文。
