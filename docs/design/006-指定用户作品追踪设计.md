# 指定用户作品追踪设计

日期：2026-09-25。本版接受 S00、S01 的 X 身份解析离线子片，以及来源无关的账号稳定身份/别名本地持久化子片和观测时间单调性修正；完整身份确认交互、HTTP/Web、调度、真实来源及 AC-006-001—006 均未完成。没有开发者 App/Token 和用户指定的账期美元上限时，任何 X 请求都不得发出。

## 1. 现状、目标与非目标

- 002 的 `XApiAdapter` 已用 `httpx.MockTransport` 离线验证按稳定作者 ID 获取作品及引用/转帖目标 ID；它未注册真实 X 处理器。007 已持久化作品的 `author_external_id`，并将 quote/repost 目标关系与当前作品作者分开。004/009/037 已有连接、任务和免费预算的内部先行输出，但 037 的 X 唯一付费例外及账期金额门禁尚未装配。
- 本片先固定“输入主页或 @handle → 官方 User Lookup 的稳定 user ID → 用户显式确认”的身份边界。用户名、展示名、粉丝数和主页 URL 只作候选证据与可变别名；未来关注主键必须包含 owner、source_key 与稳定 user ID，不因改名或同名自动改绑。
- 当前离线范围在 Lookup 之后增加一个独立存储子片：只将调用方已确认的稳定身份写入 owner 隔离的账号登记与别名历史；它不发起来源请求，不代表来源已就绪或关注追踪已运行。其他平台的解析/授权仍待各自准入。
- 本子片不增加任务、HTTP API、UI、凭据文件、代理规则、Worker 或服务依赖；账号启停、采集配置、候选确认界面、作品追踪和真实来源仍留在完整 S01—S04。

## 2. 一手依据与复用

## 3. 身份及离线契约

本地只接受 `@handle`、裸 handle 或 `https://x.com/handle`（含 `www` 与末尾 `/`）。URL 必须 HTTPS、X 官方域名、单一路径段，无 userinfo、非默认端口、query 或 fragment；不跟随跳转，也不请求主页。handle 为 1—15 个 ASCII 字母、数字或下划线，拒绝 X 站内导航路径。若 X 改变用户名规则，需先更新依据和测试，不能静默截断或猜测。输入不记录到日志。

离线 Lookup 只接受 `MockTransport` 和测试用 Bearer 值；一次调用最多一次 GET、最多返回一个 User。不提供传入任意 URL 或生产 HTTP transport 的构造路径。调用方必须在请求前批准 1 次请求和最坏 1 个 User 返回，有效成功后按 1 个 User 结算；响应/传输异常按未知用量保守结算。拒绝预算时零请求。保留 `not_found`、认证/权限/限流、上游/协议失败的明确停止原因；无 User 的响应不是已确认身份。限流不自动重试。响应上限、超时及不跟随重定向沿用 002 的保守边界。

候选结果只包含 `source_key=x`、官方稳定 user ID、官方 username 与展示 name；上游额外字段忽略且不持久化。返回 ID 必须为 X 数字字符串，username 必须为安全 handle；用户名和 URL 的大小写只用于展示/查询，不作为身份相等的依据。响应中 `errors`、缺失/不合法身份、非单对象或重定向都不能冒充成功。X 官方用户名 Lookup 不是模糊搜索：相同展示名候选的选择流程留待完整 S01，不能把 Lookup 的唯一返回解释为已获用户确认。

S01 离线补片按已保存的数字 user ID 调用 `GET /2/users/{id}`；请求 ID 在预算回调前验证，响应 ID 必须与请求 ID 完全一致。查询返回的新 username 只表示可变别名，不能更换稳定 ID；旧 handle 404 或被另一个 ID 占用时，不回退为用户名重新绑定。两种 Lookup 复用同一单请求、最坏 1 User、模拟传输与停止原因契约，不新增目录或真实出口。

## 4. 后续领域与交互边界

离线存储子片在 `monitors` 中以 `FollowedAccount(owner_id, source_key, external_id, display_name, created_at, updated_at)` 登记身份，并以 `(owner_id, source_key, external_id)` 唯一约束稳定身份；`FollowedAccountAlias(owner_id, account_id, alias_value, first_seen_at, last_seen_at)` 保留别名观测历史。再次记录同一稳定身份只更新当前展示名/更新时间，并对重复别名更新 `last_seen_at`；同一别名出现在不同稳定 ID 下时保留多个身份候选，禁止仅凭别名自动合并或改绑。`display_name` 只保留最近观测值，不建立展示名历史。读取服务始终按 owner 过滤。此表不包含任务/启停状态，不能据此声称账号可采集。

重复确认时，`updated_at` 与已存在别名的 `last_seen_at` 取当前持久值和本次观察时间中的较晚 UTC 时刻，避免系统时钟回拨使观察时间倒退；`first_seen_at` 不变。此规则不新增字段、DDL 或外部请求。

完整 S01 还需要在该持久模型之上完成候选确认、关注配置与生命周期；API 依现有会话/CSRF/046 错误及运行时 OpenAPI 装配，前端 `app/accounts/` 用生成客户端展示候选并显式确认。输入解析和 Lookup 属来源调用；保存关注属于 `monitors` 事务，不能由 `sources` 写 ORM。未完成来源/费用门禁前不提供会使用户误以为可运行的按钮、路由或 Worker 注册。默认关键词关闭；评论开关只创建后续 008 的合法任务，不隐式外采。

按已确认稳定 ID 请求作者作品；`SourcePost.author_external_id` 是当前作品作者，`quote_external_id`/`repost_external_id` 是目标作品 ID，目标作者只能来自其自身来源证据，不能从目标关系反推。当前作品作者不等于关注 ID 时拒绝归为该账号的新作。无关键词新作先属于账号列表；事件关联归其他计划。置顶、旧帖重排与改名不得凭观察顺序推进“新作”水位；首次回填与新作按 010 的 `scan_kind`/已证实范围区分。S02/S03 仍待真实端点和产品切片设计。

## 5. 冻结样本、验证与停止条件

S01 离线样本 v1：`@small` 与 `https://x.com/small/` 指向相同 ID；相同展示名的两个不同 ID 不可自动互换；同一 ID 改用户名保持身份；无数据、401、403、404、429、500、302、错误结构/超大正文；预算拒绝零请求、成功 1 User 和异常未知结算。v2 增加已确认 ID 的改名回查、旧 handle 被另一 ID 占用、响应 ID 不匹配与非法 ID 零请求。测试仅使用 MockTransport，断言请求仅访问官方固定主机、无跟随跳转、无附加 `user.fields`、不泄漏 token/原始输入。后续 S01/S02 再加引用/转帖、无词新作、置顶/回填与 owner/版本/停用的真实 PostgreSQL/浏览器样本。

离线存储样本使用合成 `(owner, source_key=x, external_id=1001)`：`small` 改名为 `small_new` 后 stable ID 不变且两条别名观测保留；另一个 `external_id=2002` 重用 `small` 时查询必须返回两个候选；未知 owner 不能读取这些记录。只验证数据库/服务语义，不模拟真实 X 已确认、也不触发平台请求。

文件：`backend/app/sources/adapters/x_user_lookup.py` 仅 X 解析与纯适配；`backend/app/monitors/models.py`、`services.py`、`schemas.py` 和唯一 DDL `backend/database/schema.sql` 持有离线账号登记；`backend/app/db/metadata.py` 注册 ORM；单元/隔离 PostgreSQL 测试覆盖身份与别名规则。本子片不改 OpenAPI、Web 或 Compose，也不对现有 `hotkey-server` 数据库执行 DDL；无迁移系统时，schema.sql 仅是新空库 DDL 来源，运行期不自动建表。执行相关 pytest、后端全量 pytest、Ruff、format、mypy 与架构测试。不能以模拟通过填产品 AC。

`OPEN-006-001` 的“首轮 50 件、7 天、60 分钟”仍是 PRD 建议：无已授权真实作者样本、端点可用性和已确认费用上限时不设产品默认，也不自动启动首次回填。后续真实解析/采集必须先完成 002 S01b、037 paid 门禁和 004 连接状态，核对 Developer Console 当期费率/权限并做逐能力实测；未通过则维持 `not_connected`。离线存储不执行任何现有数据库 DDL；回退通过回退代码/schema 变更处理，不删除用户数据。日志、错误和审计不可写入原始输入、URL、Token 或平台响应正文。
