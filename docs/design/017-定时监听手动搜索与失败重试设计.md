# 定时监听、手动搜索与失败重试设计

## 现状与问题

HotKey 已具备生产采集主链路：CollectionScheduler 每分钟读取 active 的已发布监控目标，按来源、查询签名和时间窗合并 `collect_source` 持久任务；Worker 重新读取发布事实后执行 Connector，并在成功时进入 normalize 流水线。CollectionRun、目标结果、错误分类、检查点、指数退避和管理员原子重试也已落地。

当前缺口是用户无法从某个已启用监控即时触发相同链路。若前端直接调用 Connector，会绕开持久队列、幂等、权限、冷却、运行事实和后续标准化；若直接修改检查点，又会污染自动调度时间。

## 目标

- active 且已有 published 配置的监控继续由现有调度器自动监听。
- Editor/Admin 可对一个 active 监控执行“立即搜索”，请求只负责提交持久任务，不同步调用上游。
- 自动与手动任务复用同一个 `collect_source → normalize` Handler 和 CollectionRun，不建立数据旁路。
- 同一来源与查询在 5 分钟冷却桶内只创建一个手动任务，并合并所有当前仍符合条件的发布目标。
- Editor/Admin 可查看批次进度；只有 Admin 可对 failed/cancelled 批次执行原子重试。

## 非目标

- 不新增第二套调度器、内存队列或同步搜索结果接口。
- 不为 Viewer 开放手动触发、运行目录或重试。
- 不在本条新增暂停/取消 API；队列管理员已有通用任务取消能力，采集页只呈现 CollectionRun 事实。
- 不改变 Connector、查询编译、内容标准化、相关性、事件聚类或热度算法。
- 不承诺绕过上游配额；手动搜索与自动采集使用同一限流和错误分类。

## 核心设计

### 1. 自动调度保持单一事实源

CollectionScheduler 继续只读取：

- `monitor.status = active`；
- 配置版本为 published；
- MonitorSource 与 SourceConnection 均启用且未归档；
- 检查点已到期；
- 采集间隔为 5 分钟至 24 小时。

任务唯一键仍由来源、查询签名和时间窗构成。Worker 执行前重新读取这些事实，因此暂停、改版或禁用来源后，旧任务不会采集过期目标。

### 2. 手动触发契约

新增 `POST /api/v1/monitors/{id}/collect`：

- 仅 Editor/Admin；
- 仅接受正整数监控 ID，不接收来源、查询、时间窗或 Connector 参数；
- 后端在事务内读取该监控当前 active published 目标；
- 按来源与查询签名分组，每组提交一个现有 `collect_source` 任务；
- 返回请求分组数、新建数、复用数与 `cooldown_until`，不暴露查询、来源端点、游标或凭据。

手动时间窗以服务端当前 UTC 为结束时间，按监控发布间隔向前取窗。客户端不能操纵窗口或配额。

### 3. 冷却、合并与运行类型

手动任务唯一键由来源、查询签名和服务端 5 分钟 UTC 桶构成。同桶并发提交依赖数据库 `(kind, unique_key)` 唯一约束原子复用，不依赖进程内锁。

队列 Payload 增加受限的 `trigger_type`，只允许 `schedule` 或 `manual`。Worker 将其写入 CollectionRequest；CollectionRepository 创建运行时保存真实 trigger type。历史空值只按 schedule 解释，不扩展任意字符串。

手动 Worker 重新读取所有 active published 且共享来源/查询签名的目标，因此多个监控不会重复请求同一上游窗口，也不会因先触发的监控而遗漏后续目标。自动 Worker 仍按检查点精确读取到期目标。

### 4. 失败与重试

- Connector 临时错误继续由 River 有界重试，认证、解析和永久错误终止。
- CollectionRun 失败后保留稳定 `error_code`，不保存第三方错误正文。
- Admin 人工重试在一个事务中锁定来源/查询、确认没有更新窗口、恢复原检查点与目标，并重新激活原持久任务。
- 原运行保留初始 trigger type 与 scheduled time，用于精确恢复自动或手动任务唯一键；对外重试后的运行类型仍记录为 retry。
- 目标已暂停、改版、禁用或集合变化时，重试返回冲突，不污染新配置。

### 5. 前端交互

热点监控页在 active 且 published 的监控操作区展示 shadcn/ui Button“立即搜索”：

- Editor/Admin 可见；Viewer 不可见；
- 提交中禁用并显示加载状态；
- 成功 Toast 显示新建/复用批次数和冷却时间，并提供前往采集内容页的明确路径；
- paused、draft、archived 监控不显示可执行入口。

采集内容页继续使用现有 Card、Badge、Empty、Pagination：Editor/Admin 可查看批次；仅 Admin 看到 failed/cancelled 的“重试”按钮。Viewer 只查看内容，不请求批次 API。

## 安全与可观测性

- API 不接受任意 URL、查询或时间窗，不增加 SSRF 与凭据面。
- 队列 Payload 仍是有大小上限的 ID/版本/哈希信封，不保存查询正文。
- 手动触发由角色门禁和 5 分钟原子冷却双重限制；上游仍执行 Connector 自身限流。
- 指标分别记录 manual、list、retry 的 success/error；响应和日志只使用稳定代码与数量。

## 验收边界

- 同来源/查询的并发手动触发在一个冷却桶内只有一个持久任务。
- paused、无 published 配置或无可用来源的监控不能触发。
- 手动运行写入 `trigger_type=manual`，并进入与自动运行相同的 CollectionRun 和 normalize 链路。
- Editor 可触发和查看进度但不能人工重试；Admin 可重试；Viewer 均不可执行。
- 自动调度、失败分类、历史来源与全量回归保持通过。
