# 凭据与应用安全设计

日期：2026-09-21。本文冻结 034 S00—S01 的身份、会话和密码保护边界；S02 的外来内容、S03 的网络目标与业务连接秘密另行增量设计。本文不把身份底座通过解释为 034 完整产品验收。

## 1. 范围与决策

HotKey 首版是单使用者自托管工作台，只建立一个 owner，不提前实现团队、角色矩阵、OAuth、JWT、通用秘密库或独立认证服务。

| 决策 | 冻结值 | 理由 |
|---|---|---|
| 首次初始化 | `POST /api/identity/initialize`，同时要求 JSON 请求、`X-HotKey-CSRF: 1` 与部署者配置的 bootstrap 凭据 | 无通用默认账号/密码；浏览器跨站简单请求不能完成初始化 |
| 密码 | 12—128 字符；使用 `pwdlib` 推荐的 Argon2 参数保存单向散列 | 复用项目已选依赖，不自研密码算法 |
| 会话 | CSPRNG 生成 32 字节不透明令牌，数据库只保存 SHA-256 摘要；12 小时绝对过期，不滑动续期 | 令牌无业务含义，服务端可立即撤销 |
| Cookie | `hotkey_session`：HttpOnly、SameSite=Strict、Path=/；`hotkey_csrf`：SameSite=Strict、Path=/；staging/production 强制 Secure | 会话令牌不可被脚本读取；CSRF 值供同源 Web 请求写入请求头 |
| CSRF | 写请求统一要求 `X-HotKey-CSRF`；未登录初始化/登录固定为 `1`，已登录写请求必须与 CSRF Cookie 及数据库摘要同时匹配 | SameSite 是纵深防护，不替代显式写请求校验 |
| 恢复 | `python -m cli identity reset-password` 从隐藏交互输入读取新密码，使用数据库维护权限执行并撤销全部旧会话 | 不把高权限恢复入口暴露给未登录 HTTP，也不把密码放进命令参数或环境 |
| 会话存储 | PostgreSQL | 撤销与恢复必须有持久事实，不依赖可丢失的 Redis 缓存 |

`OPEN-034-001` 在 S01 范围内冻结为上述 12 小时服务端会话、PostgreSQL 撤销事实和环境注入 bootstrap 凭据。可信网络目标仍属于 S03，当前不提前关闭。

## 2. 数据与事务

`backend/database/schema.sql` 继续是唯一 DDL 事实源，SQLAlchemy 只映射、不建表。

### identity_users

- `id UUID` 主键；`singleton_key SMALLINT UNIQUE CHECK (= 1)` 保证并发初始化也只能建立一个 owner。
- `username VARCHAR(64) UNIQUE`，规范化为小写；只允许 ASCII 字母、数字、点、下划线和连字符。
- `password_hash TEXT`；普通 DTO、日志和导出均无此字段。
- `credential_version INTEGER` 初始为 1；恢复密码时递增。
- `created_at/updated_at TIMESTAMPTZ`。

### identity_sessions

- `id UUID` 主键，`user_id` 外键。
- `token_digest BYTEA UNIQUE`、`csrf_digest BYTEA`，均只保存 32 字节摘要。
- `credential_version` 捕获创建会话时的用户凭据版本。
- `created_at/expires_at/revoked_at/revoked_reason`；注销和恢复保留撤销事实，不物理删除。

初始化在一个事务内创建 owner 与首个会话；失败回滚后不产生 owner、会话或可进入工作台的状态。登录验证后创建会话。注销只撤销当前会话。维护恢复在同一事务内更新密码、递增凭据版本并撤销全部活跃会话。受保护请求同时校验令牌摘要、未撤销、未过期及凭据版本。

## 3. HTTP 契约

所有端点位于 `identity` tag，成功响应只返回 `IdentitySessionView`：`user{id, username}` 与 `expires_at`，不返回密码、密码散列、bootstrap 值、会话令牌或 CSRF 值。

| 方法与路径 | operation_id | 成功 | 关键错误 |
|---|---|---|---|
| `POST /api/identity/initialize` | `initializeOwner` | 201，并设置两枚 Cookie | 403 `bootstrap_forbidden`；409 `identity_already_initialized` |
| `POST /api/identity/sessions` | `createIdentitySession` | 200，并设置两枚 Cookie | 401 `invalid_credentials` |
| `GET /api/identity/session` | `getIdentitySession` | 200 | 401 `invalid_session` |
| `DELETE /api/identity/session` | `deleteIdentitySession` | 204，清除 Cookie | 401 `invalid_session`；403 `csrf_invalid` |

用户名不存在与密码错误使用同一公开错误。初始化配置缺失与错误值均公开为相同的 `bootstrap_forbidden`，不回显配置状态。API Router 只处理 HTTP 和 Cookie，通过 `api/dependencies.py` 注入服务；领域服务拥有事务。

## 4. Web 与运行配置

S01 不额外创建“安全功能页”。浏览器请求封装在非安全方法外自动发送 `X-HotKey-CSRF`：优先读取同源 `hotkey_csrf` Cookie，否则发送初始化/登录所需的 `1`。身份业务页随 035 接入；本切片先交付可生成的契约与真实 API 闭环。

新增配置仅为：

- `HOTKEY_BOOTSTRAP_TOKEN`：可选启动配置，但调用初始化时必须存在且至少 32 字符；样例只放占位说明，不提供可用默认值。
- `HOTKEY_SESSION_TTL_SECONDS`：默认 43200，限制 900—86400。

访问日志继续只记录方法、路径模板、状态和 request ID，不记录 Header、Cookie 或请求体。密码、bootstrap 值和令牌不进入异常 context。生产与 staging 必须通过 HTTPS，Cookie 自动开启 Secure；development/test 允许本机 HTTP 验证。

## 5. 验证与证据边界

S01 先以真实隔离 PostgreSQL 证明端点缺失，再实现并验证：

1. 错误 bootstrap 初始化被拒绝且数据库为空；正确初始化成功；并发/重复初始化被拒绝。
2. 正确登录可访问受保护会话；错误用户名和密码表现一致。
3. 缺失或错误 CSRF 不能注销；注销后旧 Cookie 的读写均失败。
4. 维护 CLI 恢复密码后，所有旧会话立即失效，旧密码不能登录，新密码可登录。
5. HTTP body、错误响应、结构化访问日志和普通 DTO 不出现密码、bootstrap、Cookie 或令牌值。
6. Ruff、格式、mypy、全量 pytest、架构测试、运行时 OpenAPI 漂移和前端全量门禁通过。

真实 PostgreSQL 证据可证明 S01 身份会话闭环，不证明 S02 外来内容、S03 网络目标、连接凭据撤销、浏览器页面体验或 034 全部 AC。运行环境不执行自定义脚本；数据库初始化直接挂载 `schema.sql`，验证使用现有 CLI、pytest、Compose 与工作流命令。

## 6. 停止与回退

启用前备份现有空库状态；当前项目不支持对存量库自动迁移。出现异常先移除 bootstrap 配置以停止新初始化，再停止 API 写入口并保留 PostgreSQL 撤销记录。程序回退只适用于尚无身份数据的环境；已有身份数据时保留新表并以前向修复恢复，禁止删除表或持久卷来伪造回退。
