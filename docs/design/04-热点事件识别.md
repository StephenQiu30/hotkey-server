# 04 热点事件识别

对应 [04-热点事件识别](../requirement/04-热点事件识别.md)；实施拆分见 [04-热点事件识别](../plan/04-热点事件识别.md)。需求为范围依据，本文件不表示功能已实现；进度只在仓库根目录BACKLOG。

## 设计目标

从相关材料中识别具体事情，避免同主题直接当同事件。

## 结构与交互

- 相关性显示 bool、理由、错误和未分析；线索、事件候选与具体事件分开，单条材料不表现为多源确认。
- 候选对照展示主体、动作、时间与代表证据；相同关键词或标题相似只帮助召回候选。
- 同主体多事件、旧闻重发、传闻与确认、跨平台搬运保留可检查关系；纠正入口进入05的版本操作。

## 数据与复用边界

先核对现有入口：[backend/app/analysis](../../backend/app/analysis)、[backend/app/events/clustering.py](../../backend/app/events/clustering.py)、[backend/app/events/signals.py](../../backend/app/events/signals.py)。入口存在只代表可核对，不能据此宣称真实能力已验收。

优先复用现有业务身份、版本、服务与组件；展示派生值、本机阅读状态和持久事实分别处理。新字段仅在同编号需求有实际消费路径时补齐，接口/数据库的唯一合同仍在代码及schema。

## 状态与核对重点

数值由程序计算，结论有原文；跨平台案例评测不等于第二平台采集已验收。

读写状态使用真实回执；已有数据刷新失败保留可读内容并标过期，未知写入先核对结果。正常、空、加载、错误、无权限以及键盘行为按实际交互覆盖；静态内容无远程状态时标不适用。

视觉、组件与响应式沿用 [00-产品目标与边界](../design/00-产品目标与边界.md)；跨页状态沿用 [11-质量评测与验收](../design/11-质量评测与验收.md)；权限、安全渲染和许可沿用 [10-权限与数据生命周期](../design/10-权限与数据生命周期.md)。

## 从材料到具体事件

相关材料（含原帖/可得父链）→按冻结主题规则运行相关性→同owner可读集合召回事件候选→比较主体/动作/时间和证据→写入事件成员或保留线索→05提取事实并形成修订。每一步保留原材料和规则/模型版本，未分析与执行错误不进入“无关”统计。

现有`cluster_candidates`使用标题相似、时间和命中词召回候选；现有注释和实现均不把标题相似认定为同一事件。优先核对`signals`对单材料线索和事件更新的承接，不降低旧批量候选条件来制造多源确认；相似度参数是否需要调整由真实误合并/漏合并样本决定。

| 判断维度 | 保留的区分 |
|---|---|
| 同主体、不同动作或时间 | 分别为事件，不按关键词合并 |
| 旧闻重发与首次发现 | 发现时间不改写发生时间，重复不产生新事实 |
| 搬运与独立证据 | 保持不同帖子身份，注明证据关系；平台数不等于独立确认数 |
| 传闻与确认 | 记录证据状态变化及引用，不能用新摘要抹去旧依据 |

校准样本用于调整规则；冻结后的保留样本用于独立验收。程序计算TP/FP及误合并/漏合并等统计，模型只提供可引用判断。纠正调用05/39既有修订路径。
