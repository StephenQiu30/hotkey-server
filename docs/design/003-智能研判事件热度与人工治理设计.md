# 智能研判事件热度与人工治理设计

## 现状

当前 `intelligence`、`ingestion` 与 `event` 模块已经包含模型配置、AI Run、Embedding、混合召回、相关性评估、内容家族、MicroEvent、Heat、Claim/Evidence、摘要和人工反馈等数据与代码。运行时可配置 OpenAI、DeepSeek、Ollama 与 ONNX，并使用 pgvector 保存现有向量事实。

新基线的目标智能运行时是 Go Worker 内的受控 Codex CLI Adapter，但当前多 Provider、Embedding 与 pgvector 能力尚未移除，也没有获得可以删除其数据和调用路径的验收证据。本设计只定义目标边界和迁移约束，不宣称迁移已经发生。

## 目标

| 需求 ID | 目标 |
|---|---|
| BR-003-001 | 智能能力必须提升筛选和整理效率，但不能成为事实、权限或来源权利的拥有者。 |
| BR-003-002 | 系统必须把相关内容聚合为可持续更新的事件，同时抑制重复转载对热度和来源广度的放大。 |
| BR-003-003 | Relevance、Heat 和 Evidence State 必须独立解释和治理。 |
| BR-003-004 | 任何自动决定都必须允许授权用户反馈、复核和追加式纠正。 |

设计将这些需求落为“确定性召回先于智能建议”、“Document 家族与 MicroEvent 分层”、“Heat 使用时间窗增量”、“智能输出通过 Schema 与 Evidence 白名单校验”、“人工治理追加事实”以及“评论仅在权利与预算边界内有界展开”。

## 非目标

- 不让 Codex CLI 直接写 PostgreSQL、修改 Vault 或决定最终领域状态。
- 不以 AI 输出声明事实真伪概率、来源可信等级或法律结论。
- 不把高热度等同于高相关性或证据充分。
- 不全量采集所有评论，不把多条评论计为多个独立事实来源。
- 不在本设计中删除现有 Provider、向量表、模型运行或来源数据。
- 不新增 Python Agent 服务、独立向量库、RAG、重排服务或通用规则引擎。

## 核心决策

### DEC-003-001：Codex 是受控建议适配器

Codex Adapter 运行在 Go Worker 进程管理边界内。每个任务使用独立临时目录、固定输入清单、只读或最小写入 Sandbox、超时和进程组终止；Prompt 通过标准输入传递，不进行 Shell 拼接。输出先写临时结果，再经 Go 校验后进入 Application。

容量不使用未经测量的固定并发。批准并发前必须按 Skill/任务类型和 Context 大小分别执行并发 2、3、4 的校准，记录目标环境、Context 字节数或 Token 数、CPU 使用、内存峰值、执行时长、成功率和失败类别；默认值只能来自这些可复测结果。

### DEC-003-002：确定性召回先于智能判断

来源身份、关键词、实体、时间、链接和内容指纹先生成候选集合。智能任务只能在候选或明确人工请求范围内工作，不能绕过来源权利或自行联网扩展证据。

### DEC-003-003：内容家族与事件分层

Observation 表达来源观察，Document Version 表达可引用文本，Content Family 表达转载或近重复根，MicroEvent 表达同一现实事件。事件成员以 Content Family 为基本去重单位，避免转载量直接放大热度和来源广度。

### DEC-003-004：三类判断分离

- `relevance`：内容与监控意图的匹配程度和理由。
- `heat`：事件传播是否在指定时间窗升温，由 Go 使用独立谱系根宽度、速度、加速度、来源覆盖、可选的归一化互动和时效六类分量确定性计算；缺失互动保持 unknown，并按 `available_weight` 重归一化，不能按零值惩罚。
- `claim_evidence`：某条 Claim 到不可变 Document Version 引文选择器的可引用关系、权利、出处和关系类型；报告逐句审批检查这一层。
- `evidence_state`：Event 级 Snapshot，根据当前 ClaimEvidence 集合、独立出处数、争议、纠正或撤回聚合；它用于概览，不能代替报告的 Claim 级引用校验。

### DEC-003-005：人工治理追加事实

相关性覆盖、成员修正、合并、拆分、证据纠正和摘要重生成均记录操作者、理由、基准版本与时间。治理不静默改写历史自动运行，查询层计算当前有效视图。

### DEC-003-006：现有 AI 能力按证据迁移

Plan 必须先盘点 Provider Profile、AI Run、Embedding、召回、River Handler、页面/API 和报表等全部调用方，再决定兼容读取、停止新写或替换顺序。迁移验收必须同时包含固定样本质量比较、历史与新增数据的保留/停止新写/归档/删除处置、旧记录读兼容、按 Skill/Monitor 灰度和实际切回演练。迁移期间新旧路径不得对同一目标产生无来源区分的双写；任何物理删除都需要备份、对账、独立批准和回滚验证。

## 数据与状态

- 产品文档中的 `Event` 在新写链路中专指 `micro_events` v2 事实及其成员、Heat、Claim/Evidence 和治理记录。Legacy `events/topics` 只保留历史读取与回滚兼容，未经专项迁移验收不得与 `micro_events` 对同一输入双写，也不得作为新通知、报告或知识事实源。
- AI Run 保存任务类型、目标身份、目标版本、输入哈希、Evidence Set Hash、执行适配器、状态、尝试、错误码、耗时、成本或资源计量以及结果版本。合法主路径为 `queued → running → validating → succeeded`；可重试失败进入 `retry_wait → running`，终态为 `failed / cancelled`。只有同复用键的在途或成功运行可以复用；非法/越权输出不得成为复用结果，修复输出必须形成新 Attempt。容量校准另保存任务类型、Context 字节数或 Token 数、目标环境、CPU 使用、内存峰值、执行时长和并发 2–4 的结果，不能只保存一个最终并发数字。
- Codex 结构化结果只保存允许的字段；运行日志与临时上下文按保留策略处理，不作为长期业务事实。
- Document Match Decision 保存候选信号、智能建议、最终决定和人工覆盖；历史决定追加而不覆盖。
- MicroEvent 沿用当前稳定身份和版本，当前状态只包含 `active / review_pending / closed / merged`；附件中的 `candidate / emerging / trending / verified / disputed / declining / archived / rejected` 不得直接写入现有枚举，新增生命周期展示必须通过 PRD 和 Schema 评审。
- Heat Snapshot 保存计算窗、独立谱系根数、速度、加速度、覆盖、可选归一化互动、时效、可用权重和 Profile 版本；缺少互动保持 unknown，缺少时间基线时显示 warming-up 语义，不制造增量。Mention Volume、Novelty、Monitor Relevance 和 Spam Penalty 若要进入 Heat，必须另立 Profile/Schema 决策，不能从其他分数暗中推导。
- Claim、ClaimEvidence Version、Event Evidence State Snapshot 和 Summary Sentence 保存分层引用关系；未知 Evidence ID 不得落库，Event 级状态不得替代 Claim 级可引用性。
- 评论会话若实施，必须保存根内容、父子关系、来源外部身份、Checkpoint 和抽样依据，不复制成第二套事件事实。

## 接口与交互

- 监控预览展示确定性命中、召回原因、智能建议、警告和待人工确认项。
- 内容详情展示正文版本、引用定位、相关性决定、反馈入口和所属内容家族。
- 事件雷达展示 Heat、趋势、更新时间、来源覆盖和证据状态；详情展示成员、时间线、Claim、Evidence 与摘要句引用。
- 编辑者可提交相关性覆盖、事件成员反馈、证据纠正、合并/拆分建议和摘要重生成请求。
- 智能任务是异步操作，API 返回运行身份；查询接口只展示已验证结果和稳定失败码。
- 所有接口继续使用统一 Result 和生成 OpenAPI Client。

## 安全与合规

- Codex 任务不包含数据库 DSN、来源凭据、JWT Secret 或非目标用户数据；Evidence 通过授权后的有界上下文提供。
- 来源文本使用明确的不可信边界，禁止其中的命令改变系统策略、工具权限或输出 Schema。
- Adapter 默认不挂载源码和用户主目录；网络按任务关闭或只允许批准出口，认证文件使用最小文件权限。
- 评论采集必须先验证来源 Capability、Rights、Credential 和保留/删除义务。
- 人工治理需要 editor 或 admin 权限；所有越权尝试返回稳定错误并可审计。
- 智能结果中的个人信息、诽谤性判断和敏感分类不得未经人工审查成为对外结论。

## 失败与降级

- Codex 未安装、未认证或不可达：运行标记为不可用，候选、确定性相关性信号、去重和 Heat 继续。
- 超时或进程异常：终止整个进程组，保留净化后的错误码；在最大尝试内重试，不能无限修复输出。
- JSON 或 Schema 无效：拒绝结果；可选的一次修复必须产生新的运行尝试并保留原输出哈希。
- Evidence 引用伪造或越权：整项结果失败，不丢弃原始证据，也不部分写入 Claim。
- Heat 缺少指标基线：展示基线不足，不用当前绝对量填充增量。
- 事件聚类低置信：进入 `review_pending` 或保持独立候选，不强制合并。
- 迁移期间旧 Provider 或向量读取失败：使用明确的降级原因，禁止无标记切换造成结果来源不可追踪。

## 验收边界

| 验收 ID | 边界 |
|---|---|
| AC-003-001 | Go Worker 在隔离工作区与最小权限下启动 Codex CLI；不信任正文无法取得数据库、来源、Vault 或源码秘密，结果只能经 Application/Domain 提交；并发批准前实际记录各任务类型、Context、CPU、内存、时长和并发 2–4 候选结果。 |
| AC-003-002 | Codex 超时、未认证、Skill/Schema 版本不符、输出非法 JSON、枚举/长度越界、错误码未知或伪造 Evidence ID 时，返回稳定失败码，不写有效决定或 Claim，保留净化运行事实并可按策略重试。 |
| AC-003-003 | Codex 暂时不可用时，证据、精确去重和指标继续保存，内容显式待分析；恢复后补算不重复产生有效决定或事件成员；旧 Provider/Embedding 切流前完成调用方盘点、质量比较、数据处置、读兼容、灰度和实际回滚验收。 |
| AC-003-004 | 跨来源相关内容形成一个 Event，转载家族不重复放大成员和来源广度，相同输入重复执行幂等。 |
| AC-003-005 | Relevance、Heat、ClaimEvidence 与 Event Evidence State 在 API、数据库与界面中使用独立字段、状态和解释；改变任一项不会隐式改写其他项，报告批准逐句检查 ClaimEvidence 而不是只检查 Event 汇总状态。 |
| AC-003-006 | 固定 Heat 输入与 Profile 多次计算结果一致且六类分量可解释；归一化互动不可用时保持 unknown 并按可用权重重算，无时间基线时显示 `warming-up`，不以绝对值伪造速度或加速度。 |
| AC-003-007 | Editor 对成员、证据、争议、合并或拆分的治理动作追加操作者、理由、基准版本和审计；版本冲突被拒绝，重放不重复产生当前副作用。 |
| AC-003-008 | 四产品角色访问研判与治理页面或直接 API 时五态清晰；Viewer 只读、Analyst 提交建议、Editor 采纳、Admin 配置运行，未实现 Analyst 时按真实角色拒绝。 |

## 未决项

- OPEN-003-001：Codex CLI 的固定命令参数、版本验证、认证来源和可用 Sandbox 能力需以目标部署实测。
- OPEN-003-002：现有 Provider 与 pgvector 是长期兼容能力还是迁移过渡，需要调用方、数据量、成本和质量对比后决策。
- OPEN-003-003：相关性、聚类与 Heat 的首版阈值和基准数据集尚未批准。
- OPEN-003-004：首批评论来源、账号权限、抽样策略和删除同步义务需单独合规评审。
- OPEN-003-005：合并/拆分采用立即执行还是双人复核，需要结合目标用户规模确定。
