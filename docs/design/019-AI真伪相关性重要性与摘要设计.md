# AI真伪相关性重要性与摘要设计

## 现状

项目已有 OpenAI、DeepSeek、Ollama、ONNX/Embedding、结构化 Schema、相关性复核、实体声明提取和事件摘要，但尚未用一套产品分数完整覆盖参考项目的 isReal、relevance、importance、summary 体验。

## 目标

对每条候选内容生成可解释、可降级、可追溯的真实性风险、相关性、重要性和摘要结果，并控制模型成本。

## 非目标

不在本条复制相邻领域的数据或服务，不以纯前端假数据宣称功能完成，也不引入第二套事实源。

## 核心决策

- 真实性不是无证据的真假裁决，而是 `credibility_status + confidence + reasons + evidence_ids`；单一模型不得把内容永久标成虚假。
- 相关性结合确定性规则、Embedding 和可选 LLM 复核；重要性以来源质量、传播宽度、新颖度、影响和时效组成。
- 所有模型输出使用版本化 JSON Schema，保存 provider/model/prompt/schema/input_hash/evidence/cost/latency。
- 模型不可用时使用规则和证据摘要降级，事件、热度、告警与列表仍可运行。

## 数据、接口与交互

- 真实性风险与理由
- 监控相关性分数和反馈
- 重要性分数与组成
- 内容/事件结构化摘要及模型运行证据

所有状态变化保存明确版本、时间和操作者；跨端字段由 Schema、后端 DTO 和生成 OpenAPI 驱动，前端不得手写重复类型。

## 安全、失败与降级

把模型结论当事实会产生误导；必须显示置信度、理由、证据和降级标识。

外部 AI、邮件、实时连接或归档不可用时，业务事实先可靠落库，异步重试或降级读取，不在请求链路丢失结果。

## 设计验收边界

- 相同输入和模型版本可追溯且幂等
- 低置信度不会被 UI 表达为确定事实
- 预算耗尽或模型故障时核心流水线成功降级
