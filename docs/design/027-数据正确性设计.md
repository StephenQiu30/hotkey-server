# 数据正确性设计

日期：2026-09-21。本版只完成 027 S00，冻结后续内容实体与观察记录必须遵守的身份、版本、缺失和关系边界，为 028 S01 提供稳定输入引用前置。本版不创建 `content` 代码、数据库表、适配器或产品 Acceptance。

## 1. 当前事实与缺口

- `sources/contracts.py` 已为作品和评论保留 `source_key`、`object_type`、不透明 `external_id`、作者/父链、可空指标、发布时间及页级 `observed_at`，但它只是适配器边界，不是内容持久化模型。
- `evidence_resources` 已保存 owner、资源 ID、来源/保留策略版本及采集/到期时间，可作为生命周期锚点；它不保存正文，也不是作品/评论身份真相。
- `jobs` 已保存 job/operation、配置版本、来源能力及执行/阶段尝试，可串联一次处理活动；当前尚无内容实体、不可变观察或冲突隔离表。

因此 027 S00 只定义后续实现不变量，不以现有 DTO 或生命周期记录冒充已完成的数据正确性能力。

## 2. 一手资料与采用结论

| 依据 | 采用结论 |
|---|---|
| [W3C PROV Primer](https://www.w3.org/TR/prov-primer/) | 区分持续对象、每次版本/观察实体和生成活动；更新产生新版本，不静默改写历史观察。027 后续以 job/operation 表示活动，以不可变观察表示当时事实。 |
| [W3C PROV Constraints](https://www.w3.org/TR/prov-constraints/) | 生成、使用和派生关系必须满足时间顺序；观察时间早于处理并不等于发布时间，几类时间不得合并。 |
| [PostgreSQL Constraints](https://www.postgresql.org/docs/current/ddl-constraints.html) | 跨行身份唯一和跨表归属用 `UNIQUE`/`FOREIGN KEY`，不用读取其他行的 `CHECK`；可空唯一字段必须显式决定 `NULLS NOT DISTINCT` 或拆分结构。 |
| [RFC 9562](https://www.rfc-editor.org/rfc/rfc9562.html) | 名称型 UUID 只有在命名空间与规范形式冻结后才稳定；027 不对未知平台身份自行 trim、转小写或拼 URL，避免把不同原生身份错误合并。 |

## 3. 冻结的不变量

### 3.1 对象身份

后续内容实体的身份由 `(owner_id, source_key, object_type, native_scope, external_id)` 确定：

- `external_id` 是来源返回的不透明字符串，不转数值、不补零、不从 URL 猜测。
- `native_scope` 仅在来源官方契约或合法样本证明 ID 只在账号/频道等范围内唯一时使用；全局唯一来源必须显式使用无作用域分支，不能用空串代替未知。
- `object_type` 至少区分 `post` 与 `comment`；作者、父评论和根作品引用不得共用一个无类型 ID 槽位。
- 作用域和字段单位仍须逐来源在 038 S02 或对应来源切片核实。`OPEN-027-001` 只关闭公共身份外壳，不伪造尚未验证的来源映射。

### 3.2 观察与版本

- 每次被接受的来源页产生独立观察身份，关联 job/operation、页级 `observed_at` 与实际配置/组件版本；重放同一观察不得产生第二份事实。
- 内容发生变化时新增内容版本，旧观察继续指向当时版本；“当前内容”是受控投影，不覆盖历史。
- `published_at`、来源事件时间、`observed_at`、系统接收时间和处理时间分别保存；未知时间保持 `None`，不得取当前时间补齐。
- `0` 是已知值，`None` 是未知或未提供；未支持字段由来源能力/字段政策表达，不转成 0。

### 3.3 关系与冲突

- 评论必须关联根作品；父评论缺失时保留其来源身份和明确未解析状态，不改挂到根评论或其他评论。
- 作者、引用、转帖和父子关系使用有类型引用；关系端点的 owner/source 必须一致，跨来源映射只能由后续显式归并产生。
- 同一身份出现互斥作者或关键作用域时进入冲突隔离，不能以“最后写入”覆盖。具体隔离状态和修复入口留给 027 S03。

## 4. 对 028 S01 的前置输出

028 的输入清单不得复制正文或另建内容真相。尚无内容表时，S01 使用现有 `EvidenceResource.id` 作为受生命周期约束的资源锚点，并为每项输入保存：

1. 角色（目标输入或比较参考）；
2. 资源记录 ID；
3. 调用方冻结的版本引用；
4. 稳定序号。

版本引用只标识调用时使用的不可变快照，不承诺当前仓库已具备内容版本表。028 S02 在内容版本落地后接入真实版本关系；删除和到期仍由 036 优先约束，不能从溯源清单恢复正文。

## 5. 目录与后续切片

- `sources/` 只持有平台无关适配器契约，不写数据库。
- 未来 `content/` 由 007/008 与 027 共同持有实体、观察、版本和关系；实际创建前补 architecture 门禁，不提前建空包。
- `evidence/` 继续持有准入、生命周期和 028 的证据清单，不持有作品“最新值”。
- `jobs/` 持有执行活动与配置上下文，不复制内容字段。

027 S01 再以受控样本和真实 PostgreSQL 实现身份/关系基线；S02 处理缺失、单位、时间和版本；S03 处理冲突隔离和三次重放。没有业务页面或 HTTP 变化时不创建空接口或 E2E 文件。

## 6. 验证与边界

S00 通过文档链接、当前契约字段和依赖状态核对；不运行产品 AC，不建立 Acceptance。真实来源身份作用域、字段单位和异常样本仍待来源切片验证，027 保持 `in_progress`、产品 AC 0/6。
