# 32 监控主题工作区

对应 [32-监控主题工作区](../requirement/32-监控主题工作区.md)；实施拆分见 [32-监控主题工作区](../plan/32-监控主题工作区.md)。需求为范围依据，本文件不表示功能已实现；进度只在仓库根目录BACKLOG。

## 设计目标

在同一屏理解主题关键词、采集平台、命中变化和告警，并进入必要设置。

## 结构与交互

- 主题列表每页20条，置于详情上方并默认展开；详情按标题、关键词、真实24小时统计、平台、规则和最近告警连续展示。
- 平台区按实际能力呈现，8行设计槽位不等于8平台可用；规则历史最多50条，结果/运行/编辑是次级互斥展开区。30秒刷新只读，最近5项不当总量。

### 区域与显示边界

下面保留需求定义的区域和数量；必需字段、操作语义和业务约束以同编号需求表为准，不另建字段字典。

| 区域/操作 | 数量与范围 |
|---|---|
| 主题列表 | 20条/页，全宽列表位于当前主题详情上方 |
| 标题/关键词 | 选中1主题 |
| 每小时命中 | 24小时桶 |
| 采集平台 | 原稿8行；实际以来源目录为准 |
| 告警规则 | 当前主题规则 |
| 最近告警 | 最近可读历史，按规则最多50 |
| 次级操作 | 展开区保持草稿和运行回执 |

## 数据与复用边界

先核对现有入口：[frontend/src/app/topics/components/topics-workspace.tsx](../../frontend/src/app/topics/components/topics-workspace.tsx)、[backend/app/api/routers/monitor_topics.py](../../backend/app/api/routers/monitor_topics.py)。入口存在只代表可核对，不能据此宣称真实能力已验收。

优先复用现有业务身份、版本、服务与组件；展示派生值、本机阅读状态和持久事实分别处理。新字段仅在同编号需求有实际消费路径时补齐，接口/数据库的唯一合同仍在代码及schema。

## 状态与核对重点

自然启用不显示执行中；列表折叠、异步高度、隐藏字段校验、深链接与受理后任务跟踪。

读写状态使用真实回执；已有数据刷新失败保留可读内容并标过期，未知写入先核对结果。正常、空、加载、错误、无权限以及键盘行为按实际交互覆盖；静态内容无远程状态时标不适用。

视觉、组件与响应式沿用 [00-产品目标与边界](../design/00-产品目标与边界.md)；跨页状态沿用 [11-质量评测与验收](../design/11-质量评测与验收.md)；权限、安全渲染和许可沿用 [10-权限与数据生命周期](../design/10-权限与数据生命周期.md)。

## 主题工作区交互

- 主视图按稿连续展示主题标题、关键词、小时命中、采集平台、规则和最近告警，不使用默认四页签。结果和设置作为次级展开区；编辑、手动运行和错误恢复仍可访问。
- 工作台、监控主题和主题详情的全宽主题列表位于当前详情上方，桌面和手机均默认展开并可收起，深链接主题保持可访问。该结构只针对工作台列表与详情；首页、阅读、榜单、刊物、账户、表单及管理页各自保持适用的响应式布局。
- 结果、运行与编辑设置继续作为概览后的互斥展开区，保留原有按钮行和语义面板，复用官方Collapsible的180ms高度过渡；按钮保留aria-controls／aria-expanded，切换不重挂内容或丢失草稿。进阶／报告设置同样过渡，收起时fieldset禁用以排除隐藏字段的原生表单校验，展开或发生字段错误时恢复。过渡逐帧测量内容高度以适应异步响应；关闭后隐藏区域不得保留键盘焦点；减少动态效果时立即切换。
- `active` 显示为“定时已启用”，不代表任务正在执行。只展示接口返回的帖子与时间，不把最近列表长度当总量，不提供没有数据支持的相关度或定时历史。
