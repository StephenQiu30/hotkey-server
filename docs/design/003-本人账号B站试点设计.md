# 本人账号B站试点设计

本 Design 是 M2 Epic，从 [总设计 001 v3.2](001-热点舆情监控平台总体设计.md) 正向拆解；总设计现为 v4.0。需求为 [PRD 003](../prd/003-本人账号B站试点需求.md)，逐 Issue 执行计划见 [Plan 010—013](../plan/README.md)。本文中的“已有”仅表示代码或指定运行证据，不代表产品验收。

## 1. 范围与不包含

仅本人账号、公开可见 B 站内容，以宿主机 MediaCrawler 子进程和独立 CDP 资料试点搜索、同轮缓存的一级评论、入库、Codex 相关性、状态与覆盖。每帖一级评论最多 20 条。不包含楼中楼完整覆盖、微博等登录平台、事件归并、推送；B 站热榜属于 M1 公开热榜，不能替代本试点。现行需求与计划分别见 [PRD 003](../prd/003-本人账号B站试点需求.md) 和 [Plan 010—013](../plan/README.md)。

## 2. 当前能力与证据分层

`mediacrawler.py`、B 站预设与 Worker 装配已有代码；新建库离线回放 5 条视频、2 条评论。修复前两次真实运行分别因综合排序返回旧视频、空简介导致整页回滚而失败；修复后尚未真实运行，开关关闭。受控回放不代表平台真实通过，更不代表 72 小时产品验收。版本与未知非零退出分类尚待修正。

## 3. 架构与数据流

`sources/adapters/mediacrawler.py` 在宿主机从固定的 `hotkey-safe` 工作树启动 `main.py --platform bili --type search` 子进程，读取独立运行目录的受限 JSONL 并将搜索结果按时间窗映射为帖子；评论 Job 仅按视频 ID 读取同次运行的索引与缓存。MediaCrawler 使用本机 Chrome 的独立 CDP 资料；执行入口和资料保护见 §8，容器入口不参与 HotKey 调用。

版本证据分开记录：上游基线 `380b426000aac3d612837ed72c99808347dc94c9`、应用 `~/Desktop/Docker/mediacrawler-start-local/hotkey-safe.patch` 后的固定提交 `fb4e6c57ade1c7a2b3a61e69abc4fd4130047eb2`、适配器 `ADAPTER_VERSION=mediacrawler-fb4e6c5-hotkey-safe`。运行前校验补丁后 HEAD 与已跟踪文件无改动；来源组件策略记录前两者，采集页/Job 记录实际适配器版本，并以 operation ID 关联。当前 B 站预设仍写旧 `mediacrawler-380b426-hotkey-safe`，须在真实验收前校准，不用单一 `component_version` 混记三类版本。

`connections` 在执行前判定连接版本、停用和认证状态；`jobs` 持有执行权、预算、尝试与 Outbox；`sources` 只映射外部结果；`content` 保存帖子/评论身份和发现关系；`analysis` 对内容版本调用本机 Codex。调度和截止见 §6，失败与恢复见 §7。

## 4. 领域、数据与状态

`keyword.search` 与 `source.comments` 沿用共享任务类型，来源键固定 B 站预设和连接版本。`content_discoveries`、内容版本、`content_threads` 分别存搜索命中、内容及同轮评论；`jobs`、`job_attempts`、`coverage_windows`、预算账本和来源连接版本保留操作与停止证据。三类版本分别为上游基线、补丁后提交、实际适配器版本，必须关联 Job，旧单字段不能冒充。来源可用状态须由真实采集/持久化证据推进；认证失效或访问频繁进入停用待人工核查状态。

## 5. 接口与页面

现有主题/来源/内容/任务查询沿用生成 OpenAPI 契约；本试点的来源详情应呈现版本、开关、验证/限流/失败码、最近尝试、覆盖与人工恢复入口。恢复为授权写操作，先检查资料与平台状态，再显式启用；路由不直接读写数据库或接收任意 CDP 文件路径。具体操作和 DTO 在实施切片设计，遵循 PROJECT.md 与 AGENTS.md 的现行错误/响应契约（旧 Design 046 已删除，见 Git 历史）。

## 6. 调度、执行与截止

当前硬编码节奏为 6 小时一次、00:00—08:00 静默、每轮最多 3 词、每词最多 5 条、保守预留每词最多 26 次请求、每日网络预算 60、搜索 Job 220 秒和父进程 240 秒硬截止；应依 [Design 002 §3.1](002-信息获取主链路设计.md#31-来源预设与连接) 移至可版本化来源预设（DEC-001-213），不能仅靠页面频率放宽。调度锁与适配器文件锁双重限制同源并发。取消、预算耗尽、父进程硬截止均终止整个子进程组并有界回收；父进程保留 Kafka Consumer、offset 与最终状态。普通重试遵守 DEC-001-217，验证/限流不得自动恢复。

## 7. 失败语义与恢复

验证码、滑块、扫码/登录失效归 `authentication_required`；访问频繁归 `rate_limited`，均立即停止子进程和该来源后续调度，并记录人工下一步。普通非零退出、协议/文件错误、未知退出要独立分类和脱敏记录，可按边界有限重试；现有未知非零退出误归认证失效，暂停及分类路径须先修正和真实验证。`PARTIAL/EMPTY`、旧视频或页截断保留实际证据，不把空结果说成成功。有权限的用户在 Web/CLI 检查资料和平台状态后显式重新启用连接；验证/限流不自动重试，不破解、自动换号、代理绕过或自动恢复旧写端。

## 8. 安全、风控与可观测

仅个人/非商业研究、本人账号和公开可见内容；MediaCrawler 使用本机 Chrome 的独立 `browser_data/cdp_bili_user_data_dir`，不复用日常资料，调试端口仅绑 `127.0.0.1`。资料目录权限 `700`、运行 `umask 077`；子进程只传必要环境变量，不传 `HOTKEY_*`；输出目录私有并拒绝符号链接、宽权限与超限文件。登录态和资料不进 HotKey 数据库、日志、Git、容器或模型输入；运行说明与补丁记录留在 `~/Desktop/Docker/mediacrawler-start-local/`。记录 Job 对应三类版本、词/页/视频/评论计数、预算、停止原因和认证状态，不记录 Cookie、令牌或资料内容。

## 9. 验收设计要点

先核对补丁 HEAD、CDP 本地绑定、私有资料、预算、连接版本和开关；低频真实 1 词 × 2 视频，核对帖子、同轮一级评论 ≤20、Codex 相关性及状态。受控模拟验证码、认证失效、限流并逐一证明没有自动续跑，人工恢复后再跑；未知退出应独立失败。修复后的真实运行尚未记录，不能称 B 站接入完成；随后按 M2 计划独立观察连续 72 小时，不把 M1 热榜或离线回放替代。

## 10. 决策、风险与对照

沿用 DEC-001-205/206/207/212/213/214/217/218/220。DEC-001-214 替代“B 站与微博同批接入/容器入口”；DEC-001-220 替代单一组件版本混记。本次不另设 DEC-003-xxx。风险为账号验证/封禁、补丁漂移、未知退出误分类与敏感资料泄露；控制见上节。对应原总设计 v3.2 §4.5、§6、§15—16；历史参考：旧 Design 008 评论与回复采集（已删除，见 Git 历史）、旧 Design 037 费用与资源约束（已删除，见 Git 历史）、旧 Design 047 本地网页与浏览器采集（已删除，见 Git 历史）。
