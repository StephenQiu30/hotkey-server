# 扩展能力设计

本 Design 是 M6 Epic，从 [总设计 001 v3.2](001-热点舆情监控平台总体设计.md) 正向拆解；总设计现为 v4.0。需求为 [PRD 007](../prd/007-扩展能力需求.md)，逐 Issue 执行计划见 [Plan 027—030、045—050、053—054](../plan/README.md)。本文中的“已有”仅表示代码或指定运行证据，不代表产品验收。

## 1. 范围与不包含

M6 是逐能力准入边界：报告 Markdown/PDF 与原始数据 CSV/JSON 导出；依赖 M3/M5 的突发告警；本人获授权指定账号追踪；Reddit、X、小红书、抖音、微信公众号及后续登录来源。微博/知乎登录能力由blocked研究Plan053/054承接，六榜不能代替平台接入。不包含绕过平台验证、未定预算的付费 API 请求或以模拟/空结果宣称采集成功。现行需求与计划分别见 [PRD 007](../prd/007-扩展能力需求.md) 和 [Plan 027—030、045—050、053—054](../plan/README.md)。

## 2. 当前能力与证据分层

M1 来源契约、`sources/adapters/x_api.py` 的 MockTransport、内容/任务/预算底座可复用；X 无凭据/月度上限，禁止真实请求。指定账号的旧设计和部分结构可作历史参考，但当前 M6 各来源、告警、增强导出均无逐项真实运行/产品验收；不要用热榜或 B 站试点替代。

## 3. 架构与数据流

候选来源先调研官方能力、许可、授权、分页、限流、稳定 ID、评论父链和费用，再登记来源预设与能力，复用 `sources` 适配器 → `content` 持久化 → `jobs` 执行/预算/覆盖 → `analysis`。指定账号由 `monitors` 保存授权目标和规则，来源适配器只取已准入能力；已授权作者的新帖不受主题关键词过滤，分页或权限导致的未确认缺口必须可见。告警由 `events`/`analysis` 提供可追溯事实，`notifications` 在 M5 已验渠道上投递；导出从有权限的 `reports`/`content` 读取确定版本。共享 Worker/调度、错误契约和数据库门槛沿用总设计；尚无实现切片确定的新拓扑。

## 4. 领域、任务与数据状态

本轮目标设计由以下Issue承接，均不代表已部署：

- Plan028复用现有 `followed_accounts`/FollowedAccountService，monitors持有稳定账号ID、别名与授权连接版本；来源须具备作者采集能力。`account.scan` 以账号/版本/窗口幂等，只有可信尾段才推进水位；授权撤销后禁止继续写入。不能退化为关键词搜索。
- Plan027在notifications域新增告警规则和触发记录；阈值/冷却必填、默认关闭，每5分钟评估最近1小时有效负面计数或同公式热度增量，持久锁保护触发/冷却。投递扩展subject_type/id/version并保留原报告唯一键，不能伪造报告对象。unknown占用冷却且不自动重发。
- Plan030新增 `report_exports`，唯一(owner,report_id,version,format,renderer_version)，固定报告版本；Plan045新增 `content_export_requests`，受理时冻结内容版本清单、格式与schema_version。两者保存对象引用、哈希、状态与失败，使用既有MinIO桶和jobs体系，失败不改源对象。
- Plan029在connections既有模型/服务校验能力、许可/授权依据、版本、主机、保留期和预算；Plan046—050及053/054逐来源补官方/授权证据；053/054分别为微博/知乎登录研究。未通过准入的能力保持blocked；获准后从058起续建该来源的采集、分页/评论和真实验收Plan，准入调研通过不等于FR-007-004完成。

## 5. 接口与页面

Plan028规定 `/api/followed-accounts` 管理及手动runs；Plan027规定 `/api/alerts` 配置/历史；Plan030规定报告下POST exports和独立 `/api/report-exports/{id}` 状态/下载；Plan045规定 `/api/content-exports` 受理/状态/下载。各独立router经 `api/router.py` 聚合添加 `/api`；owner/CSRF、operation_id、状态和错误由各Plan固定，运行OpenAPI后生成客户端。Web提供配置、进度、空集、失败、无权限与下载入口。上述均为目标接口；导出分别核对报告引用、CSV公式防护、JSON null、原始字段与权限。

## 6. 调度、执行与截止

来源节奏按各自准入结果固定，不直接复制B站参数；X在凭据/月度上限确认前零真实请求。账号任务复用对应来源硬截止、预算和禁用检查。告警每5分钟评估、结果/冷却同事务提交，真实送达必须使用已获准渠道。`report.export` 和 `content.export` 初始硬截止120秒，报告产物上限5MB、原始导出单请求10000条；超限明确失败/422，不以截断文件冒充完整导出。PDF使用现有Playwright/browser装配，受限本地HTML、禁脚本/远程资源/文件URL，中文字体和renderer_version固定。以上是可调整的工程保护值，修改须同步Design、Plan与测试。

## 7. 失败语义与恢复

访问拒绝、验证/登录失效、429、有限分页、删除内容和网络/解析异常分别保留；不把空页或 HTTP 200 当完整采集。登录来源遇验证/频繁立即停用并由本人核查后人工恢复，不换号或绕过。告警发送后结果未知时沿用 M5 unknown 人工确认，不自动重发；导出失败不改变源报告/内容状态。跨轮次水位只有可信页尾/时间窗证据才推进。

## 8. 安全、风控与可观测

仅个人非商业、公开或本人授权数据；每个外部 HTTP 适配器强制主机白名单及逐跳重定向校验。X 只用官方 API 且真实请求以前确认凭据与月度上限；Reddit 只走官方 OAuth，匿名 RSS 不算接入。小红书、抖音、公众号需先完成固定源码/许可、授权、实际分页/父链、限流及失败态调研，不继承 B 站成功结论。按来源/能力/时间窗显示版本、请求页数、预算、停止原因、入库/去重与缺口；导出/告警显示对象版本、权限和结果。

## 9. 验收设计要点与逐能力准入

| 能力 | 前置调研/决定 | 准入与真实验收 |
|---|---|---|
| X | 官方 API 凭据、定价/月度硬上限、端点/分页/配额 | 未确认前零真实请求；确认后只读映射、预算、错误翻译与持久覆盖逐能力验 |
| Reddit | 官方 OAuth 应用与授权、端点和配额 | 稳定 ID、分页、评论父链与重放真实验；匿名 RSS 无效 |
| 小红书/抖音 | 本人授权、固定源码/许可、账号风控与评论能力 | 各平台独立低频真实帖子/评论、验证停用/人工恢复，不能复用 B 站结果 |
| 公众号 | RSSHub 路由来源、可见范围、原始身份/时间与更新率 | 逐路由核对真实新内容、分页/缺口；RSS 可解析不等于覆盖 |
| 微博登录（053） | 本人授权、许可、入口、预算/风控 | 搜索/作品/评论/作者逐能力研究；公开热榜不算登录证据 |
| 知乎登录（054） | OPEN-001-107入口、本人授权、许可与分页/父链 | 问题/回答/文章/评论/作者逐能力研究；公开热榜不算登录证据 |
| 指定账号 | 目标授权、平台稳定账号/作品 ID、轮询频次 | 新帖/旧帖更新、去重、停用及缺口逐来源验 |
| 告警 | M3 热度/情感与 M5 实际渠道通过 | 一小时阈值、冷却、去重、unknown 与真实送达分开验 |
| 导出 | 真实有权限的报告/原始数据和格式定义 | Markdown/PDF、CSV/JSON 分别核对版本、引用、脱敏与失败 |

## 10. 决策、风险与对照

沿用 DEC-001-203/208/212/213/216/218 及 PRD DEC-001-106/108/115。X 待 OPEN-001-104、知乎登录路径待 OPEN-001-107、分页准入待 OPEN-001-108；本阶段无足够证据新增 DEC-007-xxx。风险为许可/平台规则变化、账号风控、费用越限、分页错漏、误发告警与泄露导出。对应原总设计 v3.2 §4.1—4.2、§10、§12—15 的扩展边界；历史参考：旧 Design 002 X免费采集与热点监控（已删除，见 Git 历史）、旧 Design 006 指定用户作品追踪（已删除，见 Git 历史）、旧 Design 037 费用与资源约束（已删除，见 Git 历史）、旧 Design 047 本地网页与浏览器采集（已删除，见 Git 历史）。
