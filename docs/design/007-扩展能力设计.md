# 扩展能力设计

本设计从 [总设计 001 v3.2](001-热点舆情监控平台总体设计.md) 正向拆解；总设计现为 v4.0。PRD 已为 [PRD 007](../prd/007-扩展能力需求.md)；现行计划为 [Plan 007](../plan/007-扩展能力计划.md)。本文中的“已有”仅表示代码或指定运行证据，不代表产品验收。

## 1. 范围与不包含

M6 是逐能力准入边界：报告 Markdown/PDF 与原始数据 CSV/JSON 导出；依赖 M3/M5 的突发告警；本人获授权指定账号追踪；Reddit、X、小红书、抖音、微信公众号及后续登录来源。微博/知乎登录能力仍需另行调研，六榜不能代替平台接入。不包含绕过平台验证、未定预算的付费 API 请求或以模拟/空结果宣称采集成功。现行需求/计划为 [007](../prd/007-扩展能力需求.md)/[007](../plan/007-扩展能力计划.md)。

## 2. 当前能力与证据分层

M1 来源契约、`sources/adapters/x_api.py` 的 MockTransport、内容/任务/预算底座可复用；X 无凭据/月度上限，禁止真实请求。指定账号的旧设计和部分结构可作历史参考，但当前 M6 各来源、告警、增强导出均无逐项真实运行/产品验收；不要用热榜或 B 站试点替代。

## 3. 架构与数据流

候选来源先调研官方能力、许可、授权、分页、限流、稳定 ID、评论父链和费用，再登记来源预设与能力，复用 `sources` 适配器 → `content` 持久化 → `jobs` 执行/预算/覆盖 → `analysis`。指定账号由 `monitors` 保存授权目标和规则，来源适配器只取已准入能力；已授权作者的新帖不受主题关键词过滤，分页或权限导致的未确认缺口必须可见。告警由 `events`/`analysis` 提供可追溯事实，`notifications` 在 M5 已验渠道上投递；导出从有权限的 `reports`/`content` 读取确定版本。共享 Worker/调度、错误契约和数据库门槛沿用总设计；尚无实现切片确定的新拓扑。

## 4. 领域、任务与数据状态

候选来源、指定账号、告警、导出所需表/字段和唯一键尚待逐项 Design，不预造 Schema。`followed_accounts` 为历史目标，可复核后使用；每个来源保存授权范围、能力、连接版本、预算、稳定身份、游标/缺口与失败状态。告警目标状态需区分待评估、触发、冷却、已发送/未知；导出需保存对象版本、生成格式、授权与失败证据。`alert.evaluate` 在总设计任务清单仅是目标，尚未实现；新任务类型只有对应切片确定事务、幂等与恢复后才注册。

## 5. 接口与页面

指定账号管理、逐来源状态、告警配置/历史和导出入口为候选界面；每项在 PRD/实施 Design 确认权限、正常/空/加载/部分/错误状态、操作 ID、DTO、游标、失败码和生成客户端。导出须核对报告版本/引用与原始字段脱敏；不能把尚未设计的候选端点写成已公开 API。

## 6. 调度、执行与截止

按来源预设给频率、静默、每轮词/账号数、请求/页与时间硬上限，预算账本原子预留并记录实际使用；对 X 在凭据及月度上限确认前不调度真实请求。指定账号轮询的水位必须由稳定 ID/页尾证据确认；告警一小时阈值和冷却需在 M3 事件与 M5 渠道通过后定计算窗口和去重键；导出任务只读冻结对象版本。实际截止、重试与并发须各来源调研后定，不直接复制 B 站试点数值。

## 7. 失败语义与恢复

访问拒绝、验证/登录失效、429、有限分页、删除内容和网络/解析异常分别保留；不把空页或 HTTP 200 当完整采集。登录来源遇验证/频繁立即停用并由本人核查后人工恢复，不换号或绕过。告警发送后结果未知时沿用 M5 unknown 人工确认，不自动重发；导出失败不改变源报告/内容状态。跨轮次水位只有可信页尾/时间窗证据才推进。

## 8. 安全、风控与可观测

仅个人非商业、公开或本人授权数据；每个外部 HTTP 适配器强制主机白名单及逐跳重定向校验。X 只用官方 API 且真实请求以前确认凭据与月度上限；Reddit 只走官方 OAuth，匿名 RSS 不算接入。小红书、抖音、公众号需先完成固定源码/许可、授权、实际分页/父链、限流及失败态调研，不继承 B 站成功结论。按来源/能力/时间窗显示版本、请求页数、预算、停止原因、入库/去重与缺口；导出/告警显示对象版本、权限和结果。

## 9. 验收设计要点与逐能力准入

| 能力 | 前置调研/决定 | 准入与真实验收 |
|---|---|---|
| X | 官方 API 凭据、定价/月度硬上限、端点/分页/配额 | 未确认前零真实请求；确认后只读映射、预算、错误翻译与持久覆盖逐能力验 |
| Reddit | 官方 OAuth 应用与授权、端点和配额 | 稳定 ID、分页、评论父链与重放真实验；匿名 RSS 无效 |
| 小红书/抖音 | 本人授权、固定源码/许可、账号风控与评论能力 | 各平台独立低频真实帖子/评论、验证停用/人工恢复，不能复用 B 站结果 |
| 公众号 | RSSHub 路由来源、可见范围、原始身份/时间与更新率 | 逐路由核对真实新内容、分页/缺口；RSS 可解析不等于覆盖 |
| 指定账号 | 目标授权、平台稳定账号/作品 ID、轮询频次 | 新帖/旧帖更新、去重、停用及缺口逐来源验 |
| 告警 | M3 热度/情感与 M5 实际渠道通过 | 一小时阈值、冷却、去重、unknown 与真实送达分开验 |
| 导出 | 真实有权限的报告/原始数据和格式定义 | Markdown/PDF、CSV/JSON 分别核对版本、引用、脱敏与失败 |
