# 05 事件证据与新事实

对应 [05-事件证据与新事实](../requirement/05-事件证据与新事实.md)；实施拆分见 [05-事件证据与新事实](../plan/05-事件证据与新事实.md)。需求为范围依据，本文件不表示功能已实现；进度只在仓库根目录BACKLOG。

## 设计目标

了解事件变化、新进展及原始证据，能够纠正误归并。

## 结构与交互

- 事件头部呈现摘要、当前修订、最早/最新证据时间、成员与作者数和来源分布。
- 时间线突出本轮新增事实，事实逐条关联可读材料与版本；区分事件发生时间、证据时间和发现时间。
- 热点条件显示窗口、最低样本及规则版本；误归并/拆分提交原因和预期修订，冲突不覆盖输入。

## 数据与复用边界

先核对现有入口：[backend/app/events/facts.py](../../backend/app/events/facts.py)、[backend/app/events/corrections.py](../../backend/app/events/corrections.py)、[backend/app/api/routers/events.py](../../backend/app/api/routers/events.py)。入口存在只代表可核对，不能据此宣称真实能力已验收。

优先复用现有业务身份、版本、服务与组件；展示派生值、本机阅读状态和持久事实分别处理。新字段仅在同编号需求有实际消费路径时补齐，接口/数据库的唯一合同仍在代码及schema。

## 状态与核对重点

新事实能指向证据与固定修订，热点不是简单摘要或热榜标签，关联不改变原帖身份。

读写状态使用真实回执；已有数据刷新失败保留可读内容并标过期，未知写入先核对结果。正常、空、加载、错误、无权限以及键盘行为按实际交互覆盖；静态内容无远程状态时标不适用。

视觉、组件与响应式沿用 [00-产品目标与边界](../design/00-产品目标与边界.md)；跨页状态沿用 [11-质量评测与验收](../design/11-质量评测与验收.md)；权限、安全渲染和许可沿用 [10-权限与数据生命周期](../design/10-权限与数据生命周期.md)。

## 事实差分与修订读写

一次事件更新以此前可核对修订为基准：新增事实、既有事实补证和重复转述分别呈现；程序统计成员/作者/来源，模型生成的数字不能直接作为指标。每条事实至少能回到可读原帖/评论与正文版本，缺少证据的结论保留未知。

误归并/拆分/移动→提交预期修订与原因→原子写入新的关联/事实视图→失效受影响派生结果→重读新修订。旧版用于核对，但每次读取仍执行当前许可，撤回不能通过旧修订绕过。热点窗口与最低样本由基线校准后冻结，判定引用该规则版本。
