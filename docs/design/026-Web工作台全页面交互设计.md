# Web工作台全页面交互设计

## 现状

已有首页、认证、Radar、监控、来源、内容列表/详情、事件、告警、订阅、资料和设置页面；reports 与 users 管理页缺失，topics/favorites 为旧重定向，部分复杂页状态与移动体验不完整。

## 目标

用 Next.js+TypeScript+shadcn/ui+Radix+Tailwind 全面完成所有页面，使用户从创建监控到阅读证据、处理告警和发布报告无需离开工作台。

## 非目标

不在本条复制相邻领域的数据或服务，不以纯前端假数据宣称功能完成，也不引入第二套事实源。

## 核心决策

- 信息架构固定为 Overview、Monitors、Sources、Contents、Events、Alerts、Reports、Subscriptions、Administration、Profile；移除无业务意义旧入口。
- Overview 采用 Vercel 式密集但克制的网格：关键指标、趋势事件、运行状态和快捷动作，不使用装饰性大卡片堆叠。
- 列表页统一 Search/Filter/Sort/Table-or-Card/Pagination；详情页统一 Header/Summary/Tabs-or-Sections/Timeline/Actions。
- 服务端组件负责壳和可静态内容，交互数据区使用客户端组件；复杂编辑使用 React Hook Form+Zod（引入前先确认现有依赖），基础控件只用 shadcn/ui。

## 数据、接口与交互

- 公共首页与完整认证流
- Overview、监控、来源、内容、事件和告警
- 报告、订阅、用户管理、资料与系统设置
- 响应式导航、全状态、可访问性和错误恢复

所有状态变化保存明确版本、时间和操作者；跨端字段由 Schema、后端 DTO 和生成 OpenAPI 驱动，前端不得手写重复类型。

## 安全、失败与降级

一次性视觉重写容易掩盖未接 API；每个页面必须先列真实契约和状态，再做视觉组合。

外部 AI、邮件、实时连接或归档不可用时，业务事实先可靠落库，异步重试或降级读取，不在请求链路丢失结果。

## 设计验收边界

- 导航没有死链或只重定向的遗留主入口
- 全部页面覆盖 loading/empty/error/forbidden 并可键盘操作
- 360px、768px、1280px 关键视口完成浏览器端到端验证
