# 可用性与可访问性设计

日期：2026-09-25。本文是 040 S00 的 proposed 设计提案，不代表 UI 已修复或产品验收通过。目标用户、主要浏览器矩阵和正式无障碍基线仍由 `OPEN-040-001` 待确认；在关闭前不进入 S01。

## 1. 当前事实与差距

| 位置               | 已核对事实                                                                                                                                                                                       | 设计影响                                                                                               |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------ |
| 总体信息架构       | [001 总体 Design](001-热点事件监控平台总体设计.md) 提出 `/discovery`、`/search`、`/monitors` 等目标入口；当前前端实际以 `/events`、`/monitors/new`、`/content`、`/jobs`、`/sources` 等路由组织。 | 本提案以当前页面为改进起点，不把目标路由描述成已实现，不新增导航或产品能力。                           |
| 监控创建           | `frontend/src/app/monitors/new/components/topic-form.tsx` 使用现有 `Label`、`Input` 和关键词组字段；来源未选时显示暂停，保存不会发起采集。名称帮助文字未连接到输入，字段使用 `autoFocus`。       | 保留现有表单和词组组件；窄屏不主动弹出键盘，程序化关联标签、帮助与错误。                               |
| 事件入口           | `frontend/src/app/events/components/events-workspace.tsx` 的“尚无事件”是静态内容；页面未查询事件，只在其后展示主题列表。                                                                         | 不能把静态占位文案当成查询成功的空结果；在事件数据事实接入前明确区分“当前未提供事件结果”和真实空结果。 |
| 资料与状态         | `/content`、`/content/[contentId]` 读取资料 API，并区分加载、失败、空列表、正文缺失或文本范围；资料列表加载骨架仅带 `aria-label`。                                                               | 沿用资料 API 与现有 presenter；动态状态仅在确有变化时提供可访问名称/通知，不复制业务状态。             |
| 页面框架与基础控件 | `frontend/src/app/layout.tsx` 设置 `lang="zh-CN"`，页面各自提供 `<main>`；全局没有跳过导航链接。共享 `Button` 保留 `focus-visible` 样式，但使用 `transition-all`。                               | 复用现有语义控件并补主内容跳转；如需调整共享 Button 动画，只替换为明确属性且检查所有调用方。           |
| 验证能力           | `frontend/package.json` 提供 Vitest、lint、typecheck、format、build 与 OpenAPI 检查；测试目前与组件共置，没有 `test:e2e` 脚本，也未声明 Playwright E2E。                                         | 先用现有验证链；真实浏览器入口及自动化选择留到 G2，不添加临时脚本或非必要 `.sh`。                      |

## 2. 目标与非目标

目标是让用户沿“创建监控 → 查看实际结果 → 定位原文资料”的既定流程，能判断当前是否已查询、结果是否为空、来源是否失败或只得到部分结果，并能用键盘及窄屏完成必要操作。实现复用现有路由、服务事实、shadcn/Radix 控件、Lucide 图标和共置 Vitest 测试。

本计划不创建独立的“可访问性”业务页、状态存储、后端质量表、第二套组件库或新的采集接口；不通过静态演示、颜色或自动化单测宣称 WCAG 认证或用户任务完成。无障碍标准与浏览器范围未获确认前，只将 WCAG 2.2 AA 作为待评审候选，不视为项目承诺。

## 3. 约束、依赖与未决项

- 需求来源是 [040 PRD](../prd/040-可用性与可访问性.md) 的 NFR-040-001—006 和 AC-040-001—006；语义不得偏离 001 总纲及 003/004/007/009/012/014 的业务边界。
- [046 Design](046-全局异常与响应契约设计.md) 是 API 错误及请求编号的唯一公共契约；不在前端维护第二套错误 DTO。
- [042 Plan S01](../plans/042-容量与部署可重复性计划.md) 已提供运行与契约验证前置，但不代表 040 的用户、浏览器或体验验收通过。
- `OPEN-040-001` 待产品确认：目标用户/允许的代理用户定义、主要桌面与移动浏览器、正式对照的无障碍标准/等级。暂建议 5 名样本中至少 4 名独立完成 PRD 核心任务；该数值沿用 PRD，不扩展招募规模。
- 来源真实访问、目标样本、费用与权限仍受 M0 准入约束；本设计不授权新增平台请求或付费服务。

## 4. 方案比较与选择

| 方案                                                                                 | 取舍                                                                 | 结论                                               |
| ------------------------------------------------------------------------------------ | -------------------------------------------------------------------- | -------------------------------------------------- |
| 在现有业务页和共享语义控件上修正流程、状态及窄屏行为，并使用共置测试和真实浏览器检查 | 改动贴近用户路径，可复用现有依赖；浏览器矩阵确认后才选择自动化入口。 | 采用，符合 MVP。                                   |
| 现在引入新的 E2E/无障碍框架并搭建全站测试项目                                        | 增加依赖和维护面；当前没有选定浏览器矩阵，也没有已声明 E2E 脚本。    | 暂缓；只有 G2 证明确有缺口且选型评审通过后才考虑。 |
| 新建统一状态服务、无障碍配置页或后端验收记录表                                       | 重复现有 API/领域状态，不直接解决核心任务理解。                      | 不采用。                                           |

## 5. 模块边界与事实归属

| 信息或状态                   | 事实 owner                                           | 前端呈现边界                                                                            |
| ---------------------------- | ---------------------------------------------------- | --------------------------------------------------------------------------------------- |
| 监控规则及暂停/启用状态      | 003 监控主题 API 与持久记录                          | 创建、主题列表与编辑页只显示服务端确认状态；不在页面推导来源就绪。                      |
| 来源连接与能力               | 004 连接记录及 `SourceCapabilityEvidence`            | 说明连接/来源证据的现状；不得把一次探测等同于持续可用。                                 |
| 单次执行与错误归属           | 009 `jobs` 执行记录及结果；未知归属沿用 031 保守规则 | 未运行由无执行记录表达；来源错误须有来源失败证据；无法确定时标为“未归属”，不猜测原因。  |
| 事件身份、关系与时间线       | 012 事件域；当前 `/events` 尚未接入该查询            | 查询成功后才可显示“暂无事件”；未接入/未查询需表达为功能或状态未就绪，不能伪装成零结果。 |
| 作品正文与原文依据           | 007 资料、版本与来源字段；014 检索范围               | 复用详情页的正文范围/来源信息；不提升片段、历史发现或缺失正文的证据等级。               |
| HTTP/网络失败                | 046 `ErrorView`、`ApiRequestError` 与有效 request ID | 显示安全业务文案和下一步；不透传原始异常、URL 或 HTML。                                 |
| 加载、焦点、展开等纯界面状态 | 当前页面组件内状态                                   | 不持久化、不进入数据库或 API。                                                          |

不新建公共 `Result` 外壳、可访问性状态机或副本字段；只在 UI 组合层适配已存在的类型和组件。

## 6. 状态呈现与交互

| 场景               | 必要区分与数据依据                                                                                                 |
| ------------------ | ------------------------------------------------------------------------------------------------------------------ |
| 加载               | 请求尚未结束；用简短状态文字和适当的 `role="status"`/`aria-live="polite"` 宣告异步变化，不把骨架本身当成唯一提示。 |
| 未运行             | 没有本次执行记录；解释可用的下一步，不显示为查询后的空结果。                                                       |
| 正常空结果         | 服务端查询成功且结果为零；说明查询对象/范围和可采取的动作。                                                        |
| 部分结果或来源失败 | 仅按 004 来源证据及 009 执行结果显示；文字明确标注不完整或失败，不仅改变颜色/图标。                                |
| 未归属失败         | 没有足够证据确定故障归属时使用“未归属”语义，按 031 保守计入失败，不归咎于来源。                                    |
| 输入/API 错误      | 错误邻近对应字段或操作，保留可修正输入；使用 046 安全文案和真实请求编号。                                          |

交互规则：

- 每个页面使用有序标题和语义 landmark；全局提供键盘可见的“跳到主要内容”链接，目标页面 `<main>` 稳定可定位。
- 输入使用现有 Label/表单控件；帮助和错误通过 `aria-describedby` 等正确关联，提交错误后将焦点移至第一个无效字段。
- 不依赖 hover 才能发现必要操作；可见键盘焦点、合理顺序、弹层焦点回收和 Escape 关闭行为均按实际控件验证。
- 创建主题页面默认不抢焦点，以免移动端自动弹出键盘；若目标浏览器验证表明桌面聚焦有益，再以受控方案单独评审。
- 只有结果容器可用键盘滚动时才允许局部横向滚动；URL、长中文及缺失字段需换行/截断并可读，320 CSS 像素与 200% 缩放不能遮住主操作。
- 状态文字、图标与颜色互为补充；使用现有设计系统，不为单页增加全局 CSS 例外。

## 7. 安全、隐私与可观测性

- 可用性测试只用合法、脱敏且已授权的样本；招募记录仅包含 PRD 所需的样本类型、设备/浏览器、任务完成、耗时、帮助次数和误解，不记录秘密或不必要的正文。
- 访问控制仍由各业务 API 执行；隐藏按钮不是授权边界。错误文案不展示他人数据、凭据、内部异常或任意来源 URL。
- 质量研究产物记录版本、环境、执行者角色和结论；不写入新的业务数据库表，不把单测报告伪装成用户研究。
- 使用 039/046 既有日志、request ID 和错误结构；不记录键盘输入全文、口令或原始页面内容。

## 8. 失败、降级与回退

事件 API 未接入、来源证据缺失或查询失败时，分别呈现“尚未提供结果”“未归属/不可确认”或请求错误；绝不退化成“暂无事件”。关键服务不可用时保留用户已输入内容和已持久资料的只读访问，不重复提交或伪造成功。UI 改动回退只恢复页面/组件版本；若后续证明需 API/数据契约变更，须另行扩展设计、同步 046/所属 Plan 与生成客户端，并在兼容性确认后发布；本提案不含 schema 迁移。

## 9. 验收边界与证据

当前没有用户研究、真实浏览器或本提案代码变更的验收证据；六项产品 AC 全部保持待执行。实现后按 PRD 的 AC 逐条取证，设计提案和代码级 Vitest 均不计为完整验收。

| PRD 验收       | 设计覆盖                         | 必要证据                                                                                        |
| -------------- | -------------------------------- | ----------------------------------------------------------------------------------------------- |
| AC-040-001—003 | 核心流程和状态区分               | 真实结果状态、任务脚本；至少 5 名目标/明确标注的代理用户的逐人结果，达到 PRD 门槛且无关键误导。 |
| AC-040-004—005 | 键盘、焦点、标签、错误与状态语义 | 目标浏览器键盘路径、可访问树/辅助技术核对；不以截图或 DOM 单测代替。                            |
| AC-040-006     | 窄屏、长内容和缩放               | 320/375 CSS 像素及 200% 缩放下真实页面操作记录，核对局部溢出与可达性。                          |

G2 冻结目标浏览器和测试入口后，至少执行现有 `pnpm test`、`pnpm lint`、`pnpm typecheck`、`pnpm format:check`、`pnpm build`；若改动 API，再执行 `pnpm openapi:check` 和适用后端测试。真实浏览器验证使用经 G2 选定的现有运行环境；在引入新依赖或脚本前先验证必要性与许可。
