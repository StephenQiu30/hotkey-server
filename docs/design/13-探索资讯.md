# 13 探索资讯

对应 [13-探索资讯](../requirement/13-探索资讯.md)；实施拆分见 [13-探索资讯](../plan/13-探索资讯.md)。需求为范围依据，本文件不表示功能已实现；进度只在仓库根目录BACKLOG。

## 设计目标

按关键词找事件、资讯和讨论，用来源和时间核对搜索结果。

## 结构与交互

- 搜索和类别写入URL：全部/事件/资讯/评论，普通列表30条、搜索40条、时间游标20条按各自合同读取；无查询时禁用搜索排序。
- 评论、事件需服务端检索；不能过滤首页50条冒充站内搜索。侧栏专题最多6项，“存为监控”只预填查询。

### 区域与显示边界

下面保留需求定义的区域和数量；必需字段、操作语义和业务约束以同编号需求表为准，不另建字段字典。

| 区域/操作 | 数量与范围 |
|---|---|
| 搜索与类型 | 搜索框1、类型4项 |
| 时间/情感/排序 | 3组筛选 |
| 结果行 | 普通30条；搜索40条；兼容精选时间线20条，cursor翻页 |
| 信息来源 | 站点配置的公开来源 |
| 主题/相关搜索 | 侧栏最多6个主题，完整目录单独入口；建议缺省 |
| 存为监控 | 1个CTA |

## 数据与复用边界

先核对现有入口：[frontend/src/app/discover](../../frontend/src/app/discover)、[backend/app/api/routers/publication.py](../../backend/app/api/routers/publication.py)。入口存在只代表可核对，不能据此宣称真实能力已验收。

优先复用现有业务身份、版本、服务与组件；展示派生值、本机阅读状态和持久事实分别处理。新字段仅在同编号需求有实际消费路径时补齐，接口/数据库的唯一合同仍在代码及schema。

## 状态与核对重点

不同类别分页不串用游标；搜索未知和无匹配分开；个人来源仅本人可见。

读写状态使用真实回执；已有数据刷新失败保留可读内容并标过期，未知写入先核对结果。正常、空、加载、错误、无权限以及键盘行为按实际交互覆盖；静态内容无远程状态时标不适用。

视觉、组件与响应式沿用 [00-产品目标与边界](../design/00-产品目标与边界.md)；跨页状态沿用 [11-质量评测与验收](../design/11-质量评测与验收.md)；权限、安全渲染和许可沿用 [10-权限与数据生命周期](../design/10-权限与数据生命周期.md)。
