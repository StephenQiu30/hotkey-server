# 49 运营工作区

对应 [49-运营工作区](../requirement/49-运营工作区.md)；实施拆分见 [49-运营工作区](../plan/49-运营工作区.md)。需求为范围依据，本文件不表示功能已实现；进度只在仓库根目录BACKLOG。

## 设计目标

作为独立运营人员，我需要处理运行问题并保留可审计证据。

## 结构与交互

- 运营页聚合健康、预算使用/预留/余额、版本和审计；反馈20条、通知及评测50条沿各自合同。
- 普通用户不获运营权限；侧栏不为状态轮询健康接口，诊断页读取不触发采集。

### 区域与显示边界

下面保留需求定义的区域和数量；必需字段、操作语义和业务约束以同编号需求表为准，不另建字段字典。

| 区域/操作 | 数量与范围 |
|---|---|
| 健康与维护 | 按当前API聚合 |
| 反馈与审计 | 反馈和审计20条/页 |
| 通知与评测 | 通知50条/页；评测明细50条/页 |

## 数据与复用边界

先核对现有入口：[frontend/src/app/operations](../../frontend/src/app/operations)、[backend/app/api/routers/operations.py](../../backend/app/api/routers/operations.py)。入口存在只代表可核对，不能据此宣称真实能力已验收。

优先复用现有业务身份、版本、服务与组件；展示派生值、本机阅读状态和持久事实分别处理。新字段仅在同编号需求有实际消费路径时补齐，接口/数据库的唯一合同仍在代码及schema。

## 状态与核对重点

运营权限、预算未知非零、独立区块失败和无隐式外部请求。

读写状态使用真实回执；已有数据刷新失败保留可读内容并标过期，未知写入先核对结果。正常、空、加载、错误、无权限以及键盘行为按实际交互覆盖；静态内容无远程状态时标不适用。

视觉、组件与响应式沿用 [00-产品目标与边界](../design/00-产品目标与边界.md)；跨页状态沿用 [11-质量评测与验收](../design/11-质量评测与验收.md)；权限、安全渲染和许可沿用 [10-权限与数据生命周期](../design/10-权限与数据生命周期.md)。
