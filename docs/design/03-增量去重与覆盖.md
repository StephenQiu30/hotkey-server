# 03 增量去重与覆盖

对应 [03-增量去重与覆盖](../requirement/03-增量去重与覆盖.md)；实施拆分见 [03-增量去重与覆盖](../plan/03-增量去重与覆盖.md)。需求为范围依据，本文件不表示功能已实现；进度只在仓库根目录BACKLOG。

## 设计目标

再次采集时分清新材料、重复身份、旧帖变化与未覆盖部分。

## 结构与交互

- 以来源和有界窗口组织回执，返回、新增、重复、更新分别显示并说明计数口径。
- 提供原任务、最近成功时间、预算、停止原因及过期状态；旧数据可读但不能冒充本轮结果。
- 游标循环、失效、截断和部分覆盖显式标出；完整仅针对可证明终点的有界查询。

## 数据与复用边界

先核对现有入口：[backend/app/content](../../backend/app/content)、[backend/app/sources/contracts.py](../../backend/app/sources/contracts.py)、[backend/app/api/routers/collection_coverage.py](../../backend/app/api/routers/collection_coverage.py)、[backend/app/jobs](../../backend/app/jobs)。入口存在只代表可核对，不能据此宣称真实能力已验收。

优先复用现有业务身份、版本、服务与组件；展示派生值、本机阅读状态和持久事实分别处理。新字段仅在同编号需求有实际消费路径时补齐，接口/数据库的唯一合同仍在代码及schema。

## 状态与核对重点

相似文案不误去重不同平台对象，缓存重读不当真实增量，失败不当零条或穷尽。

读写状态使用真实回执；已有数据刷新失败保留可读内容并标过期，未知写入先核对结果。正常、空、加载、错误、无权限以及键盘行为按实际交互覆盖；静态内容无远程状态时标不适用。

视觉、组件与响应式沿用 [00-产品目标与边界](../design/00-产品目标与边界.md)；跨页状态沿用 [11-质量评测与验收](../design/11-质量评测与验收.md)；权限、安全渲染和许可沿用 [10-权限与数据生命周期](../design/10-权限与数据生命周期.md)。

## 身份、观察与覆盖计算

复用content的原生身份与正文版本：同来源同原生对象再次出现是已有对象；正文或指标变化更新对应版本/观察语义，不能复制成新帖。跨平台搬运保持各自原生身份，是否属于同事件交给04判断。

| 对照情形 | 回执解释 |
|---|---|
| 相同窗口首次返回 | 给出原始返回及归档计量；不直接称全网新增 |
| 第二轮返回已有对象 | 记重复身份；若内容/指标改变，另解释更新，计数可重叠时明确分母，不把各列机械相加 |
| 空页但无终点证据 | 区分真实零结果、部分覆盖、游标异常与上游失败 |
| 到达可证明终点 | 按`SourceTerminalEvidence`核对有界窗口、排序和终点证明，才称该查询完整 |

复用`SourcePageState`及`SourceStopReason`表达more/complete/empty/partial/stopped及限流、认证、预算、游标等原因。用户可读提示映射原因，枚举与字段不在文档另定义一套。两轮对照必须保留相同账号、来源、查询、排序和窗口的可见集合基准，缓存重读不算真实增量。
