# 02 关键词采集

对应 [02-关键词采集](../requirement/02-关键词采集.md)；实施拆分见 [02-关键词采集](../plan/02-关键词采集.md)。需求为范围依据，本文件不表示功能已实现；进度只在仓库根目录BACKLOG。

## 设计目标

按关键词取得原帖及可访问评论，并知道命中原因。

## 结构与交互

- 显式运行后先显示受理回执与 job 链接，再展示采集、分析和覆盖状态；保存成功不能当采集完成。
- 结果行显示原帖、命中词、发现方式、来源发布时间与观察时间；从原帖进入可访问根评论和回复。
- 对不支持的能力、预算上限和部分结果给出原因；错误、未授权和未接入不显示为“没找到”。

## 数据与复用边界

先核对现有入口：[backend/app/sources/contracts.py](../../backend/app/sources/contracts.py)、[backend/app/sources/adapters/bilibili_chrome.py](../../backend/app/sources/adapters/bilibili_chrome.py)、[backend/app/sources/adapters/hackernews.py](../../backend/app/sources/adapters/hackernews.py)、[backend/app/jobs](../../backend/app/jobs)。入口存在只代表可核对，不能据此宣称真实能力已验收。

优先复用现有业务身份、版本、服务与组件；展示派生值、本机阅读状态和持久事实分别处理。新字段仅在同编号需求有实际消费路径时补齐，接口/数据库的唯一合同仍在代码及schema。

## 状态与核对重点

各对象有来源和时间证据；停止与预算从第一轮生效；原帖、评论和回复逐项验收。

读写状态使用真实回执；已有数据刷新失败保留可读内容并标过期，未知写入先核对结果。正常、空、加载、错误、无权限以及键盘行为按实际交互覆盖；静态内容无远程状态时标不适用。

视觉、组件与响应式沿用 [00-产品目标与边界](../design/00-产品目标与边界.md)；跨页状态沿用 [11-质量评测与验收](../design/11-质量评测与验收.md)；权限、安全渲染和许可沿用 [10-权限与数据生命周期](../design/10-权限与数据生命周期.md)。

## 有界采集处理链

主题冻结版本与窗口→来源能力/准入检查→jobs受理与预算预留→适配器查询→原帖归档与本地命中→可访问根评论/回复→覆盖结算→分析消费。沿现有jobs/outbox和content通道推进，采集结束与模型分析结束分开显示。

| 阶段 | 必须可追溯的输出 | 停止边界 |
|---|---|---|
| 受理 | owner、主题/来源/适配器版本、查询与窗口、任务回执 | 未准入、超预算或不支持的请求不发出 |
| 原帖 | 来源原生身份、原文URL、正文版本、发布时间/观察时间、命中词与发现方式 | 查询分页、条数与时间有界，风控和认证错误即停 |
| 评论与回复 | 所属原帖、可得父链、原生身份、独立分页和能力说明 | 根评论与回复分别验收，达到上限保留部分回执 |
| 交接 | 返回/新增/重复/更新与覆盖状态、可分析材料引用 | 模型不可用保留材料与积压，不伪造分析成功 |

命中记录使用冻结规则与可读文本，评论需要原帖/可得父上下文。平台评论总数独立于本轮采集数量；“支持评论”不推导“回复可用”。对应界面落点为32、36/37、44及46/47。
