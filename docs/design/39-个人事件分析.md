# 39 个人事件分析

对应 [39-个人事件分析](../requirement/39-个人事件分析.md)；实施拆分见 [39-个人事件分析](../plan/39-个人事件分析.md)。需求为范围依据，本文件不表示功能已实现；进度只在仓库根目录BACKLOG。

## 设计目标

作为所属用户，我需要理解本人事件的事实、热度和关系并纠错。

## 结构与交互

- 详情按固定事件修订呈现摘要、成员、事实、证据和趋势，成员每页20条。
- 合并/拆分/移动携带预期修订与原因；48点响应不称为24小时窗口，不同平台搬运关系保留。

### 区域与显示边界

下面保留需求定义的区域和数量；必需字段、操作语义和业务约束以同编号需求表为准，不另建字段字典。

| 区域/操作 | 数量与范围 |
|---|---|
| 概览与固定修订 | 单事件，可选择已有revision |
| 成员/事实/关联 | 成员20条/页；事实/关联按当前响应 |
| 热度与修订动作 | 历史最多48点；操作使用预期revision |

## 数据与复用边界

先核对现有入口：[frontend/src/app/events/[eventId]](../../frontend/src/app/events/[eventId])、[backend/app/api/routers/events.py](../../backend/app/api/routers/events.py)。入口存在只代表可核对，不能据此宣称真实能力已验收。

优先复用现有业务身份、版本、服务与组件；展示派生值、本机阅读状态和持久事实分别处理。新字段仅在同编号需求有实际消费路径时补齐，接口/数据库的唯一合同仍在代码及schema。

## 状态与核对重点

误合并/漏合并、传闻到确认、重复证据、冲突、撤回和跨平台身份。

读写状态使用真实回执；已有数据刷新失败保留可读内容并标过期，未知写入先核对结果。正常、空、加载、错误、无权限以及键盘行为按实际交互覆盖；静态内容无远程状态时标不适用。

视觉、组件与响应式沿用 [00-产品目标与边界](../design/00-产品目标与边界.md)；跨页状态沿用 [11-质量评测与验收](../design/11-质量评测与验收.md)；权限、安全渲染和许可沿用 [10-权限与数据生命周期](../design/10-权限与数据生命周期.md)。
