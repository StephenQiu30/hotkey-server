# 热点事件监控平台总体设计

日期：2026-09-24。本文为 001 S01 的总体设计输入，约束首版边界、核心服务能力、信息架构、领域协作、来源准入和验证顺序。当前状态为 `proposed`：已按用户确认将四个国内评论来源交给 008/047 分片承接，并补齐从监控配置到证据交付的能力地图；发现能力次序、真实样本/访问条件和实际资源仍需准备。2026-09-24 官方访问路径复核未改变四平台必需范围，但确认当前应用权限、付费和书面许可仍是不同的准入门槛。本文不代表来源已接通或产品已经验收。

## 1. 当前事实与问题

- 截至 2026-09-24，身份、任务、监控主题、连接能力证据、作品资料等内部切片已有实现，唯一网页采集处理器已注册并复用现有 Firecrawl；X 与国内平台的真实来源处理器、事件/证据/分析产品闭环及产品验收仍未完成。实现进度以 HANDOVER 和对应领域 Plan 的证据为准。
- 43 项需求和 47 份 Plan 已登记（含 047 本地采集专项），但逐项文件不能替代一个共同的产品流程、领域边界和页面导航。
- X 与国内平台的技术可抓取性、官方授权和可持续免费性是不同问题；未满足来源条件时仍可建设内部底座，但不能显示为可用来源。
- 首版面向单人自建研究工作台。团队、多模型、离线渠道和通用爬虫平台按原优先级推进；2026-09-22 用户已明确四个国内来源的评论需求，按 008/047 分片交付，不因 MVP 编排删除其中任何一个。

## 2. 目标与非目标

### 2.1 首版目标

用户能够完成一条可核查闭环：

1. 配置一个主题或确认一个账号；
2. 查看来源能力、任务状态和采样边界；
3. 发现作品并归入具体事件；
4. 阅读时间线、评论样本和引用证据；
5. 人工修订关系或观点；
6. 查看变化记录并导出当前范围的结果。

首版退出仍以 18 项 P0 功能、16 项 P0 质量要求及 X 验收为准；搜索/账号发现先验证一个国内来源，评论按用户补充在 B站、小红书、抖音、微博分别完成 008/047。阶段性受控样本只证明内部切片，不改变发布口径。

### 2.2 非目标

- 不做公共注册、组织/团队、多租户或 P2 协作。
- 不把大模型聊天、自动摘要、媒体理解或离线通知作为 P0 必需路径。
- 不建设通用爬虫编排器、代理池管理产品或平台写操作机器人。
- 不承诺全网覆盖、全量评论、平台原生排序复刻或统一的跨平台互动总分。
- 不先创建所有领域目录、页面、表或通用 CRUD；只随当前垂直切片落地。

## 3. 核心决策

| ID | 决策 | MVP 理由 |
|---|---|---|
| DEC-001-001 | 以“事件研究”而非“抓取任务”作为默认产品入口 | 用户目标是理解热点，任务和来源是可见的支撑状态 |
| DEC-001-002 | P0 采用单人、受控初始化身份；不开放注册 | 保留权限边界，同时避免提前建设团队模型 |
| DEC-001-003 | 来源按搜索、作者作品、评论、回复四种能力分别准入 | 一个接口成功不能推导整个平台可用 |
| DEC-001-004 | 所有外采均为持久任务；浏览页面只读已保存结果 | 避免页面刷新触发不可控请求、重复费用或不可恢复执行 |
| DEC-001-005 | 内容、事件、证据、分析分别拥有事实；页面只做组合 | 防止来源适配器、报告或索引成为第二套业务事实源 |
| DEC-001-006 | 基础分析先使用可解释规则和人工整理 | P0 不依赖付费或未验证模型，允许低置信弃判 |
| DEC-001-007 | 首轮 Web 复用现有 shadcn/Radix 组件，不先安装导航、图表或表格框架 | 等真实页面证明复用和交互需求后再增加依赖 |
| DEC-001-008 | 首批国内来源优先评审有官方关键词与评论授权路径的平台 | 合规、可重复验证优先于非官方 SDK 的表面能力 |

## 4. MVP 信息架构与用户流程

### 4.1 导航

公开首页 `/` 继续承担产品说明。登录后的工作台只保留四个一级入口：

| 一级入口 | URL | 用户任务 | 关联实现 |
|---|---|---|---|
| 事件 | `/events` | 查看正在发生什么、进入事件时间线和证据 | 011—013、015、016、019 |
| 发现 | `/discovery` | 查看已采集候选及来源/采样边界 | 005、021、044、045 |
| 监控 | `/monitors` | 管理主题；账号追踪从上下文进入 `/accounts` | 003、006 |
| 资料 | `/search` | 检索已保存作品、评论和事件，不触发外采 | 007、008、014 |

`/jobs`、`/notifications` 和 `/settings` 是顶栏状态/工具入口；`/sources`、`/exports` 从设置或相关业务上下文进入。首版不增加单独的 KPI 仪表盘，`/events` 的合法空态直接引导创建监控。

桌面使用语义化顶栏导航；窄屏复用现有 `Sheet` 展开同一导航。只有稳定一级入口超过六个或实际层级证明需要常驻导航时，才评估 shadcn `Sidebar`。不同时维护桌面侧栏、移动底栏和顶栏三套信息架构。[S01]

### 4.2 首次使用

`受控初始化/登录 → 事件空态 → 新建主题或确认账号 → 查看逐能力来源状态 → 保存配置 → 显式启动一次任务 → 查看任务 → 查看发现结果 → 进入事件`

- 来源未满足授权时允许保存不执行的配置，但不得显示“连接成功”或暗中发起探测。
- 合法零结果、任务延期、部分采集、来源受限和协议故障是不同状态。
- 页面刷新只查询持久状态；写操作使用幂等键，不由前端自动重试。

### 4.3 事件研究

`事件列表 → 事件概览/覆盖范围 → 时间线 → 作品与评论证据 → 讨论焦点 → 人工修订 → 变化记录/导出`

事件页以概览、时间线、讨论与证据四个渐进区域组织；不在首屏堆叠全部指标。每个结论必须能回到输入范围和引用，缺失父帖、样本截断、旧数据与不同平台口径均显式显示。

## 5. 组件与页面状态

### 5.1 复用策略

| 能力 | 当前选择 | 增加条件 |
|---|---|---|
| 导航 | `Button`、`Sheet`、`DropdownMenu` 与 Next `Link` | 一级入口稳定超过六个后评估官方 `Sidebar` |
| 筛选/表单 | `Input`、`Select`、`Switch`、`Textarea`、`Dialog` | 真实字段复杂度需要时再增加表单库，不手写第二套校验契约 |
| 列表 | 现有 `Table` 或语义列表，组件留在所属路由 | 只有实际排序、筛选、列显隐需求出现时评估 TanStack Table；不先建万能 DataTable [S02] |
| 详情分区 | 标题、语义背景、`Tabs` 及锚点 | 窄屏不得把关键失败或覆盖信息藏在默认不可见 Tab |
| 页面反馈 | `PageState`、字段错误、确认对话框 | 持久失败保留下一步；短时操作反馈随首个真实写操作选择，不先安装 Toast 依赖 |
| 图表 | 先用数值、表格和可访问文本 | 015 Design 明确趋势交互后再选图表库 |
| 图标 | 现有 `lucide-react` | 不引入第二套图标库或自绘占位图 |

shadcn 官方将 Sidebar 定义为可组合但结构复杂的应用组件；Data Table 指南也建议先按具体数据和交互构建，再在出现稳定复用时抽取。本文因此登记可用组件，但不把“组件存在”变成提前安装或全局抽象。[S01][S02]

### 5.2 状态语义

每个业务页面至少设计以下状态，但只实现当前切片可达的分支：

| 状态 | 展示原则 |
|---|---|
| loading | 保留页面结构，避免把加载写成空结果 |
| empty | 说明当前筛选/配置范围，并给一个主要下一步 |
| data | 展示结果、范围、更新时间和必要操作 |
| partial | 保留已取得结果，同时说明缺口、原因和是否可继续 |
| stale | 展示最后成功时间；刷新失败不清空旧数据 |
| error | 稳定原因、恢复动作和 request ID；不展示异常字符串 |
| forbidden | 不暴露资源正文或存在性，只提供返回/重新认证入口 |

来源能力状态沿用 004 的“未配置、待验证、可用、部分可用、需登录、受限、停用”；任务状态沿用 046/009 的 `queued → running → succeeded / partial / failed / cancelled`。页面状态不得覆盖或重新解释业务状态。

## 6. 系统与领域边界

```text
Web (generated client)
        │
FastAPI Router ── dependency injection ── Domain Service ── PostgreSQL
                                              │                 │
                                              └── Outbox ── Kafka ── Worker
Sources Adapter ── normalized DTO ────────────┘
Evidence Adapter ── MinIO manifest/object
Redis ── cache/rate limit/rebuildable state only
```

- `identity`：初始化身份、会话和资源授权。
- `monitors`：主题、账号观察和来源选择；不保存作品事实。
- `sources`：纯能力契约与平台适配器；无 ORM，不决定事件归属。
- `content`：作品、评论、回复、版本和指标快照的唯一事实。
- `jobs`：任务、尝试、预算、租约、Outbox 和恢复；Kafka/Redis 不成为唯一状态。
- `events`：事件身份、内容归属、时间线及人工合并/拆分约束。
- `evidence`：引用、对象清单、证据版本和生命周期；MinIO 不承担业务查询。
- `analysis`：可复算分数、样本范围、观点与分析版本。
- `notifications`、`exports`、`audit`：分别持有变化记录、交付产物和脱敏操作审计。

跨领域同步写入显式共享同一 Session，由最外层用例提交；异步扩散使用业务事务中的 Outbox。不得通过 API 路由、前端或来源 SDK 直接拼装跨领域事实。

### 6.1 核心服务能力地图

该地图将首版 P0 主路径映射到已有领域与执行计划，不新增通用服务层、空目录或第二套事实存储。平台具体接口仍由子 Design 冻结；来源的实际可用性按单平台、单能力分别验收。

```text
监控与账号配置
      ↓ 版本化采集意图、逐能力准入
持久任务与来源采集 ──→ 唯一作品/评论资料
                              ↓
事件发现与研究 ←──────────────┘
      ↓ 固定范围与输入版本
证据化分析与人工修订
      ↓ 可解释变化
站内通知与报告/导出

全链路保护：身份/权限 · 请求与费用预算 · 幂等/恢复 · 审计/可观测 · 删除/保留
```

| 能力 | 用户可见结果 | 事实与执行主责 | 计划映射 |
|---|---|---|---|
| 监控与账号配置 | 创建、版本化、预览、暂停主题或确认关注账号；能看出每个来源的具体能力状态 | `monitors` 持有用户配置，`connections` 持有连接版本与验证证据，`sources` 声明来源能力；保存配置本身不外采 | 003、004、006；来源扩展接 005/021 |
| 持久任务与资料采集 | 显式启动后可跟踪进度、取消/恢复、预算与部分结果；作品、评论、观察和采样缺口可回查 | `jobs` 持有执行、预算、尝试与恢复；`sources` 适配器返回标准 DTO；`content` 持有唯一平台内容及不可变观察/发现关系 | 005—010、031、037、038、042；平台路径由 002/047 与各来源专项承接 |
| 事件发现与研究 | 从已保存资料识别候选、排序和检索事件，查看时间线，并能人工纠正跨平台关联 | `content` 仍是作品/评论事实源；`events` 持有事件身份与人工关系；`analysis` 持有带口径的派生排序，检索不隐式外采 | 011—014、019、028、029、041 |
| 证据化分析与修订 | 看讨论焦点、趋势、样本范围和精确引用；修订可追踪，旧版可辨认 | `analysis` 持有带输入范围/方法版本的结论；`evidence` 持有引用清单、证据版本和对象生命周期；人工判断不改写来源原文 | 015、016、028、036、041 |
| 变化与成果交付 | 查看去重的站内变化记录，按权限生成可回查的报告/导出 | `notifications` 持有变化及发送状态；`exports` 持有生成产物与范围；二者都是派生交付，不取代事件、内容或分析事实 | 017、018、020；离线渠道仅在 024/P1 单独验收 |

身份授权、来源/连接能力、请求与费用预算、任务幂等和恢复、审计与运行状态、保留/删除与备份是贯穿以上能力的保护条件，不是可以绕过的“基础设施后补项”。对应由 027—042 及各业务 Plan 在真实链路中验收；计划名称或模拟测试通过不等于产品能力可用。

首版之外的能力继续复用上述主责，不另造旁路：021/044/045 扩展来源发现，022/023/043 扩展分析与媒体上下文，024 扩展离线通知，025 复用检索/证据，026 仅在多人协作评审通过后扩展身份授权与审计。各项仍按 P1/P2 独立准入，不成为核心主路径前置。

### 6.2 跨能力服务契约

1. **配置与执行分开：**保存/预览只写配置；任何外采都由持久任务触发，受理成功前任务与 Outbox 已提交，页面读取不直接调用来源。
2. **准入按能力细分：**执行前核对当前连接版本、来源政策、权限与预算；关键词搜索、作者作品、评论和回复分别可用或受限，不能由其中一项推导整个平台已接通。
3. **来源和内容分责：**适配器仅映射受限响应为来源 DTO，不访问 ORM；内容服务用稳定来源 ID 幂等保存作品/评论、版本/观察及其发现依据。
4. **事实和派生分开：**事件归属、分析与排序能回到原始内容和输入版本；人工修订记录新关系/结论版本，不覆盖来源资料。
5. **证据和交付可追溯：**分析引用具体输入范围、采样边界与方法版本；提醒/导出重复执行幂等，并在读取和生成时检查当前权限、删除与保留状态。
6. **保护边界贯穿调用链：**请求/费用预算在网络动作前预留并按结果结算；失败保留可见任务状态和恢复边界；PostgreSQL 是业务事实，Kafka/Redis 不成为唯一业务状态。

本节是依赖与职责图，不预先冻结各 Plan 的字段、端点、表或 UI 组件。现有 FastAPI/OpenAPI 生成链、来源适配器边界和 shadcn/Radix 组件足以承载首版；每个垂直切片仍须证明具体复用价值后再抽象或加依赖。

## 7. 数据、API 与执行顺序

每个垂直切片遵循同一顺序：

1. 领域 Design 冻结实体身份、缺失值、状态、权限、保留和幂等键；
2. 同批更新 `database/schema.sql` 与 SQLAlchemy Model；
3. Service 实现事务，必要时写 Outbox；
4. Worker/Adapter 实现有界执行、取消、预算和错误归类；
5. Router 只做 HTTP 与依赖注入，声明实际错误响应；
6. 从运行时 OpenAPI 生成 Web 客户端；
7. 页面组合生成 DTO，并验证正常、空、部分、失败和权限分支；
8. 在隔离真实依赖上验证，再按来源条件执行有界真实探针。

浏览页面不发起外部网络；创建或重跑外采返回 `JobAcceptedView`，持久提交任务和 Outbox 后才能返回 202。列表统一使用不透明 cursor；文件、204 和错误遵循 046，不另建 Result 外壳。

## 8. 来源准入与当前结论

截至 2026-09-24，准入复核仅查阅官方公开文档，未登录平台、申请权限或执行采集。准入顺序固定为：官方接口/授权 Feed → 明确书面许可 → 合规人工导入；非官方组件只能作为受控技术候选，不能绕过平台条款。

| 来源 | 当前一手资料结论 | B00 状态 |
|---|---|---|
| X | 现行条款要求使用已发布接口或另行书面许可，并明确禁止未经许可的抓取；twscrape 有搜索、作者和回复技术能力且为 MIT，但其自身也提示账号与平台风险 [S03][S04] | 自动采集 `blocked`；取得官方 API 资格或书面许可前不得启用生产适配器 |
| 抖音 | `item.comment`/回复接口需应用权限与用户授权；关键词 `video.search` 为默认关闭的特殊权限 [S05][S06][S10][S11] | 官方候选；取得具体应用 scope、授权账号和作品范围前不启用 |
| 微博 | 官方 CLI 声明有搜索/评论能力，但需开发者认证；体验限时限次，正式服务按积分计费 [S07][S12][S13] | 不满足当前可持续零付费约束；保留候选，不调用正式付费接口 |
| B站 | 用户协议要求自动程序获取平台服务、内容或数据前取得明确书面许可；公开文档未找到通用第三方评论读取出口 [S08][S14] | `blocked`；取得书面许可或适用官方接口后再评审 |
| 小红书 | 当前公开 scope 仅 `basic_info` 已开放，`read_notes` 尚在规划，API 参考未列评论读取能力 [S15][S16] | 当前官方能力不满足评论采集；等待官方权限或明确授权 |

本表是截至 2026-09-24 对公开官方资料的路径核对，不是对每个平台所有免费/自建路径的最终结论。四平台评论均为必需；准入仍绑定具体实现/能力/范围。某条官方路径收费或权限不足不自动排除整个平台，也不证明其他路径已获准。未满足条件时保留对应未完成项，不静默删除平台或把受控样本记为实采成功。

## 9. 安全、生命周期与可观测性

- 首次部署必须有受控身份初始化和恢复；无有效身份不能进入工作台。
- Token、Cookie、查询正文、原始响应和连接字符串不进代码、通用日志或普通导出；业务库只保存必要的 `secret_ref`。
- 外部 URL 使用允许域名/路径、重定向、DNS、类型和体积限制；外部正文仅作为不可信数据。
- 记录发布时间、首次发现、入库、最后尝试和最后成功；缺失值不补零。
- 每次来源请求、翻页和重试均计入预算；达到限制时延期或部分完成，不切换付费服务。
- 删除和撤权传播至索引、分析、导出、缓存及备份恢复约束；各领域 Design 冻结具体保留期。
- 访问日志与任务日志使用 request/job ID 关联，保留来源、阶段、安全错误类别和下一步，不记录原始敏感输入。

## 11. 失败、迁移与回滚

- 来源拒绝、授权失效、预算耗尽或解析不兼容时，只停止受影响能力；历史资料保持可读并标记陈旧。
- 持久化失败时不得先返回受理成功；Worker 中断从持久状态恢复，重复投递不产生重复实体或通知。
- 适配器版本升级先跑冻结样本和有限探针；失败回退版本并保持业务 DTO 与历史数据兼容。
- 数据结构目前只支持新库完整初始化。后续变更先确认备份/导入策略，不在应用启动时自动迁移。
- Web 页面按切片发布；未接通的入口隐藏或明确不可用，不放置无行为的占位导航。

|---|---|

| `frontend/src/components/<feature>/` | 至少两个页面稳定复用后的领域组件 |
| `frontend/src/components/ui/` | 经官方 shadcn CLI 审阅后加入的基础组件源码 |
| `frontend/src/api/`、`request.ts` | 生成端点/DTO与唯一传输层，不手改生成文件 |
| 根 `compose.yaml` | 唯一编排；由 042 S01 建立并验证真实隔离依赖 |
