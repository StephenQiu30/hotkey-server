# 21 公开固定刊期阅读

对应 [21-公开固定刊期阅读](../requirement/21-公开固定刊期阅读.md)；实施拆分见 [21-公开固定刊期阅读](../plan/21-公开固定刊期阅读.md)。需求为范围依据，本文件不表示功能已实现；进度只在仓库根目录BACKLOG。

## 设计目标

阅读一份固定日报，通过目录和证据理解当天事件。

## 结构与交互

- 固定kind/key/修订读取一份刊期，约3要点、10社媒行、4事件组是设计目标；不足时如实显示，不补造。
- edition-columns保留正文、社媒表和事件双栏；情感用冻结快照，历史导航最多5期，打印恢复文档流。

### 区域与显示边界

下面保留需求定义的区域和数量；必需字段、操作语义和业务约束以同编号需求表为准，不另建字段字典。

| 区域/操作 | 数量与范围 |
|---|---|
| 报头 | 固定1期 |
| 今日要点 | 原稿3条；实际依据合法引用 |
| 今日社媒热点 | 原稿10行 |
| 重点事件 | 原稿4组 |
| 舆情提示 | 1个提醒区 |
| 辅栏 | 往期最多5条 |

## 数据与复用边界

先核对现有入口：[frontend/src/app/reports/[reportId]/[key]](../../frontend/src/app/reports/[reportId]/[key])、[backend/app/api/routers/publication_editions.py](../../backend/app/api/routers/publication_editions.py)、[刊期正文](../../backend/app/api/routers/publication.py)。入口存在只代表可核对，不能据此宣称真实能力已验收。

优先复用现有业务身份、版本、服务与组件；展示派生值、本机阅读状态和持久事实分别处理。新字段仅在同编号需求有实际消费路径时补齐，接口/数据库的唯一合同仍在代码及schema。

## 状态与核对重点

不存在刊期、旧修订、导航上限、移动布局及打印；更新最新刊物不改固定刊期。

读写状态使用真实回执；已有数据刷新失败保留可读内容并标过期，未知写入先核对结果。正常、空、加载、错误、无权限以及键盘行为按实际交互覆盖；静态内容无远程状态时标不适用。

视觉、组件与响应式沿用 [00-产品目标与边界](../design/00-产品目标与边界.md)；跨页状态沿用 [11-质量评测与验收](../design/11-质量评测与验收.md)；权限、安全渲染和许可沿用 [10-权限与数据生命周期](../design/10-权限与数据生命周期.md)。
