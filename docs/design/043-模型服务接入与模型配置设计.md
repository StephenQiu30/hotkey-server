# 模型服务接入与模型配置设计

日期：2026-09-17。本文为 proposed，与 [调研](../research/043-模型服务接入与模型配置调研.md)、[PRD](../prd/043-模型服务接入与模型配置.md) 和 [Plan](../plans/043-模型服务接入与模型配置计划.md) 共用 043；不是已运行架构。


用户已确认两种信息获取入口都需要：044 采集平台自身公开信息，045 通过模型联网工具检索外部线索。本项仅提供模型连接/配置基础；044 不依赖模型推理，045 显式复用本项能力。详见 [044 PRD](../prd/044-模型平台信息采集与变更监控.md)、[045 PRD](../prd/045-模型联网检索与线索采集.md)。

## 1. 当前事实、目标与非目标

当前仓库只存在文档，未重建模型服务。022 定义自动分析产物，但没有模型接入和选择机制。本设计补齐通用连接、目录、任务配置、执行约束和使用量；不新增 Agent 服务、Node 后端、计费商城或模型训练。

沿用 FastAPI、SQLAlchemy 2、Kafka 消费者与 Redis 和 Next.js，模型 SDK 只在 `ai/adapters`。本地优先，外部默认禁用；收费和未知路线拒绝执行。开放权重许可、运行时开源许可、外部托管条款分别管理。

## 2. 方案比较和决策

| 方案 | 优点 | 限制 | 选择 |
|---|---|---|---|
| 每个分析功能直接使用供应商 SDK | 起步代码少 | 重复秘密、预算、回退和能力判断 | 不采用 |
| 薄适配器＋业务配置/预算服务 | 复用成熟协议，差异可测，保留业务事实 | 需要少量标准化契约 | 本期建议 |
| 追加独立代理/多 Agent 平台 | 可集中管理更多供应商 | 多一层部署、凭据和计量，当前价值未证明 | 暂不引入 |

承接 PRD 的 DEC-043-001：不把供应商的默认自动回退当作业务授权。SDK 是否采用、版本和网络协议在 S00 锁定；使用成熟客户端不免除端点能力验证。Vercel AI SDK UI 暂不纳入 043 设置页，025 确需流式问答时再做协议设计。

## 3. 模块边界和调用链

| 模块（拟建/拟改） | 主责 | 禁止承担 |
|---|---|---|
| `analysis/models.py / schemas.py / services.py` | 模型连接业务档案、用途配置版本、分析运行和输出；服务管理事务 | 直接在路由内调 SDK |
| `ai/contracts.py`、`ai/adapters/` | 目录/能力查询、推理协议转换、错误分类、标准化返回；本地、OpenRouter、Vercel 各适配器 | ORM、业务授权、队列状态、决定是否付费 |
| `jobs/` | 持久任务、预算预留、租约、尝试、取消与恢复，复用 009/031/037 | 为模型另建一套队列/预算账本 |
| `identity/`、`audit/` | 复用凭据存取边界和脱敏审计；模型密钥与社交会话有独立资源类型 | 将密钥交给浏览器或把正文写进通用日志 |
| `evidence/` | 经授权的输入集合、输出证据和失效关系 | 把原文永久复制到模型日志 |
| `api/routers/model_services.py` | 注入服务、输入校验、认证、稳定错误与受理结果 | ORM / SDK / 执行器直连 |
| `frontend/src/app/features/model_settings/` | 连接、模型卡、用途配置、测试与用量界面 | 持有供应商密钥、复制后端预算规则 |

资料或已授权检索查询 → 当前权限与用途配置解析 → 数据最小化 → 能力/费用/路由资格检查 → 原子预算预留与任务受理 → Worker 派发前再次检查当前约束 → 适配器 → 结果验证/使用量对账 → 待复核分析及证据。目录同步为只读元数据请求；推理测试为独立持久任务，不能被保存设置隐式触发。

跨领域仅通过所属模块服务/DTO 交互；原子写入使用明确共享 Session，由编排服务拥有事务，不直接导入其他领域 ORM。043 扩展 analysis 的共用职责，022 只接入用途结果，避免两个模型注册表。

## 4. 数据设计与状态

以下为逻辑对象，是否独立成表于 S00 按现有切片输出确定，不预建空表。

| 对象 | 核心字段和约束 |
|---|---|
| ModelConnection | owner_id、provider_kind、approved_endpoint_ref、secret_ref/version、enabled、policy_version；秘密本体复用安全存储，不回读 |
| ModelCatalogSnapshot / ModelEntry | 连接、完整 ID、fetched_at、原始来源摘要、能力/价格/政策字段与未知原因；快照不可变；唯一键至少含连接、ID、版本 |
| TaskModelProfileVersion | 用途、模型/目录版本、所需能力、prompt/schema_version、参数/上限、路由白名单、data_policy_ref、评估引用；draft/validated/active/retired |
| AnalysisRun | owner、任务/输入集合版本、profile_version、输出/人工复核状态；业务输出仍由 analysis 管理 |
| ModelAttempt | run/job ID、序号、供应商 request ID、请求/实际 model 和 provider、状态/延迟、usage/cost 来源；无返回时 unknown，不能伪造实际提供方 |
| BudgetReservation | 复用 jobs 的账户/连接/用途维度计数、预留、结算和计量未知状态；相同任务重投不重复预留 |

连接启停与健康状态分开：`disabled/enabled` 不等于 `unverified/available/degraded/auth_failed`。目录状态 `fresh/stale/withdrawn` 独立。任务可到 `succeeded/failed/cancelled/partial/unknown`，流式 HTTP 200 之后的 error 仍是失败/部分结果，不算成功。

“模型已验证”按连接、端点、模型、用途、配置版本记录；摘要验证不能放行立场或 OCR。激活新版本不改旧运行记录；任何版本不得绕过当前撤权、删除、停用和更紧预算。

## 5. 费用和路由的强制边界

1. 对每个候选请求解析全部适用计费维度；缺失字段默认 unknown，只有官方明确不适用才记 N/A。零输入输出价格不足以证明工具/媒体/附加项免费。
2. 当前仅允许 local 或资格有效的 zero_price；free_credit / paid / unknown 只作目录展示。没有预算、目录已陈旧或无法确认费用政策时不向上游发请求。
3. 账户级请求预算跨密钥共享；原子预留覆盖并发、探测、重试和候选本地回退。token 子项按提供方语义去重，不重复相加缓存/推理已包含项；资源和货币分账。
4. OpenRouter 明确完整免费 ID、提供方范围、必要参数和数据政策，默认关闭上游 fallback；`max_price` 仅为纵深措施，不能替代本地所有费用维度判断。无符合条件的端点时结束为 policy_blocked。
5. Vercel 仅为已核查零单价和免费账号资格建立候选；付费层 BYOK、自动充值、收费附加项全部禁用。不能证明网关不存在收费路由时不启用该连接；不虚构“已经禁用系统凭据回退”的参数。
6. 网络超时后供应商是否执行可能未知：保留尝试并阻止自动重发，若有无推理副作用的查询则对账；无法对账由用户显式决定新尝试。幂等保障业务结果唯一，不能声称远端推理恰好一次。

配置中的请求/时间/token 目标是本地上限，不等于提供方 SLA。额度耗尽不提出购买作为继续核心分析的必要步骤。

## 6. API 与交互

候选资源：`/api/model-connections`、`/api/model-catalog`、`/api/model-profiles`、`/api/model-runs`。连接创建/更新返回脱敏 DTO；目录同步不推理；`POST /api/model-connections/{id}/tests` 显式受理 202；运行查询和取消沿用 jobs。统一 operation_id、权限、幂等键、分页和错误 Schema，G2 冻结后由 FastAPI 生成 OpenAPI，再生成前端客户端。

测试请求只选允许的合成样例及任务类型，不能传任意 URL 或 secret 字段。错误建议分类：credential_invalid、catalog_stale、capability_unsupported、cost_policy_blocked、data_policy_blocked、quota_exhausted、provider_unavailable、result_unknown；HTTP 状态与重试语义在 API SPEC 冻结。

页面包含四个区域：服务连接、模型卡、用途配置、运行/用量。模型卡展示“本地计算 / 零单价 / 赠送额度 / 收费 / 未知”，能力区展示“提供方声明 / 本用途已测”。不合格项可阅读但不能激活。设置页无需聊天窗口；模型细节和账单解释采用渐进展开。

## 7. 数据外发、网络和可观测性

外部连接默认关闭，开启需记录服务、主题/用途、字段及政策版本；每次派发复查。秘密、内部备注及不必要的个人标识不进入提示。可识别正文仍按真实外发处理，删除姓名不等于自动匿名化。默认要求经核查的上游零保留；不能保证条件时禁止外发，保留本地方案。

外部端点固定 HTTPS 白名单，禁止任意跳转、内网/元数据地址和 DNS 变更造成绕过；本地运行时是明确登记的私网目标例外，限定主机端口和访问范围。模型输出和采集正文均为不可信数据，不能增加工具权限或执行动态代码；045 明确授权的只读检索用途单独受控，普通分析用途不自动获得工具权限。

记录 request/run/attempt ID、模型与策略版本、耗时、token/资源和错误类。通用 HTTP 日志沿用规范，不能加入 prompts、账号标识或原始 URL。详细输出保留在有权限和保留期约束的业务证据中。删除传播至配置引用的输入和派生物；审计仅保留必要状态/摘要，恢复后重放删除记录。

## 8. 失败、兼容与回退

目录查询失败保留上次快照并标陈旧；模型下架冻结新运行。可重试错误有次数/时长上限并遵循 Retry-After；所有重试重新检查资格。中断流保存必要诊断，不能合并为已确认完整分析。

本地回退必须事先登记兼容用途、资源和质量门槛；不因“本地”就自动放行。全部模型不可用时回到原文、统计和人工，不删除已确认结果。撤销密钥停止未来请求，在途请求能取消则取消，不能承诺远端未发生消费。

迁移只随实际切片建立新增兼容结构；已有任务绑定不可变版本。回退先关闭新派发，保留运行记录和对账状态，再回退兼容程序/配置，禁止删表/卷清账。外部未验证路线不能影响本地路径发布，但不得据此宣称全部提供方接入通过。

## 9. 未决项、风险与验收

OPEN-043-001/002 与 RSK-043-001—003 以 PRD 为唯一清单；本设计不另造已批准决定。初期仅完成文档和公开目录核查。Plan 的 S01—S03 分别验证连接/目录、用途/数据政策、预算/运行退化；S04 执行全部 AC-043-001—006 与受影响 NFR。

真实提供方证据必须记录账号资格（脱敏）、模型/目录/政策版本、请求结果与用量；没有它只能报告适配器契约验证，不能报告生产可用。供应商宣称的上下文、限额或零保留不是 HotKey 的性能/隐私验收结果。
