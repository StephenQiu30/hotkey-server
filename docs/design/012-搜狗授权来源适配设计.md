# 搜狗授权来源适配设计

## 现状

参考项目通过搜狗网页搜索采集热点。2026-08-07 核验到的搜狗官方开放平台只说明站方向搜狗提交结构化资源、Sitemap 或站内搜索代码，没有公开可验证的服务端搜索结果读取契约。公开资料缺失不等于搜狗永远不提供商业合作接口，但在 HotKey 获得书面授权、固定端点和测试凭据前，不能把网页搜索页当成 API。

## 目标

在来源目录展示可解释的“需要授权”能力与准入清单，但不增加 `SourceType`、不创建连接、不进入调度。只有获得书面授权、稳定读取接口和明确条款后，才以新的设计版本实现关键词采集。

## 非目标

不使用未授权网页抓取、浏览器会话、验证码绕过或不稳定私有接口补齐能力；本条不实现其他编号的业务细节。

## 核心决策

- 不得解析搜狗搜索结果页、绕过验证码或复用浏览器 Cookie。
- `SourceType` 只能在授权契约落地后加入；当前 UI 只显示“需要授权”的静态能力卡片，不提供创建、探测或启用操作，也不写入可调度连接。
- 准入清单必须同时具备：书面读取授权与条款、固定 HTTPS 端点和认证 scope、服务端 `env:NAME` 凭据、配额与分页规则、删除同步义务、可控沙盒/fixture 和契约测试。
- 未来授权适配器复用既有协议中立 `Connector` 端口，实现 `Validate`、`Fetch` 与 `Health`；在契约测试通过前不得注册到 Connector Registry 或数据库来源枚举。
- 授权适配器必须实现固定端点、凭据引用、速率限制、分页、删除同步和原始字段证据。
- 若无读取授权，以站点官方 RSS/Atom 或其他已批准来源覆盖信息需求，不声称数据来自搜狗。

## 数据、接口与交互

- 前端来源目录中的不可调度能力卡片与官方说明链接
- 管理员可见但不可操作的授权准入清单
- 复用既有 Connector 端口的解除阻塞条件
- 禁止搜狗 HTML 搜索页抓取的架构门禁

跨端契约先修改 Schema 与后端注解，再生成 OpenAPI 和前端 Client。来源能力必须在发布监控前可检测，禁用或阻塞状态不能进入调度。

## 安全、失败与降级

当前缺少可验证的公开读取接口，因此“搜狗关键词采集能力”保持 blocked；012 任务本身可以在交付授权说明和技术门禁后通过验收。不得为了功能数量牺牲合规。

第三方失败按认证、限流、临时、解析和永久错误分类；关闭单个来源不影响历史证据和其他来源。

## 设计验收边界

- 未配置授权合同时系统无法发布搜狗来源
- 没有任何 HTML 搜索页抓取实现
- 授权版本通过契约测试和新一轮验收后才可加入来源注册
- 管理员和只读用户都能理解该能力为什么不可用，且页面没有伪造的来源连接或可执行操作

## 官方依据

- [搜狗数据开放平台帮助](https://data.open.sogou.com/data-resource/help.html?type=1)：描述站长提交 XML 结构化资源，由搜狗抓取并展示。
- [搜狗数据开放平台](https://data.open.sogou.com/data-resource/index.html)：官方流程为资质提交、数据提交、审核和上线。
- [搜狗站内搜索代码](https://help.sogou.com/code.html)：提供嵌入网页的搜索代码，不是服务端结果读取 API。

以上依据只支持“当前未发现公开读取契约”的保守结论；若后续获得非公开商业授权，必须保存合同版本、条款、端点、scope、配额和删除义务，并重新走 Design → PRD → Plan → Acceptance。
