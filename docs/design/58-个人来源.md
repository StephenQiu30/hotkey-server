# 58 个人来源

对应 [58-个人来源](../requirement/58-个人来源.md)；实施拆分见 [58-个人来源](../plan/58-个人来源.md)。需求为范围依据，本文件不表示功能已实现；进度只在仓库根目录BACKLOG。

## 设计目标

维护本人RSS、网页或JSON来源，独立控制采集与公开许可。

## 结构与交互

- RSS/网页/JSON来源按本人范围列出和编辑，默认关闭、显式保存版本；保存不发外部请求。
- 说明各发现能力与准入条件，个人来源不自动进入公开探索或任意关键词搜索支持列表。

## 数据与复用边界

先核对现有入口：[frontend/src/app/sources/personal](../../frontend/src/app/sources/personal)、[backend/app/api/routers/personal_sources.py](../../backend/app/api/routers/personal_sources.py)。入口存在只代表可核对，不能据此宣称真实能力已验收。

优先复用现有业务身份、版本、服务与组件；展示派生值、本机阅读状态和持久事实分别处理。新字段仅在同编号需求有实际消费路径时补齐，接口/数据库的唯一合同仍在代码及schema。

## 状态与核对重点

他人ID/游标替换、恶意URL、默认关闭、保存无外部请求和版本冲突。

读写状态使用真实回执；已有数据刷新失败保留可读内容并标过期，未知写入先核对结果。正常、空、加载、错误、无权限以及键盘行为按实际交互覆盖；静态内容无远程状态时标不适用。

视觉、组件与响应式沿用 [00-产品目标与边界](../design/00-产品目标与边界.md)；跨页状态沿用 [11-质量评测与验收](../design/11-质量评测与验收.md)；权限、安全渲染和许可沿用 [10-权限与数据生命周期](../design/10-权限与数据生命周期.md)。
