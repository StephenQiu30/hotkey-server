# 平台与连接管理设计

日期：2026-09-22。本版接受 004 S00—S02 与 S03 先行证据版本屏障：S01 已实现能力目录、状态投影和只读 API/UI；S02 已实现分立的 probe/persisted read 证据登记、owner 幂等和入口隔离；S03 先行片已校验显式执行版本并拒绝更换/停用后的迟到新增写入。受控记录只证明机制；当前仍没有真实平台连接、令牌、探测或持久采集证据，连接更换/停用 HTTP/UI 和真实产品验收仍留在 S03—S04。

## 1. 当前事实与范围

- `sources` 已由 038 冻结为无 ORM 的纯能力 DTO 与适配器端口；`evidence` 的 `source_access_policies` 只负责准入、字段最小化和生命周期，不是连接运行状态。004 不把连接 ORM 塞入 `sources`、`evidence` 或 `monitors`。
- 034/035 已提供服务端会话、CSRF、单 owner 与默认拒绝边界；038 已提供 `search`、`author_posts`、`comments`、`replies` 四种唯一能力枚举。S01 复用这些事实源。
- 002 S01 已提供受控 X 适配器，但当前没有获授权的真实 X 或国内平台连接、固定样本或持久采集证据。开发库中的受控记录只能验证机制和页面，不关闭任何产品 AC。
- S01 只增加能力矩阵读取闭环；S02 只增加领域证据写入和显式 CLI 登记入口。两个切片都不新增依赖、外部请求、Worker 处理器、Redis/Kafka/MinIO 用法、服务、脚本或 `.sh`。

## 3. 领域与唯一事实源

新增 `connections` 领域，只拥有连接身份、不可变连接版本、能力验证证据及状态投影；它依赖 `identity` 的 owner 规则、`sources.contracts.SourceCapability` 和 `evidence` 的当前准入事实，不依赖具体适配器。

```text
API / Web
   │
   ▼
connections ──读取──> evidence source access policy
   │                         │
   └──引用 SourceCapability──┘
                             ▼
                  sources/contracts.py
```

- `sources`：平台无关请求/结果与适配器端口；继续无 ORM。
- `connections`：平台目录、owner 连接、连接版本、验证证据和能力状态。
- `evidence`：允许以何种依据处理哪些字段、保留多久；批准不等于连接可用。
- `jobs`：后续任务受理、预算和执行；S01 不创建 job。
- `content`：后续作品/评论事实；只有可重新读取的持久记录才能作为 S02 的 `persisted_read` 成功证据。

S01 不建立 Repository、插件注册器、通用状态机框架或第二份 `SourceCapability`。

## 4. 目录与状态语义

产品目录是代码内受评审的小型只读定义，不由前端或平台响应动态扩张：X 为 `required`，抖音为 `candidate`；候选不等于已选定。每个平台列出产品要求的四种能力和官方接入条件，不把官方文档声明写成实测支持。

### 4.1 原子能力状态

| 状态 | 判定 |
|---|---|
| `unconfigured` | 没有当前 owner 的连接；只展示接入条件。 |
| `pending_verification` | 有连接但当前版本没有可放行的持久读取证据，或只有探测成功/瞬时失败。 |
| `available` | 当前连接版本、当前入口已有 `persisted_read/succeeded`，且当前准入政策仍为 approved + enabled。 |
| `authentication_required` | 当前版本最新证据明确为登录/令牌失效。 |
| `restricted` | 产品费用边界、准入政策、权限拒绝或未支持阻止执行。X 在零采购约束下属于此状态。 |
| `disabled` | owner 显式停用连接；优先于旧成功证据。 |

`partial` 只作为平台聚合状态：至少一个能力/入口可用且至少一个不可用。原子能力不保存 `partial`，避免同一事实双写。

每项能力分别投影 `manual` 与 `scheduled` 两个入口；未来技能入口只有在正式需求进入时新增，不用字符串兜底。手动证据不得自动放行定时入口。合法空结果可以证明调用完成，但 S02 仍必须有可重新读取的持久业务记录才可标 `available`。

### 4.2 状态优先级与时效

状态按以下顺序计算：产品/费用硬限制 → 连接停用 → 无连接 → 当前准入拒绝或过期 → 当前连接版本最新证据 → 待验证。连接版本变化立即使旧证据失效，但旧记录保留可查。

`OPEN-004-001` 采用不臆造 TTL 的处理：没有全平台统一有效期；准入政策的 `review_expires_at`、连接版本变化、显式停用和真实授权错误立即失效。S02 没有真实授权样本，因此不新增时间失效规则；来源特定的主动复验周期待实际接入取得官方限制和真实样本后冻结。页面显示最后检查、最后持久成功和明确下一动作，不把旧成功静默续期。

## 5. 数据模型与不变式

S01 在唯一 `backend/database/schema.sql` 增加三张表；SQLAlchemy Model 同批更新：

| 表 | 核心字段 | 不变式 |
|---|---|---|
| `source_connections` | `id`、`owner_id`、`source_key`、`status`、`current_version`、时间 | owner + source 唯一；status 仅 active/disabled；版本至少 1。 |
| `source_connection_versions` | `(connection_id, version)`、`secret_ref`、`created_by`、`created_at` | 不可变；只保存受控引用，不保存 token/Cookie/secret 值；S01 只为受控测试准备记录，不开放写 API。 |
| `source_capability_evidence` | `id`、`operation_id`、owner/connection/version、capability、entry_point、kind、outcome、stop_reason、`resource_ref`、组件版本、`observed_at` | append-only；operation 幂等；probe 成功不得带资源引用，persisted_read 成功必须引用可重读资源；失败必须有稳定原因且不保存原始响应。 |

能力证据 kind 只有 `probe` 与 `persisted_read`，outcome 只有 `succeeded` 与 `failed`。失败原因复用 `SourceStopReason` 的稳定安全分类；S01 不保存 SDK 异常文本。列表查询只选择当前连接版本、每个能力/入口最新证据，并结合当前准入政策投影状态，不把投影结果另存一份。

S02 在现有表上增加唯一写入 Service：事务内按 owner 锁定连接，返回不含秘密的证据视图。S03 先行片已将自动绑定当前版本改为 §8.1 的显式执行版本校验。`operation_id` 在 owner 内重放相同事实时返回原记录，重用于不同事实时拒绝为 `idempotency_conflict`。`record_probe` 和 `record_persisted_read` 是分立入口：成功 probe 禁止资源引用；成功 persisted read 必须提供由采集业务已经持久且可重读的 `resource_ref`；失败必须提供稳定 `stop_reason`。不接收原始异常、上游响应或令牌。

`secret_ref` 是服务端预配置秘密的受控引用。S01 没有创建/更换连接 API，也不修改 `.env`；S03 冻结允许引用的配置键和替换流程。API 输出只给 `has_credentials`/版本，永不返回 `secret_ref`。

## 6. HTTP、CLI 与页面契约

| 操作 | 契约 | 边界 |
|---|---|---|
| 能力目录 | `GET /api/source-capabilities`，`listSourceCapabilities` | 会话；`200 PageView[SourcePlatformView]`、`Cache-Control: no-store`；无 owner 数据时仍返回 X/抖音目录及真实受限/未配置状态。 |
| 探测证据 | `python -m cli connections record-probe` | 仅登记由操作者显式执行的探测结果；必填 owner、connection、connection-version、operation、能力/入口、结果和组件版本，不读取或输出秘密。命令本身不发起外部请求。 |
| 持久读取证据 | `SourceCapabilityEvidenceService.record_persisted_read` | 仅供后续采集用例在业务数据持久后调用；不开放人工 CLI/HTTP 伪造成功。 |

`SourcePlatformView` 包含稳定 source key、中文展示名、rollout role、平台聚合状态和四个能力；能力包含 manual/scheduled 状态、连接版本、最后检查、最后持久成功、稳定原因和下一动作。owner ID、secret ref、原始错误、上游响应和 token 均不输出。未登录返回 401；S01 无写操作，因此 CSRF 不适用。

Web 新增 `/sources`，使用现有顶栏工具入口进入。桌面用语义 Table；390×844 以同一数据转为逐平台分组，不强塞横向表格。状态同时使用文字与 Badge，不只靠颜色。页面覆盖加载、无连接、X 受限、候选未配置、受控部分可用、请求失败、未登录和重新加载；浏览页面只读持久状态，不发外部探测。

## 8. Red/Green 与证据边界

S01 Red 必须先证明：`connections` 领域不存在；已认证调用 `GET /api/source-capabilities` 返回 404；当前无法表达“搜索可用、评论受限”且区分 manual/scheduled。环境未启动不计业务失败。

Green 至少验证：

1. 无连接、待验证、可用、需登录、受限、停用及平台 partial 的冻结状态矩阵。
2. X 因官方按量付费与项目零采购约束保持受限；抖音只显示候选及权限前提，不显示已可用。
3. probe 成功仍待验证；只有当前版本的 persisted_read + 当前准入批准才能放行相应入口。
4. 换版本、准入过期/阻断、停用立即覆盖旧成功；owner 之间不可读取，API 不含秘密引用或原始错误。
5. 真实 PostgreSQL、运行时 OpenAPI/生成客户端、后端全量门禁和前端 lint/typecheck/format/test/build 通过。
6. 真实 Web 的加载/受限/未配置/受控 partial/失败/未登录、桌面与 390×844、键盘焦点和 WCAG A/AA 检查通过；QA 数据清理。

S01 通过只证明目录与状态投影正确，不证明连接已配置、探测成功、数据已持久、任何来源可用或 AC-004-001—006 通过。S02 才登记探测与持久读取证据，S03 才实现连接更换/停用，S04 才能在真实来源上建立 Acceptance。

S02 Red 必须证明：当前只能直接写表，CLI 没有探测证据命令，领域 Service 也不能幂等登记持久读取证据。Green 至少验证：

1. CLI 登记成功 probe 后只更新对应入口的最后检查，状态仍为 `pending_verification`，不会带 `resource_ref`。
2. 持久读取成功必须有资源引用，且只放行同一 capability + entry point；manual 成功不会放行 scheduled。
3. 同 owner + operation 重放相同事实只有一行，改变事实会冲突；非 owner 连接不可登记。
4. 失败结果只保存稳定原因；不输出秘密引用、资源引用、原始错误或上游响应。
5. 真实 PostgreSQL 上的领域/CLI/状态投影验证与后端全量门禁通过；受控数据清理后不留残留。

S02 通过只证明证据机制可供后续采集切片回写，不证明受控 `resource_ref` 是真实平台内容、任何来源已可用或产品 AC 通过。

### 8.1 S03 先行：证据版本屏障

在开放连接写操作前，先修复 S02“写入时自动绑定当前版本”的竞态。复用 PostgreSQL [行级锁](https://www.postgresql.org/docs/18/explicit-locking.html#LOCKING-ROWS) 与既有不可变版本，不增加库、表、脚本或通用锁框架。

- `ProbeEvidenceInput`、`PersistedReadEvidenceInput` 和 `PersistContentPostInput` 必填正整数 `connection_version`，由执行上下文提供；CLI 必填 `--connection-version`。不能在完成时猜测或补成当前版本。
- 证据 Service 按 owner 锁定连接。已提交的同 operation、同事实（含原连接版本）重放返回原证据，即使连接后来更换或停用；改变事实仍为 `idempotency_conflict`，不写入新记录。
- 对尚未提交的 operation，连接已停用则拒绝 `connection_disabled`，版本与当前不同则拒绝 `connection_version_conflict`。错误归 conflict，由现有 API 错误映射登记为 409；本片没有新增 HTTP 写接口。
- 作品持久化把执行版本传入同事务证据登记；被拒绝时作品、观察、版本、发现、生命周期和能力证据整笔回滚。既有历史资料及原版本证据保留可读。
- 当前只证明写入屏障，不等于已完成新任务受理/每次外部请求前的执行权校验。连接配置/停用 HTTP/UI、引用白名单、连接级失效传播和真实 Worker 仍由 S03 后续完成。

修改路径限定为现有 `connections/{schemas,services}.py`、`content/{schemas,services}.py`、`cli/commands.py`、`core/errors.py`、`api/exception_handlers.py`，测试位于既有 unit/integration 的 `test_source_connections.py`、`test_content_records.py`。无新增目录、模型、DDL、依赖或生成契约变化。

Red/Green 覆盖旧版本迟到、停用后迟到、相同事实历史重放、不同事实冲突、owner 隔离、事务整体回滚与独立 Session 行锁竞争；全量后端和运行时 OpenAPI 漂移回归后独立提交。完整 S03 门禁与产品 AC 不因本片通过而勾选。
