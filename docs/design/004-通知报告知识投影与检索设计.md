# 通知报告知识投影与检索设计

## 现状

当前运行时已经注册 PostgreSQL Notification Outbox、User Notification、Delivery Attempt、短期 Delivery Claim、WebSocket 推送和邮件派发，前端能够断线重连并补拉通知。当前“已读”仅由前端 `localStorage` 中的 `readThroughID` 保存，没有服务端 Read Receipt、跨设备收敛或已读 API；邮件发送成功但 Attempt 提交失败的 lost-ack 窗口也尚未形成显式 `unknown` 状态。仓库还存在报告、交付、知识 Vault 与搜索相关代码和 Schema，但并非所有源码模块都已注册到当前 API 或页面。新基线不能把“源码存在”写成“用户闭环已完成”，也不能用附件的目标页面代替真实验收。

PostgreSQL、MinIO 与本地 Vault 已是批准存储边界。目标检索继续使用 PostgreSQL 可用的全文检索、规范化字段、`pg_trgm` 和必要索引，不引入 Elasticsearch，也不把搜索索引变成第二业务事实源。

## 目标

| 需求 ID | 目标 |
|---|---|
| BR-004-001 | 热点提醒必须及时、可补拉、低噪声，交付通道失败不得丢失通知事实。 |
| BR-004-002 | 日报必须冻结输入和 Evidence，经过人工审批后形成不可变、可复核版本。 |
| BR-004-003 | Obsidian 必须是人类可维护、可重建的知识投影，自动内容不得破坏人工内容。 |
| BR-004-004 | 用户必须能通过非向量全文检索找到权限内知识，而不会得到未经引用的生成式回答。 |

为满足这些需求，站内通知以 PostgreSQL 事实为恢复锚点，WebSocket 只做已提交事实的实时投影；邮件失败不回滚站内通知；报告经预览与批准后形成不可变 Revision；Vault 的自动区域与人工区域互不覆盖；检索使用 PostgreSQL 全文与 trigram 能力，投影失败不回滚已提交业务事实。

## 非目标

- 不自动向社交平台或外部网站发布内容。
- 不将 WebSocket、邮件、Vault 文件或搜索索引作为业务事实源。
- 不引入 Kafka、Logstash、Elasticsearch 或外部全文检索集群。
- 不实现向量知识问答、RAG 或基于搜索结果的自动答案生成。
- 不在首版提供无限可配置报告模板、多人文档协作或多 Vault。
- 不宣称当前未注册的报告和知识页面已经可用。

## 核心决策

### DEC-004-001：通知使用 PostgreSQL Outbox 事实

领域用例在同一事务中保存业务变化与通知 Outbox。Dispatcher 以可重入 Claim 读取待交付事实，生成用户通知并按通道记录尝试；WebSocket 只推送通知 ID 和安全 DTO，不承载唯一副本。

### DEC-004-002：告警规则与交付通道分离

告警规则决定“何时应通知”，用户偏好决定“通过哪些通道交付”。邮件失败不会撤销站内通知，WebSocket 未连接也不会阻止通知事实提交。去重键覆盖用户、监控、事件、规则版本和触发窗口；Dispatcher 在每次交付前重读当前用户偏好，并在同一事务边界执行最小通知间隔和重复抑制，同一去重窗口复用既有通知事实而不是创建第二份事实。

### DEC-004-003：报告先冻结证据，再生成内容

报告任务先保存时间窗、入选事件版本、Claim 和 Evidence 清单，再执行确定性组装或受控 Codex 建议。标题、摘要、Claim 正文、链接和任何模型建议都按不可信内容处理；在保存草稿、预览或审批前，通过字段白名单和上下文渲染边界拒绝或清理脚本标签、事件属性、脚本 URL、恶意 SVG/HTML。校验通过后创建草稿 Revision；批准操作冻结 Revision 与引用，后续修订创建新版本。

### DEC-004-004：Vault 是可对账的人类投影

Vault 文件由稳定业务 ID 定位，文件名可包含可读标题但不承担身份。系统只接受根目录下的受控相对路径；路径解析器在任何文件 I/O 前拒绝绝对路径、`..`/编码穿越、分隔符绕过和符号链接逃逸，并用稳定错误码记录不含宿主路径的审计事件。系统拥有的 Frontmatter 与自动区域可从 PostgreSQL 事实重建；人工区域通过明确标记保留，只能从现存 Vault、已保存 Knowledge Revision 或备份恢复，不能由系统重新生成。恶意 Markdown、脚本 URL 和不可信 HTML 在渲染/发布前被拒绝或清理并审计；冲突生成独立副本或提案，不静默覆盖人工内容。

### DEC-004-005：PostgreSQL 提供首版检索

拥有模块维护规范化检索文本、语言、时间、实体和状态字段，并建立 PostgreSQL 全文与 trigram 索引。查询 Application 在查询和组装 DTO 两个边界重检当前角色、对象权限以及删除/撤权状态，过滤后再生成经过上下文转义的安全高亮，拒绝标签、属性、脚本 URL 等 XSS 载荷。搜索结果只返回业务对象身份，再由拥有模块组装可见 DTO；投影延迟不得成为继续展示已删除或已撤权对象的理由。

### DEC-004-006：读取回执与外部交付显式处理竞态和不确定结果

服务端以追加式 Notification Read Receipt 保存用户单调前进的 `read_through_id`，查询时的已读状态由每个用户的最新合法回执派生；前端 `localStorage` 只作为可丢弃缓存，登录或换设备后以服务端为准。Read Receipt 只能引用该用户可见且已提交的 User Notification，使用幂等命令，不允许客户端倒退或越过权限边界。

外部通道 Claim 使用不可猜测 Token、租约截止和递增 Fencing Generation。完成 Attempt 时必须在同一事务中用数据库时间验证当前 Token/Generation；租约自然过期后可由其他 Worker 抢占，旧 Worker 的迟到完成必须被拒绝。每个通道适配器声明 Provider 是否支持幂等键和交付回执查询：支持时必须把稳定派发键传给 Provider，并在重试前查询/复用回执；请求可能已离开进程但本地无法确认时，必须追加 `unknown` Attempt 或等价不可变不确定事实并暂停自动重发，待 Provider 对账或经批准人工处置。对不支持幂等或回执查询的 SMTP/外部通道不宣称 exactly-once，也不得把 lost-ack 当普通失败盲重试。

## 数据与状态

- Notification Outbox 表达待投影领域变化；User Notification 表达用户可见事实；目标 Notification Read Receipt 表达单调已读游标；Delivery Attempt 表达邮件等外部交付尝试，四者不可合并。
- 通知读取状态与交付状态分离；邮件发送成功不能自动标记用户已读。当前前端 `readThroughID` 在服务端 Receipt 上线前只是本地缓存，不是持久业务事实。
- Notification Outbox、User Notification、上线后的 Notification Read Receipt 及 Delivery Attempt 是持久事实和游标/交付审计锚点，禁止像搜索索引一样清空重建。恢复时只允许清理 Delivery Claim/租约、WebSocket 会话和客户端缓存等临时状态；外部交付恢复必须保留既有 Attempt，并遵守 Fencing、Provider 幂等/回执和 `unknown` 停止规则，同时保持原稳定 ID、派发键和游标顺序。
- Report 保存类型、窗口和当前状态；Report Revision 保存不可变正文结构、输入快照哈希和引用；批准后禁止原地修改。
- Knowledge Document 保存稳定业务身份与当前投影状态；Knowledge Revision、Proposal、Annotation 与 Vault Sync Run 保存历史、人工提案和对账结果。
- Notification/Report/Knowledge/Projection Run 使用不可注入正文的安全运行 ID 贯通通知、报告、Vault 和检索日志；关联字段只保存受控业务 ID，不保存正文、邮件地址列表、宿主路径或凭据。
- 搜索字段是可重建投影；删除、撤权、归档或纠正后必须同步改变可搜索范围。
- Vault 不保存无界原始响应；原始证据仍由 MinIO 持有，文件只引用允许展示的业务身份和出处。

## 接口与交互

- 通知中心支持列表、服务端未读/已读状态、事件深链和实时更新；连接失败时显示可恢复状态而不是伪装实时，跨设备重新登录后以服务端 Read Receipt 收敛。
- 通知设置允许用户配置站内与邮件偏好、监控范围和低噪声策略，权限和地址由服务端校验。
- 报告工作台支持构建、预览、校验警告、批准、查看历史 Revision 和再次生成草稿。
- 知识界面展示投影状态、Vault 路径、最近同步、冲突和人工提案，但不允许提交任意本地路径。
- 搜索支持关键词、类型、监控、来源、实体、时间与状态过滤，返回安全高亮和稳定游标。
- WebSocket 使用当前同源通知端点和认证握手；所有恢复读取仍通过普通 API 与统一 Result。

## 安全与合规

- 通知和搜索查询在服务端按用户角色与对象权限过滤，不能依赖前端隐藏导航。
- 邮件正文只包含必要摘要和安全深链，不包含来源凭据、私密证据正文或内部错误。
- Vault 根路径来自部署配置，所有生成路径在规范化后必须保持在根目录内，拒绝符号链接逃逸和路径穿越。
- 报告预览/审批、Vault Markdown 和浏览器渲染统一清理危险 HTML、事件属性、脚本 URL、恶意 SVG 与不受信任链接；搜索高亮经过上下文安全转义。
- 报告事实性句子只能引用冻结清单中的 Evidence；自动生成内容明确标识来源和不确定性。
- 删除、撤权与保留策略跨 PostgreSQL、MinIO、通知、Vault 和搜索投影执行，并保存审计结果。

## 失败与降级

- WebSocket 断开：指数退避重连，并用 `after_id` 或等价游标补拉；普通通知列表始终可用。
- 邮件确定失败：保存 Attempt 和稳定错误，在预算内重试；站内通知与事件事实不回滚。Provider 已可能接收但本地提交失败时保存 `unknown`，禁止按普通失败自动重发；只有 Provider 幂等键/回执对账或经批准人工处置能解除。
- Delivery Claim 过期或抢占：新 Worker 使用更高 Fencing Generation；旧 Token 的迟到完成失败停止，不能写 Attempt 或删除新 Claim。
- 报告智能生成失败：保留冻结输入和失败运行，可用确定性骨架或稍后重试，不发布不完整报告。
- Evidence 校验失败：报告保持草稿并显示缺失引用，禁止批准。
- Vault 不可写或哈希冲突：保存待重试/冲突状态，不覆盖人工区域。
- PostgreSQL 检索索引异常：业务详情和列表仍可按基础字段查询；修复索引后从业务事实重建。
- 投影任务重复：依靠稳定业务 ID、Revision 和幂等键返回既有结果。

## 验收边界

| 验收 ID | 边界 |
|---|---|
| AC-004-001 | 已提交站内通知在 WebSocket 在线推送、断线和从最后位置重连补拉后只展示一次且顺序稳定；最小通知间隔、重复抑制和交付时用户偏好均生效，离线不丢失，连接故障不影响普通列表与通知事实。设备 A 提交单调 Read Receipt 后，设备 B 以服务端状态收敛；本地缓存丢失不会把已读事实倒退。 |
| AC-004-002 | 日报中只有白名单内完整 ClaimEvidence 支撑的事实句可通过审批，事实性 Claim 的 Evidence ID 覆盖率为 100%；Event 级 Evidence State 不能替代逐句校验，无引用、伪造或撤权引用被拒绝，报告标题、摘要、Claim、链接中的脚本标签、事件属性、脚本 URL、恶意 SVG/HTML 在草稿持久化、预览和审批前被拒绝或清理，浏览器中不执行。 |
| AC-004-003 | 已批准 Report Revision 在重新生成或修改同日报告时保持不可变，新内容形成可追溯草稿/Revision，版本和操作者可查询。 |
| AC-004-004 | 对含自动区域、人工笔记和冲突变体的 Vault 重复发布、改标题、标记丢失或 Revision 倒退时，正常重复不新建文件且人工内容逐字保留；绝对路径、路径穿越、符号链接逃逸、恶意 Markdown 与不可信 HTML 在写入/发布前被拒绝并留下不泄露宿主路径的审计。 |
| AC-004-005 | 关键词、实体、来源、时间和状态检索返回权限内高亮结果，高亮对标签/属性/脚本 URL 等 XSS 载荷安全转义，删除或撤权对象立即受当前权限过滤；链路不调用向量、Embedding、RAG 或 Elasticsearch，越权对象不泄露。 |
| AC-004-006 | 清理可丢弃的 Delivery Claim/租约、WebSocket 会话、客户端缓存、知识自动区域或检索投影，或在 Claim 过期抢占、旧 Worker 迟到完成、Provider 成功后本地 Attempt 提交失败时恢复；Notification Outbox/User Notification/Notification Read Receipt/Delivery Attempt、稳定游标及 Vault 人工区域不被清空。新 Worker 只能用更高 Fencing Generation，旧 Token 无法提交；支持 Provider 幂等/回执时恢复不重复派发，结果无法确认时形成可见 `unknown` 并停止自动重发，而不虚构 exactly-once；自动知识与检索投影可幂等重建，差异有报告。 |
| AC-004-007 | 四产品角色的交付页面五态与直接 API 一致，Viewer/Analyst/Editor/Admin 只能执行矩阵允许动作，未实现 Analyst 时真实拒绝。 |
| AC-004-008 | 在固定语料、查询集、并发、硬件、文件系统和缓存状态下，通知、日报发布、Vault 与全文检索基线输出 P50/P95/P99、错误率、投影积压和资源报告；全链路以安全运行 ID 关联，日志扫描证明不泄露正文、邮件地址列表、宿主路径或凭据，候选时延只有达标并批准后转为承诺。 |

## 未决项

- OPEN-004-001：日报、周报在首版的必需字段、批准角色和自动发送策略需产品评审。
- OPEN-004-002：当前报告、交付与知识源码中哪些路径继续复用、哪些只保留历史读取，需要运行时调用图确认。
- OPEN-004-003：Vault 自动/人工区域标记、冲突副本命名和 Git 使用方式需跨平台实测。
- OPEN-004-004：中文、英文及其他语言的 PostgreSQL 分词策略与检索质量门槛需建立数据集后确定。
- OPEN-004-005：通知去重窗口、邮件重试上限和用户频控默认值需要真实使用数据。
- OPEN-004-006：P0 使用的邮件/外部 Provider 是否支持稳定幂等键和回执查询需在 G2 前形成 Capability 证据；不支持时按 `DEC-004-006` 保持 `unknown` 并禁止自动重发。
