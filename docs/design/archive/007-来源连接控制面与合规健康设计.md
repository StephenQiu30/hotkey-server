# 来源连接控制面与合规健康设计

## 现状

来源 CRUD、启停、归档、恢复、健康检查、指标能力档案和凭据环境变量引用已实现，目前实际连接器只有 RSS/Atom 与 Hacker News。

## 目标

为 MVP 来源提供统一而合规的连接、授权、健康、能力和成本控制面，让业务流水线不感知第三方 SDK。

## 非目标

本条不跨越相邻编号实现其业务细节，也不建立第二套身份、任务、数据、API 或 UI 事实源。

## 核心决策

- 每个来源连接保存类型、官方端点、授权方式、`env:NAME` 凭据引用、HTTPS 条款地址、语言/地区、保留策略、请求超时、分页上限和速率限制，绝不保存明文密钥。
- 连接器实现统一 Connector 端口并返回标准 Capture；第三方类型只存在于 infrastructure。
- 准入只允许官方 API、RSS、Atom 或书面授权 Feed；不得绕过登录、验证码、robots、反爬或访问限制。
- 健康状态区分 unknown、healthy、degraded、unavailable；认证、限流、临时、解析、永久错误分别处理。
- MVP 只在创建表单暴露已实现的 RSS/Atom 与 Hacker News；不支持的类型在 Transport 和领域边界双重拒绝。
- viewer/editor 只读取名称、类型、状态、条款和“凭据已配置”布尔事实；仅 admin 可读取端点和白名单配置，所有角色都不得读取凭据引用或诊断中的敏感事实。
- 指标能力档案沿用既有管理员 API 和不可变版本，不在本条增加第二套 Schema；来源列表只展示连接级配额与保留摘要。

## 数据、接口与交互

- 来源目录和完整连接配置表单
- 连接健康检测与诊断
- 能力档案、配额和指标映射
- 凭据引用与条款审计

所有新增跨端字段先进入 `backend/db/schema.sql` 和后端 DTO/Swaggo 注解，再生成 `docs/openapi/swagger.json` 与前端 Client。页面同时提供正常、加载、空、错误和权限不足状态。

## 安全、失败与降级

来源条款和产品能力会变化；每种来源必须由独立 Design 决定能否启用。

失败必须被分类、可观测且不破坏历史事实；可选外部依赖不可用时，核心读取链路继续工作。

## 设计验收边界

- 不支持的来源类型在保存前失败
- SSRF、重定向、DNS 重绑定和凭据泄露测试通过
- 来源故障不阻塞其他来源或历史数据读取
