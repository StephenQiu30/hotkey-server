# 内容与事件检索筛选排序设计

## 决策结论

021 不新建搜索服务、搜索表或第二套分数。内容检索扩展现有 `GET /contents`，事件检索扩展现有冻结 Radar；服务端完成过滤、排序和游标分页，前端只把 URL 状态映射为生成 Client 参数。019 定义的 Radar `attention` 继续作为事件重要性/热度，不创建 Content 级“重要性”分数。

## 现有事实与差距

- Content 列表只有按 `published_at,id` 倒序的 shape-bound Cursor；API 没有关键词、来源、时间、Monitor 或相关性参数，页面状态也不进入 URL。
- Content 已有安全来源投影，`monitor_matches` 已保存 Monitor 内的最终相关性与决定；Event 关系由 `event_contents` 唯一事实维护，但 Content 列表尚未通过 Event 的批量只读端口投影归属。
- Radar 已具备 1h/6h/24h/7d 窗口、Monitor、生命周期、趋势、确认状态、最低热度、五种排序、冻结 `as_of`、过滤指纹和不透明 Cursor。
- TopNav 已可从任意页面提交关键词，但事件页只在最多 100 条 Radar 结果上做前端过滤，也没有分页；Monitor、窗口和排序是不可分享的本地状态。
- 现有索引覆盖 Content 最新顺序、来源+时间、Monitor Match 分数和 Event 最新顺序，但没有 Content 标题/摘要 trigram 索引与 Monitor 最新 Match 覆盖索引。

## 查询契约

### Content

- `q`：对标准化后的标题与 excerpt 做大小写不敏感包含搜索，去除首尾空白，最大 100 个字符。
- `source_connection_id`、`published_from`、`published_to`：按 Content 自有事实过滤；时间为 RFC3339 且起点不晚于终点。
- `monitor_id`、`decision`：读取该 Monitor 每个 Content 的最新 Match；相关性排序必须携带 `monitor_id`，缺失 Match 的 Content 不进入该排序。
- `sort=latest|relevance`：latest 使用 `(published_at,id)`，relevance 使用 `(final_score,id)`；默认 latest。
- 响应继续显示来源和时间，并可选投影 `relevance_score`、`match_decision`、`event_id` 与 `event_title`。事件归属由 Event 模块批量只读端口补充，不从 ingestion Repository 跨表读取。

### Event/Radar

- Radar 增加 `q`，在冻结 `as_of` 内搜索事件中英文标题和摘要；关键词进入 ShapeHash。
- 继续复用 Monitor、窗口、生命周期、趋势、确认状态与最低热度过滤。
- 排序固定为 momentum、attention、breadth、latest、relevance；其中 attention 是重要性/热度，relevance 仍要求 Monitor。
- 冻结 Cursor 保持跨页顺序；任何关键词、筛选、排序或页大小变化都清空旧 Cursor，旧 Shape Cursor 返回 400。

## URL 与交互

- TopNav 是全局搜索入口，默认进入事件结果；事件与内容页面提供同关键词的范围切换，不拼接两套结果冒充统一排序。
- `q`、筛选、排序和 `limit` 使用稳定 URL 参数；`cursor` 只用于当前前进位置，页面内保存返回历史。刷新、复制、前进/后退恢复同一查询首屏或显式 Cursor。
- 搜索输入 300ms 防抖，Enter 立即提交；清除关键词或任一筛选后回到第一页。
- 空结果明确展示当前条件并建议清除关键词、扩大时间或移除筛选；错误只替换对应结果区。
- UI 使用现有 shadcn/ui `Input`、`Select`、`Button`、`Badge`、`Card`、`Table` 与 `Empty`，移动端自然换行。

## 索引、权限与失败

- 唯一 Schema 增加 active Content 标题/excerpt trigram 部分索引，以及 Monitor+Content 最新 Match 覆盖索引；不新增表或外部搜索引擎。
- 查询上限保持 100；对 latest、keyword、source+time、relevance 和 Radar keyword 保存 EXPLAIN/容量测试，不允许无界全表结果。
- 所有列表先经过 Bearer 认证中间件；Repository 只读取 active、未删除 Content/Event 及合法 Monitor 投影。Viewer 与 Editor/Admin 的读取范围一致，管理事实不进入响应。
- Event 归属批量端口不可用时 Content 结果仍返回，归属字段为空；相关性是筛选/排序事实，相关性查询失败则整次查询明确失败，不降级为错误顺序。

## 设计验收边界

- 静态数据下 Content latest/relevance 与 Radar 任一排序跨页无重复或遗漏，变更查询条件后旧 Cursor 被拒绝。
- 关键词与所有可见筛选由真实 API 执行；页面没有对分页结果二次过滤或排序。
- 刷新、后退与分享保留关键词、筛选、排序和页大小；TopNav 查询可在事件/内容范围间切换。
- 匿名请求在进入 Repository 前被拒绝；安全响应不包含 excerpt、原始正文、对象键、内部解释或删除记录。
- Viewer/Admin、桌面/390px、加载/空/错误、键盘焦点与 axe 全部通过。
