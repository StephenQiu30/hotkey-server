# AI 真伪、相关性、重要性与摘要设计

## 决策结论

019 不新增 `isReal` 布尔值或第二套 AI 分数。HotKey 把用户所说的“真伪”表达为事件级证据确认状态，把“相关性”限定在所选 Monitor，把“重要性”复用现有 Heat/Radar 事实，把“摘要”限定为带 Content 引用的 Event Summary。页面必须同时展示置信度、证据和降级语义，禁止把模型输出包装成确定事实。

## 现有事实源

- `monitor_matches` 已保存规则、Embedding、可选 LLM 复核、理由、降级、模型版本与人工反馈。
- `event_claims` 与 `claim_evidences` 已保存声明状态、置信度、支持/反驳证据和人工锁定；Radar 已由这些声明派生 confirmation。
- `event_metric_snapshots` 已按独立来源、内容速度、来源宽度、互动、时效与来源可信权重计算 Heat，并保存版本与理由。
- `ai_runs`、预算账本和版本化 JSON Schema 已保存模型、prompt/schema/input/evidence hash、Token、成本、延迟、状态和幂等 reuse key。
- Event Summary 已验证每个句子的 Content/locator 引用；模型不可用时只生成代表证据绑定的事实型 fallback。

## 产品语义

### 证据确认，而非真假裁决

- `corroborated` 表示存在多源相互支持声明；`single_source` 表示只有单源；`unverified` 表示证据不足；`disputed` 表示存在冲突；`insufficient` 表示尚无可评估声明。
- confirmation score 只表示证据确认强度，不表示事实为真的概率。低置信度与证据不足必须使用中性文案。
- 研判详情展示声明、置信度、状态及其 Content 证据入口，不显示“真/假”按钮。

### Monitor 相关性

- 只有选择 Monitor 后才展示/排序 `watch_relevance` 与 `watch_final_score`；未选择时展示“未选择监控”，不把空值当 0。
- Radar 的 relevance 排序必须绑定 `monitor_id`；界面在无 Monitor 时禁用该选项，后端约束继续作为最终门禁。

### 重要性

- `attention` 即现有 24 小时 Heat 投影，作为“重要性”主分数；`momentum`、`breadth` 和 `data_confidence` 是解释维度。
- 重要性不是 AI 主观打分。其算法版本、来源宽度、时效和降级理由继续由 Event/Metric 领域维护。

### 摘要与降级

- 页面展示持久化 Event Summary 和最新变化；声明证据作为可展开的事实依据。
- AI Run 相同输入与版本依赖 reuse key 幂等；预算耗尽、Provider 不可用或超时时，规则相关性、Heat、Radar、告警和报告不停止。

## 数据、契约与交互

- 本条不修改 Schema，也不复制后端评分。前端只消费生成的 Monitor、Radar、Event Update 和 Event Intelligence Client。
- 事件页增加 Monitor 上下文选择、可解释研判卡和声明证据；使用 shadcn/ui `Select`、`Badge`、`Card`、`Progress`、`Alert`、`Button`。
- 选择事件后并行读取 Update 与 Intelligence；任一辅助读取失败只降级对应区域，不清空 Radar 主列表。

## 安全与失败

- Viewer 只能读取安全投影；Editor/Admin 的复核写入继续走既有授权 API，本条不绕过角色门禁。
- 页面不暴露 provider payload、prompt 正文、对象键、凭据、内部错误或成本明细；配额与成本治理留给 025。
- 任何空置信度、空相关性或无声明状态都显示未知/未选择，不使用确定性颜色和措辞。

## 设计验收边界

- 无 Monitor 时不会发送非法 relevance 排序请求；选择 Monitor 后显示对应相关性。
- 低置信度/单源/争议状态不会显示为“已证实”；声明证据可回到 Content 详情。
- 重要性及解释维度来自真实 Radar 字段，摘要和声明来自真实 API；移动端与 axe 通过。
