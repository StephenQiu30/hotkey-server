# X官方搜索连接器设计

## 现状

来源控制面、查询规划、CollectionRun、checkpoint 和统一采集流水线已经存在，但 SourceType、Schema、OpenAPI、前端和 ConnectorRegistry 尚不识别 X，仓库也没有安全读取 env Bearer Token 的 X 连接器。

## 目标

只通过 X API v2 Recent Search 获取最近 7 天公开帖子，使关键词、账号、语言与地区规则进入统一采集流水线，并在分页期间保持可恢复的轮询高水位。

## 非目标

不使用未授权网页抓取、浏览器会话、验证码绕过或不稳定私有接口补齐能力；本条不实现其他编号的业务细节。

## 核心决策

- 根端点固定为 `https://api.x.com/2/tweets/search/recent`，仅允许 Bearer Token 的 `env:NAME` 引用；运行时从服务环境读取，任何响应、日志和持久化事实均不包含 Token。
- 复用已发布监控的规范查询：关键词、短语、排除词和显式官方运算符保留原义；语言编译为 `lang:`，地区编译为 `place_country:`。MVP 按自助套餐的保守 512 字符上限校验，不写死套餐名称、价格或额度。
- checkpoint 使用版本化不透明游标同时保存本轮 `since_id`、分页 `next_token` 和首屏 `newest_id`。分页期间保持原 `since_id`；仅在最后一页完成后把首屏 `newest_id` 提升为下一轮 `since_id`。
- 请求 `author_id`、附件、引用、时间、语言、敏感/限制字段和公开指标。帖子映射为 `post`；回复/引用父项保存为 `parent_external_id`；公开指标保持缺失与显式零值的差异。
- `withheld` 和 `possibly_sensitive` 帖子不保存正文并形成稳定诊断；响应中的不可用资源错误形成稳定诊断，不把“本次搜索未返回”推断为已删除。
- 新 X 来源创建时默认停用；只有健康探测成功后才能启用。禁用、删除、凭据缺失或撤销时不发起搜索请求。
- `429` 使用 `x-rate-limit-reset` 形成 retry 时间；认证、限流、临时、解析和永久错误进入既有分类，不抓取 x.com 页面回退。

## 数据、接口与交互

- SourceType、固定端点、Bearer env 引用、健康状态和启用门禁复用来源控制面。
- SourceConfig 继续使用既有保留期、语言、地区、配额、超时和单次页数白名单；不新增任意 JSON 或明文凭据字段。
- `source_connections` 与 `metric_capability_profiles` 只扩展 `x` 枚举约束；采集继续使用 CapturedItem v2 JSON、CollectionRun 与既有 checkpoint，不新增业务表。

跨端契约先修改 Schema 与后端注解，再生成 OpenAPI 和前端 Client。来源能力必须在发布监控前可检测，禁用或阻塞状态不能进入调度。

## 安全、失败与降级

X 套餐、价格与运算符会变化；能力档案必须运行时可配置，不能在 Domain 写死商业套餐。

第三方失败按认证、限流、临时、解析和永久错误分类；关闭单个来源不影响历史证据和其他来源。

## 设计验收边界

- AC-010-1：分页保持同一 `since_id`，最后一页才推进首屏 `newest_id`，重复运行由既有幂等键去重。
- AC-010-2：禁用、删除、凭据缺失或撤销的连接不发起 Recent Search；新连接健康前不可启用。
- AC-010-3：`withheld`、敏感和不可用资源形成稳定诊断且不保存正文，父项、附件和公开指标按官方字段映射。
