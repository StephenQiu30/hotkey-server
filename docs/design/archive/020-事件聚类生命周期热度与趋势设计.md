# 事件聚类、生命周期、热度与趋势设计

## 决策结论

020 复用现有 Event 聚类、治理、指标快照、EventUpdate 与 Radar，不建立第二套事件或分数。后端唯一新增事实是把 `heat-v1` 已计算的六维组成随快照持久化并安全投影；前端把既有成员锁定、生命周期、合并和拆分 API 组合成最小治理入口。

## 现有事实与差距

- 候选召回已按 lexical、temporal、fingerprint、vector 四条有界通道执行；lexical/fingerprint 已包含获批实体、关键词和短语，向量不可用时确定性通道继续工作。
- 确定性成员分由实体动作、语义、时间、地点和来源上下文组成；每个候选决定、特征快照、证据 Content 和算法版本已追加保存。
- Content 行锁与唯一约束保证并发重放只归属一个 Event；人工锁定成员或 Event 不被自动聚类覆盖。
- 生命周期事实固定为 `detected`、`active`、`cooling`、`closed`、`archived`、`rejected`、`merged`；`emerging/rising/stable/falling/dormant` 是趋势状态，不是生命周期。
- `heat-v1` 已计算 1/6/24 小时快照、趋势、原因码和来源能力 hash，但快照未保存六维组成，前端无法解释互动指标缺失后的权重归一。
- EventUpdate 已按首次快照、升温、降温、重新活跃、来源扩张和热度变化阈值追加；事件行锁与幂等键保证并发只写一条。
- 事件工作台已展示 Radar 和 Intelligence，但未读取 Heat/Member，也没有角色受限的治理入口。

## 聚类与治理

- Recall 通道保持最大 50 个去重候选；向量不可用明确记录 degraded，不丢弃规则候选。
- 成员分 `>=80` 自动加入，`65–80` 进入 review，低于阈值创建新事件；硬冲突直接拒绝。
- Event 创建与成员归属、Monitor 投影、聚类决定和治理审计在同一事务中完成。
- Editor/Admin 可锁定或解锁成员；仅 Admin 可变更生命周期、合并和拆分。所有写操作继续使用 expected version、原因码和审计。
- `closed → archived` 是唯一新增的生命周期边，Archived、Rejected、Merged 保持终态。

## 热度、趋势与能力缺失

`heat-v1` 的六维组成是：

1. 独立性 25%：按 SourceConnection 或 Author 去重后的独立证据数。
2. 内容速度 25%：窗口内有效内容数量按窗口归一。
3. 来源宽度 15%：不同 SourceType 的覆盖。
4. 互动 15%：只使用来源能力声明支持且存在基线/最新值的指标；全部缺失时保持 `null`，不得补 0。
5. 时效 15%：以 24 小时半衰期衰减。
6. 来源可信度 5%：使用发布的 MetricCapabilityProfile 权重。

互动不可用时，15% 权重按其他可用维度归一，并保存 `metrics_unavailable`；小样本归一化保存 `normalization_fallback`。快照新增一个 `component_scores jsonb` 对象，不新建表；旧快照默认空对象并在 API 中省略组成，绝不伪造零值。

趋势继续使用短/长窗口 EMA 与加速度，范围为 -100 到 100。前端只展示后端快照，不重算 Heat、Trend 或能力覆盖。

## EventUpdate 与 Radar

- 24 小时快照才生成 EventUpdate；无实质变化不写事实。
- 首次有效快照、趋势跨越、独立来源显著扩张或绝对热度变化至少 10 才生成更新。
- 幂等键绑定 Event、时间窗口、算法/证据/能力 hash 与投影字段；并发重算返回同一更新。
- Radar 继续使用冻结 `as_of`、签名 Cursor 和真实 EventUpdate，不新增缓存事实。

## API 与前端

- `GET /events/:id/heat` 增加可选 `components`，旧快照返回省略字段。
- 事件页选中事件后并行读取 Update、Intelligence、Heat 和 Members；任一辅助区域失败只局部降级。
- Heat 卡使用 shadcn/ui `Progress`、`Badge`、`Alert`；成员治理使用 `Button`、`Checkbox`、`Select`、`AlertDialog`。
- Viewer 只读；Editor 可成员锁定；Admin 额外看到生命周期、合并和拆分。移动端保持单列，不把危险操作隐藏在无标签图标中。

## 安全、失败与回滚

- API 不暴露原始指标序列、Provider payload、对象键、凭据、内部 SQL 或审计 metadata。
- 没有组成的旧快照显示“组成尚未记录”；互动缺失显示“不可用”，而不是 0。
- 治理冲突使用 409 并刷新最新版本；失败后不乐观伪造成功状态。
- 回滚先移除前端治理与 Heat 组成，再停止写 `component_scores`；保留列和历史 JSON，不删除事件、成员、更新或审计事实。

## 设计验收边界

- 并发聚类与 EventUpdate 重放分别只产生一个事件归属和一条更新。
- Heat 卡能逐项解释六维，互动缺失保持 null 并显示重加权原因。
- 人工锁定成员后自动任务不能移动它；Admin 的生命周期、合并和拆分受版本与确认门禁保护。
- Viewer、Editor、Admin、匿名、390px 与 axe 均通过。
