# 账户认证与会话安全设计

## 现状

邮箱验证、注册、登录、刷新、退出、忘记密码、重置密码和修改密码接口及页面已存在。

## 目标

让用户在浏览器与 API 中安全完成完整账号生命周期，并在会话过期、跨站请求和凭据泄露场景下可预测地失败。

## 非目标

本条不跨越相邻编号实现其业务细节，也不建立第二套身份、任务、数据、API 或 UI 事实源。

## 核心决策

- 短期 Access Token 与可轮换 Refresh Token 分离；刷新令牌只进入 HttpOnly、Secure、SameSite Cookie。
- 密码使用成熟自适应哈希；邮箱验证码和重置票据只保存 HMAC 摘要并设单次使用与过期时间。
- 刷新与退出校验精确 Origin，认证错误使用统一业务码，不泄露账号是否存在。
- 前端由单一 AuthSession 状态机处理初始化、刷新、过期与安全重定向。

## 数据、接口与交互

- 注册登录与邮箱验证
- 找回、重置和修改密码
- 会话刷新、撤销和设备退出
- 认证页面全状态交互

所有新增跨端字段先进入 `backend/db/schema.sql` 和后端 DTO/Swaggo 注解，再生成 `docs/openapi/swagger.json` 与前端 Client。页面同时提供正常、加载、空、错误和权限不足状态。

## 安全、失败与降级

Cookie、CORS 与反向代理配置不一致会导致刷新失败；部署配置必须纳入端到端测试。

失败必须被分类、可观测且不破坏历史事实；可选外部依赖不可用时，核心读取链路继续工作。

## 设计验收边界

- 刷新令牌不可由前端 JavaScript 读取
- 重复验证码、过期票据和重放刷新均被拒绝
- 未认证访问安全返回登录页且保留允许的站内回跳
