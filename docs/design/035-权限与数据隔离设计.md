# 权限与数据隔离设计

日期：2026-09-21。本文冻结 035 S00—S01 的默认私有和入口授权边界；关联对象、缓存、异步任务、撤权与审计分别留给 S02—S03。本文不把单 owner 工作区闭环解释为 035 完整产品验收。

## 1. 范围与决策

HotKey P0 继续采用单使用者自托管模型。当前唯一有效主体是经 034 会话认证的 owner；不提前增加第二个持久账号、团队、角色、共享邀请或通用策略引擎。

| 决策 | 冻结值 | 理由 |
|---|---|---|
| 默认归属 | 新建业务资源必须保存 `owner_id`，值只能来自服务端认证上下文 | 客户端不能代替服务端声明资源所有者 |
| 当前工作区 | `GET /api/identity/workspace`，owner 从会话派生，不接受 owner 或 workspace ID | P0 不暴露无必要的可枚举标识 |
| 对象授权 | 读取、修改、删除、统计、搜索、导出、关系展开和重试均在领域服务中比较当前主体与资源 owner | 路由隐藏和前端状态不构成授权 |
| 默认拒绝 | 身份缺失返回 `401 invalid_session`；资源不存在或不属于当前主体统一返回 `404 resource_not_found` | 拒绝优先，避免通过状态和正文差异探测资源存在性 |
| 批量语义 | P0 全量预检；任一对象不可访问则整体拒绝，不产生部分写入 | 语义简单且不泄漏合法/非法对象的组合情况 |
| Web 导航 | Proxy 只根据 Cookie 是否存在做 `/events` 到 `/login` 的乐观跳转；页面仍调用受保护 API，API 仍逐请求认证与授权 | 边缘跳转只改善体验，不能成为安全边界 |

`OPEN-035-001` 在 S01 范围内冻结为上述公开拒绝语义和批量整体拒绝。P2 的角色、显式共享及部分成功展示不在本期实现。

## 2. 授权边界

`identity.services.require_resource_owner(actor_id, owner_id)` 是当前最小 owner 规则：仅在两个 UUID 完全相同时返回；否则抛出已登记的 `resource_not_found`。领域服务必须在返回实体、计数、片段、关系或任务状态前调用该规则，不能先查询/聚合后再由路由裁剪。

S01 的受控资源是 owner 工作区。`IdentityService.get_workspace(identity)` 仅使用已认证会话中的 owner，并执行同一 owner 规则；HTTP 不接收资源归属参数。该接口让 Web 工作台使用真实受保护入口，同时避免为了测试 IDOR 而发布一个无产品用途的任意用户查询接口。

后续资源接入遵循相同顺序：

1. 从会话得到 `actor_id`；
2. 在持久化查询或锁定记录中得到 `owner_id`；
3. 调用统一 owner 规则；
4. 通过后才返回或修改资源；
5. 批量操作在事务内先校验全部对象，再执行副作用。

工作区 DTO 只返回 `owner{id, username}`。密码散列、会话令牌、CSRF 值、bootstrap 配置及授权内部状态均不进入响应或日志。

## 3. HTTP 与 Web 契约

| 方法与路径 | operation_id | 成功 | 关键错误 |
|---|---|---|---|
| `GET /api/identity/workspace` | `getIdentityWorkspace` | 200 `IdentityWorkspaceView` | 401 `invalid_session`；404 `resource_not_found` |

`/login` 是公开登录页；提交时复用生成客户端 `createIdentitySession`。凭据错误在表单内稳定呈现，不暴露用户名是否存在。`/events` 是首个受保护工作台入口；加载时调用生成客户端 `getIdentityWorkspace`，无有效会话则替换导航到 `/login`，成功后呈现事件空状态。注销复用 `deleteIdentitySession` 并返回登录页。

两个页面都设置 `noindex`。组件保持页面内聚，不建立全局权限 UI 框架，不为尚未实现的监控、共享或角色提供占位导航和无效按钮。

## 4. 数据与运行边界

S01 不新增表、迁移、Redis 键、Kafka Topic 或环境变量。owner 工作区由现有 `identity_users` 与有效 `identity_sessions` 事实派生；后续业务资源必须在各自 Plan 中同步更新 `schema.sql` 与 ORM，并增加 `owner_id` 索引和外键约束。

服务端授权是唯一安全边界。Next.js Proxy 不连接数据库、不验证会话真实性；伪造或过期 Cookie 最终由 API 拒绝。运行日志沿用 046 契约，只记录路径模板、状态和 request ID，不记录 Cookie、Header、请求体或资源正文。

## 5. 验证与证据边界

S01 使用以下证据闭环：

1. Red：真实 PostgreSQL 环境中，受保护工作区入口尚不存在或未执行授权。
2. 单元规则：owner 主体允许；不同 UUID 的外部主体统一得到 `resource_not_found`。
3. HTTP：未认证和伪造会话均为 `401 invalid_session`；真实 owner 为 200，且响应无秘密字段。
4. Web：无 Cookie 访问 `/events` 被乐观引导到 `/login`；登录后可进入事件空状态；伪造/过期 Cookie 仍由 API 拒绝；注销后不能返回工作台。
5. Ruff、格式、mypy、全量 pytest、架构门禁、运行时 OpenAPI 漂移和前端全量门禁通过。

这些证据只证明单 owner 工作区和可复用 owner 规则，不证明作品、事件、任务、统计、导出、缓存、下载、关联、撤权或 P2 共享已接入。两个真实可登录账号不符合当前 P0 单 owner 设计；S01 以两个隔离主体 UUID 验证规则，并把完整双账号业务矩阵保留到相应账号与共享范围实际启用后。

## 6. 停止与回退

本切片无 DDL 和外部依赖迁移。异常时可停止 Web 工作台入口并回退程序版本，既有 owner、会话和撤销记录保持不变。不得通过删除身份表、清空持久卷或放宽 API 授权恢复可用性；若前端 Proxy 与 API 状态不一致，以 API 拒绝为准并以前向修复处理。

## 7. S02 当前资源接入（2026-09-22）

本次接入已存在的主题、任务、作品/引用关系与来源证据，不新建第二个持久账号、角色引擎、缓存或导出功能。S02 仍须随评论/事件、异步结果、缓存、导出和下载落地继续验证，不能以本次矩阵代替整个切片或产品 AC。

依据 [OWASP 逐请求授权](https://cheatsheetseries.owasp.org/cheatsheets/Authorization_Cheat_Sheet.html) 复核主体—资源—操作矩阵；依据 [RFC 9111](https://www.rfc-editor.org/rfc/rfc9111.html#section-5.2.2.5) 使用标准 `Cache-Control: no-store`。404 可以被缓存，Cookie 本身不是禁止缓存的声明；已有成功响应禁存不能覆盖异常处理器生成的拒绝响应。统一错误出口补禁存头，不改错误 body/status/请求 ID，不引入缓存中间件或缓存库。

| 文件 | 变更与验证 |
|---|---|
| `backend/app/api/exception_handlers.py` | 公共错误出口显式禁存，覆盖拒绝、校验及故障响应；成功与流式协议不改 |
| `backend/tests/integration/test_resource_isolation.py` | 真实 PostgreSQL 创建主题/任务，使用 owner 与受控外部主体验证读、改、复制、启停/归档、取消/重试、列表及无副作用；会话缺失/注销/过期及错误禁存 |
| `backend/tests/integration/test_content_records.py` | 复用作品 fixture，跨主体读取/列表/引用关系、错误连接或任务关联的事务回滚 |
| `backend/tests/integration/test_provenance_replay.py` | 混合可读/不可读输入整体拒绝且无部分清单，已持久结果读取复核 |
| `backend/tests/integration/test_http_contract_046.py` | 统一 500 故障响应同样禁止缓存，原有脱敏和请求 ID 保持不变 |

受控外部主体通过测试依赖注入，保留真实领域服务、SQL 和事务；不伪称两个真实可登录账号。没有 DDL、DTO、路由、消息、UI、依赖或 env 变化；不新增脚本。浏览器布局为 N/A，运行 API 与 Web 代理仍需验证禁存头透传，生成契约不得漂移。失败优先验证后执行后端全量与前端既有门禁，证据回写同编号 Plan。
