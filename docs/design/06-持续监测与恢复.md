# 06 持续监测与恢复

对应 [06-持续监测与恢复](../requirement/06-持续监测与恢复.md)；实施拆分见 [06-持续监测与恢复](../plan/06-持续监测与恢复.md)。需求为范围依据，本文件不表示功能已实现；进度只在仓库根目录BACKLOG。

## 设计目标

保存主题后持续发现变化，故障时安全停止并恢复。

## 结构与交互

- 主题状态区分“定时已启用”、实际执行与已采未分析；展示下一轮/到期与静默信息，以真实接口为准。
- 按应执行窗口追踪成功、部分、失败、漏轮与停止原因；页面30秒刷新只读，不触发采集。
- 暂停、取消与恢复由合法状态控制；未知结果先核对，执行中请求的结束和部分材料保留在回执中。

## 数据与复用边界

先核对现有入口：[backend/app/monitors](../../backend/app/monitors)、[backend/app/jobs](../../backend/app/jobs)、[backend/app/worker](../../backend/app/worker)、[backend/app/api/routers/collection_jobs.py](../../backend/app/api/routers/collection_jobs.py)。入口存在只代表可核对，不能据此宣称真实能力已验收。

优先复用现有业务身份、版本、服务与组件；展示派生值、本机阅读状态和持久事实分别处理。新字段仅在同编号需求有实际消费路径时补齐，接口/数据库的唯一合同仍在代码及schema。

## 状态与核对重点

自然故障如实记录，未出现的异常用受控场景补验并区分证据；真实告警无触发则继续观察。

读写状态使用真实回执；已有数据刷新失败保留可读内容并标过期，未知写入先核对结果。正常、空、加载、错误、无权限以及键盘行为按实际交互覆盖；静态内容无远程状态时标不适用。

视觉、组件与响应式沿用 [00-产品目标与边界](../design/00-产品目标与边界.md)；跨页状态沿用 [11-质量评测与验收](../design/11-质量评测与验收.md)；权限、安全渲染和许可沿用 [10-权限与数据生命周期](../design/10-权限与数据生命周期.md)。

## 自然窗口与恢复

现有调度器从到期配置取得应执行窗口，沿用[worker/scheduler](../../backend/app/worker/scheduler.py)与主题、连接版本形成可核对调度身份，再进入同一jobs执行链。默认小时级低频；静默、预算、到期和暂停在调度与实际发送前都核对，页面刷新不参与调度。

| 情形 | 处理与用户可见结果 |
|---|---|
| 应执行窗口 | 任务回执或漏轮原因；静默窗口有计划依据，不能当成功采集 |
| 暂停/取消/风控/到期 | 不再发新请求，正在执行的请求如何结束及已采材料保留在最终回执 |
| 限流/认证失效/验证码 | 按原因安全停止，提示必要人工动作；不自动换账号、绕过或密集重试 |
| 超时、崩溃或租约过期 | 先核对已有结果和幂等身份，再沿冻结配置有界恢复；不重建任务系统 |
| 模型积压 | 区分已采/待分析/错误，延后消费不丢材料，展示真实滞后 |

自然观察逐应执行窗口核对，而非只数成功任务。七日观察由11统一冻结口径；04/05/07就绪后开始完整闭环观察，不将缺失功能的空转时间算作核心验收。

## 主题暂停与采集代次

关键词搜索和评论采集复用同一主题保护。任务受理时由服务端把主题已有状态事件的递增序号冻结到 `scope.topic_collection_sequence`，与规则版本分别保留；不新增表或另一套队列。领取、逐请求预算预留前、请求准入、取消探测、心跳及手动重试均核对同 owner 的主题仍处于 active 且序号一致。暂停后立即恢复也只允许新操作运行，旧任务和缺少序号的历史任务不能重新绑定当前代次；幂等重放仍返回原任务。

请求准入检查是停止边界：暂停提交后才进入检查的请求必须拒绝；暂停前已获准的请求按在途处理。工作进程可终止采集子进程，父进程负责完成取消状态、部分覆盖回执和已开始请求的保守预算结算，重投不重复扣量。已提交材料与已确认覆盖保留，尚未提交的在途响应不承诺入库；损坏的旧任务不能凭空补造覆盖事实。

暂停事务不批量锁任务，逐请求检查不锁主题，避免主题、调度和任务之间的锁顺序冲突。非主题来源热榜以及其他主题、其他账号的任务继续按各自准入运行。归档与移除全部自动来源导致的暂停遵守同一保护。

逐请求保护必须覆盖每一次实际 HTTP 调用，不能把整批预算预扣等同于整批请求已经在途。当前 MediaCrawler 搜索子进程只有轮询终止，线上工厂在启动前拒绝该方式；Chrome 的逐请求回调及本地已保存样本/评论读取可继续复用。MediaCrawler 搜索恢复前必须补每次发送前的准入桥并受控验证。
