# 作品资料与上下文设计

日期：2026-09-22。本版接受 007 S00—S01，只冻结作品身份、发现关系、不可变指标观察、生命周期读取屏障和 owner 只读列表/详情。S02 的正文版本与上下文、S03 的编辑/可见性历史须在各自 Red 前修订本 Design；本版不实现真实来源采集、刷新任务、评论、媒体下载、跨平台归并或产品 Acceptance。

## 1. 当前事实与范围

- `sources/contracts.py` 已提供无 ORM 的 `SourcePost`，保留不透明 `external_id`、可空作者/发布时间/互动数和页级 `observed_at`；它是适配器边界，不是持久化模型。
- `jobs` 已持有 owner、job/operation、配置版本、来源能力和执行轨迹；作品发现只引用现有 job，不复制主题名称、查询词或任务状态。
- `evidence` 已实现来源字段白名单、保留期、`EvidenceResource` 及删除/到期读取屏障；`connections` 已将 probe 与 persisted read 分开登记。当前服务的独立事务入口须增加显式同 Session 内层入口，才能由内容写入用例原子编排，不能绕过现有门禁或跨领域直接读 ORM。
- 当前没有 `content` 领域、业务表、HTTP 契约或页面，也没有真实平台连接或合法样本。S01 只使用受控样本证明内部规则，不将结果表述为 X、抖音或其他平台已接入。

`content` 新增为作品、后续评论、版本、观察和内容关系的唯一业务事实域。`sources` 继续只负责平台契约/适配器，`evidence` 只负责准入和生命周期，`jobs` 只负责执行活动，均不复制“当前作品”投影。

## 2. 一手资料与复用结论

| 依据 | 采用结论 |
|---|---|
| [W3C Activity Streams 2.0 Core](https://www.w3.org/TR/activitystreams-core/) 与 [Vocabulary](https://www.w3.org/TR/activitystreams-vocabulary/) | `Object`、`attributedTo`、`inReplyTo`、`summary`、`published`、`updated` 证明对象、作者、关系、摘要及时间应分开表达；HotKey 不引入 JSON-LD/ActivityStreams 存储层，只复用其语义边界。 |
| [RFC 3339](https://www.rfc-editor.org/rfc/rfc3339) | API 时间使用带时区的互联网时间表达；未知发布时间保持 `null`，不得用接收时间补齐。数据库继续使用 `TIMESTAMPTZ`。 |
| [PostgreSQL Constraints](https://www.postgresql.org/docs/current/ddl-constraints.html) | 复合身份、owner 归属和发现关系使用数据库 `UNIQUE`/`FOREIGN KEY`；全局原生 ID 的空作用域用 `UNIQUE NULLS NOT DISTINCT` 明确只允许一条，不用空串替代。 |
| 现有 FastAPI、Pydantic、SQLAlchemy、PostgreSQL、Umi OpenAPI、shadcn/ui | 直接扩展既有模块化单体、运行时 OpenAPI 生成链、`PageView`、会话/错误契约及 Table/Card/Skeleton 等组件；不新增 repository 框架、状态库、内容协议、脚本或依赖服务。 |

## 3. 核心决策与未决项关闭

### 3.1 稳定身份

作品身份固定为 `(owner_id, source_key, object_type, native_scope, external_id)`：

- `external_id` 和可选 `native_scope` 是来源原样提供的不透明字符串，不转数字、不 trim/转小写、不从 URL 猜测；S01 只接受 `object_type=post`，字段为后续 008 评论复用保留。
- 来源证明 ID 全局唯一时 `native_scope=null`；只有来源正式契约证明 ID 仅在账号/频道等范围内唯一时才填写稳定作用域。未知作用域不以空串代替。
- URL 只是一次观察的属性，不参与身份；跨平台相同正文保持不同实体，不做指纹归并。
- `OPEN-007-001` 关闭：只有链接且没有稳定来源 ID 的输入停留在后续发现/线索边界，不写入 `content_records`，不开放完整作品详情，也不从 URL 派生伪 ID。

### 3.2 零、未知与指标名称

S01 固定六个共享指标槽位：`like_count`、`comment_count`、`repost_count`、`view_count`、`play_count`、`danmaku_count`。每项为可空非负 `BIGINT`：`0` 表示来源明确返回零，`null` 表示未提供或当前不可取得。`view` 与 `play`、`comment` 与 `danmaku` 不互相填充；真实来源启用前仍须在对应来源 Design/政策中核对单位和统计范围。

不在 S01 建通用指标字典或 JSON 指标仓库。出现共享槽位无法忠实表达的新平台语义时，先补来源证据和 Design，再扩展显式字段，不能把不同语义塞进现有列。

### 3.3 观察、发现与当前投影

- 每次成功保存的作品项产生不可变 `content_observations`；原文链接、作者、发布时间和指标均属于当次观察。列表/详情中的“当前值”只是按 `observed_at DESC, received_at DESC, id DESC` 选择的最新可读观察，不回写历史行。
- 同一作品可由多个 job 发现；`content_discoveries` 对 `(owner_id, content_id, job_id)` 唯一。主题/账号语义继续由 job 的 `configuration_ref/version` 表达，不在内容域复制查询词或主题 ORM。
- `source_operation_id` 是单个被持久化来源项的幂等键。同一 owner、作品和 operation 的等价重放返回原观察；字段不同则明确冲突。新的 operation 即使指标相同也保留为独立观察。
- 观察时间、系统接收时间和发布时间分列。输入时间必须带时区；未来观察时间、无时区时间或以当前时间补来源时间均拒绝。

## 4. S01 数据与服务契约

### 4.1 `content_records`

| 字段 | 规则 |
|---|---|
| `id` / `owner_id` | UUID；owner 外键级联，另建 `(owner_id,id)` 唯一键供复合外键使用 |
| `source_key` | 1—64 位稳定小写来源 key，与现有来源契约一致 |
| `object_type` | 首版只写 `post`；数据库预留 `post/comment`，评论实现仍归 008 |
| `native_scope` | 可空、不透明、最长 512；空串非法 |
| `external_id` | 必填、不透明、最长 512；不得规范化或从 URL 推导 |
| `created_at` | 系统接收 UTC 时间，不冒充发布时间 |

使用 `UNIQUE NULLS NOT DISTINCT (owner_id, source_key, object_type, native_scope, external_id)`。并发首次写入由数据库唯一约束收敛并重读现有记录，不采用先查后插作为唯一保证。

### 4.2 `content_discoveries`

每行只保存 `id`、`owner_id`、`content_id`、`job_id`、`first_observed_at`、`created_at`，以复合外键同时约束 content/job owner；`(owner_id, content_id, job_id)` 唯一。重复页或任务重投不增加关系，不同 job 可形成多条发现依据。S01 API 返回 job ID 及稳定配置引用/版本的只读 DTO；跨领域查询通过 `jobs` 服务函数完成，不导入其 ORM。

### 4.3 `content_observations`

每行保存：

- `id`、`owner_id`、`content_id`、`job_id`、`source_operation_id`；`(owner_id, content_id, source_operation_id)` 唯一；
- `observed_at`、`received_at`、可空 `published_at`；满足 `received_at >= observed_at`，但不要求发布时间存在；
- 可空 `canonical_url`、`author_external_id`，均作为数据展示，不作为请求目标；URL 只允许 `http/https`、最长 2048；
- 六个可空非负指标列。数据库 `CHECK` 只验证单行范围，不跨行判断“最新”。

创建观察前必须取得 `AdmittedSourcePayload`：来源 key/capability、取得时间、政策/保留版本及 `fields` 全部来自 036 白名单投影；稳定 ID 缺失或政策未放行所需字段时拒绝。内容服务不得再读取原始响应补字段。

每个观察以 `resource_type=content_observation`、`resource_id=observation.id` 登记 `EvidenceResource`。内容写入是最外层事务：content 记录、发现关系、观察、生命周期记录及成功 persisted-read 证据共用同一 Session，要么全部提交，要么全部回滚。为此只在 `evidence/services.py` 和 `connections/services.py` 增加显式的 session 内层写入口，保留现有独立用例包装；不直接导入对方 ORM，不建立通用 UnitOfWork。成功证据引用 `content_observation:<uuid>`，失败或回滚不能把来源能力标为可用。

读取时先由 evidence 领域批量返回当前可读 observation ID，再由 content 领域构造投影；没有任一未到期、未删除观察的作品对该 owner 返回 404/不进入列表。S01 只形成逻辑屏障，数据库正文清除与回补阻止仍在 036 S03/007 S03 联验。

### 4.4 服务输入与错误

`PersistContentPostInput` 为严格 DTO，包含 `job_id`、`source_operation_id`、可选 `native_scope`、带时区 `observed_at`、当前 `AdmittedSourcePayload` 及 004 persisted-read 所需的 connection/入口/组件上下文。允许持久化的内容字段只有本节已冻结字段；正文、媒体、任意 metadata、Token、Cookie、查询词和整份原始 payload 均拒绝或忽略前即不得进入 DTO。

稳定业务错误复用 046：身份或可读资源不存在为 `resource_not_found`，幂等键异义重用为 `idempotency_conflict`，来源政策/保留期不可用沿用 evidence 领域错误，跨 owner 不透露资源是否存在。日志只记 request/job/operation/content UUID 与稳定错误类别，不记原生 ID、URL、正文或外部 payload。

## 5. S01 HTTP 与 Web

只开放两个会话保护的同步读取端点：

| 端点 | 契约 |
|---|---|
| `GET /api/contents?limit=20&cursor=<uuid>` | owner 范围内按稳定 UUID 游标分页；返回来源、原生身份、最新可读观察、六个可空指标和发现数。`limit` 为 1—100。 |
| `GET /api/contents/{content_id}` | 返回同一身份、最新可读观察及全部当前可读发现依据；不存在、跨 owner、到期或已删除统一 404。读取不触发网络、刷新或任务提交。 |

路由放在 `api/routers/content_records.py`，只经 `ContentServiceDependency` 调用服务；响应使用 `ContentRecordSummaryView`、`ContentRecordDetailView`、`ContentMetricView`、`ContentDiscoveryView` 和现有 `PageView`。每个操作定义人工 `operation_id`、中文 summary、响应模型及 401/404 错误。运行时 `/openapi.json` 仍是唯一事实源，随后生成 `frontend/src/api/`。

Web 使用 `/content` 列表与 `/content/[contentId]` 详情，复用现有 Shell、Card/Table/Badge/Skeleton、错误提示和生成客户端。明确显示 `0` 与“未知”，原生 ID/URL 只按文本或安全外链渲染；不得使用 `dangerouslySetInnerHTML`。首版不放“刷新”按钮，因为 010/真实来源处理器尚未提供该能力。组件测试放现有前端测试目录；真实浏览器用现有浏览器工具验证，不创建 `frontend/tests/e2e`、脚本或 `.sh`。

## 6. 后续切片边界

### 6.1 S02 正文版本与上下文

S02 Red 前修订本 Design，再增加不可变 `content_versions` 与有类型关系：完整/摘要/截断/仅媒体、来源原文/机器提取来源、标题/正文、引用/转帖目标和未解析目标身份。观察指向当时内容版本；摘要不得升级成全文，媒体说明不等于已理解媒体。届时增加 observation/version 读取，不提前创建空表或字段。

### 6.2 S03 编辑与可见性

S03 增加追加式可见性观察，至少区分 `visible/deleted/restricted/transient_failure/unknown`；只有来源明确证据才能标记 deleted，超时/限流/认证失败保持 transient 或受限。正文变化生成新版本，乱序观察不能覆盖较新投影；同时完成 PostgreSQL 业务行的删除传播与回补阻止。刷新任务由 010/具体来源编排，007 不自建空 POST 入口。

## 7. 文件、验证与回退

S01 只创建实际使用的以下路径：

| 路径 | 职责 |
|---|---|
| `backend/app/content/{models,schemas,services}.py` | 三表 ORM、严格 DTO、事务/幂等/读取投影；`__init__.py` 仅标识包 |
| `backend/app/api/routers/content_records.py`、`api/dependencies.py`、`api/router.py` | 会话保护只读契约与服务装配 |
| `backend/app/evidence/services.py`、`connections/services.py` | 同 Session 内层门禁/登记入口，不复制业务表 |
| `backend/app/db/metadata.py`、`backend/database/schema.sql` | 模型登记与唯一 DDL |
| `backend/tests/unit/test_content_records.py` | DTO、零/未知、时间、URL、投影与幂等规则 |
| `backend/tests/integration/test_content_records.py` | 真实 PostgreSQL 的并发身份、两 job 发现、重放/冲突、owner、生命周期及 HTTP |
| `frontend/src/app/content/`、现有组件测试与生成的 `frontend/src/api/` | 列表/详情和前端契约；不建 e2e 目录 |
| `backend/tests/architecture/test_structure.py` | 登记 `content` 主责及禁止依赖 |

Red 固定样本：同一 owner 的两个 job 发现 `source_key=x, native_scope=null, external_id=post-001`；第一次观察 `like_count=0, view_count=null`，相同 operation 原样重放，另一次 operation 形成新观察；另一个 owner 使用同原生 ID。先证明当前 `content` 契约不存在，再实现一实体/两发现、0 与 unknown 分离、重放不增加观察、跨 owner 隔离及生命周期屏障。

验证顺序：专用 unit → 真实 PostgreSQL integration → architecture → 后端全量/Ruff/format/mypy → 重建空 `hotkey_dev` 核对 DDL/ORM → 重启现有 API（不启动第二套依赖）→ OpenAPI 生成/漂移 → 前端 test/lint/typecheck/format/build → 桌面和 390×844 真实浏览器、键盘/错误/空态与 axe。S01 没有 Kafka/Redis/MinIO I/O、真实外部请求或产品 AC；这些不得以 N/A 之外的文字冒充已验证。

回退先停止新内容写入，旧只读服务只读取仍通过生命周期 gate 的数据。数据库结构只通过全新空库应用完整 `schema.sql`；不直接修改旧系统库、不删除卷。若程序回退不识别新增表，表保持原样待向前修复；不以 DROP 表作为回退。
