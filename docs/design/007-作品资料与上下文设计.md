# 作品资料与上下文设计

日期：2026-09-22。本版接受 007 S00—S03，冻结作品身份、发现关系、不可变指标/正文版本、完整度/来源标签、引用/转帖目标、追加式可见性、乱序投影、版本历史及 PostgreSQL 内容观察清理。本文不实现真实来源采集、刷新任务、回复树、媒体下载/理解、跨平台归并、备份回放门禁或产品 Acceptance。

## 1. 当前事实与范围

- `sources/contracts.py` 已提供无 ORM 的 `SourcePost`，保留不透明 `external_id`、可空作者/发布时间/互动数和页级 `observed_at`；它是适配器边界，不是持久化模型。
- `jobs` 已持有 owner、job/operation、配置版本、来源能力和执行轨迹；作品发现只引用现有 job，不复制主题名称、查询词或任务状态。
- `evidence` 已实现来源字段白名单、保留期、`EvidenceResource` 及删除/到期读取屏障；`connections` 已将 probe 与 persisted read 分开登记。S01 已增加显式同 Session 内层入口，由内容写入用例原子编排，未绕过现有门禁或跨领域直接读 ORM。
- S01/S02 已交付作品、发现、不可变指标观察/正文版本、关系、只读 API 及 Web 页面；当前没有独立可见性历史和版本历史投影，生命周期删除也只提供读取屏障，尚未登记实际 PostgreSQL 业务行清理目标。当前仍没有真实平台连接或合法样本；S03 继续只使用受控样本证明内部规则，不将结果表述为 X、抖音或其他平台已接入。

`content` 新增为作品、后续评论、版本、观察和内容关系的唯一业务事实域。`sources` 继续只负责平台契约/适配器，`evidence` 只负责准入和生命周期，`jobs` 只负责执行活动，均不复制“当前作品”投影。

## 2. 一手资料与复用结论

| 依据 | 采用结论 |
|---|---|
| [W3C Activity Streams 2.0 Core](https://www.w3.org/TR/activitystreams-core/) 与 [Vocabulary](https://www.w3.org/TR/activitystreams-vocabulary/) | `Object`、`attributedTo`、`inReplyTo`、`summary`、`published`、`updated` 应分开表达；`Tombstone/deleted` 表示来源明确知道对象已删除。HotKey 不引入 JSON-LD/ActivityStreams 存储层，只复用其语义边界。 |
| [RFC 9110 HTTP Semantics](https://www.rfc-editor.org/rfc/rfc9110.html#name-404-not-found) | 404 不说明缺失是暂时还是永久，410 才表示来源认为状态很可能永久；因此通用 `not_found` 只能投影为 `unknown`，不能自动写成 `deleted`。 |
| [X API Post fields](https://docs.x.com/x-api/posts/english-language-firehose-stream) | X 将 `text`/`note_tweet`、`author_id`、`created_at`、`edit_history_tweet_ids`、`referenced_tweets` 及关联展开分开返回；这只支持“正文、作者、编辑和目标关系不能混为一个字段”的通用设计，不构成 X 接入或字段映射默认值。 |
| [RFC 3339](https://www.rfc-editor.org/rfc/rfc3339) | API 时间使用带时区的互联网时间表达；未知发布时间保持 `null`，不得用接收时间补齐。数据库继续使用 `TIMESTAMPTZ`。 |
| [PostgreSQL Constraints](https://www.postgresql.org/docs/current/ddl-constraints.html) | 复合身份、owner 归属和发现关系使用数据库 `UNIQUE`/`FOREIGN KEY`；全局原生 ID 的空作用域用 `UNIQUE NULLS NOT DISTINCT` 明确只允许一条，不用空串替代。 |
| 现有 FastAPI、Pydantic、SQLAlchemy、PostgreSQL、Umi OpenAPI、shadcn/ui | 直接扩展既有模块化单体、运行时 OpenAPI 生成链、`PageView`、会话/错误契约及 Table/Card/Skeleton 等组件；不新增 repository 框架、状态库、内容协议、脚本或依赖服务。 |

## 3. 核心决策与未决项关闭

### 3.1 稳定身份

作品身份固定为 `(owner_id, source_key, object_type, native_scope, external_id)`：

- `external_id` 和可选 `native_scope` 是来源原样提供的不透明字符串，不转数字、不 trim/转小写、不从 URL 猜测；S01 只接受 `object_type=post`，字段为后续 008 评论复用保留。
- 来源证明 ID 全局唯一时 `native_scope=null`；只有来源正式契约证明 ID 仅在账号/频道等范围内唯一时才填写稳定作用域。未知作用域不以空串代替。
- URL 只是一次观察的属性，不参与身份；跨平台相同正文保持不同实体，不做指纹归并。
- `OPEN-007-001` 关闭：只有链接且没有稳定来源 ID 的输入停留在后续发现/线索边界，不写入 `content_records`，不开放完整作品详情，也不从 URL 派生伪 ID。

### 3.2 零、未知与指标名称

S01 固定六个共享指标槽位：`like_count`、`comment_count`、`repost_count`、`view_count`、`play_count`、`danmaku_count`。每项为可空非负 `BIGINT`：`0` 表示来源明确返回零，`null` 表示未提供或当前不可取得。`view` 与 `play`、`comment` 与 `danmaku` 不互相填充；真实来源启用前仍须在对应来源 Design/政策中核对单位和统计范围。

不在 S01 建通用指标字典或 JSON 指标仓库。出现共享槽位无法忠实表达的新平台语义时，先补来源证据和 Design，再扩展显式字段，不能把不同语义塞进现有列。

### 3.3 观察、发现与当前投影

- 每次成功保存的作品项产生不可变 `content_observations`；原文链接、作者、发布时间和指标均属于当次观察。列表/详情中的“当前值”只是按 `observed_at DESC, received_at DESC, id DESC` 选择的最新可读观察，不回写历史行。
- 同一作品可由多个 job 发现；`content_discoveries` 对 `(owner_id, content_id, job_id)` 唯一。主题/账号语义继续由 job 的 `configuration_ref/version` 表达，不在内容域复制查询词或主题 ORM。
- `source_operation_id` 是单个被持久化来源项的幂等键。同一 owner、作品和 operation 的等价重放返回原观察；字段不同则明确冲突。新的 operation 即使指标相同也保留为独立观察。
- 观察时间、系统接收时间和发布时间分列。输入时间必须带时区；未来观察时间、无时区时间或以当前时间补来源时间均拒绝。

### 3.4 S02 正文完整度与来源

- 只有准入字段明确提供内容时才创建不可变 `content_versions`；未提供不等于空正文，观察的 `content_version_id` 保持 `null`。
- `text_scope` 只有 `full/summary/truncated/media_only`。`full/summary/truncated` 至少有非空标题或正文；`truncated` 还必须声明 `source_limit` 或 `collector_limit`；`media_only` 不保存伪文本，仅显示“来源仅表明含媒体，未保存或理解媒体内容”。
- `text_origin` 只有 `source` 和 `machine_extracted`。来源原文不允许凭空填 `origin_ref`；机器提取必须同时提供经白名单准入、无敏感信息的稳定 `origin_ref`，读取时明示“机器提取”及该引用，不冒充平台原文。S02 不实现 023 的媒体提取流程。
- 标题/正文保持来源文本，最长分别为 2,000/100,000 字符；只允许常规换行和制表符，其他控制字符拒绝。HTTP/Web 始终作为纯文本输出，不解析来源 HTML。
- 版本指纹由完整度、来源、标题/正文、截断原因及关系的规范化值生成 SHA-256；同作品的等价内容复用版本，文本或关系变化只追加新版本，不更新旧行。

### 3.5 S02 关系、作者与时间精度

- 当前观察的 `author_external_id` 是当前作品作者；引用/转帖目标的作者另存，不反向覆盖。S02 只接受 `quote` 和 `repost`；`reply` 及父子回复树归 008。
- 每种关系通过显式准入标量字段传入：目标 `external_id`、可空 `native_scope` 和可空目标作者 ID；目标与当前作品同来源，不从 URL 推导。表内允许同类多目标，S02 写入 DTO 为 MVP 最多一个 quote 和一个 repost，不扩展 evidence 的标量白名单契约。
- 关系只保存可追溯的目标身份，不创建占位正文。读取时若同 owner 下的目标作品已存在且至少有一个当前可读观察，才动态返回 `target_content_id`；否则为 `null` 并显示“目标作品未获取或当前不可读”。
- `published_at` 只接受带时区、必含秒的 RFC 3339 输入，可选小数秒最多 6 位；新列 `published_at_fractional_digits` 保留 0—6 位的来源精度，时间未知时两列均为 `null`。观察时间仍取已准入的 `collected_at`，不用接收时间伪造。

### 3.6 S03 可见性与证据矩阵

- `content_visibility_observations` 追加保存 owner、作品、job、来源 operation、来源观察时间、系统接收时间、状态和依据；与成功正文/指标观察分表，失败不会制造空正文或成功 persisted-read。
- 状态固定为 `visible/deleted/restricted/transient_failure/unknown`。依据固定为 `content_returned/source_tombstone/http_gone/access_denied/authentication_required/not_found/timeout/rate_limited/upstream_error/protocol_error`，数据库与 Pydantic 同时校验合法组合。
- `visible` 只能由一次已持久化内容观察自动产生；`deleted` 只接受来源 tombstone 或明确 410；权限拒绝和认证失败属于 `restricted`；超时、限流和上游失败属于 `transient_failure`；404 或无法解释的协议结果属于 `unknown`。来源删除事实不自动等同用户要求清除本地证据，后者继续走 036 生命周期指令。
- 独立失败入口只供 010/具体来源任务调用，不开放 HTTP 写端点。它必须引用同 owner、同来源的既有 content/job，带时区且不晚于接收时间，并以 `(owner_id, content_id, source_operation_id)` 保证等价重放和异义冲突。

### 3.7 S03 当前投影、历史与清理

- 当前成功内容与当前可见性分别按 `(observed_at, received_at, id)` 最大值选择；较晚接收但 `observed_at` 更旧的结果只能进入历史，不覆盖较新的投影。最新可见性为失败时仍返回最后一个当前可读成功内容，并持久提示状态和时间。
- 详情返回当前可读观察形成的去重正文版本历史，记录首次/末次观察时间与观察数；稳定 `content_version.id` 可供后续分析绑定。列表只返回当前可见性，不复制完整历史。
- 每个 `content_observation` 在既有生命周期资源中登记 `postgres_content_observation` 清理目标。现有 `lifecycle cleanup-once` 复用内容领域处理器物理删除该观察、无引用版本，并在作品没有其他观察时删除作品/发现；处理器幂等，外部 I/O 与数据库 lease 事务仍分离。
- 原 operation 清理后再次投递会与已保留的 persisted-read operation/resource 证据冲突并整体回滚；新的 operation 代表显式新业务观察，仍须重新通过当前授权和保留门禁。备份恢复前应用删除指令及跨 operation 自动回补阻止属于 036 S03，不在本切片假装完成。

## 4. S01 数据与服务契约

### 4.1 `content_records`

| 字段 | 规则 |
|---|---|
| `id` / `owner_id` | UUID；owner 外键级联，另建 `(owner_id,id)` 唯一键供复合外键使用 |
| `source_key` | 1—64 位稳定小写来源 key，与现有来源契约一致 |
| `object_type` | 首版只写 `post`；数据库预留 `post/comment`，评论实现仍归 008 |
| `native_scope` | 可空、不透明、最长 512；空串非法 |
| `external_id` | 必填、不透明、最长 512；不得规范化或从 URL 推导 |
| `created_at` | 系统接收 UTC 时间，不冒充发布时间 |

使用 `UNIQUE NULLS NOT DISTINCT (owner_id, source_key, object_type, native_scope, external_id)`。并发首次写入由数据库唯一约束收敛并重读现有记录，不采用先查后插作为唯一保证。

### 4.2 `content_discoveries`

每行只保存 `id`、`owner_id`、`content_id`、`job_id`、`first_observed_at`、`created_at`，以复合外键同时约束 content/job owner；`(owner_id, content_id, job_id)` 唯一。重复页或任务重投不增加关系，不同 job 可形成多条发现依据。S01 API 返回 job ID 及稳定配置引用/版本的只读 DTO；跨领域查询通过 `jobs` 服务函数完成，不导入其 ORM。

### 4.3 `content_observations`

每行保存：

- `id`、`owner_id`、`content_id`、`job_id`、`source_operation_id`；`(owner_id, content_id, source_operation_id)` 唯一；
- `observed_at`、`received_at`、可空 `published_at`；满足 `received_at >= observed_at`，但不要求发布时间存在；
- 可空 `canonical_url`、`author_external_id`，均作为数据展示，不作为请求目标；URL 只允许 `http/https`、最长 2048；
- 六个可空非负指标列。数据库 `CHECK` 只验证单行范围，不跨行判断“最新”。

创建观察前必须取得 `AdmittedSourcePayload`：来源 key/capability、取得时间、政策/保留版本及 `fields` 全部来自 036 白名单投影；稳定 ID 缺失或政策未放行所需字段时拒绝。内容服务不得再读取原始响应补字段。

每个观察以 `resource_type=content_observation`、`resource_id=observation.id` 登记 `EvidenceResource`。内容写入是最外层事务：content 记录、发现关系、观察、生命周期记录及成功 persisted-read 证据共用同一 Session，要么全部提交，要么全部回滚。为此只在 `evidence/services.py` 和 `connections/services.py` 增加显式的 session 内层写入口，保留现有独立用例包装；不直接导入对方 ORM，不建立通用 UnitOfWork。成功证据引用 `content_observation:<uuid>`，失败或回滚不能把来源能力标为可用。

读取时先由 evidence 领域批量返回当前可读 observation ID，再由 content 领域构造投影；没有任一未到期、未删除观察的作品对该 owner 返回 404/不进入列表。S01 只形成逻辑屏障，数据库正文清除与回补阻止仍在 036 S03/007 S03 联验。

### 4.4 服务输入与错误

`PersistContentPostInput` 为严格 DTO，包含 `job_id`、`source_operation_id`、可选 `native_scope`、带时区 `observed_at`、当前 `AdmittedSourcePayload` 及 004 persisted-read 所需的 connection/入口/组件上下文。允许持久化的内容字段只有本节已冻结字段；正文、媒体、任意 metadata、Token、Cookie、查询词和整份原始 payload 均拒绝或忽略前即不得进入 DTO。

稳定业务错误复用 046：身份或可读资源不存在为 `resource_not_found`，幂等键异义重用为 `idempotency_conflict`，来源政策/保留期不可用沿用 evidence 领域错误，跨 owner 不透露资源是否存在。日志只记 request/job/operation/content UUID 与稳定错误类别，不记原生 ID、URL、正文或外部 payload。

### 4.5 `content_visibility_observations`

每行保存 `id/owner_id/content_id/job_id/source_operation_id/observed_at/received_at/status/basis`。content/job 均用 owner 复合外键，operation 唯一，时间满足 `received_at >= observed_at`；状态/依据使用第 3.6 节固定矩阵，不保存响应正文、错误消息、Token、URL 或供应商 payload。

### 4.6 PostgreSQL 内容观察清理

`CleanupTargetKind` 只新增实际使用的 `postgres_content_observation`，reference 必须是 UUID。CLI 装配内容领域处理器，处理器只操作 content ORM：删除目标观察、随后删除无引用版本；若作品已无观察则级联移除作品和发现。`evidence` 保留删除指令、最小资源身份和 target 结果，不直接导入 content ORM，也不增加通用 SQL target。

## 5. S01 HTTP 与 Web

只开放两个会话保护的同步读取端点：

| 端点 | 契约 |
|---|---|
| `GET /api/contents?limit=20&cursor=<uuid>` | owner 范围内按稳定 UUID 游标分页；返回来源、原生身份、最新可读观察、六个可空指标和发现数。`limit` 为 1—100。 |
| `GET /api/contents/{content_id}` | 返回同一身份、最新可读观察及全部当前可读发现依据；不存在、跨 owner、到期或已删除统一 404。读取不触发网络、刷新或任务提交。 |

路由放在 `api/routers/content_records.py`，只经 `ContentServiceDependency` 调用服务；响应使用 `ContentRecordSummaryView`、`ContentRecordDetailView`、`ContentMetricView`、`ContentDiscoveryView` 和现有 `PageView`。每个操作定义人工 `operation_id`、中文 summary、响应模型及 401/404 错误。运行时 `/openapi.json` 仍是唯一事实源，随后生成 `frontend/src/api/`。

Web 使用 `/content` 列表与 `/content/[contentId]` 详情，复用现有 Shell、Card/Table/Badge/Skeleton、错误提示和生成客户端。明确显示 `0` 与“未知”，原生 ID/URL 只按文本或安全外链渲染；不得使用 `dangerouslySetInnerHTML`。首版不放“刷新”按钮，因为 010/真实来源处理器尚未提供该能力。组件测试放现有前端测试目录；真实浏览器用现有浏览器工具验证，不创建 `frontend/tests/e2e`、脚本或 `.sh`。

### 5.1 S02 API 投影

S02 不新增端点，只扩展现有列表/详情的 `latest_observation`：增加可空 `content_version`和 `published_at_fractional_digits`。版本返回 `id/text_scope/text_origin/origin_ref/title/body/truncation_reason/relations`；关系返回类型、目标身份、可空目标作者及可空 `target_content_id`。列表使用同一 DTO 的摘要投影，不单独维护平行“当前正文”字段。

读取仍以可读观察为入口：返回该观察指向的版本与关系，不向前追溯已过期/删除观察的文本。版本可被多次观察复用；只要至少有一个当前可读观察引用它就可读，否则不对 owner 暴露。

### 5.2 S02 Web 表达

列表增加完整度 badge 和最长受控预览；详情页显示标题/正文、“完整原文/摘要/已截断/仅媒体”、“来源原文/机器提取”、截断原因和引用/转帖目标。缺少版本显示“未取得正文”；摘要和仅媒体始终有持久文字提示，不只依赖颜色或 toast。关系目标未解析时只显示原生 ID/作者与缺失提示，不制造正文。

### 5.3 S03 API 与 Web 表达

不新增端点。列表/详情增加可空 `current_visibility`；详情再增加 `version_history` 与 `visibility_history`。当前失败状态使用持久 Badge＋文字说明并同时显示观察时间，不能只用颜色、toast 或把最后成功正文隐藏成空白。详情按最新在前展示版本 ID、首次/末次观察及可见性记录；外来依据只显示受控枚举中文标签，不渲染原始错误。
