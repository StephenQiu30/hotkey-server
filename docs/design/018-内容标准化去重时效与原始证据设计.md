# 内容标准化去重时效与原始证据设计

## 决策结论

HotKey 继续使用现有 `CapturedItem → Content → MonitorMatch → Event` 单链路。本条不新建存储或任务旁路，只收紧三个 P0 语义：去重只折叠同一来源内的重复事实；发布时间超过 7 天的内容保留为可查背景、但不进入新事件候选；原始证据无法阅读时返回可解释的状态，绝不用标题或摘要伪造正文。

## 现有基线

- Source 已按捕获策略保存有界 `CapturedItem`，Ingestion 已实现 HTML 清理、Unicode/文本归一、canonical URL、Content Hash 和稳定外部 ID。
- PostgreSQL 已保存 Content、去重关系、证据摘要与生命周期事实；MinIO 已按来源和 SHA-256 保存确定性 Markdown 投影。
- 删除已采用 Content tombstone、证据 `delete_pending/deleted` 和可重试清理；本条不改写历史。
- 当前缺口是跨来源 exact URL/hash 会被标记为 duplicate，旧内容仍会进入 cluster，证据状态只能表达 `ready/not_captured`。

## 领域语义

### 标准化与同一性

1. `source_connection_id + normalized external_id` 是来源事实的首要精确身份；重复采集和跨 Monitor 命中复用同一 Content。
2. canonical URL 只保留 HTTP(S)，移除 fragment、默认端口、常见跟踪参数和非根尾斜杠；Content Hash 由归一标题与正文生成。
3. exact URL、exact hash 和 near text 只在同一 SourceConnection 内产生 Content duplicate。near text 仅检查发布时间相差 24 小时且文本集合相似度不低于 0.98 的候选。
4. 不同 SourceConnection 即使 URL 或正文相同，也保留独立 Content 与各自证据；跨源关联由 Event 聚类处理，不用 Content duplicate 代替传播证据。

### 7 天时效边界

- `published_at >= evaluated_at - 7d` 的 active Content 是新事件候选；恰好位于边界时仍属于新鲜。
- 超过 7 天的 Content 仍保留 active、可列表、可阅读证据，也可作为后续背景检索输入；P0 不为它创建 Cluster 任务，因此不会单独新建 Event、Heat 或 Alert。
- 时效以 Worker 评估时的服务器 UTC 时钟为准，不使用客户端时间或未验证的队列字段。
- 现有 `expired` 生命周期操作是独立的保留策略，不用它实现 7 天新鲜度，避免删除背景证据。

### 证据与阅读投影

- 只有来源允许保存且实际提供的正文/摘要才转换为 Markdown。转换器只处理已捕获内容，不发起网络请求。
- `ready` 必须同时通过资产状态、MIME、大小和 SHA-256 验证；只在该状态返回 Markdown。
- `not_captured` 表示来源未提供或未授权保存；`unavailable` 表示已有证据事实但当前不可读。后者只暴露稳定原因枚举：`pending`、`missing`、`deleting`、`read_failed` 或 `integrity_failed`。
- 证据读取失败返回成功的安全文档投影，Markdown/SHA-256/对象键为空；不把 MinIO 端点、对象键、SDK 错误或密钥暴露给前端。

## 数据、契约与交互

- 不新增 Schema；继续使用 `contents`、`content_assets`、`collection_item_contents` 与现有状态约束。
- `GET /api/v1/contents/{id}/document` 的 `availability` 扩展为 `ready|not_captured|unavailable`，增加可选 `unavailable_reason`；其他 Content 允许列表不暴露正文或证据定位。
- 前端继续使用生成 Client 和现有 shadcn/ui `Badge`、`Card`、`Empty`、`Button`；未捕获与已捕获但不可用必须显示不同文案。

## 安全、并发与失败

- SourceConnection + external ID 唯一约束、确定性对象键和队列唯一键共同保障重放幂等；前端禁用态不是事实约束。
- 证据先写对象，再在 Content/资产/捕获绑定同一事务中确认；事务失败执行补偿，无引用对象由对账用例清理。
- 同源重复 Content 不重复创建相同对象资产；跨源证据保持来源命名空间隔离。
- 任何完整性失败都 fail closed：不返回部分正文，不用标题/摘要填充 Markdown。

## 设计验收边界

- 同来源重复 external ID、URL、hash 或近似文本不重复生成正文资产；不同来源的同 URL/hash 保留独立 active Content 和证据。
- 新鲜边界、超过 7 天和未来时间受单元测试覆盖；超时 Content 不产生 cluster 任务，因此不单独触发 Event/Alert。
- 证据未捕获、生命周期不可用、对象读失败和完整性失败均返回无正文的稳定状态，UI 显示对应原因。
