# 内容标准化去重时效与原始证据设计

## 现状

内容标准化、canonical URL/fingerprint 去重、MinIO 原始证据、Markdown 投影和生命周期墓碑已实现；需要按对标 MVP 明确 7 天新鲜度和跨来源重复语义。

## 目标

把异构采集结果转换为统一、可查证、可删除同步的 Content，同时抑制 URL、文本和重复转载噪声。

## 非目标

不使用未授权网页抓取、浏览器会话、验证码绕过或不稳定私有接口补齐能力；本条不实现其他编号的业务细节。

## 核心决策

- 先做 URL 规范化和来源 external_id 精确去重，再用内容指纹做近似候选；跨来源转载保留各自证据并在事件层聚合。
- 默认只让最近 7 天内容进入新事件候选，较旧内容可用于背景证据但不制造新热点。
- 原始响应/正文按来源许可进入 MinIO，PostgreSQL 保存摘要、哈希、位置和事实状态，Markdown 为可重建投影。
- 删除采用 tombstone、证据清理和审计；不得静默覆盖原始版本。

## 数据、接口与交互

- 统一 Content 模型
- URL、ID、指纹和时间去重
- 7 天时效窗口与背景内容规则
- MinIO 原始证据和 Markdown 阅读

跨端契约先修改 Schema 与后端注解，再生成 OpenAPI 和前端 Client。来源能力必须在发布监控前可检测，禁用或阻塞状态不能进入调度。

## 安全、失败与降级

过度去重会丢失多源传播证据；Content 去重与 Event 聚类必须保持不同语义。

第三方失败按认证、限流、临时、解析和永久错误分类；关闭单个来源不影响历史证据和其他来源。

## 设计验收边界

- 重复抓取与跨 Monitor 命中不会重复存正文
- 超时内容不会单独触发新事件或告警
- 证据不可用时 UI 明确显示缺失原因而非伪造正文
