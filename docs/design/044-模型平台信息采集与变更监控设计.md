# 模型平台信息采集与变更监控设计

日期：2026-09-17。proposed；依据 [调研](../research/044-模型平台信息采集与变更监控调研.md) 与 [PRD](../prd/044-模型平台信息采集与变更监控.md)。已证明公开入口一次可读，未交付定时采集和变化监控。

## 1. 范围和方案

把 OpenRouter/Vercel 当作信息提供方，采集目录和公告并形成可追溯变化；不调用推理、不开通付费服务、不访问私有控制台。JSON 优先，RSS 发现，HTML 公告按需提取；复用既有 HTTP/RSS/HTML 组件、021 订阅流程和 jobs，不另建浏览器/爬虫平台。

044 和 043 可复用纯目录解析函数，但语义分开：前者观察外部模型信息，后者决定是否允许使用模型。**可监控收费模型的价格，不代表允许调用收费模型。** 044 不依赖 043。

## 2. 模块和领域主责

| 拟建/拟改模块 | 责任 |
|---|---|
| sources/contracts；sources/adapters/model_platforms/ | 官方 JSON/RSS/公告读取与字段映射；返回来源、范围、完整性及标准化观察，不依赖 ORM |
| monitors | 平台信息订阅、关键词、厂商/精确模型关注、频率/阈值/启停；扩展 003/021，不新建通用配置中心 |
| content | 外部模型资料、公告与不可变快照，提供版本对比 DTO；模型信息不是伪造的社交帖子 |
| events | 消费字段变化建立/关联事件、跨来源关系与人工纠正，不重建事件库 |
| jobs / notifications / evidence | 原子任务与预算、变化提醒幂等、来源响应摘要和必要原文证据 |
| api/routers/model_platform_sources.py；frontend/src/app/discovery/ | 订阅及变化查询协议；来源选择、模型信息列表、差异详情、事件/提醒入口 |

业务服务持有事务；路由只注入服务。跨领域通过服务/DTO，不导入他域 ORM。复用原有 secret/network 策略但公开 GET 不要求 API Key。

## 3. 数据与时间语义

逻辑对象：SourceSubscription、CatalogObservation、ModelInformation、FieldChange、OfficialAnnouncement；随切片决定是否独立成表。观察至少记录 source/endpoint/query_scope、observed_at、fetch_status、completeness、HTTP 验证信息、parser_version、payload_hash、必要证据位置。

模型身份为 source＋完整 ID；同厂商跨平台建立 explicit related_model 关系，不覆盖各平台价格/限制。价格存 Decimal 原值、currency、unit、tier、provider_scope 和有效期；比较键包括全部维度。单位/档位不明时只能展示变化，不能计算涨跌百分比。

区分 published_at（官方明确时间）、provider_created_at（目录字段）、first_seen_at（本系统首次发现）与 observed_at（抓取时间）。日期未知留 null 与原因；目录字段不自动提升为全球发布日期。

每次快照完整性仅指该 API/参数范围返回成功且通过完整性检查，不证明平台全量内容。目录请求范围改变要新建基线。首次同步默认不触发新增通知；RSS 历史有限也不做全量假设。

## 4. 变化检测、事件和排序

1. 先验证响应、解析和完整性；失败/部分结果只更新运行状态，不推进完整水位。
2. 按相同来源/范围读取前一完整快照，对稳定字段归一化后比较，忽略顺序与抓取时间噪声。
3. 新 ID 为“本平台新发现”；价格/能力变化保留前后值。持续缺失候选阈值在 S00 冻结，默认至少两个成功完整快照；仍标“待核查”，只有明确官方依据才能标确认下架。
4. 生成 change_id（来源实体＋前后快照＋差异类型），同任务重投不重复；不同时间的同值往返属于新变化，不误去重。
5. RSS/目录/公告通过原始链接和明确模型身份关联；无法确定同一事件时保留候选给人工，不能按标题相似直接合并。
6. 变更与关注规则匹配后生成一次逻辑通知；保留发现链。重要性展示相关性、新鲜度、变更影响与关注命中，权重由 013 冻结；无互动数据不输出社交热度。

## 5. API、任务与前端

候选接口：GET/POST/PATCH `/api/model-source-subscriptions`，GET `/api/model-information`，GET `/api/model-information/{id}/changes`；手动同步显式受理 202，历史比较、事件关联和通知复用领域接口。G2 冻结 operation_id、分页、幂等和权限后由 FastAPI/Pydantic 导出 OpenAPI，再生成前端客户端。

同步任务按订阅、范围和调度窗口幂等。支持来源缓存/条件请求时使用 ETag/Last-Modified；未声明支持时不假设 304。轮询初始建议小时级、公告更低频，S00 依据来源缓存与用户时效冻结；重试有退避/抖动和账户预算，不重复打源。

页面入口是“信息源—模型平台”，不是“配置模型 Key”。列表可筛新增/价格/能力/公告，详情显示原始来源、前后值与时间；显示部分/陈旧/待核查状态，停用后历史仍可查。022 自动摘要不是这些页面的必要依赖。

## 6. 安全、运行与恢复

仅请求批准的公开域名和路径；公告 URL 校验跳转、DNS、响应体大小与类型；页面内容不执行脚本或指令。全套访问与导出保持个人研究权限。原始大响应按生命周期存必要证据，通用日志不含正文或查询。

指标包括同步成功/部分/失败、快照陈旧时间、变更数、待核查缺失、通知去重和请求消耗；不以请求成功率证明业务变更正确。403 明确 access_denied，不绕过、不自动买付费通道。

新增结构在唯一 `backend/database/schema.sql` 与 ORM 中同批定义；旧类型不改成模型信息。不提供存量库自动迁移，需要保留数据时按 PROJECT 的备份、新库建表、校验导入流程实施；先小范围开启，出现误差先暂停新增比较/通知，保留旧快照，修正解析版本后有界重算并标版本。回退不删资料/卷，不重发旧通知；删除与恢复遵守 036。

## 7. 验收与风险

Plan 执行 AC-044-001—006。真实证据至少含两平台的一次持久读取和两轮合法观察；若真实窗口没有变化，用受控变更验证算法并明确边界，不把合成改价当真实平台消息。需额外验证同名不同单位、首次基线、截断/失败、持续缺失、重投和暂停恢复。

OPEN-044-001 / RSK-044-001 以 PRD 为准。公开端点将来可变，解析及覆盖版本必须可停用、可替换；当前不宣称生产可用。
