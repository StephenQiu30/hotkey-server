# 19 收藏与阅读记录

对应 [19-收藏与阅读记录](../requirement/19-收藏与阅读记录.md)；实施拆分见 [19-收藏与阅读记录](../plan/19-收藏与阅读记录.md)。需求为范围依据，本文件不表示功能已实现；进度只在仓库根目录BACKLOG。

## 设计目标

保存阅读线索、写个人备注、再次找回并导出所选资料。

## 结构与交互

- 筛选包含全部/事件/资讯/评论/报告；现有资讯收藏与其他类型待补入口明确区分，每页20个ID，收藏最多500、阅读最多5000、单备注2000字。
- 搜索仅覆盖当前页；选中、取消和批量动作有清楚反馈。本机备注使用现有命名空间，导出仅元数据与备注。

### 区域与显示边界

下面保留需求定义的区域和数量；必需字段、操作语义和业务约束以同编号需求表为准，不另建字段字典。

| 区域/操作 | 数量与范围 |
|---|---|
| 头部/筛选 | 类型全部/事件/资讯/评论/日报；最近/最早 |
| 收藏行 | 20条/页，选择复选框 |
| 备注 | 每个已收藏ID一条；最多500条 |
| 批量工具栏 | 仅当前可读选择 |
| 关注事件 | 原稿4行；当前缺省 |
| Markdown导出 | 所选或本页 |

## 数据与复用边界

先核对现有入口：[frontend/src/app/discover/starred](../../frontend/src/app/discover/starred)、[backend/app/api/routers/publication.py](../../backend/app/api/routers/publication.py)。入口存在只代表可核对，不能据此宣称真实能力已验收。

优先复用现有业务身份、版本、服务与组件；展示派生值、本机阅读状态和持久事实分别处理。新字段仅在同编号需求有实际消费路径时补齐，接口/数据库的唯一合同仍在代码及schema。

## 状态与核对重点

不可读ID不导出；批量操作只反馈一次；跨设备导入、超上限、取消与会话切换按合同验证。

读写状态使用真实回执；已有数据刷新失败保留可读内容并标过期，未知写入先核对结果。正常、空、加载、错误、无权限以及键盘行为按实际交互覆盖；静态内容无远程状态时标不适用。

视觉、组件与响应式沿用 [00-产品目标与边界](../design/00-产品目标与边界.md)；跨页状态沿用 [11-质量评测与验收](../design/11-质量评测与验收.md)；权限、安全渲染和许可沿用 [10-权限与数据生命周期](../design/10-权限与数据生命周期.md)。
