# 安全运维质量与交付设计

## 现状

当前系统使用自建邮件验证、bcrypt 密码、JWT Access Token、PostgreSQL Session/Refresh Token 和 Redis 短期验证码，角色为 `viewer / analyst / editor / admin`。Analyst 已在唯一 Schema、Domain、HTTP、DTO、OpenAPI、生成客户端与页面权限中兼容落地；既有用户不自动重映射，新注册用户仍为 Viewer，仅 Admin 可显式分配 Analyst。来源请求已有端点规范化、SSRF 防护、受管凭据与权利决策；后端暴露健康、就绪、Metrics 和 OpenTelemetry 能力；根 Compose 编排前端、后端、PostgreSQL、Redis 与 MinIO。

数据库结构由 `backend/db/schema.sql` 单独维护，后端测试集中在 `backend/test/`，前端测试集中在 `frontend/test/`。新文档基线必须把这些已有约束转化为可重复的质量与恢复门禁，而不能用附件提出的 Keycloak、Kubernetes、Kafka、ELK 或 migrations 代替当前系统事实。

## 目标

| 需求 ID | 目标 |
|---|---|
| BR-005-001 | 所有权限、来源权利和数据访问必须在服务端执行，客户端隐藏不能代替授权。 |
| BR-005-002 | 秘密与业务数据必须分离，任何角色和普通运行记录都不能泄露认证材料。 |
| BR-005-003 | 系统必须能够诊断、恢复和对账核心主链，投影或 Worker 故障不得变成静默数据损坏。 |
| BR-005-004 | 24 周交付必须以可验证 P0 和恢复门禁为准，不以功能数量或文档状态冒充完成。 |

上述需求覆盖四角色服务端权限与会话、凭据和敏感数据外发面、PostgreSQL/MinIO/Vault 联合恢复、API/Worker/来源/Codex/通知/投影可观测性、保留与删除、Schema/OpenAPI/前后端/Compose 质量门禁及非破坏性回滚。

## 非目标

- 不迁移到 Keycloak、外部 IAM 或另建身份服务；Analyst 在现有 Identity 模块内兼容演进。
- 不以 Kubernetes、Helm 或多节点高可用作为首版必需交付。
- 不引入 ELK、Kafka、Temporal、独立密钥服务或第二套监控事实源。
- 不创建增量 migration 目录或在启动时自动修改 Schema。
- 不在日志中保存完整 Prompt、来源私密正文、Cookie、Bearer Token 或 Codex 认证文件。
- 不用一次性终端输出或未复现的人工观察冒充 Acceptance 证据。

## 核心决策

### DEC-005-001：保留当前身份边界并补齐 Analyst

后端继续签发短期 Access Token，并以数据库 Session 验证撤销和用户状态；Refresh Token 轮换、重放检测、绝对寿命与安全 Cookie 由 Identity 模块拥有。产品角色为 `viewer / analyst / editor / admin`，在现有 Identity 模块和唯一 Schema 内兼容演进，并同步 Domain 枚举、数据库约束、权限矩阵、DTO、OpenAPI、生成客户端、页面导航与正负向权限测试。迁移语义固定为：既有用户不自动重映射；新注册用户仍为 Viewer；仅 Admin 可显式分配 Analyst；回滚由 Admin 将目标用户显式恢复为原角色，并保留角色变更审计，不改写历史会话、运行或业务事实。

### DEC-005-002：密钥与业务数据分离

部署环境注入 JWT Secret、认证 HMAC、SMTP 凭据、来源凭据主密钥、MinIO 凭据和可选 Codex 认证。来源明文只在 Connector 请求边界解密，Codex Adapter 不获得来源或数据库凭据。备份与主密钥分开保存。

轮换不是简单替换环境变量：每类 Secret 必须定义新凭据预检、兼容窗口（适用时新签名/新加密只用新 Key，验证/解密暂时接受新旧 Key）、服务滚动、旧凭据撤销、会话/密文影响、失败回退和脱敏审计。泄漏响应先停用受影响入口和凭据，再评估会话、来源、对象、备份与 Codex 认证的影响；不得把旧 Secret 写入 Runbook 或 Acceptance。

### DEC-005-003：完整 Schema 与显式初始化

`backend/db/schema.sql` 是唯一结构事实源。空库通过 `db init --empty-only --confirm-empty` 初始化，运行时只验证兼容性。非空数据升级若确有需求，必须由受控命令读取编译的 canonical Schema 并经过预检、备份、显式确认和对账，不创建第二套 DDL。

### DEC-005-004：可观测性围绕用户主链

Metrics 和日志至少关联请求、任务、采集运行、监控、事件、通知与 Codex 运行的安全身份。指标覆盖队列积压、任务成功率和耗时、来源错误分类、证据写入、智能失败、通知延迟和投影冲突。业务错误使用稳定码，详细原因只进入净化日志。结构化日志使用固定字段名白名单；只有批准的安全 ID 和稳定错误码进入可检索维度，高基数 ID 作为普通字段而非 Metric 标签。邮件、完整 URL/查询、正文、Prompt、上游 Payload 和任意用户输入既不能成为字段名或标签，也不能以未限长原值进入索引；按字段采用拒绝、截断或稳定摘要并保留净化原因。

### DEC-005-005：恢复优先于高可用扩张

首版先证明单机/Compose 的备份、恢复、重建和回滚，不把多副本或 HA 作为可运行前提，再评估高可用扩张。PostgreSQL 是恢复锚点；MinIO 与 Vault 按引用和哈希对账；Redis 丢失只影响短期票据，不能造成业务事实丢失。候选 99.5% 可用性必须先固定探针、分钟统计、维护窗口、依赖故障与错误预算口径；本轮直接使用当前本机开发环境和固定 CI Runner 记录容量与余量，不设置另一套目标硬件前置门槛。

### DEC-005-006：分层质量门禁

行为变更测试先行；后端执行静态检查、单元/集成测试、架构约束、Schema 和 OpenAPI 漂移检查；前端执行 OpenAPI Client、类型、单元测试和构建；Compose 执行配置与必要烟测。文档变更检查 frontmatter、交叉链接、敏感信息和 `git diff --check`。

## 数据与状态

- User、角色、Session、Refresh Token 和审计事实由 PostgreSQL 持有；Analyst 迁移保留现有用户角色语义并经过显式映射，Redis 验证码和冷却键过期后不需恢复。
- Audit Log 记录操作者、动作、目标、前后版本或结果、请求身份与时间，但不保存明文秘密。
- Retention Policy 按数据类别、来源与动作版本化；预览与执行分离，执行产生不可变结果和失败明细。
- River Job 与 Attempt 是 Worker 恢复和容量观测依据；取消、失败和重试不删除历史尝试。
- Backup/Restore、Evidence Reconciliation、Vault Sync 和质量评估运行均需稳定运行身份、状态、开始/结束时间和摘要。
- OpenAPI JSON 与后端运行时注册代码是同一生成契约；生成物必须与注解同提交。

## 接口与交互

- 公共运行端点包括 liveness、readiness 与 metrics；readiness 在接流量前拒绝 Schema、OpenAPI 或配置不兼容实例；生产环境不暴露不必要的 Swagger 和内部诊断。
- 治理页面向 admin 展示任务、用量、保留策略、审计和运行概览；敏感值只显示配置状态或脱敏标识。
- 用户安全页面支持登录、刷新、退出、修改密码和必要的会话失效反馈。
- 运维命令必须支持预检、明确目标、幂等或可重入、非交互自动化和可解释退出码；危险动作要求显式确认。
- API 和页面错误使用稳定业务码与可行动文案，不回显堆栈、SQL 或上游秘密。
- 发布和回滚步骤写入 Operations，不在 Design 中保存个人绝对路径或一次性流水。

## 安全与合规

- JWT 与认证 HMAC 每环境独立且满足最小熵；Refresh Cookie 使用 HttpOnly、SameSite 和生产 Secure 策略。
- 登录、验证、重置、来源探测、采集、Codex、报告和运维动作均进入版本化的全入口边界矩阵，逐项定义速率、并发、尝试和墙钟限制。
- SSRF、私网重定向、Prompt Injection、路径穿越/符号链接逃逸、恶意 Markdown/XSS 和压缩炸弹必须逐类在对应网络连接、工具/子进程动作、文件写入、渲染/交付或解压落盘等外部副作用之前拒绝；拒绝留存净化审计，不创建或改写业务事实。
- 所有来源 URL 执行 SSRF 防护；重定向逐跳重新解析并验证，限制响应体和压缩展开。
- Codex Adapter 使用独立运行目录、最小权限认证、网络出口控制、进程超时和输出 Schema；工作区退出后按策略清理。
- 日志字段、Metrics 标签和审计元数据控制基数，不使用邮件、完整 URL 查询、正文或 Token 作为标签。
- 依赖和镜像执行漏洞检查；真实秘密、数据库 dump、Vault、对象内容、日志和构建产物不得提交。
- 来源权利变化触发停用、删除同步或保留缩短，不用“技术可访问”替代授权。

## 失败与降级

- PostgreSQL 不可用：readiness 失败并停止写业务事实；不把任务降级到内存队列。
- Redis 不可用：需要验证码或短期票据的流程明确不可用，已有数据库会话和非相关读取按安全边界决定是否继续。
- MinIO 不可用：证据相关新写停止，数据库已有事实保持可查询；恢复后对账缺失对象。
- Worker 停止：River 任务保留，租约到期后受控重领；重复执行仍满足幂等。
- Codex Adapter 连续失败：熔断新智能任务或降低并发，确定性链路继续，告警不暴露输入正文。
- 发布失败：readiness 先阻止不兼容实例接流量，旧版本和持久卷保持不动，根据兼容性回滚应用与配置；不删除 PostgreSQL 事实、MinIO 对象、Vault 内容或 River 任务历史，不执行破坏性 Schema 回滚。
- 恢复对账不一致：保持隔离恢复环境，输出缺失/多余/哈希错误清单，未经确认不覆盖生产。

## 验收边界

| 验收 ID | 边界 |
|---|---|
| AC-005-001 | 活跃/禁用用户、有效/撤销会话及 Viewer/Analyst/Editor/Admin 四角色访问页面、直接 API、刷新或重放 Token 时，服务端权限一致，禁用/撤销立即失效；Analyst 只管理自有 Monitor、扫描与反馈，Editor 审核，Admin 管理用户、来源和运行，契约与回归完整。 |
| AC-005-002 | 错误路径、构建、OpenAPI、日志、文档和前端 Bundle 扫描在含测试 Secret、Token、DSN、来源凭据和 Codex 认证的受控环境中证明所有外发面无明文秘密；API 只返回配置状态/脱敏标识，一次泄露即阻断发布。对 JWT/HMAC、来源主密钥、数据库/MinIO/SMTP 与 Codex 测试凭据执行新凭据预检、兼容窗口、滚动、旧凭据撤销和失败回退，既有会话/密文按批准策略可解释，审计不含新旧明文。 |
| AC-005-003 | SSRF、私网重定向、Prompt Injection、路径穿越/符号链接逃逸、恶意 Markdown/XSS 和压缩炸弹均在对应外部副作用前逐类拒绝并净化审计，不污染业务事实；登录、验证、重置、来源探测、采集、Codex、报告和运维的速率/并发/尝试/墙钟矩阵越界同样在副作用前失败停止。各类边界都保存可重复 Fixture、停止点和审计断言。 |
| AC-005-004 | 跨 API、River、来源、Codex、Event、通知和 Vault 的运行可在运行中心、Metrics 和净化日志中以安全 ID 串联，关键失败与积压触发可测试告警；固定日志字段白名单、可检索维度和 Metric 标签保持有界，唯一 URL/邮件/正文/Prompt/Payload 等高基数或敏感输入不能成为字段名、索引维度或标签，超长值按策略拒绝、截断或摘要且不泄露原文。 |
| AC-005-005 | 覆盖各数据类别、撤权和部分失败的保留策略支持预览、执行、中断、恢复，并对账 API、MinIO、Vault 自动投影、通知深链可见性和检索；删除只影响批准范围，Notification Outbox/User Notification/Notification Read Receipt/Delivery Attempt 与 Vault 人工区域保持存在。命中未批准范围或产生未解释差异时按明确条件停止，失败可重入，撤权对象不再通过任何读取面暴露；固定 Fixture、策略版本、运行 ID、差异和审计证据可重复。 |
| AC-005-006 | River 任务在排队、运行、重试、外部调用后本地提交前和失败阶段被终止 Worker 后可恢复并执行取消/重试；任务与业务事实不丢失、不重复。外部副作用遵循通道的 Fencing、Provider 幂等/回执或显式 `unknown` 停止契约，不把本地幂等误报为外部 exactly-once；历史尝试可诊断，普通运维 DTO 不泄露 Payload 或秘密。 |
| AC-005-007 | 独立恢复环境从一致的 PostgreSQL、MinIO、Vault 备份执行全量恢复、对象哈希对账、任务恢复和投影重建；校验和、Schema 兼容或对账不通过即在隔离环境停止、不覆盖目标，并保存可重复时间线、命令参数、校验和、差异与失败证据。只有真实 RPO/RTO 达到并批准后才能承诺 15 分钟/2 小时目标。 |
| AC-005-008 | 001–005 P0 候选版本在单机 Compose、不依赖 HA 的前提下通过全量质量、E2E、UAT 与发布门禁；固定探针、分钟统计、维护窗口、依赖故障与错误预算后报告候选可用性，并记录当前本机开发环境和固定 CI Runner 的容量与余量。readiness 在接流量前阻断 Schema/OpenAPI/配置不兼容实例，应用/配置回滚不删除 PostgreSQL、MinIO、Vault 或任务历史；所有 P0 AC 有证据且生成物无漂移，评论、周报、更多来源、邮件和 HA 保持 P1。 |

## 未决项

- OPEN-005-001：可用性、RPO、RTO、备份频率与保留期需要基于目标部署环境和数据增长测量批准。
- OPEN-005-002：Codex 认证文件的部署注入、轮换和故障撤销方式需要本地与容器分别演练。
- OPEN-005-003：生产秘密使用主机级 Secret、加密文件或外部系统，需要在不扩大首版运维面的前提下选择。
- OPEN-005-004：Metrics 告警阈值、日志保留和通知责任人需在 Operations 演练后激活。
- OPEN-005-005：非空数据库兼容升级是否属于首版范围，需结合现有部署数量与数据价值确认。
- OPEN-005-006（已关闭）：既有用户不自动映射，新注册仍为 Viewer，Admin 显式分配或回滚 Analyst，并保留角色变更审计。
- OPEN-005-007：根 `AGENTS.md` 要求 `make openapi` / `make ci`，但当前仓库没有 Makefile；G3 前必须选择新增真实包装入口或将治理规则改为现有 runner/脚本命令，不能让 Acceptance 引用不存在的门禁。
