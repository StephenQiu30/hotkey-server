# 实时热点监控 MVP 功能基线计划

## 计划结论

实现顺序围绕一条纵向主链展开：先让一个 Monitor 通过一个来源产生一张正确热点卡片，再扩展到六类 Web 来源、筛选搜索和实时通知。不得先建设事件聚类、证据图谱、报告平台或新基础设施。

037 已于 2026-08-13 进入实现阶段。只有当 P0 主链、代码门禁和真实浏览器验收全部通过后才创建 Acceptance，未经验证的能力不标记完成。

## 前置门禁

- [ ] 只审计与 037 直接相关的现有 OpenAPI、Schema、Monitor、来源适配、采集任务、热点查询、通知、邮件和工作台文件；不进行无目标的全仓代码阅读。
- [ ] 建立“保留、修改、删除、缺失”差距表，优先复用已有事实和端点，不创建第二套 Hotspot/Notification/Job。
- [ ] 每个对外来源保存权利依据、实际授权能力和真实冒烟前置条件；未授权来源不进入实现。
- [ ] 为固定提交 [`cd48b08`](https://github.com/liyupi/yupi-hot-monitor/tree/cd48b0885bfa8ae9c8043cf78ef6cfd045530bdb) 的用户行为保存只读参考，不复制其代码、视觉资产或非官方抓取方式。

## 预计变更范围

精确文件在 Slice 0 的最小差距审计后锁定，原则上只涉及：

| 范围 | 目标文件/目录 |
|---|---|
| 数据 | `backend/db/schema.sql`，仅在现有模型无法表达多 Monitor 命中、扫描状态或最新互动指标时修改 |
| 后端领域/应用 | `backend/internal/` 中现有 monitor、source、collection/ingestion、hotspot/event、notification、mail 和 agent/application 模块 |
| 后端入口 | 现有 HTTP、Worker/River 注册、WebSocket 和 Bootstrap；不新增第二个服务 |
| 契约 | 现有 Swaggo 注解、`backend/openapi/docs.go`、`docs/openapi/swagger.json` |
| 前端 | `frontend/src/app/dashboard/` 相关热点、监控、搜索页面，以及现有 dashboard 组件、状态和生成 Client |

| 文档 | 037 Design/PRD/Plan；实现完成后才新增 037 Acceptance，必要时更新 Operations |

如果 Slice 0 发现现有对象已经覆盖逻辑契约，则修改现有对象，不按上表名称机械创建新目录或表。

## 简单对象与冗余清理原则

- [ ] 主链只对外暴露 `Monitor`、`Hotspot`、`Scan`、`SourceStatus` 和 `Notification` 五类简单对象；Go struct 不依赖运行时框架，TypeScript 对象只来自 OpenAPI 生成客户端。
- [ ] 一个事实只有一种公开 DTO 形状；热点雷达和即时搜索复用同一卡片字段，不再通过 `analysis`、MicroEvent 或手写前端类型包装第二层。
- [ ] 替换默认主链后删除已无调用方的旧页面、组件、路由、组装代码和测试；不破坏性删除已持久化历史事实。
- [x] 每个可独立验收的功能切片都必须按“失败测试→最小实现→冗余清理→相关回归→Conventional Commit”收口。
- [x] 一个切片提交后立即执行 `git status --short`；只有工作区干净或者剩余改动已明确归属下一个正在开发的切片时，才继续下一步。

## Slice 1：Monitor 与扫描任务

### 测试先行

- [x] 后端保存创建、重复、编辑、暂停、恢复、删除和历史保留测试。
- [x] 保存自动调度只读取启用 Monitor、手动任务幂等、同 Monitor 不重叠、部分来源失败状态测试。
- [x] 前端保存新增后立即扫描、状态反馈、暂停/恢复、删除确认和错误状态测试。

### 实现

- [x] 复用现有 Monitor 用例补齐 CRUD 和状态；不另建 Keyword 旁路。
- [x] 默认每 30 分钟由现有持久任务执行器创建扫描任务；手动接口只负责入队并立即返回任务状态，不同步等待整轮采集。
- [x] 使用确定性任务键保护同一 Monitor/时间桶，重复点击返回既有任务。
- [x] Scan 暴露 `queued/running/succeeded/partial/failed` 和每来源摘要，页面无需读取 Worker 日志判断进度。

## Slice 2：Web 自动扫描与即时搜索来源

### 统一合同测试

- [ ] 建立来源 contract suite，要求所有适配器返回统一字段、明确状态、超时/配额信息和确定性外部 ID。
- [ ] 每个来源使用本地 HTTP fixture 覆盖成功、空结果、分页、限流、超时、上游错误和字段缺失。
- [ ] 未配置/无授权连接必须返回 `unavailable`，禁止降级为 HTML 抓取。

### 来源实施顺序

1. [ ] X 官方 API：Recent Search、排回复/转发、作者与互动指标。
2. [ ] Hacker News 官方 API：最新/热门 item、本地关键词匹配和原生分数。
3. [ ] RSS/Atom：作为开发期稳定的合法纵向来源和额外产品来源。
4. [ ] Bing Grounding/授权网页搜索：网页发现与引用 URL。
5. [ ] Bilibili 开放平台/授权 webhook：视频与账号更新。
6. [ ] 微博开放平台/授权 Feed：明确热榜匹配或全文搜索能力。
7. [ ] 授权中文网页搜索：只有获得搜狗授权时使用“搜狗”品牌，否则使用实际来源名称。
8. [ ] Google Agent Search 与 DuckDuckGo Instant Answer：可进入 Web 即时搜索，不冒充 Web 自动六源主链。

- [ ] Registry、自动 Scan、即时搜索和来源筛选都由同一个 capability registry 驱动。
- [ ] 每个声明可用来源在发布前执行真实凭据冒烟；结果和日期写入未来 Acceptance，不进入稳定单元测试。

## Slice 3：查询扩展、规范化、去重与 AI

### 测试先行

- [ ] 保存扩展词真实进入支持来源 query 的测试，而不是只进入 Prompt。
- [ ] 保存发布时间超过 7 天、发布时间未知、外部 ID 去重、规范 URL 去重、跟踪参数和 fragment 测试。
- [ ] 保存一个 Hotspot 命中两个 Monitor、同 Monitor 重试不重复通知、重复发现更新指标测试。
- [ ] 保存结构化 AI 输出、50/65 阈值、可疑默认隐藏、未分析降级和不发高优先级邮件测试。

### 实现

- [ ] 查询扩展只生成 3–8 个受控别名/缩写/翻译；原始查询永远保留，结果随 Monitor 版本可追溯。
- [ ] 来源结果进入一个规范化函数；未知字段保留 null，不用当前时间或 0 掩盖缺失。
- [ ] 身份键优先 `source_type + external_id`，规范 URL 作为回退；仅删除明确跟踪参数，不做语义聚类。
- [ ] 复用现有关系表达 Hotspot 与多个 Monitor；若现有模型不能表达，才在唯一 Schema 中加入最小关联事实。
- [ ] 结构化 AI 结果保存质量、相关性、理由、直接提词、重要性和摘要；Prompt 外显阈值由 Application 执行。
- [ ] 事务内保存 Hotspot/Match/Notification，提交后再触发 WebSocket 与邮件任务。

## Slice 4：单一热度、热点雷达和即时搜索

### 测试先行

- [ ] 后端保存统计、五种组合筛选、五种稳定排序、两页翻页和非法参数测试。
- [ ] 保存卡片 `heat_score` 与热度排序使用同值的契约测试。
- [ ] 保存即时搜索三来源成功一来源失败、统一 DTO、默认不持久化/不通知测试。
- [ ] 前端保存正常、空、加载、部分失败、全失败、分页和筛选重置测试。

### 实现

- [ ] 在服务端维护唯一热度函数，映射点赞、转发、评论、回复、引用、浏览和来源原生分数；将最终值作为 DTO 字段返回。
- [ ] PostgreSQL 完成筛选、排序和分页；删除应用层全量加载排序路径。
- [ ] 热点雷达展示四项统计和统一卡片；AI 理由及原始片段按需展开，原文链接始终可见。
- [ ] 即时搜索复用来源 Registry、规范化、AI 和卡片 DTO，返回 `results + source_statuses`；默认不写业务事实。
- [ ] 来源筛选项只展示 Registry 中当前实际可用或明确不可用的来源，不展示未接线幽灵选项。

## Slice 5：实时通知、顶栏铃铛与邮件

### 测试先行

- [ ] 保存提交后 2 秒内在线送达、用户/Monitor 隔离、断线重连、重新订阅和 REST 补拉测试。
- [ ] 保存通知事务一致性、重复任务不重复通知、未读数、最近通知、跳转和全部已读测试。
- [ ] 保存 high/urgent 邮件、low/medium 不发送、SMTP 缺失、暂时失败、幂等和最终失败测试。
- [ ] 保存桌面与移动导航均不出现“通知”菜单文字、右侧铃铛仍可达的回归测试。

### 实现

- [ ] 继续以 PostgreSQL Notification 为事实，WebSocket 只传递已提交 ID；重连用 `after_id` 或等价游标补拉。
- [ ] 客户端重连后重新订阅所有启用 Monitor，并以 ID 去重实时与补拉结果。
- [ ] 顶栏铃铛同步更新未读数和最近通知，点击定位对应 Hotspot；不恢复一级菜单通知入口。
- [ ] 邮件作为独立持久任务发送，转义上游标题/摘要，记录尝试并有界退避；失败不回滚热点。

## 契约变化原则

- 先扩展现有业务契约，不新建版本相同但字段不同的 `/hotspots2`、`SearchResultV2` 或手写前端 DTO。
- OpenAPI 至少能表达 Monitor CRUD、Scan 状态、Hotspot 列表/统计、即时搜索结果及来源状态、Notification 列表/已读和实时补拉游标。
- 即时搜索与持久热点共享卡片字段；搜索特有的 `source_statuses` 放在响应信封，不把 AI 结果嵌套成另一种形状。
- 任何 API 变化先更新 Swaggo 注解和后端测试，再生成发布 OpenAPI 与前端 Client。

## 数据迁移

- 迁移前备份 PostgreSQL，并统计现有 Monitor、热点、关联和通知数量。
- 优先原位扩展现有事实；若历史热点只能关联一个 Monitor，回填当前关联为一条 Match，不猜测其他 Monitor。
- 热度字段可从现有最新互动指标重算；缺失指标保持 null，不能伪造历史趋势。
- 新唯一约束上线前先输出冲突报告并以确定性规则合并，不静默删除历史热点或通知。
- Schema 只能修改 `backend/db/schema.sql`，使用现有空库初始化/兼容性升级流程，不引入第二套迁移框架。

## 回滚

- 自动调度可按 037 任务类型暂停；手动查询和历史读取保持可用。
- 单个来源适配器可独立禁用，Registry 与 UI 同步显示不可用，不回退到未授权抓取。
- WebSocket 可暂时关闭，REST 通知补拉与邮件事实不受影响。
- AI 异常时切到 `unavailable` 降级，不把所有内容标为可信；恢复后重试未分析任务。
- 数据变更只追加最小关联/状态字段；回滚应用前保留数据，禁止删除历史 Hotspot、Match 或 Notification。
