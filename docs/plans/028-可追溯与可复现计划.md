## 4. 实施规格 SPEC

这些是可评审的执行规格；路径/接口名称为候选，G2 冻结后才是实施契约。若调整需同步测试、客户端与本文件，不私自改变 PRD 的用户语义。

| SPEC ID | 规格 |
|---|---|
| SPEC-028-API-001 | 在业务响应暴露允许的来源、时间、输入与方法版本；复算通过受限任务提交，不直接读取别人的输入清单。 |
| SPEC-028-DATA-001 | 记录全链标识、输入集合、比较参考集、规则与实际输出；不可变引用与删除后允许保留的元数据分开。 |
| SPEC-028-JOB-001 | 确定性计算复用冻结输入；非确定模型保留实际运行记录，不保证逐字相同；删除后的复算明确受限。 |
| SPEC-028-UI-001 | 改进本质量要求影响的实际业务页面、状态或运维记录，不默认新建一个独立质量功能页面；无界面变化时以书面理由说明该 UI 分支不适用，不能跳过实际受影响界面。 |
| SPEC-028-SEC-001 | 先检查当前身份及资源权限；配置版本不能绕过撤权、删除、停用和更严格预算。秘密不可回读，正文与外部输入只作数据。关键变更留操作者、对象、时间与版本。 |
| SPEC-028-OBS-001 | 对断链、过期和方法变化提供诊断，通用日志脱敏；回退保留版本链与当前授权。 |
| SPEC-028-OPS-001 | 在隔离依赖验证后渐进启用本能力；保持历史资料可读。配置缺失或外部条件不满足时明确拒绝/延期。变更前评估数据兼容与回退，停止新增操作优先于破坏性迁移。 |

数据/接口/前端执行顺序：先冻结字段、状态与权限 → 同步更新 schema.sql 与 ORM → 领域服务和 Worker → FastAPI/Pydantic 运行契约 → 导出并核对 OpenAPI → 生成客户端 → 页面接入 → 配置/镜像与完整验收。无 API 或数据变更的质量项在 G2 记录不适用，不强建空接口或无效 DDL。
