## 4. 实施规格 SPEC

这些是可评审的执行规格；路径/接口名称为候选，G2 冻结后才是实施契约。若调整需同步测试、客户端与本文件，不私自改变 PRD 的用户语义。

| SPEC ID | 规格 |
|---|---|
| SPEC-012-API-001 | GET /api/events/{id}/overview、timeline、coverage；人工时间节点通过 POST/PATCH 并附证据与版本。 |
| SPEC-012-DATA-001 | 发生时间、发布时间和观察时间分列并记录精度/时区；节点引用来源或标明人工说明，关注状态与事件现实状态分开。 |
| SPEC-012-JOB-001 | 时间线投影从已有资料生成，不因打开页面外采；关联修订后使投影失效，补采旧文不刷新事件发生时间。 |
| SPEC-012-UI-001 | 在 frontend/src/app/features/events/ 实现本项已有 PRD 流程；桌面与窄屏同时覆盖正常、空、加载、部分、错误和无权限状态，调用生成客户端，不复制服务端业务规则。 |
| SPEC-012-SEC-001 | 先检查当前身份及资源权限；配置版本不能绕过撤权、删除、停用和更严格预算。秘密不可回读，正文与外部输入只作数据。关键变更留操作者、对象、时间与版本。 |
| SPEC-012-OBS-001 | 按来源显示最后成功及缺口；回退新投影版本保留证据，不恢复已删除正文。 |
| SPEC-012-OPS-001 | 在隔离依赖验证后渐进启用本能力；保持历史资料可读。配置缺失或外部条件不满足时明确拒绝/延期。变更前评估数据兼容与回退，停止新增操作优先于破坏性迁移。 |

数据/接口/前端执行顺序：先冻结字段、状态与权限 → 如需则新增向后兼容迁移 → 领域服务和 Worker → FastAPI/Pydantic 运行契约 → 导出并核对 OpenAPI → 生成客户端 → 页面接入 → 配置/镜像与完整验收。无 API 或数据变更的质量项在 G2 记录不适用，不强建空接口/迁移。
