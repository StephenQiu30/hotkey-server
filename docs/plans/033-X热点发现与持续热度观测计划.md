## 测试先行步骤

1. X 连接器契约测试先改为 `tweet.fields`、`referenced_tweets`，新增 `note_tweet` 长帖、缺失/显式零、部分错误与凭据泄漏回归；新增首次 `relevancy` 补齐与日常 `recency` checkpoint 隔离测试，先证明旧实现失败。
2. 新增批量 Lookup 测试：最多 100 ID、稳定排序、去重、部分错误、429 reset、401/403、超大响应、私网 DNS 与跨端点重定向。
3. 新增持久刷新用例测试：资格筛选、跨 Monitor 去重、刷新优先级、预算耗尽、过期对象和相同任务重放。
4. 新增 PostgreSQL 集成测试：同一 Post 重复观测只保留一个 Content/Observation/DocumentVersion，指标快照递增且当前指标更新。
5. 新增 Content→MicroEvent 关系测试，证明指标提交只调用 v2 重算，legacy Event/Heat 不增长，部分失败可由任务重试。
6. 扩展 EventHeatRepository 集成测试：单帖不恒为 1.0、窗口增量单调、来源外总体参与、缺 baseline 为 null、样本不足带 fallback。
7. 新增 MicroEvent 查询与 HTTP 契约测试：`heat/latest` 排序、冻结游标、无快照排后、非法旧游标 400。
8. 前端先新增事件列表测试：Heat、窗口、加速度、谱系、降级原因、URL 状态、加载/空/错误和移动布局。

## 实现步骤

### A. X 官方契约修正

- 修改 `backend/internal/modules/source/infrastructure/x/connector.go` 的字段参数和响应模型，支持 `note_tweet` 与 `referenced_tweets`。
- 保留历史 `referenced_posts/repost_count` 只作为响应兼容读路径，不再作为官方请求字段。
- 增加一次性 `relevancy` 补齐请求形状，使用独立游标/运行身份，不改变日常 `recency` checkpoint，也不命名为热门结果。
- 更新连接器 profile version，使新原始证据可与旧解析器区分。

### B. X 批量指标刷新

- 在 Source application/domain 增加只表达已知 Post ID 的官方 Lookup 端口和结果 DTO，不暴露 HTTP/供应商结构。
- 在 X infrastructure 实现固定 `https://api.x.com/2/tweets` 批量读取，复用安全 transport、凭据、限流和 raw EvidenceSnapshot。
- 在 Ingestion/Event 边界增加待刷新 X Content Reader，按当前 Monitor、MicroEvent、观察期、最近快照和预算返回有界候选。
- 使用现有持久队列增加稳定 X metric refresh job；成功项归档响应、关联既有 Observation、更新 Content 指标并追加 snapshot。
- 如果现有 collection run 无法诚实表达 Lookup 运行，先提交 Schema 变更设计评审；不得把 Lookup 响应伪装成 Recent Search。

### C. Heat v2 指标重算

- 扩展 Event-owned Content 关系 Reader，返回关联的当前 MicroEvent ID。
- 复用 `event/domain.NormalizeEngagement` 的增量、百分位与小总体对数降级，不在 SQL 中复制第二套公式；首次绝对量只用于刷新候选优先级。
- 为 MicroEvent 加载 baseline/latest 与来源外滚动总体；Heat v2 只读取归一化互动，不读取 credibility。
- 指标提交后按统一分钟边界重算 1h、6h、24h；确保 snapshot 幂等收据和 retry 行为。
- 修正 `ContentRepository.AppendMetricSnapshot`，使独立刷新同时维护 Content 当前指标投影。

### D. 热点列表与跨端契约

- 扩展 `MicroEventListQuery`、PostgreSQL Repository、Transport DTO 和 OpenAPI，支持 `sort=heat|latest` 与不透明游标。
- Latest Heat 明确返回或选择窗口，不能依赖同结束时间下 `window_started_at DESC` 的隐含顺序。
- 使用后端生成 OpenAPI 和前端 Client；禁止手改生成文件。
- 更新 `MicroEventWorkspace` 列表项和 URL 状态，移除任何前端本地热度计算。

### E. 配置、可观测性与文档

- SourceConfig 只增加有界 X 刷新字段；同步 Domain、Transport、Schema/OpenAPI、来源对话框和配置测试。
- 增加刷新请求、Post 数、部分失败、预算延后、指标陈旧与 v2 重算失败指标；标签不得包含 Post ID、查询或正文。
- 更新来源故障手册、容量阈值和 033 Acceptance；真实 X 验收仅使用测试 Monitor，不提交 Token 或原始响应。

## 迁移与回滚

- 配置字段使用向后兼容默认值，升级后持续刷新保持关闭；旧 X 来源继续执行现有 Recent Search。
- 回滚先关闭 X 持续刷新并等待运行中批次完成，再回退应用。已归档原始证据、指标快照和 Heat 快照作为审计事实保留。
- 不回退 `since_id`，不删除 Content/Observation/DocumentVersion，不把新 Heat 快照覆写为旧算法结果。
- 如果跨端游标契约回滚，旧游标返回 400 并要求客户端重新加载，不猜测转换。
