|---|---|
| SPEC-032-API-001 | 运维 CLI/受控任务负责备份和恢复，不向普通用户开放原始备份下载；状态页面只暴露授权范围内摘要。 |
| SPEC-032-DATA-001 | 备份清单包含配置、业务关系、证据对象清单、版本及一致性时间点；密钥材料与备份分开。 |
| SPEC-032-JOB-001 | 计划备份校验后才替代上一有效副本；恢复在隔离实例进行，先重放删除/撤权再允许用户访问。 |
| SPEC-032-UI-001 | 改进本质量要求影响的实际业务页面、状态或运维记录，不默认新建一个独立质量功能页面；无界面变化时以书面理由说明该 UI 分支不适用，不能跳过实际受影响界面。 |
| SPEC-032-SEC-001 | 先检查当前身份及资源权限；配置版本不能绕过撤权、删除、停用和更严格预算。秘密不可回读，正文与外部输入只作数据。关键变更留操作者、对象、时间与版本。 |
| SPEC-032-OBS-001 | B0 实际演练 RPO≤24小时、RTO≤2小时候选目标；核心读写核对完成才停止计时，恢复采集保持暂停。 |
| SPEC-032-OPS-001 | 在隔离依赖验证后渐进启用本能力；保持历史资料可读。配置缺失或外部条件不满足时明确拒绝/延期。变更前评估数据兼容与回退，停止新增操作优先于破坏性迁移。 |

数据/接口/前端执行顺序：先冻结字段、状态与权限 → 同步更新 schema.sql 与 ORM → 领域服务和 Worker → FastAPI/Pydantic 运行契约 → 导出并核对 OpenAPI → 生成客户端 → 页面接入 → 配置/镜像与完整验收。无 API 或数据变更的质量项在 G2 记录不适用，不强建空接口或无效 DDL。
