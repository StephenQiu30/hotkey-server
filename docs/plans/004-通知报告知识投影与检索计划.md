# 通知、报告、知识投影与检索计划

## 当前实现与差距

### 当前实现

- `notification`、`alert` 与 `delivery` 模块已保存 Notification Outbox、User Notification、Delivery Attempt、短期 Delivery Claim、WebSocket/REST 读取和邮件等能力；当前已读游标仅在前端 `localStorage`，邮件 lost-ack 也没有服务端 `unknown` 结果；
- `report` 模块已有报告构建、存储、River Job、候选读取和 HTTP 入口；
- `knowledge` 模块已有文档、Proposal、Snapshot、Reconciliation、MinIO 与 Vault Writer；
- `ingestion` 与 `event` 已提供内容/事件检索、结构化字段、`pg_trgm` 和 PostgreSQL FTS 投影基础；
- `backend/db/schema.sql` 已包含通知 Outbox、用户通知、报告、知识文档/Revision、Vault Sync 和投递记录；
- 前端已有通知、搜索、热点和内容详情页面，以及 WebSocket 状态与安全 Markdown 组件。

### 主要差距

- 站内通知必须以 PostgreSQL 通知事实为源，通过 River 投递和 WebSocket 推送，断线后以 REST `after_id` 补拉；WebSocket 不能成为事实源；
- 日报中的事实性 Claim 必须 100% 引用有效 Evidence，审批后冻结不可变 Revision，重新生成不能覆盖已批准版本；
- Vault 自动区域和人工区域需要稳定边界、原子写入、Hash/Revision 冲突和 Inbox 流程；自动发布不能覆盖人工编辑；
- 全文知识检索必须使用 PostgreSQL FTS、`pg_trgm`、过滤、聚合和安全高亮，不使用 Elasticsearch、Embedding、向量召回或 RAG；
- Notification Outbox、User Notification、目标 Notification Read Receipt 和 Delivery Attempt 是追加式持久事实与游标/交付审计锚点，禁止清空；前端 `localStorage` 只保留可丢弃缓存。恢复只清理 Delivery Claim/租约、WebSocket 会话和客户端缓存；外部交付必须补齐租约过期抢占、Fencing、Provider 幂等/回执与 lost-ack `unknown` 停止语义，不能用本地唯一键虚构 exactly-once。报告、Vault 自动区域和搜索投影必须提供从 PostgreSQL 事实重新排队、对账和恢复的运维路径，Vault 人工区域只从现存 Vault/Revision/备份恢复；
- 四角色权限和前端五态需要同时覆盖通知、报告审批、知识冲突和搜索结果撤权；
- 通知可见、报告生成、Vault 发布和搜索索引延迟需要固定基准环境；
- 周报、评论报告、外部 Webhook 和新增通知通道不进入 24 周 P0。既有邮件能力保持兼容但不在本计划扩大。

#### S01 T06 实施证据（2026-08-28）

- `TestEmailDeliveryRepositoryClaimsWithCurrentPermissionBackoffAndTerminalAttempt` 直接读取 PostgreSQL `clock_timestamp()`、`claimed_at` 与 `lease_until`，证明租约由数据库时间生成；客户端不再提交领取或完成时间。
- `TestEmailDeliveryRepositoryReusesDispatchKeyWithHigherFenceForIdempotentProvider` 从既有 Generation 7 Attempt 建立 Worker A Generation 8、过期后 Worker B Generation 9 的抢占链；B 复用同一稳定派发键，A 的旧 Token/Generation 无法提交 Attempt，最终 Attempt 只绑定 Generation 9。
- `TestEmailDeliveryRepositoryFencesExpiredWorkersAndStopsUnknownSMTPReplay` 在发送开始、租约过期、权限撤销和 A 迟到的停止点注入故障；无幂等/回执能力的 SMTP Claim 被追加为 `unknown / provider_outcome_unconfirmed`，随后不再进入自动领取。
- `TestEmailDeliveryStartsFencedDispatchBeforeCallingProvider` 固定 `claim → start → send → complete` 顺序；`TestEmailDeliveryReconcilesProviderReceiptWithoutSendingAgain` 证明已有 Provider 回执时发送计数为零；`TestEmailDeliveryReusesStableDispatchKeyForIdempotentProvider` 证明仅以原派发键重试一次；`TestEmailDeliveryStopsWhenProviderReceiptCannotBeConfirmed` 证明无幂等保护且回执不可确认时追加 `unknown` 而不发送；`TestEmailDeliveryLeavesStartedFenceWhenProviderAcceptedButAttemptCommitFails` 保存 Provider 已接收而本地提交失败的恢复锚点。
- SMTP 适配器显式声明不支持 Provider 幂等与回执。该实现只承诺“有能力时按稳定键对账/幂等重试；无能力或结果不确定时停止并形成 `unknown`”，不承诺外部 exactly-once。旧版未带派发键的临时 Claim 在 Schema 升级时被保守标记为已开始，过期后同样进入 `unknown`，不会盲目重发。

#### S03 T02 实施证据（2026-08-28）

#### S03 T03 实施证据（2026-08-28）

- PostgreSQL 适配器只在当前 Knowledge Document、同 Revision 的不可变 Revision、`applied` Proposal、Revision New Hash、Generated Hash 和 Frontmatter 全部闭合时返回自动区重建事实；无法从事实重建正文时返回不可用/冲突，不根据 Hash 或 Vault 内容猜测正文。
- Revision 快照写入使用 `If-None-Match: *` 条件创建：同键同内容重试幂等，不同内容返回冲突，禁止并发 Proposal 覆盖受保护恢复来源。Vault 文件缺失时，恢复服务以 4 MiB 上限读取该快照；仅当快照不存在时才读取显式备份。恢复出的完整文件必须仍等于 PostgreSQL 当前 Content Hash，并通过“目标必须不存在”的 Compare-and-Swap 发布；当前文件存在但 Hash 冲突时不读取旧快照、不覆盖，交由 Proposal/Reconciliation 治理。

## 数据与契约顺序

1. 先保存通知 Read Receipt、Claim/Fencing/lost-ack、Revision、Vault、搜索和重建的失败测试；
2. 数据变化只在 canonical `schema.sql` 向前兼容增加，先同步 Read Receipt/Delivery `unknown`、Repository/Model/Schema 检查；
3. 先提交 PostgreSQL 事实和 River Job，再推送 WebSocket、写 Vault 或刷新搜索投影；外部投影失败不回滚事实；
4. 报告先冻结时间窗和 Evidence，再生成草稿、审批、冻结 Revision，最后发布知识投影；
5. 搜索读模型先影子构建和对比，确认权限/召回后切换默认读取；
6. Transport 注解完成后生成 OpenAPI，再生成客户端和更新 UI；
7. 重建/对账和停用入口必须在生产灰度前完成。

## 灰度、迁移与回滚

- 通知先对内部用户启用服务端 Read Receipt 和 WebSocket，同时保留 REST 读取；迁移时将本地 `readThroughID` 仅作为一次性候选，服务端校验后追加 Receipt，此后服务端为准。实时故障时关闭 WebSocket 但不停止通知事实和补拉；
- 外部交付先用 Fake Provider 验证 Fencing、幂等/回执和 lost-ack，再按 Provider Capability 灰度；出现 `unknown` 时暂停该派发键自动重试，不删除 Claim/Attempt 证据；
- 日报先生成不可发布草稿，Evidence 覆盖和审批稳定后开放发布；回滚只停新生成/发布，不修改已冻结 Revision；
- Vault 先写隔离目录并做 Hash 对账，再按 Monitor/报告灰度；异常时暂停 Writer，保留 Proposal 和已冻结报告；
- PostgreSQL FTS 先影子查询并与当前搜索比较，再切换默认；质量或性能回退时切回旧读路径，不删除新投影；
- 现有 Embedding/向量表和旧搜索代码在替换验收与回滚窗口内保留，本计划不删除；
- 任何撤权和删除先在读取/搜索层阻断，再由 005 的保留工作流处理投影与对象；
- 邮件等既有通道保持兼容，不在本计划新增通道或删除历史投递事实。
