## 3. RED/GREEN

1. RED：`go run ./test/runner test ./internal/platform/queue -run 'TestReactivateByUniqueKey'` 要求 available 可提前、discarded/cancelled 保留 attempt/history 且只增加一次 max attempt，completed/running/缺失冲突；当前 Store 无该能力。
2. RED：`go run ./test/runner test ./internal/modules/source/application -run 'TestCollectionControlRetry'` 构造 failed run、已推进的 failure checkpoint 与 discarded job，要求同事务恢复原窗口并 queued/available；当前只改变 run，任务保持终态，原 job 即使人工恢复也无法解析 target。
3. RED：`go run ./test/runner test ./internal/modules/monitor/infrastructure/postgres -run 'TestPublishedCollectionTargetReaderUsesCallerTransactionForRetryCheckpoint'` 证明 reader 必须看到事务内 checkpoint；当前直接使用 pool，无法读取未提交恢复值。
4. GREEN：实现配置 advisory lock、source/query collection claim lock、checkpoint CAS、事务感知 Published Target Reader、Queue 激活、Source retry hook 与基础设施适配器；不得从 application/domain 导入 Queue，Fetch 不得进入事务。
5. 验证任意较新窗口、较新成功 checkpoint、失效 target 与任务异常均完整回滚且不改变新旧 run；重复与并发重试只有一个成功；在 Retry 最新窗口检查后、提交前启动较新 Worker，断言只能一个窗口 claim 且无额外 failed/queued run；真实 `queue.Worker.RunOnce` 领取后 retry run 必须离开 queued。
6. 定向运行上述命令，并运行 `go run ./test/runner test ./internal/modules/source/...`、`go run ./test/runner test ./internal/modules/monitor/infrastructure/postgres`、`go run ./test/runner test ./internal/modules/operations/infrastructure/postgres`、`go run ./test/runner test ./internal/bootstrap`。
7. 运行 `make lint`、`make test`、`make build`、`make validate`、`git diff --check`；对 `db/schema.sql`、`internal/platform/database/model` 与 `docs/openapi` 执行 Git 零差异核对。浏览器只作为跨仓产品验收，不作为 Server 开工或完成门禁。

## 4. 提交与回滚

测试红灯与实现分离提交；文档和索引随任务提交。回滚必须同时恢复 Source 重试协调、Queue 激活和装配，不能保留只重置 run 的旧行为；若线上已有孤立 queued run，回滚前由运维核对并恢复其原任务或归档该测试数据。

## 5. 残余风险

River 终态任务若已被保留策略清理，无法安全恢复原 envelope，接口按冲突失败；系统不猜测或重建丢失任务。
