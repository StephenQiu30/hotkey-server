## 4. 实施规格 SPEC

这些是可评审的执行规格；S02 字段、状态映射与路径已在 Design v1.1 / G2 冻结。若调整需同步测试、客户端与本文件，不私自改变 PRD 的用户语义。

| SPEC ID | 规格 |
|---|---|
| SPEC-029-API-001 | 在任务/来源/事件响应提供各阶段时间、最后成功/尝试与陈旧原因；不添加读取即刷新接口。 |
| SPEC-029-S02-001 | `JobStatusView.source_freshness` 只服务现有任务详情/控制响应；精确按 owner/source/capability/configuration_ref/configuration_version 聚合 `JobAttempt.started_at` 与 `Job.status='succeeded'` 的 `completed_at`。 |
| SPEC-029-S02-002 | queued 才有当前 delay：无 defer 且到期后为 `internal_queue`；rate limit、collector budget、transient、manual retry 归入固定 enum；未知内部 defer 归为 `other`，不透传原字符串。 |
| SPEC-029-S02-003 | 完整成功才推进 `last_success_at`；partial/failed/cancelled 不推进。延期时长为非负 integer microseconds，未来 schedule/顺序异常不产生负时长。 |
| SPEC-029-S02-004 | 复用现有 job detail 页面展示新鲜度字段；OpenAPI 类型只从运行中的当前 API 生成，不手写 DTO/客户端。 |
| SPEC-029-DATA-001 | 统一时区和时间精度，保存计划、受理、启动、获取、持久化及可查询时间；未知保留未知。 |
| SPEC-029-JOB-001 | 用受控时钟分别注入本地排队、限流及预算等待，计算内部目标与整体新鲜度；重试不刷新成功时间。 |
| SPEC-029-UI-001 | 改进本质量要求影响的实际业务页面、状态或运维记录，不默认新建一个独立质量功能页面；无界面变化时以书面理由说明该 UI 分支不适用，不能跳过实际受影响界面。 |
| SPEC-029-SEC-001 | 先检查当前身份及资源权限；配置版本不能绕过撤权、删除、停用和更严格预算。秘密不可回读，正文与外部输入只作数据。关键变更留操作者、对象、时间与版本。 |
| SPEC-029-OBS-001 | 验证 B0 任务到期至启动 P95≤60秒、单批完成至可见≤30秒的候选目标；同时报告所有延期。 |
| SPEC-029-OPS-001 | 在隔离依赖验证后渐进启用本能力；保持历史资料可读。配置缺失或外部条件不满足时明确拒绝/延期。变更前评估数据兼容与回退，停止新增操作优先于破坏性迁移。 |

数据/接口/前端执行顺序：S02 无数据/ORM 变更；更新 job schema 与只读服务投影 → FastAPI 运行契约 → 复用当前 API 的 OpenAPI → 生成客户端 → 详情页 → 自动化/浏览器验证。无 Redis/Kafka/新进程职责变更，不强建空接口或无效 DDL。
