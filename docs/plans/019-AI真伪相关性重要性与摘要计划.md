# AI 真伪、相关性、重要性与摘要计划

## 前置门禁

- Design v1.1 已 accepted，PRD v1.1 已 approved，006 与 018 已验收。
- 复用现有 AI Run、Relevance、Claims、Heat、Radar 与 Summary，不新增 Schema 或第二套分数。
- 行为先由事件页单测锁定，再修改页面；真实浏览器只使用隔离数据，不调用第三方模型。

## 变更范围

- `frontend/src/app/dashboard/events/page.tsx`：Monitor 上下文、辅助请求和研判布局。
- `frontend/src/components/dashboard/EventIntelligencePanel.tsx`：确认、相关性、重要性与声明证据的 shadcn/ui 组合。
- `frontend/src/lib/radarPresentation.ts`：稳定中文标签和不确定性语义。
- `frontend/test/unit/app/dashboard-events-page.test.tsx` 与组件测试：真实生成类型、请求参数、降级与证据。
- `docs/design|prd|plans|acceptance` 与索引：设计决策、完成证据和状态。

## 执行顺序

1. 保存无 Monitor/relevance、低置信度、真实 Radar 分量、声明证据和局部失败的前端失败测试。
2. 提取纯展示组件，复用 `Badge`、`Card`、`Progress`、`Alert`、`Select`、`Button`，不引入客户端分数算法。
3. 事件页并行读取 Monitor/Radar，并在选中事件后并行读取 Update/Intelligence；保持独立错误状态。
4. 运行 React 最佳实践复核、OpenAPI/typecheck/unit/build，确认无请求瀑布和派生状态 Effect。
5. 运行后端全量 CI 保护 AI Run、预算、相关性、声明、摘要和 Heat 降级事实。
6. 运行 Compose/diff 与 `$agent-browser` 的 Viewer/匿名、Monitor 相关性、证据链接、390px 和 axe 验收。
7. 新增 Acceptance、完成 Plan 和索引，以中文 Conventional Commit 提交。
