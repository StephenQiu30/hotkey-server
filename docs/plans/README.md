## 如何执行和更新

每份逐项 Plan 都含：

- 当前差距、责任角色、优先级和切片依赖。
- 拟建/拟改文件、主责和实现顺序；这些不是已存在的代码。
- API、DATA、JOB、UI、SEC、OBS、OPS 七类 SPEC。
- S00 开工准备；S01—S03 三个具体业务/质量切片；S04 完整验收与交付。
- 每个实施切片包含 Red → Green → Refactor；G0—G6 检查关联 AC 和预期 EV。
- 原 PRD 的 6 个验收场景逐项保留，规则到任务的追踪矩阵、验证入口、回退和完成定义。

43 份逐项计划共 **559 个任务、731 个 checklist 项**。总计划与 X 专项另有统筹任务和验收检查，不混入上述统计；文件或勾选数量不作为工时估算。

S00 可先进行范围与设计准备；除 046 本身外，进入任何实现切片前，必须有 **046 S03** 通过证据，再检查各 Plan 的其他显式先行输出。45 份既有 Plan 的 `architecture_prerequisite` 均登记此项；042 已有代码也不豁免。046 基于现有骨架，不依赖 042、031 或 App 初始化；其自身设计复核后先行修复，不形成循环。共同约束的最终业务验收仍在相应领域完成。

同编号 Design 尚未建立的 Plan 用 `design: null`，S00 明确补齐。003/004/007/009 Design 已接受 S00—S03，005 已接受 S00 与 S01 来源无关契约，010 已接受内部 S01/S02 契约，031 已接受 S00—S02，028/029/032 已接受 S00/S01，027 已接受 S00，034、035、036、037、038、039 与 042 已接受各自先行范围；002 整体仍为 proposed，仅 S01 受控范围已冻结，043—045 仍须实施前复核。只有真实产品实现和验收后才能创建 Acceptance，不能用技术切片证据提前生成 passed 记录。
