# X 热点核心链路收敛与遗留系统清理计划

> **终止说明（2026-08-12）**：本计划因错误采用 X-only 假设而终止，未完成的 Slice 4 及所有非 X 退出动作永久取消。已完成且仍有效的单 ID、停止 legacy 双写、运行面去重工作转入 [035 Plan](035-多源AI热点监控首版收敛计划.md) 继续验证。本处 `completed` 表示计划已关闭，不表示原 X-only 验收成立。

## 执行前置

本计划只有在 034 Design=`accepted`、PRD=`approved` 且用户确认 X 核心边界后才能改为 `in_progress`。033 与 034 必须共同评审；禁止先把 033 接到 legacy/v2 双写再清理。

## Slice 0：冻结边界与保存失败测试

1. 保存 Bootstrap 架构测试，列出每个 route group、Scheduler、Worker Handler 和其读写表；测试先证明当前 legacy/v2 同时注册。
2. 保存任务扇出测试，证明当前 `CollectSource` 会进入 legacy Normalize/Match/Event/Heat，同时 v2 文档链也可运行。
3. 保存 Content 与 Alert 深链契约测试，用相同数值但不同 legacy/micro 事件记录复现错误 ID 语义。
4. 保存 Schema 写入者清单和数据库探针，覆盖 legacy Event、Heat、Update、Alert、Report、Knowledge、notification 与非 X source 表。
5. 保存 OpenAPI/生成 Client/前端路由引用快照；新增规则禁止任何新代码引用 legacy Event ID。

验证：上述测试在当前实现至少有一项失败，并精确指向重复 producer 或错误消费者，而不是只断言文件数量。

## Slice 1：单一 MicroEvent ID

1. 为 Content v2 关联新增 Repository/Application 行为测试：从 DocumentVersion→ContentFamily→active MicroEventMember 返回唯一 `micro_event_id`，无唯一关系返回 null。
2. 修改 Content DTO/OpenAPI，移除含混 `event_id/event_title`，输出明确 `micro_event_id/micro_event_title`。
3. 修改 CollectionWorkspace、Content 列表和通知深链，只接受 MicroEvent ID；移除 legacy Alert 深链。
4. 为历史 legacy Content/Alert 提供 Admin 导出，不建立 legacy→v2 猜测映射表。
5. 运行 OpenAPI 生成和前端 Client 生成，禁止手写兼容 DTO。

验证：构造 legacy Event ID 与 MicroEvent ID 冲突，所有用户链接仍只打开正确 MicroEvent 或不显示链接。

## Slice 2：停止 legacy 新写

1. 先扩展队列与数据库集成测试，断言 X 采集后 legacy `monitor_matches/events/event_* /alert_*/reports/knowledge_documents/notification_events` 不增长。
2. 保留 `NormalizeContent` 维护 Content/指标兼容投影，但移除它到 legacy `EvaluateRelevance/ClusterContent` 的扇出；采集成功的业务链只进入 v2 SourceDocument/DocumentMatch/Family/MicroEvent。
3. 指标刷新只重算 MicroEvent 1h/6h/24h Heat v2；移除 033 中 legacy heat 重算要求。
4. UserNotification 继续由 v2 Outbox 投影；卸载 EventUpdate→Alert Thread→Alert Email 路径。
5. 停止 Report Scheduler、Knowledge product producer 和 legacy Delivery handler 新入队。
6. 对部署前已有的 pending/running legacy Job 做 dry-run 清单；排空可安全完成项，对不再合法的项显式取消并写审计，不直接删队列表。

验证：重复、重试、部分失败和重启场景下只有 v2 事实增长，原始证据和指标提交不因下游失败回滚。

## Slice 3：收窄 API 与工作台

1. 从 API Bootstrap 卸载 legacy Event/Radar/EventUpdate/Alert/Report/Delivery Subscription/Knowledge/legacy Agent 路由及不再需要的 service provider。
2. 从 Worker Bootstrap 卸载对应 Handler、Scheduler 和 Dispatcher；启动图测试证明缺少 legacy 依赖仍能启动 API/Worker。
3. 删除生成契约中的 legacy endpoints 并重新生成 OpenAPI Client。
4. 前端导航保留概览、监控、X 来源、内容证据、事件、通知；删除 Alert/Report/Subscription/Profile 中的报告统计和 Agent Token 产品面。
5. 保留 Admin 的最小审计、凭据和事件纠错入口；普通用户不显示 rights/quality/merge-split 等后台面板。
6. 改写 Landing、空状态和 onboarding，使首个任务明确是 X 监控，不再宣传 8+ 来源、私有 Feed、报告和通用情报平台。

验证：API route snapshot、Next.js route build、键盘与 390px/桌面主故事通过；删除导航不能掩盖后台仍在写 legacy 表。

## Slice 4：非 X 来源退出核心运行时

1. 保存现有非 X SourceConnection、MonitorSource 与队列引用 dry-run 清单。
2. 新建来源 UI 只提供 X，默认即 X；后端拒绝核心产品新建非 X 连接。
3. 停止非 X 自动调度，现有连接置为 disabled 并保留历史读取；监控发布不得隐式补 RSS。
4. 当活跃引用为零后，从 Connector Registry、Transport webhook 和 source-specific UI 移除 RSS/HN/Bing/Bilibili/Weibo/Google 实现。
5. 删除 SourceType/配置字段前先验证历史导出和 canonical Schema 引用；遇到活跃连接则阻止物理删除。

验证：X 认证、限流或预算失败时只显示明确降级，不产生任何非 X 请求。

## Slice 5：不可达代码与 Schema 清理

1. 用 `rg`、Go package graph、OpenAPI 和前端 build 确认 legacy Application/Domain/Repository 无生产引用，再用 `apply_patch` 分模块删除。
2. 提供 034 cleanup dry-run：报告 legacy 表行数、外键、队列任务、API/Client 引用、SourceConnection、MinIO/Vault 引用和最近写入时间。
3. 完成一致备份与独立恢复演练，记录数据库、对象和 Vault 清单摘要。
4. 在经评审的完整回滚窗口内证明零 legacy 写入；不满足时保持只读表，不执行 DDL。
5. 从 `backend/db/schema.sql` 删除已批准的 legacy 表、列、索引、函数与种子数据；不创建 migrations 目录或第二份 SQL。
6. 验证空库初始化、非空升级 dry-run/apply、重复 apply、失败事务、恢复、API/Worker 启动和 X 端到端故事。

首批候选删除仅包括已经退出运行面的 legacy Event/Radar/EventUpdate/Alert/Report/Subscription/Knowledge product/notification 表。Rights、Evidence、Document、MicroEvent、Heat v2、UserNotification、Audit 与 Queue 表不在候选中。

## 与 033 的编排

推荐实施顺序：

1. 034 Slice 0–2：锁定单 ID 并停止 legacy 双写；
2. 033：实现官方 X 发现、Post Lookup、指标窗口和 Heat v2 排序；
3. 034 Slice 3–5：卸载非核心运行面并在门槛满足后物理清理。

## 回滚

- Slice 1–4 回滚只恢复上一已审计应用版本和 v2 profile，不删除新 v2 事实，也不重新启动 legacy 双写作为长期状态。
- 物理 Schema 删除前必须有已验证备份；删除后回滚通过恢复备份和上一应用版本完成，不尝试从 v2 猜测重建 legacy 事实。
- 任一 dry-run、引用扫描、零写入或恢复门槛失败时停止在只读隔离状态，核心 X v2 链继续运行。

## 完成定义

- 033 的 X 输入在重试和重启下只产生一套 v2 事件、热度和通知事实。
- 当前 API、OpenAPI、Client、UI 和深链只有 MicroEvent ID。
- 默认 API/Worker/前端启动图不包含 legacy 产品链和非 X 自动采集。
- 历史数据处置有导出、审计、恢复和删除证据；未满足门槛的数据未被破坏。
- 新增 Acceptance 034，记录实际命令、启动图、零写入探针、恢复演练和完整 X 用户旅程。
