## 4. 实施规格

| ID | 规格 |
|---|---|
| SPEC-044-API-001 | GET/POST/PATCH /api/model-source-subscriptions；GET 模型资料/变化，手动同步受理 202；所有权、分页、幂等及 operation_id 冻结后走唯一 OpenAPI/客户端生成链。 |
| SPEC-044-DATA-001 | source＋完整 ID＋范围及不可变快照；价格用 Decimal 保留币种/单位/档位；发布/创建/首次发现/抓取时间分开；完整性不足不推进水位。 |
| SPEC-044-JOB-001 | 复用订阅调度和预算；条件请求仅在支持时使用；失败不清空旧快照；变化/提醒幂等；首次建基线不刷历史通知。 |
| SPEC-044-UI-001 | 信息源—模型平台，模型/公告列表、前后差异、关注命中、事件及通知；展示空/部分/陈旧/待核查/无权限，不要求模型 Key。 |
| SPEC-044-SEC-001 | 来源公开域名和跳转/网络目标校验；JSON/RSS/HTML 均不执行指令；个人关注和事件仍鉴权，不采购付费抓取。 |
| SPEC-044-OBS-001 | 快照范围/版本/完整性、前后证据、同步延迟和通知去重可核查；接口 GET 成功不计产品验收。 |
| SPEC-044-OPS-001 | 按源小范围启用，解析变化先暂停差异/提醒再修复；历史保持可读；没有模型推理依赖，原有来源不受阻。 |

顺序：字段/状态/权限冻结 → 必要 schema.sql/ORM 变更及新库校验 → 领域服务/Worker → FastAPI/Pydantic → OpenAPI/生成客户端 → 页面 → 环境/浏览器及真实来源证据。无变更层说明 N/A，不增加旁路。
