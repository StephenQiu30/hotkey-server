这些是可评审的执行规格；路径/接口名称为候选，G2 冻结后才是实施契约。若调整需同步测试、客户端与本文件，不私自改变 PRD 的用户语义。

| SPEC ID | 规格 |
|---|---|
| SPEC-006-API-001 | POST /api/followed-accounts/resolve；POST/PATCH /api/followed-accounts；POST /api/followed-accounts/{id}/runs。先展示候选身份再显式确认，解析本身属于需计量操作。 |
| SPEC-006-DATA-001 | 以平台稳定用户 ID 建立关注对象，别名历史、原作/引用/转帖归属及监控配置分离。 |
| SPEC-006-DATA-002 | 离线存储以 `(owner_id, source_key, external_id)` 唯一身份；别名按稳定身份保留观测历史；同名/别名冲突返回多个候选，不自动合并、改绑或宣称来源已确认。所有读取按 owner 过滤，不持久化原始输入、URL、Token 或响应正文。 |
| SPEC-006-JOB-001 | 默认不按主题关键词过滤作品；时间线采样和旧作品刷新分开，置顶旧帖不推进不正确水位。 |
| SPEC-006-UI-001 | 在 frontend/src/app/accounts/ 实现本项已有 PRD 流程；桌面与窄屏同时覆盖正常、空、加载、部分、错误和无权限状态，调用生成客户端，不复制服务端业务规则。 |
| SPEC-006-SEC-001 | 先检查当前身份及资源权限；配置版本不能绕过撤权、删除、停用和更严格预算。秘密不可回读，正文与外部输入只作数据。关键变更留操作者、对象、时间与版本。 |
| SPEC-006-OBS-001 | 用户名变更与身份冲突均记录，不自动以粉丝量选人；停用关注不删已有合法作品。 |
| SPEC-006-OPS-001 | 在隔离依赖验证后渐进启用本能力；保持历史资料可读。配置缺失或外部条件不满足时明确拒绝/延期。变更前评估数据兼容与回退，停止新增操作优先于破坏性迁移。 |

数据/接口/前端执行顺序：先冻结字段、状态与权限 → 同步更新 schema.sql 与 ORM → 领域服务和 Worker → FastAPI/Pydantic 运行契约 → 导出并核对 OpenAPI → 生成客户端 → 页面接入 → 配置/镜像与完整验收。无 API 或数据变更的质量项在 G2 记录不适用，不强建空接口或无效 DDL。
