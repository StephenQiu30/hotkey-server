## 4. 实施规格 SPEC

这些是可评审的执行规格；路径/接口名称为候选，G2 冻结后才是实施契约。若调整需同步测试、客户端与本文件，不私自改变 PRD 的用户语义。

| SPEC ID | 规格 |
|---|---|
| SPEC-007-API-001 | S01 只开放 `GET /api/contents` 与 `GET /api/contents/{content_id}`；观察/版本读取在 S02/S03 按实际表补充。读取不得隐式抓取；刷新任务归 010/真实来源编排，本项不预建空 POST。 |
| SPEC-007-DATA-001 | S01 以 owner＋来源＋对象类型＋可空原生作用域＋原生 ID 唯一；作品、job 发现关系和不可变观察分表，六类指标为可空非负整数。S02 已加入正文版本与关系；S03 加入可见性历史及实际 PostgreSQL 清理 target。 |
| SPEC-007-JOB-001 | 内容写入由任务调用，同一作品/operation 等价重投返回原观察、异义重用拒绝；发现按 content/job 去重，当前投影按观察/接收时间稳定选择且不改写历史。 |
| SPEC-007-UI-001 | 在 frontend/src/app/content/ 实现本项已有 PRD 流程；桌面与窄屏同时覆盖正常、空、加载、部分、错误和无权限状态，调用生成客户端，不复制服务端业务规则。 |
| SPEC-007-SEC-001 | 先检查当前身份及资源权限；配置版本不能绕过撤权、删除、停用和更严格预算。秘密不可回读，正文与外部输入只作数据。关键变更留操作者、对象、时间与版本。 |
| SPEC-007-OBS-001 | 隔离身份冲突，保留来源时间精度与原文链接；仅停用新写入即可回退，不破坏既有版本关系。 |
| SPEC-007-OPS-001 | 在隔离依赖验证后渐进启用本能力；保持历史资料可读。配置缺失或外部条件不满足时明确拒绝/延期。变更前评估数据兼容与回退，停止新增操作优先于破坏性迁移。 |

数据/接口/前端执行顺序：先冻结字段、状态与权限 → 同步更新 schema.sql 与 ORM → 领域服务和 Worker → FastAPI/Pydantic 运行契约 → 导出并核对 OpenAPI → 生成客户端 → 页面接入 → 配置/镜像与完整验收。无 API 或数据变更的质量项在 G2 记录不适用，不强建空接口或无效 DDL。
