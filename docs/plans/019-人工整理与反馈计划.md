## 4. 实施规格 SPEC

这些是可评审的执行规格；路径/接口名称为候选，G2 冻结后才是实施契约。若调整需同步测试、客户端与本文件，不私自改变 PRD 的用户语义。

| SPEC ID | 规格 |
|---|---|
| SPEC-019-API-001 | POST /api/curation-actions；POST /api/curation-actions/{id}/undo；PATCH /api/events/{id}/follow。每次操作明确对象、最小作用范围与期望版本。 |
| SPEC-019-DATA-001 | 人工备注、关注标记、关联排除和撤销记录；保留前后版本，不能覆盖来源原文或全局误删实体。 |
| SPEC-019-JOB-001 | 人工反馈使受影响评分/分析失效，优先更新仍入同一受限调度队列；下一轮自动归并读取已确认约束。 |
| SPEC-019-UI-001 | 在 frontend/src/app/events/[eventId]/components/ 实现本项已有 PRD 流程；桌面与窄屏同时覆盖正常、空、加载、部分、错误和无权限状态，调用生成客户端，不复制服务端业务规则。 |
| SPEC-019-SEC-001 | 先检查当前身份及资源权限；配置版本不能绕过撤权、删除、停用和更严格预算。秘密不可回读，正文与外部输入只作数据。关键变更留操作者、对象、时间与版本。 |
| SPEC-019-OBS-001 | 审计操作者与原因，撤销是新记录；权限变化后不能撤销恢复自己无权访问的数据。 |
| SPEC-019-OPS-001 | 在隔离依赖验证后渐进启用本能力；保持历史资料可读。配置缺失或外部条件不满足时明确拒绝/延期。变更前评估数据兼容与回退，停止新增操作优先于破坏性迁移。 |

数据/接口/前端执行顺序：先冻结字段、状态与权限 → 同步更新 schema.sql 与 ORM → 领域服务和 Worker → FastAPI/Pydantic 运行契约 → 导出并核对 OpenAPI → 生成客户端 → 页面接入 → 配置/镜像与完整验收。无 API 或数据变更的质量项在 G2 记录不适用，不强建空接口或无效 DDL。
