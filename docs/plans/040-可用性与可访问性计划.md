## 4. 实施规格 SPEC

这些是可评审的执行规格；路径/接口名称为候选，G2 冻结后才是实施契约。若调整需同步测试、客户端与本文件，不私自改变 PRD 的用户语义。

| SPEC ID | 规格 |
|---|---|
| SPEC-040-API-001 | 复用业务接口及稳定错误码；界面业务文案不透传异常类名，也不隐去失败原因。 |
| SPEC-040-DATA-001 | 测试只保存脱敏任务完成记录、设备/浏览器条件和问题清单；受试者帮助次数与代理身份单列。 |
| SPEC-040-JOB-001 | 后台状态变化转为可感知通知，不依赖轮询动画或颜色；无后台新任务实现需求。 |
| SPEC-040-UI-001 | 改进本质量要求影响的实际业务页面、状态或运维记录，不默认新建一个独立质量功能页面；无界面变化时以书面理由说明该 UI 分支不适用，不能跳过实际受影响界面。 |
| SPEC-040-SEC-001 | 先检查当前身份及资源权限；配置版本不能绕过撤权、删除、停用和更严格预算。秘密不可回读，正文与外部输入只作数据。关键变更留操作者、对象、时间与版本。 |
| SPEC-040-OBS-001 | 桌面、375/320 CSS像素窄屏、键盘、焦点和语义检查；5名目标或代理用户至少4名无现场指导完成核心任务的候选门槛。 |
| SPEC-040-OPS-001 | 在隔离依赖验证后渐进启用本能力；保持历史资料可读。配置缺失或外部条件不满足时明确拒绝/延期。变更前评估数据兼容与回退，停止新增操作优先于破坏性迁移。 |

数据/接口/前端执行顺序：先冻结字段、状态与权限 → 如需则新增向后兼容迁移 → 领域服务和 Worker → FastAPI/Pydantic 运行契约 → 导出并核对 OpenAPI → 生成客户端 → 页面接入 → 配置/镜像与完整验收。无 API 或数据变更的质量项在 G2 记录不适用，不强建空接口/迁移。
