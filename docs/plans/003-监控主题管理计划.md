| SPEC ID | 规格 |
|---|---|
| SPEC-003-API-001 | S01 冻结 POST `/api/topics`、GET/PATCH `/api/topics/{topic_id}`；写入返回配置版本，过期 `expected_version` 返回 409。列表、clone、pause/resume、archive 只在 S02 增加，不提前建空端点。 |
| SPEC-003-DATA-001 | S01 以 `monitor_topics` 保存稳定身份/当前指针，`monitor_topic_versions` 保存不可变规则快照；新建固定暂停/待选来源。后续运行任务显式引用主题 ID 和版本。 |
| SPEC-003-JOB-001 | 保存和预览均不入采集队列；显式启动交给 009；暂停后调度不再创建任务，已运行任务可另行取消。 |
| SPEC-003-UI-001 | 在 frontend/src/app/monitors/ 实现本项已有 PRD 流程；桌面与窄屏同时覆盖正常、空、加载、部分、错误和无权限状态，调用生成客户端，不复制服务端业务规则。 |
| SPEC-003-SEC-001 | 先检查当前身份及资源权限；配置版本不能绕过撤权、删除、停用和更严格预算。秘密不可回读，正文与外部输入只作数据。关键变更留操作者、对象、时间与版本。 |
| SPEC-003-OBS-001 | 记录主题变更版本与启动/暂停审计，普通日志不写原始词组；恢复默认暂停，防止重放保存触发采集。 |
| SPEC-003-OPS-001 | 在隔离依赖验证后渐进启用本能力；保持历史资料可读。配置缺失或外部条件不满足时明确拒绝/延期。变更前评估数据兼容与回退，停止新增操作优先于破坏性迁移。 |

数据/接口/前端执行顺序：先冻结字段、状态与权限 → 同步更新 schema.sql 与 ORM → 领域服务和 Worker → FastAPI/Pydantic 运行契约 → 导出并核对 OpenAPI → 生成客户端 → 页面接入 → 配置/镜像与完整验收。无 API 或数据变更的质量项在 G2 记录不适用，不强建空接口或无效 DDL。
