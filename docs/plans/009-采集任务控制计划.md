## 4. 实施规格 SPEC

这些是可评审的执行规格；路径/接口名称为候选，G2 冻结后才是实施契约。若调整需同步测试、客户端与本文件，不私自改变 PRD 的用户语义。

| SPEC ID | 规格 |
|---|---|
| SPEC-009-API-001 | POST /api/jobs；GET /api/jobs/{id}；POST /api/jobs/{id}/cancel、retry。提交携带幂等标识，持久化成功才返回受理；拒绝非法状态转换。 |
| SPEC-009-DATA-001 | 任务、尝试、配置版本、时间窗、取消标记、阶段结果、稳定错误和 outbox 共事务保存；Redis 缓存与 Kafka 消费进度不作业务事实源。 |
| SPEC-009-JOB-001 | 明确排队、运行、延期、部分、失败、取消与成功转换；取消后停止新增请求，重试使用受限尝试且重新校验权限。 |
| SPEC-009-UI-001 | 在 frontend/src/app/jobs/ 实现本项已有 PRD 流程；桌面与窄屏同时覆盖正常、空、加载、部分、错误和无权限状态，调用生成客户端，不复制服务端业务规则。 |
| SPEC-009-SEC-001 | 先检查当前身份及资源权限；配置版本不能绕过撤权、删除、停用和更严格预算。秘密不可回读，正文与外部输入只作数据。关键变更留操作者、对象、时间与版本。 |
| SPEC-009-OBS-001 | 任务与阶段关联 ID 贯通日志；撤回 Worker 版本前停止新派发并核对在途任务，不删除队列或业务记录。 |
| SPEC-009-OPS-001 | 在隔离依赖验证后渐进启用本能力；保持历史资料可读。配置缺失或外部条件不满足时明确拒绝/延期。变更前评估数据兼容与回退，停止新增操作优先于破坏性迁移。 |

数据/接口/前端执行顺序：先冻结字段、状态与权限 → 同步更新 schema.sql 与 ORM → 领域服务和 Worker → FastAPI/Pydantic 运行契约 → 导出并核对 OpenAPI → 生成客户端 → 页面接入 → 配置/镜像与完整验收。无 API 或数据变更的质量项在 G2 记录不适用，不强建空接口或无效 DDL。
