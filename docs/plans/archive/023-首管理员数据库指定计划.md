# 首管理员数据库指定计划

## 1. 开工门禁

Plan 必须经非主要编写者评为 `accepted/approved/ready` 后修改生产代码。

## 2. 文件边界

删除 `internal/bootstrap/user_command.go`、对应集中测试，以及 identity PostgreSQL 的 `BootstrapAdmin`/`ErrBootstrapUnavailable` 和专用竞争测试。修改 `internal/bootstrap/app.go`、config、`.env.example`、本机 `.env`、README、`test/_suite/internal/modules/identity/infrastructure/postgres/user_repository_test.go`、`test/_suite/internal/modules/identity/application/service_integration_test.go`、架构门禁和文档索引；检查并清理存在时的 `.env.prod`，由 Operations-009 明确部署环境与 Secret Store 清理步骤。创建 Operations-009；不修改 Schema、OpenAPI 和业务 HTTP 契约。

## 3. RED/GREEN

1. RED：架构测试扫描生产代码、`.env.example`、存在时的 `.env.prod` 和 README，当前 bootstrap key/command 必须失败；配置测试确认加载结果不再暴露专用字段或键。
2. GREEN：删除配置字段/键、命令分发、专用文件和 Repository 实现；保留普通注册、角色生命周期与最后管理员测试，测试管理员用例由测试数据库直接提升已创建用户。
3. Operations 初始指定 SQL 使用 advisory xact lock、零 active admin guard、唯一目标条件、数据库 `current_user`、必填变更单号和事务审计；最终核对只匹配目标的 active/admin/未删除记录。break-glass SQL 必须确认当前唯一错误 admin 与正确 viewer，先提升正确用户再降级错误用户，并以同一变更单号记录两条审计。
4. 隔离 PostgreSQL 表驱动集成测试必须覆盖：成功指定；错误邮箱；disabled、deleted、editor 目标；已有 active admin；两个不同 viewer 并发指定时恰好一个成功；成功审计的主体/变更单/前后角色；任一失败或显式回滚不留下角色或审计变化；break-glass 成功以及目标不满足时的原子回滚。
5. 验证 config/bootstrap/identity 定向测试、模块编译、`make lint/build/validate`、diff-check、Schema/OpenAPI 零差异；隔离 DSN 不存在时上述数据库集成逐项记录 blocked，不伪造通过。
6. 独立实现复审无 P0/P1/P2 后提交、归档。

## 4. 回滚

不得在“已有 viewer、尚无 admin”的数据库上只回滚代码：旧 bootstrap CLI 会因用户表非空而不可用。回滚前必须先按 Operations-009 成功指定首管理员，或把整个数据库恢复到任务前的空库备份；数据库角色回滚不得直接把唯一 active admin 降级。
