# 内容标准化去重时效与原始证据计划

## 前置门禁

- Design v1.1 已 accepted，PRD v1.1 已 approved，017 已验收。
- 仅处理现有官方 API、RSS、Atom 或授权 Feed 已捕获的数据；不为归档读取新增原网页请求。
- 行为变更先保存失败测试，实现后不放宽旧有安全、幂等和完整性断言。

## 变更范围

- `backend/internal/modules/ingestion/domain/`：7 天事件候选策略、文档可用性和原因值对象。
- `backend/internal/modules/ingestion/application/`：同源去重语义和安全证据投影。
- `backend/internal/modules/ingestion/infrastructure/jobs/`：relevance 后的新鲜度门禁，不改变队列信封。
- `backend/internal/modules/ingestion/transport/http/`、`docs/openapi/swagger.json`、`backend/openapi/docs.go`：文档状态契约与生成物。
- `frontend/src/components/dashboard/ContentDocumentViewer.tsx`、生成 Client 和 `frontend/test/`：使用现有 shadcn/ui 组合显示证据原因。
- `backend/test/`：领域、任务、集成、HTTP 和 Schema 回归。本条预期不修改 Schema。

## 执行顺序

1. 增加去重失败测试：同源 exact URL/hash/near text 仍折叠，跨源 exact URL/hash 保留 active。
2. 增加 7 天策略边界测试和 Evaluate Worker 测试：新鲜内容建 cluster 任务，旧内容仅保存 relevance 事实。
3. 增加文档投影失败测试：未捕获、pending/missing/delete_pending、MinIO 读失败和完整性失败均返回稳定无正文结果。
4. 修改最小 Domain/Application/Job 代码，运行相关 Go 包测试并保持旧有并发、删除、对账与幂等回归。
5. 修改 Swaggo DTO/注解，运行 `make openapi`，然后在前端运行 `npm run openapi:generate`；不手写 DTO 或 API 路径。
6. 使用 `Badge`、`Card`、`Empty`、`Button` 组合已归档、未捕获与不可用界面，补齐前端单元测试。
7. 运行后端全量 CI、前端契约/typecheck/unit/build、Compose 与 diff 检查；用 `$agent-browser` 验收 Viewer/Editor、正常/缺失/不可用、390px 和 axe。
8. 新建同编号 Acceptance，将 Plan 更新为 completed，更新索引并使用中文 Conventional Commit 提交。
