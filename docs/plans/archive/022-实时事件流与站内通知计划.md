# 实时事件流与站内通知计划

## 前置门禁

- Design/PRD v1.1 已评审；003、017、020 已验收，021 已完成且不构成运行依赖。
- 现有四类业务事实保持唯一来源；通知只保存恢复和展示所需的安全投影。
- 行为变化先保存失败测试；生成物仅通过 Swaggo 与官方 OpenAPI Client 生成器更新。

## 变更范围

- `backend/db/schema.sql`、数据库模型门禁：notification outbox、索引、append-only 与四类事务触发器。
- `backend/internal/modules/notification/`：领域事件、角色过滤、Repository、补拉 Service、JSON/SSE Transport。
- `backend/internal/platform/config` 与 HTTP middleware：流轮询/心跳/连接上限、正式 stream 超时豁免和 CORS Header。
- `backend/internal/bootstrap/app.go`：通知仓库、服务与路由装配；OpenAPI 与架构白名单同步。
- `frontend/src/stores/notificationStore.ts`、实时控制器与 SSE parser：持久 ID、去重、退避、轮询与 Toast。
- `frontend/src/layouts/BasicLayout.tsx`、TopNav、通知页与 menu：未读徽标、通知列表、传输状态；保留订阅区。

## 执行顺序

1. 保存 Domain 事件/角色校验、Repository 顺序/容量/RBAC、触发器事务/幂等失败测试。
2. 新增唯一 outbox 表和触发器，最小实现 Repository/Application；更新数据库模型与 Schema 门禁。
3. 保存 JSON 补拉、Bearer SSE、Last-Event-ID、心跳、断连、连接上限和匿名短路测试，再实现 Transport/配置/bootstrap。
4. 生成 Swaggo/OpenAPI 与前端 Client；确认 stream 和 list 都来自生成服务与 DTO。
5. 保存 SSE parser、Zustand 去重/已读、重连/轮询、TopNav 与通知页失败测试。
6. 使用 shadcn/ui Alert/Badge/Button/Card/Empty/ScrollArea 组合通知区，保留现有发布订阅 CRUD。
7. 运行 React 最佳实践复核、后端全量 CI、前端全量门禁、Compose 和 diff 检查。
8. 使用 `$agent-browser` 验收真实新事件→Toast/徽标/通知页、断线补拉、轮询降级、Admin/Viewer/匿名、1440px/390px 与 axe。
9. 新增 Acceptance，归档 022 Design/PRD/Plan，并按中文 Conventional Commit 独立提交。

- `cd frontend && npm run openapi:check && npm run typecheck && npm run test:unit && npm run build -- --webpack`

- 根目录运行开发/生产 Compose 配置检查及 `git diff --check`。
