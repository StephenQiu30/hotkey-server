# 来源凭据与个性化配置计划

## 变更范围

- `backend/db/schema.sql`、Source domain/application/infrastructure/transport、配置与 Bootstrap
- 后端领域、加密仓储、应用、Transport、Schema 与集成测试
- `frontend/src/components/dashboard/SourceConnectionDialog.tsx`、来源页、生成客户端与单测
- 环境模板、根/子项目 README、OpenAPI 与本条 Acceptance

## 测试先行步骤

1. 保存托管引用、仅写字段、加密往返/篡改拒绝、事务轮换和前端直填凭据的失败测试。
2. 增加 `source_credentials` 与约束，使用 AES-256-GCM 实现 Source-owned 凭据仓储。
3. 在 Source 应用中实现创建/轮换事务，兼容 env 引用，并通过注册表向连接器注入短生命周期明文。
4. 生成 OpenAPI 与前端客户端，把来源表单从 env 引用改为密码输入并增加轮换入口。
5. 运行后端 CI、前端类型/单测/构建、Compose、Schema、泄露扫描和真实浏览器验收。

## 回滚

回滚先停用托管来源，再恢复旧应用。Schema 和密文保留，不删除来源、历史采集或审计；env 引用来源不受影响。
