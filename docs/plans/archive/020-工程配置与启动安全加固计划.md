## 3. 测试优先步骤

`internal/bootstrap/app.go` 已在所有角色装配前调用 `cfg.Validate()`，本任务不改该生产文件；bootstrap 测试必须证明 Worker 会沿此现有入口拒绝错误 SMTP 配置。如果测试证明该入口不成立，停止实施、更新本 Plan 文件边界并重新评审。

### Task 1：冻结失败配置契约

- RED：增加 `TestConfigValidateRejectsUnsupportedEnvironment`、`TestConfigValidateRejectsInvalidEnabledSMTP`、`TestValidateAuthenticationRuntimeRejectsKnownPlaceholderSecrets`、`TestValidateAuthenticationRuntimeRejectsInvalidCORSOrigins` 和 `TestNewAppRejectsInvalidEnabledSMTPForWorker`。
- RED 命令：`go run ./test/runner test ./internal/platform/config ./internal/bootstrap -run 'Test(ConfigValidateRejectsUnsupportedEnvironment|ConfigValidateRejectsInvalidEnabledSMTP|ValidateAuthenticationRuntimeRejectsKnownPlaceholderSecrets|ValidateAuthenticationRuntimeRejectsInvalidCORSOrigins|NewAppRejectsInvalidEnabledSMTPForWorker)$' -count=1`。
- 预期信号：新增用例至少因当前实现接受错误配置而失败；错误断言同时验证不包含敏感输入。

### Task 2：最小化启动前校验

- 在 `Config.Validate` 固定环境枚举。
- 在认证运行时校验中拒绝三个已公开占位密钥，并严格解析 CORS origin。
- CORS 用例拒绝相对 URL、非 HTTP(S)、userinfo、任意路径（包括 `/`）、query、fragment 和无 host，同时接受 `http://localhost:3000`。
- 在所有角色均调用的 `Config.Validate` 中，邮件启用时验证 host、1–65535 port、TLS mode、from email 与凭据配对；bootstrap 测试证明纯 Worker 在装配前失败。
- GREEN：重跑 Task 1 命令；三个合法环境和完整安全配置必须通过。

### Task 3：工程入口与示例配置

- 共享 DIRECTORY 类型 GoLand 配置，运行目录为 `cmd/hotkey`，工作目录为 Server 根目录；该形式与 GoLand 在当前项目自动生成且可运行的目录配置一致，不依赖 PACKAGE 对项目模块名的额外解析。
- `.env.example` 使用中文说明，JWT/HMAC 留空；保留现有 Provider/ONNX 配置契约，不写本机凭据。
- `.editorconfig` 只定义跨 IDE 的基础格式，不代替 `gofmt`。
- 同步修改 `README.md`、`README_EN.md` 中的 PACKAGE/完整 import path 说明，统一为 DIRECTORY 与 `$PROJECT_DIR$/cmd/hotkey`。
- 验证：`xmllint --noout .run/HotKey_Server.run.xml`、`go test ./cmd/hotkey`、`git diff --check`；随后让 GoLand 重新加载项目，选择共享的 `HotKey 后端一键启动`，实际 Run 或 Debug 成功并记录该配置名、构建命令、监听地址和停止结果。IDE 临时配置成功不能替代此证据。

### Task 4：回归与验收

- `go run ./test/runner test ./internal/platform/config -count=1`
- `make lint`
- `make build`
- `make validate`
- `git diff --check`
- `git diff --exit-code -- db/schema.sql docs/openapi`
- 若存在可丢弃的 `HOTKEY_TEST_DSN` 和隔离的 `HOTKEY_TEST_REDIS_URL`，执行 `make ci`；缺失时记录限制，不得复用开发数据库伪造证据。
- 由非主要实施者复核实现和证据，无 P0/P1/P2 后才可结案。

## 4. 错误、安全与回滚

- 所有新增错误只指出配置字段和约束，不回显 secret、origin、用户名、密码或邮件地址。
- URL 解析失败、缺失字段和不支持枚举都在监听端口、连接数据库或发送邮件之前失败。
- 回滚以独立文件变更为单位；GoLand/.editorconfig 可单独删除，配置校验回滚不得把公开占位密钥重新设为默认值。
- 本任务没有数据迁移，不产生 Schema 回滚。
