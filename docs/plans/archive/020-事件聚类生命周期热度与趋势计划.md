# 事件聚类、生命周期、热度与趋势计划

## 前置门禁

- Design v1.1 已 accepted，PRD v1.1 已 approved，018、019 已验收。
- 复用现有聚类、Event、Heat、EventUpdate、Radar 和治理 API；先保存失败测试，再改 Schema/实现。
- 本条只增加一个快照 JSONB 字段，不引入新表、第二套分数或第三方模型调用。

## 变更范围

- `backend/db/schema.sql` 与 Event Metric domain/repository/DTO：持久化并投影六维组成。
- Event lifecycle domain：补齐 `closed → archived` 合法边。
- `frontend/src/app/dashboard/events/page.tsx`：并行 Heat/Member 读取和治理状态。
- `frontend/src/components/dashboard/EventHeatPanel.tsx`：总分、趋势、六维、缺失与旧数据状态。
- `frontend/src/components/dashboard/EventGovernancePanel.tsx`：成员锁定、生命周期、合并、拆分。
- 对应领域、PostgreSQL、HTTP、页面和组件测试，以及 020 Acceptance/索引。

## 执行顺序

1. 保存 Heat 六维 JSON、null/旧快照、closed→archived 和 HTTP 契约失败测试。
2. 最小扩展 `HeatResult` 与 `event_metric_snapshots.component_scores`，完成写入、读取、Swaggo/OpenAPI/Client。
3. 保存事件页 Viewer/Editor/Admin、锁定、生命周期、合并、拆分和局部失败的前端失败测试。
4. 使用生成 Client 与 shadcn/ui 组合 Heat/Governance 面板；四个辅助读取并行，写成功后刷新真实事实。
5. 运行 React 最佳实践复核、后端全量 CI、前端全量门禁、Compose 与 diff。
6. 使用 `$agent-browser` 验收 Viewer/Editor/Admin/匿名、真实治理、错误态、桌面/390px 与 axe。
7. 新增 Acceptance、完成索引，以中文 Conventional Commit 独立提交。
