# 内容与事件检索筛选排序计划

## 前置门禁

- Design v1.1 已 accepted，PRD v1.1 已 approved；018、020 已验收。
- 复用 Content Repository、Relevance 快照、Event 只读端口和冻结 Radar；不新增表、搜索服务或分数。
- 行为变化先保存失败测试，生成文件只由 Swaggo/Orval 更新。

## 变更范围

- `backend/internal/modules/ingestion/domain/content.go` 与 Repository/Query/DTO/Handler：Content 查询、动态 Shape Cursor、相关性投影。
- `backend/internal/modules/event/domain/radar.go` 与 Radar Repository/Handler：服务端关键词、ShapeHash 与筛选计划。
- Event application/PostgreSQL：批量 Content→Event 安全归属读取；bootstrap 注入 Content Query。
- `backend/db/schema.sql`：active Content trigram 与 Monitor 最新 Match 覆盖索引。
- `frontend/src/app/dashboard/contents/page.tsx`、`events/page.tsx`：URL 查询、服务端筛选、Cursor 历史和状态隔离。
- 最小检索控件组件与现有 `CollectionWorkspace`、`CursorPagination`、TopNav；不复制 shadcn 基础组件。

## 执行顺序

1. 保存 Content 查询校验、Shape Cursor、关键词/来源/时间/relevance 排序与 Event 归属批量读取失败测试。
2. 最小扩展 Content Domain/Repository/Application/HTTP，增加两个索引和容量 EXPLAIN；验证匿名请求不进入用例。
3. 保存 Radar `q`、ShapeHash、SQL 参数、旧 Cursor 拒绝和冻结跨页失败测试，再扩展现有实现。
4. 更新 Swaggo/OpenAPI/生成 Client；确保可选分数与归属保持 null，不生成伪零。
5. 保存内容页/事件页 URL、300ms 防抖、清除、筛选、分页、范围切换、局部错误和空态失败测试。
6. 使用 shadcn/ui Input/Select/Button/Badge/Card/Table/Empty 组合页面，删除事件页本地结果过滤。
7. 运行 React 最佳实践复核、后端全量 CI、前端全量门禁、Compose 与 diff。
8. 使用 `$agent-browser` 验收 Viewer/Admin/匿名、真实 Content/Event 搜索筛选排序、跨页、刷新/后退/分享、错误/空态、桌面/390px 和 axe。
9. 新增 Acceptance、归档 021 Design/PRD/Plan，以中文 Conventional Commit 独立提交。
