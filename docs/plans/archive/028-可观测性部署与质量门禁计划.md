## 执行步骤

1. 先增加失败测试：指标注册必须包含来源/任务/滞后/配额/成本家族，且标签不含高基数字段；队列尝试不能保存 fixture 秘密或上游原始错误。
2. 在 `operations/infrastructure/postgres` 中以现有 `collection_runs`、`source_connections`、`river_job`、`quota_usage_ledgers`、`ai_runs`、`ai_budget_ledgers` 生成 Prometheus 安全投影；通过 Bootstrap 注册到唯一 Registry，不修改 Schema。
3. 将 `river_job_attempt.error` 收紧为稳定失败码，Operations 任务 DTO 只增加经验证的安全资源 ID 和失败码；更新 Swaggo 并生成 OpenAPI 与前端 Client。
4. 在现有治理页用 shadcn/ui `Card`、`Table`、`Badge`、`Select`、`AlertDialog`、`Alert`、`Skeleton` 组合运行总览与最近任务；不新建路由或自定义基础组件。
5. 为 MinIO 和 Web 增加容器健康检查与依赖顺序；补充全新环境验证脚本或可直接执行的 README 命令。
6. 将后端、前端、生产依赖审计、Compose 配置和 `agent-browser` 容器烟测编排进 GitHub Actions，并保留每个失败阶段的独立名称。
7. 新增备份恢复、升级回滚、密钥轮换、来源授权、故障处置与容量基线 Operations，命令只使用占位变量且先验证再变更。
8. 运行后端 `make ci`、前端契约/类型/单测/构建、开发/生产 Compose、生产依赖审计和全新容器启动。
9. 使用 `$agent-browser` 完成登录→运行总览→来源/任务失败→重试/取消与主业务故事，覆盖 360/768/1280 视口、键盘、焦点、错误态和 WCAG 2 A/AA。
10. 新增 028 Acceptance，全部通过后将三件套移入 `archive/`，同步索引并创建独立中文 Conventional Commit。

## 验证

- `cd backend && make ci`
- `cd frontend && npm run openapi:check && npm run typecheck && npm run test:unit && npm run build`
- 启动完整环境，以浏览器验证登录→监控→采集→事件→告警→报告主故事。
- 根目录运行开发/生产 Compose 配置检查及 `git diff --check`。

## 迁移与回滚

新行为通过配置或 capability 逐步启用。回滚先关闭新入口和任务生产者，等待/取消可重试任务，再回退应用；保留事实、审计、投递和模型运行记录。
