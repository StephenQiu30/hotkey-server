# 低噪声告警与邮件交付计划

## 前置门禁

- Design 023 已 accepted，PRD 023 已 approved；依赖 005、020、022 已验收。
- 现有实现清单已完成：复用 Alert Thread/Occurrence、状态审计、River、SMTP Mailer 和报告 Delivery 重试模式。
- 行为变化先补测试，跨端字段只通过 Swaggo/OpenAPI/生成 Client 传播。

## 预计变更范围

- `backend/internal/modules/monitor/`：告警策略领域、持久化、HTTP 契约与配置哈希。
- `backend/internal/modules/event/`：从不可变 EventUpdate 输出维度快照。
- `backend/internal/modules/alert/`：多维评估、快照、事务协调与详情投影。
- `backend/internal/modules/delivery/`：告警邮件 Delivery、Attempt、模板和任务处理器。
- `backend/internal/platform/queue/`、`backend/internal/platform/bootstrap/`：任务种类、依赖装配和事务适配。
- `backend/db/schema.sql`、模型/Schema 验证测试：两张最小新增表及索引约束。
- `frontend/src/components/dashboard/MonitorDraftDialog.tsx`、`frontend/src/lib/monitorDraft.ts`：完整策略表单。
- `frontend/src/app/dashboard/alerts/page.tsx`：真实详情、历史、审计和投递诊断。

## 执行步骤

1. 为 Monitor 策略范围、默认值、哈希和 HTTP 映射补失败测试，扩展唯一 Schema 与仓储。
2. 为 EventUpdate 维度提取、四门槛判断、严重级别和可配置冷却补领域/应用/仓储测试与实现。
3. 新增告警邮件 Delivery/Attempt，保证 Occurrence + Delivery + River Job 同事务、并发唯一和 5 次安全重试。
4. 扩展告警详情的脱敏投递投影、权限与契约测试；更新 Swaggo 并生成 OpenAPI Client。
5. 使用 shadcn/ui 组合完成监控策略表单和告警详情，补前端单元测试并做 React 最佳实践复核。
6. 运行后端 CI、前端全门禁、Compose 配置和差异检查，修复所有回归。
7. 启动完整服务，使用 agent-browser 验收匿名/角色、配置、触发、详情、状态、空错态、桌面/移动、键盘与 axe。
8. 写入同编号 Acceptance，将 Design/PRD/Plan 归档，更新索引，并按中文 Conventional Commit 规范独立提交。

## 迁移与回滚

新增列具备保守默认值，现有已发布配置立即获得可解释策略；邮件默认关闭，不会自动扩大外发。回滚先关闭告警邮件生产者并等待/取消可重试任务，再回退应用。Thread、Occurrence、Delivery、Attempt 与审计均保留，不删除业务事实。
