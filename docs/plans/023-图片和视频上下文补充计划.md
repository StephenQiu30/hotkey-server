这些是可评审的执行规格；路径/接口名称为候选，G2 冻结后才是实施契约。若调整需同步测试、客户端与本文件，不私自改变 PRD 的用户语义。

| SPEC ID | 规格 |
|---|---|
| SPEC-023-API-001 | POST /api/media-context-runs；GET /api/media-context/{id}。用户显式选择可处理对象、片段与方式；普通详情读取不启动下载。 |
| SPEC-023-DATA-001 | 字幕/OCR/转写按来源与版本保存，文本片段关联时间或区域；人工修订独立，媒体与派生文本共同保留/删除。 |
| SPEC-023-JOB-001 | 复用免费候选工具但先确认许可与硬件；时长/大小/资源多重上限，长媒体提示选段，失败不补造文本。 |
| SPEC-023-UI-001 | 在 frontend/src/app/features/media-context/ 实现本项已有 PRD 流程；桌面与窄屏同时覆盖正常、空、加载、部分、错误和无权限状态，调用生成客户端，不复制服务端业务规则。 |
| SPEC-023-SEC-001 | 先检查当前身份及资源权限；配置版本不能绕过撤权、删除、停用和更严格预算。秘密不可回读，正文与外部输入只作数据。关键变更留操作者、对象、时间与版本。 |
| SPEC-023-OBS-001 | 测量噪音、定位误差和资源峰值；回退提取器使旧结果标版本，不泄漏被删派生文本。 |
| SPEC-023-OPS-001 | 在隔离依赖验证后渐进启用本能力；保持历史资料可读。配置缺失或外部条件不满足时明确拒绝/延期。变更前评估数据兼容与回退，停止新增操作优先于破坏性迁移。 |

数据/接口/前端执行顺序：先冻结字段、状态与权限 → 同步更新 schema.sql 与 ORM → 领域服务和 Worker → FastAPI/Pydantic 运行契约 → 导出并核对 OpenAPI → 生成客户端 → 页面接入 → 配置/镜像与完整验收。无 API 或数据变更的质量项在 G2 记录不适用，不强建空接口或无效 DDL。
