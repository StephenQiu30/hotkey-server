# 热点舆情监控平台总计划

日期：2026-09-25。本计划是唯一的执行计划。v3.0 按 [Design 001 v3.0](../design/001-热点舆情监控平台总体设计.md) 把 P1 重排为"先竖切、再扩面"，并把每个任务写成可直接交给 Codex 执行的任务卡。

## 1. 工作方式

- **执行**：每张任务卡独立交给 Codex（`/codex:rescue` 带上任务卡编号与内容）实现；Claude 负责审查差异、跑验证、按规范提交。一张卡一个提交。
- **Codex 模型**：2026-09-25 已把 `~/.codex/config.toml` 默认改为 `gpt-5.6-sol` + `high`（ChatGPT Pro 账号不支持 `gpt-6-*` 系列，实测重新登录后仍被拒）；首次使用前可运行 `/codex:setup` 检查。
- **测试门禁**（沿用）：Ruff、mypy、pytest（隔离库 `hotkey_test`）、OpenAPI 漂移、前端 lint/typecheck/build；DDL 变更先写失败测试；适配器用固定样本契约测试 + 一次真实冒烟。
- **进度标准**：每张卡的"验收"全部满足才算完成；阶段验收记录写入 `docs/acceptance/`。
- **状态**：BACKLOG 是唯一进度看板（阶段、验收、任务卡、待办、风险，≤ 10 KB）；HANDOVER 只记运行快照（≤ 5 KB）。

## 4. P1-A 竖切：Hacker News

### A1 来源预设与连接配置

- **目标**：一条命令让一个来源可用：`python -m cli sources preset apply <preset>`。
- **文件**：`connections/presets.py`（新增，预设数据）、`connections/services.py`（`SourcePresetService`）、`connections/catalog.py`、`connections/models.py`、`connections/schemas.py`、`evidence/services.py` 与 `jobs/services.py`（补 `*_in_transaction` 保存变体）、`cli/commands.py`、`database/schema.sql`（`source_connection_versions.config JSONB`）。
- **要点**：
  - 一个事务写：连接与连接版本（含 `config`）、每个能力的准入策略与字段用途、同版本保留策略、组件策略、来源预算。
  - 重复应用幂等；预设变化时升版本。
  - `config` 只接受白名单键（如 `feed_url_template`、`base_url`、`engines`、`allowed_hosts`），拒绝任何看起来像凭据的键。
  - 预设首批：`hackernews`（search、comments）。
- **验收**：空库上应用两次结果一致；应用后 `keyword.search` 与 `source.comments` 的准入、保留、组件、预算检查全部通过（集成测试）；字段用途覆盖契约全部字段，不被最小化误删。
- **依赖**：无。

### A2 适配器安全修正并提交

- **目标**：把已写的三个适配器改到可上线标准。
- **文件**：`sources/adapters/http_source.py`、`rss.py`、`web_search.py`、`hackernews.py`，对应单测。
- **要点**：
  - 构造参数增加 `allowed_hosts`；请求与每一跳重定向都校验主机白名单，并复用 `web_targets.py` 的私网拒绝规则；不在白名单返回 `access_denied`。
  - `rss.py` 不再接受任意模板，模板主机必须在白名单内。
- **验收**：新增重定向越界、私网地址、白名单外主机三类失败用例；原有 5 个契约测试通过；三个适配器真实冒烟各一次。
- **依赖**：无。

### A3 注册关键词搜索处理器，修正时间口径

- **目标**：Worker 能执行真实的 `keyword.search`。
- **文件**：`worker/app.py`（处理器注册表）、`content/discovery_execution.py`（按 `source_key` 从预设 `config` 构造适配器）、`content/discovery.py`（无发布时间条目的接收规则）、`core/config.py`（按任务类型的截止时间）。
- **要点**：
  - 适配器工厂按来源键选择 `HackerNewsAdapter` / `RssSourceAdapter` / `WebSearchAdapter`，参数来自连接版本 `config`。
  - 无发布时间的条目不再过滤，以首次发现时间为时间依据（Design 4.3）。
  - 任务硬截止改为按任务类型取值（Design 6.2）。
- **验收**：真实 Kafka + PostgreSQL 下，手动受理一次 HN `keyword.search`，帖子入库、字段完整；无发布时间样本被接收；重投消息不产生重复。
- **依赖**：A1、A2。

### A4 评论采集处理器

- **目标**：`source.comments` 端到端可用。
- **文件**：`content/comments_execution.py`（新增执行器）、`content/discovery.py` 或新文件中的 `CommentPageCommitService`、`worker/app.py`、`content/schemas.py`。
- **要点**：结构与关键词发现一致（租约、连接版本、准入、逐条 `persist_comment_in_transaction`、游标、计量）；上限：一级 200、每条回复 20。
- **验收**：对一条真实 HN 帖子采集评论，楼中楼父子关系与原站一致；Worker 重启后重放不重复；父评论被删除时占位记录正确。
- **依赖**：A3。

### A5 竖切验收

- **目标**：完成 AC-001-100 并记录。
- **内容**：从空库开始：初始化 owner → 应用 HN 预设 → 建主题 → 手动搜索 → 手动评论 → 杀掉并重启 Worker → 重放；记录数据库查询结果。
- **产出**：`docs/acceptance/001-P1A-HN竖切验收.md`。
- **依赖**：A4。

### A6 其余 A 档来源预设

- **目标**：Google News、新闻搜索（SearXNG）、行业 RSS 可用。
- **文件**：`connections/presets.py`、`connections/catalog.py`。
- **验收**：每个预设一次真实 `keyword.search` 入库；SearXNG 结果带发布时间。
- **依赖**：A3。

## 5. P1-B 调度

### B1 主题设置与调度表

- **目标**：主题可配置来源、频率、报告时间、推送目标。
- **文件**：`database/schema.sql`（`monitor_schedules`，主题设置字段）、`monitors/models.py`、`schemas.py`、`services.py`、`api/routers/monitor_topics.py`、前端 `frontend/src/app/monitors/` 与生成客户端。
- **验收**：API 与页面可设置并保存；主题"就绪"判定改为"至少选了一个已应用预设的来源"；OpenAPI 漂移检查通过。
- **依赖**：A1。

### B2 调度进程与采集扫描

- **目标**：主题按频率自动采集。
- **文件**：`worker/scheduler.py`（新增，入口 `python -m worker.scheduler`）、`jobs/services.py`（`accept_in_transaction`）、`content/discovery.py`（入口类型不再写死 `MANUAL`）。
- **要点**：每 30 秒一轮；`FOR UPDATE SKIP LOCKED`；确定性 operation ID；两个调度进程并存不重复。
- **验收**：频率设为 10 分钟，1 小时内生成 6 次采集且无重复；并发两个调度进程测试通过。
- **依赖**：B1、A3。

### B3 评论扫描

- **目标**：热门帖子自动采评论。
- **文件**：`worker/scheduler.py`、`content/services.py`（候选查询）。
- **验收**：近 24 小时互动前 N 的帖子自动产生 `source.comments`，6 小时内不重复。
- **依赖**：B2、A4。

## 6. P1-C 模型与分析

### C1 AI 领域

- **目标**：安全、可审计、可限流的 Codex 调用。
- **文件**：`ai/adapters/codex_app_server.py`（已写，需修正）、`ai/services.py`、`ai/models.py`、`database/schema.sql`（`ai_calls`）、`core/config.py`（`HOTKEY_AI_MODEL`、`HOTKEY_AI_COMMAND`、`HOTKEY_AI_TIMEOUT_SECONDS`）、`db/metadata.py`。
- **要点**：
  - `Popen` 只传 `PATH`、`HOME`、`CODEX_HOME`、`LANG`；每次新建空工作目录并在结束时删除。
  - 验证能否用 `-c` 配置关闭 shell 工具，结论写回 Design 7.2。
  - 调用前经预算账本 `analysis_attempt` 预留、调用后结算；`ai_calls` 不存提示词和回答原文。
- **验收**：`test_ai_calls.py` 转绿；单测覆盖环境变量不泄漏（假服务端打印收到的环境变量）；一次真实调用成功并留下调用记录。
- **依赖**：无（可与 A 并行）。

### C2 批量标注

- **目标**：相关内容都有相关性、情感、摘要、观点。
- **文件**：`analysis/`（新增：models、schemas、services、提示词与输出 schema）、`database/schema.sql`（`content_annotations`）、`worker/app.py`（`analysis.annotate`）、`worker/scheduler.py`（分析扫描）。
- **要点**：批 ≤ 30 条且 ≤ 24,000 字符；输出 `{"items": [...]}`；唯一键按 Design 第 8 节；单条不合法只影响该条；限流延后。
- **验收**：真实 HN 数据跑通；人工抽检 50 条相关性与情感（完整 100 条在 F 阶段）；重复扫描不重复标注。
- **依赖**：C1、B2。
