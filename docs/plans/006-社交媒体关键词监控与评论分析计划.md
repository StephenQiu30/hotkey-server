## 执行前提与边界

个人非商业学习项目；SQLAlchemy 与 RabbitMQ 为固定约束。首轮单人单实例，按学习切片推进，允许按许可复用 MediaCrawler 等组件；不因非商用许可直接排除。Celery 为当前 Worker 框架方案，固定连接 RabbitMQ。

本计划按用户要求从零重建全 Python 服务端，不依赖旧 Go、River、Agent、Schema 或旧验收的正确性。v1 保留 Go 控制面的计划已撤回。用户已授权实施，当前进入 Python 基础切片；尚未真实采集，旧工作树已清理，不创建整体验收通过记录。旧实现仅作为待核查的历史材料。

目标最小栈：FastAPI / Pydantic v2 / SQLAlchemy 2 / psycopg 3 / Alembic，PostgreSQL、Celery prefork / RabbitMQ、对象存储，HTTPX / Playwright，TypeScript 工作台。框架版本在实施时验证并锁定。服务拆分按资源和秘密隔离，不为每个业务模块建立微服务。

## 实施规格（SPEC）

### API

`SPEC-006-API-001`：固定栈检查：所有业务持久化通过 SQLAlchemy，迁移用 Alembic；实际任务 broker 必须是 RabbitMQ。Celery eager 或内存替身只能用于局部单测，不能作为集成通过依据。

新 `/api/v1` 契约由 FastAPI/Pydantic 生成 OpenAPI，TypeScript Client 从同份文档生成；不兼容旧 Go DTO。当前错误体统一 code/request_id，客户端负责可读提示，HTTP 状态表达鉴权/冲突/限流；202 返回持久 run/job ID，错误信息不包含来源秘密。以下路径是待实现提案。

| 路径 | 要点 |
|---|---|
| `POST /sessions`、`DELETE /sessions/current`、`GET /me` | 新会话、撤销和身份，不导入旧会话 |
| `GET /source-connections/{id}/capabilities` | 操作、范围、费用/试用、最后验证与凭据状态 |
| `POST /monitors/preview`、`POST /monitors/{id}/versions` | 编译预览、不可变发布与幂等请求键 |
| `POST /objects/{id}/conversation-runs` | 评论策略/预算；返回持久任务身份 |
| `GET /objects/{id}/comments` | flat/tree、parent、受限 depth/limit，游标绑定权限/对象/排序/快照 |
| `GET /collection-runs/{id}`、`POST /collection-runs/{id}/cancel` | 进度/覆盖/预算/稳定停因，取消不等于已停止 |
| `GET /events/{id}/opinions`、`GET /evidence/{id}` | 冻结输入版本、样本、引用和下载权限；不暴露任意对象 Key |

首轮只允许 owner 与默认 workspace，拒绝客户端切换归属；列表、节点、下载和后台任务均核对来源可见范围。新身份采用同源安全 Cookie、会话摘要/撤销、CSRF 校验、成熟密码散列、限速与审计。

### DATA

`SPEC-006-DATA-001`：新建 social_objects/object_versions/observations/raw_artifacts 与 object_relations，外部唯一身份含 workspace/platform/resource_kind/visibility_scope/external_id。类型保留 post/comment/reply；reply、quote、repost、thread_member 分开。评论通过根帖关联事件，不能只用 comment.text LIKE 关键词查询归属。

`SPEC-006-DATA-002`：未知 parent 保存 typed 外部引用与 unresolved，关系拒绝循环/自环/错误根；同根并发更新需串行校验。编辑追加版本，指标追加快照，缺失不填零或推断删除。X conversation_id 不作为直接父。旧 captured_item 只能在证据有效且通过新校验后导入。

`SPEC-006-DATA-003`：conversation_collections 保存计划/实际排序、根/回复数、上游口径和停因；sampling_members 冻结 object_version IDs 与 provenance。候选每轮200/日400/每帖7日1000新增节点，单分析批最多200，深度3；跨重试/排序共享预算，多入口只计一次。

`SPEC-006-DATA-004`：撤权/删除先设读侧屏障，再清理原始对象、正文、索引、报告/分析和缓存；任务提交检查屏障版本。备份恢复先重放删除账本，过期报告不能继续暴露撤权文本。

### JOB

`SPEC-006-JOB-001`：PostgreSQL jobs/attempts/checkpoints/outbox 为持久事实；Celery JSON 消息只含 job_id/dispatch_epoch/contract_version。搜索、详情、根评论、每父回复、指标/可见性、标准化、事件/分析分别为有界任务。任务与解析版本固定，不让新版解释旧 cursor。

`SPEC-006-JOB-002`：业务事务同时写 job 与 Outbox；Dispatcher 发布持久消息、检测不可路由并等待 publisher confirm 后标 sent。重复窗口正常，Consumer 按状态/epoch/租约领取并 fencing。Reconciler 同时恢复 unsent、sent 未领取和失联租约；测试 broker 清空/重启后恢复。来源事务保存页/观察/checkpoint/后继 Outbox，内容事务保存对象/版本/关系/分析 Outbox。原始对象先落存储可产生孤立对象，由保留任务回收，不假设跨存储原子事务。

`SPEC-006-JOB-003`：每父回复独立 checkpoint；固定窗口与重叠、末页数据、重复 cursor、过期游标、迟到/排序变化、半页超限均有 Fixture。先处理 items 再判 has_more；重扫去重不漏页，不把热门排序遇旧对象当结束。

`SPEC-006-JOB-004`：Scheduler 基于数据库 due rows/唯一时间槽；停机窗口有界合并补扫。数据库 next_attempt_at 为业务重试唯一时钟，禁止多层 autoretry 与长 ETA 堆积。外部调用前原子预留请求/额度/节点/字节/时间，未知费用对账后结算。acks_late/worker_lost 重投需配合 attempt/deadline 上限、旧 epoch 拒收和毒任务隔离。取消/暂停/撤权在每请求与提交前检查。

`SPEC-006-JOB-005`：分析按 input hash + schema/model/prompt version 幂等，输入冻结、有界且含父上下文；输出经 Pydantic、引用归属与代码数值校验。模型不可用保留 pending_analysis，采集、树和确定性时间线继续，补算不重复通知意图。外部通知按供应商幂等能力对账，响应未知不承诺恰好一次。

`SPEC-006-JOB-006`：Celery prefork 同步入口、每任务独立同步 DB Session；API 每事务独立同步 Session（同步路由）。可信 Worker 调用隔离执行器，执行器无业务 DB/broker/通用对象存储权限。执行契约含版本、deadline、lease/fencing、typed ID/query、cursor、预算 grant；结果有长度/hash/Schema/覆盖校验。busy 不建立执行器持久队列。取消确认或硬截止前不启动相同会话重叠执行；操作超时+监督器回收整个浏览器进程树，不能仅测 HTTP Mock。

### UI

`SPEC-006-UI-001`：重新设计来源能力→主题/查询预览→评论策略/成本→发布→事件→评论/观点→引用主链。React/TypeScript 工作台通过生成客户端调用新 API，权限与正文安全输出独立验证。

`SPEC-006-UI-002`：正常/空/加载/错误/权限不足，移动/桌面/键盘/reduced-motion 均验证。来源失败不是声量零；评论树有等价列表，未知父与未知计数可见，抽样分母/缺失排序明确，不将样本占比描述成总体民意。

### SEC / OBS / OPS

`SPEC-006-SEC-001`：首轮重建 owner/会话/来源边界，拒绝未登录、非默认归属、会话撤销后调用和 CSRF；多用户角色矩阵在 P1 验收；端点准入后才取密。凭据只注入允许的执行器通道，不进消息/日志/模型。浏览器环境白名单和出站过滤覆盖跳转/子资源/DNS/内网；正文指令不触发工具，来源采集/保留/模型/展示/导出用途逐项检查。

`SPEC-006-OBS-001`：从事务提交统计 observed/stored/deduplicated/root/reply 数，不用退出码判业务完成。监测 source lag、Outbox 最老年龄、sent 未领取、过期租约、无进展游标、解析漂移、预算/未知成本、删除积压与维护工时；指标不含用户/关键词/正文/游标高基数标签。

`SPEC-006-OPS-001`：逐平台/产品/账号/操作记录官方或网页入口、权限、配额、免费/试用、字段/用途、适配器版本和实测窗口。固定合成 Fixture 与真实有界运行分别验收；国内外各一个完整闭环并连续观察7日，试用不足如实标记，不以 HN/导入或海外成功抵消国内缺口。

`SPEC-006-OPS-002`：Alembic 新库从空库重放及上版升级一致，单迁移发布任务，自动生成候选须审查。旧库不直接登记新基线；可信数据经新标准化和权限核验导入，接受/拒绝/未知清单可对账，历史批次无实时告警。切换先停止旧调度和账号副作用，再交接水位；新系统停用 Go/River/旧 Agent 后仍完成主链。备份恢复与删除重放演练，不自动 destructive down 或删旧库。
