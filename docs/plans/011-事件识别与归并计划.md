## 4. 实施规格 SPEC

这些是可评审的执行规格；路径/接口名称为候选，G2 冻结后才是实施契约。若调整需同步测试、客户端与本文件，不私自改变 PRD 的用户语义。

| SPEC ID | 规格 |
|---|---|
| SPEC-011-API-001 | GET/POST /api/events；POST /api/events/{id}/merge、split、exclude。写操作含期望版本与原因，冲突返回可复核差异。 |
| SPEC-011-DATA-001 | 事件、作品关联、转载关系、人工约束、合并转向和版本历史；评论保持唯一实体，通过作品关联事件。 |
| SPEC-011-JOB-001 | 自动候选与人工确认区分；关联变更发出受控重算事件而非复制数据，下游报告失效需可追踪。 |
| SPEC-011-UI-001 | 在 frontend/src/app/events/ 实现本项已有 PRD 流程；桌面与窄屏同时覆盖正常、空、加载、部分、错误和无权限状态，调用生成客户端，不复制服务端业务规则。 |
| SPEC-011-SEC-001 | 先检查当前身份及资源权限；配置版本不能绕过撤权、删除、停用和更严格预算。秘密不可回读，正文与外部输入只作数据。关键变更留操作者、对象、时间与版本。 |
| SPEC-011-OBS-001 | 记录合并/拆分操作者、前后关系及影响；回退以新的补偿修订恢复关系，保留历史不强删。 |
| SPEC-011-OPS-001 | 在隔离依赖验证后渐进启用本能力；保持历史资料可读。配置缺失或外部条件不满足时明确拒绝/延期。变更前评估数据兼容与回退，停止新增操作优先于破坏性迁移。 |

数据/接口/前端执行顺序：先冻结字段、状态与权限 → 同步更新 schema.sql 与 ORM → 领域服务和 Worker → FastAPI/Pydantic 运行契约 → 导出并核对 OpenAPI → 生成客户端 → 页面接入 → 配置/镜像与完整验收。无 API 或数据变更的质量项在 G2 记录不适用，不强建空接口或无效 DDL。
