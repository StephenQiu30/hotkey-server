# Plan 051：运行库保留与恢复演练

从009分出DEC-001-218运行门槛；此卡是有明确恢复产物的运维Issue，归总Design001，承接NFR-001-101/104。共享技术验收编号 `TECH-001-051`：同库/Schema版本的独立恢复、对账与回退点可复核；不关闭任何M1/M2产品AC。所有修改保留库Schema的Plan以及009/013长窗验收都需引用本卡当次库/Schema版本证据。

| SPEC | 路径与操作 |
|---|---|
| SPEC-051-OPS-001 | 复用 `backend/app/backups/services.py`、`backups/restore.py`、`backups/adapters/postgres.py`、`backups/adapters/minio.py` 和现有CLI。执行前记录源库身份、代码/Schema哈希、保存范围、现有备份命令帮助与目标库。只使用现有hotkey-evidence桶，不新建存储服务。 |
| SPEC-051-OPS-002 | 暂停受影响调度/Worker写入并记录最后提交边界；备份后在独立新库实际恢复，读取关键表。需要新Schema时只在新空库以 `psql -X --set ON_ERROR_STOP=on` 应用完整schema；文件内 `BEGIN`/`COMMIT` 是原子边界，`--single-transaction` 可额外使用。失败后核对无部分业务表；按依赖导入后复核owner/外键、内容身份、版本、Job/Outbox/processed_messages、覆盖与预算。不得直接对旧库执行完整Schema。 |
| SPEC-051-DATA-001 | 对账源/目标行数、唯一身份、外键、关键JSON与对象引用/哈希，验证一条已完成和一条待处理Job的恢复/重放；源库写入边界之后产生的变化不能漏导。无法证明一致时停止切换，保留源库回退。 |
| SPEC-051-OBS-001 | 记录恢复耗时、备份/对象哈希、源目标Schema、对账结果和回退点；备份存在不等于恢复成功，同桶副本不能宣称独立灾备/WORM。长窗运行中发生重建不得拼接两库统计。 |

- [ ] CHK-051-001 → OPS-001：审CLI帮助与 `backend/tests/integration/test_backup_restore.py`，确认目标为隔离库；不打印环境秘密。
- [ ] CHK-051-002 → OPS-002/DATA-001：真实PostgreSQL+MinIO恢复及FK/身份/Job/账本对账，损坏备份/缺对象受控失败不能误报告可恢复。
- [ ] CHK-051-003 → OBS-001：验证回退说明和一次恢复后只读抽查，形成具备库身份与版本的证据；每次保留库DDL需再判断证据是否仍适用。

针对验证 `uv run pytest tests/integration/test_backup_restore.py tests/integration/test_provenance_replay.py`，失败不切换、不删除旧库。本卡证据归 `docs/acceptance/001-共享运行门槛验收.md` 的Plan051；不关闭M1/M2产品AC。
