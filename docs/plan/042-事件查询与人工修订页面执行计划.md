# Plan 042：事件查询与人工修订页面

交付事件列表、详情、时间线、热度历史和合并/拆分交互。FR-004-001/002、AC-004-001；现有 `frontend/src/app/events/components/events-workspace.tsx` 不构成事件业务已实现证据。

| SPEC | 交付契约 |
|---|---|
| SPEC-042-API-001 | 新增 `backend/app/api/routers/events.py`，登记 `api/router.py`、`api/dependencies.py`；GET `/api/events`（listEvents）按topic_id、时间窗、状态和稳定游标查询；GET `/api/events/{id}`（getEvent）返回revision、成员/平台计数、代表帖/评论、首次出现、情感分布、缺口和最新热度；GET `/{id}/members`（listEventMembers）和 `/{id}/heat`（listEventHeat）分页读取。 |
| SPEC-042-UI-001 | 修改 `frontend/src/app/events/components/events-workspace.tsx`；新增 `frontend/src/app/events/[eventId]/page.tsx` 及同目录 `components/event-detail.tsx`、`event-revision-dialog.tsx`。只消费生成客户端；显示候选未确认、数据不足、新出现/升温及公式版本；成员可跳转内容，缺情感/缺指标不显示成零。 |
| SPEC-042-UI-002 | 合并/拆分使用 015 的有版本写接口，先预览受影响成员，再显式提交；409 后刷新revision并重新确认，不自动重放写请求。被合并旧ID展示去向与历史，不悄悄查无此项。空、加载、权限、失败和窄屏操作均覆盖。 |

- [ ] CHK-042-001 → API-001：新增 `backend/tests/integration/test_events_http.py`，验证稳定分页、owner隔离、历史revision、旧ID去向和热度窗口。
- [ ] CHK-042-002 → UI-001/002：新增 `events-workspace.test.tsx`、`event-revision-dialog.test.tsx`，测试三平台成员显示、选择拆分、并发409及未确认候选。
- [ ] CHK-042-003 → AC-004-001：浏览器用真实三平台样本合并后拆分，核对审计、代表评论、热度与公式，再重跑聚类确认人工修订保留。

运行 B、C、F 门禁；M3 完整验收需要 014—016 和本卡证据共同汇入 `docs/acceptance/004-事件与热度验收.md`。回退页面写入口不删除事件历史。
