# Plan 044：推送目标与投递记录页面

FR-006-001/002 的配置与查询交付；技术实现可用受控目标验证，真实SMTP/飞书发送分别受025/026启用条件约束。

| SPEC | 实施契约 |
|---|---|
| SPEC-044-API-001 | 新增 `backend/app/api/routers/notifications.py`，修改 `notifications/schemas.py`、`notifications/services.py` 和API注册/依赖。GET/POST `/api/notification-targets`（listNotificationTargets/createNotificationTarget）、PATCH `/{id}`（updateNotificationTarget）；目标默认disabled，允许配置名称、channel、收件人、服务器已登记的secret_ref，禁止输入/返回秘密值。版本冲突409、凭据未配置409。 |
| SPEC-044-API-002 | GET `/api/notification-deliveries`（listNotificationDeliveries）按report_id/target/status游标查询；POST `/{id}/confirm`（confirmNotificationDelivery）输入expected_status、resolution、evidence_note，遵循024状态机。不存在/跨owner404、未登录401、CSRF403、非法迁移409。 |
| SPEC-044-UI-001 | 新增 `frontend/src/app/notifications/page.tsx` 与 `components/notification-target-form.tsx`、`delivery-history.tsx`、`delivery-confirm-dialog.tsx`；修改报告详情链接至该版本投递历史。明确 succeeded 是渠道接受结果，产品实际收到需接收方证据；unknown 显示待人工确认，不能只给“重试”按钮。 |

- [ ] CHK-044-001 → API-001/002：新增 `backend/tests/integration/test_notifications_http.py`，验证owner、凭据引用白名单、目标停用/换版、历史接收方不被改写、重复确认和审计。
- [ ] CHK-044-002 → UI-001：新增 `delivery-history.test.tsx`，覆盖pending/sending/succeeded/failed/unknown、配置缺失、确认冲突和窄屏状态。
- [ ] CHK-044-003 → FR-006-001：浏览器完成创建关闭目标、修改、启用条件拒绝、查看固定报告版本和unknown人工处置；受控验证不发送真实消息。
