# Plan 023：知识库问答

## 问答服务、数据与入口

检索从本卡拆至052。新增 `backend/app/knowledge/answers.py`、`api/routers/knowledge.py`；修改knowledge models/schemas、schema/db注册、Worker/调度、API依赖与路由、`cli/commands.py`。新增 `knowledge_answers` 保存id/owner/question/topic/time_range/status、检索词、引用对象版本清单、句子列表、资料范围、ai_call_id、失败码和Job；问题长度1—2000字符、仅owner，日志不写问题正文。

POST `/api/knowledge/answers`（createKnowledgeAnswer）输入operation_id/question/topic_id/time_range→202 JobAcceptedView；GET `/{id}`（getKnowledgeAnswer）返回pending/running/answered/insufficient/failed及独立export_state，GET列表（listKnowledgeAnswers）游标分页。新 `knowledge.answer` Job硬截止600秒，预算限制；Codex先改写3—5词→052检索最多20条→冻结引用快照→有效资料<3直接insufficient→逐句生成与引用校验。剔除无效引用后没有有效句子视资料不足/生成失败，不能返回成功空答案。

保存回答后由独立knowledge.export扫描写 `HotKey/问答/YYYY-MM-DD <净化问题前30字>-<短ID>.md`，保留资料时间范围；vault失败只影响export_state不抹掉回答。`python -m cli knowledge ask` 调用同一受理/查询服务；新增 `frontend/src/app/knowledge/page.tsx`、`components/knowledge-question-form.tsx`、`answer-detail.tsx`，显示逐句出处、资料不足、生成/失败、导出失败与重试，轮询有界并取消旧请求。

- [ ] CHK-023-101 → API/DATA：新增 `backend/tests/integration/test_knowledge_answers.py` 验证owner/CSRF、重复operation、引用对象失效、少于3条、模型限流、作业取消、答案成功但vault失败。
- [ ] CHK-023-102 → OPS：新增 `backend/tests/unit/test_knowledge_answers.py` 验证2/3/20资料边界、越权/未知引用、注入文本、句子全部无效、时间范围与提示词版本。
- [ ] CHK-023-103 → UI：新增 `answer-detail.test.tsx`，实际浏览器Web和CLI同一问题状态一致；使用真实资料内外10问，至少8问正确且出处可打开，全部问答笔记独立核对成功，不能把“资料不足”计作随意答对。

运行B/C/F和真实Codex/库/vault证据，归M4 Acceptance Plan023；有效引用不等于事实回答正确，10问仍需人工答案对照。

## 范围与需求

依赖020安全写入与052检索，本卡按 [PRD 005](../prd/005-报告与知识库需求.md) FR-005-007、NFR-001-101、NFR-005-002交付问答服务及Web/CLI。真实AC-005-004/008使用M1/M2已验资料，事件资料仅M3通过后加入；路径、接口、任务与失败用例已在本文固定。

## SPEC

| ID | 规格 |
|---|---|
| `SPEC-023-API-001` | Web/CLI 问题有长度、权限和预算边界；回答逐句给可打开出处与资料时间范围，资料不足时明确不足，不虚构引用。 |
| `SPEC-023-DATA-001` | 检索只用已采且获准资料，保存问题、检索输入版本、回答和引用关系以供复核。 |
| `SPEC-023-OPS-001` | 结果写入现有 vault `HotKey/问答/`，原子更新管理区块并保留用户区块；写入失败与回答失败分别呈现。 |

## 验收与 Checklist

Given：准备资料内外共十问，答案和出处人工可核。When：Web/CLI 问答并写问答笔记。Then：至少八问正确且出处可打开；资料外说明不足，笔记写入成功；缺任一项不得以模型文本宣称完成。

- [ ] `CHK-023-G0-001`：核对 046 S03、PRD/Design、Plan 020、真实资料和授权范围。
- [ ] `CHK-023-G1-001`：冻结三项 SPEC 的检索、引用粒度、权限和写入契约。
- [ ] `CHK-023-G2-001`：受控验证无资料、错误引用、权限不足、模型失败及 vault 只读。
- [ ] `CHK-023-G3-001`：实施问答、出处校验和笔记写入；API 变化同步生成客户端。
- [ ] `CHK-023-G4-001`：运行后端、前端、OpenAPI、真实 PostgreSQL/模型和文件系统门禁。
- [ ] `CHK-023-G5-001`：保存十问真实输入、答案、出处和现有 vault 的问答笔记。
- [ ] `CHK-023-G6-001`：按 `AC-005-004/008` 记录正确率、出处、时间范围与写入结论。

失败时保留问题和检索版本，标记回答或写入失败，不自动发布无出处文本；用户笔记不得覆盖。
