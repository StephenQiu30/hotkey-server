# Plan 019：周报冻结输入与存档

## 范围与需求

周报尚未见完整实现，日报代码不能代替。依赖 Plan 018 的冻结输入与存档口径；事件区块待 M3。本卡承接 [PRD 005](../prd/005-报告与知识库需求.md) `FR-005-005` 和 `AC-005-003/007` 的周报生成/存档；周一 09:15 前渠道送达属于 M5。预计涉及 `reports/`、调度/Worker、报告 API/Web、测试及必要 DDL，精确文件开工复核。

## SPEC

| ID | 规格 |
|---|---|
| `SPEC-019-DATA-001` | 周一 09:00 Asia/Shanghai 冻结上一 ISO 周：上周一 00:00 至本周一 00:00；保存输入版本、覆盖缺口、引用和程序数字。 |
| `SPEC-019-DATA-002` | 周报数字与该周已存档日报按同口径合计一致；差异记录原因且本项不通过，修正后以新版本重验。 |
| `SPEC-019-JOB-001` | 分析水位最多等至 09:10，Job 硬截止 600 秒；重复周一调度幂等，失败状态可恢复。 |
| `SPEC-019-UI-001` | Web 可读正常/模板版、冻结范围、引用和缺口；不把送达状态当报告生成状态。 |

## 验收与 Checklist

Given：上周日报已存档且输入可核对。When：周一 09:00 触发周报并复算日报合计。Then：周窗准确、引用有效、数字一致且 Web 可读；有差异则明确不通过。

- [ ] `CHK-019-G0-001`：核对 046 S03、PRD/Design、Plan 018 和上周日报版本。
- [ ] `CHK-019-G1-001`：冻结四项 SPEC 的 ISO 周、时区、截止和合计口径。
- [ ] `CHK-019-G2-001`：受控验证跨年周、夏令/UTC 环境、延迟分析、数字差异和重复调度。
- [ ] `CHK-019-G3-001`：实施冻结、计算、存档和 Web 读取。
- [ ] `CHK-019-G4-001`：运行后端、前端、OpenAPI、真实 PostgreSQL/Kafka 与浏览器门禁。
- [ ] `CHK-019-G5-001`：真实周一触发并保存周报、对应日报、程序合计和引用。
- [ ] `CHK-019-G6-001`：判断 `AC-005-003/007` 周报部分，渠道送达另验。

差异或超时保持失败并保留冻结输入/旧版本；修复后新版本复算，不把推送成功当生成通过。
