# Plan 019：周报冻结输入与存档

周报只在现有 `monitor_topics.weekly_report_enabled` 启用时按 `report_time/report_timezone` 调度；043负责单一设置源和冻结，本卡消费其ISO周manifest并生成/对账，不新增报告设置表。

## 完整周报实现契约

新增 `backend/app/reports/weekly.py`，修改 `reports/services.py`、`schemas.py`、`render.py`、`worker/app.py`/`scheduler.py`，复用reports表kind=weekly并注册 `report.weekly` 600秒硬截止。读取043上一ISO周窗口，冻结该周每日选定final report_id/version与其manifest；每天选择的版本固定后，日后重生成日报不改既有周报。缺任一日记录缺报和差异，本次对账AC不通过，不能默认缺日为0。

程序按日报相同统计单位计算总数、平台/情感分布与周内趋势；去重周内容数与每日出现次数分别命名，不能把一个数与另一个合计相等冒充口径一致。保存reconciliation（每日版本、统计项、日报合计、周报值、差异原因）；有差异保留草稿或明确不通过结果，不伪标已验收。与上周比较要求同口径且覆盖可比，否则显示不可比较。

M3未通过时只出重点内容周报并标事件功能未启用；042通过后消费事件只读DTO，提供Top事件、时间线、持续/平息、观点变化和下周关注。引用热度附formula_version/window/输入缺口。事件部分是FR-005-005的后续条件，完整含事件周报验收须补042证据。

- [ ] CHK-019-101 → DATA/JOB：新增 `backend/tests/unit/test_weekly_reports.py`、`backend/tests/integration/test_weekly_reports.py`：跨年ISO周、七日报合计、重复内容不同计数、缺日、日报后改版、冻结重试、Codex失败模板、任务重放。
- [ ] CHK-019-102 → API/UI：现有018报告列表/详情支持kind=weekly，生成客户端和页面显示ISO周、每日版本与对账差异，浏览器能从周报追到日报/原帖。
- [ ] CHK-019-103 → AC-005-003/007：真实周一09:00触发、09:10最晚开始、存档窗口及数字对账，不能用改系统时间模拟替代真实周一证据；送达时限另由025/026验。

运行B/C/F，证据归M4 Acceptance Plan019。失败停周报扫描，日报继续运行，已冻结版本不被覆盖。

## 范围与需求

本卡依赖018/043，承接 [PRD 005](../prd/005-报告与知识库需求.md) FR-005-005和AC-005-003/007的周报生成/存档；具体文件、冻结清单、合计与页面按本文合同。事件区块等042，渠道周一09:15前收到另属M5。

## SPEC

| ID | 规格 |
|---|---|
| `SPEC-019-DATA-001` | 周一 09:00 Asia/Shanghai 冻结上一 ISO 周：上周一 00:00 至本周一 00:00；保存输入版本、覆盖缺口、引用和程序数字。 |
| `SPEC-019-DATA-002` | 周报数字与该周已存档日报按同口径合计一致；差异记录原因且本项不通过，修正后以新版本重验。 |
| `SPEC-019-JOB-001` | 分析水位最多等至 09:10，Job 硬截止 600 秒；重复周一调度幂等，失败状态可恢复。 |
| `SPEC-019-UI-001` | Web 可读正常/模板版、冻结范围、引用和缺口；不把送达状态当报告生成状态。 |

## 验收与 Checklist

Given：上周日报已存档且输入可核对。When：周一 09:00 触发周报并复算日报合计。Then：周窗准确、引用有效、数字一致且 Web 可读；有差异则明确不通过。

- [ ] `CHK-019-G2-001`：受控验证跨年周、夏令/UTC 环境、延迟分析、数字差异和重复调度。
