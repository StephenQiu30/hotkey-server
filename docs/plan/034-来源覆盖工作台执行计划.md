# Plan 034：来源覆盖工作台

## 交付和规格

承接 FR-002-007、NFR-001-111 和 AC-002-006 的用户操作：从来源选择能力和日期范围，看缺口，再打开 Job、原帖或固定快照。后端和计量由 004/033 交付，本卡不得从 Job 列表猜出覆盖率。

| SPEC | 文件与行为 |
|---|---|
| SPEC-034-UI-001 | 修改 `frontend/src/app/sources/page.tsx`；新增该路由 `components/source-coverage-panel.tsx`、`coverage-window-table.tsx`、`coverage-window-detail.tsx`，仅该路由使用。筛选 source_key/capability/start/end 写 URL，Asia/Shanghai 输入转 UTC；展示窗口、准入与执行状态、计数、预算、缺口。 |
| SPEC-034-UI-002 | 列表游标来自 API，筛选变化清游标；详情显示当前连接版本与 Job 固定版本、attempt、请求页数和停止原因。没有 Job 的漏窗仍有详情；内容链接使用内容 ID，热榜链接使用 snapshot_id。null 显示“未知”，明确零才显示 0。 |
| SPEC-034-UI-003 | 首次加载骨架、真实无到期窗口空状态、部分结果、接口失败重试、会话失效、权限不足分别呈现；切换来源时取消旧请求，晚到响应不覆盖新筛选。预算/风控持续原因内联可见。窄屏表格改逐窗卡片，状态不只靠颜色。 |
| SPEC-034-SEC-001 | 只使用 `frontend/src/api/` 生成类型与 `src/request.ts`；不展示秘密、内部路径或未授权对象。页面浏览不调用来源采集。 |

## Checklist 与验收

- [ ] CHK-034-001 → UI-001/002：新增 `source-coverage-panel.test.tsx` 覆盖时区、筛选、游标重置、无 Job 漏窗、null 和零的不同渲染。
- [ ] CHK-034-002 → UI-003/SEC-001：测试慢请求竞态、401/403/500、空/部分状态；网络断开恢复后仍保留筛选。
- [ ] CHK-034-003 → AC-002-006：真实浏览器打开一个关键词窗和一个热榜失败窗，逐字段与 API/库核对，完成 Job→内容/快照下钻，桌面与窄屏均可操作。

运行 C、F 门禁；新增组件不得出现在来源路由树外。证据写 M1 Acceptance 的 Plan 034；通过仅代表覆盖操作可用，三天观测在 009。回退页面入口不改变后端窗口事实。
