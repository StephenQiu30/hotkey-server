# Plan 053：微博登录来源准入研究

## 边界与需求

承接 FR-007-004、NFR-001-107/110 与 AC-007-003 的准入研究部分；M1 `hotlist_weibo` 公开榜单与微博登录搜索/帖子/评论是不同能力。当前无获准登录方案、账号资料边界和真实分页证据，本卡不得发真实登录请求或创建假适配器。解除阻塞需用户确认本人账号、允许用途、平台入口、成本/部署边界及频次上限；实施者固定一手许可/接口或组件源码、版本和可停用条件。获准能力仍须另建实施 Plan，产品 AC 不由本卡关闭。

## SPEC 与文件

| SPEC | 本卡交付 |
|---|---|
| SPEC-053-SEC-001 | 修改 `docs/design/007-扩展能力设计.md`、`docs/prd/007-扩展能力需求.md` 的逐来源准入记录：许可/授权/账号与资料隔离、请求预算、验证或访问频繁即停用及本人核查后人工恢复；只记录秘密引用，不记录值。 |
| SPEC-053-DATA-001 | 分别核对登录搜索、作品详情、一级评论/回复、作者追踪的原生不透明 ID、父链、分页尾段、发布时间、删除/不可见/权限/限流状态；不能由公开热榜结果推断。 |
| SPEC-053-OPS-001 | 在 `docs/plan/README.md` 登记每个获准能力的后续单 Issue 实施合同，预定 `sources/adapters/`、`content/`、`jobs/` 所属责任、真实样本、测试与预算；准入研究阶段无代码/Schema/客户端生成文件。 |

## Checklist 与证据

- [ ] CHK-053-001 → SEC-001：核对一手规则日期、用户授权和硬上限；缺一项维持 blocked，零真实登录请求。
- [ ] CHK-053-002 → DATA-001：能力矩阵逐项写支持/不支持/未知及身份、分页和失败证据。
- [ ] CHK-053-003 → OPS-001：仅对获准能力创建实施卡，明确真实样本与失败先行测试；公开热榜不能充当样本。
- [ ] CHK-053-G0-001：核对历史046 S03、029与M1热榜能力边界，记录当前无登录证据。
- [ ] CHK-053-G1-001：冻结SEC/DATA/OPS问题、证据来源日期和解除阻塞责任。
- [ ] CHK-053-G2-001：保存授权缺失、验证码、限流、父链未知时停止/不宣称成功的受控情景。
- [ ] CHK-053-G3-001：完成逐能力研究表与实施卡合同，不预建模块。
- [ ] CHK-053-G4-001：核对文档链接、来源、秘密引用和计划依赖；无运行部署。
- [ ] CHK-053-G5-001：研究卡不适用真实采集；授权、许可、方案和上限未定时保持 blocked。
- [ ] CHK-053-G6-001：在M6 Acceptance只记录AC-007-003的准入状态，不关闭产品AC。

失败或登录失效保持来源未连接、保留缺口和研究记录；不自动恢复。验证只用文档与准入资料，不把无请求写成真实验收。
