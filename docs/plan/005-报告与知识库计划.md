# 报告与知识库计划

状态说明：本轮仅完成文档拆分；本计划为 `planned`，实现暂停、待用户确认恢复。计划状态表示文档/任务准备进度，不表示产品 AC 通过。执行方统一为 Codex 实现与自检、Claude 规划审查/代码审查/真实库全量测试和真实运行验证、用户负责本人账号与决策；Claude 仅在用户授权后提交推送。

## 1. 范围、目标与实施门禁

依据 [PRD 005](../prd/005-报告与知识库需求.md)、[总需求 PRD 001](../prd/001-热点舆情监控平台需求.md)、[里程碑 Design 005](../design/005-报告与知识库设计.md) 和 [总计划 Plan 001](001-热点舆情监控平台总计划.md)。范围：分析质量、日报/周报的冻结输入与存档、Obsidian 分阶段导出及可溯源问答，各结果独立验收。退出目标：每主题 100 条质量抽检、连续三自然日日报、每周一 09:00 Asia/Shanghai 触发上一 ISO 周周报并与该周日报合计核对、现有 vault 各笔记与 10 问 ≥8 正确分别满足对应 AC；09:15 前收到周报归 M5 渠道验收。

046 S03 门禁已满足：旧 Acceptance 046 全局异常与响应契约验收（已删除，见 Git 历史） 为 `status: passed`，其中 `AC-046-006` 含真实本地上游验证；继续沿用 PROJECT.md 与 AGENTS.md 中的统一错误、响应及请求 ID 契约；旧 Design 046 全局异常与响应契约已删除，见 Git 历史。此项是已完成的公共前置证据，不再作为每张卡待满足依赖。每卡实施前在卡下补精确新增/修改/移动/生成文件、事务所有者、接口/任务状态与失败测试。默认先验证行为失败，再改代码；API 变更遵守运行 OpenAPI → 生成客户端，数据库 DDL 只用 schema.sql 新库原子执行。此处路径为预计范围，不提前创建空模块。

证据等级：代码/受控测试、真实运行、产品验收分别记录；以下“所需证据”是完成卡的要求，“现有证据”不推定 AC 通过。统一证据登记位置为 `docs/acceptance/005-报告与知识库验收.md`（通过阶段验收后建立），每卡对应 `EV-005-NNN` 段及原始命令、库、时间窗、查询/截图链接。`CHK-005-G0-001`：开工时引用已通过的 046 验收证据，登记文件/职责、其余依赖和失败用例；`CHK-005-G4-001`：API/OpenAPI/客户端与真实依赖核对；`CHK-005-G6-001`：逐 AC 由 Claude 核对真实运行与产品结论。缺项保留未通过状态。

### 1.1 建议执行顺序与并行约束

`TASK-005-S01-T01` 的真实样本清点与 `TASK-005-S02-T01` 的日报受控降级/冻结输入准备可并行；日报产品取证仍须使用已验收输入并核对 S01 的质量结果。先交付 S02 的报告冻结输入契约，再做 `TASK-005-S03-T01` 周报：两卡都可能改 `reports/`、`worker/scheduler.py`、`frontend/src/app/reports/`，代码与生成客户端串行。`TASK-005-S04-T01` 的日报笔记部分可在 S02 稳定后与 S03 的独立周报取证并行，但周报笔记待 S03、事件/精选帖子笔记待 M3；S04 与 `TASK-005-S05-T01` 都改 `knowledge/`，先完成目标笔记与链接契约，再实现问答。各 AC 的报告存档、vault 写入和问答结果分别取证。

## 4. 退出条件、风险与回退

退出：每主题 100 条质量抽检、连续三自然日日报、周一 09:00 触发上一 ISO 周周报并与该周日报合计核对、现有 vault 各笔记与 10 问 ≥8 正确分别满足对应 AC；渠道 09:15 前收到另验。每个 AC 的受控、真实、产品证据须按 PRD 原文逐项记结果；只有对应证据齐全时才写 Acceptance `passed`。Ruff、mypy、pytest、OpenAPI 漂移、前端类型/构建、真实 PostgreSQL/Redis/Kafka 与浏览器等门禁按实际变更执行并留命令结果，不以静态通过代替真实来源结果。

风险与回退：模型失败导致引用或数字漂移、vault 只读及悬空双链；报告保留冻结输入并降级模板版，知识库写失败可见且不回滚报告，保留旧笔记版本。
