# Plan 028：指定账号追踪

## 账号管理与执行交付

复用已存在 `backend/app/monitors/models.py` 的followed_accounts和 `FollowedAccountService`，不要重建平行账号表。新增 `monitors/tracking.py`，扩展monitors schemas/services、content/discovery_execution、sources/contracts、Worker/调度、schema；新增 `api/routers/followed_accounts.py` 及注册。账号身份以source_key+平台稳定账号ID固定，改名仅追加alias；授权范围/状态随配置revision留证。

POST `/api/followed-accounts`（createFollowedAccount）提交来源与账号标识/授权说明，由已经准入的identity lookup确认稳定ID；GET列表/详情、PATCH `/{id}`（updateFollowedAccount）配置enabled/interval及expected_revision，POST `/{id}/runs`（runFollowedAccount）手动受理。来源无作者枚举能力返回409 capability_not_admitted，不能退化成关键词搜索。当前X lookup只算受控实现，047未过不得真实调用。

`account.scan` 固定账号/连接版本和窗口，沿031节奏/预算受理。读取已准入作者作品页，直接按作者身份入库，明确绕开主题关键词过滤而不绕开授权、时间和预算；稳定ID去重，旧帖指标更新追加观察。cursor/高水位只有可信尾段才推进，中断保留gap并使用重叠回看；撤销授权后新单/排队/运行写入均停止。

新增 `frontend/src/app/accounts/page.tsx`、`components/followed-account-form.tsx`、`account-coverage.tsx`，显示来源实际支持的能力、授权/暂停、最近新帖和缺口。每个实际平台adapter的作者枚举必须有单独获准能力Plan；本卡仅完成管理和公共执行链路不能关闭全部来源AC。

- [ ] CHK-028-101 → DATA/SEC：扩展 `backend/tests/unit/test_account_tracking.py` 与 `backend/tests/integration/test_followed_accounts.py`，验证改名ID稳定、同名不同平台、关键词不匹配仍入库、授权撤销、禁止能力、分页重复/截断。
- [ ] CHK-028-102 → JOB：真实PostgreSQL/Kafka核对watermark不越未知尾段、重放幂等、预算和停止；前端新建/停用/无能力状态测试与浏览器验证。
- [ ] CHK-028-103 → AC-007-002：用户确定授权账号且来源有已准入作者能力后，逐个真实新帖/旧帖更新、原帖、缺口与时间对账；否则真实验收blocked，不用受控author夹具填数。

运行B/C/F，证据归M6 Acceptance Plan028，所有未确定真实目标显式保留外部条件。

## 范围与需求

本卡按 [PRD 007](../prd/007-扩展能力需求.md) FR-007-003、NFR-001-107/111和AC-007-002交付账号管理和公共扫描链路；实现文件/契约按本文。每个平台作者枚举需029准入及对应单能力实现；未指定获准真实账号时，产品验收阻塞，技术夹具不代替来源接入。

## SPEC

| ID | 规格 |
|---|---|
| `SPEC-028-SEC-001` | 每账号保存本人授权范围、来源能力、有效期、操作人与预算；未授权或未准入来源不得受理追踪。 |
| `SPEC-028-DATA-001` | 作者新帖按来源原生 ID 逐条收录，独立于主题关键词；发布时间/发现时间分离，去重与分页尾段可核。 |
| `SPEC-028-OBS-001` | 逐账号/来源显示请求页、限流、权限、失败、入库/去重和未确认缺口，不把实际空结果当完整历史覆盖。 |

## 验收与 Checklist

Given：本人授权账号且目标来源能力已准入。When：运行新帖追踪和分页/权限故障。Then：新帖不受关键词过滤并逐条持久，缺口按来源可见；其他来源结果不代替本来源。
