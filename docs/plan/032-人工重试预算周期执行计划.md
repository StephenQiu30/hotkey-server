# Plan 032：人工重试预算周期

## 交付与现状

从原 Plan 002 分出 A7b：修复首次失败两分钟后人工重试立即耗尽采集时间的问题。FR-002-002、NFR-001-112 对应 AC-002-007。候选 stash 只作差异参考，不能直接恢复整份 stash；当前分支代码为实施基线。

## 实施规格

| SPEC | 数据、行为和文件 |
|---|---|
| SPEC-032-DATA-001 | `backend/app/jobs/models.py`、`jobs/schemas.py`、`backend/database/schema.sql` 为 Job 保存 `collection_cycle_no`、`collection_cycle_started_at`，为 attempt 保存该周期号。首次领取周期 1；人工重试受理只设置待开新周期标记，下一次成功领取时原子递增并取当前时间。`jobs.started_at` 永远保留首次启动；队列等待不消耗尚未开始的新周期。 |
| SPEC-032-JOB-001 | `jobs/services.py` 的人工 retry 事务校验失败状态、owner、执行版本、来源开关和每日预算；重复 retry 请求只能有一个待重试状态/Outbox。`jobs/execution.py` 领取与 `content/discovery_execution.py`、`content/comments_execution.py`、`content/hotlist_execution.py` 的截止计算消费周期时钟。自动重试、429 重排、租约失效重放不新开周期。 |
| SPEC-032-OBS-001 | 现有 `POST /api/jobs/{job_id}/retry` 与 `GET /api/jobs/{job_id}` 增加只读周期/attempt 时间信息，保留 operation_id；页面 `frontend/src/app/jobs/[jobId]/components/job-detail.tsx` 区分排队等待、当前尝试、整单历时、周期剩余额度，未开始用空值。每日/全局请求实耗不回退、不返还。 |

## Checklist 与验收用例

- [ ] CHK-032-001 → DATA-001：`backend/tests/unit/test_job_reliability.py` 先固定失败时钟；首次失败后 +120 秒受理、再排队 +60 秒领取，新周期从领取开始，首次时间不变。
- [ ] CHK-032-002 → JOB-001：`backend/tests/integration/test_job_reliability.py` 验证并发点击、受理事务回滚、领取崩溃、自动/限流重排、旧租约回写；周期最多递增一次，旧写被拒绝。
- [ ] CHK-032-003 → OBS-001：`backend/tests/integration/test_resource_budgets.py` 核对来源/全局实耗累计，额度为零时人工 retry 无外部请求；`job-detail.test.tsx` 核对三个时长和未开始状态。
- [ ] CHK-032-004 → AC-002-007：既有获准来源记录一次首次失败后的人工重试真实请求、attempt、内容与账本；不人为向外部平台制造限流。自动重试受控证明与人工重试真实证据分别保留。

运行 B、C、F 门禁及上述针对测试，DDL 在隔离新库验证，保留库变更先满足 Plan 051。证据归 M1 Acceptance 的 Plan 032；任何重复扣费、返还日预算或旧租约写入即失败。回退暂停受影响任务，保留周期和账本，不把失败 Job 删除重建。
