# Plan 006：逐来源时效与分母统计

## 计算与接口合同

新增 `backend/app/jobs/metrics.py`；修改 `jobs/schemas.py`、`jobs/coverage.py`、`analysis/services.py` 和 `api/routers/collection_coverage.py`。提供 GET `/api/collection-coverage/metrics`（getCollectionCoverageMetrics，静态路由在window_id路由之前注册），沿用004筛选/权限，返回metric_version、截止时间、分子分母、排除窗及逐来源明细；页面属于034。CLI在 `backend/app/cli/jobs.py` 加 `jobs coverage-metrics`，调用同一服务，不复制计算逻辑。

`SPEC-006-OBS-001`：窗口取due_at∈[start,end)，采集延迟=finished_at−due_at，单位秒。到截止仍未受理/未结束的正常到期点记超时；精确中位数无法确定时返回median=null、median_lower_bound_seconds与timeout_count，只有下界已超目标可明确失败，其余保持不可判定，不能从中位数样本删除超时后宣布达标。最终有充分结果才按PRD判定≤300秒（M2≤900秒）。

`SPEC-006-OBS-002`：按来源和 `(content_version_id,topic_id,topic_rule_version,prompt_version)` 建需分析集合，起点为该分析需要产生的入库/发现时间；旧内容首次加入新主题不能拿旧全局入库时刻倒算。已到60分钟观察期限的样本计分母，首次有效结论≤3600秒计分子；未成熟样本单列pending_observation，不宣称通过，009结束后至少等尾部60分钟。失败/invalid保留分母。Codex限流须有实际受影响样本与时间区间证据，不能按整个自然日删除样本。

`SPEC-006-DATA-001`：静默、来源限流、Codex限流分别给reason/start/end/evidence_id；只排除相应指标，预算耗尽/普通失败/未调度不作为无条件排除。六榜桶分母是整个共同观察窗应到期的30分钟桶，即使失败/暂停也保留；零分母ratio=null。

## 范围与需求

按 [PRD 002](../prd/002-信息获取主链路需求.md) NFR-002-001和NFR-001-103/111，为AC-002-002/005/008提供可复算分母和延迟。依赖004事实DTO和005有效标注，不新增可漂移的持久汇总表；API/CLI按本文合同实施，页面交034，最终72小时交009。

## SPEC

| ID | 规格 |
|---|---|
| `SPEC-006-OBS-001` | 四关键词来源及六榜逐来源统计到期至 Job 结束的正常窗口中位延迟，目标 ≤5 分钟；未受理、未结束计超时并单列缺口。 |
| `SPEC-006-DATA-001` | 静默、来源限流延后、Codex 限流分别标时间范围与排除依据；分母、排除数、有效样本和原始 Job 可导出复算，不因失败减少应到期桶。 |
| `SPEC-006-OBS-002` | 入库且需分析的内容为标注率分母，60 分钟内有相关/不相关和理由的有效结论为分子；待处理、失败、空值仍留正常时段分母，目标 ≥95%。 |

## 验收与 Checklist

Given：有正常完成、未受理、未结束、静默、限流和标注失败/积压样本。When：对四来源、六榜和 Codex 分别计算同窗指标。Then：可从原始到期桶、Job 与标注复算每个分母、排除依据及结果；无合格样本不得写达标。
