# Plan 006：逐来源时效与分母统计

## 范围与需求

现有时间戳不足以证明逐来源时效。按 [PRD 002](../prd/002-信息获取主链路需求.md) `NFR-002-001` 和共享 `NFR-001-103/111`，为 `AC-002-002/005/008` 提供可复算分母与延迟；最终 72 小时结论在 Plan 009。先行 Plan 002 节奏、003 桶、004 覆盖、005 有效标注。预计修改 `backend/app/jobs/` 统计 DTO/服务、`analysis/` 有效结论统计、来源 API/页面及测试；是否持久聚合须先核对唯一 DDL。

## SPEC

| ID | 规格 |
|---|---|
| `SPEC-006-OBS-001` | 四关键词来源及六榜逐来源统计到期至 Job 结束的正常窗口中位延迟，目标 ≤5 分钟；未受理、未结束计超时并单列缺口。 |
| `SPEC-006-DATA-001` | 静默、来源限流延后、Codex 限流分别标时间范围与排除依据；分母、排除数、有效样本和原始 Job 可导出复算，不因失败减少应到期桶。 |
| `SPEC-006-OBS-002` | 入库且需分析的内容为标注率分母，60 分钟内有相关/不相关和理由的有效结论为分子；待处理、失败、空值仍留正常时段分母，目标 ≥95%。 |

## 验收与 Checklist

Given：有正常完成、未受理、未结束、静默、限流和标注失败/积压样本。When：对四来源、六榜和 Codex 分别计算同窗指标。Then：可从原始到期桶、Job 与标注复算每个分母、排除依据及结果；无合格样本不得写达标。

- [ ] `CHK-006-G0-001`：确认 PRD/Design、046 S03 与 Plan 002—005 的状态口径和文件职责。
- [ ] `CHK-006-G1-001`：冻结 `SPEC-006-OBS-001/002`、`SPEC-006-DATA-001` 的样本、时区、排除和中位数定义。
- [ ] `CHK-006-G2-001`：保存跨 UTC/Asia/Shanghai 边界、未完成窗口、限流、空值、无样本的失败先行用例。
- [ ] `CHK-006-G3-001`：实现统计与页面，保证查询结果可回溯到原始事实。
- [ ] `CHK-006-G4-001`：运行后端 Ruff/mypy/pytest，API 变化核对 OpenAPI/客户端，页面变化运行前端门禁和浏览器验证。
