# Plan 016：事件热度与升温复算

## 公式、任务与输入快照

新增 `backend/app/events/heat.py`；修改 `events/models.py`、`schemas.py`、`services.py`、schema、Worker与调度注册。`event_heat_snapshots` 唯一(event_id,event_revision,window_end,formula_version)，保存各成员metric_observation_id、缺失字段、权重、样本量、覆盖、得分、baseline及判定原因。

v1实现按Design004公式：每成员 `ln(1+likes+2*comments+3*shares+0.01*views)*source_weight` 求和，加 `ln(1+distinct_post_count)`；初始source_weight=1，系数和对数底数一起写formula_version配置。未知指标只在计算中贡献0，并保存missing_mask/coverage，绝不回写源指标0；所有指标未知时score=null、reason=insufficient_metrics，不能宣称低热度。此为本轮工程初始口径，真实三平台校准后任何系数调整另升版本，不能改旧快照。

每30分钟独立扫描当前revision缺快照的事件创建 `events.heat` Job，初始硬截止60秒；取窗口结束之前最近一次可用互动观察。升温取近3小时得分差，与之前24小时8个连续3小时增量均值比较，达到3倍且当前增量>0才标升温；基线不足、均值≤0、窗口缺口或revision不同无法同口径复算时标“基线不足/不可比较”，不得除零或跨版本比较。新出现独立按first_seen_at落入当前窗口判断。
