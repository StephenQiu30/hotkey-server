# Plan 017：分析质量抽检

## 可执行抽检与修复范围

先补 FR-005-002 的评论情感/观点可追溯：修改 `backend/app/analysis/schemas.py`、`prompts.py`、`services.py`、`models.py` 和schema，将评论采样ID/版本、截断数、正中负/未知计数与主要观点引用保存到同一批分析结果；每帖最多50评论的结论必须标为样本，不能冒充全帖分布。模型每条评论结果须引用输入ID，未知/重复ID拒绝，计数由程序汇总。帖子相关性、60字内一句话摘要、情感和最多5条观点沿用现有schema；M1相关性成功不证明评论分析完成。

抽检清单按每主题100条真实入库内容固定随机/分层抽样方法、来源与日期覆盖、内容版本、prompt_version及人工标准答案；抽样前冻结，不按模型是否答对换样本。相关性100条都判；情感在人工判相关且有可判情感的子集上评估并记录分母，未生成/invalid算错误，无法判人工样本另列原因。目标相关性≥90%、情感≥80%；摘要/观点另核对无事实臆造、评论引用存在、代表性与“样本观察”说明。

- [ ] CHK-017-101 → FR-005-002：扩展 `backend/tests/unit/test_analysis_annotations.py`，覆盖评论ID、50条截断、重复/漏项、未知情感、程序计数和样本引用。
- [ ] CHK-017-102 → NFR-001-108：输出每主题100条的人工判定表、混淆矩阵/分子分母、失败/空值清单与误判原因；少于100不宣称达标。
- [ ] CHK-017-103 → AC-005-001：修复提示词/schema时升版本，对同一冻结集重验并补来源反例，记录修复前后；不能只挑成功新样本。真实模型预算沿用040。

技术运行B门禁，产品抽检不由unit测试代替。证据归M4 Acceptance Plan017；M1/M2产品未通过的来源样本不能用于正式质量结论。未达标停用对应报告质量结论，保留原始分析和错误样本。

## 范围与需求

开发库有标注代码及局部结果，但 3 条空值未解释，真实质量抽检未完成。本卡按 [PRD 005](../prd/005-报告与知识库需求.md) `FR-005-002`、`NFR-001-108`、`AC-005-001`，每主题从已验收 M1/M2 资料人工抽检 100 条，分别核对相关性 ≥90%、情感 ≥80%；事件输入待 M3。先完成 Plan 005 的异常分类。验证优先，失败后再明确 `analysis/`、模型适配和 tests 的修改文件。

## SPEC

| ID | 规格 |
|---|---|
| `SPEC-017-DATA-001` | 固定主题、时间窗、抽样方法、原帖、内容/模型版本、人工标签与模型输出；失败和空值单列，不当正确或已完成。 |
| `SPEC-017-OBS-001` | 每主题 100 条分别复算相关性和情感准确率，保留混淆样本、分母与判定人；不拿创建 Job 或开发库总数替代抽检。 |
| `SPEC-017-SEC-001` | 抽检附件只保留授权可查看内容与引用，外部正文按不可信输入处理，不记录凭据。 |

## 验收与 Checklist

Given：M1/M2 已验收真实资料和可打开原帖。When：每主题独立抽样 100 条并人工复核。Then：准确率及异常分母可重算，达到目标才判本卡通过。

- [ ] `CHK-017-G0-001`：核对 046 S03、PRD/Design、Plan 005 和样本来源有效性。
- [ ] `CHK-017-G1-001`：冻结三项 SPEC 的抽样、标签、版本和质量计算口径。
- [ ] `CHK-017-G2-001`：受控验证空值、失败、同名歧义和分母计算。
- [ ] `CHK-017-G3-001`：按真实错例修复分析行为或记录无代码变化，保留原样本。
- [ ] `CHK-017-G4-001`：运行适用 Ruff/mypy/pytest 和真实数据库/模型契约检查。
- [ ] `CHK-017-G5-001`：保存每主题 100 条真实抽检、原帖与人工结论。
- [ ] `CHK-017-G6-001`：按 `AC-005-001` 分主题记录通过/失败、分母、限制和复核人。

失败时暂停质量声明并保留原始标注、抽样和差异；重新抽检要固定新样本版本，不覆盖旧结论。
