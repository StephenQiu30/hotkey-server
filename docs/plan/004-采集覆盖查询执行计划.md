# Plan 004：采集覆盖查询

## 范围与需求

旧 `TASK-002-S01-T01` 的 Job、预算、热榜局部代码已有，统一来源窗口查询尚待实现。本卡只交付只读API：到期事实依033，桶状态依003，标注状态依005；006消费本卡结果计算时效，034负责页面，依赖不能反向。源需求为 [PRD 002](../prd/002-信息获取主链路需求.md) 的 `FR-002-007`、`NFR-001-101/111`；贡献 `AC-002-002/004/006`。

新增 `backend/app/api/routers/collection_coverage.py`；修改 `jobs/coverage.py`、`jobs/schemas.py`、`content/services.py`、`analysis/services.py`、`api/dependencies.py`、`api/router.py`。Job覆盖服务在同一只读事务调用各领域DTO；分页前以owner和窗口筛选，不逐行重复查询。生成 `frontend/src/api/`；UI规格的交付迁至034。

## SPEC

| ID | 规格 |
|---|---|
| `SPEC-004-API-001` | 输入来源、能力、UTC 起止窗口和有界分页；owner 只读，返回到期、连接版本、Job/attempt、请求/页、起止与最近成功、状态/原因、入库/去重、分析和预算/缺口。 |
| `SPEC-004-DATA-001` | 完成、明确空、部分、失败、停止、未尝试和待分析不合并；未知尾段与 24 小时回看不显示为已完整覆盖，缺失计数不当零。 |
| `SPEC-004-SEC-001` | 仅按当前 owner 和可访问来源返回记录；游标不泄漏内部事实，日志不写原始查询和敏感正文。 |

## 验收与 Checklist

Given：成功、部分页、空榜、限流、预算截断、中途失败和分析异常均有可复查窗口。When：按来源、能力及时间查询API。Then：各窗口计量与数据库一致，状态和停止原因明确，内容/快照ID可供034下钻；无记录到期桶显示缺口。页面交互与浏览器证据由034交付，连续三天缺口核对在009完成。

- [ ] `CHK-004-G0-001`：核对 PRD/Design、046 S03、Plan 003/005 数据口径及真实现状，列文件和读取边界。
- [ ] `CHK-004-G1-001`：核对本文已固定API/DATA/SEC的DTO、权限、分页、空值和错误契约；UI消费合同交034。
- [ ] `CHK-004-G2-001`：保存正常、空、部分、失败、跨页、越权与未知尾段的失败先行验证。
- [ ] `CHK-004-G3-001`：实现API/DATA/SEC；运行响应、OpenAPI和生成客户端同批一致；UI由034交付。
- [ ] `CHK-004-G4-001`：运行B/C门禁和下列具体失败测试；前端构建/浏览器交034。
- [ ] `CHK-004-G5-001`：对真实四关键词来源与六榜抽窗核对API、原始Job/预算与库计数；页面对账由034承接。
- [ ] `CHK-004-G6-001`：记录 `AC-002-002/004/006` 的本卡结论及仍待 Plan 009 的时间窗证据。

每项记录版本、环境、库、筛选窗口、分母和原始命令。失败时关闭新查询入口，保留持久 Job、桶与预算；不可通过清空缺口“修复”页面。父级 AC 由 M1 整体验收关闭。

## 固定接口与验收断言

`SPEC-004-API-001`：GET `/api/collection-coverage`（listCollectionCoverage）参数source_key、capability、topic_id可选、UTC start/end必填（最多31天）、limit默认20最大100、cursor；返回 `PageView[CollectionCoverageView]`，排序due_at/id倒序。GET `/api/collection-coverage/{window_id}`（getCollectionCoverage）返回固定窗详情。列表/详情同owner，无权限对象404、未登录401、非法窗/游标422、内部500脱敏，读取不访问源站。

DTO明确包含window_id、due_at、window_start/end、admission_state/reason、current_connection_version与job_connection_version、job_id/attempts、started/finished/last_success、coverage_status/terminal_evidence、request/page/observed/inserted/deduplicated计数、analysis pending/failed/invalid/valid、预算limit/reserved/consumed、gaps(start/end/reason)、content_ids/snapshot_ids。没有Job、无实耗证据等字段为null，已证实0才填0；禁止多表JOIN乘法放大计数。
