# Plan 004：采集覆盖查询

## 范围与需求

旧 `TASK-002-S01-T01` 的 Job、预算、热榜局部代码已有，统一的来源 × 能力 × 固定时间窗查询尚无证据。本卡建立可追溯只读视图；桶状态依 Plan 003，标注状态依 Plan 005，统计口径依 Plan 006。源需求为 [PRD 002](../prd/002-信息获取主链路需求.md) 的 `FR-002-007`、`NFR-001-101/111`；贡献 `AC-002-002/004/006`。

预计涉及 `backend/app/jobs/` 覆盖 DTO/服务、`content/` 与 `analysis/` 所属领域只读 DTO、`api/dependencies.py` 和资源路由、`frontend/src/app/sources/` 页面专属组件、后端/前端测试；API 变化后生成 `frontend/src/api/`。不为查询建立第二份覆盖事实；跨领域读取由所属服务提供，事务所有者开工时明确。

## SPEC

| ID | 规格 |
|---|---|
| `SPEC-004-API-001` | 输入来源、能力、UTC 起止窗口和有界分页；owner 只读，返回到期、连接版本、Job/attempt、请求/页、起止与最近成功、状态/原因、入库/去重、分析和预算/缺口。 |
| `SPEC-004-DATA-001` | 完成、明确空、部分、失败、停止、未尝试和待分析不合并；未知尾段与 24 小时回看不显示为已完整覆盖，缺失计数不当零。 |
| `SPEC-004-UI-001` | 从窗口可进入内容、原帖或热榜快照；桌面与移动分别呈现加载、空、部分、错误、权限不足，标明时间窗和未确认缺口。 |
| `SPEC-004-SEC-001` | 仅按当前 owner 和可访问来源返回记录；游标不泄漏内部事实，日志不写原始查询和敏感正文。 |

## 验收与 Checklist

Given：成功、部分页、空榜、限流、预算截断、中途失败和分析异常均有可复查窗口。When：按来源、能力及时间筛选并下钻。Then：各窗口计量与数据库一致，状态和停止原因明确，原帖/快照可追到；无记录到期桶显示缺口。连续三天缺口核对在 Plan 009 完成。

- [ ] `CHK-004-G0-001`：核对 PRD/Design、046 S03、Plan 003/005 数据口径及真实现状，列文件和读取边界。
- [ ] `CHK-004-G1-001`：确定 `SPEC-004-API-001`、`SPEC-004-DATA-001`、`SPEC-004-UI-001`、`SPEC-004-SEC-001` 的 DTO、权限、分页、空值和错误契约。
- [ ] `CHK-004-G2-001`：保存正常、空、部分、失败、跨页、越权与未知尾段的失败先行验证。
- [ ] `CHK-004-G3-001`：实现四项 SPEC；运行响应、OpenAPI 和生成客户端同批一致。
- [ ] `CHK-004-G4-001`：运行适用的 Ruff/mypy/pytest、前端 lint/test/typecheck/build、OpenAPI 漂移及浏览器检查。
- [ ] `CHK-004-G5-001`：对真实四关键词来源与六榜抽窗核对 API、页面、原始 Job/预算与库计数。
- [ ] `CHK-004-G6-001`：记录 `AC-002-002/004/006` 的本卡结论及仍待 Plan 009 的时间窗证据。

每项记录版本、环境、库、筛选窗口、分母和原始命令。失败时关闭新查询入口，保留持久 Job、桶与预算；不可通过清空缺口“修复”页面。父级 AC 由 M1 整体验收关闭。
