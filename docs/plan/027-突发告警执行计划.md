# Plan 027：突发告警

## 范围与需求

本卡依据 [PRD 007](../prd/007-扩展能力需求.md) `FR-007-002`、`NFR-001-104/106` 和 `AC-007-001`，按已验收负面内容或事件热度的一小时阈值触发告警，并设置冷却。依赖 M3 事件和至少一个 M5 已启用渠道；未启用渠道不宣称真实告警通过。预计新建告警业务服务、状态/Outbox、调度装配、API/Web 与 tests，具体目录在 Design/开工门禁确定。

## SPEC

| ID | 规格 |
|---|---|
| `SPEC-027-DATA-001` | 规则保存阈值、窗口、对象、公式版本和来源事件/内容版本；冷却键持久化且重复窗口幂等。 |
| `SPEC-027-JOB-001` | 仅真实一小时窗口超阈值并且不在冷却期时生成告警；投递复用 M5 已启用渠道与 unknown 状态。 |
| `SPEC-027-OBS-001` | 可核对触发、抑制、冷却、投递及失败原因；报告推送不充当告警证据。 |

## 验收与 Checklist

Given：真实已验收事件/内容与渠道可用。When：跨阈值、重复触发和冷却后再触发。Then：每个事件窗口仅按规则发送，冷却和结果可复查。

- [ ] `CHK-027-G0-001`：核对 046 S03、PRD/Design、M3/M5 产品证据与文件边界。
- [ ] `CHK-027-G1-001`：冻结三项 SPEC 的阈值、窗口、冷却与状态。
- [ ] `CHK-027-G2-001`：受控验证阈值边界、重复、冷却、消息重放和渠道失败。
- [ ] `CHK-027-G3-001`：实现规则、持久冷却、任务与显示。
- [ ] `CHK-027-G4-001`：运行后端、前端、OpenAPI、真实 PostgreSQL/Kafka 与浏览器门禁。
- [ ] `CHK-027-G5-001`：用真实事件和已启用渠道保存告警发送与接收证据。
- [ ] `CHK-027-G6-001`：按 `AC-007-001` 独立判定告警，不借报告送达结果。

失败时停用告警规则、保留阈值窗口和投递身份；不得返还已用预算或删除冷却历史。
