# Plan 043：报告配置与冻结调度

## 交付、事实源与 AC

承接 FR-005-001/003/005、NFR-005-001，贡献 AC-005-002/003/005/007 的**配置与冻结输入部分**。日报生成、Web 阅读及三自然日证据在 018，周报合计与真实周一在 019。本卡不关闭这些产品 AC。设置唯一事实源为现有 `monitor_topics.report_time`、`report_timezone`、`weekly_report_enabled`；不得新增 `report_schedules` 或第二份可写设置。主题已有默认 09:00、Asia/Shanghai、周报关闭；日报调度按现有主题与报告时间，周报只在启用时调度。报告设置不决定采集就绪。

## 文件与 SPEC

| SPEC | 文件、输入与预期 |
|---|---|
| SPEC-043-DATA-001 | 修改 `backend/app/monitors/services.py`、`schemas.py` 与 `reports/services.py`；沿用 `monitor_topics` 三个字段和主题 `current_version`。设置更改只更新主题行并升版本，旧 Job/冻结清单不受影响；同版本重复提交幂等，旧版本冲突 409。无需新表或 DDL。若确有报告状态字段需求，先在 Design 005 明确由报告/Job 持有，不能复制设置。 |
| SPEC-043-API-001 | 复用 `api/routers/monitor_topics.py` 已有主题读写端点及 `api/dependencies.py` 注入；在既有主题 DTO 暴露三字段、当前版本和推导的下次日报/周报到期时间。owner 限定，未登录 401、CSRF 403、跨 owner 404、旧版本 409、非法本地时间 422；不新增独立写设置路由。修改 `frontend/src/app/monitors/[topicId]/components/topic-editor.tsx` 的报告设置区域。 |
| SPEC-043-JOB-001 | 修改 `worker/scheduler.py`、`reports/services.py`，以主题 ID、报告 kind、本地自然日/ISO 周、主题版本推导到期与唯一 operation ID；同事务写 Job/Outbox 并冻结候选内容版本、标注身份和覆盖清单。重复扫描不重建；更改报告时间只影响之后到期的窗口。 |
| SPEC-043-JOB-002 | 分析未完最多等待至设定时间后 10 分钟，只在固定候选集合内补入截止前完成的标注并锁定最终 manifest。到限仍缺的明确计数并生成模板/缺口报告；重生成沿用最终 manifest。600 秒进程硬截止与 15 分钟生成目标分别记录，不能以等待掩盖超时。 |

生成文件：主题响应契约变化时从运行 `/openapi.json` 重生 `frontend/src/api/`，与源同批交付；不手改生成物。新增/修改测试：`backend/tests/integration/test_monitor_topics.py`、`backend/tests/unit/test_scheduler.py`、`backend/tests/unit/test_daily_reports.py`、主题编辑器组件测试。保留库无新 DDL；若实施中产生 DDL 新需求，先修 Design 并按 051 恢复门槛处理。
