# Plan 038：HN 评论分页与旧帖新回复

从 Plan 007 分出评论交付；FR-002-004、NFR-001-102/104/106，AC-002-001/003/004。真实样本需 10 条可打开高热帖，不以同库外的旧 45 线程抵数。

| SPEC | 文件和行为 |
|---|---|
| SPEC-038-JOB-001 | 修改 `backend/app/content/services.py` 的CommentScanService、`content/comments.py`、`content/comments_execution.py`、`worker/scheduler.py`，仅选主题匹配且comment_count>0的HN帖。将当前每主题20帖、6小时刷新、24小时候选期、每Job10页/10请求移入版本化预设，按interaction_score倒序、content_id稳定排序；每帖最多200根/每根20回复，截断显式保留。自动候选期外旧帖提供授权手动复采，仍受预算/频次约束，真实验收至少含一帖跨24小时新增回复，不能用24小时过滤跳过旧帖AC。工程参数校准同步Design002并升版本。 |
| SPEC-038-DATA-001 | `sources/adapters/hackernews.py`、`content/models.py`、`content/services.py` 分别保留原生 comment ID、post ID、root ID、direct parent ID、reply target；未知父节点不得猜补。每根的游标/页尾证据独立；删除/不可访问节点保留缺口而不是接到帖子下。 |
| SPEC-038-DATA-002 | 评论轮次以 post ID、固定来源版本和时间窗确定 operation；跨轮再次扫描已有根以发现新回复，不能因为根 ID 已见而跳过子树。内容身份去重、正文变更追加版本、互动缺失保持 null。页提交和检查点同事务，租约过期写入拒绝。 |
| SPEC-038-API-001 | 在 `api/routers/content_records.py` 新增POST `/api/contents/{content_id}/comment-runs`（runContentComments），输入operation_id，owner/CSRF校验后复用评论受理服务，固定来源版本与轮次；202新JobAcceptedView/200重放，404不可见、409能力/频次/预算不足。仅对已入库且所属主题允许的来源操作，不接受任意URL；原帖年龄不影响手动资格，6小时来源最短间隔仍生效。 |
