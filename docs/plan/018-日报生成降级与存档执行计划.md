# Plan 018：日报生成、降级与存档

## 范围与需求

日报已有代码和受控测试，连续真实存档、引用和 Web 读取未验。本卡按 [PRD 005](../prd/005-报告与知识库需求.md) `FR-005-001/003/004`、`NFR-005-001`，贡献 `AC-005-002/005/007`。与 Plan 017 约定分析状态；真实取证使用 M1/M2 已验收资料，事件区块待 M3。Obsidian 和推送分别由 Plan 020 与 M5 承接，不作为本卡完成条件。预计复核 `reports/`、调度/Worker、报告 API/Web 与 tests，开工定精确路径。

## SPEC

| ID | 规格 |
|---|---|
| `SPEC-018-DATA-001` | 按主题和自然日冻结输入；数字、排序、引用由程序计算，模型只润色；存档版本、覆盖说明和十条原帖引用可追溯。 |
| `SPEC-018-JOB-001` | 默认 09:00 Asia/Shanghai 生成，目标设定时间后 15 分钟内完成存档；重复调度不重复报告。 |
| `SPEC-018-JOB-002` | 来源或 Codex 停用时仍用已知输入存档，明确缺口或模板版；vault/渠道故障不回滚报告。 |
| `SPEC-018-UI-001` | Web 可读取指定报告版本并区分正常、模板、缺口、加载、空、失败和权限不足。 |

## 验收与 Checklist

Given：M1/M2 真实资料可核对。When：连续三个自然日按配置生成、存档并在 Web 读取，另停用一个来源或 Codex。Then：三份报告可复算数字并打开十条原帖，降级版明确缺口，生成与 vault/推送相互独立。

- [ ] `CHK-018-G0-001`：核对 PRD/Design、046 S03、Plan 017 与真实输入。
- [ ] `CHK-018-G1-001`：冻结四项 SPEC 的日窗、版本、引用、截止和降级契约。
- [ ] `CHK-018-G2-001`：受控验证重复触发、模型失败、来源停用、引用缺失和 Web 权限。
- [ ] `CHK-018-G3-001`：按失败证据修复报告生成/存档/读取，OpenAPI 变化同步客户端。
- [ ] `CHK-018-G4-001`：运行后端、前端、OpenAPI、真实 PostgreSQL/Kafka 与浏览器门禁。
- [ ] `CHK-018-G5-001`：保存三自然日日报、冻结输入、时间、十条引用和降级真实证据。
- [ ] `CHK-018-G6-001`：分别判断 `AC-005-002/005/007` 的日报部分；vault/送达不混算。

失败时保留冻结输入和旧存档，停止错误版本的再发布；修正后新建版本并重新核对，不覆盖审计事实。
