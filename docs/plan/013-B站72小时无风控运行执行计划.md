# Plan 013：B 站 72 小时无风控运行

## 范围与需求

Plan 012 低频真实采集和 Plan 011 风控受控验收通过后，才启动 [PRD 003](../prd/003-本人账号B站试点需求.md) `AC-003-004` 的连续窗口。本卡按 `NFR-003-001/002` 核对无风控、到期至完成中位延迟 ≤15 分钟和入库后 60 分钟有效标注率 ≥95%；同时承接 `AC-003-002` 的连续三天缺口。来源仍由本人显式控制，不扩至其他平台。

## SPEC

| ID | 规格 |
|---|---|
| `SPEC-013-JOB-001` | 每 6 小时一次，Asia/Shanghai 00:00—08:00 静默；非静默且预算允许的到期窗口均有真实尝试或明确未尝试原因。 |
| `SPEC-013-OBS-001` | 固定连续 72 小时同一库和版本；逐窗记录计划到期、排队、执行、结束、请求/页、入库/去重、预算及缺口。 |
| `SPEC-013-OBS-002` | 只对非静默正常到期窗口算中位延迟 ≤15 分钟；Codex 可用时需分析入库内容 60 分钟有效结论率 ≥95%，失败/积压留分母，排除时段单列。 |
| `SPEC-013-SEC-001` | 任一验证码、登录失效或访问频繁立即停用并使本轮不通过；须本人核查后重新评估，不拼接新旧窗口。 |

## 验收与 Checklist

Given：`AC-003-001/003` 已有证据且本人允许继续低频。When：按预设连续观察 72 小时。Then：每个非静默预算允许窗口有真实尝试及结果，期间无风控，延迟和标注率可复算；否则明确失败与缺口。

- [ ] `CHK-013-G0-001`：核对 046 S03、Plan 010—012、账号状态、预算和运行库保留。
- [ ] `CHK-013-G1-001`：冻结四项 SPEC、时区、分母、静默与排除理由。
- [ ] `CHK-013-G2-001`：受控验证未尝试、失败、限流、静默边界和风控即停不会被统计排除。
- [ ] `CHK-013-G3-001`：固定运行库、版本、来源开关与证据查询；故障归原 Issue 修复。
- [ ] `CHK-013-G4-001`：保存适用代码、真实 PostgreSQL/Kafka、任务监督及浏览器门禁。
- [ ] `CHK-013-G5-001`：保存连续 72 小时逐窗、逐标注的真实原始证据。
- [ ] `CHK-013-G6-001`：分别判断 `AC-003-002/004`、`NFR-003-001/002` 并写 M2 Acceptance。

触发风控即停止，留原始 Job/缺口，不自动恢复或另起来源绕过；统计不达标时重新完整运行，不能以局部时段宣布通过。
