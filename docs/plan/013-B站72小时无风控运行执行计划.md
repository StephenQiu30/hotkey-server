# Plan 013：B 站 72 小时无风控运行

## 观察清单与退出判定

起窗前在 `docs/acceptance/003-本人账号B站试点验收.md` 固定库/Schema/代码、三版本、连接/策略版本、主题与 `[T0,T0+72小时)`，按版本化6小时间隔和00:00—08:00静默展开每个应到期点，不能假设固定每天四次实际请求。每个点保留静默/预算/风控/实际attempt原因；非静默且预算允许点必须真实尝试。

复用006的原始样本集合及超时/未成熟规则，采集阈值改900秒，相关性仍3600秒≥95%；T1后保留尾部60分钟观察，失败/invalid/积压仍在正常分母。无足够样本给不可判定。风控停用可在时效报表单列，但AC-003-004整轮立即失败，不能排除该段后通过。

- [ ] CHK-013-101 → OBS：核对每个到期窗的策略、Job/attempt、请求/页、两种预算、内容与标注ID，原始列表可复算。
- [ ] CHK-013-102 → SEC：只用受控夹具证明风控即停路径；实际72小时内不主动制造风控，不因赶验收缩短间隔。
- [ ] CHK-013-103 → AC-003-002/004：核对72小时无风控、非静默实际尝试、900秒与95%指标、缺口页面和尾部成熟样本后分别出结论。

本卡无新业务代码；观察发现问题回到对应实现Plan修复并按原始证据决定重启完整窗口。已证据化的短时故障保留，不把本人的重新授权推断为本轮已通过。

## 范围与需求

Plan 012 低频真实采集和 Plan 011 风控受控验收通过后，才启动 [PRD 003](../prd/003-本人账号B站试点需求.md) `AC-003-004` 的连续窗口。本卡按 `NFR-003-001/002` 核对无风控、到期至完成中位延迟 ≤15 分钟和入库后 60 分钟有效标注率 ≥95%；同时承接 `AC-003-002` 的连续三天缺口。来源仍由本人显式控制，不扩至其他平台。

## SPEC

| ID | 规格 |
|---|---|
| `SPEC-013-JOB-001` | 每 6 小时一次，Asia/Shanghai 00:00—08:00 静默；非静默且预算允许的到期窗口均有真实尝试或明确未尝试原因。 |
| `SPEC-013-OBS-001` | 固定连续 72 小时同一库和版本；逐窗记录计划到期、排队、执行、结束、请求/页、入库/去重、预算及缺口。 |
| `SPEC-013-OBS-002` | 只对非静默正常到期窗口算中位延迟 ≤15 分钟；Codex 可用时需分析入库内容 60 分钟有效结论率 ≥95%，失败/积压留分母，排除时段单列。 |
| `SPEC-013-SEC-001` | 任一验证码、登录失效或访问频繁立即停用并使本轮不通过；须本人核查后重新评估，不拼接新旧窗口。 |
