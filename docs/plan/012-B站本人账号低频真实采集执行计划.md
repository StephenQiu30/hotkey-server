# Plan 012：B 站本人账号低频真实采集

## 范围与需求

修复前的两次真实尝试失败，修复后尚无真实采集；来源开关保持关闭。本卡依据 [PRD 003](../prd/003-本人账号B站试点需求.md) `FR-003-001/002`、`NFR-003-001` 和 `AC-003-001/003`，只做本人账号 1 词 × 2 条真实视频的低频试点。Plan 010/011 的版本与风控受控证据、本人的独立 CDP 资料核查均为先行；其他登录平台和 B 站楼中楼不在范围。

## SPEC

| ID | 规格 |
|---|---|
| `SPEC-012-SEC-001` | MediaCrawler 只从固定补丁工作树作为宿主机子进程运行；独立私有 CDP 资料、独立输出目录和仅 `127.0.0.1` 绑定的调试端口。 |
| `SPEC-012-JOB-001` | 来源级互斥、进程组截止/取消回收、来源开关和预算在真实运行前可核对；风控信号按 Plan 011 即停。 |
| `SPEC-012-DATA-001` | 1 词 × 2 条真实视频保存原生 ID、原帖、时间、Job、版本和覆盖；只读同轮缓存一级评论，每帖 ≤20，明确不声明楼中楼。 |
| `SPEC-012-OBS-001` | 两视频均能核对 Codex 有效相关/不相关及理由、请求/页、入库/去重、预算和停止状态。 |

## 验收与 Checklist

Given：本人核对账号、补丁、资料、端口和预算，Plan 010/011 通过。When：显式启用并低频运行 1 词 × 2 视频。Then：两视频与同轮评论真实入库、原帖可开、状态及相关性可查，未触发风控；实际空或失败照实记录，本项不通过。

- [ ] `CHK-012-G0-001`：核对 PRD/Design、046 S03、Plan 010/011、本人的启用条件和精确文件。
- [ ] `CHK-012-G1-001`：冻结四项 SPEC 的低频边界、身份与采集/评论字段。
- [ ] `CHK-012-G2-001`：受控验证缓存评论上限、空简介、旧视频、超时与取消回收。
- [ ] `CHK-012-G3-001`：仅按失败证据修复；真实运行前复查开关和预算。
- [ ] `CHK-012-G4-001`：运行适用 Ruff/mypy/pytest、真实库与进程监督门禁。
- [ ] `CHK-012-G5-001`：记录本人账号两视频、一级评论、版本、Codex、预算和缺口的真实证据。
- [ ] `CHK-012-G6-001`：逐项核对 `AC-003-001/003`，72 小时指标留 Plan 013。

任何验证、登录失效或访问频繁立即停用并交本人检查；不暴露账号资料、凭据或浏览器状态。失败时保留 Job、输出摘要和库事实，不自动重试绕过。
