# Plan 050：微信公众号来源准入

FR-007-004、NFR-001-101/102/107/111、AC-007-003。RSSHub可运行不证明任意公众号路由可用；当前未指定合法路由、账号范围与更新边界，本卡交付逐路由准入。

| SPEC | 交付 |
|---|---|
| SPEC-050-SEC-001 | 在Design007登记目标公众号、官方或RSSHub路由来源、许可与授权、固定组件版本/路由、主机白名单及频率预算；需要登录/凭据的路径单独登记，不能混成公开Feed。 |
| SPEC-050-DATA-001 | 明确文章稳定身份（原始文章ID/规范URL依据）、作者/公众号身份、原始发布时间与首次发现、摘要/正文可用性；缓存更新时间和请求时间分离，Feed头部不证明历史完整。删除、无法打开原文、空Feed和上游失败分开。 |
| SPEC-050-OPS-001 | 各获准路由输出采集实施Plan，目标复用 `sources/adapters/rss.py` 或有实际差异时创建专用适配器；来源预设、内容发现、覆盖、模型与页面验收齐全，不能只加一条RSS地址。 |

- [ ] CHK-050-001 → SEC-001：用户明确目标范围，实施者记录许可/路由与凭据要求，缺项维持blocked。
- [ ] CHK-050-002 → DATA-001：核对真实获准新文章、原文、时间和缓存/分页限制；无样本保留未知。
- [ ] CHK-050-003 → OPS-001：逐路由实施Plan有失败用例与真实新文/重复扫描/缺口验收；研究完成不关闭AC-007-003。

产物归M6 Acceptance研究证据；未确定路由不发起真实采集。微博/知乎登录仍属Design007待决范围，不能因公开热榜或本卡完成认定接入。
