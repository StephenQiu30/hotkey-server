# Plan 054：知乎登录来源准入研究

## 边界与需求

承接 FR-007-004、OPEN-001-107、NFR-001-107/110 和 AC-007-003 的准入研究部分。M1 `hotlist_zhihu` 公开榜单只证明榜单能力，不证明知乎登录搜索、回答/文章、评论或作者追踪。当前登录入口/许可、本人授权、分页和费用未定，状态 blocked；用户确认用途、账号、部署与预算，实施者固定一手规则和可复现组件版本后才可评估真实请求。获准后逐能力另建实施 Plan。

## SPEC 与文件

| SPEC | 本卡交付 |
|---|---|
| SPEC-054-SEC-001 | 修改 `docs/design/007-扩展能力设计.md`、`docs/prd/007-扩展能力需求.md` 记录官方或获准入口、许可/授权、资料隔离、主机/重定向、频次与总预算、验证/失效/频繁即停与人工恢复。不能复用B站CDP或热榜身份。 |
| SPEC-054-DATA-001 | 分别核对问题、回答、文章、评论/回复、作者的原生 ID 与父链、发布时间/首次发现、分页游标/尾段、删除或私有状态；列支持/不支持/未知，不用页面可打开冒充覆盖。 |
| SPEC-054-OPS-001 | 在 `docs/plan/README.md` 登记获准能力的实施卡所需文件、DTO、预算、失败测试、真实样本和页面/覆盖链路；此研究卡没有代码、DDL或客户端生成文件。 |

## Checklist 与证据

- [ ] CHK-054-001 → SEC-001：一手规则、用户授权、合法入口与硬上限齐全才解除阻塞。
- [ ] CHK-054-002 → DATA-001：逐类内容核对原生身份、评论父链和可信分页终点，未知保留缺口。
- [ ] CHK-054-003 → OPS-001：获准后编写逐能力实施卡；AC-007-003仍需真实入库与产品核对。
- [ ] CHK-054-G0-001：核对历史046 S03、029、OPEN-001-107及公开榜单和登录能力边界。
- [ ] CHK-054-G1-001：冻结SEC/DATA/OPS研究问题与授权/预算决策责任。
- [ ] CHK-054-G2-001：保存登录失效、频繁访问、未知尾段和权限不足的停止情景。
- [ ] CHK-054-G3-001：完成能力矩阵与实施卡合同，不预建空适配器。
- [ ] CHK-054-G4-001：审文档链接、来源日期、敏感引用和依赖；无部署。
- [ ] CHK-054-G5-001：研究卡不适用真实采集；入口/授权/预算未确认前保持 blocked。
- [ ] CHK-054-G6-001：在M6 Acceptance仅记录AC-007-003准入状态，不关闭产品AC。

发生验证或登录失效立即停用并由本人核查；未获准保持来源未连接。研究证据不能代替真实采集。
