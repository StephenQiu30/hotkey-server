# Plan 039：热榜历史快照与排名页面

FR-002-006/007 的“比较前后快照”不能由当前 latest API 单独完成。本卡交付历史读取与 Web 热榜页面，贡献 AC-002-005/006；实时采集由 008 承担。

| SPEC | 文件与契约 |
|---|---|
| SPEC-039-API-001 | 修改 `backend/app/api/routers/hotlists.py`、`content/hotlist.py`、`content/schemas.py`；保留现有 latest；新增 `GET /api/hotlists/{source_key}/snapshots`（listHotlistSnapshots）和 `GET /api/hotlists/{source_key}/snapshots/{snapshot_id}`（getHistoricalHotlistSnapshot）。列表按 observed_at,id 倒序游标、limit 默认20最大100，固定 snapshot_id 内按 rank 分页。owner 隔离，未应用/不存在返回404、游标不匹配422。 |
| SPEC-039-DATA-001 | 排名始终对同来源前一成功快照比较，返回 previous_snapshot_id；明确空快照参与观察序列、失败桶不产生伪榜单。期间有缺口须展示；同 URL 重复条目保留原始排名证据并按已定去重规则报告，不能静默改 rank。 |
| SPEC-039-UI-001 | 新增 `frontend/src/app/hotlists/page.tsx`、`components/hotlist-workspace.tsx`、`snapshot-selector.tsx`；显示六来源、观察时间、前一快照、new/up/down/same、命中主题和 content_id。未命中只可打开原链接；已命中可进内容详情。URL 保留 source/snapshot；空榜、无快照、失败缺口、加载/错误/权限分别显示。 |

- [ ] CHK-039-001 → API-001/DATA-001：扩展 `backend/tests/unit/test_hotlist.py`，新增 `backend/tests/integration/test_hotlist_queries.py`；翻页中出现新快照不改变固定快照条目，跨来源/owner 查不到，成功空与失败序列不混淆。
- [ ] CHK-039-002 → UI-001：新增 `hotlist-workspace.test.tsx`，覆盖选择历史、空快照、无内容 ID、权限与请求竞态。
- [ ] CHK-039-003 → AC-002-005：浏览器核对两个真实同来源快照的排名变化、失败桶提示及命中内容链接；六来源均有可选择入口，桌面/窄屏可用。
