# Plan 007：HN 重放与评论父链

## 范围与需求

旧库曾有 45 个 HN 评论线程，但库已重建，不能与当前库合计；Worker 重启、消息重放和十帖抽查尚未完成。本卡依据 [PRD 002](../prd/002-信息获取主链路需求.md) `FR-002-003/004`、`NFR-001-102/104`，完成 `AC-002-001/003/004` 的 HN 样本核对。Plan 004 覆盖查询先就绪。验证优先；仅真实故障出现后，在本卡明确 `content/`、`jobs/`、Worker 与测试的实际修改文件。

## SPEC

| ID | 规格 |
|---|---|
| `SPEC-007-DATA-001` | 同来源同原生帖子/评论 ID 唯一；线程根、直接父节点、回复目标分别记录，不从展示顺序猜父链。 |
| `SPEC-007-DATA-002` | 发布时间与首次发现时间分离；无发布时间保留空值并标明统计替代依据，旧帖新回复和未知分页尾段留下可定位缺口。 |
| `SPEC-007-JOB-001` | 手动真实搜索、Worker 重启和消息重投后内容、评论、Job 不重复，指标观察可追加而缺失不写作零。 |
| `SPEC-007-OBS-001` | 十条可打开 HN 高热帖逐条记录一级、楼中楼父链、分页尾段与旧帖新回复核对结果。 |

## 验收与 Checklist

Given：HN 来源预设、主题、预算及 PostgreSQL/Kafka/Worker 可用，准备十条高热帖。When：真实搜索、重启、重放并人工核对评论。Then：帖子与父链持久、重放无重复，十帖的层级和尾段有逐项证据；未知尾段不报完整。

- [ ] `CHK-007-G0-001`：核对 046 S03、PRD/Design、Plan 004 和当前库，列实际验证/修复文件。
- [ ] `CHK-007-G1-001`：冻结四项 SPEC 的身份、父链、时间与重放判据。
- [ ] `CHK-007-G2-001`：受控测试覆盖重复消息、缺失父节点、分页尾段未知和旧帖新回复。
- [ ] `CHK-007-G3-001`：按失败证据修复，或注明无需改代码；保留数据库对账结果。
- [ ] `CHK-007-G4-001`：运行 Ruff/mypy/pytest 与真实 PostgreSQL/Kafka 的重启重放验证。
- [ ] `CHK-007-G5-001`：记录真实 HN 搜索、十帖可打开原帖、评论/回复及时间窗证据。
- [ ] `CHK-007-G6-001`：逐项核对 `AC-002-001/003/004` 的 HN 部分，未完成四来源窗口留给 Plan 009。

证据按版本、数据库、帖子/评论原生 ID、父链、Job 和缺口保存；失败时停用 HN 评论任务并保留已入库内容与未确认尾段，不清库重跑代替恢复。
