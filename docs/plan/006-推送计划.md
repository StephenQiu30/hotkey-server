# 推送计划

状态说明：本轮仅完成文档拆分；飞书暂缓、SMTP 凭据与渠道启用条件未定，因此本计划为 `blocked`。其他计划的实现仍暂停、待用户确认恢复。计划状态表示文档/任务准备进度，不表示产品 AC 通过。执行方统一为 Codex 实现与自检、Claude 规划审查/代码审查/真实库全量测试和真实运行验证、用户负责本人账号与决策；Claude 仅在用户授权后提交推送。

## 1. 范围、目标与实施门禁

依据 [PRD 006](../prd/006-推送需求.md)、[总需求 PRD 001](../prd/001-热点舆情监控平台需求.md)、[里程碑 Design 006](../design/006-推送设计.md) 和 [总计划 Plan 001](001-热点舆情监控平台总计划.md)。范围：M4 已存档报告的 SMTP 与飞书分渠道推送；飞书当前暂缓，重新排期并获渠道启用条件后才执行真实送达。退出目标：SMTP 与飞书获准后各自证明接收方真实送达、同报告版本同接收方幂等、unknown 人工确认；渠道结果不阻断 M1/M4。

046 S03 门禁已满足：旧 Acceptance 046 全局异常与响应契约验收（已删除，见 Git 历史） 为 `status: passed`，其中 `AC-046-006` 含真实本地上游验证；继续沿用 PROJECT.md 与 AGENTS.md 中的统一错误、响应及请求 ID 契约；旧 Design 046 全局异常与响应契约已删除，见 Git 历史。此项是已完成的公共前置证据，不再作为每张卡待满足依赖。每卡实施前在卡下补精确新增/修改/移动/生成文件、事务所有者、接口/任务状态与失败测试。默认先验证行为失败，再改代码；API 变更遵守运行 OpenAPI → 生成客户端，数据库 DDL 只用 schema.sql 新库原子执行。此处路径为预计范围，不提前创建空模块。

证据等级：代码/受控测试、真实运行、产品验收分别记录；以下“所需证据”是完成卡的要求，“现有证据”不推定 AC 通过。统一证据登记位置为 `docs/acceptance/006-推送验收.md`（通过阶段验收后建立），每卡对应 `EV-006-NNN` 段及原始命令、库、时间窗、查询/截图链接。`CHK-006-G0-001`：开工时引用已通过的 046 验收证据，登记文件/职责、其余依赖和失败用例；`CHK-006-G4-001`：API/OpenAPI/客户端与真实依赖核对；`CHK-006-G6-001`：逐 AC 由 Claude 核对真实运行与产品结论。缺项保留未通过状态。

### 1.1 建议执行顺序与并行约束

先由 `TASK-006-S02-T01` 固定发送状态、幂等键和 `unknown` 人工确认契约及失败测试，再由 `TASK-006-S01-T01` 接入 SMTP；两卡都改 `notifications/`、Worker 与发送状态，代码合并串行。飞书 `TASK-006-S03-T01` 只做现有代码的独立受控复核准备，真实送达须等用户重新排期和渠道启用条件；其真实验证可与 SMTP 独立取证，但同版本去重和 `unknown` 流程统一由 S02 校验。当前 `blocked` 原因是飞书暂缓、SMTP 凭据与启用条件未定；M1/M4 不依赖本计划。

## 2. 任务卡

- **目标**：实现有凭据边界的报告邮件发送

- **实施与验证要点**：接收人、报告版本和发送预算显式配置；凭据不入日志/Git；先用受控 SMTP 验证失败、超时、返回，再对获准接收方真实送达。
- **执行方**：Codex 实现/自检；Claude 独立送达验证；用户提供渠道决策。
- **依赖**：M4 报告已存档；S02 发送状态契约；用户 SMTP 启用条件。

- **所需证据等级**：受控测试＋真实送达＋产品验收。

- **旧卡**：M5-01、E2。

## 4. 退出条件、风险与回退

退出：SMTP 与飞书获准后各自证明接收方真实送达、同报告版本同接收方幂等、unknown 人工确认；渠道结果不阻断 M1/M4。 每个 AC 的受控、真实、产品证据须按 PRD 原文逐项记结果；只有对应证据齐全时才写 Acceptance `passed`。Ruff、mypy、pytest、OpenAPI 漂移、前端类型/构建、真实 PostgreSQL/Redis/Kafka 与浏览器等门禁按实际变更执行并留命令结果，不以静态通过代替真实来源结果。

风险与回退：发送结果未知时重复送达或误报成功；记录 unknown，人工确认后处理，停用渠道并保留发送记录；飞书未排期不自动启用。
