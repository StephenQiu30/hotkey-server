# Plan 011：B 站风控分类与人工恢复

## 错误、状态与具体文件

修改 `backend/app/sources/adapters/mediacrawler.py`、`connections/services.py`、`connections/schemas.py`、`worker/execution.py`、`worker/app.py`、`api/routers/source_connections.py` 与 `frontend/src/app/sources/components/source-connection-actions.tsx`。验证码/滑块/登录失效→authentication_required，明确频繁访问→rate_limited，普通非零退出→mediacrawler_process_failed，损坏/超限输出→mediacrawler_output_invalid，信号不明→mediacrawler_unknown_exit。不能从任意stderr关键词猜认证结论，映射仅用受控协议证据。

来源安全停用为当前执行权，不仅是旧Job固定配置；`pause_bilibili_connection_in_transaction` 同事务记录reason、trigger_job_id、停用时间和当前version，调度拒绝新受理、排队Job领取再拒绝、运行子进程组TERM后有界KILL回收。旧租约执行器提交前再验安全停用，不允许停止后写成功。

恢复复用 `PUT /api/source-connections/{source_key}`（updateSourceConnection）：输入期望version、enabled=true及本人已核查确认，409拒绝版本冲突/未核查，记录actor、时间、原因、前后版本审计。CLI `sources` 子命令调用同一服务，API/CLI不接受任意CDP路径。前端持续显示停用原因和核查后恢复入口，不因刷新页面自动启用。

- [ ] CHK-011-101 → JOB/DATA：扩展 `backend/tests/unit/test_mediacrawler_adapter.py`、`test_worker_execution.py`，验证五类输出、挂起进程组、取消和硬截止无残留子进程。
- [ ] CHK-011-102 → SEC：扩展 `backend/tests/integration/test_source_connections.py`，验证停用/受理竞争、排队旧Job、旧租约回写、重复恢复及owner/CSRF；风控后零新增外部请求。
- [ ] CHK-011-103 → UI：扩展 `source-connection-actions.test.tsx` 和浏览器验证，普通未知退出与认证停用呈现不同下一步。

运行B/C/F门禁。受控状态机通过后允许012按本人核查条件做低频恢复；不要求先制造真实验证码以完成本卡，真实恢复证据与012汇合。

## 范围与需求

本卡依据 [PRD 003](../prd/003-本人账号B站试点需求.md) FR-003-002、NFR-003-001和AC-003-002/003，修正未知退出误归认证失效，交付风控停用及本人检查后人工恢复。版本、受理和重试依赖010/031/032；本文已固定错误映射、路径、事务和恢复API。

## SPEC

| ID | 规格 |
|---|---|
| `SPEC-011-JOB-001` | 验证、登录失效或访问频繁即终止对应进程组、停用来源和后续调度；排队 Job 不自动受理，未确认窗口保留缺口。 |
| `SPEC-011-DATA-001` | 风控、限流、普通非零退出、协议/文件错误使用独立稳定状态与原因，unknown 不默认当认证失败。 |
| `SPEC-011-SEC-001` | 不破解、不换号、不绕过、不自动恢复；只有 owner 本人核查后才可通过显式入口恢复，操作有版本、时间和审计。 |
| `SPEC-011-UI-001` | Web/CLI 显示停用原因、待本人处理和恢复结果；无权限与重复恢复有明确响应。 |
