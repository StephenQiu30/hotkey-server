# Plan 026：飞书渠道真实送达

## 范围与需求

飞书暂缓，旧代码和受控证据不能证明真实送达。[PRD 006](../prd/006-推送需求.md) `FR-006-002` 与 `AC-006-001` 要求飞书独立于 SMTP 验收。依赖已存档 M4 报告、Plan 024 的投递身份，以及用户重新排期和启用条件；条件未满足时保持 blocked，不发真实消息。

## SPEC

| ID | 规格 |
|---|---|
| `SPEC-026-SEC-001` | 仅获准群/接收方和显式启用的凭据可用于真实发送，密钥不入日志、前端或验收附件。 |
| `SPEC-026-JOB-001` | 同报告版本与接收方幂等，超时或结果不确定走 Plan 024 unknown 人工确认，不自动补发。 |
| `SPEC-026-OBS-001` | 独立核对三自然日日报与周报的真实收到时间、版本、数字、模板/缺口及来源/Codex/vault 故障隔离。 |

## 验收与 Checklist

Given：用户已恢复飞书排期、报告与群机器人获准。When：受控故障后发送真实正常版/模板版日报与周报。Then：群接收方独立核实版本和时限；SMTP 证据不得替代。

- [ ] `CHK-026-G0-001`：核对 046 S03、PRD/Design、Plan 024 与用户启用条件。
- [ ] `CHK-026-G1-001`：冻结三项 SPEC 的目标、版本、状态与时限。
- [ ] `CHK-026-G2-001`：受控验证重复、unknown、故障隔离、凭据缺失和权限。
- [ ] `CHK-026-G3-001`：按失败证据修复飞书适配和任务状态，不直接沿用 SMTP 结果。
- [ ] `CHK-026-G4-001`：运行后端、真实 PostgreSQL/Kafka、配置与合同门禁。
- [ ] `CHK-026-G5-001`：重新排期后保存真实群接收方收到的版本、时间和数字证据。
- [ ] `CHK-026-G6-001`：记录 `AC-006-001` 飞书独立结论，与 SMTP 结果分列。

未获准前不得进行真实发送；unknown 停止自动重发并由 owner 人工核查。来源、报告和 vault 状态不得随送达失败回滚。
