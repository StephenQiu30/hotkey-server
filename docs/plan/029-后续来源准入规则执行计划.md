# Plan 029：后续来源准入规则

## 范围与需求

本卡只统一 [PRD 007](../prd/007-扩展能力需求.md) `FR-007-004` 和 `AC-007-003` 的来源准入规格与逐来源证据门槛。Reddit、小红书、抖音、微信公众号、X、微博/知乎登录等真实接入必须在许可、授权、预算和能力确定后各建独立 Issue Plan；本卡通过不表示任何候选平台接入成功。Reddit 仅官方 OAuth；X 仅官方 API，凭据与月度上限未定前不发真实请求。公开热榜不能替代登录能力。

## SPEC

| ID | 规格 |
|---|---|
| `SPEC-029-SEC-001` | 每来源先记录许可、授权/凭据持有人、允许能力、端点与重定向白名单、频次和月/日预算；未决定项阻断真实请求。 |
| `SPEC-029-DATA-001` | 每来源/能力独立定义原生 ID、分页/评论父链、空/部分/失败/权限状态、回看上限与持久证据。 |
| `SPEC-029-OPS-001` | 准入结果与逐来源 Issue Plan、真实采集、停止条件及恢复责任关联；跨平台证据不可互相替代。 |

## 验收与 Checklist

Given：候选来源清单和现有来源契约可读。When：逐来源审查能力、许可、预算与失败状态。Then：每个候选都有准入、阻断或待决策结论及所需独立计划；无真实来源验收时 `AC-007-003` 保持未通过。

- [ ] `CHK-029-G0-001`：核对 046 S03、PRD/Design、候选来源与现有预算边界。
- [ ] `CHK-029-G1-001`：逐来源填写三项 SPEC，明确许可、授权、分页和失败状态。
- [ ] `CHK-029-G2-001`：受控验证未授权、超预算、重定向、空/部分/限流不会误判成功。
- [ ] `CHK-029-G3-001`：获准来源各建独立 Issue Plan，列精确适配器/领域/测试文件；本卡不建空平台模块。
- [ ] `CHK-029-G4-001`：评审来源独立计划的契约与必要真实依赖门禁。
- [ ] `CHK-029-G5-001`：逐来源真实运行只记在其独立 Plan；本卡汇总证据索引。
- [ ] `CHK-029-G6-001`：`AC-007-003` 仅按每个获准来源独立真实结论判断，不因准入表完成而通过。

候选未获准时保持关闭，不以模拟数据、HTTP 200 或其他平台截图充当接入证据。
