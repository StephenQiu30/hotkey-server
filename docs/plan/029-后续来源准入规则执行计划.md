# Plan 029：后续来源准入规则

## 本卡的可关闭产物

交付可复用的准入记录规则和执行前校验，平台研究已分别分配046 Reddit、047 X、048小红书、049抖音、050公众号；本卡不能以“以后再建计划”代表FR-007-004已覆盖实现。各研究Issue输出获准能力后，必须在索引建立新的单能力实现Plan并链接验收，研究结束和平台接入是两个不同完成条件。

修改 `backend/app/connections/presets.py`、`schemas.py`、`services.py`、`catalog.py`，复用source capability证据和component policy。执行准入记录必须同时具备source/capability、授权/许可证据引用和日期、固定组件版本、允许主机、数据用途/保留、请求/频率/并发/费用上限、分页与停止契约；missing/rejected/expired状态拒绝受理。配置记录与真实persisted_read证据分开，应用预设不把状态升级成真实可用。

- [ ] CHK-029-101 → SEC/DATA：扩展 `backend/tests/unit/test_source_presets.py`、`backend/tests/integration/test_source_connections.py`，缺许可/授权/预算、组件换版、证据过期或能力不匹配均拒绝外部请求，既有M1准入不被无关平台记录覆盖。
- [ ] CHK-029-102 → OPS：按046—050逐来源填写阻塞清单、解除责任与下一实施产物；微博/知乎登录保持Design007未决，不因公开热榜可用授予登录能力。
- [ ] CHK-029-103 → FR-007-004：形成“研究证据→获准能力→实现Plan→真实验收”的可点击台账，尚无能力实现Plan时覆盖状态必须写未就绪，禁止关闭AC-007-003。

运行B门禁；只对准入校验的受控路径作技术结论，不要求也不触发候选平台真实请求。产物归M6 Acceptance的Plan029技术小节与研究台账。

## 范围与需求

本卡实现 [PRD007](../prd/007-扩展能力需求.md) FR-007-004/AC-007-003共用的准入记录与受理校验。各平台实际采集另在许可/授权/预算/能力明确后建实施Plan；本卡通过不表示任何平台接入成功。Reddit仅官方OAuth，X仅官方API且凭据/月度上限未定前零真实请求；热榜不能替代登录能力。

## SPEC

| ID | 规格 |
|---|---|
| `SPEC-029-SEC-001` | 每来源先记录许可、授权/凭据持有人、允许能力、端点与重定向白名单、频次和月/日预算；未决定项阻断真实请求。 |
| `SPEC-029-DATA-001` | 每来源/能力独立定义原生 ID、分页/评论父链、空/部分/失败/权限状态、回看上限与持久证据。 |
| `SPEC-029-OPS-001` | 准入结果与逐来源 Issue Plan、真实采集、停止条件及恢复责任关联；跨平台证据不可互相替代。 |

## 验收与 Checklist

Given：候选来源清单和现有来源契约可读。When：逐来源审查能力、许可、预算与失败状态。Then：每个候选都有准入、阻断或待决策结论及所需独立计划；无真实来源验收时 `AC-007-003` 保持未通过。

- [ ] `CHK-029-G0-001`：核对 046 S03、PRD/Design、候选来源与现有预算边界。
- [ ] `CHK-029-G1-001`：逐来源填写三项 SPEC，明确许可、授权、分页和失败状态。
- [ ] `CHK-029-G2-001`：受控验证未授权、超预算、重定向、空/部分/限流不会误判成功。
- [ ] `CHK-029-G3-001`：获准来源各建独立 Issue Plan，列精确适配器/领域/测试文件；本卡不建空平台模块。
- [ ] `CHK-029-G4-001`：评审来源独立计划的契约与必要真实依赖门禁。
- [ ] `CHK-029-G5-001`：逐来源真实运行只记在其独立 Plan；本卡汇总证据索引。
- [ ] `CHK-029-G6-001`：`AC-007-003` 仅按每个获准来源独立真实结论判断，不因准入表完成而通过。

候选未获准时保持关闭，不以模拟数据、HTTP 200 或其他平台截图充当接入证据。
