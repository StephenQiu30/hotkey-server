# Plan 033：到期窗口与采集计量事实

## 交付

FR-002-007、NFR-001-101/104/111 要求能查到尚未创建 Job 的到期缺口。现有 `coverage_windows` 隶属采集 Job，`monitor_schedules.next_run_at` 只保存下一次时间，直接聚合 Job 会丢失未受理窗口。本卡补事实与领域只读 DTO；Plan 004 消费查询，031 将调度受理接入。

## SPEC 与文件

| SPEC | 明确契约 |
|---|---|
| SPEC-033-DATA-001 | 新增 `backend/app/jobs/coverage.py`，扩展 `jobs/models.py`、`jobs/schemas.py`、`backend/database/schema.sql`：`collection_due_windows` 唯一键 `(owner_id, schedule_key, due_at)`；保存 topic_id 可空、source_key、capability、due_at、window_start/end、connection_version、policy_snapshot、admission_state、reason、operation_id/job_id 可空、recorded_at。窗口按 `[start,end)`；due_at 是计划时间，不能用扫描时间替代。 |
| SPEC-033-DATA-002 | admission_state 为 pending/accepted/skipped/missed；skipped 须说明 quiet/disabled/rate_limited/budget，missed 表示运行中断未受理。扫描恢复按上一持久到期点补漏窗记录；只有实际创建 Job 才填 job_id。该表保存到期事实，执行、预算和覆盖尾段仍从既有表读取，不复制可变余额。 |
| SPEC-033-DATA-003 | `content/discovery.py`、`content/comments.py`、`content/hotlist_execution.py` 在提交页的同一事务记请求、页、观察数、首次入库数与去重数，保留空值/未知；重复同页通过 operation/页身份去重计量。请求失败仍记实耗与停止原因；同一内容跨主题发现不重复算新内容。 |
| SPEC-033-API-001 | `jobs/coverage.py` 提供 owner 限定的到期/执行事实 DTO；`content/services.py`、`analysis/services.py` 各提供窗口内容计数和标注状态 DTO。跨领域由服务组合，路由无 SQL；覆盖 COMPLETE 必须附固定窗可信 terminal evidence，RSS 头部或截断不能确认完整。 |
