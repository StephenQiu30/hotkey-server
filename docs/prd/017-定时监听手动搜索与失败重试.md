# 定时监听、手动搜索与失败重试

## 用户问题

监控发布后会按频率自动采集，但 Editor/Admin 无法在突发热点出现时立即执行一次相同搜索，也无法在同一界面确认请求是否进入队列。现有采集页已展示运行事实和管理员重试能力，但角色边界与手动入口尚未闭环。

## 产品目标

用最少新增契约补齐“发布后持续监听—按需立即搜索—查看进度—安全重试”的 MVP 闭环，同时保持所有采集都进入既有持久队列和标准化流水线。

## 用户故事

- 作为 Editor，我能对 active 的已发布监控立即搜索，并看到请求是新建还是被冷却规则复用。
- 作为 Editor，我能在采集内容页观察 queued/running/succeeded/failed 进度，但不能人工重试。
- 作为 Admin，我能在确认失败后重试最后一个仍有效的采集窗口。
- 作为 Viewer，我只能阅读内容与监控配置，不会看到或调用手动采集控制面。

## 功能要求

- FR-017-1：自动调度只处理 active、published、已启用且到期的目标；采集间隔限制 5 分钟至 24 小时。
- FR-017-2：`POST /api/v1/monitors/{id}/collect` 只允许 Editor/Admin，且只接受路径中的监控 ID。
- FR-017-3：手动触发按来源/查询签名分组，使用服务端时间窗并提交 `collect_source` 持久任务，不同步调用 Connector。
- FR-017-4：同一来源/查询在 5 分钟 UTC 冷却桶内原子复用任务；响应返回 requested/created/reused/cooldown_until。
- FR-017-5：Worker 执行手动任务前重新读取所有共享来源/查询且仍 active published 的目标；暂停、改版和禁用事实必须生效。
- FR-017-6：手动 CollectionRun 保存 `trigger_type=manual`，成功后复用现有 normalize 及后续流水线。
- FR-017-7：Editor/Admin 可列出安全的 CollectionRun 投影；仅 Admin 可重试 failed/cancelled 运行。
- FR-017-8：人工重试必须原子恢复原窗口和原持久任务；存在更新窗口或目标集合变化时返回冲突。
- FR-017-9：监控页只对 active published 监控显示“立即搜索”；提交状态、成功数量、冷却时间和失败信息可见。

## 非功能要求

- 幂等依赖 PostgreSQL 唯一约束，不使用进程内锁或前端防抖作为事实门禁。
- Queue Payload 继续限制为 4096 bytes，trigger type 使用固定枚举；不包含查询正文、端点、凭据或第三方响应。
- 错误只返回稳定 AppError/error_code；日志、Toast 和 CollectionRun 不展示密钥或上游响应正文。
- 390px 宽度无横向溢出，按钮具备可访问名称、禁用态和键盘行为。
- 自动化测试不得调用真实第三方来源；Connector 行为使用现有 fixture/fake。

## 非目标

- 不提供自定义查询文本、来源选择或时间窗的临时搜索表单。
- 不让手动搜索绕过来源健康、上游配额、内容策略和后续处理。
- 不新增 CollectionRun 取消接口、批量重试或无限重试。
- 不在本条实现新的 Connector、内容模型或事件算法。

## 验收标准

- AC-017-1：自动调度对相同来源/查询/窗口只产生一个任务，paused 监控不产生新任务。
- AC-017-2：Editor/Admin 对 active published 监控手动触发成功；Viewer 为 403，paused/无发布目标为 409/404 稳定错误。
- AC-017-3：同一冷却桶的并发手动请求只有一个新任务，其余返回 reused；下一冷却桶可新建。
- AC-017-4：手动任务创建 `trigger_type=manual` 的 CollectionRun，并复用 collect→normalize 链路与安全运行投影。
- AC-017-5：Editor/Admin 可查看运行进度；Editor 不出现重试操作且直接调用为 403；Admin 可重试仍有效的 failed/cancelled 窗口。
- AC-017-6：桌面、390px、Admin、Editor、Viewer、匿名和 axe 验收通过；后端 CI、前端全测与生产构建通过。

## 成功指标

- 0 个同步 Connector 手动调用入口。
- 冷却桶内重复请求的新增任务率为 0。
- 100% AC 具有自动化或浏览器证据。

## 发布与回滚

该功能不新增表，只扩展现有队列信封、CollectionRun 创建类型、API 和界面。回滚时先隐藏手动按钮并撤销路由，再回退 Worker；既有自动任务、CollectionRun、检查点和内容均保留。
