# 微博开放平台关键词来源适配

## 用户问题

管理员无法通过微博当前官方、按套餐授权且可撤销的接口，把关键词结果接入 HotKey；直接模仿网页或旧接口会造成合规、稳定性和凭据风险。

## 产品目标

交付一个最小、完整的微博关键词来源：管理员配置官方 API Token 的环境引用，系统验证账号和命令可用性后启用，通过官方 `search statuses/limited` 分页采集并映射可追溯内容和公开指标。

## 用户故事

- 作为管理员，我能看到开发者认证、套餐/OAuth、命令和额度前提，且系统不保存或回显 Token。
- 作为管理员，我只有在关键词搜索命令真实 available 时才能启用来源。
- 作为编辑者，我能把健康的微博来源加入监控并复用现有关键词查询。
- 作为阅读者，我能看到微博事实、作者、时间、转发关系、原文链接和已知指标。
- 作为 Viewer，我只能查看来源公开状态，不能读取配置或执行管理操作。

## 功能要求

- FR-014-1：新增 `weibo` 来源；官方 API 基址、Bearer、开发者协议和合规开关固定，凭据只允许 `env:NAME`，创建强制 disabled。
- FR-014-2：健康探测验证 whoami，并从当前 Token 的 available 命令清单确认 `search/statuses/limited`。
- FR-014-3：采集前再次验证能力，调用固定 invoke 契约，传递规范化关键词、count 和分页页码。
- FR-014-4：映射稳定 ID、正文、作者、发布时间、转发父 ID、官方 URL 与已返回的点赞/评论/转发指标；重复页和重试幂等。
- FR-014-5：删除/不可见项只输出稳定诊断，不保存正文；认证、限流、临时、解析和永久错误分类不泄漏上游载荷。
- FR-014-6：前端使用既有 shadcn/ui Select、Input、Alert、Checkbox 和 Button 组合，不新增专用视觉体系。

## 非功能要求

- 固定 HTTPS 主机、DNS/重定向复验、TLS 1.2、超时和 4 MiB 响应上限。
- Token 仅在请求 Header 中短暂存在；日志、错误、数据库、OpenAPI、前端和验收证据不得包含明文。
- 连接器契约、数据库约束、权限脱敏、分页、错误态和浏览器流程具备自动化覆盖。

## 非目标

- 账号时间线、热搜趋势、发布或互动写操作。
- 网页/移动接口抓取、Cookie、验证码、浏览器会话和私有接口。
- OAuth 授权页托管、套餐购买和 Token 自动刷新。

## 验收标准

- AC-014-1：Token 无效、开发者/套餐未就绪或搜索命令不可用时，来源不能启用或采集。
- AC-014-2：关键词、分页、稳定 ID、转发、作者、时间和指标映射正确，重试不重复 Content。
- AC-014-3：不可见/删除提示、错误分类、SSRF、响应大小和凭据脱敏全部通过。
- AC-014-4：管理员/Viewer 权限、OpenAPI、桌面/移动布局和可访问性全部通过。
