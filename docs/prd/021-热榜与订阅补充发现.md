# 热榜与订阅补充发现 PRD

日期：2026-09-17。状态：详细需求草案；承接既定范围 FR-001-019，保持 P1 优先级。本文是独立评审和验收依据，不代表功能已实现。对应 [执行计划](../plans/021-热榜与订阅补充发现计划.md) 已建立且为 planned；同编号 Design 与真实 Acceptance 尚未建立。

入口：[逐项 PRD 索引](README.md) · [平台需求总纲](001-热点事件监控平台功能与非功能需求.md) · [鱼皮项目功能研究](../research/001-热点事件监控平台调研.md)。

## 1. 背景、问题与用户价值

预设关键词无法覆盖所有新事件，热榜和订阅可补充线索。但热榜标题匹配不能替代用户要求的原生关键词搜索。

总纲原始要求：提供各平台热榜、公开订阅等线索；可以转为事件或监控主题，保持与关键词搜索结果的来源区分。

研究者在来源热榜看到未设置关键词的新事件，将其加入研究，同时保留它来自热榜的观察记录。

## 2. 目标与成功指标

**BR-021-001：**低成本补充未知事件发现，并确保热榜、订阅与主动搜索的覆盖范围不混淆。

| 指标 | 统计口径 | 目标或判定 |
|---|---|---|
| 来源标注率|线索附来源、榜单/订阅、观测时间与位置|100% |
| 重复通知|同一条目重采产生重复变化通知|0 |
| 补充价值|用户转入主题/事件的线索占已评审线索|建立基线，不以源数量为目标 |

指标用于评审和后续测量，尚未取得运行结果。涉及新增数量、时长和默认值的建议须在实施前冻结；不据此扩大既定平台范围或付费权限。质量目标不以“页面有按钮”替代。

## 3. 范围、优先级与边界

- **本期范围（P1）：**来源榜单/公开 Feed、榜单快照、可选本地关键词过滤、线索转主题/事件、来源失败状态。
- **明确不包括：**全站热榜就是全网、公共实例永久免费稳定承诺、抓取不存在的原生搜索。
- **与相邻能力的边界：**线索转成主题后仍需经过 005 主动发现；保存榜单排名不是平台真实热度算法。
- **发布条件：**本文件全部适用验收通过，并满足关联质量要求；本文件展开后仍属后续阶段，不因文档已写完自动提升首版优先级。

## 4. 用户流程与关键结果

1. 选择已验证的热榜或公开订阅来源。
2. 按来源缓存与预算获取条目并标榜单快照。
3. 用户查看全部线索或应用本地主题过滤。
4. 将有价值条目加入事件或创建新主题，保留发现依据。
5. 周期更新排名/新增条目，旧快照仍可复查。

完成后用户获得：有来源和时间的补充线索及可追踪的研究转化关系。取消、失败或权限拒绝时，不显示与实际不符的成功结果。

## 5. 输入、配置与信息展示

| 信息项 | 规则与校验 | 默认或展示要求 |
|---|---|---|
| 来源标识|平台、榜单/Feed 名称和地址|仅已验证来源 |
| 读取周期|遵守来源更新/缓存和应用预算|不默认高频轮询 |
| 过滤规则|标明本地关键词筛选而非上游搜索|默认可查看未过滤线索 |
| 历史保留|榜单时间、位次、条目身份|不因下榜删除已有研究资料 |

配置变更记录操作者、时间和版本；正在执行的操作绑定启动时的业务规则版本。当前权限、连接停用、删除要求与更严格预算始终优先，不能以旧版本继续越权或超额执行。冲突的输入必须明确拒绝或延期，不能静默修改用户意图。

## 6. 详细需求与业务规则

| 需求 ID | 规则 | 详细行为 | 对应验收 |
|---|---|---|---|
| FR-021-001 | 发现标签 | 热榜、RSS、新闻线索分别标来源类别，不能在 UI 或报告中伪称关键词全网检索。 | AC-021-002 |
| FR-021-002 | 快照语义 | 榜单位置仅对本次抓取时间成立；跨快照比较记录时间差，缺榜不自动变成零热度。 | AC-021-003 |
| FR-021-003 | 条目身份 | 标准化来源标识与链接去重，但保留跨源发现；链接参数去除不能误合并不同作品。 | AC-021-004 |
| FR-021-004 | 转化保留 | 加入事件/主题后保留原线索记录和判断理由，不自动宣称正文和评论已采集。 | AC-021-005 |
| FR-021-005 | 缓存与故障 | 尊重来源缓存/限额；失败保留最后快照并标过期，不展示为当前实时榜单。 | AC-021-006 |
| FR-021-006 | 基础独立 | 不配置此增强时 P0 关键词和作者监控仍正常；不自动引入收费云采集服务。 | AC-021-006 |

**DEC-021-001：**热榜与订阅作为补充来源，并在所有页面保留其能力边界。

以上规则解释 FR-001-019，不重编号或替换总纲条目。后续发现冲突应显式更新总纲及受影响文档，不由某一页面或适配器单独改变语义。

## 7. 状态、异常与权限

| 状态或场景 | 展示与处理 |
|---|---|
| 榜单正常|显示榜单时间与位置，不仅显示当前抓取时间。 |
| 空/过期|区别来源无条目与获取失败，允许查看有时标的历史。 |
| 转化待补充|条目已加入研究但正文/评论未获得时明确提示。 |
| 加载或执行中 | 展示已知阶段和可用操作；未知进度不用虚假百分比，已持久化历史结果可以继续查看。 |
| 无权访问 | 显示稳定的权限提示，不通过错误内容泄露其他使用者的数据或凭据。 |

所有者管理自己的订阅和转化结果；共享公开 Feed 不意味着共享个人研究配置。

| 身份 | 访问与操作边界 |
|---|---|
| 资料或配置所有者 | 在本文件范围内处理自己的业务资料与配置；维护职责的动作仍须相应授权。 |
| 获授权维护者 | 仅诊断或维护明确授权的范围，不自动获得业务正文、规则修改或秘密回读权限。 |
| 其他身份 | 默认拒绝；仅在 026 团队协作正式启用且被显式授权后，按实际角色开放对应操作。 |

本项专门权限规则优先约束上述通用边界，后续角色设计不能扩大已有秘密或数据访问权限。

重复点击、刷新页面或网络重试不得重复产生同一业务结果；若本操作是有意新建的一次业务行为，必须有独立标识和清晰的版本/时间范围。

## 9. 验收标准

AC-001-019 是父级验收，本文件第一项完整保留其场景，其余补充边界、异常和业务细节。以下全部是待执行标准，不是已通过记录。

| 验收 ID | 场景 | Given：前提 | When：操作 | Then：可核查结果 |
|---|---|---|---|---|
| AC-021-001 | 总纲场景继承 | 一条事件来自热榜 | 加入主题 | 保留热榜来源与原始观测位置，不标成关键词全网检索命中。 |
| AC-021-002 | 本地过滤 | 在热榜条目中输入关键词 | 查看结果说明 | 标为热榜本地匹配，非平台原生搜索 |
| AC-021-003 | 下榜缺失 | 条目下一轮未出现 | 查看历史趋势 | 保留旧观察，缺失不是零热度 |
| AC-021-004 | URL 差异 | 同条目带跟踪参数但另有真实不同 ID | 去重 | 合并跟踪变体，不合并不同作品 |
| AC-021-005 | 线索转化 | 只有标题链接的条目 | 加入事件 | 保留发现依据并提示正文/评论未采集 |
| AC-021-006 | 故障与独立 | 订阅服务失败或未启用 | 运行 P0 监控 | 旧快照标过期，关键词与作者路径不受阻 |

交付证据应包含输入/规则版本、执行记录、实际结果和人工核对结论。界面能力须有真实浏览器证据；运行、恢复与来源能力按相应环境验证，纯文档检查不计作产品验收。
