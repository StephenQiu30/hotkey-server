# 来源连接控制面与合规健康

## 用户问题

来源 CRUD、启停、归档、恢复、健康检查、指标能力档案和凭据环境变量引用已实现，目前实际连接器只有 RSS/Atom 与 Hacker News。

## 产品目标

为所有来源提供统一而合规的连接、授权、健康、能力和成本控制面，让业务流水线不感知第三方 SDK。

## 范围

- 来源目录和完整连接配置表单（RSS/Atom、Hacker News）
- 连接健康检测与诊断
- 能力档案、配额和指标映射
- 凭据引用与条款审计

## 用户故事

- 作为 viewer/editor，我能够查看来源名称、类型、生命周期、健康、条款和凭据是否已配置，但看不到端点、内部配额配置或凭据引用。
- 作为管理员，我能够创建 RSS/Atom 或 Hacker News 连接，配置合规、地区语言、配额和保留参数，并完成健康探测、启停和安全删除。
- 作为管理员，我能够通过既有指标能力档案 API 管理不可变草稿、发布和归档，而不直接修改数据库事实。

## 功能要求

- FR-007-1：每个来源连接保存类型、官方端点、授权方式、env 凭据引用、条款地址、保留策略和速率限制，绝不保存明文密钥。
- FR-007-2：连接器实现统一 Connector 端口并返回标准 Capture；第三方类型只存在于 infrastructure。
- FR-007-3：准入只允许官方 API、RSS、Atom 或书面授权 Feed；不得绕过登录、验证码、robots、反爬或访问限制。
- FR-007-4：健康状态区分 unknown、healthy、degraded、unavailable；认证、限流、临时、解析、永久错误分别处理。
- FR-007-5：管理端表单必须校验 HTTPS 条款地址与 `env:NAME` 凭据引用；服务端响应、日志和普通成员投影不得回显引用或明文。
- FR-007-6：admin 可查看白名单配置并执行探测、启停、归档；viewer/editor 只读公共投影，不显示管理动作。

## 非功能要求

- 所有写操作具备认证、授权、输入校验、幂等或乐观锁保护和审计。
- 列表支持稳定分页；第三方调用具备超时、配额、重试和降级。
- Web 覆盖桌面与移动端，并满足键盘操作、可见焦点和减弱动效。

## 非目标

不使用未授权抓取补齐来源能力，不为本条引入与仓库规范冲突的新基础设施。

## 验收标准

- AC-007-1：不支持的来源类型在保存前失败
- AC-007-2：SSRF、重定向、DNS 重绑定和凭据泄露测试通过
- AC-007-3：来源故障不阻塞其他来源或历史数据读取
- AC-007-4：管理员可通过桌面和移动端完成完整连接配置与生命周期操作；viewer/editor 保持安全只读，WCAG A/AA 无确认违规
