# 信息获取主链路需求

本文从 [总需求 001 v5.0](001-热点舆情监控平台需求.md) 保留的 PRD 001 v3.0 基线按 M1 拆出，现与 [Design 002](../design/002-信息获取主链路设计.md) 对齐；[Plan 002](../plan/002-信息获取主链路计划.md) 已按同号里程碑迁入 `docs/plan/`。需求状态 `approved` 不表示产品验收通过。

## 1. 目标与范围

**目标**：设置主题后核对四个关键词来源、六个公开热榜和 Codex 相关性；从来源能力时间窗进入帖子、评论或快照，区分空榜、部分、失败与待分析。

**不包含**：本人账号 B 站及其他登录平台、跨平台事件归并、日报/周报、Obsidian、推送、告警与导出增强。

## 2. 用户场景与状态

- 日常打开主题，查看四个关键词来源与六榜最新采集的帖子、评论、命中条目及 Codex 相关/不相关理由；待处理或异常标注单列。
- 选定来源、能力和时间窗，核对计划到期、实际请求/页数、预算、入库/去重与未确认缺口，再进入原帖或热榜快照。
- 比较同一来源前后两次热榜快照的排名变化；核对命中主题的条目已入库并完成相关性判断，未命中者只保留快照。
- 看到失败、部分页、空榜或分析积压时追查停止原因；在允许的预算和权限内手动重试，并核对新旧尝试与剩余预算。

权限沿用总需求的单 owner 登录；加载及权限不足沿用现有界面和权限契约。以上场景按本里程碑 FR/AC 与总需求 NFR 核对。

## 3. 业务需求

| ID | 业务需求 | 成功判断 |
|---|---|---|
| BR-002-001 | 持续获取关键词相关的帖子和评论 | 四个关键词来源按各自有效节奏运行；真实内容可追溯，覆盖、缺口和未分析数可见 |
| BR-002-002 | 判断内容与主题的相关性 | 命中主题的真实内容由本机 Codex 判相关并记录理由；待处理、调用失败和无效或缺失标注单列，不能算已判断。 |
| BR-002-003 | 在预算内长期、安全地运行 | 来源与模型有硬上限；来源故障、限流、账号风控或模型故障不会静默吞掉任务和缺口 |
| BR-002-004 | 通过公开热榜发现与主题有关的新内容 | 六榜分别保存快照和排名变化；命中项入库并由 Codex 判相关，事件归并另验 |
| BR-002-005 | 分辨已覆盖、部分结果、失败和待分析 | 来源 × 能力 × 时间窗可核查请求、页数、结果、预算、分析积压、标注异常与缺口 |

## 4. 功能需求

| ID | 功能 | 要求 |
|---|---|---|
| FR-002-001 | 监控主题 | 配置任一/全部/排除关键词和来源选择；主题请求频率默认 30 分钟、最短 10 分钟。 |
| FR-002-002 | 定时与手动采集 | 主题频率与来源最短间隔、静默时段及预算取更保守有效值；支持立即运行、暂停、有限重试；来源节奏/开关随连接版本固定到 Job，变更只影响后续 Job |
| FR-002-003 | 帖子采集 | 保存来源、原生 ID、链接、标题、正文、作者 ID 与昵称、发布时间、首次发现时间、互动指标及采集证据；来源无发布时间时保留空值，以首次发现时间作为统计依据并标注，不丢弃、不伪造发布时间；重复采集只追加指标观察，不把缺失值写作 0 |
| FR-002-004 | 评论采集 | 对命中主题且热度靠前的帖子按来源预设采集评论，保留评论身份与父链，分页和旧帖新回复逐来源验收。HN 保持现有每帖最多 200 条一级评论、每条最多 20 条回复。 |
| FR-002-005 | 相关性判断 | 关键词规则初筛后，由本机 Codex app-server 按主题判断相关与否、排除同名歧义并给出理由；无效或缺失标注单列，不能算已判断 |
| FR-002-006 | 六榜发现 | RSSHub 路由分别为微博 `/weibo/search/hot`、百度 `/baidu/top`、知乎 `/zhihu/hot`、B 站热门 `/bilibili/popular/all`、36Kr `/36kr/hot-list`、澎湃 `/thepaper/featured`。保存快照、观察时间、实际排名和同来源前一快照的 `new/up/down/same`；主题规则匹配标题/摘要，英文/ASCII 词按字母数字边界整词匹配。命中条目按 URL 入内容库并交 Codex 判相关；未命中条目仅留快照。空榜与失败分开，失败时间桶不被后续成功覆盖；进入事件待 M3 |
| FR-002-007 | 采集覆盖查询 | 按来源 × 能力 × 时间窗显示计划到期、当前连接版本、Job/尝试、实际请求和页数、起止/最近成功时间、完成/空/部分/停止状态及原因、入库与去重、分析待处理/失败/标注异常、预算上限/预留/实耗、未确认缺口；可追到内容或热榜快照 |

**来源与时间口径**：四关键词来源为 `hackernews` Algolia、`google_news` Google News 搜索 RSS、`news_search` 本机 SearXNG `duckduckgo news`、`rss_36kr` RSSHub `/36kr/newsflashes`；六榜为微博、百度、知乎、B 站热门、36Kr、澎湃 RSSHub 路由，具体路径见 FR-002-006。主题默认 30 分钟、最短 10 分钟；来源预设取更保守节奏。默认 24 小时回看、上限 7 天，不证明历史完整覆盖；发布时间、首次发现与热榜观察时间分别记录。

## 6. 验收标准与退出条件

**证据门槛**：表中列出的等级须分别具备。受控测试验证状态机、边界与故障；真实运行验证实际来源、外部依赖和持久结果；产品验收按本条样本、连续窗口或用户核对口径作结论。低一级证据不能替代高一级；“代码已合入”本身不属于通过证据。

**退出条件**：四关键词来源与六榜共用连续 72 小时窗口；十来源逐一核对延迟，六榜逐榜 ≥90% 的有效桶，Codex 相关性及时率 ≥95%，覆盖与缺口可查。受控测试、真实运行与产品验收分层记录；一项结果不替代另一项。
