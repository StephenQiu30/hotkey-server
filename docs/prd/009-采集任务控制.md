# 采集任务控制 PRD

日期：2026-09-17。状态：详细需求草案；承接既定范围 FR-001-007，保持 P0 优先级。本文是独立评审和验收依据，不代表功能已实现。对应 [执行计划](../plans/009-采集任务控制计划.md) 已建立且为 planned；同编号 Design 与真实 Acceptance 尚未建立。

入口：[逐项 PRD 索引](README.md) · [平台需求总纲](001-热点事件监控平台功能与非功能需求.md) · [鱼皮项目功能研究](../research/001-热点事件监控平台调研.md)。

## 1. 背景、问题与用户价值

监控必须能解释一次采集是否开始、在哪里停下和能否恢复。仅靠页面刷新或后台日志，用户无法分辨零结果、故障和预算延期。

总纲原始要求：提供定时/手动运行、暂停、取消、按原因重试、进度、历史记录；区分零结果、部分完成、等待预算、限流、需登录、无权限与解析失败。

用户手动刷新事件时来源限流，希望系统告诉他何时重试，同时避免重复点击发起多份相同任务。

## 2. 目标与成功指标

**BR-009-001：**让每次采集拥有可追踪、可控制、可恢复的业务状态，失败与部分完成不被掩盖。

| 指标 | 统计口径 | 目标或判定 |
|---|---|---|
| 确认后可追踪率|已受理任务中能查询到持久状态的比例|100% |
| 重复操作影响|相同提交重试产生额外业务效果|0 |
| 状态解释率|终态/延期具有稳定原因和结果范围|100% |

指标用于评审和后续测量，尚未取得运行结果。涉及新增数量、时长和默认值的建议须在实施前冻结；不据此扩大既定平台范围或付费权限。质量目标不以“页面有按钮”替代。

## 3. 范围、优先级与边界

- **本期范围（P0）：**手动与定时任务受理、排队、执行、取消、进度、重试、预算延期和历史。
- **明确不包括：**用户可视化编排任意爬虫、无上限重试、以日志代替任务记录。
- **与相邻能力的边界：**本模块管理一次执行；周期意图由主题/账号维护，内容幂等及回补由 010。
- **发布条件：**本文件全部适用验收通过，并满足关联质量要求；缺失该能力不能用演示或其他功能替代 P0 完成。

## 4. 用户流程与关键结果

1. 用户显式执行或周期到期，保存任务意图及配置版本。
2. 核对能力、预算和重复请求，受理后立即返回可查询记录。
3. 进入队列后展示等待原因，执行中更新阶段与已保存条数。
4. 正常、部分、失败或取消结束，保留停止原因与样本范围。
5. 用户重试时明确是继续缺口还是创建新轮次，避免重复结果。

完成后用户获得：任务记录、可理解的状态、持久进度与下一步处理入口。取消、失败或权限拒绝时，不显示与实际不符的成功结果。

## 5. 输入、配置与信息展示

| 信息项 | 规则与校验 | 默认或展示要求 |
|---|---|---|
| 任务来源|主题、账号、事件/作品及触发方式|记录手动/定时/回补 |
| 幂等标识|同一次用户提交的网络重试保持相同标识|有意新轮次另建身份 |
| 执行范围|配置版本、时间窗口、预算和优先级|受理后不可静默改变 |
| 取消/重试|说明已写入数据是否保留及重试范围|取消默认保留已取得证据 |

配置变更记录操作者、时间和版本；正在执行的操作绑定启动时的业务规则版本。当前权限、连接停用、删除要求与更严格预算始终优先，不能以旧版本继续越权或超额执行。冲突的输入必须明确拒绝或延期，不能静默修改用户意图。

## 6. 详细需求与业务规则

| 需求 ID | 规则 | 详细行为 | 对应验收 |
|---|---|---|---|
| FR-009-001 | 受理语义 | 任务已保存才报告受理；受理不等于已完成，HTTP 不等待整个外部采集。 | AC-009-002、AC-009-006 |
| FR-009-002 | 状态机 | queued→running→succeeded/partial/failed/cancelled；延期为 queued 附原因与 next_run，不将预算延期报为上游成功。 | AC-009-002、AC-009-005 |
| FR-009-003 | 进度语义 | 展示已发请求、已保存数量和阶段，未知总量不用百分比；保留最后一次进度时间。 | AC-009-003 |
| FR-009-004 | 取消边界 | 接受取消后不再发新请求，处理在途响应及已落库结果后进入 cancelled；取消超时可见且可复查。 | AC-009-003 |
| FR-009-005 | 重试分类 | 暂时故障有界重试计预算；会话、权限或结构错误暂停等待处理，不无限重试或绕过。 | AC-009-004、AC-009-005 |
| FR-009-006 | 并发与公平 | 同连接受统一并发/预算；相同有效意图不重复执行，低优先级延期有原因与最大等待可观测。 | AC-009-006 |

**DEC-009-001：**受理、运行进度与数据结果分别表达，用户看到的任务状态必须与持久记录一致。

以上规则解释 FR-001-007，不重编号或替换总纲条目。后续发现冲突应显式更新总纲及受影响文档，不由某一页面或适配器单独改变语义。

## 7. 状态、异常与权限

| 状态或场景 | 展示与处理 |
|---|---|
| 排队/延期|显示原因与预计尝试时间，未知时间明确未知。 |
| 部分/失败|列出成功来源、数据范围、错误类别和可重试范围。 |
| 取消中/已取消|显示仍在处理的在途请求，不能瞬间假报所有外部请求已消失。 |
| 加载或执行中 | 展示已知阶段和可用操作；未知进度不用虚假百分比，已持久化历史结果可以继续查看。 |
| 无权访问 | 显示稳定的权限提示，不通过错误内容泄露其他使用者的数据或凭据。 |

只有所有者可取消/重试自己的任务；维护者可在授权范围停止故障执行，不修改用户采集规则。

| 身份 | 访问与操作边界 |
|---|---|
| 资料或配置所有者 | 在本文件范围内处理自己的业务资料与配置；维护职责的动作仍须相应授权。 |
| 获授权维护者 | 仅诊断或维护明确授权的范围，不自动获得业务正文、规则修改或秘密回读权限。 |
| 其他身份 | 默认拒绝；仅在 026 团队协作正式启用且被显式授权后，按实际角色开放对应操作。 |

本项专门权限规则优先约束上述通用边界，后续角色设计不能扩大已有秘密或数据访问权限。

重复点击、刷新页面或网络重试不得重复产生同一业务结果；若本操作是有意新建的一次业务行为，必须有独立标识和清晰的版本/时间范围。

## 9. 验收标准

AC-001-007 是父级验收，本文件第一项完整保留其场景，其余补充边界、异常和业务细节。以下全部是待执行标准，不是已通过记录。

| 验收 ID | 场景 | Given：前提 | When：操作 | Then：可核查结果 |
|---|---|---|---|---|
| AC-009-001 | 总纲场景继承 | 相同主题依次收到合法空结果、限流和解析错误 | 查看任务结果 | 三种状态可区分；受限任务不无限重试，取消最终停止新增请求。 |
| AC-009-002 | 受理后刷新 | 任务已确认受理但未开始 | 刷新页面 | 记录仍存在，显示排队而非成功 |
| AC-009-003 | 取消在途 | 已有一个请求在途 | 取消任务 | 停止后续请求，保留结果范围后转取消 |
| AC-009-004 | 重试预算 | 暂时超时连续发生 | 自动重试 | 达到上限后延期/失败，全部尝试计预算 |
| AC-009-005 | 不可重试错误 | 连接失效或访问拒绝 | 到达下一周期 | 暂停受影响能力，不自动换账号继续 |
| AC-009-006 | 重复提交 | 同一次请求重复发送三次 | 受理并运行 | 同一有效任务不产生三份数据或通知 |

交付证据应包含输入/规则版本、执行记录、实际结果和人工核对结论。界面能力须有真实浏览器证据；运行、恢复与来源能力按相应环境验证，纯文档检查不计作产品验收。
