# 事件变化雷达与低噪声告警

## 范围

- 新增按时间窗口、Monitor、生命周期、趋势和核验状态筛选的 Radar API，返回独立、可解释的热点维度；首屏冻结最多 100 个有序位置，后续页通过 15 分钟有效的 HMAC-SHA256 签名游标消费剩余位置。
- 在 24 小时 Event heat 重算后确定性生成 append-only EventUpdate，并提供事件变化时间线查询。
- 新增 Alert Thread、Occurrence 和 State Audit，基于 EventUpdate、当前 MonitorEvent 和 published Monitor threshold 生成幂等告警。
- 新增 `evaluate_event_alerts` 持久任务；重复处理、并发 Worker 和入队重试不产生重复 Update、Occurrence 或 Thread。
- 提供 Alert 列表、详情、acknowledge、resolve、suppress API；列表使用 15 分钟有效的 HMAC-SHA256 签名游标，详情在只读 REPEATABLE READ 快照中组装，状态写入使用 expected version 并记录 actor/reason。
- AI Provider 不可用时完整保留 Radar、EventUpdate、Watch matching 与 Alert 行为。

## 非目标

- 不实现前端页面、Workspace 多租户、SSE/WebSocket、Email/Webhook 告警投递或移动推送。
- 不在本任务重命名现有 Monitor/Content/Report 物理表，不新建 migrations 目录。
- 不实现自然语言 Watch 编译、不可变 Signal Snapshot、自动 Claim 抽取、深度 Analysis 或新 Connector。
- 不移除已存在的 Knowledge、Report 和 Subscription 能力。

## 验收条件

1. Radar 在 24h Fixture 中按 momentum 返回正确顺序，同时返回 attention、momentum、breadth、confirmation、data confidence、ranking reason 和最新 EventUpdate；首屏冻结最多 100 个有序位置，后续投影变化或 `as_of` 后新增不可变事实不改变剩余页成员与顺序。
2. Radar 支持 1h/6h/24h/7d、monitor、lifecycle、trend、verification、min heat 与五种排序；没有 monitor 时 relevance 排序返回参数错误。
3. 首次 24h heat 快照、进入 rising、复燃、来源扩展和 heat 大幅变化各产生一条确定 kind 的 EventUpdate；非实质重算不产生 Update。
4. 同输入重复或两个 Worker 并发记录 EventUpdate，最多写一条，sequence 单调且 UPDATE/DELETE 被数据库拒绝。
5. active Monitor 的 visible MonitorEvent 达到 published `event_threshold` 时，eligible EventUpdate 产生一个 Alert Thread 和一个 Occurrence；线程冻结 config ID/revision/hash/threshold，Occurrence 冻结 final score；cooling 不产生 Alert。
6. 同一任务重复执行不增加 occurrence；每个唯一 occurrence 累加 count/version，但只有 `(triggered_at,event_update_id)` 严格更新的输入推进线程快照、冷却和 reopen。乱序输入不覆盖最新快照、不使 `updated_at` 倒退，也不重新打开线程；suppressed 永不重新打开。
7. acknowledge/resolve/suppress 使用乐观锁，成功写 Alert State Audit；旧版本和非法状态返回 409 且无部分写入。
8. Radar 与 Alert 游标均有 HMAC-SHA256 完整性、用途隔离和 15 分钟过期校验；篡改、过期或跨查询复用返回参数错误。viewer 可 acknowledge/resolve 但不能 suppress；editor/admin 可执行三种动作。
9. `RecordOccurrence` 拒绝非有限 final score/threshold、`final_score < threshold` 和不匹配的 severity；Alert 详情在同一只读 REPEATABLE READ 事务中返回线程、最近 50 条 occurrence 与完整状态审计。
10. 认证、角色、统一 Result、敏感信息边界、OpenAPI、Schema、数据库记录模型和索引一致。
11. AI Profile 为空，或 Provider unavailable/transient/timeout 时，自动链仍产生 EventUpdate、Radar 和 Alert；summary 明确 degraded 且不生成无证据事实。
12. 完整质量门禁通过；隔离 PostgreSQL 测试不得使用当前开发数据库。

## 运行成功标准

- 当前本机没有 active Source/Monitor/AI Profile 时，服务仍能启动且全局 Radar 安全返回；没有匹配 Monitor 时 Alert 列表为空而不是失败。
- 使用两个测试 Source、一个 active Monitor 和同一事件 Fixture，流水线最终得到一个 Radar Event、至少一个 EventUpdate 和恰好一个 Alert Thread。
- 重放相同 Fixture 与任务两次，业务事实数量不增加。
