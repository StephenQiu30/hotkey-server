# AI真伪相关性重要性与摘要

## 用户问题

项目已有 OpenAI、DeepSeek、Ollama、ONNX/Embedding、结构化 Schema、相关性复核、实体声明提取和事件摘要，但尚未用一套产品分数完整覆盖参考项目的 isReal、relevance、importance、summary 体验。

## 产品目标

对每条候选内容生成可解释、可降级、可追溯的真实性风险、相关性、重要性和摘要结果，并控制模型成本。

## 范围

- 真实性风险与理由
- 监控相关性分数和反馈
- 重要性分数与组成
- 内容/事件结构化摘要及模型运行证据

## 用户故事

- 作为阅读者，我能快速看到重要变化、依据、可信程度和更新时间。
- 作为编辑者，我能从发现、研判到处理和交付完成闭环。
- 作为管理员，我能查看成本、失败、权限和审计并安全恢复。

## 功能要求

- FR-019-1：真实性不是无证据的真假裁决，而是 `credibility_status + confidence + reasons + evidence_ids`；单一模型不得把内容永久标成虚假。
- FR-019-2：相关性结合确定性规则、Embedding 和可选 LLM 复核；重要性以来源质量、传播宽度、新颖度、影响和时效组成。
- FR-019-3：所有模型输出使用版本化 JSON Schema，保存 provider/model/prompt/schema/input_hash/evidence/cost/latency。
- FR-019-4：模型不可用时使用规则和证据摘要降级，事件、热度、告警与列表仍可运行。

## 非功能要求

- 写操作具备认证授权、审计、幂等或乐观锁；异步操作可追踪和重试。
- 列表使用稳定分页，慢任务不阻塞 HTTP；错误使用统一业务码。
- 前端使用 shadcn/ui/Radix 组合，覆盖响应式、键盘、焦点、对比度与减弱动效。

## 非目标

不以静态 Mock、不可追溯模型文本或仅桌面可用页面通过验收。

## 验收标准

- AC-019-1：相同输入和模型版本可追溯且幂等
- AC-019-2：低置信度不会被 UI 表达为确定事实
- AC-019-3：预算耗尽或模型故障时核心流水线成功降级
