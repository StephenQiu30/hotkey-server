# AI 真伪、相关性、重要性与摘要

## 用户问题

系统已经计算相关性、声明证据、热度与摘要，但事件页只展示标题、来源数和趋势。用户看不到确认状态的含义、声明依据或重要性组成，还可能在没有选择 Monitor 时触发无效的相关性排序。

## 产品目标

把现有可追溯智能事实组合成一个可读的事件研判面板：明确“证据确认不等于真假裁决”，在 Monitor 上下文中解释相关性，以真实 Heat/Radar 字段解释重要性，并展示可回溯 Content 的声明证据与摘要。

## 角色与用户故事

- 作为 Viewer，我能区分多源确认、单源、未核实、争议和证据不足，并打开每条声明的来源内容。
- 作为 Viewer，我能看到重要性、动量、来源宽度和数据置信度，而不是一个无解释的 AI 分数。
- 作为 Editor/Admin，我能按具体 Monitor 查看事件相关性，不会把跨 Monitor 分数混在一起。

## 功能要求

### FR-019-1 证据确认

- 事件选中后读取真实 Intelligence Claims，显示状态、置信度、声明文本和 Content 证据。
- confirmation score 标注为“证据确认强度”，并明确不是事实为真的概率；`single_source/unverified/disputed/insufficient` 使用非确定性表达。

### FR-019-2 相关性

- 页面列出 active/paused Monitor 作为上下文；选择后把 `monitor_id` 传给 Radar，并展示 watch relevance/final score。
- 未选择 Monitor 时禁用 relevance 排序且不显示虚假的 0 分。

### FR-019-3 重要性

- 使用 Radar `attention` 作为重要性主分数，同时展示 `momentum`、`breadth`、`data_confidence` 与独立来源数。
- 不在前端重新计算或持久化产品分数。

### FR-019-4 摘要、追溯与降级

- 展示真实 Event Summary、最新变化和声明证据；证据链接进入 Content 详情。
- Intelligence/Update 辅助请求失败时显示局部降级提示，Radar 主列表仍可用。
- 既有 AI Run/JSON Schema/reuse key/预算和 fallback 自动化必须继续通过。

## 非功能要求

- 页面使用生成 Client 和 shadcn/ui 官方组件，桌面与 390px 可用，键盘焦点、对比度与 axe 通过。
- 请求不暴露模型原始 payload、对象键、凭据或内部错误；空值使用未知语义。
- 本条不改 Schema，不增加第三方模型调用，不影响无 AI 配置的默认运行。

## 非目标

- 不提供法律/事实核查结论，不把 confirmation 映射为真/假。
- 不新增 Content 级生成摘要、通用知识图谱编辑器、模型成本控制台或搜索排序；分别由证据详情、025 和 021 承担。

## 验收标准

- AC-019-1：现有 AI Run 幂等、版本、Schema、证据 hash、成本/延迟和预算降级回归通过。
- AC-019-2：五种 confirmation 均有中性文案；低置信度不显示为确定事实，声明证据可打开 Content。
- AC-019-3：无 Monitor 时 relevance 排序不可用；选择 Monitor 后请求带 monitor_id 并展示真实相关性。
- AC-019-4：重要性、动量、来源宽度和数据置信度完全来自 Radar，不在前端重算。
- AC-019-5：Intelligence/Update 失败局部降级；无模型或预算耗尽时核心 Radar/Heat/告警链继续工作。
- AC-019-6：后端全量 CI、前端全量测试/build、Compose、桌面/390px、角色/匿名和 axe 全部通过。
