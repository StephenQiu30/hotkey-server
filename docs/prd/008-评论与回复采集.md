# 评论与回复采集 PRD

日期：2026-09-17。状态：详细需求草案；承接既定范围 FR-001-006，保持 P0 优先级。本文是独立评审和验收依据，不代表功能已实现。对应 [执行计划](../plans/008-评论与回复采集计划.md) 已建立且为 planned；同编号 Design 与真实 Acceptance 尚未建立。

入口：[逐项 PRD 索引](README.md) · [平台需求总纲](001-热点事件监控平台功能与非功能需求.md) · [鱼皮项目功能研究](../research/001-热点事件监控平台调研.md)。

## 1. 背景、问题与用户价值

评论中大量信息依赖父帖或上一层回复。无边界递归既会耗尽预算，也会把有限样本误呈现成全部讨论。

总纲原始要求：按事件和代表作品采集评论、回复及可访问上下文；支持采样数量/时间/层级预算，保留父子关系；显示来源排序、样本范围和停止原因。

用户在某召回事件中选择代表作品，查看支持、反对和追问的上下文，并知道哪些回复没有采到。

## 2. 目标与成功指标

**BR-008-001：**以有界、可追溯的采样获取评论和回复，让讨论分析具备上下文而不夸大覆盖。

| 指标 | 统计口径 | 目标或判定 |
|---|---|---|
| 关系准确性|冻结样本父评论、根帖与回复对象核对|全部通过 |
| 采样说明完整率|讨论页显示来源/时间/排序/停止原因|100% |
| 重跑重复条数|同平台评论 ID 重复实体数|0 |

指标用于评审和后续测量，尚未取得运行结果。涉及新增数量、时长和默认值的建议须在实施前冻结；不据此扩大既定平台范围或付费权限。质量目标不以“页面有按钮”替代。

## 3. 范围、优先级与边界

- **本期范围（P0）：**事件/作品触发评论采样、根评论和嵌套回复、增量刷新、父节点缺失、采样预算与统计说明。
- **明确不包括：**全量评论承诺、获取受限评论、无限深度遍历、将弹幕默认当评论。
- **与相邻能力的边界：**采集保存原文及关系，观点归纳由 015；评论是否含主题词不决定其是否属于作品讨论。
- **发布条件：**本文件全部适用验收通过，并满足关联质量要求；缺失该能力不能用演示或其他功能替代 P0 完成。

## 4. 用户流程与关键结果

1. 选择事件或作品并核对来源评论能力。
2. 设置代表作品数、评论排序意图、条数/层级/时间预算。
3. 先取得根帖和直接讨论，再在预算内补充分支。
4. 去重保存关系与采样记录，展示未获得上下文的位置。
5. 对活跃旧帖再次刷新，分析时固定本轮样本范围。

完成后用户获得：带父子关系的讨论样本、覆盖说明和可继续采样的进度。取消、失败或权限拒绝时，不显示与实际不符的成功结果。

## 5. 输入、配置与信息展示

| 信息项 | 规则与校验 | 默认或展示要求 |
|---|---|---|
| 根作品/会话|使用明确原生身份，不以关键词直接替代根对象|根对象未验证时先补详情 |
| 采样模式|来源支持的热门/最新或接口默认分别标注|不能把本地排序称为上游排序 |
| 数量与层级|建议每事件 3 个根作品、每作品 50 条、最多 3 层|来源/总请求预算更严格时提前停止 |
| 时间与刷新|记录发布时间窗口和本次观测时间|旧帖可有新回复，不能只追新作品 |

配置变更记录操作者、时间和版本；正在执行的操作绑定启动时的业务规则版本。当前权限、连接停用、删除要求与更严格预算始终优先，不能以旧版本继续越权或超额执行。冲突的输入必须明确拒绝或延期，不能静默修改用户意图。

## 6. 详细需求与业务规则

| 需求 ID | 规则 | 详细行为 | 对应验收 |
|---|---|---|---|
| FR-008-001 | 父子关系 | 保留原生评论 ID、所属作品/会话和父 ID；未知父节点保留关系并提示未获取。 | AC-008-002 |
| FR-008-002 | 采样边界 | 条数、页数、时长、请求及层级多重约束，任一耗尽停止新增请求并标部分完成。 | AC-008-003 |
| FR-008-003 | 排序诚实 | 默认返回样本、本地热门排序、平台原生热门是不同标签；不支持的模式不能显示为已完成。 | AC-008-004 |
| FR-008-004 | 增量去重 | 旧根评论的新回复可追加，同 ID 重采更新可变字段与观察，不产生重复计数。 | AC-008-005 |
| FR-008-005 | 数量说明 | 来源显示总数与实采样本量并列，口径不确定时不计算完整率；不把未获取当无评论。 | AC-008-006 |
| FR-008-006 | 归属不扩张 | 引用帖和转帖不是直接回复；没有关键词的相关上下文仍可纳入，不从父节点缺失猜测文本。 | AC-008-002 |

**DEC-008-001：**评论采集以关系和采样证据为核心，显示真实不完整性而非追求虚假的完成百分比。

以上规则解释 FR-001-006，不重编号或替换总纲条目。后续发现冲突应显式更新总纲及受影响文档，不由某一页面或适配器单独改变语义。

## 7. 状态、异常与权限

| 状态或场景 | 展示与处理 |
|---|---|
| 等待能力/根帖|显示需连接或补全的对象，不误报空讨论。 |
| 部分样本|给出数量、未获父帖、停止原因和可继续条件。 |
| 删除/受限|保留允许保留的标识与状态，正文按数据生命周期处理。 |
| 加载或执行中 | 展示已知阶段和可用操作；未知进度不用虚假百分比，已持久化历史结果可以继续查看。 |
| 无权访问 | 显示稳定的权限提示，不通过错误内容泄露其他使用者的数据或凭据。 |

所有者可对自己有权研究的作品请求采样；评论作者公开身份只用于内容溯源，不推断私人属性。

| 身份 | 访问与操作边界 |
|---|---|
| 资料或配置所有者 | 在本文件范围内处理自己的业务资料与配置；维护职责的动作仍须相应授权。 |
| 获授权维护者 | 仅诊断或维护明确授权的范围，不自动获得业务正文、规则修改或秘密回读权限。 |
| 其他身份 | 默认拒绝；仅在 026 团队协作正式启用且被显式授权后，按实际角色开放对应操作。 |

本项专门权限规则优先约束上述通用边界，后续角色设计不能扩大已有秘密或数据访问权限。

重复点击、刷新页面或网络重试不得重复产生同一业务结果；若本操作是有意新建的一次业务行为，必须有独立标识和清晰的版本/时间范围。

## 9. 验收标准

AC-001-006 是父级验收，本文件第一项完整保留其场景，其余补充边界、异常和业务细节。以下全部是待执行标准，不是已通过记录。

| 验收 ID | 场景 | Given：前提 | When：操作 | Then：可核查结果 |
|---|---|---|---|---|
| AC-008-001 | 总纲场景继承 | 样本含根评论、直接和嵌套回复，部分父帖不可见 | 采集并打开讨论 | 关系正确、缺失父帖有提示；达到预算显示部分完成，不宣称全量。 |
| AC-008-002 | 缺父帖 | 有子回复但父文本不可访问 | 展示讨论树 | 保留父 ID 并提示缺失，不编造内容 |
| AC-008-003 | 触及层级 | 第三级回复仍有下层游标 | 达到配置深度 | 停止且标层级截断，不宣称线程全部完成 |
| AC-008-004 | 排序能力 | 来源只返回默认顺序 | 用户选择热门意图 | 说明只可对已采样数据本地排序 |
| AC-008-005 | 旧帖新回复 | 第二轮出现旧根评论下的新回复 | 增量采集 | 新回复加入且原评论不重复 |
| AC-008-006 | 总数不一致 | 来源总数 260、实采 83 且含多层回复 | 查看采样说明 | 显示两者口径和时间，不声称 31.9% 完整率 |

交付证据应包含输入/规则版本、执行记录、实际结果和人工核对结论。界面能力须有真实浏览器证据；运行、恢复与来源能力按相应环境验证，纯文档检查不计作产品验收。
