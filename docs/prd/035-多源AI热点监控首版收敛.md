# 多源 AI 热点监控首版收敛

## 用户目标

用户配置一个需要持续关注的主题，系统从 Twitter/X、Bing、Hacker News、B 站等 7 个正式来源聚合发现内容，经 AI 查询扩展、相关性和可信度分析后形成热点，在 Web 页面中实时看到并可收到邮件通知。

## 功能要求

- FR-035-1：来源控制面必须能创建、编辑、探测、启停 RSS、Hacker News、X、Bing Grounding、Bilibili、Weibo、Google Agent Search；启用且被已发布 Monitor 引用的来源进入自动调度。
- FR-035-2：单个来源认证、配额、限流或上游失败只产生该来源的明确失败，不触发隐藏回退，也不阻塞其他来源。
- FR-035-3：Monitor 支持 AI 查询扩展候选的生成、审核、发布和版本回溯；扩展服务不可用时使用原始查询与确定性规则。
- FR-035-4：内容相关性使用发布版本的 Compiled Intent 与 DocumentMatch 决策；低相关内容不得进入有效 MicroEvent 成员。
- FR-035-5：真假/可信度界面展示可引用证据状态与冲突/更正/撤回原因，不显示无证据的真伪概率；AI 自动抽取失败不能回滚已采集内容或热点。
- FR-035-6：`micro_event_id` 是唯一对外热点 ID；legacy Event/Radar/Alert/Report 不得继续产生新事实或出现在默认 API/工作台。
- FR-035-7：热点列表支持按来源、Monitor、可信状态、事件状态、开始时间筛选，按 Heat v2、相关性和时间排序，使用稳定游标分页。
- FR-035-8：WebSocket 对当前用户通知提供鉴权、`after_id` 重放、Monitor 筛选、心跳、容量限制和断线恢复；SSE 可作为兼容降级。
- FR-035-9：邮件通知消费同一 UserNotification，发送前复核用户、Monitor 和已发布邮件开关，失败退避且最多五次，结果只追加 DeliveryAttempt。
- FR-035-10：X 使用官方 Recent Search 和 Post Lookup，支持受预算约束的持续指标快照；其他来源不因该增强被降级或移除。
- FR-035-11：Landing、来源、监控、热点和通知页面使用多源 AI 热点监控语言，不宣传已退出范围的报告、知识库或 Agent 产品。
- FR-035-12：Bilibili webhook 继续作为正式来源入口出现在 API 启动图、OpenAPI 和生成 Client 中。

## 非功能要求

- 所有凭据只由服务端加密保存，不回显；来源 URL 继续遵循固定端点/SSRF 契约。
- WebSocket/SSE 不成为事实源，服务重启后能从 PostgreSQL 游标恢复。
- 数据库筛选和排序不得先全量读取后在应用内分页。
- AI 不可用、文档不可引用、来源不足时必须显示不确定性，不伪造“真实”。

## 不在首版

- 日报、周报、私有 RSS Feed、独立知识库、Agent Token/Agent Skill。
- 通用搜索门户、自动发帖、组织协作、第二套告警/事件系统。
- 评论/回复正文、评论树和通用浏览器爬虫；该后续候选范围由 036 单独评审。
- 新增第八类未授权爬虫或使用浏览器 Cookie 抓取平台。

## 验收标准

- AC-035-1：七类来源分别通过 Domain、ConnectorRegistry、HTTP/OpenAPI、表单和自动 CollectionTarget 测试；其中一个失败时其余目标仍会被调度。
- AC-035-2：发布 Monitor 后，Query Expansion、DocumentMatch、MicroEvent、Heat 和 EvidenceState 的版本/ID 可追溯，且 legacy 表不增长。
- AC-035-3：列表组合筛选及三种排序在至少两页数据上无重复、跳项或跨筛选游标复用。
- AC-035-4：WebSocket 能重放断线期间通知、隔离用户和 Monitor、发心跳、拒绝超容量连接；轮询降级仍可用。
- AC-035-5：SMTP 成功、暂时失败、永久失败、撤权和关闭邮件开关均有测试，通知事实不被投递结果覆盖。
- AC-035-6：390px 与桌面用户能完成“创建多源连接—发布监控—查看可信热点—实时/邮件通知—回溯原文”主故事。
- AC-035-7：默认 API/Worker/前端启动图没有报告、知识库、Agent 和 legacy 热点链，仍包含多源与 Bilibili webhook。
