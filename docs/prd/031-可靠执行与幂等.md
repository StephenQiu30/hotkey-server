# 可靠执行与幂等 PRD

日期：2026-09-24。状态：详细需求草案；承接既定范围 NFR-001-005，保持 P0 优先级。本文是独立评审和验收依据，不代表功能已完整实现。对应 [执行计划](../plans/031-可靠执行与幂等计划.md) 已完成 S00—S02，[同编号 Design](../design/031-可靠执行与幂等设计.md) 已冻结这些切片及 S03 的保守归属/原始观察规则；用户已冻结 `webpage.collect` 端到端目标 30 分钟，统计实现、72 小时观察和真实 Acceptance 尚未完成。

入口：[逐项 PRD 索引](README.md) · [平台需求总纲](001-热点事件监控平台功能与非功能需求.md) · [鱼皮项目功能研究](../research/001-热点事件监控平台调研.md)。

## 1. 背景、问题与用户价值

监控会长期运行，页面确认、调度和数据写入之间任一处中断，都可能让用户漏掉事件或反复收到同一提醒。可靠性需要以用户已经获得的确认和实际业务结果为依据。

总纲原始要求：重复调度、消息重投、并发点击和进程中断不能造成业务数据重复或任务静默丢失；先有持久化状态再对用户确认。

使用者提交评论补采后关闭页面，执行进程随后重启；再次查看时应能找到原任务，已保存评论继续保留，重复执行不会产生第二份评论或相同提醒。

## 2. 目标与成功指标

**BR-031-001：**使每个已确认任务均有持久记录、可恢复执行轨迹和确定的业务结果，重复调度不增加业务重复。

| 指标 | 统计口径 | 目标或判定 |
|---|---|---|
| 已确认任务可追踪率|有持久任务记录的成功受理请求数 / 全部成功受理请求数|100%，无法持久化不得返回已受理 |
| 重复业务结果|同一幂等范围下重复作品、评论、提醒记录数量|至少三组故障验证中为 0 |
| 内部任务执行率|按唯一逻辑 Job 计数；计划任务从 `scheduled_for_at`、即时任务从 `created_at` 起，至 `completed_at` 终态止，排队和重试均计入历时；按 SLA 截止落窗的任务构成分母；在截止时刻或之前完成预期内部处理的占比|当前 `webpage.collect` 目标 30 分钟；72 小时试运行候选 ≥99%；完整成功或有同一 Job 持久来源失败证据且按期记录，计为内部处理按期完成，来源结果单列；其余失败列“未归属”并保守计入执行失败；部分采集不算全量成功；零分母比率未定义 |

指标用于评审和后续测量，尚未取得运行结果。涉及新增数量、时长和默认值的建议须在实施前冻结；不据此扩大既定平台范围或付费权限。质量目标不以“页面有按钮”替代。

## 3. 范围、优先级与边界

- **本期范围（P0）：**任务确认、重复投递、恢复、调度重叠、有限重试，以及运行质量统计。
- **明确不包括：**承诺第三方平台永远可用、外部通知收件端严格只收到一次、不可达来源仍能采全。
- **与相邻能力的边界：**采集任务控制定义用户操作；本文件保证其确认可靠。外部通知超时仍可能为未知结果，依照 024 保留投递状态，不能用重发掩盖。
- **发布条件：**本文件全部适用验收通过，并满足关联质量要求；缺失该能力不能用演示或其他功能替代 P0 完成。

## 4. 用户流程与关键结果

1. 用户提交或调度生成任务，系统先检查配置、权限和预算。
2. 持久化任务标识、业务范围、配置版本和状态后返回已受理。
3. 执行者在有效执行权内处理，结果和进度按可恢复单元保存。
4. 发生崩溃或重复投递时按同一业务标识恢复，失效执行者不能覆盖新进度。
5. 用户查看最终结果、部分结果和恢复过程，运维按固定口径评估试运行。

完成后用户获得：可查询、可解释且不会因重试增殖的任务及业务结果。取消、失败或权限拒绝时，不显示与实际不符的成功结果。

## 5. 输入、配置与信息展示

| 信息项 | 规则与校验 | 默认或展示要求 |
|---|---|---|
| 业务操作标识|同一次操作重试复用；主动创建不同时间范围的新任务使用新标识|展示任务号、范围和创建原因 |
| 幂等范围|按所有者、来源、对象稳定 ID 和操作语义界定；指标快照另含采样时刻|跨主题可关联同一对象，不重复计数 |
| 执行期限与重试|每类任务定义期限、可重试错误、次数与退避上限|耗尽后失败或部分完成，不能无限运行 |
| 运行统计窗口|保存计划到期时间、实际开始/结束及分类原因|内部处理和外部来源结果分别展示 |

配置变更记录操作者、时间和版本；正在执行的操作绑定启动时的业务规则版本。当前权限、连接停用、删除要求与更严格预算始终优先，不能以旧版本继续越权或超额执行。冲突的输入必须明确拒绝或延期，不能静默修改用户意图。

## 6. 详细需求与业务规则

| 需求 ID | 规则 | 详细行为 | 对应验收 |
|---|---|---|---|
| NFR-031-001 | 持久确认 | 只有持久任务及必要配置引用落地才确认受理；确认响应丢失后的同标识重试返回原任务。存储失败必须说明未受理，不创建不可追踪成功状态。 | AC-031-002 |
| NFR-031-002 | 业务幂等 | 同一平台对象只产生一个业务实体或明确版本；同一次采样、事件关联和业务提醒按各自语义防重。原文更新不是重复记录，跨主题关联不等于新作品。 | AC-031-002、AC-031-003 |
| NFR-031-003 | 中断恢复 | 进度只推进到已保存结果；恢复能够从最后有效进度继续。执行权失效的旧进程不能提交覆盖，取消和删除约束在恢复前重新校验。 | AC-031-003 |
| NFR-031-004 | 调度重叠 | 相同主题、能力和时间窗口的调度不并发产生等价采集；漏执行窗口合并或有限补偿并记录覆盖范围，不能重启后无界补跑。 | AC-031-004 |
| NFR-031-005 | 有限重试与隔离 | 仅暂时性故障重试，授权失效、格式不兼容和禁止访问转可操作状态；不可处理任务隔离并保留原因，不能堵住队列或静默丢弃。 | AC-031-005 |
| NFR-031-006 | 可靠性度量 | 执行率分母为观察期内已到执行期限的内部单元，系统自身失败不得剔除；等待来源恢复等非到期工作另列数量和等待时长。仅同一逻辑 Job 关联到 `persisted_read/failed` 证据时列来源结果；其他失败列“未归属”并保守计入执行失败，不假定为内部故障。部分采集独立展示，不能冒充完整成功。 | AC-031-006 |

**DEC-031-001：**以持久业务结果和状态机恢复定义可靠性，不以队列已接收、进程存活或第三方响应一次成功替代。

以上规则解释 NFR-001-005，不重编号或替换总纲条目。后续发现冲突应显式更新总纲及受影响文档，不由某一页面或适配器单独改变语义。

## 7. 状态、异常与权限

| 状态或场景 | 展示与处理 |
|---|---|
| 受理失败|说明尚未创建有效任务，允许用户重试同一操作 |
| 恢复中|展示上次持久进度和恢复原因，不将进度清零或重复计数 |
| 重试耗尽或无法处理|保留已保存结果，说明人工可重试条件及不能自动恢复的原因 |
| 加载或执行中 | 展示已知阶段和可用操作；未知进度不用虚假百分比，已持久化历史结果可以继续查看。 |
| 无权访问 | 显示稳定的权限提示，不通过错误内容泄露其他使用者的数据或凭据。 |

任务重放沿用当前所有者权限和当前数据删除约束，不能借历史凭据或旧权限继续执行；运维可查看脱敏故障信息，不能默认读取正文。

| 身份 | 访问与操作边界 |
|---|---|
| 资料或配置所有者 | 在本文件范围内处理自己的业务资料与配置；维护职责的动作仍须相应授权。 |
| 获授权维护者 | 仅诊断或维护明确授权的范围，不自动获得业务正文、规则修改或秘密回读权限。 |
| 其他身份 | 默认拒绝；仅在 026 团队协作正式启用且被显式授权后，按实际角色开放对应操作。 |

本项专门权限规则优先约束上述通用边界，后续角色设计不能扩大已有秘密或数据访问权限。

重复点击、刷新页面或网络重试不得重复产生同一业务结果；若本操作是有意新建的一次业务行为，必须有独立标识和清晰的版本/时间范围。

- **适用质量要求：**本文件即质量要求的细化，受总纲免费、数据边界和真实验收约束。
- **验证口径：**至少验证确认响应丢失后重复提交、写入结果后进程中断并重投、旧执行者与恢复执行者并发提交三组场景；另验证重启调度追赶、永久错误和通知重投。72 小时试运行公布全量计数、期限和排除明细，故障注入验收与正常试运行分开记录。

总纲质量目标：在至少 3 组重复投递/中断场景中，已确认任务可恢复追踪，重复业务实体和重复通知为 0。试运行 72 小时记录内部任务执行率，拟定 ≥99%，分母不剔除系统自身失败。
来源访问条件未满足时，使用受控样本验证内部规则，并单独记录真实来源验证未完成；不能用模拟成功冒充真实平台接入。涉及性能沿用总纲 B0，分析质量沿用 Q0；未采用相关基线时需注明适用样本和环境。

## 9. 验收标准

AC-001-029 是父级验收，本文件第一项完整保留其场景，其余补充边界、异常和业务细节。以下全部是待执行标准，不是已通过记录。

| 验收 ID | 场景 | Given：前提 | When：操作 | Then：可核查结果 |
|---|---|---|---|---|
| AC-031-001 | 总纲场景继承 | 已确认任务执行中进程中断且重复投递 | 恢复执行 | 任务可找到且幂等继续；没有已确认却无记录的任务。 |
| AC-031-002 | 确认响应丢失 | 任务已持久化但客户端未收到确认 | 使用同一操作标识再次提交 | 返回同一任务；若首次写入失败则无成功确认也无幽灵任务 |
| AC-031-003 | 中断与旧执行者 | 已保存半批结果且原执行者失去执行权 | 恢复任务后旧执行者又提交 | 保留唯一业务实体，进度不倒退，不越过未保存数据 |
| AC-031-004 | 调度追赶 | 服务停机跨过多个周期且存在进行中窗口 | 重新启动调度 | 补偿范围明确且受限，相同窗口不同时执行两次 |
| AC-031-005 | 永久错误 | 来源授权失效或某条记录持续不可解析 | 执行到错误处理分支 | 不无限重试，明确阻塞范围，其他任务可继续 |
| AC-031-006 | 统计真实性 | 试运行含内部异常、外部限流和部分采集 | 汇总 72 小时执行结果 | 自身失败进入分母及失败数，外部结果独立展示，不能把部分采集算全量成功 |

交付证据应包含输入/规则版本、执行记录、实际结果和人工核对结论。界面能力须有真实浏览器证据；运行、恢复与来源能力按相应环境验证，纯文档检查不计作产品验收。
