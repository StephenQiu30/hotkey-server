# 事件聚类、生命周期、热度与趋势

## 用户问题

系统已自动聚类并计算 Heat/Trend，但用户只能看到 Radar 投影，看不到热度六维、来源能力缺失或事件成员；后端已有锁定、生命周期、合并和拆分能力，却没有安全的工作台入口。

## 产品目标

让 Viewer 能解释事件为何升温、由哪些 Content 组成，让 Editor 能保护人工成员决定，让 Admin 能使用版本化确认操作治理生命周期、合并和拆分，同时保持自动聚类与 EventUpdate 幂等。

## 角色与用户故事

- 作为 Viewer，我能看到事件成员、成员分、来源角色、热度六维和互动能力缺失。
- 作为 Editor，我能锁定重要成员，后续自动聚类不会撤销人工决定。
- 作为 Admin，我能按合法状态机关闭/归档事件，或确认合并、拆分错误聚类。

## 功能要求

### FR-020-1 自动聚类

- 保持四通道有界召回、确定性评分、review 和新事件创建；向量降级不阻塞规则路径。
- 聚类决定、成员归属、Monitor 投影和治理审计同事务、可重放、可追溯。

### FR-020-2 成员与生命周期治理

- 事件页读取真实 Event Members；每条显示 Content 入口、成员分、证据角色、来源和人工锁定状态。
- Editor/Admin 可锁定或解锁成员；Admin 可按合法边变更生命周期，并用确认对话框合并或拆分。
- 所有命令携带 expected version 和稳定原因码；冲突后刷新，不伪造成功。

### FR-020-3 热度与趋势解释

- 每个新 Heat 快照保存独立性、内容速度、来源宽度、互动、时效和可信度六维。
- 互动能力或指标缺失必须返回 null 和原因；旧快照无组成时省略字段。
- Heat 卡展示真实总分、趋势、窗口、算法版本、六维和降级原因，不在前端重算。

### FR-020-4 EventUpdate 与 Radar

- 只有达到既有实质变化阈值才追加 EventUpdate；并发相同输入只产生一条。
- 最新变化继续进入 Radar、告警和摘要；辅助请求失败不得清空 Radar 主列表。

## 非功能要求

- Schema 仅增加一个向前兼容 JSONB 列；生成 OpenAPI 与 Client 不漂移。
- 写操作保持 RBAC、审计、乐观锁与确认门禁；Viewer 和匿名不能触发治理请求。
- 页面由 shadcn/ui/Radix 组件组合，桌面和 390px 无横向溢出，键盘、焦点、对比度与 axe 通过。

## 非目标

- 不新增可编辑聚类阈值、算法实验台、原始指标序列或通用审计浏览器。
- 不以趋势状态替代生命周期，不在前端计算 Heat，不自动调用第三方模型。

## 验收标准

- AC-020-1：四通道召回、阈值、新事件创建、向量降级、并发归属和决定追溯回归通过。
- AC-020-2：成员锁定优先于自动任务；RBAC、乐观锁、审计、合法生命周期、合并和拆分通过。
- AC-020-3：新快照持久化并投影六维；互动缺失为 null、旧快照无伪零，Heat 卡逐项可解释。
- AC-020-4：无实质变化不写更新，相同并发输入只写一条；Radar/告警/摘要回归通过。
- AC-020-5：前后端全量门禁、Compose、Viewer/Editor/Admin/匿名、桌面/390px、错误态和 axe 全部通过。
