# 日报周报私有Feed与知识归档

## 用户问题

用户无法在一个页面创建、检查、发布和订阅报告，也无法确认报告中的结论来自哪个事件版本和证据。管理员还缺少可操作的知识提案工作台，现有自动归档可能绕过人工审批边界。

## 产品目标

把高价值事件组织成可预览、可发布、可订阅、可归档的日报周报，并保留每项证据和发布版本。

## 范围

- 报告列表、详情、构建、预览和发布
- 日报/周报订阅
- 邮件与私有 Feed
- 知识提案、审批、同步和对账

## 用户故事

- 作为阅读者，我能查看报告及其固定的事件版本、摘要、热度、证据哈希和更新时间。
- 作为编辑者，我能按日报或周报、时区与监控范围创建或刷新草稿并预览。
- 作为管理员，我能发布草稿、维护交付订阅、审批知识提案并通过对账发现 Vault 漂移。

## 功能要求

- FR-024-1：Report 构建产生草稿快照，预览不修改事实，发布冻结内容与排序；同一范围和周期保持幂等。
- FR-024-2：每个 ReportItem 引用报告周期内的 EventUpdate、摘要、理由码和证据集哈希，不复制不可追溯的模型文本。
- FR-024-3：订阅支持 email 与私有 RSS/Atom；Feed Token 可轮换、仅保存摘要，不进入日志。
- FR-024-4：知识归档通过 proposal→approve/reject→apply→reconcile 流程更新 Vault，不让任务直接覆盖人工文件。
- FR-024-5：发布、幂等投递事实和知识提案处于同一数据库事务；失败时整体回滚。
- FR-024-6：报告工作台覆盖报告、订阅和知识归档，按 Viewer/Editor/Admin 隐藏或禁用越权操作。

## 非功能要求

- 写操作具备认证授权、审计、幂等或乐观锁；异步操作可追踪和重试。
- 列表使用稳定分页，慢任务不阻塞 HTTP；错误使用统一业务码。
- 前端使用 shadcn/ui/Radix 组合，覆盖响应式、键盘、焦点、对比度与减弱动效。

## 非目标

不以静态 Mock、不可追溯模型文本或仅桌面可用页面通过验收。

## 验收标准

- AC-024-1：给定跨周期事件，创建或刷新草稿只包含目标周期内最新 EventUpdate，条目返回 EventUpdate ID、证据集哈希与理由码；发布后再次构建或发布返回 409，快照不变。
- AC-024-2：同类型、监控与周期的重复创建只返回一个报告；发布同时生成至多一组交付事实和一个待审知识提案，任一依赖失败时报告仍为草稿。
- AC-024-3：email 与 RSS 的日报/周报订阅可配置监控、时区和发送时间；创建/轮换只展示一次 Token，轮换后旧 Feed 返回 404，新 Feed 支持 RSS、Atom、ETag 与 304。
- AC-024-4：管理员可列出知识文档和提案，完成 approve/reject/apply/reconcile；未审批、基线修订或 Vault 哈希冲突时不得覆盖文件，报告发布本身不直接写 Vault。
- AC-024-5：报告工作台在桌面与移动端支持加载、空态、错误恢复、筛选分页、创建、预览、发布、订阅和管理员知识流程；Viewer、Editor、Admin 权限边界正确，键盘路径与自动可访问性检查通过。
- AC-024-6：后端 CI、OpenAPI 漂移、前端类型/单测/构建、Compose 配置、`git diff --check` 与 `$agent-browser` 主故事全部通过。
