# 可观测性部署与质量门禁

## 用户问题

项目已有 health/readiness/metrics、结构化日志、OpenTelemetry 基础、运行概览、单二进制角色、双环境 Compose、后端 CI 和前端构建测试入口。

## 产品目标

让 MVP 在本地和生产可重复部署、诊断、升级和回滚，并以端到端质量门禁约束所有 001–027 实现。

## 范围

- 健康、指标、日志、追踪和运行总览
- 开发/生产容器部署
- CI、契约、浏览器和安全门禁
- 备份恢复、发布回滚和容量基线

## 用户故事

- 作为阅读者，我能快速看到重要变化、依据、可信程度和更新时间。
- 作为编辑者，我能从发现、研判到处理和交付完成闭环。
- 作为管理员，我能查看成本、失败、权限和审计并安全恢复。

## 功能要求

- FR-028-1：保持 all/api/worker 三种角色和 PostgreSQL、Redis、MinIO 基础设施；开发与生产只通过根 Compose 覆盖环境差异。
- FR-028-2：每个已注册外部来源和持久任务类型暴露耗时、成功/失败、重试与队列滞后指标；API 暴露路由级耗时和状态；配额与 AI 成本暴露当前安全投影。所有标签必须低基数且不得含用户内容、ID、URL、凭据或上游原始错误。
- FR-028-3：CI 包含后端架构/Schema/OpenAPI/测试/构建门禁、前端生成 Client/类型/单测/构建门禁、生产依赖漏洞审计、开发/生产 Compose 校验和真实容器浏览器烟测。
- FR-028-4：备份恢复、密钥轮换、来源授权和故障处置在对应功能验收后形成 Operations；发布使用向前兼容和能力开关。
- FR-028-5：任务失败历史只保存稳定原因码；管理员能查看任务 ID、类型、状态、尝试次数、安全资源 ID 与原因码，不能读取任务参数或原始错误。

## 非功能要求

- 写操作具备认证授权、审计、幂等或乐观锁；异步操作可追踪和重试。
- 列表使用稳定分页，慢任务不阻塞 HTTP；错误使用统一业务码。
- 前端使用 shadcn/ui/Radix 组合，覆盖响应式、键盘、焦点、对比度与减弱动效。

## 非目标

不以静态 Mock、不可追溯模型文本或仅桌面可用页面通过验收。

## 验收标准

- AC-028-1：全新环境按 README 可启动并通过 readiness
- AC-028-2：任一流水线失败能定位到来源、采集运行和持久任务，指标、API、日志与持久失败记录均不含业务内容、凭据或上游原始错误。
- AC-028-3：main 分支不能合入 Schema、OpenAPI、生成客户端、Compose 配置或高危生产依赖漂移。
- AC-028-4：`/metrics` 可见 HTTP、来源采集、任务、队列滞后、配额和 AI 成本指标，且指标采集失败不影响健康端点或泄露数据库错误。
- AC-028-5：Admin 在现有治理界面可查看运行总览与安全任务投影，支持加载、空、错误、筛选、重试/取消确认和响应式键盘操作；非 Admin 同时被界面与服务端拒绝。
- AC-028-6：备份恢复、发布回滚、密钥轮换、来源授权、故障处置和容量基线均有可重复执行的 Operations 手册。
