# 工程配置与启动安全加固

## 1. 背景与目标

后端已经能够启动，但开发者仍需要手工拼装运行参数，示例配置中的公开占位密钥又可能因长度合格而通过校验。目标是在不引入脚本、不增加配置框架、不调整业务模块的前提下，提供一个 GoLand 可直接运行的后端入口，并让明显错误或不安全的配置在进程启动前失败。

参考成熟 Go 项目的共同做法：保留单一 `cmd` 入口和 `internal` 实现边界，运行配置作为项目文件共享，配置错误尽早返回且错误消息不回显敏感值。目录只在存在真实职责时调整，不机械复制模板仓库。

## 2. 范围

- 共享一个 GoLand `Go Application` 的 DIRECTORY 运行配置，运行目录固定为 `cmd/hotkey`，工作目录固定为 Server 仓库根目录。
- 提供中文注释的 `.env.example`；认证密钥默认留空，不提供能通过校验的公开默认值。
- `HOTKEY_ENV` 只接受 `development`、`testing`、`production`。
- JWT 与认证 HMAC 除长度外，还必须拒绝仓库公开过的三个占位值：`change-me-with-at-least-32-characters`、`replace-with-your-random-secret-at-least-32-bytes`、`replace-with-another-random-secret-32-bytes`；错误不得包含密钥内容。
- CORS 每一项必须是完整的 `http` 或 `https` origin，不允许用户信息、路径、查询参数或片段。
- 邮件启用时校验主机、1–65535 端口、`tls`/`starttls` 模式、发件地址以及用户名/密码成对出现；该校验适用于 `all`、`api`、`worker` 三种运行角色。
- 增加仓库级 `.editorconfig`，统一 Go、Markdown、YAML/JSON 和 SQL 的基础格式。

## 3. 非目标

- 不通过 `.sh`、Makefile 包装命令或 GoLand Compound 配置启动前端。
- 不迁移现有 `cmd/internal/test/docs/db` 目录，不创建通用 `pkg`、微服务或新配置框架。
- 不改变数据库 Schema、HTTP API、OpenAPI、业务模块或前端启动方式。
- 不把本机真实密码、Token、DSN 或个人绝对路径提交到仓库。

## 4. 验收条件

1. 在 GoLand 中选择共享配置后可用一次 Run/Debug 启动后端，不依赖 shell 文件。
2. 支持的三个环境值通过，其他值在启动前返回只包含字段名的稳定错误。
3. 已知占位密钥、畸形 CORS origin、启用但不完整的 SMTP 配置均被拒绝，错误不泄露配置值。
4. 显式填写的安全开发配置能够通过验证，`.env.example` 不含可直接使用的认证密钥。
5. 配置测试、构建、仓库验证和差异检查通过；需要一次性测试数据库的门禁若环境未提供，必须如实记录为未执行。
6. `db/schema.sql` 与 OpenAPI 零差异。

## 5. 参考依据

- JetBrains GoLand Run/Debug Configuration：项目级共享配置、Directory 类型与工作目录语义。
- `golang-standards/project-layout`：仅作为常见目录经验，不视为官方标准，也不整体复制。
- Ardan Labs Service、ThreeDotsLabs Wild Workouts、Grafana、Gitea 与 Prometheus：验证单入口、内部实现边界和按业务职责组织的真实工程实践。
- Uber Go Style Guide 与 Google Go Style Decisions：错误处理、全局状态、生命周期和可维护性基线。
