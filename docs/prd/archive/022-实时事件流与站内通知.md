# 实时事件流与站内通知

## 用户问题

事件、告警、采集和报告变化已经落库，但用户必须刷新各页面才能发现；当前“通知”页面实际只是发布订阅，铃铛也只表示开放告警。短暂断网、API 重启或多实例切换后没有可恢复的实时游标。

## 产品目标

让已认证用户在不刷新页面的情况下收到角色范围内的关键变化，并在断线后从持久游标补齐；实时通道失败时自动退化为轮询，原业务写入不受影响。

## 角色与用户故事

- 作为 Viewer，我实时看到事件更新、告警与已发布报告，并能回到正式详情核查。
- 作为 Editor，我额外看到采集成功通知，以便继续研判，不接收仅管理员可见的失败诊断。
- 作为 Admin，我能看到采集/报告失败通知和连接降级状态，并通过正式运维页面处理。

## 功能要求

### FR-022-1 持久通知事实

- 原业务事务同步写入 append-only outbox；事件更新、告警触发、报告发布/失败、采集成功/失败具有全局单调 ID 与唯一 dedupe key。
- 通知只保存类型、资源、发生时间、audience 与最小安全展示字段；详情继续由原 API 提供。

### FR-022-2 认证 SSE 与补拉

- Bearer 认证 SSE 按 ID 升序发送当前角色可见通知，支持 `Last-Event-ID` 和 `after_id`。
- JSON 补拉 API 使用同一过滤和 1–100 上限；心跳无业务数据，代理不缓存，连接上限、轮询和心跳可配置。

### FR-022-3 重连与轮询降级

- 客户端按用户保存最新接收 ID，重复帧不重复展示；断线指数退避并从旧 ID 继续。
- 连续连接失败后自动使用 JSON 补拉，显示“轮询中”而不是伪装实时；服务恢复后自动回到 SSE。

### FR-022-4 站内通知体验

- 新消息显示本地化 Toast 和铃铛未读徽标；通知页展示最近消息、时间、类型、传输状态及正式资源链接。
- 打开通知页标记当前消息已读；保留既有报告订阅区域，不把订阅配置当通知。

### FR-022-5 权限与失败隔离

- Viewer 只见 viewer audience；Editor 可见 viewer/editor；Admin 可见全部。采集成功至少 Editor，采集/报告失败仅 Admin。
- 匿名或无效 Token 在读取 outbox 前返回 401；实时连接失败不回滚或阻塞业务事实写入。

## 非功能要求

- PostgreSQL 是唯一通知恢复事实源；不增加 Kafka、Redis Pub/Sub、Socket.io、WebSocket 或进程内事实总线。
- Stream 客户端使用生成 Client 与生成 DTO；页面复用 shadcn/ui/Radix，覆盖 1440px/390px、键盘、焦点、对比度和 axe。
- Repository 容量计划覆盖 1000 条通知与角色过滤；单实例慢连接有明确上限且不无限缓存。

## 非目标

- 不做双向命令、在线状态、浏览器 Push、通知偏好、逐用户复制、长期保留清理或跨模块详情快照。

## 验收标准

- AC-022-1：四类来源事实与通知同事务提交，幂等重放不重复；补拉按全局 ID 稳定有序。
- AC-022-2：SSE Bearer、Last-Event-ID、心跳、断连取消和连接上限正确；断线恢复不漏可见通知且允许客户端幂等去重。
- AC-022-3：Viewer 收不到采集/报告失败与 Admin 诊断，Editor/Admin 层级正确，匿名不进入 Repository。
- AC-022-4：Toast、徽标、通知页、已读与资源链接可用；现有发布订阅功能保持可用。
- AC-022-5：SSE 不可用时轮询继续补拉并明确显示降级；全量门禁及 Admin/Viewer/匿名、桌面/390px、空/错误/降级和 axe 通过。
