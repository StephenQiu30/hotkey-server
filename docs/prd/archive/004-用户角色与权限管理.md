# 用户角色与权限管理

## 用户问题

viewer、editor、admin 角色和管理员用户接口已经存在，账户资料页可显示角色，但缺少完整用户管理工作台。

## 产品目标

以最小权限控制读取、编辑和管理操作，并让管理员能够审计地调整用户状态和角色。

## 范围

- 用户列表、筛选和分页
- 角色与状态调整
- 删除与恢复
- 权限不足状态和审计记录

## 用户故事

- 作为普通用户，我能够看懂当前状态、结果来源和下一步动作。
- 作为编辑者，我能够在权限范围内完成配置或处理任务，并获得明确反馈。
- 作为管理员，我能够治理配置、失败、成本与审计，而不直接修改数据库事实。

## 功能要求

- FR-004-1：角色固定为 viewer、editor、admin；MVP 不引入自定义 RBAC 规则引擎。
- FR-004-2：Transport 执行粗粒度角色门禁，Application 再验证资源动作；前端隐藏不是安全边界。
- FR-004-3：删除用户采用可恢复软删除，禁止操作者删除或降级最后一个可用管理员。
- FR-004-4：角色、禁用、恢复等敏感操作记录 actor、before、after、request_id 和结果。

## 非功能要求

- 所有写操作具备认证、授权、输入校验、幂等或乐观锁保护和审计。
- 列表支持稳定分页；第三方调用具备超时、配额、重试和降级。
- Web 覆盖桌面与移动端，并满足键盘操作、可见焦点和减弱动效。

## 非目标

不使用未授权抓取补齐来源能力，不为本条引入与仓库规范冲突的新基础设施。

## 验收标准

- AC-004-1：viewer 不能调用写接口，editor 不能执行管理员动作
- AC-004-2：最后一个管理员保护有并发测试
- AC-004-3：管理员页面在移动端和键盘操作下可用
