# Hacker-News热门榜单与持续观测

## 用户问题

当前用户只能监控刚出现的 Hacker News 项目，无法直接获取官方热门候选，也无法观察同一热点的 score 和评论数如何变化。事件热度模块因此缺少持续输入，系统尚不能作为可运行的热点事件监控平台。

## 产品目标

管理员可以零密钥接入 Hacker News 官方热门或最佳榜单；系统定时重复观测榜单项目、刷新公开互动指标，并复用现有关键词监控、事件聚类、趋势、告警和通知能力。

## 功能要求

- FR-031-1：HN 来源支持 `new`、`top`、`best` 三种受控模式，历史配置缺失时使用 `new`，新建 UI 默认 `top`。
- FR-031-2：`top`/`best` 每轮读取对应官方 ID 列表，去重、限量并保持官方顺序。
- FR-031-3：榜单项目每轮重复返回，使既有 Content Upsert 刷新 score/comment 并追加指标快照。
- FR-031-4：榜单部分失败保留成功项目与安全诊断，全部失败不产生伪成功；健康探测检查实际模式端点。
- FR-031-5：来源页面说明模式差异，管理 API 与 OpenAPI 能完整读写该配置且不暴露凭据。
- FR-031-6：单轮标准化排空全部 captured-item 页；HN 未提供语言/地区时不因未知元数据误拒绝相关内容。

## 用户故事

- 作为管理员，我能在新增 HN 来源时选择热门、最佳或最新模式，不需要配置密钥或任意 URL。
- 作为运营人员，我能让监控主题持续匹配官方热门项目，而非只看到新 ID。
- 作为分析人员，我能在内容和事件中看到持续刷新的互动指标，供现有热度和趋势判断使用。

## 非功能要求

- 只调用 HN 官方 HTTPS API，单轮 item 并发不超过 4，响应取消、超时和上游限流。
- 不增加新的调度器、队列或重复表；保持历史来源与 `new` checkpoint 兼容。
- 前后端、OpenAPI、数据库约束和浏览器流程具有自动化回归。

## 验收标准

- AC-031-1：热门与最佳模式访问正确官方列表、保持榜单顺序、受请求上限和 4 worker 并发约束。
- AC-031-2：同一榜单项目连续两轮均被返回，第二轮公开指标可变化；最新项目模式仍不重复读取已完成 ID。
- AC-031-3：真实 HN 热门来源产生 Content 和指标快照，并进入现有监控匹配、事件、趋势与通知流水线；浏览器可完成来源配置并查看结果。
