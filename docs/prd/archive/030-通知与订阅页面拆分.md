# 通知与订阅页面拆分

## 用户目标

用户可以分别查看持续增长的站内通知和长期配置的报告订阅，不再通过滚动一个混合页面寻找另一类信息。

## 功能要求

- FR-030-1：通知页只显示通知页头、实时状态、刷新、通知列表及其空态。
- FR-030-2：订阅页只显示报告订阅页头、新建订阅、列表、分页、错误重试、启停、删除与 Feed 轮换。
- FR-030-3：桌面和移动主导航只提供“订阅”入口；通知统一通过带未读状态的铃铛进入。
- FR-030-4：两个页面保持既有权限、API、加载、错误、空态、焦点与响应式行为。

## 非目标

不修改 Schema、OpenAPI、通知事实、SSE、订阅投递规则、权限或历史审计；不增加通知偏好、浏览器 Push 或新的组件库。

## 验收标准

- AC-030-1：`/dashboard/notifications` 与 `/dashboard/subscriptions` 均为真实独立路由，且不会渲染对方的主标题或业务区域。
- AC-030-2：主导航和移动抽屉均不重复展示通知入口；铃铛与订阅入口分别进入对应独立页面。
- AC-030-3：通知自动已读、订阅错误重试和新建订阅对话框无回归。
- AC-030-4：类型、单测、构建、浏览器桌面/移动检查和视觉 QA 通过。
