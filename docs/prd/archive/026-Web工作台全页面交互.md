# Web工作台全页面交互

## 用户问题

功能页面已经存在，但入口与恢复路径不完整：部分 Viewer 可读页面被藏在管理菜单后，告警无主导航入口，报告通知进入旧重定向页；若 Profile 或订阅请求失败，用户会看到误导性零值或空态。移动端宽表和跨页原生链接也降低键盘与连续操作体验。

## 产品目标

让所有已实现的 MVP 页面组成可发现、可恢复、无死链且响应式可访问的完整工作台，不增加新的后端产品范围。

## 范围

- 八个主产品入口、Profile 与两个 Admin 治理入口
- 删除旧重定向路由并修正全部仓库内终点
- 段级与页面级 loading/empty/error/forbidden、重试和安全降级
- Next.js 客户端导航、三档响应式、宽表键盘滚动与 Radix 焦点管理

## 用户故事

- 作为 Viewer，我能从同一导航到达来源、内容、事件、告警、报告与订阅，不会因为角色而丢失只读入口。
- 作为 Editor，我能连续完成监控、内容研判、告警处理和报告交付，站内链接不会整页刷新或落到旧页面。
- 作为 Admin，我能从账户与移动导航进入用户、配额和审计；请求失败时能安全重试而不误判为空数据。

## 功能要求

- FR-026-1：主导航按概览、监控、来源、内容、事件、告警、报告、通知与订阅排序；Profile 在账户菜单，用户与权限、配额与审计仅 Admin 可见。
- FR-026-2：删除 `topics`/`favorites` 路由与所有引用；报告通知进入报告中心，事件通知使用 `event` 深链。
- FR-026-3：Dashboard 提供共享 loading/error 兜底；Profile、订阅、事件、内容与告警读取失败显示明确错误和可操作重试，不与 empty 混用。
- FR-026-4：所有站内页面跳转使用 Next.js `Link`；外链保持新窗口与 `rel=noreferrer`，同页锚点保持原生链接。
- FR-026-5：所有可能横向滚动的表格具有具名、可聚焦区域；1280px 使用完整主导航，768px/360px 使用 Radix Sheet 并包含 Admin 入口。
- FR-026-6：保持现有 Vercel 式中性令牌与 shadcn/ui/Radix 组件，不引入新 UI、表单或状态依赖。

## 非功能要求

- 不更改既有写操作、分页和业务码；026 只修复前端组合与读取恢复。
- 无新增手写 DTO/API 路径，无 OpenAPI 漂移；页面错误不泄露堆栈、内部地址或响应体。
- 360、768、1280 三档无页面级横向溢出；WCAG 2 A/AA 自动检查 0 violations、0 incomplete，关键焦点路径人工通过。

## 非目标

不新增后端能力、第二套页面、静态 Mock、全局搜索引擎、个性化首页或仅桌面可用交互。

## 验收标准

- AC-026-1：八个主入口与 Admin/Profile 入口均指向真实页面；仓库无 `topics`/`favorites` 页面或链接，旧地址返回 404。
- AC-026-2：Profile、订阅、事件、内容、告警和共享错误边界均可从错误态重试；适用页面 loading/empty/forbidden 证据完整。
- AC-026-3：站内链接使用客户端导航并保留正确事件/报告深链；全局事件搜索可刷新且无死终点。
- AC-026-4：移动 Sheet 包含全部产品入口和角色化 Admin 入口，Escape/焦点循环/触发器恢复通过；宽表可键盘聚焦滚动。
- AC-026-5：Viewer 与 Admin 在 360×800、768×1024、1280×800 完成登录→监控→内容→事件→告警→报告/订阅主路径，无页面横向溢出。
- AC-026-6：前端 OpenAPI、类型、全部单测、生产构建、后端回归、开发/生产 Compose、React 审查与 agent-browser WCAG 全部通过。
