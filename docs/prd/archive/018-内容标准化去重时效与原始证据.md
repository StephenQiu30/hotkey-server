# 内容标准化去重时效与原始证据

## 用户问题

热点监控会反复命中同一来源内容，也会遇到多个独立来源报道同一事实。如果两者使用同一去重语义，系统要么产生噪声，要么丢失多源传播证据。同时，旧内容不应被包装成新热点，未授权、缺失或损坏的原始证据不应被伪装为正文。

## 产品目标

在不增加第二套存储和不抓取原网页的前提下，把授权采集事实转换为统一、幂等、可查证的 Content；让 7 天内内容才可创建新事件候选；让用户能分辨已归档、未捕获与归档不可用。

## 角色与用户故事

- 作为 Viewer，我能阅读经校验的 Markdown 证据，并看到来源、原始链接、发布时间和摘要哈希。
- 作为 Viewer，当证据未捕获或不可读时，我看到真实原因，不会把标题当成正文。
- 作为 Editor，我能从内容列表与证据详情审核标准化结果，不因多 Monitor 命中看到重复正文。
- 作为 Admin，我能删除内容并依赖 tombstone 和证据清理事实重试，不需要直接操作 MinIO。

## 范围

### FR-018-1 统一 Content 与标准化

- 使用已捕获的来源字段归一外部 ID、类型、Unicode 文本、语言、作者、时间、可空指标和 canonical URL。
- 没有标题也没有正文、URL 非 HTTP(S)、类型非法或指标为负数时，单条失败并记录稳定错误码，不阻断同批其他内容。

### FR-018-2 去重与多源证据

- 同 SourceConnection 内按 external ID 幂等 upsert；对不同 external ID 再按 exact canonical URL、exact Content Hash、24 小时内 near text 的顺序决策 duplicate。
- 同一内容被多 Monitor 命中时复用同一 Content 与证据对象，只新增各自的 MonitorMatch 事实。
- 不同 SourceConnection 的同 URL/hash 保留为 active Content，其事件关联由 Event 聚类完成。

### FR-018-3 7 天新事件候选

- Worker 在 relevance 评估完成后以当前 UTC 时间评估 `published_at`。
- 最近 7 天（包含边界）的 active Content 进入现有 cluster 任务；更旧内容不建 cluster 任务，不单独触发 Event、Heat 或 Alert。
- 更旧内容不因新鲜度被删除或 expired，仍可列表与阅读证据。

### FR-018-4 原始证据与 Markdown 阅读

- 来源允许且已提供的正文/摘要在本地清理为 Markdown，按来源 + SHA-256 写入 MinIO；PostgreSQL 保存 MIME、大小、哈希、捕获时间和状态。
- 文档 API 返回 `ready|not_captured|unavailable`。只有 `ready` 返回 Markdown；`unavailable` 返回稳定原因，不返回对象键或内部错误。
- 前端显示归档、未捕获或不可用状态，只在 `ready` 启用打印/保存 PDF。

### FR-018-5 删除与对账

- Editor/Admin 删除内容时先写 tombstone，再将证据标记为 deleted 或 delete_pending；Viewer 无删除入口。
- 删除失败可重试；对账只清理确认无 PostgreSQL 引用的对象。

## 非功能要求

- 不从文档详情发起任何第三方网络抓取；对象读取最大 4 MiB 并验证 MIME、大小与 SHA-256。
- 证据、日志、错误和 HTTP 响应不暴露 MinIO 凭据、内部端点、对象键或第三方 Token。
- 重复采集、并发 Worker 和人工重试保持幂等，单条失败不阻塞同批其他内容。
- 页面在桌面和 390px 移动视口可用，键盘焦点、对比度与 axe 核心规则通过。

## 非目标

- 不实现跨来源 Content 合并、通用语义向量去重、原网页抓取或 OCR。
- 不在本条重写 Event 聚类、告警策略、全文检索或长期保留策略。
- 不因 7 天新鲜度删除 Content 或 MinIO 证据。

## 验收标准

- AC-018-1：标准化输出和 canonical URL 在重放下稳定；同源重复 external ID/URL/hash/near text 不重复生成正文资产，跨 Monitor 命中复用 Content。
- AC-018-2：跨来源同 URL/hash 保留两个 active Content 及各自证据，不使用 Content duplicate 抹去传播事实。
- AC-018-3：7 天边界内容进入 cluster，超时内容仍可查但不建 cluster/heat/alert 任务。
- AC-018-4：经 MIME、大小和 SHA-256 验证的证据才返回 Markdown；未捕获和不可用均返回稳定无正文投影。
- AC-018-5：Viewer 可安全阅读但无删除操作；Editor/Admin 可删除，tombstone、delete_pending/已删除和对账回归通过。
- AC-018-6：后端全量 CI、前端 OpenAPI/typecheck/unit/build、Compose、桌面/移动浏览器、角色门禁和 axe 验收全部通过。
