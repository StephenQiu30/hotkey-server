# 热点事件语义监控与出处正文

## 基线声明

本需求由业务目标和外部标准重新推导，按“尚未实现”定义完整范围，不以仓库历史设计、既有表结构、接口或页面作为需求依据。v1.1 已完成实现前独立审核；后续实现可以复用经重新验证且符合本需求的基础设施，但不能以兼容旧行为为由削弱本需求。

## 用户问题

用户希望输入一个热点监控目标后，系统能够持续发现不同语言、不同表达和不同来源中与目标相关的内容，并把描述同一具体事件的报道聚合起来。仅依靠关键词包含关系会漏掉别名、语义改写和跨语言内容，也会把同一主题下的不同事件混在一起。

搜索、榜单和聚合来源通常只提供标题或摘要，用户无法判断页面展示的是完整正文、Feed 摘要还是搜索片段。将内容直接标记为“可信/不可信”的做法无法由单条内容或模型评分证实；用户真正需要的是可追溯的出处、原文地址、归档正文、证据摘录和多个独立内容起源之间的关系。

## 产品目标

- 用户以自然语言目标、关键词、短语、实体、排除条件和正反例定义可版本化的监控意图。
- 系统使用词法、向量、实体和结构化约束进行混合召回与相关性判断，并解释每个分项和降级状态。
- 系统持续采集官方 API、RSS、Atom 或明确授权 Feed，区分来源记录、发布站原文和正文版本。
- 系统将完整正文、摘要、搜索片段、平台帖子和派生摘要分别标记，并通过安全 Markdown 阅读器展示可归档内容。
- 系统保留同一内容的多个发布观察与版本，识别精确副本、近重复、转载和翻译关系。
- 系统按语义、实体、动作、地点和时间把内容聚合为具体微事件，并可进一步组成长期议题。
- 系统只描述证据覆盖和报道关系，不输出事实真假、可信度百分比或把相关性分数解释为真实性。
- 在线页面通过持久实时事件更新；P2 移动后台提醒使用用户主动订阅的 Web Push，并保留站内通知作为事实源。
- 系统以 Source-owned MinIO raw snapshot 为证据 master，以不可变 DocumentVersion 和 Vault Markdown/plaintext 为可读投影，并能在非空数据库上安全升级、影子运行和回滚。

## 产品原则

1. **关键词是意图入口，不是最终判断。** 监控目标必须能表达 MUST、SHOULD、MUST_NOT、实体、动作、地点、语言、时间和来源范围。
2. **五个维度互不替代。** 相关性、同一事件、热度、证据覆盖和正文完整度分别计算、存储和展示。
3. **出处优先于结论。** 每条可引用内容必须能回到不可变正文版本、来源记录 URL、发布站 URL、时间和内容哈希。
4. **正文状态必须诚实。** 搜索 snippet 不得显示为原文；从官方 API、RSS、Atom 或授权 Feed 载荷中抽取的正文也不得伪装成发布方确认的完整正文。
5. **多来源不等于真实。** 独立来源数量只表示多个内容起源曾作出报道；转载副本不能虚增来源覆盖。
6. **AI 只提供可审计建议。** 扩展词、相关性复核、事件归并、摘要和证据关系均需保存模型与输入版本，失败时回落到复核，不自动给出肯定结论。

## 范围与阶段

### P0：可审计的监控与正文闭环

- 监控意图、不可变版本、人工规则和待审批 AI 扩展候选。
- 官方或授权来源发现、正文归档策略、来源记录与发布站 URL 分离。
- 正文版本、原始证据对象、Markdown 衍生物、完整度和失败原因。
- 版本化 RightsPolicy/Decision、SourceObservation 与 raw snapshot 多对多 locator，以及 PostgreSQL/MinIO/Vault 可恢复状态机。
- 词法、向量、实体混合召回，RRF 融合和接受/复核/忽略决策。
- 异步扩展/预览 run、人工匹配复核、并发与幂等契约。
- Transport、生成 OpenAPI Client，以及内容匹配列表与详情中的来源、正文完整度、版本化归档阅读和原站链接。
- legacy 可信度语义隔离、heat-v2/evidence-state-v2 影子切换和非空库幂等回填。

### P1：内容家族、事件与证据闭环

- 相关性正反反馈、扩展词审批反馈、错误合并/拆分反馈。
- 时间隔离评测集、阈值校准、模型灰度和回放。
- 精确去重、近重复内容家族、转载/翻译谱系和独立内容起源。
- 微事件在线聚类、长期 storyline、事件 merge/split 和热度。
- 带正文定位的原子陈述及 `asserts`、`mentions`、`contradicts`、`corrects`、`withdraws` 关系。
- 事件摘要逐句引用与证据图。
- 事件详情中的来源、摘录、归档正文、原站链接、证据覆盖状态和站内 SSE 更新。

### P2：移动后台交付

- PWA、Service Worker、Web Push、免打扰时段和事件深链；能力必须交付，但每个用户和设备必须主动 opt-in。
- 用户级 Monitor 订阅、通知折叠和失效订阅清理。
- 在现有 PostgreSQL/pgvector、持久任务和单体部署边界内完成索引、并发、限流与容量验证，不改变技术栈。

## 用户故事

- 作为分析人员，我能用“实体 + 动作 + 排除场景 + 正反例”表达监控目标，而不是猜测一组完美关键词。
- 作为运营人员，我能在发布监控前查看真实候选样本、匹配原因和误报风险。
- 作为内容核查人员，我能在事件页直接看到每条报道的发布主体、来源记录、原文地址、发布时间和正文完整度。
- 作为内容核查人员，我能点击证据摘录跳到对应 Markdown 正文位置，并核对归档哈希与采集时间。
- 作为管理人员，我能知道正文因未授权、仅有摘要、上游限流、解析失败或来源撤回而不可用，而不是只看到统一错误。
- 作为事件分析人员，我能区分“两个独立内容起源表达一致”和“十个平台转载同一通讯社稿件”。
- 作为移动用户，我能在主动授权后收到事件告警，点击后进入对应事件证据页。

## 功能要求

### 监控意图

- FR-032-1：监控配置必须版本化；已发布版本不可原地覆盖，任何匹配结果都关联准确版本。
- FR-032-2：监控版本支持自然语言目标、MUST、SHOULD、MUST_NOT、实体及别名、动作、地点、语言、时间、来源范围、正例、反例和告警偏好。
- FR-032-3：AI 扩展只产生带来源、理由、模型版本和输入哈希的待审批候选；未批准候选不得进入来源查询或最终匹配。
- FR-032-4：批准后的扩展词必须实际编译进适用来源查询和词法召回，而不只是用于采集后的提示词。

### 来源、正文与出处

- FR-032-5：每个来源连接公开能力清单，包括轮询/推送、游标、条件请求、更新、删除、正文、许可、限流和分页能力。
- FR-032-6：采集使用 `(source_id, external_id, upstream_version_or_payload_digest)` 幂等；canonical URL 不作为来源记录唯一身份。
- FR-032-7：系统分别保存 `source_record_url`、`canonical_url`、可选 `discussion_url`、采集时间、发布时间、发布主体、作者和版本键。
- FR-032-8：正文记录 `body_origin`、`completeness`、字数、语言、截断、提取质量、解析器版本、内容 SHA-256、归档可用性和失败原因。
- FR-032-9：正文归档动作必须由来源权利策略允许；权利未知或冲突时只保存允许范围内的元数据和链接，不推断正文授权。
- FR-032-10：原始响应作为不可变证据保存在 MinIO，Markdown 和纯文本作为人类可读投影保存在本地 Vault，PostgreSQL 保存两者的版本、引用和哈希；Markdown 必须能从原始快照按转换器版本重建，安全 HTML 在读取时渲染且不作为第二份持久正文。
- FR-032-25：Source 模块必须在响应生命周期内按 RightsDecision 归档 raw EvidenceSnapshot，并通过带 selector/片段哈希的关联表表达一个 snapshot 对多个 observation、一个 observation 对多个 snapshot；任务只传实体 ID。
- FR-032-26：RightsPolicy 和每个 action 的 RightsDecision 必须版本化并保留作用域、优先级、依据、输入摘要和审批人；`fetch`、raw/derived 存储、private display、quote、local embedding、发送外部模型和 retention 分别求值，unknown/冲突默认拒绝。
- FR-032-27：PostgreSQL、MinIO 和 Vault 使用可恢复状态机而非伪分布式事务；对象写入、清单提交、Vault 原子 rename、失败补偿、孤儿宽限期、哈希对账、权利撤回和保留到期均可重入并可审计。

### 相关性、去重与事件

- FR-032-11：词法、向量和结构化规则独立召回并保留各自名次；使用 RRF 等排名融合产生候选，不混用不同原始分数量纲。
- FR-032-12：相关性重排保留语义、词法、标题、正文、实体、动作、地点、语言、来源、时间、正反例和排除条件的分项结果。
- FR-032-13：Embedding 或模型不可用时必须显式标记降级，只使用可用信号，禁止伪造语义分或默认接受。
- FR-032-14：内容去重形成内容家族并保留所有来源观察；关系至少支持精确副本、近重复、转载、翻译、修订和不相关。
- FR-032-15：事件聚类先形成具体微事件，再由微事件组成长期 storyline；同一主题但人物、动作、地点或时间不同的内容不得仅凭主题相似自动合并。
- FR-032-16：每次自动归并、复核、新建、合并和拆分都保存算法版本、分项特征、阈值、候选排名和人工修订记录。

### 证据与阅读

- FR-032-17：每条原子陈述必须关联不可变正文版本、原文摘录、字符位置或文本定位、发布主体、URL、发布时间、采集时间和哈希。
- FR-032-18：证据关系只使用 `asserts`、`attributes_to`、`mentions`、`contradicts`、`corrects`、`withdraws` 或 `unknown`，不得映射为事实真假。
- FR-032-19：证据覆盖状态只显示“暂无可引用正文、一个内容起源有此报道、多个独立内容起源表达一致、存在相反表述、原发布者已更正、原发布者已撤回”。
- FR-032-20：事件详情一次返回安全引用投影，包含出处、双 URL、正文类型、归档状态、摘录定位和哈希；不得暴露对象存储内部键、来源凭据或原始供应商载荷。
- FR-032-21：Markdown 阅读器禁止 raw HTML，限制 URL 协议，默认不加载源站远程图片，并支持从证据摘录跳到正文位置。
- FR-032-28：固定引用必须使用 `document_version_id` 级 Citation/Document API；content 级便利入口必须返回实际版本 ID，ClaimEvidence、ETag 和定位不得随“最新正文”漂移。
- FR-032-29：正文定位必须声明规范化版本和 UTF-8 byte offset，服务端校验字符边界并保存 plaintext→Markdown anchor map；前端不得用 UTF-16 下标自行切分。

### 反馈与通知

- FR-032-22：用户可反馈相关/不相关、同一事件/错误合并、重复/非重复、证据关系错误、摘录错误以及扩展词接受/拒绝。
- FR-032-23：站内通知由持久事件记录驱动，SSE 断线后按事件 ID 回放；实时通道不传输完整正文。
- FR-032-24：Web Push 仅在用户主动授权后启用，支持用户级监控订阅、免打扰、TTL、折叠和事件深链；Push 不是通知事实源。
- FR-032-30：扩展生成和真实样本预览必须是可查询状态的异步 run；草稿更新、审批、发布和人工 match decision 使用资源版本并发控制和 Idempotency-Key，相同键不同输入必须冲突。
- FR-032-31：`review` 匹配必须提供人工接受/拒绝入口，写入新 Override 并保留原自动决策；未决 review 不进入自动聚类或告警。
- FR-032-32：legacy credibility、claim confidence、unverified/corroborated、Radar confirmation/data confidence 在 v2 中只允许隔离回滚读取；heat-v2 不读取信誉权重，evidence-state-v2 只输出报道覆盖枚举和 reason codes。
- FR-032-33：P0 必须交付 Transport、生成 OpenAPI Client、最小监控设置、匹配复核、Citation 和安全 Markdown UI，不能延后到 P1。
- FR-032-34：通知必须区分领域 OutboxEvent、用户级 UserNotification 和渠道 DeliveryAttempt；SSE、邮件和 Push 只向仍有 Monitor 权限的用户投递。

## 非功能要求

- NFR-032-1：可引用证据的出处字段完整率必须为 100%。
- NFR-032-2：自动相关告警在时间隔离测试集上的 Precision 不低于 90%，Recall 不低于 80%；候选 Recall@100 不低于 95%。
- NFR-032-3：近重复 Precision 不低于 99.5%，错误合并率低于 0.5%；事件聚类 Pairwise Precision 不低于 95%。
- NFR-032-4：所有训练、校准和评测按时间切分，同一事件及转载家族不得跨训练集与测试集。
- NFR-032-5：正文与来源内容始终作为不可信数据；模型没有数据库、通知、来源管理或浏览工具权限。
- NFR-032-6：采集遵守来源授权、限流、条件请求、删除/撤回和保留策略，不绕过登录、付费墙、验证码或平台访问限制。
- NFR-032-7：Markdown 页面覆盖桌面与移动布局、键盘操作、正常/空/加载/错误/无权限/仅元数据状态。
- NFR-032-8：每个处理步骤记录 trace、任务、来源、监控、文档版本、事件和模型运行标识；不得在指标标签中放置正文或高基数敏感值。
- NFR-032-9：`backend/db/schema.sql` 是唯一结构事实源；非空库升级必须支持 canonical schema dry-run、显式确认、批次回填、断点重入、影子切换、非破坏回滚和 PostgreSQL/MinIO/Vault 对账，不得创建 migration 目录或第二份 DDL。
- NFR-032-10：Vault 拆分 API/Worker 部署时必须使用同一具备 POSIX rename/locking 语义的受控卷，worker 单写、API 只读；无法证明共享语义时 readiness 失败。
- NFR-032-11：自动决策 profile 必须经过版本化时间隔离评测；关键测试集至少包含 200 正例、200 负例，每个承诺切片至少 50 样本，并报告 95% Wilson 区间；样本不足保持 shadow。
- NFR-032-12：Push endpoint 与订阅密钥加密保存，VAPID 私钥只从环境 Secret 注入；原始响应和日志不得保存 Authorization、Cookie、Set-Cookie 或完整 Prompt。

## 非目标

- 不构建通用互联网爬虫，不绕过来源访问控制，也不因页面公开可访问就推断可存储或再分发。
- 不输出 `true/false`、`is_real`、真假概率、来源信誉分或“AI 已证实”等结论。
- 不让 LLM 直接发布扩展词、直接决定高风险告警、静默合并事件或覆盖人工反馈。
- 不把搜索摘要、AI 摘要、来源载荷中的结构化字段或正文抽取结果一律称为发布方原文。
- 不在首期引入第二套数据库 Schema、独立向量库、Elasticsearch、Kafka、微服务或通用规则引擎。
- 不在本需求中实现开放互联网事实核查、司法级取证、版权授权判断或 C2PA 身份背书。
- 不把回滚窗口内保留的 legacy 字段视为 v2 可用事实，也不从旧 Markdown 对象反推 raw evidence。

## 验收标准

- AC-032-1（P0）：用户发布包含正反例、实体和排除条件的监控后，批准扩展词实际进入查询；候选结果展示词法、向量、规则和融合路径，向量不可用时明确降级。
- AC-032-2（P0）：同一测试事件的 Feed 全文、搜索片段和平台帖子均保留各自来源记录，并分别显示正文类型、发布站地址和归档状态；搜索片段不会显示为完整正文。
- AC-032-3（P1）：相同内容的多个转载形成同一内容家族但保留所有观察记录；来源覆盖按独立内容起源统计。
- AC-032-4（P1）：同一具体发生项的多篇报道进入同一微事件；同一主题下时间或动作不同的 hard negative 不会自动合并。
- AC-032-5（P1）：事件详情直接展示来源、摘录、正文类型、“阅读归档”“访问原文”“查看来源记录”，并能从摘录定位到安全 Markdown。
- AC-032-6（P1）：两个不同内容起源出现相反表述时，页面显示“存在相反表述”，不显示任一方为真或可信度百分比。
- AC-032-7（P0–P1）：被撤回、权利未知、正文缺失、模型不可用、来源限流、MinIO 不可用和 Vault 不可用均进入可区分、可审计的失败或降级状态。
- AC-032-8（P1）：SSE 在断线后按持久事件 ID 回放遗漏通知，并只向有权用户发送安全摘要和深链。
- AC-032-9（P2）：移动端主动订阅后可收到带事件深链的 Web Push，并支持免打扰、TTL、折叠和失效订阅清理。
