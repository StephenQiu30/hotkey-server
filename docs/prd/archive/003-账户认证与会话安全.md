# 账户认证与会话安全

## 用户问题

邮箱验证、注册、登录、刷新、退出、忘记密码、重置密码和修改密码接口及页面已存在。

## 产品目标

让用户在浏览器与 API 中安全完成完整账号生命周期，并在会话过期、跨站请求和凭据泄露场景下可预测地失败。

## 范围

- 注册登录与邮箱验证
- 找回、重置和修改密码
- 会话刷新、撤销和设备退出
- 认证页面全状态交互

## 用户故事

- 作为普通用户，我能够看懂当前状态、结果来源和下一步动作。
- 作为编辑者，我能够在权限范围内完成配置或处理任务，并获得明确反馈。
- 作为管理员，我能够治理配置、失败、成本与审计，而不直接修改数据库事实。

## 功能要求

- FR-003-1：短期 Access Token 与可轮换 Refresh Token 分离；刷新令牌只进入 HttpOnly、Secure、SameSite Cookie。
- FR-003-2：密码使用成熟自适应哈希；邮箱验证码和重置票据只保存 HMAC 摘要并设单次使用与过期时间。
- FR-003-3：刷新与退出校验精确 Origin，认证错误使用统一业务码，不泄露账号是否存在。
- FR-003-4：前端由单一 AuthSession 状态机处理初始化、刷新、过期与安全重定向。

## 非功能要求

- 所有写操作具备认证、授权、输入校验、幂等或乐观锁保护和审计。
- 列表支持稳定分页；第三方调用具备超时、配额、重试和降级。
- Web 覆盖桌面与移动端，并满足键盘操作、可见焦点和减弱动效。

## 非目标

不使用未授权抓取补齐来源能力，不为本条引入与仓库规范冲突的新基础设施。

## 验收标准

- AC-003-1：刷新令牌不可由前端 JavaScript 读取
- AC-003-2：重复验证码、过期票据和重放刷新均被拒绝
- AC-003-3：未认证访问安全返回登录页且保留允许的站内回跳
