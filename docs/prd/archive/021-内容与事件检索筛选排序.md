# 内容与事件检索筛选排序

## 用户问题

用户可从全局导航输入关键词，但当前只在事件页已加载的有限结果中做前端匹配；内容页不能按关键词、来源、时间或 Monitor 查询，事件筛选也无法通过刷新、后退或分享保留。

## 产品目标

让已认证用户使用同一关键词在事件与内容范围间切换，以真实服务端条件定位结果；所有可见查询均可分享、可稳定翻页并解释排序依据。

## 角色与用户故事

- 作为 Viewer，我能按关键词、来源和时间查找 Content，并看到来源、时间、Monitor 相关性与 Event 归属。
- 作为 Viewer，我能按 Monitor、窗口、生命周期、趋势、确认状态和最低热度筛选 Event，并按重要性/热度、动量、来源宽度、时间或相关性排序。
- 作为 Editor/Admin，我得到与 Viewer 相同的安全检索结果，现有治理权限不因搜索参数扩大。

## 功能要求

### FR-021-1 全局关键词与范围

- TopNav 提交关键词进入 Event 搜索；Event/Content 结果页可携带同一个 `q` 切换范围。
- Event 关键词匹配中英文标题与摘要；Content 关键词匹配标题与 excerpt。两者均由服务端执行。
- 输入 300ms 防抖、Enter 立即提交、清除后回到第一页；最大 100 字符。

### FR-021-2 Content 筛选与结果

- 支持来源连接、发布时间起止、Monitor、Match 决定筛选。
- 默认按发布时间倒序；选择 Monitor 后可按最新 Match 的 `final_score` 倒序。
- 每项展示来源、发布时间、相关性/决定（存在时）与当前 Event 归属（存在时）；不暴露 excerpt 或正文。

### FR-021-3 Event 筛选与排序

- 支持 Monitor、1h/6h/24h/7d、生命周期、趋势、确认状态和最低 Heat。
- 支持动量、重要性/热度、来源宽度、最新变化和 Monitor 相关性排序；相关性排序在无 Monitor 时不可用。
- 结果继续展示重要性、趋势、独立来源数与更新时间，并保持 019/020 的研判和治理详情。

### FR-021-4 URL 与游标

- 关键词、筛选、排序和页大小进入 URL；刷新、复制、前进/后退恢复同一查询。
- Content Cursor 绑定 sort 与全部过滤指纹；Radar Cursor 绑定冻结 `as_of` 与全部 Shape。条件变化清空 Cursor，错误 Shape 返回 400。
- 每页最多 100 条；静态数据连续翻页不重复、不遗漏。

### FR-021-5 空态、错误与权限

- 空态显示当前条件并提供清除入口；Content 与 Event 查询失败只影响本结果区。
- 匿名请求在查询用例前返回 401；所有角色只读 active、未删除的安全投影，前端隐藏不是权限边界。

## 非功能要求

- Schema 只增加必要索引，不新增表、外部搜索引擎或重复分数；关键词、来源+时间、相关性排序有容量和查询计划验证。
- OpenAPI、生成 Client、Domain、Repository、Transport 与页面测试同步；统一错误码不包含 SQL 或内部事实。
- 页面使用现有 shadcn/ui/Radix 组合，桌面与 390px 无横向溢出，键盘、焦点、对比度和 axe 通过。

## 非目标

- 不做跨 Content/Event 的混合分数或统一交错列表，不增加全文搜索语言分词、搜索建议服务或历史查询保存。
- 不创建 Content 级重要性分数，不搜索原始正文、对象存储、已删除/重复 Content 或内部审计数据。

## 验收标准

- AC-021-1：Event/Content 关键词、范围切换和清除均调用真实 API，分页结果没有前端二次过滤或排序。
- AC-021-2：Content 来源/时间/Monitor/决定筛选与 latest/relevance 排序正确，展示相关性与 Event 归属；缺失值不显示为 0。
- AC-021-3：Radar 全部筛选和五种排序正确，attention 作为重要性/热度，relevance 必须绑定 Monitor。
- AC-021-4：Content 与 Radar 跨页无重复遗漏；条件变化拒绝旧 Cursor；关键词、筛选、排序和页大小刷新/后退/分享可恢复。
- AC-021-5：认证在 Repository 前生效，查询上限与索引计划通过；全量门禁及 Viewer/Admin/匿名、桌面/390px、加载/空/错误和 axe 通过。
