# 团队协作 PRD

日期：2026-09-17。状态：详细需求草案；承接既定范围 FR-001-024，保持 P2 优先级。本文是独立评审和验收依据，不代表功能已实现。对应 [执行计划](../plans/026-团队协作计划.md) 已建立且为 planned；同编号 Design 与真实 Acceptance 尚未建立。

入口：[逐项 PRD 索引](README.md) · [平台需求总纲](001-热点事件监控平台功能与非功能需求.md) · [鱼皮项目功能研究](../research/001-热点事件监控平台调研.md)。

## 1. 背景、问题与用户价值

多人研究时，共享范围、编辑权和研究记录需要明确。直接把单人工作台公开会暴露连接凭据，也会造成无法归责的修改。

总纲原始要求：在确有多人使用需求后提供共享、只读角色、分派、评论与团队审计。首版不预建企业组织体系。

所有者分享一个事件给只读同事查看证据，允许另一位研究者修改分析，但不希望任何人看到采集会话。

## 2. 目标与成功指标

**BR-026-001：**在确有多人需求后提供最小协作与访问控制，所有共享和修改可撤销、可追踪。

| 指标 | 统计口径 | 目标或判定 |
|---|---|---|
| 角色正确性|角色×操作矩阵的允许/拒绝结果|全部验收组合正确 |
| 撤销有效性|撤权后新请求仍访问内容的次数|0 |
| 审计覆盖|共享、角色改变与协作修改可追溯|100% |

指标用于评审和后续测量，尚未取得运行结果。涉及新增数量、时长和默认值的建议须在实施前冻结；不据此扩大既定平台范围或付费权限。质量目标不以“页面有按钮”替代。

## 3. 范围、优先级与边界

- **本期范围（P2）：**团队成员、显式分享、所有者/编辑/只读角色、协作备注、轻量分派、撤销和审计。
- **明确不包括：**首版默认企业组织体系、匿名公开全部资料、成员共享采集凭据、复杂审批工单。
- **与相邻能力的边界：**个人资料默认私有；协作授权不自动赋予采集连接使用权、导出权或对外通知权。
- **发布条件：**本文件全部适用验收通过，并满足关联质量要求；本文件展开后仍属后续阶段，不因文档已写完自动提升首版优先级。

## 4. 用户流程与关键结果

1. 所有者创建明确协作范围并添加受邀成员。
2. 选择事件/主题及阅读、编辑等权限，展示继承关系。
3. 成员进入共享资料，只看到允许的数据与动作。
4. 编辑者修改分析/备注时保留身份和版本，冲突显式处理。
5. 撤销成员或分享后立即更新读取权限，并处理相关导出和缓存。

完成后用户获得：边界清楚的共享范围、角色权限、协作记录与撤销结果。取消、失败或权限拒绝时，不显示与实际不符的成功结果。

## 5. 输入、配置与信息展示

| 信息项 | 规则与校验 | 默认或展示要求 |
|---|---|---|
| 角色|所有者、编辑者、只读者为初始建议|最小权限默认只读 |
| 分享对象|明确事件/主题及关联证据范围|不默认整库 |
| 额外权限|导出、采集、管理成员单独控制|只读角色均默认禁止 |
| 协作记录|备注、分派、修改版本和操作者|不覆盖来源原文 |

配置变更记录操作者、时间和版本；正在执行的操作绑定启动时的业务规则版本。当前权限、连接停用、删除要求与更严格预算始终优先，不能以旧版本继续越权或超额执行。冲突的输入必须明确拒绝或延期，不能静默修改用户意图。

## 6. 详细需求与业务规则

| 需求 ID | 规则 | 详细行为 | 对应验收 |
|---|---|---|---|
| FR-026-001 | 默认私有 | 未分享资料对其他成员不可见，加入团队不等于访问所有个人数据。 | AC-026-002 |
| FR-026-002 | 角色分离 | 只读可查看授权内容，编辑可在范围内修改研究结果；连接秘密始终不向协作者回显。 | AC-026-003 |
| FR-026-003 | 授权不扩张 | 事件分享需检查关联证据可共享性；不能因链接到其他私有事件而带出全部资料。 | AC-026-004 |
| FR-026-004 | 并发修改 | 检测基于旧版本的修改，要求合并或重新确认，不以最后写入静默覆盖他人研究。 | AC-026-005 |
| FR-026-005 | 撤销传播 | 撤权影响新读取、查询、引用、下载和后台执行；在途不可撤回外部发送有明确记录。 | AC-026-006 |
| FR-026-006 | 审计与责任 | 邀请/分享/角色/修改/分派留痕，可定位操作者；删除成员不抹去必要变更记录。 | AC-026-006 |

**DEC-026-001：**团队能力从显式分享和最小权限开始，与个人连接和资料所有权分离。

以上规则解释 FR-001-024，不重编号或替换总纲条目。后续发现冲突应显式更新总纲及受影响文档，不由某一页面或适配器单独改变语义。

## 7. 状态、异常与权限

| 状态或场景 | 展示与处理 |
|---|---|
| 待接受/已加入|未接受前不开放资料，说明角色范围。 |
| 只读/可编辑|操作入口与实际权限一致，接口也执行校验。 |
| 冲突/已撤销|阻止旧版本覆盖或继续读取，给出可处理提示。 |
| 加载或执行中 | 展示已知阶段和可用操作；未知进度不用虚假百分比，已持久化历史结果可以继续查看。 |
| 无权访问 | 显示稳定的权限提示，不通过错误内容泄露其他使用者的数据或凭据。 |

所有者管理分享与成员；编辑者不能管理凭据或自动扩权；只读者无修改、采集、导出权限，除非显式独立授予。

| 身份 | 访问与操作边界 |
|---|---|
| 资料或配置所有者 | 在本文件范围内处理自己的业务资料与配置；维护职责的动作仍须相应授权。 |
| 获授权维护者 | 仅诊断或维护明确授权的范围，不自动获得业务正文、规则修改或秘密回读权限。 |
| 其他身份 | 默认拒绝；仅在 026 团队协作正式启用且被显式授权后，按实际角色开放对应操作。 |

本项专门权限规则优先约束上述通用边界，后续角色设计不能扩大已有秘密或数据访问权限。

重复点击、刷新页面或网络重试不得重复产生同一业务结果；若本操作是有意新建的一次业务行为，必须有独立标识和清晰的版本/时间范围。

## 9. 验收标准

AC-001-024 是父级验收，本文件第一项完整保留其场景，其余补充边界、异常和业务细节。以下全部是待执行标准，不是已通过记录。

| 验收 ID | 场景 | Given：前提 | When：操作 | Then：可核查结果 |
|---|---|---|---|---|
| AC-026-001 | 总纲场景继承 | 开启共享后只读者打开事件 | 尝试修改监控或读取连接凭据 | 只允许已授权读取，不能修改或读取秘密。 |
| AC-026-002 | 默认私有 | 新成员加入但未分享资料 | 浏览搜索 | 看不到其他个人资料或存在性统计 |
| AC-026-003 | 只读限制 | 用户只读一个事件 | 修改分析或请求导出/秘密 | 按权限拒绝，内容阅读限已授权范围 |
| AC-026-004 | 关联越权 | 共享事件链接私有证据 | 打开关联对象 | 不扩大资料权限，显示不可访问 |
| AC-026-005 | 并发冲突 | 两编辑基于同版本修改 | 后者保存 | 显式冲突或合并，不静默覆盖 |
| AC-026-006 | 撤销与留痕 | 成员有缓存和待执行操作 | 撤销分享 | 后续访问/执行重新判权，审计保留 |

交付证据应包含输入/规则版本、执行记录、实际结果和人工核对结论。界面能力须有真实浏览器证据；运行、恢复与来源能力按相应环境验证，纯文档检查不计作产品验收。
