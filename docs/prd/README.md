# 逐项 PRD 索引

日期：2026-09-17。以下是对 [001 平台需求总纲](001-热点事件监控平台功能与非功能需求.md) 的逐项展开，共 **43 份独立 PRD：27 份功能需求、16 份非功能需求**。全部为 `draft`，用于产品评审；没有将文档完成写成实现或验收通过。

## 阅读与评审方式

1. 先读总纲中的用户场景、产品对象、平台范围与优先级，再按下表打开独立 PRD。
2. 每份文件包含背景与需求、目标及成功指标、范围与非目标、流程、输入规则、详细业务规则、状态与权限、依赖与验证环境、Given–When–Then 验收、追踪关系、风险与待定项。
3. 先评审“要解决什么问题、哪些边界不可省略”，再冻结建议默认值、样本、时效与容量目标。文中的候选数量和时长不是已确认的运行承诺。
4. “依赖或关联 PRD”表示共同约束与信息关系，包含双向关联，不是强制串行施工顺序。具体阻塞关系与实现顺序由后续 Design / Plan 明确。

## 编号和追踪规则

- `001` 保留总体需求与同主题调研；`002` 保留 X 来源专项设计。
- `003—026` 对应 `FR-001-001—FR-001-024`，`027—042` 对应 `NFR-001-001—NFR-001-016`，另有 `043—045` 对应新增 `FR-001-025—FR-001-027`；一项来源需求对应一份独立 PRD。
- 新文档具有独立 `doc_no`；通过 `parent` 和 `source_requirement` 保留父级关系，原始需求 ID 与优先级不变。
- 每份含 1 项业务目标、6 项细化规则、1 项产品决策、6 个验收场景。合计 **258 项细化规则、258 个子文档验收场景**；其中 43 个继承父级场景，215 个补充具体边界与异常。
- 本地 `AC-NNN-001` 完整继承父级场景，但不因此声称覆盖全部新增规则；规则表按实际对应的补充验收编号建立映射。父级 AC 仍保留，不删除或替换。
- 状态、编号台账和文件命名遵守 [正式文档模板](../TEMPLATE.md)；下一个独立交付项编号为 **046**。

## 共同验收基线

总纲第 5 节是 B0 与 Q0 的唯一基线定义；独立 PRD 引用并补充本项验证条件，有冲突时显式修改相关文档，不能各自选择有利口径。

| 基线 | 适用内容 | 必须保留的边界 |
|---|---|---|
| B0 | 自建环境、读取性能、任务执行、容量与恢复 | 总计 4 vCPU / 8 GiB / SSD，10 万作品、50 万评论、100 万快照；10 主题、20 账号和 5 并发读取。记录数据分布与完整负载；不是来源吞吐保证 |
| Q0 | 排序、事件归并及已纳入范围的自动分析 | 至少 200 作品、300 评论、10 事件、20 组检索结果，至少 X 和一个中文来源；人工标注、调参与验收切分、困难样本、短结果与弃判分别报告 |
| 真实来源 | X 及首批国内来源的关键词、账号、评论路径 | 来源条件满足后有限验证；样本回归不能替代真实接入，不能以其他平台替代 X |
| 免费约束 | 核心采集与基础分析 | 不依赖付费订阅、按量数据或云推理；所有请求尝试计预算。开源免费不等于硬件与运维无成本 |
| 证据与权限 | 原文、评论、分析、导出、缓存与备份 | 缺失不填零，部分不冒充完整，删除和撤权传播至派生结果；不能承诺全网覆盖或全量评论 |
