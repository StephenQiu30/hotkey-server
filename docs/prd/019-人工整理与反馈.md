# 人工整理与反馈 PRD

日期：2026-09-17。状态：详细需求草案；承接既定范围 FR-001-017，保持 P0 优先级。本文是独立评审和验收依据，不代表功能已实现。对应 [执行计划](../plans/019-人工整理与反馈计划.md) 已建立且为 planned；同编号 Design 与真实 Acceptance 尚未建立。

入口：[逐项 PRD 索引](README.md) · [平台需求总纲](001-热点事件监控平台功能与非功能需求.md) · [鱼皮项目功能研究](../research/001-热点事件监控平台调研.md)。

## 1. 背景、问题与用户价值

自动匹配和归并难免出错，研究者还需要标记哪些内容值得继续看。没有持久反馈入口，同样的错误会在下一轮反复出现。

总纲原始要求：支持收藏、关注、归档、不相关标记及研究备注；记录误匹配、误归并、分析纠正，修正影响要能解释；人工关注可提高事件采样优先级但不得越过预算。

用户将一条误关联帖子移出事件，给另一条作品添加研究备注，并关注一个低热但值得跟进的事件。

## 2. 目标与成功指标

**BR-019-001：**让用户以可追溯的轻量操作整理研究资料，并将明确纠正稳定应用于后续自动处理。

| 指标 | 统计口径 | 目标或判定 |
|---|---|---|
| 反馈保留率|下轮自动处理仍尊重已确认纠正|100% |
| 操作可追溯率|关联改变有操作者、时间、前后状态|100% |
| 优先级约束|人工关注导致突破预算的次数|0 |

指标用于评审和后续测量，尚未取得运行结果。涉及新增数量、时长和默认值的建议须在实施前冻结；不据此扩大既定平台范围或付费权限。质量目标不以“页面有按钮”替代。

## 3. 范围、优先级与边界

- **本期范围（P0）：**收藏、关注、归档、不相关标记、研究备注、误归并纠正入口、撤销与反馈范围。
- **明确不包括：**复杂工单审批、多人任务分派、永久修改上游原文、以个人判断代表事实结论。
- **与相邻能力的边界：**本模块提供研究者操作入口；事件结构变更由 011 保持一致，调度优先级由 009 控制。
- **发布条件：**本文件全部适用验收通过，并满足关联质量要求；缺失该能力不能用演示或其他功能替代 P0 完成。

## 4. 用户流程与关键结果

1. 在作品或事件上选择收藏、关注、标不相关或备注。
2. 高影响操作预览对关联、分数和报告的影响。
3. 确认后记录范围与理由，应用到当前研究对象。
4. 后续自动任务遵守人工约束，显示受影响派生结果状态。
5. 用户撤销或修改时保留历史并产生新版本。

完成后用户获得：个人研究状态、可编辑备注和不被自动覆盖的纠正记录。取消、失败或权限拒绝时，不显示与实际不符的成功结果。

## 5. 输入、配置与信息展示

| 信息项 | 规则与校验 | 默认或展示要求 |
|---|---|---|
| 操作对象|作品、事件、主题关联分别明确|不能混用对象级与全局操作 |
| 反馈范围|当前主题/当前事件/自己的研究资料|默认最小范围 |
| 备注|建议最多 2,000 字，支持普通文本与引用|默认私有，不作为源事实 |
| 优先关注|提升采样排队意图，不改变来源限额|默认不强制立即重采 |

配置变更记录操作者、时间和版本；正在执行的操作绑定启动时的业务规则版本。当前权限、连接停用、删除要求与更严格预算始终优先，不能以旧版本继续越权或超额执行。冲突的输入必须明确拒绝或延期，不能静默修改用户意图。

## 6. 详细需求与业务规则

| 需求 ID | 规则 | 详细行为 | 对应验收 |
|---|---|---|---|
| FR-019-001 | 收藏与关注 | 收藏用于找回，关注可影响后续采样/提醒；两者不是同义开关。 | AC-019-006 |
| FR-019-002 | 纠正范围 | 标不相关默认只影响当前主题或事件关系，不删除全局作品或其他主题关联。 | AC-019-002 |
| FR-019-003 | 人工优先 | 确认的排除和纠正持久生效，自动处理不得静默覆盖；规则变化提示复核而非直接撤销。 | AC-019-003 |
| FR-019-004 | 影响一致 | 移出后当前事件指标、时间线和分析及时标重算，原始证据仍按权限保留。 | AC-019-004 |
| FR-019-005 | 备注与撤销 | 备注标人工内容；撤销以新操作恢复适用关系，保留原操作记录，不抹去历史。 | AC-019-005 |
| FR-019-006 | 优先级有界 | 关注只调整队列优先级，不能绕过总预算、暂停来源或隐式付费。 | AC-019-006 |

**DEC-019-001：**把人工反馈视为有范围的业务规则和研究记录，不直接改写上游内容。

以上规则解释 FR-001-017，不重编号或替换总纲条目。后续发现冲突应显式更新总纲及受影响文档，不由某一页面或适配器单独改变语义。

## 7. 状态、异常与权限

| 状态或场景 | 展示与处理 |
|---|---|
| 未整理/已收藏/已关注|明确不同效果和生效范围。 |
| 纠正已应用/待重算|显示关联变化和派生结果更新时间。 |
| 冲突/无法撤销|说明后续修改或对象删除导致的限制，提供重新确认入口。 |
| 加载或执行中 | 展示已知阶段和可用操作；未知进度不用虚假百分比，已持久化历史结果可以继续查看。 |
| 无权访问 | 显示稳定的权限提示，不通过错误内容泄露其他使用者的数据或凭据。 |

所有者修改自己的整理状态；共享资料的个人收藏不自动变成团队结论，团队范围修改留待 026。

| 身份 | 访问与操作边界 |
|---|---|
| 资料或配置所有者 | 在本文件范围内处理自己的业务资料与配置；维护职责的动作仍须相应授权。 |
| 获授权维护者 | 仅诊断或维护明确授权的范围，不自动获得业务正文、规则修改或秘密回读权限。 |
| 其他身份 | 默认拒绝；仅在 026 团队协作正式启用且被显式授权后，按实际角色开放对应操作。 |

本项专门权限规则优先约束上述通用边界，后续角色设计不能扩大已有秘密或数据访问权限。

重复点击、刷新页面或网络重试不得重复产生同一业务结果；若本操作是有意新建的一次业务行为，必须有独立标识和清晰的版本/时间范围。

## 9. 验收标准

AC-001-017 是父级验收，本文件第一项完整保留其场景，其余补充边界、异常和业务细节。以下全部是待执行标准，不是已通过记录。

| 验收 ID | 场景 | Given：前提 | When：操作 | Then：可核查结果 |
|---|---|---|---|---|
| AC-019-001 | 总纲场景继承 | 用户移除一条误关联作品并关注另一事件 | 重新查看统计与下一轮计划 | 误关联不再贡献该事件分数，保留修改记录；关注任务仍受来源限额约束。 |
| AC-019-002 | 范围最小 | 同帖属于两个主题 | 在一个主题标不相关 | 仅该关系受影响，另一主题和原帖仍存在 |
| AC-019-003 | 自动重跑 | 人工排除已生效 | 重新执行匹配 | 不静默恢复，修改历史可见 |
| AC-019-004 | 影响重算 | 移出一条高互动作品 | 查看事件与报告 | 统计重算或标过期，不继续当当前结论 |
| AC-019-005 | 撤销留痕 | 曾误标不相关且尚可恢复 | 撤销 | 形成新操作并保留原记录，备注仍标人工 |
| AC-019-006 | 预算优先 | 关注事件但来源已限额 | 请求优先更新 | 任务有界延期，不突破限额 |

交付证据应包含输入/规则版本、执行记录、实际结果和人工核对结论。界面能力须有真实浏览器证据；运行、恢复与来源能力按相应环境验证，纯文档检查不计作产品验收。
