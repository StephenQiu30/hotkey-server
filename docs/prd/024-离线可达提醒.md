# 离线可达提醒 PRD

日期：2026-09-17。状态：详细需求草案；承接既定范围 FR-001-022，保持 P1 优先级。本文是独立评审和验收依据，不代表功能已实现。对应 [执行计划](../plans/024-离线可达提醒计划.md) 已建立且为 planned；同编号 Design 与真实 Acceptance 尚未建立。

入口：[逐项 PRD 索引](README.md) · [平台需求总纲](001-热点事件监控平台功能与非功能需求.md) · [鱼皮项目功能研究](../research/001-热点事件监控平台调研.md)。

## 1. 背景、问题与用户价值

站内通知只在用户打开产品时可见。离线提醒必须处理渠道失败、重复发送和静默时段，不能把服务接收等同用户已经阅读。

总纲原始要求：接入一种可自建或免费使用的通知渠道，具备发送状态、重试、去重、静默和凭据管理；不要求同时集成所有渠道。

用户离开网页后希望由已配置的免费渠道收到重要新事件，同时夜间静默且不会因重试被重复轰炸。

## 2. 目标与成功指标

**BR-024-001：**通过至少一种用户显式启用的免费/自建渠道送出有用提醒，并清楚报告接受、失败和不确定状态。

| 指标 | 统计口径 | 目标或判定 |
|---|---|---|
| 业务通知一致性|外发关联到唯一站内业务通知|100% |
| 发送状态可追踪率|每次尝试有渠道、时间、结果和稳定原因|100% |
| 用户偏好遵守|停用/静默仍新发外部消息次数|0，已在途消息单独说明 |

指标用于评审和后续测量，尚未取得运行结果。涉及新增数量、时长和默认值的建议须在实施前冻结；不据此扩大既定平台范围或付费权限。质量目标不以“页面有按钮”替代。

## 3. 范围、优先级与边界

- **本期范围（P1）：**渠道配置验证、启停、最小消息内容、静默/汇总、发送记录、有界重试和撤销配置。
- **明确不包括：**默认替用户发送任何消息、同时集成所有平台、保证绝对一次送达或用户已读。
- **与相邻能力的边界：**业务提醒来自 017；本模块只负责传输，投递失败不能重新生成事件或重复业务通知。
- **发布条件：**本文件全部适用验收通过，并满足关联质量要求；本文件展开后仍属后续阶段，不因文档已写完自动提升首版优先级。

## 4. 用户流程与关键结果

1. 用户选择部署支持的免费渠道并输入目标和凭据引用。
2. 明确接收对象与测试内容，用户显式触发测试并查看结果。
3. 启用后按站内提醒规则和渠道偏好排队。
4. 发送结果记录为已接受、失败或状态不确定，按策略有界重试。
5. 用户停用/换目标后停止后续发送，历史记录脱敏可查。

完成后用户获得：与站内通知关联的外部发送结果、重试记录与可维护渠道配置。取消、失败或权限拒绝时，不显示与实际不符的成功结果。

## 5. 输入、配置与信息展示

| 信息项 | 规则与校验 | 默认或展示要求 |
|---|---|---|
| 目标与渠道|只允许用户授权的收件地址或受信目标|不从正文自动提取收件人 |
| 消息范围|标题、变化摘要、原事件链接|敏感正文默认不外发 |
| 静默与重试|建议静默期合并摘要，最多 3 次临时失败重试|权限/凭据错误暂停 |
| 连接秘密|加密引用、创建和更新不回显|不同使用者不共享秘密 |

配置变更记录操作者、时间和版本；正在执行的操作绑定启动时的业务规则版本。当前权限、连接停用、删除要求与更严格预算始终优先，不能以旧版本继续越权或超额执行。冲突的输入必须明确拒绝或延期，不能静默修改用户意图。

## 6. 详细需求与业务规则

| 需求 ID | 规则 | 详细行为 | 对应验收 |
|---|---|---|---|
| FR-024-001 | 显式授权 | 配置保存不等于启用，测试和实际发送都有明确用户动作或已保存启用规则。 | AC-024-002 |
| FR-024-002 | 最小内容 | 默认只发变化摘要与需登录的事件链接，不附全部评论、会话或私有原始响应。 | AC-024-003 |
| FR-024-003 | 业务幂等 | 同业务通知保持一个传输关联；若渠道支持幂等键则使用，不能用新业务通知模拟重发。 | AC-024-004 |
| FR-024-004 | 状态真实性 | HTTP/SMTP 接受只标渠道已接受；超时后无法判断时标不确定，不保证接收或已读。 | AC-024-004 |
| FR-024-005 | 重试与静默 | 临时失败有界退避，凭据/权限失败暂停；静默按用户时区处理，汇总不增加新的事件计数。 | AC-024-005 |
| FR-024-006 | 撤销与隔离 | 停用阻止新的发送；在途尝试如无法撤回须明确，目标更换后不能复用旧地址队列而无规则。 | AC-024-006 |

**DEC-024-001：**将送达阶段与业务通知分开，允许明确的不确定状态，不能承诺外部渠道绝对一次投递。

以上规则解释 FR-001-022，不重编号或替换总纲条目。后续发现冲突应显式更新总纲及受影响文档，不由某一页面或适配器单独改变语义。

## 7. 状态、异常与权限

| 状态或场景 | 展示与处理 |
|---|---|
| 未启用/待测试|说明不会发送正式消息。 |
| 已接受/失败/不确定|各阶段独立标记，给出下一步处理。 |
| 静默/停用/凭据失效|保留站内通知，停止未经允许的新发送。 |
| 加载或执行中 | 展示已知阶段和可用操作；未知进度不用虚假百分比，已持久化历史结果可以继续查看。 |
| 无权访问 | 显示稳定的权限提示，不通过错误内容泄露其他使用者的数据或凭据。 |

只有所有者可配置和启用自己的渠道；维护者可停用故障渠道，但不能擅自新增收件人或查看秘密。

| 身份 | 访问与操作边界 |
|---|---|
| 资料或配置所有者 | 在本文件范围内处理自己的业务资料与配置；维护职责的动作仍须相应授权。 |
| 获授权维护者 | 仅诊断或维护明确授权的范围，不自动获得业务正文、规则修改或秘密回读权限。 |
| 其他身份 | 默认拒绝；仅在 026 团队协作正式启用且被显式授权后，按实际角色开放对应操作。 |

本项专门权限规则优先约束上述通用边界，后续角色设计不能扩大已有秘密或数据访问权限。

重复点击、刷新页面或网络重试不得重复产生同一业务结果；若本操作是有意新建的一次业务行为，必须有独立标识和清晰的版本/时间范围。
