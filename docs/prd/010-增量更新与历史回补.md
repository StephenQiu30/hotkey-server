# 增量更新与历史回补 PRD

日期：2026-09-17。状态：详细需求草案；承接既定范围 FR-001-008，保持 P0 优先级。本文是独立评审和验收依据，不代表功能已实现。对应 [执行计划](../plans/010-增量更新与历史回补计划.md) 已建立且为 planned；同编号 Design 与真实 Acceptance 尚未建立。

入口：[逐项 PRD 索引](README.md) · [平台需求总纲](001-热点事件监控平台功能与非功能需求.md) · [鱼皮项目功能研究](../research/001-热点事件监控平台调研.md)。

## 1. 背景、问题与用户价值

重复抓取不能等同于重复保存，补采也不能制造新热点。持续监控还要发现旧作品上的新评论并显式记录未覆盖时间。

总纲原始要求：作品、评论和指标分别增量更新；新回复可落在旧帖下；重叠回看去重，记录漏采时窗；历史回填独立限额，不用补采时间制造新事件。

系统中断两小时后恢复，用户要求补齐缺口，保留旧作品指标变化，且不收到一批伪装成刚发生的历史提醒。

## 2. 目标与成功指标

**BR-010-001：**在有限采样范围内安全更新资料、恢复缺口并避免重复业务效果，诚实表达不能证明的覆盖。

| 指标 | 统计口径 | 目标或判定 |
|---|---|---|
| 幂等结果|相同页重放后的重复作品/评论/通知|0 |
| 缺口可见率|被中断或截断窗口保留可查询记录|100% |
| 补采时间正确性|历史数据被误标为当前新增事件次数|0 |

指标用于评审和后续测量，尚未取得运行结果。涉及新增数量、时长和默认值的建议须在实施前冻结；不据此扩大既定平台范围或付费权限。质量目标不以“页面有按钮”替代。

## 3. 范围、优先级与边界

- **本期范围（P0）：**窗口重叠、作品与评论去重、指标更新、旧帖刷新、断点恢复、有限历史回填和水位管理。
- **明确不包括：**保证搜索全量召回、无限历史回补、把游标当永久有效凭证、恢复已删除资料。
- **与相邻能力的边界：**009 管一次任务状态，本模块管理跨轮次的观察与缺口；原始对象与快照语义依 007。
- **发布条件：**本文件全部适用验收通过，并满足关联质量要求；缺失该能力不能用演示或其他功能替代 P0 完成。

## 4. 用户流程与关键结果

1. 根据最后确认窗口和仍未处理缺口制定新轮次范围。
2. 使用适量重叠窗口取得内容，按原生 ID 幂等合并。
3. 追加新的互动观察与旧帖新回复，保留其真实时间。
4. 窗口按实际终止结果标完成/部分/待回补，不越过未完成缺口。
5. 恢复时优先继续有效游标，失效则从时间窗重扫并去重。

完成后用户获得：可续接的窗口进度、无重复实体的新变化、带原因的历史缺口。取消、失败或权限拒绝时，不显示与实际不符的成功结果。

## 5. 输入、配置与信息展示

| 信息项 | 规则与校验 | 默认或展示要求 |
|---|---|---|
| 观察窗口|起止时间和时区明确，记录查询版本|边界重叠建议 10 分钟，待来源校准 |
| 游标/水位|保存所对应来源、排序、版本和范围|不能跨来源或配置复用 |
| 历史回补|设置起止时间、条数、每日预算|默认不自动无限回补 |
| 活跃对象|作品/评论刷新依据事件关注和活跃度|跟新帖和刷新旧帖分别排队 |

配置变更记录操作者、时间和版本；正在执行的操作绑定启动时的业务规则版本。当前权限、连接停用、删除要求与更严格预算始终优先，不能以旧版本继续越权或超额执行。冲突的输入必须明确拒绝或延期，不能静默修改用户意图。

## 6. 详细需求与业务规则

| 需求 ID | 规则 | 详细行为 | 对应验收 |
|---|---|---|---|
| FR-010-001 | 业务去重 | 作品/评论以来源原生 ID 唯一，刷新不阻止新增发现关系与新快照。 | AC-010-002 |
| FR-010-002 | 窗口确认 | 只有已明确执行完的可见采样窗口推进确认水位；部分窗口保留缺口，执行完成不等于全网覆盖完成。 | AC-010-003 |
| FR-010-003 | 时间语义 | 补采按原始发布时间归档，同时记录本次观测；提醒区分历史回填与真正新增。 | AC-010-004 |
| FR-010-004 | 游标失效 | 过期、乱序或循环游标触发有界重扫/暂停；重扫仍以幂等规则保护数据，不猜测跳页成功。 | AC-010-005 |
| FR-010-005 | 旧帖更新 | 活跃旧作品和已选线程有刷新机制，新增回复与指标增长不依赖发布新帖。 | AC-010-006 |
| FR-010-006 | 删除与公平 | 回补不得复活删除标记的数据；历史任务不得长期占满新内容预算，所有延期范围可见。 | AC-010-006 |

**DEC-010-001：**将执行水位与数据完整性分开，允许重叠采样和安全重放，同时保存不能补齐的缺口。

以上规则解释 FR-001-008，不重编号或替换总纲条目。后续发现冲突应显式更新总纲及受影响文档，不由某一页面或适配器单独改变语义。

## 7. 状态、异常与权限

| 状态或场景 | 展示与处理 |
|---|---|
| 追新/刷新/回补|明确本次类型，历史内容不作为实时新事件。 |
| 缺口待处理|显示时间范围、来源、原因及预算需求。 |
| 游标失效/无法补齐|说明重扫或不可恢复的范围，停止无意义循环。 |
| 加载或执行中 | 展示已知阶段和可用操作；未知进度不用虚假百分比，已持久化历史结果可以继续查看。 |
| 无权访问 | 显示稳定的权限提示，不通过错误内容泄露其他使用者的数据或凭据。 |

所有者可申请自己主题范围的回填，不能藉回填恢复已无权访问或已按要求删除的内容。

| 身份 | 访问与操作边界 |
|---|---|
| 资料或配置所有者 | 在本文件范围内处理自己的业务资料与配置；维护职责的动作仍须相应授权。 |
| 获授权维护者 | 仅诊断或维护明确授权的范围，不自动获得业务正文、规则修改或秘密回读权限。 |
| 其他身份 | 默认拒绝；仅在 026 团队协作正式启用且被显式授权后，按实际角色开放对应操作。 |

本项专门权限规则优先约束上述通用边界，后续角色设计不能扩大已有秘密或数据访问权限。

重复点击、刷新页面或网络重试不得重复产生同一业务结果；若本操作是有意新建的一次业务行为，必须有独立标识和清晰的版本/时间范围。

## 9. 验收标准

AC-001-008 是父级验收，本文件第一项完整保留其场景，其余补充边界、异常和业务细节。以下全部是待执行标准，不是已通过记录。

| 验收 ID | 场景 | Given：前提 | When：操作 | Then：可核查结果 |
|---|---|---|---|---|
| AC-010-001 | 总纲场景继承 | 两轮结果部分重叠，旧帖有新回复，期间任务中断 | 恢复并补采 | 不重复作品/评论/提醒，新增回复可见；未完成窗口保留，不越过缺口宣称完整。 |
| AC-010-002 | 重叠窗口 | 相邻两轮含相同作品与新指标 | 写入第二轮 | 作品不重复但新增有效快照与发现关系 |
| AC-010-003 | 截断水位 | 窗口采到一半即耗尽预算 | 任务结束 | 保留缺口，不推进到未采样尾端 |
| AC-010-004 | 历史补采 | 旧作品今天才入库 | 完成回填 | 发布时间保持原值，通知明确历史而非新发生 |
| AC-010-005 | 失效游标 | 恢复时游标已不可用 | 按窗口重扫 | 有限重试且去重，不跳过未知页报完成 |
| AC-010-006 | 旧回复与删除 | 旧帖新增回复，另一作品已有删除标记 | 增量与回补同时运行 | 新回复可见，删除对象不复活，新任务预算不被回填占尽 |

交付证据应包含输入/规则版本、执行记录、实际结果和人工核对结论。界面能力须有真实浏览器证据；运行、恢复与来源能力按相应环境验证，纯文档检查不计作产品验收。
