# 事件详情与发展时间线 PRD

日期：2026-09-17。状态：详细需求草案；承接既定范围 FR-001-010，保持 P0 优先级。本文是独立评审和验收依据，不代表功能已实现。对应 [执行计划](../plans/012-事件详情与发展时间线计划.md) 已建立且为 planned；同编号 Design 与真实 Acceptance 尚未建立。

入口：[逐项 PRD 索引](README.md) · [平台需求总纲](001-热点事件监控平台功能与非功能需求.md) · [鱼皮项目功能研究](../research/001-热点事件监控平台调研.md)。

## 1. 背景、问题与用户价值

仅有热点列表无法回答事件先后经过、最新进展和哪些信息仍待核实。抓到旧新闻的时间还可能被误当成事件发生时间。

总纲原始要求：展示事件标题、涉及主题、代表作品、平台分布、首次发现和最近实质更新；时间线区分发生/发布/采集时间，支持关注和归档。

研究者打开召回事件，希望看到最初反馈、官方回应和后续处理，同时知道哪些节点来自评论推测。

## 2. 目标与成功指标

**BR-012-001：**提供可核查的事件阅读页，让用户迅速理解进展、来源和当前数据边界。

| 指标 | 统计口径 | 目标或判定 |
|---|---|---|
| 节点溯源率|时间线节点具备至少一个证据或明确人工备注来源|100% |
| 时间误用|把采集时间默认为发生时间的次数|0 |
| 阅读任务完成|用户找到最新进展、原帖和讨论的能力|按 040 核心流程测试 |

指标用于评审和后续测量，尚未取得运行结果。涉及新增数量、时长和默认值的建议须在实施前冻结；不据此扩大既定平台范围或付费权限。质量目标不以“页面有按钮”替代。

## 3. 范围、优先级与边界

- **本期范围（P0）：**事件概要、关键进展时间线、代表作品、平台分布、讨论入口、状态与关注归档。
- **明确不包括：**无证据自动补全经过、将评论多数意见写成事实、复杂项目工单管理。
- **与相邻能力的边界：**事件身份来自 011；本页组织可读信息，热度由 013 解释，评论分析由 015 提供。
- **发布条件：**本文件全部适用验收通过，并满足关联质量要求；缺失该能力不能用演示或其他功能替代 P0 完成。

## 4. 用户流程与关键结果

1. 从主题或提醒进入事件详情，先看到范围、更新时间与摘要。
2. 浏览关键进展，区分原文事实、引用观点和人工注释。
3. 点击节点进入相关作品及讨论上下文。
4. 查看分数、平台样本分布与缺失来源。
5. 关注或归档事件，记录个人研究状态。

完成后用户获得：含来源与时间说明的事件资料页和可追溯发展时间线。取消、失败或权限拒绝时，不显示与实际不符的成功结果。

## 5. 输入、配置与信息展示

| 信息项 | 规则与校验 | 默认或展示要求 |
|---|---|---|
| 事件概要|标题、涉及主体、主题、证据覆盖|未知要素明确未知 |
| 时间节点|优先发生时间；缺失则用发布时间并标类型|采集时间单列 |
| 代表作品|依据相关性、时间和观点差异选取|不只按粉丝量筛选 |
| 当前状态|候选/关注/归档与资料新鲜度分开|归档不代表事件已结束 |

配置变更记录操作者、时间和版本；正在执行的操作绑定启动时的业务规则版本。当前权限、连接停用、删除要求与更严格预算始终优先，不能以旧版本继续越权或超额执行。冲突的输入必须明确拒绝或延期，不能静默修改用户意图。

## 6. 详细需求与业务规则

| 需求 ID | 规则 | 详细行为 | 对应验收 |
|---|---|---|---|
| FR-012-001 | 时间类型 | 发生、发布、观测时间分别存义；仅知道日期则显示日期精度，不虚构小时。 | AC-012-002、AC-012-004 |
| FR-012-002 | 节点证据 | 每项实质进展引用可核对作品；用户备注标人工判断，不冒充来源事实。 | AC-012-003 |
| FR-012-003 | 实质更新 | 新增回应或处理结果可改变最近进展；重复转载、补采旧闻、指标刷新不自动变成新进展。 | AC-012-004 |
| FR-012-004 | 观点区分 | 摘要标事实、指控/推测、作者观点和系统归纳；相互矛盾材料并列呈现而不强行裁决。 | AC-012-003 |
| FR-012-005 | 分布口径 | 平台分布为已采样作品/讨论分布，不表达全网声量；来源缺失和样本量同屏可见。 | AC-012-005 |
| FR-012-006 | 归档行为 | 归档停止该事件额外优先采样与提醒，主题监控仍可发现新进展；重新关注行为明确。 | AC-012-006 |

**DEC-012-001：**时间线以有证据的进展组织，区分事件实际发展与系统发现时间。

以上规则解释 FR-001-010，不重编号或替换总纲条目。后续发现冲突应显式更新总纲及受影响文档，不由某一页面或适配器单独改变语义。

## 7. 状态、异常与权限

| 状态或场景 | 展示与处理 |
|---|---|
| 资料充足|概要、进展、分数、作品和讨论可顺序浏览。 |
| 资料不足/来源冲突|缺失要素或冲突明确标注，仍可查看已有原文。 |
| 过期/归档|显示最后成功时间和归档状态，不用旧页面伪装实时。 |
| 加载或执行中 | 展示已知阶段和可用操作；未知进度不用虚假百分比，已持久化历史结果可以继续查看。 |
| 无权访问 | 显示稳定的权限提示，不通过错误内容泄露其他使用者的数据或凭据。 |

所有者可修改标题和研究备注；原始引用不能被直接覆盖，修改应保留记录。

| 身份 | 访问与操作边界 |
|---|---|
| 资料或配置所有者 | 在本文件范围内处理自己的业务资料与配置；维护职责的动作仍须相应授权。 |
| 获授权维护者 | 仅诊断或维护明确授权的范围，不自动获得业务正文、规则修改或秘密回读权限。 |
| 其他身份 | 默认拒绝；仅在 026 团队协作正式启用且被显式授权后，按实际角色开放对应操作。 |

本项专门权限规则优先约束上述通用边界，后续角色设计不能扩大已有秘密或数据访问权限。

重复点击、刷新页面或网络重试不得重复产生同一业务结果；若本操作是有意新建的一次业务行为，必须有独立标识和清晰的版本/时间范围。

## 9. 验收标准

AC-001-010 是父级验收，本文件第一项完整保留其场景，其余补充边界、异常和业务细节。以下全部是待执行标准，不是已通过记录。

| 验收 ID | 场景 | Given：前提 | When：操作 | Then：可核查结果 |
|---|---|---|---|---|
| AC-012-001 | 总纲场景继承 | 旧新闻今天被补采，新回应今天发布 | 查看事件时间线 | 旧新闻按原发布时间展示，新回应可识别；不能把今天采到当作今天发生。 |
| AC-012-002 | 时间精度 | 只知道事件发生日期 | 展示节点 | 只显示日期和来源，不补造时分 |
| AC-012-003 | 观点与事实 | 评论指控与官方回应矛盾 | 查看概要 | 分别标注说法及证据，不写为已证实结论 |
| AC-012-004 | 旧闻补采 | 昨天的报道今天采到 | 更新时间线 | 按原发布时间放置，不提升为今天发生 |
| AC-012-005 | 平台分布 | 只接入两个来源 | 查看讨论分布 | 标为已采样分布，并提示其他来源未覆盖 |
| AC-012-006 | 归档后进展 | 归档事件被主题发现新回应 | 查看记录 | 主题资料可更新，额外提醒按归档规则抑制并可重新关注 |

交付证据应包含输入/规则版本、执行记录、实际结果和人工核对结论。界面能力须有真实浏览器证据；运行、恢复与来源能力按相应环境验证，纯文档检查不计作产品验收。
