# 报告与知识库需求

本文从 [总需求 001 v5.0](001-热点舆情监控平台需求.md) 保留的 PRD 001 v3.0 基线按 M4 拆出，现与 [Design 005](../design/005-报告与知识库设计.md) 对齐；[Plan 005](../plan/005-报告与知识库计划.md) 已按同号里程碑迁入 `docs/plan/`。需求状态 `approved` 不表示产品验收通过。

## 1. 目标与范围

**目标**：研究者分别阅读日报、周报及其原帖引用，在现有 Obsidian vault 浏览、检索、提问并核对出处。

**不包含**：把报告生成等同于 Obsidian 写入或推送送达；未通过 M3 时添加事件结论；未验收来源的数据。

## 2. 用户场景与状态

- 在设定时间查看前一自然日日报或上周周报，打开原帖引用并核对数字、覆盖缺口与模板降级标记。
- 在现有 vault 的 `HotKey/` 浏览分阶段导出的日报、事件、精选帖子、周报及主题笔记；重导出后核对用户区块和双链。
- 通过 Web 或 CLI 提问，在答案中打开逐句出处；资料不足时看到明确说明，并核对问答笔记写入状态。

权限沿用总需求的单 owner 登录；加载及权限不足沿用现有界面和权限契约。以上场景按本里程碑 FR/AC 与总需求 NFR 核对。

## 3. 业务需求

| ID | 业务需求 | 成功判断 |
|---|---|---|
| BR-005-001 | 判断内容是否相关并逐步整理观点、事件 | 相关内容的情感、摘要和观点可抽检；事件能力通过后用于后续报告。 |
| BR-005-002 | 提供可追溯的日报和周报 | 报告分别生成、存档与核对；数字由程序计算，引用可打开；送达另验 |
| BR-005-003 | 沉淀可浏览、可提问的本地知识库 | 按阶段向现有 Obsidian vault 的 `HotKey/` 写入报告、事件、主题和精选帖子；问答有出处 |

## 4. 功能需求

| ID | 功能 | 要求 |
|---|---|---|
| FR-005-001 | 报告时间配置 | 报告时间在报告结果启用时配置。 |
| FR-005-002 | 摘要与情感 | 对相关帖子提供一句话摘要、正/中/负情感；评论按帖子批量判断情感并汇总主要观点，质量另行人工抽检。已有分析代码与开发运行记录不等于质量验收 |
| FR-005-003 | 日报生成 | 默认 09:00 Asia/Shanghai 按前一自然日生成日报；先冻结输入，再由程序取数、模型可选润色；模型失败生成标注“模板版”的存档报告，送达另验 |
| FR-005-004 | 报告存档 | 日报、周报按主题和时间窗保存版本、覆盖说明与引用；Web 可查看。Obsidian 导出另验 |
| FR-005-005 | 周报生成 | 每周一 09:00 Asia/Shanghai 按上一 ISO 周（上周一 00:00 至本周一 00:00，即上周日 24:00）冻结输入并生成周报；程序计算的周内数字与该周已存档日报按同一口径的合计一致，保存引用与覆盖说明。渠道送达另验，推送暂缓不阻断 M4 验收 |
| FR-005-006 | Obsidian 知识库 | 只写现有 vault `~/Desktop/Markdown/Obsidian` 的 `HotKey/`：先日报；事件及被报告或事件引用的精选帖子在事件能力上线后导出；周报和主题笔记后续加入。笔记带 frontmatter，先有目标笔记再补双链，保留用户“我的笔记”区块 |
| FR-005-007 | 知识库问答 | Web 或 CLI 提问；用已采资料检索，由 Codex 回答并逐句标出处及资料时间范围；不足则明说不足，结果写入 `HotKey/问答/` |

### 报告内容与引用

| 报告 | 内容与时间依据 |
|---|---|
| 日报 | 概览与前日比较、重点内容 Top 10、风险与代表观点、各来源覆盖与缺口；M3 事件能力通过后可增加事件区块。按发布时间入窗；缺发布时间者按首次发现时间计并单列条数，注明“样本观察，不代表全网” |
| 周报 | 周内趋势与上周比较、Top 事件和时间线、持续与平息、观点变化、下周关注、覆盖说明；引用事件热度时附公式版本和计算口径，不能把不完整窗口当全量趋势 |

日报在精选帖子笔记不存在时只链接原帖；已存在笔记可附链接。精选帖子笔记成功导出后才补 Obsidian 双链，避免悬空引用。报告、知识库写入和渠道送达分别给出成功或失败状态。

## 6. 验收标准与退出条件

**证据门槛**：表中列出的等级须分别具备。受控测试验证状态机、边界与故障；真实运行验证实际来源、外部依赖和持久结果；产品验收按本条样本、连续窗口或用户核对口径作结论。低一级证据不能替代高一级；“代码已合入”本身不属于通过证据。

**退出条件**：分析质量、日报、周报、vault 导出和问答各按自己的 AC 独立通过。受控测试、真实运行与产品验收分层记录；一项结果不替代另一项。
