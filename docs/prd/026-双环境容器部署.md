# 双环境容器部署

## 范围

- 新增非 root、多阶段构建的 Server `Dockerfile` 与最小 `.dockerignore`。
- 新增 `docker-compose-env.yml` 和 `docker-compose-prod.yml`，分别固定项目名、镜像标签和运行环境。
- Compose 提供 PostgreSQL/pgvector、Redis、MinIO、幂等数据库初始化、幂等 Bucket 初始化和 Server 健康检查。
- 新增 `.env.prod.example`，同步中英文 README 与仓库规范。
- 精简 `.env.example` 与 `.env.prod.example`：默认能力不重复配置，可选能力保持注释，生产只需填写 6 个空值。

## 验收条件

1. 两份 Compose 文件均可通过 `docker compose config`，且不存在通用 `docker-compose.yml`。
2. 日常与生产项目名、镜像标签、`HOTKEY_ENV` 和端口暴露策略明确不同。
3. Server 构建与运行基础镜像以及 Redis、MinIO/MC 使用 `latest`，pgvector 使用官方浮动 `pg16`；Server 非 root 运行并包含 CA、时区和健康检查工具。
4. 空数据库可初始化，已有兼容数据库只验证，非空不兼容数据库失败，并发初始化最终收敛；MinIO Bucket 重复初始化安全。
5. 两个环境可同时启动并通过 `/readyz`；生产命令使用原生 `--env-file .env.prod`，只有 Server 读取完整配置，基础设施只接收必要变量；配置文件缺失或 6 个必要值为空时须明确失败。
6. 生产 PostgreSQL、Redis、MinIO 和 MinIO Console 不发布宿主机端口；Server 具备 30 秒关闭宽限。
7. 完整 `make test`、Lint、构建、架构和仓库门禁通过；Schema 与 OpenAPI 零差异。

## 非目标

- 不修改业务代码、Schema、记录模型或公共 API。
- 不自动生成生产密钥，不提供公网 TLS 和备份恢复。
- 不新增启动脚本、Makefile 目标或额外部署抽象。
