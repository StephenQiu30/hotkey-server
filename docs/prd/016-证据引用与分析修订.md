# 证据引用与分析修订 PRD

日期：2026-09-17。状态：详细需求草案；承接既定范围 FR-001-014，保持 P0 优先级。本文是独立评审和验收依据，不代表功能已实现。对应 [执行计划](../plans/016-证据引用与分析修订计划.md) 已建立且为 planned；同编号 Design 与真实 Acceptance 尚未建立。

入口：[逐项 PRD 索引](README.md) · [平台需求总纲](001-热点事件监控平台功能与非功能需求.md) · [鱼皮项目功能研究](../research/001-热点事件监控平台调研.md)。

## 1. 背景、问题与用户价值

一段看似完整的摘要如果找不到依据，就无法用于研究。来源编辑、删除或事件拆分后，旧结论也需要被识别为过期。

总纲原始要求：每项观点/摘要可回到作品、评论及上下文；保存分析输入范围、时间和方法版本；支持人工纠正、重算、旧版标记过期。

用户对“退款诉求上升”提出疑问，希望看到使用了哪些评论、怎样计算，以及后来数据删除是否影响结论。

## 2. 目标与成功指标

**BR-016-001：**为每条关键结论建立可核对的证据链和修订历史，使来源变化不会产生无提示的失真报告。

| 指标 | 统计口径 | 目标或判定 |
|---|---|---|
| 结论可追溯率|有效结论可定位输入范围与具体证据|100% |
| 失效提示覆盖率|证据删除/事件调整影响的结论被标记|100% |
| 修订留痕率|人工修改有前后版本、操作者和原因|100% |

指标用于评审和后续测量，尚未取得运行结果。涉及新增数量、时长和默认值的建议须在实施前冻结；不据此扩大既定平台范围或付费权限。质量目标不以“页面有按钮”替代。

## 3. 范围、优先级与边界

- **本期范围（P0）：**作品/评论引用、上下文跳转、分析输入清单、方法版本、修订、重算、证据失效和报告引用状态。
- **明确不包括：**保留无权保留的原文、因摘要存在而推断原文、将外链永久可用作为保证。
- **与相邻能力的边界：**引用管理不负责判断事实真伪；源数据生命周期由 036 决定，分析业务由 015/022 产生。
- **发布条件：**本文件全部适用验收通过，并满足关联质量要求；缺失该能力不能用演示或其他功能替代 P0 完成。

## 4. 用户流程与关键结果

1. 生成分析时绑定输入快照和具体引用。
2. 用户从结论打开引用、上下文、采集时间与原文链接。
3. 用户纠正结论或标签，填写理由并生成新版本。
4. 来源编辑/删除或事件关系变化触发影响标记。
5. 重新分析并发布新版本，旧报告显示其生成时范围和当前有效性。

完成后用户获得：结论到原文的引用关系、方法版本和可比较的修订记录。取消、失败或权限拒绝时，不显示与实际不符的成功结果。

## 5. 输入、配置与信息展示

| 信息项 | 规则与校验 | 默认或展示要求 |
|---|---|---|
| 引用目标|作品/评论身份、内容版本、引用片段范围|缺失目标不能伪造可用引用 |
| 分析清单|样本 IDs、窗口、筛选与方法/模型版本|每次分析固定 |
| 人工修订|原文、修改后结果、原因、操作者和时间|保留只读旧版本 |
| 有效性|有效、部分失效、待重算、已替代|状态变化可追踪 |

配置变更记录操作者、时间和版本；正在执行的操作绑定启动时的业务规则版本。当前权限、连接停用、删除要求与更严格预算始终优先，不能以旧版本继续越权或超额执行。冲突的输入必须明确拒绝或延期，不能静默修改用户意图。

## 6. 详细需求与业务规则

| 需求 ID | 规则 | 详细行为 | 对应验收 |
|---|---|---|---|
| FR-016-001 | 引用精度 | 关键结论关联具体评论或作品片段，不仅链接整个事件或网站首页。 | AC-016-002 |
| FR-016-002 | 可复现范围 | 保留样本清单和计算规则；非确定性生成记录输入与输出，不能承诺逐字重现。 | AC-016-003 |
| FR-016-003 | 修订版本 | 人工修改不覆盖旧产物，记录差异与原因；重新生成不得覆盖已确认人工意见而无提示。 | AC-016-004 |
| FR-016-004 | 变更传播 | 来源删除、正文编辑、权限变化或事件拆分能定位受影响结论，标过期/失效并限制再次导出旧敏感内容。 | AC-016-005 |
| FR-016-005 | 缺失处理 | 失效引用显示标识和原因，只保留允许保留的信息，不从缓存补回已要求删除的正文。 | AC-016-005 |
| FR-016-006 | 发布与替代 | 新版本需明确当前版本关系；旧链接能看到已替代说明，不能把生成时间悄悄更新为现在。 | AC-016-006 |

**DEC-016-001：**保留版本和证据关系，以失效标记与新版本替代掩盖式覆盖。

以上规则解释 FR-001-014，不重编号或替换总纲条目。后续发现冲突应显式更新总纲及受影响文档，不由某一页面或适配器单独改变语义。

## 7. 状态、异常与权限

| 状态或场景 | 展示与处理 |
|---|---|
| 证据可用|打开时显示原文与引用片段上下文。 |
| 证据失效/无权|解释失效原因，停止展示不应继续保留的内容。 |
| 待重算/已替代|旧结论有明确标记，可跳到有权访问的新版本。 |
| 加载或执行中 | 展示已知阶段和可用操作；未知进度不用虚假百分比，已持久化历史结果可以继续查看。 |
| 无权访问 | 显示稳定的权限提示，不通过错误内容泄露其他使用者的数据或凭据。 |

所有者可修订自己的分析；维护者不能通过诊断接口读取无权评论，撤权立即影响引用读取。

| 身份 | 访问与操作边界 |
|---|---|
| 资料或配置所有者 | 在本文件范围内处理自己的业务资料与配置；维护职责的动作仍须相应授权。 |
| 获授权维护者 | 仅诊断或维护明确授权的范围，不自动获得业务正文、规则修改或秘密回读权限。 |
| 其他身份 | 默认拒绝；仅在 026 团队协作正式启用且被显式授权后，按实际角色开放对应操作。 |

本项专门权限规则优先约束上述通用边界，后续角色设计不能扩大已有秘密或数据访问权限。

重复点击、刷新页面或网络重试不得重复产生同一业务结果；若本操作是有意新建的一次业务行为，必须有独立标识和清晰的版本/时间范围。

## 9. 验收标准

AC-001-014 是父级验收，本文件第一项完整保留其场景，其余补充边界、异常和业务细节。以下全部是待执行标准，不是已通过记录。

| 验收 ID | 场景 | Given：前提 | When：操作 | Then：可核查结果 |
|---|---|---|---|---|
| AC-016-001 | 总纲场景继承 | 某结论引用的评论被删除或事件被拆分 | 查看并刷新分析 | 原结论提示证据变化/过期，新分析生成新版本；不捏造缺失原文。 |
| AC-016-002 | 精确引用 | 结论引用多个回复中的一句话 | 点击证据 | 定位具体评论和父链，而非仅跳事件首页 |
| AC-016-003 | 生成复查 | 固定样本和方法版本 | 查看分析记录 | 输入清单与规则可得，非确定性输出单独记录 |
| AC-016-004 | 人工修改 | 用户已确认一项纠正 | 重新生成分析 | 新旧版本并存，不静默覆盖纠正 |
| AC-016-005 | 证据删除 | 被引用原文按要求删除 | 打开旧报告并导出 | 明确失效并不泄漏已删除正文 |
| AC-016-006 | 替代版本 | 新版分析已发布 | 访问旧链接 | 显示旧生成时间、已替代状态和新版本入口 |

交付证据应包含输入/规则版本、执行记录、实际结果和人工核对结论。界面能力须有真实浏览器证据；运行、恢复与来源能力按相应环境验证，纯文档检查不计作产品验收。
