# 监控主题管理 PRD

日期：2026-09-17。状态：详细需求草案；承接既定范围 FR-001-001，保持 P0 优先级。本文是独立评审和验收依据，不代表功能已实现。对应 [执行计划](../plans/003-监控主题管理计划.md) 已建立且为 planned；同编号 Design 与真实 Acceptance 尚未建立。

入口：[逐项 PRD 索引](README.md) · [平台需求总纲](001-热点事件监控平台功能与非功能需求.md) · [鱼皮项目功能研究](../research/001-热点事件监控平台调研.md)。

## 1. 背景、问题与用户价值

用户关心的是一个持续研究的主题，而不是每次重输一串搜索词。规则不明确会造成漏采、误匹配和无法解释的历史结果。

总纲原始要求：创建、编辑、复制、暂停和归档主题；设置关键词/别名、任意命中/全部包含/排除、平台、语言、时间窗、频率与预算；保留规则版本。

研究者建立“某品牌召回”主题，同时排除招聘信息，希望规则改变后新采集按新规则执行，历史资料仍可复查。

## 2. 目标与成功指标

**BR-003-001：**让用户在可理解的规则范围内建立、控制并复用监控主题，避免修改设置产生隐性历史重采。

| 指标 | 统计口径 | 目标或判定 |
|---|---|---|
| 配置保存成功率|合法配置保存并可重新打开的次数/有效尝试|验收样本全部成功，失败有明确原因 |
| 规则可解释率|抽检作品能找到命中的规则版本|100% |
| 停用正确性|暂停生效后新生成的周期任务数|0，已运行任务另行展示 |

指标用于评审和后续测量，尚未取得运行结果。涉及新增数量、时长和默认值的建议须在实施前冻结；不据此扩大既定平台范围或付费权限。质量目标不以“页面有按钮”替代。

## 3. 范围、优先级与边界

- **本期范围（P0）：**主题创建、编辑、复制、启停、归档，关键词逻辑、平台和频率配置、规则版本。
- **明确不包括：**复杂正则语言、自动花费资源扩词、默认回溯全部历史、删除全局共有作品。
- **与相邻能力的边界：**主题表达关注规则；关注某个用户由 006 管理，事件归并由 011 管理。
- **发布条件：**本文件全部适用验收通过，并满足关联质量要求；缺失该能力不能用演示或其他功能替代 P0 完成。

## 4. 用户流程与关键结果

1. 填写主题名与关键词，选择平台和语言。
2. 预览“任意命中/全部包含/排除”含义，查看来源能力。
3. 选择频率与采集预算，保存配置；保存本身不触发外部探测。
4. 显式启动或执行一次采集，查看任务和命中说明。
5. 编辑生成新规则版本；暂停、归档或复制时展示影响范围。

完成后用户获得：可启停的主题、版本化配置以及对应的任务与结果入口。取消、失败或权限拒绝时，不显示与实际不符的成功结果。

## 5. 输入、配置与信息展示

| 信息项 | 规则与校验 | 默认或展示要求 |
|---|---|---|
| 主题名称|去除首尾空白后必填，建议 1–80 字|重名允许但需显示创建时间 |
| 关键词组|至少一个包含词；每类建议最多 50 项、单项 100 字|重复词规范化；排除优先 |
| 来源与语言|至少一个目标平台；不支持的能力明确提示|不自动勾选所有来源 |
| 频率与回溯|需正数且满足来源预算；回溯独立配置|建议首次 7 天、周期 60 分钟，待来源验证 |

配置变更记录操作者、时间和版本；正在执行的操作绑定启动时的业务规则版本。当前权限、连接停用、删除要求与更严格预算始终优先，不能以旧版本继续越权或超额执行。冲突的输入必须明确拒绝或延期，不能静默修改用户意图。

## 6. 详细需求与业务规则

| 需求 ID | 规则 | 详细行为 | 对应验收 |
|---|---|---|---|
| FR-003-001 | 组合语义 | 同一任意组为 OR，全部组为 AND，排除词命中即剔除；分组为空时不制造总是命中的规则。 | AC-003-002 |
| FR-003-002 | 规则版本 | 任何影响检索/筛选/采样的修改生成版本；正在运行任务继续使用启动版本，后续任务用新版本。 | AC-003-003、AC-003-006 |
| FR-003-003 | 复制与去重 | 复制得到新的主题身份和默认暂停状态；内容可复用实体，但保留独立命中关系，不复制旧任务。 | AC-003-004 |
| FR-003-004 | 生命周期 | 暂停阻止后续调度，已运行任务可单独取消；归档保留历史并停止调度；删除范围交给数据设置流程。 | AC-003-005 |
| FR-003-005 | 预览边界 | 配置预览说明逻辑和预期能力，不真实采集；尚未连通的来源可保存为待就绪配置。 | AC-003-002 |
| FR-003-006 | 扩词控制 | 别名在本地匹配或用于上游检索必须可区分；启用新的上游扩词时展示查询与预算影响，保存后才生效。 | AC-003-006 |

**DEC-003-001：**把主题保存、规则版本和开始采集三个行为分开，使用户能预测每次操作的范围。

以上规则解释 FR-001-001，不重编号或替换总纲条目。后续发现冲突应显式更新总纲及受影响文档，不由某一页面或适配器单独改变语义。

## 7. 状态、异常与权限

| 状态或场景 | 展示与处理 |
|---|---|
| 正常|显示运行/暂停/归档及当前版本，历史结果标对应版本。 |
| 无匹配|显示规则、成功检查的来源与范围，允许调整但不自动放宽排除词。 |
| 配置无效或来源待就绪|定位具体字段；可保存待就绪主题，但启动时明确阻塞能力。 |
| 加载或执行中 | 展示已知阶段和可用操作；未知进度不用虚假百分比，已持久化历史结果可以继续查看。 |
| 无权访问 | 显示稳定的权限提示，不通过错误内容泄露其他使用者的数据或凭据。 |

所有者可编辑、复制和启停自己的主题；维护者不因运维身份自动拥有修改业务规则的权力。

| 身份 | 访问与操作边界 |
|---|---|
| 资料或配置所有者 | 在本文件范围内处理自己的业务资料与配置；维护职责的动作仍须相应授权。 |
| 获授权维护者 | 仅诊断或维护明确授权的范围，不自动获得业务正文、规则修改或秘密回读权限。 |
| 其他身份 | 默认拒绝；仅在 026 团队协作正式启用且被显式授权后，按实际角色开放对应操作。 |

本项专门权限规则优先约束上述通用边界，后续角色设计不能扩大已有秘密或数据访问权限。

重复点击、刷新页面或网络重试不得重复产生同一业务结果；若本操作是有意新建的一次业务行为，必须有独立标识和清晰的版本/时间范围。

## 9. 验收标准

AC-001-001 是父级验收，本文件第一项完整保留其场景，其余补充边界、异常和业务细节。以下全部是待执行标准，不是已通过记录。

| 验收 ID | 场景 | Given：前提 | When：操作 | Then：可核查结果 |
|---|---|---|---|---|
| AC-003-001 | 总纲场景继承 | 已建立包含词与排除词的主题 | 编辑规则并再次采集 | 新任务用新版本，旧结果仍能解释原命中规则；暂停后不新增调度。 |
| AC-003-002 | 条件组合 | 标题含品牌和召回但含排除词招聘 | 执行预览与已授权采集 | 排除词优先，保留被排除原因 |
| AC-003-003 | 编辑中的任务 | 旧版本任务仍运行 | 保存新版本 | 旧任务不被静默改规则，新任务绑定新版本 |
| AC-003-004 | 复制主题 | 原主题有结果和任务 | 复制并保存 | 产生新主题且默认暂停，不复制执行记录 |
| AC-003-005 | 暂停与归档 | 主题正在周期运行 | 暂停后归档 | 不再产生周期任务，历史可查且运行中任务状态明确 |
| AC-003-006 | 扩词预算 | 仅本地别名已启用 | 改为上游扩词并保存 | 展示变更查询和预算影响后生成新版本 |

交付证据应包含输入/规则版本、执行记录、实际结果和人工核对结论。界面能力须有真实浏览器证据；运行、恢复与来源能力按相应环境验证，纯文档检查不计作产品验收。
