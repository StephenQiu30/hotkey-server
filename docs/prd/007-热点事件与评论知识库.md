# 热点事件与评论知识库

2026-09-15｜已批准进入分片实施。承接 [006 PRD](006-社交媒体关键词监控与评论分析.md) 尚未交付的采集、评论和分析目标，以本轮研究重新拆分交付；不代表现有功能已满足本文件。

v1.1补充用户决策：任务开始前先确定目录/文件归属和所需技术选择；使用现有MinIO；内容采购零付费；X等主流信息平台优先发现，B站/微博/小红书/抖音承担评论研究。AC-007-001/015的来源范围据此按“发现来源/评论来源”分别验收；新增AC-007-016目录与选型门禁。AI推理费用范围仍在询问中。

## 1. 用户、问题与目标

首期用户为个人产品研究者、品牌/行业观察者，即当前单 owner。用户希望少做跨平台重复搜索，发现重要变化，理解争议和诉求，并让历史研究可以复用。

核心问题有四个：关键词结果噪声大；同一事件跨平台分散；评论缺上下文且样本偏差不透明；报告保存后无法追溯依据或持续更新。

| ID | 业务目标 | 判断方式 |
|---|---|---|
| BR-007-001 | 持续发现与主题相关的新内容 | 新增内容可追溯到实际查询与成功运行，来源故障不显示为没有讨论 |
| BR-007-002 | 理解重点事件及其评论观点 | 用户可从观点返回样本原文与父级上下文，能修正事件归属 |
| BR-007-003 | 将研究转为可复用知识 | 按事件/时间检索历史证据，统计口径明确，回答有支持性引用 |

### KPI 与试运行评价

第一轮建立基线，不以虚构数字验收商业效果。

| 指标 | 定义/测量方式 | 首期判据 |
|---|---|---|
| 来源覆盖 | 按发现/评论角色、平台、操作、用途分别统计通过项 | X等主流信息发现入口与至少1个指定国内评论平台形成事件闭环；四类国内平台分别记录缺口，回复能力与限制明确 |
| 发现相关性 | 人工分层标注的“相关”结果数 / 已标注结果数 | S02 保存基线与误报类型；自动屏蔽前另设经评估的门槛 |
| 发现延迟 | first_seen_at − published_at；另报运行延迟 | 分平台 P50/P95，排除回填并记录缺失时间；不承诺平台索引延迟 |
| 评论分析质量 | 按标签的精确率/召回率、弃判率与人工一致性 | S04 固定评估集、目标、分母后决定是否开放自动摘要 |
| 知识可信度 | 引用存在率、引用支持性、答案范围正确性 | 引用对象/版本有效性须全部通过；无法支持的句子删去或明确未知 |
| 持续可用性 | 连续观察中的按时调度、积压、来源成功与部分结果 | S06 连续 7 日如实记录，所有缺口保留；不把进程在线率当采集可用率 |
| 用户价值 | 相同研究题的人工耗时、漏项与证据回查时间 | 比较使用前后任务记录，第一轮不预设节省百分比 |

## 2. 范围与交付版本

### P0：完整 MVP

1. **V0 发现可用版（S00–S02）**：先完成目录/选型门禁，再进行来源逐操作验证、主题配置与预览、手动/定时运行、MinIO证据和持久化收件箱、原文版本、运行范围/失败原因、预算与暂停。
2. **V1 评论研究版（S03–S04）**：关注重点帖、根评论/回复增量、人工事件档案与合并/拆分、分平台趋势、样本观点分析、站内变化提醒。
3. **V2 知识闭环版（S05–S06）**：事件知识条目、全文/语义检索、受控统计、引用问答、更新/删除传播、备份恢复和连续运行验收。

P0 允许自动分析暂缓显示而保留待分析证据；一旦模型质量尚未达标，完整自动分析能力仍列为缺口。V0 可先供用户使用，但不宣称完成用户提出的全部功能。

X优先发现与国内评论是两条数据入口，不要求B站评论属于某个X帖子的原始回复树；它们通过同一事件关联。内容付费接口、付费数据商和自动充值均不在P0/P1的默认范围；自建服务资源费用与AI推理预算单独记录。X免费持续入口不可用时需保留该核心缺口并与用户讨论，不用其他平台默默替代。

### P1

更多来源、账号/RSS订阅、跨事件比较、自动归并建议、邮件/企业协作渠道提醒、报告导出、用户配置更多采样策略。P1 外部发送需用户主动配置并启用；本次规划不发送任何通知。

### P2 与非目标

多用户多工作区、精细角色、传播关系网络、高容量独立搜索/分析引擎延后。全网全量采集、私密内容绕过、实时秒级发现、完整用户画像、媒体文件批量保存、自动真实性认证不纳入范围。

## 3. 用户故事

- 我创建“某品牌售后”主题，加入别名和排除词，先看到每个平台真正会执行的查询和可用操作，再启用监控。
- 我在收件箱读到新投诉，看到它为什么命中、何时发现、来自哪里；将它加入事件并开始跟踪评论。
- 我查看该事件的主要诉求，能知道哪些平台/时段被采样，点击“退款困难”返回对应原评论和上下文。
- 一周后我问“这次与上次有何不同”，系统分别给出可计算统计和带引用的解释，未覆盖的数据明确说明。
- 某平台授权失效时，我看到该平台最后成功时间和恢复动作；其他来源继续运行，趋势图不把缺失当成下降。

## 5. 信息展示与交互规格

### 收件箱卡片

展示标题/摘要、平台、原链接、发布时间、发现时间、命中主题、相关性状态、事件归属、评论追踪状态。可以按主题/来源/时间/待处理筛选；可关注、忽略、加入事件。未知指标显示“未提供”，不能渲染为 0。

忽略仅作用于当前主题的 monitor_match。自动低相关分类可恢复查看；模型失败的候选保留并标“待分析”。未完成来源不放入默认可启用列表，旧草稿中的来源仍保留并解释原因。

### 事件档案

顶部为事件简介、状态、时间范围、最近观察时间。内部为概览、时间线、内容/评论、观点、证据与修订。首期不要求为每个维度做独立页面；在一个详情页分区即可。合并操作先展示受影响事件/内容清单和预期归属，执行后可通过修订恢复。

### 分析卡与问答

“主要诉求”包含主题标签、代表评论、样本计数及口径。“情绪变化”只有相同采样口径才比较，否则给出变化解释。回答附时间范围、检索/统计方式、证据链接与未知项；引用失效不继续显示为可信依据。

### 全局界面状态

| 状态 | 应展示 | 可执行动作 |
|---|---|---|
| 正常 | 已采内容、观察时间、范围与限制 | 查看、追踪、归并、分析 |
| 初始空 | 还未运行或只有草稿 | 配置、预览、启用 |
| 合法空 | 某次成功查询在指定范围返回 0 | 调整查询、查看实际查询；不显示“全网没有讨论” |
| 加载 | 最近已知结果 + 本次 queued/running 状态 | 浏览旧数据、取消本次运行 |
| 部分结果 | 已得节点数、截断原因、下次计划 | 查看已得内容、按预算继续 |
| 错误 | 稳定错误码、请求ID、最后成功时间 | 重试/恢复；不会清空历史结果 |
| 权限不足 | 具体操作或用途不可用 | 更新授权或取消该操作；不能绕过 |
| 预算耗尽 | 已用/上限、停止点与恢复时间 | 调整预算或等待；禁止无限自动重试 |
| 证据过期/删除 | 过期结论或已撤回引用标记 | 查看允许的修订摘要、重新生成 |

### 权限

| 操作 | 未登录 | owner | 系统 Worker |
|---|---|---|---|
| 查看监控/证据/知识 | 不允许 | 在当前数据用途范围内 | 仅任务所需范围 |
| 编辑、启用、删除主题/事件 | 不允许 | 允许，写操作需CSRF | 只能执行已入账指令 |
| 采集/分析/外部处理 | 不允许 | 仍受来源权限和预算限制 | 每页/每次分析校验权限版本 |
| 来源凭据管理 | 不允许 | 更新私有引用，不回显明文 | 运行时按用途取得，不写入结果 |
| 导出/外部提醒 | 不允许 | P1独立授权后启用 | 按已启用规则与幂等投递执行 |

桌面使用列表与详情并排；窄屏顺序展示，不靠横向滚动隐藏关键范围、停止原因或引用。实施时在 390px 和 1440px 浏览器验证；这只是测试视口定义，不声称已经验收。

## 8. 依赖、风险与待决策

依赖顺序为真实来源准入 → 持久化内容 → 评论上下文 → 事件/样本 → 知识与问答；前端可以用明确标识的fixture并行开发，但不能代替这些业务依赖的验收。

风险与未决项统一维护在 [Design第11节](../design/007-热点事件与评论知识库设计.md)：RSK-007-001–004，OPEN-007-001–006（已关闭项保留日期/结论）。首期沿用个人学习、国内外并重，落实用户指定的X发现、国内评论、内容零付费与现有MinIO；具体模型、推理预算和保留期在对应切片前确定，不先写成已落实资源。
