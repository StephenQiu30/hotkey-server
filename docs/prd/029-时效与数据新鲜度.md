# 时效与数据新鲜度 PRD

日期：2026-09-17。状态：详细需求草案；承接既定范围 NFR-001-003，保持 P0 优先级。本文是独立评审和验收依据，不代表功能已实现。对应 [执行计划](../plans/029-时效与数据新鲜度计划.md) 已进入 `in_progress`，[Design](../design/029-时效与数据新鲜度设计.md) v1.0 已接受 S00—S01；真实 Acceptance 尚未建立。

入口：[逐项 PRD 索引](README.md) · [平台需求总纲](001-热点事件监控平台功能与非功能需求.md) · [鱼皮项目功能研究](../research/001-热点事件监控平台调研.md)。

## 1. 背景、问题与用户价值

用户看到一小时刷新设置，可能误以为每小时都获得最新数据。来源限流、任务排队和停机会带来不同类型延迟，必须分别量化。

总纲原始要求：分别记录发布时间、首次发现时间、入库时间、最后成功更新时间；显示延后和漏采窗口，不把计划频率当作实际更新频率。

某平台两小时未成功采集，用户需要知道是任务没开始、来源拒绝还是预算耗尽，而不是继续看到绿色“运行中”。

## 2. 目标与成功指标

**BR-029-001：**真实展示从内容发布到发现、从任务到期到可查询的时间链，显式呈现数据陈旧和未覆盖窗口。

| 指标 | 统计口径 | 目标或判定 |
|---|---|---|
| 调度等待|符合运行条件的任务到期至实际启动 P95|B0 目标 ≤60 秒；不符合条件的延期另列 |
| 入库可见延迟|本批采集完成至本地查询可见 P95|B0 目标 ≤30 秒 |
| 整体新鲜度|当前时间减最后成功观察时间，含来源/预算导致陈旧|全部来源展示，不剔除故障 |

指标用于评审和后续测量，尚未取得运行结果。涉及新增数量、时长和默认值的建议须在实施前冻结；不据此扩大既定平台范围或付费权限。质量目标不以“页面有按钮”替代。

## 3. 范围、优先级与边界

- **本期范围（P0）：**时间口径、更新时间展示、延迟分解、缺口/陈旧状态、调度目标与实际效果区分。
- **明确不包括：**统一分钟级平台更新保证、把限流等待隐藏在排除项、将补采当实时。
- **与相邻能力的边界：**本地执行目标不等于上游数据开放速度；029 监测延迟，009/010 负责执行和缺口恢复。
- **发布条件：**本文件全部适用验收通过，并满足关联质量要求；缺失该能力不能用演示或其他功能替代 P0 完成。

## 4. 用户流程与关键结果

1. 记录内容、任务和观察的各类时间点及统一时区语义。
2. 检查任务到期时能力与预算，保存可运行或延期原因。
3. 采集完成后记录持久化及对用户可见时间。
4. 按来源与能力展示最后尝试、最后成功、数据年龄和缺口。
5. 超出配置的新鲜度目标时标陈旧并关联运行问题。

完成后用户获得：分阶段时延指标、真实新鲜度与可处理的陈旧状态。取消、失败或权限拒绝时，不显示与实际不符的成功结果。

## 5. 输入、配置与信息展示

| 信息项 | 规则与校验 | 默认或展示要求 |
|---|---|---|
| 时间点|发布、到期、受理、启动、获取、持久化、可查询|缺失不虚构 |
| 目标周期|主题/账号设定与来源实际限制|设定不等于已达到 |
| 延期分类|预算、限流、需登录、内部排队等|每次延期计原因与时长 |
| 陈旧判定|建议超过两个目标周期未成功即提示|来源可分别配置 |

配置变更记录操作者、时间和版本；正在执行的操作绑定启动时的业务规则版本。当前权限、连接停用、删除要求与更严格预算始终优先，不能以旧版本继续越权或超额执行。冲突的输入必须明确拒绝或延期，不能静默修改用户意图。

## 6. 详细需求与业务规则

| 需求 ID | 规则 | 详细行为 | 对应验收 |
|---|---|---|---|
| NFR-029-001 | 时钟口径 | 服务侧统一时间标准并记录来源时区/精度；客户端只影响展示，时钟异常要标记。 | AC-029-006 |
| NFR-029-002 | 分阶段测量 | 本地排队、外部耗时、处理和入库可见分别统计；发布到发现仅在可信发布时间存在时计算。 | AC-029-003、AC-029-006 |
| NFR-029-003 | 成功定义 | 只有有效采样并持久化可读才刷新相应能力最后成功时间；失败尝试不刷新成功时间。 | AC-029-002 |
| NFR-029-004 | 延期透明 | 可运行队列 SLI 与所有任务端到端等待同时报告；不能将来源失败或预算不足从整体新鲜度中删掉。 | AC-029-003 |
| NFR-029-005 | 缺口展示 | 中断/部分窗口形成可查缺口，补采恢复后仍按真实发布与观察时间显示。 | AC-029-004 |
| NFR-029-006 | 陈旧联动 | 陈旧状态影响图表与报告标注，不能仅在运维页提示；重复提醒遵循通知降噪。 | AC-029-005 |

**DEC-029-001：**分别承诺可控制的本地时延并公开整体数据年龄，不把轮询设置包装为实时服务。

以上规则解释 NFR-001-003，不重编号或替换总纲条目。后续发现冲突应显式更新总纲及受影响文档，不由某一页面或适配器单独改变语义。

## 7. 状态、异常与权限

| 状态或场景 | 展示与处理 |
|---|---|
| 新鲜|给出最后成功时间及实际采样窗口。 |
| 延期/陈旧|显示原因、持续时长与可处理动作。 |
| 时间未知/时钟异常|不计算误导性延迟，保留原始时间与说明。 |
| 加载或执行中 | 展示已知阶段和可用操作；未知进度不用虚假百分比，已持久化历史结果可以继续查看。 |
| 无权访问 | 显示稳定的权限提示，不通过错误内容泄露其他使用者的数据或凭据。 |

研究者可见自己的新鲜度与缺口；维护者看脱敏聚合，不通过监控指标暴露私人关键词。

| 身份 | 访问与操作边界 |
|---|---|
| 资料或配置所有者 | 在本文件范围内处理自己的业务资料与配置；维护职责的动作仍须相应授权。 |
| 获授权维护者 | 仅诊断或维护明确授权的范围，不自动获得业务正文、规则修改或秘密回读权限。 |
| 其他身份 | 默认拒绝；仅在 026 团队协作正式启用且被显式授权后，按实际角色开放对应操作。 |

本项专门权限规则优先约束上述通用边界，后续角色设计不能扩大已有秘密或数据访问权限。

重复点击、刷新页面或网络重试不得重复产生同一业务结果；若本操作是有意新建的一次业务行为，必须有独立标识和清晰的版本/时间范围。

## 8. 依赖、质量与验证环境

- **依赖或关联 PRD：**[004 平台与连接管理](004-平台与连接管理.md)、[009 采集任务控制](009-采集任务控制.md)、[010 增量更新与历史回补](010-增量更新与历史回补.md)、[012 事件详情与发展时间线](012-事件详情与发展时间线.md)、[017 变化提醒与通知记录](017-变化提醒与通知记录.md)。
- **适用质量要求：**本文件即质量要求的细化，受总纲免费、数据边界和真实验收约束。
- **验证口径：**B0 下至少 1,000 次有明确时间点的受控任务观察，分开正常、内部排队、来源限流和预算不足；真实来源只做低频观察。

总纲质量目标：在 B0 且来源可用、预算充足时，拟定任务到期至启动 P95 ≤60 秒、单批采集完成至可查询 P95 ≤30 秒；上游延迟与预算等待独立统计并展示，不能算作本地成功。
来源访问条件未满足时，使用受控样本验证内部规则，并单独记录真实来源验证未完成；不能用模拟成功冒充真实平台接入。涉及性能沿用总纲 B0，分析质量沿用 Q0；未采用相关基线时需注明适用样本和环境。

## 9. 验收标准

AC-001-027 是父级验收，本文件第一项完整保留其场景，其余补充边界、异常和业务细节。以下全部是待执行标准，不是已通过记录。

| 验收 ID | 场景 | Given：前提 | When：操作 | Then：可核查结果 |
|---|---|---|---|---|
| AC-029-001 | 总纲场景继承 | 任务分别因本地排队、来源限流和预算不足而延后 | 查看时效与状态 | 能分辨原因及最后成功时间；不承诺所有来源分钟级实时。 |
| AC-029-002 | 失败不刷新 | 上轮成功后本轮超时 | 更新运行状态 | 最后尝试变化、最后成功不变 |
| AC-029-003 | 阶段分解 | 任务有本地等待和来源等待 | 统计延迟 | 各阶段和整体等待均报告，来源延迟不被隐藏 |
| AC-029-004 | 部分窗口 | 本轮只完成半个采样窗口 | 展示资料 | 保留缺口和范围，不标全部时段新鲜 |
| AC-029-005 | 陈旧传播 | 连续两个目标周期未成功 | 看事件和报告 | 都有数据陈旧提示，非仅运维页 |
| AC-029-006 | 时区异常 | 来源时间无时区或晚于当前明显异常 | 计算发现延迟 | 标未知/异常，不生成负延迟或改成当前时间 |

交付证据应包含输入/规则版本、执行记录、实际结果和人工核对结论。界面能力须有真实浏览器证据；运行、恢复与来源能力按相应环境验证，纯文档检查不计作产品验收。
