# X 热点核心链路收敛与遗留系统清理

> **已取消并由 035 替代（2026-08-12）**：本 PRD 的 X-only 范围与用户确认的多源首版目标冲突。任何“拒绝非 X 来源、停止非 X 调度、移除 B 站入口”的要求均不得执行；有效的主链收敛要求见 [035 PRD](035-多源AI热点监控首版收敛.md)。

## 用户问题

HotKey 已能采集来源、匹配内容、形成事件、计算热度和通知，但 032 重构后的 v2 微事件链没有替换 legacy 事件链。当前一次采集同时生成两套相关性、事件和热度事实，告警与内容列表还会把 legacy Event ID 传给只识别 MicroEvent ID 的页面。与此同时，来源、报告、订阅、知识和 Agent 等产品面继续扩大，使用户最需要的“从 X 找到正在升温的目标事件”不再是清晰主流程。

本需求先清理双系统和非核心运行面，再让 033 的 X 持续热点能力落在唯一 v2 主链上。

## 产品目标

- 用户从监控目标出发，以 X 作为唯一必需来源完成发现、相关性、微事件、Heat v2 排序、通知和原帖回溯。
- MicroEvent 成为唯一对外事件身份，Content、事件和通知不再混用 legacy Event ID。
- legacy Event/Radar/Alert/Report/Knowledge 产品链停止新写并退出默认运行时和工作台。
- RSS 与其他非 X 来源不再是默认入口、依赖或故障回退；历史配置和数据按可恢复步骤停用而非直接删除。
- 保留凭据、安全、限流、审计、原始证据和必要纠错，不把删掉保护措施当作产品简化。

## 核心发布范围

### P0：单一事件身份与停止扩散

- 冻结 legacy 新功能和新调用者。
- Content API/页面改用 `micro_event_id`；移除 legacy `event_id` 深链。
- 033 的 X 发现、指标刷新与 Heat 只接入 v2，不新增 legacy 双写。
- 站内 UserNotification 成为唯一业务通知事实源。

### P1：运行时与产品面收敛

- 保留只维护 Content/指标兼容投影的 Normalize，停止其 legacy Match/Cluster 扇出，并停止 legacy Heat/Update/Alert/Summary/Report/Knowledge producer。
- 从 Bootstrap、OpenAPI、生成 Client 和前端移除 legacy Event/Radar/Alert/Report/Subscription/Knowledge/Agent 产品路由。
- 工作台一级入口收敛为概览、监控、X 来源、内容证据、热点事件、通知；高级纠错和审计只对管理员提供。
- 新来源 UI 只支持 X；非 X 连接停止自动调度，不作为回退。

### P2：可恢复物理清理

- 导出历史 legacy Event、Alert、Report 和非 X SourceConnection 清单。
- 在零写入、无队列、无消费者、备份恢复和引用扫描全部通过后，删除不可达代码与 canonical Schema 中的 legacy 表列。
- 任何检查失败都只阻止删除，不影响 v2 X 主链。

## 功能要求

- FR-034-1：`micro_event_id` 是唯一对外事件 ID；所有当前事件列表、详情、Content 关联和通知深链使用同一数字空间。
- FR-034-2：Content 的事件关联只能从 v2 DocumentVersion/ContentFamily/MicroEventMember 得到；不得回退读取 `event_contents/events`。
- FR-034-3：X 输入可继续维护 Content/指标兼容投影，但不得再入队 legacy relevance、cluster、heat、summary、alert 或 report 任务。
- FR-034-4：legacy Event、Radar、EventUpdate、Alert、Report、Knowledge 产品 API 从默认应用启动图移除；历史数据只允许受限导出。
- FR-034-5：业务通知只由 OutboxEvent 投影为 UserNotification；邮件和 Web Push 只记录 DeliveryAttempt，不建立独立告警事实。
- FR-034-6：核心 UI 只能新建 X SourceConnection；RSS 及其他来源没有默认入口、自动调度或故障回退。
- FR-034-7：已有非 X 连接先停用并导出；在物理删除前保持历史只读，不静默改写或删除用户数据。
- FR-034-8：AI 扩展、Embedding/Reranker、Web Push 和高级治理均为可选增强；不可用时核心 X 热点链必须显式降级并继续工作。
- FR-034-9：自动 Claim、EvidenceState 摘要和 Storyline 不得成为热点入库、排序或通知前置条件；基础原帖、时间、正文状态和哈希仍须可回溯。
- FR-034-10：每个 legacy producer、route、table、frontend consumer 必须有唯一处置和验证证据；不能仅删除导航而保留后台写入。
- FR-034-11：物理删除必须提供 dry-run、显式确认、幂等重入、引用扫描和独立恢复演练；数据库结构仍只由 canonical Schema 定义。
- FR-034-12：不得为清理引入第三套 Event/Hotspot、通用 Feature Flag 平台、消息总线、微服务或第二份 Schema。

## 非目标

- 不在 034 实现 X Recent Search/Lookup 和新 Heat 算法；它们属于 033。
- 不为 RSS、HN 或其他来源补功能，也不迁移到第三方 X API、网页抓取或浏览器 Cookie。
- 不以减少文件或表数量为唯一成功指标；安全边界、不可变证据和审计不能因“代码多”被删除。
- 不把所有历史数据强行映射为 MicroEvent；无法证明唯一关系时保持未关联并允许导出。
- 不承诺通用情报平台、日报周报、知识库、Agent Skill、全局 Trends 或跨平台搜索。

## 验收标准

- AC-034-1：同一 X 测试输入只产生 v2 Observation/Document/Match/Family/MicroEvent/Heat/Notification 事实，legacy 表行数和相关 Job 数不增长。
- AC-034-2：Content 和通知深链在重复 ID、缺关系和历史数据场景下都不会打开错误微事件。
- AC-034-3：应用启动与路由清单证明 legacy 产品 API、Scheduler 和 Worker Handler 已卸载，OpenAPI 和生成 Client 无残留。
- AC-034-4：390px 与桌面工作台只呈现核心导航，用户能完成“创建 X 监控—发现—热点排序—通知—原帖回溯”故事。
- AC-034-5：X 失败、AI 不可用、Push 未配置和非 X 连接存在时均无隐式回退；MinIO/Vault 仍按证据与正文基础设施契约接受 readiness 检查。
- AC-034-6：删除 dry-run 能报告 legacy 行、外键、队列、API/Client 引用、对象引用和恢复证据；存在阻断时拒绝 apply。

## 成功指标

- 核心 X 输入的 legacy 新写入为 0。
- 当前事件深链的 ID 语义错误为 0。
- 默认启动图只有一套事件、热度和业务通知 producer/reader。
- 新用户完成首个 X Monitor 不需要配置 RSS、报告、订阅、Knowledge 或 Agent。
- 过度设计清理不降低凭据安全、SSRF、限流、审计、原始证据和数据恢复门禁。

## 决策门槛

Design 必须先确认“X 核心、v2 唯一事件、非 X/报告/知识退出核心范围”三项边界；未确认前本 PRD 保持 `draft`，不修改生产运行时或删除数据。
