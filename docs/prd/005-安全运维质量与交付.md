# 安全运维质量与交付

关联文档：[Design](../design/005-安全运维质量与交付设计.md) · [Plan](../plans/005-安全运维质量与交付计划.md)

## 用户问题与当前事实

自托管不应意味着用户自行承担不可恢复的数据、泄露的凭据或无法诊断的后台任务。系统需要把身份、来源权利、Codex 隔离、保留删除、审计、可观测、备份恢复和发布门禁变成可重复产品能力，而不是一次性人工操作。

当前系统使用自建邮件验证、密码、JWT、数据库会话/Refresh Token、Redis 短期验证码，以及 `viewer/editor/admin` 三角色。根 Compose 编排前端、后端、PostgreSQL、Redis 与 MinIO；后端已有 River 任务、健康/就绪、Metrics/OpenTelemetry 和运维模块。目标产品增加 Analyst 职责，但当前 Schema、Domain 和 OpenAPI 尚无该角色；本 PRD 必须验证这一落差，不能在权限迁移完成前声称四角色已实现。

## 目标与 KPI

| KPI | 目标 | 口径状态 |
|---|---|---|
| 密钥、Token、DSN 进入日志/错误/文档/前端 Bundle | 0 | P0 硬门禁 |
| 跨角色/对象越权 | 0 | P0 硬门禁 |
| Worker 恢复后的重复业务副作用 | 0 | P0 硬门禁 |
| 核心 API 月可用性 | 99.5% | 候选，需定义测量环境、窗口和排除条件 |
| RPO / RTO | 15 分钟 / 2 小时 | 候选，需联合恢复演练校准 |
| 单机资源参考 | 16 vCPU、64 GB RAM、2 TB NVMe | 候选上限基线，需按当前模块化单体实测 |
| 普通日志保留 | 30–90 天 | 候选，需按容量与合规批准 |
| 安全审计保留 | 至少 180 天 | 候选，需按部署司法辖区批准 |

## 范围

### P0

- 当前 JWT、Session、Refresh Token、用户状态和服务端 RBAC 加固；
- Viewer/Analyst/Editor/Admin 产品权限的差距跟踪与兼容迁移门禁；
- Secret 注入、轮换、脱敏、凭据 Envelope/受管存储和最小权限；
- 来源 SSRF、Prompt Injection、路径、Markdown/XSS、压缩炸弹和大文件边界；
- 请求、任务、来源、Codex、事件、通知、报告、Vault 和检索的净化日志、指标、Trace 关联和告警；
- 原始证据、智能上下文、指标、业务事实、日志、审计的版本化保留与删除；
- River 任务超时、重试、取消、恢复、DLQ 等价失败治理和管理员运行中心；
- PostgreSQL、MinIO、Vault 和必要任务状态的备份、恢复、对账、重建与回滚；
- Schema、OpenAPI、后端、前端、Compose、依赖、安全和文档质量门禁；
- 单机/Compose 发布、Runbook、UAT 和 24 周 P0 收敛。

### P1

- 生产多副本、高可用、横向扩展和更严格的灾备拓扑；
- 评论、周报、更多授权来源和邮件的专项安全/容量门禁；
- 外部密钥服务、集中日志平台和更长周期合规自动化的独立评审。

### P2

- 多地域灾备、组织级单点登录和复杂租户隔离；
- 自动合规证据包、长期归档介质和高级成本优化。

## 用户故事

- 作为 Viewer，我的会话失效或账号禁用后不能继续使用旧 Token，也不能读取越权数据。
- 作为 Analyst/Editor，我只能执行所属职责的业务动作，权限不足有明确反馈且不泄露对象存在性。
- 作为 Admin，我可以查看净化运行状态、审计、保留预览和任务重试，但看不到密钥明文或完整不受信 Payload。
- 作为运维人员，我可以从备份恢复事实和证据、重建投影，并证明 RPO/RTO，而不删除现有数据卷。
- 作为开发者，我可以通过统一命令验证 Schema、OpenAPI、前后端、Compose、安全和文档无漂移。
- 作为发布负责人，我可以判断 P0 是否达到 G0–G6 门禁，并把 P1 功能留在后续排期。

## 业务需求

- `BR-005-001`：所有权限、来源权利和数据访问必须在服务端执行，客户端隐藏不能代替授权。
- `BR-005-002`：秘密与业务数据必须分离，任何角色和普通运行记录都不能泄露认证材料。
- `BR-005-003`：系统必须能够诊断、恢复和对账核心主链，投影或 Worker 故障不得变成静默数据损坏。
- `BR-005-004`：24 周交付必须以可验证 P0 和恢复门禁为准，不以功能数量或文档状态冒充完成。

## 功能要求

- `FR-005-001`：Identity 必须校验用户状态、短期 Access Token、数据库 Session、Refresh Token 轮换与重放，并支持退出和管理撤销。
- `FR-005-002`：Viewer、Analyst、Editor、Admin 产品权限必须由服务端矩阵执行；当前 Analyst 缺口必须通过单一 Schema、Domain、DTO、OpenAPI、生成客户端和测试的兼容变更解决或明确延期。
- `FR-005-003`：用户、来源、事件治理、报告审批、保留、任务、恢复和权限变更必须产生包含操作者、目标、结果、请求身份和时间的审计事实。
- `FR-005-004`：JWT Secret、HMAC、数据库/对象存储/邮件/来源/Codex 凭据必须由环境或受管密钥边界注入，API 只返回配置状态与脱敏标识；每类 Secret 必须支持有审计的新凭据预检、兼容窗口（适用时）、服务滚动、旧凭据撤销、会话/密文影响判定和失败回退。
- `FR-005-005`：来源 Connector 必须执行 SSRF 与权利门禁；Codex Adapter 必须把来源内容视为不可信输入并隔离秘密、源码、Vault 写权和网络。
- `FR-005-006`：Markdown、搜索高亮、压缩对象和上传/下载必须执行内容类型、大小、解压比、路径和 XSS 安全检查。
- `FR-005-007`：日志和 Metrics 必须关联安全的 request、job、collection run、monitor、event、agent run、report 和 knowledge 身份，并提供来源错误、任务积压、Codex 失败、证据写入、通知时延和投影冲突指标。
- `FR-005-008`：P0 告警必须覆盖数据库不可用、持久任务积压/无 Worker、来源连续认证失败、MinIO 写失败、Codex 连续失败、投影冲突和备份失败；阈值必须版本化并可测试。
- `FR-005-009`：保留策略必须按数据类别、来源和动作版本化，支持预览、执行、失败重入和审计；删除/撤权必须同步 API 读取阻断、MinIO、可删除的 Vault 自动投影、通知深链可见性、检索和缓存。Notification Outbox、User Notification、由 004 上线的 Notification Read Receipt、Delivery Attempt 与 Vault 人工区域不得作为可丢弃投影删除。
- `FR-005-010`：默认候选保留为原始响应 30 天、P1 评论启用后的完整评论正文 30 天、指标快照 180 天、Codex Context 30 天、业务 Event/Claim/Report/结构化结果长期、普通日志 30–90 天、安全审计至少 180 天；批准前必须解决 Evidence 长期追溯例外。
- `FR-005-011`：River 任务必须提供安全运行详情、有限重试、取消、失败重放和积压治理；对外部副作用还必须继承所属模块的 Fencing、Provider 幂等/回执或显式 `unknown` 停止契约，不得仅凭本地唯一键宣称 exactly-once。普通 DTO 不得返回 args、完整 errors、Provider Payload 或凭据。
- `FR-005-012`：备份必须覆盖 PostgreSQL、MinIO、Vault 与恢复所需任务事实，并保存一致恢复点；Redis 短期状态可重建，不作为恢复锚点。
- `FR-005-013`：恢复流程必须验证数据库兼容、对象哈希、Vault 投影、任务状态和全文投影重建，并产生演练证据。
- `FR-005-014`：readiness 必须拒绝 Schema/OpenAPI/配置不兼容实例接流量；发布失败必须能回滚应用而不删除数据库、对象、Vault 或任务历史。
- `FR-005-015`：每个 P0 行为变更必须遵循测试先行，并通过后端、前端、OpenAPI、Schema、Compose、安全、敏感信息和文档交叉链接门禁。
- `FR-005-016`：24 周发布评审必须逐条证明 001–005 的 P0 AC；评论、周报、更多授权来源、邮件和 HA 只能记录为 P1，不得用于掩盖未完成 P0。

## 非功能要求

- `NFR-005-001`：JWT 与认证 HMAC 每环境至少 32 字节；敏感配置不得提交仓库、写入 OpenAPI、文档、日志或前端 Bundle。
- `NFR-005-002`：登录、验证、重置、来源探测、采集、Codex、报告和运维动作必须进入版本化的全入口边界矩阵，逐项定义速率、并发、尝试和墙钟限制；越界必须在排队、网络、子进程或业务写入等对应副作用前失败停止。
- `NFR-005-003`：候选核心 API 可用性为 99.5%；批准前需定义探针、分钟统计、维护窗口、依赖故障和错误预算。
- `NFR-005-004`：候选 RPO 15 分钟、RTO 2 小时；批准前必须在隔离环境完成联合备份恢复和失败重演。
- `NFR-005-005`：候选单机资源为 16 vCPU、64 GB RAM、2 TB NVMe；当前模块化单体应先测得更小可运行配置及目标负载余量。
- `NFR-005-006`：业务和安全日志必须结构化、可净化检索且限制高基数字段；任何敏感值泄露均为发布阻断。
- `NFR-005-007`：备份、恢复、保留、权限和 Prompt Injection/SSRF 安全测试必须包含失败停止条件与可重复证据。
- `NFR-005-008`：P0 只要求 Compose/单机可恢复发布；Kubernetes、Operator、多副本、Kafka、ELK 和独立 IAM 不得成为首版可用性前提。
- `NFR-005-009`：发布证据必须绑定 Git revision、应用镜像 digest、依赖锁、Schema/OpenAPI/配置哈希、SBOM 和漏洞扫描结果；上游浮动标签按仓库政策使用，但必须记录发布时解析出的 image ID。

## 界面状态

| 状态 | 产品要求 |
|---|---|
| 正常 | 显示健康摘要、最后成功、积压、失败分类、备份时间和允许动作，不显示秘密 |
| 空 | 区分无运行、无失败、无审计结果、尚未演练和过滤后为空；“未演练”不得显示为健康 |
| 加载 | 运维动作显示目标、阶段、持久运行 ID 和取消条件，刷新页面不会重复提交 |
| 错误 | 显示稳定错误码、失败步骤、已完成/未完成影响和停止条件，详细原因只在净化日志 |
| 权限不足 | 直接 API 与页面同时拒绝，不返回资源存在性、备份路径、密钥状态细节或任务 Payload |

## 非目标

- 不在 P0 迁移到 Keycloak、外部 IAM、Kafka、Temporal、ELK、Elasticsearch 或 Python 微服务。
- 不创建 `db/migrations/`、第二套 DDL、Goose/Atlas 或运行时 AutoMigrate。
- 不以 Kubernetes、Helm、Operator、多节点 HA 或多地域作为 24 周完成条件。
- 不把日志、Metric、Trace、Redis、Vault 或全文投影变成业务事实源。
- 不在普通日志保存完整 Prompt、来源正文、Cookie、Bearer Token、Codex Auth、凭据或 DSN。
- 不把文档、未复现人工观察或一次性命令输出当作 Acceptance。
