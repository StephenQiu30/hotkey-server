# 模型平台信息采集与变更监控 PRD

日期：2026-09-17。依据用户“两种都需要，分别设计采集入口”的澄清，新增 FR-001-026。本文件 draft，[调研](../research/044-模型平台信息采集与变更监控调研.md)、[设计](../design/044-模型平台信息采集与变更监控设计.md) 和 [Plan](../plans/044-模型平台信息采集与变更监控计划.md) 分别为 draft / proposed / planned，未实现或验收。

## 1. 背景和用户目标

用户不仅关注社交讨论，也需要追踪模型平台的官方动态。当前只有热榜/订阅通用需求，缺少模型目录、价格语义和快照差异监控。采集这些公开信息无需调用模型推理。

**BR-044-001：**及时发现 OpenRouter、Vercel 的模型、价格、能力与发布变化，将可核查的信息送入既有监控和事件流程。

## 2. 成功指标

| 指标 | 口径 | 目标 |
|---|---|---|
| 重复提醒 | 同一逻辑变化重复投递/重跑 | 0 次重复用户提醒 |
| 证据完整 | 变更可回到前后快照、来源和时间 | 全部已发布变更具备依据 |
| 误报下架 | 失败/截断/范围变化故障矩阵 | 0 次被当作确认下架 |
| 时效 | 来源可达且预算允许时的变更发现延迟 | 记录实际值；目标随轮询周期冻结，不承诺实时 |

以上是待验证目标；当前公开资料读取不计产品验收，数值目标在实施前冻结。

## 3. 范围、优先级和非目标

本期建议 **P1 / M6**：公开 JSON 目录、OpenRouter 模型 RSS、公开公告；模型/厂商/关键词关注、快照、变更、事件关联与站内提醒。

明确不包括：账号私有用量、平台控制台抓取、模型推理、付费数据、完整互联网覆盖、自动推断全球首发、无证据的下架或热度排名。

与相邻功能的分工：043 管模型调用配置，044 管平台官方信息，045 管模型联网线索；021 负责通用热榜/Feed，005/006/008 仍分别负责原生搜索、作者作品及评论。不同入口均可关联同一事件，但保留来源与覆盖差异。首次补充信息源不改变 P0 34 项的发布门槛。

## 4. 用户流程

1. 选择 OpenRouter、Vercel 及目录/公告类型，设置关键词、关注模型/厂商与更新周期。
2. 预览已缓存资料，显式启用后同步首轮并建立基线；默认不为全部历史条目发通知。
3. 后续同步生成字段差异，按规则筛选，查看前后值、来源及时间。
4. 将变更加入事件或新建事件，核对同一发布在不同入口的关联。
5. 按有意义的新变化通知；暂停时停止新请求并保留历史和陈旧状态。

打开页面、保存配置或预览缓存不自动发生采集/推理；显式启用的定时任务按同一规则执行。

## 5. 输入和展示信息

| 信息 | 规则 |
|---|---|
| 来源与覆盖 | 平台、入口类型、查询参数/模态范围、来源版本、周期/请求预算；保存不外采 |
| 模型及发布信息 | 来源模型 ID、厂商/承载平台、类型/模态、能力、官方日期/首次发现/采集时间分开 |
| 价格 | 币种、原计费单位、档位、缓存/媒体/搜索维度、提供方范围；无法比较时明确原因 |
| 变更关注 | 新增、价格、能力、官方公告、缺失提示；精确 ID 与关键词分别匹配；阈值/静默可配 |

配置留版本、操作者和生效时间；当前权限、停用和更紧预算优先于旧配置。空字符串、重复项和超长输入校验规则于 G2 冻结，拒绝静默改变用户范围。

## 6. 详细业务规则

| ID | 规则 | 行为 | 验收 |
|---|---|---|---|
| FR-044-001 | 来源接入 | 读取官方 JSON 优先、RSS/公告补充；标明来源类别与覆盖参数；无密钥公开读取不触发推理，不因 Feed 失败自动购买抓取服务 | AC-044-002 |
| FR-044-002 | 身份与信息 | 来源＋完整 ID 为事实身份；不同网关同模型仅关联不合并事实；记录单位/档位和声明来源，缺失字段不填零 | AC-044-003 |
| FR-044-003 | 快照与变化 | 首次同步建基线；比较同一覆盖范围的成功完整快照；首次发现不等于发布时间；不完整/失败不生成下架事件，持续缺失只标待核查 | AC-044-004 |
| FR-044-004 | 关注与重要性 | 按关键词/厂商/精确模型/变更类型筛选；金额同单位比较，零价转收费单列；无互动数据不造热度，显示新鲜度/变更影响和命中原因 | AC-044-005 |
| FR-044-005 | 事件与提醒 | 变化保留前后证据，可关联/解除既有事件；RSS、目录和公告同一变化避免重复提醒，跨平台事实仍可区分；不宣称评论已采集 | AC-044-005 |
| FR-044-006 | 有界更新与降级 | 轮询遵守来源缓存与限额，重试同计预算；失败标陈旧，暂停停止新请求；故障不影响 X 或其他来源，恢复不重发旧提醒 | AC-044-006 |

**DEC-044-001：**以官方 API/Feed/公告作为独立来源，保留快照和字段变化；不依赖模型推理，不把官方资料与社交讨论混成同一种数据。

## 7. 非功能约束、状态与权限

复用 027/028 的身份、未知和证据版本，029 的新鲜度，031 的幂等，034/035/036 的访问及生命周期，037 的预算和 039 的观测；性能沿用 B0，真实平台仅低频读取。快照规则测试须含空/部分/重复/乱序响应。

未启用、同步中、正常空、已有基线、出现变化、部分、陈旧、限流、访问失败、预算延期、已暂停与无权限分别展示；未知进度不用虚假百分比。

所有者管理自己的来源规则与关注；维护者仅维护已授权的公开入口与诊断；其他身份默认无权查看个人关注、事件关联或通知。公开模型资料不等于个人监控配置可共享。

删除、撤权、原文失效及保留期传播至缓存、证据和导出；不能因公开入口而绕过个人研究资料权限。受控测试不包含生产密钥/账号会话或付费请求。

## 9. 验收标准

第一项完整继承 AC-001-042；其余覆盖具体边界。所有场景待执行，复合前提须拆成可独立失败的用例。

| AC | 场景 | Given | When | Then |
|---|---|---|---|---|
| AC-044-001 | 总纲场景继承 | 已关注 OpenRouter 与 Vercel 的模型及关键词 | 公开目录或公告发生变化并再次同步 | 显示来源及前后证据，按规则生成一次变化提醒；不调用推理，不把目录变更当作全网热度 |
| AC-044-002 | 来源范围 | 两个平台目录、默认文本目录、RSS 及返回 403 的公告 Feed | 启用各入口并查看采集记录 | 可达数据规范化持久可查；全模态与文本范围分开，403 显示访问失败；无推理请求、充值或付费抓取 |
| AC-044-003 | 身份与价格 | 同名模型在两网关价格单位/上下文不同，部分字段缺失 | 查看和比较模型记录 | 保留两份来源事实及关联；同单位档位才比较，未知不填零，不把目录声明写成实测 |
| AC-044-004 | 快照差异 | 首次基线、重复快照、成功新增、超时/截断及持续缺失 | 多轮同步并回看时间线 | 基线不冒充新发布，重复不增事件；新增可追溯；失败/截断不推断下架，持续缺失待核查，原发布日期不被采集时间覆盖 |
| AC-044-005 | 过滤与提醒 | 关注规则含价格阈值且同一发布出现在目录/RSS/公告，模型由免费转收费 | 关联事件并产生提醒 | 命中原因/前后值可查，零价变化不算无穷涨幅；同变化通知幂等，跨平台证据保留，可撤销关联；无互动指标不伪造热度或评论 |
| AC-044-006 | 故障与暂停 | 源限流、预算耗尽及用户暂停，已有历史资料 | 继续调度后恢复 | 停止/延期有界，失败尝试计数，历史标陈旧且可读；恢复不重发旧提醒，其他来源正常 |

证据须含输入/配置版本、执行时间和环境、实际持久结果、用户界面与故障判定；必要真实接口、数据库/消息、浏览器验证各自保留，不用一个绿测摘要代替。
