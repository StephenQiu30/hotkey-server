## 用户问题与当前事实

项目为个人非商业学习用途。SQLAlchemy 与 RabbitMQ 固定使用；首轮单人、默认工作空间、单实例运行，学习目标是关键词→帖子→评论/回复→分析的完整链路。多用户协作、商业运营、计费与高可用集群不属于 P0。

用户需要从国内外主流社交媒体持续发现关键词相关帖子，获取评论与回复，分析事件发展及用户观点。旧代码仅作为不可信库存；Feed/榜单本地筛词不能替代平台关键词搜索，评论没有完整的会话事实与增量链路。

2026-09-08 用户明确选择“国内外都重要”和“先以免费接口和可维护网页采集验证需求”，并允许推倒不合理的现有架构。因此本 PRD 将评论提升为 006 的必要能力；按用户进一步澄清，业务服务、身份权限、采集、分析、调度与数据模型全部重新设计，推荐全 Python 服务端，不以保留 Go 为约束。001–005 保留历史记录，但不能作为新系统验收依据；006 已获用户实施指令，正在实现基础切片。

## 目标与 KPI

| 指标 | 定义与候选目标 | 验收限制 |
|---|---|---|
| 有效平台覆盖 | 至少一个国内平台、一个海外平台完成关键词→帖子→评论→回复闭环 | 逐平台核对账号、入口、权限、时间窗和保存用途；不能用 HN/RSS 替代国内平台 |
| 免费验证持续性 | 候选连续 7 日有计划运行且可恢复 | 试用与持续免费单独统计；试用额度不足不可伪造 7 日稳定性 |
| 新增发现延迟 | 按平台、查询及免费额度给出 P50/P95 | 从可验证的源发布时间与本系统首次可见分别计时，未知时间不混入 |
| 评论关系完整性 | 已知 parent/root 关系正确，未知关系明确保留 | 固定样本关系正确率 100%；不承诺采齐平台隐藏结果 |
| 幂等与证据 | 重复任务不重复当前节点，已接受材料有合法证据或明确受限状态 | 硬门禁，故障注入验证 |

| 分析可追溯 | 每项结论的引用全部属于输入白名单，数字来自实际样本 | 硬门禁，不接受模型补造数据 |
| 维护与资源成本 | 每来源人工维护分钟/周、百条有效材料的调用/字节/浏览器秒/Token | 实测后决定扩大平台，不承诺“免费无限” |

## 范围

### P0：可交付的完整数据链

- 操作级平台目录，明确 keyword search / account feed / trends / detail / comments / replies / refresh 的真实范围。
- 中英关键词、实体别名、包含/排除规则、平台语义差异与不可变编译预览。
- 国内/海外各至少一个真实候选来源，免费 API 或允许的网页采集；试用明确到期。
- 根据已关联帖子采集评论，包含根评论、二级回复、父节点上下文、采样策略与独立游标。
- 持久化、证据、版本、去重、增量刷新、预算、故障恢复、删除与权限撤回。
- 评论相关性、主题、目标情绪与立场，事件时间线、热度和证据状态分离。
- 来源覆盖、采集进度、评论列表/树、引用回看及五态 UI。
- 单 owner 身份/会话与来源范围、可恢复任务投递、新库迁移、可核查历史导入及不依赖 Go 的完整运行。

### P1：按实测价值扩展

- 多用户成员、Viewer/Analyst/Editor/Admin 角色和跨工作空间隔离，作为后续权限学习专题。

- 抖音、小红书、知乎、快手及更多国内入口，X/Reddit/Mastodon 等海外来源按可用权限逐一加入。
- 自有公众号留言、视频号入口验证；Facebook/Instagram 在文档和账号能力明确后另排。
- 更深回复、有界历史回填、跨平台观点对比、按运营时段动态刷新。
- 用户有权使用的导入数据作为补充分析入口，标签明确为 import，不能充当真实自动采集验收。

### P2

- 提高平台配额或扩大样本的可选实验，按个人预算决定；商业分发不在本项目范围。
- 媒体文件下载、OCR/ASR 及视频画面理解；当前关键词首先针对平台返回文本，不宣称覆盖口播和画面。

### 非目标

- “全平台、全量、实时、永久免费”承诺，自动绕过登录/验证码/平台限制，账号池/代理对抗。
- 私信、私密群组、个人敏感画像、自动发布或回复评论。
- 整体移植第三方舆情系统、多个服务分别维护冲突业务事实；允许并推荐整体重建唯一业务后端。
- 将评论情绪当作事件真伪或全体公众立场。

## 用户故事

- Analyst 输入事件主题，查看各平台实际查询与成本，在国内外来源上发布持续监控。
- Analyst 在事件下找到“不重复关键词但与根帖有关”的评论，查看父上下文和不同观点。
- Viewer 看到样本范围、来源故障、最后更新与引用，能区分零结果和未采到。
- Editor 使用重新设计的事件合并/拆分和摘要治理，原始证据不变；评论立场的人工覆盖工作流另列后续范围，不直接覆盖模型结果。
- Admin 管理来源凭据、免费额度、会话到期、操作开关与删除策略，不通过普通 API 读取凭据明文。

## 权限与界面状态

首轮仅 owner 使用，必须验证登录、注销、会话撤销、来源范围与凭据不外泄。以下四角色矩阵是 P1 扩展设计，不要求个人学习首轮实现角色管理和多用户协作；用户故事中的 Analyst/Viewer/Editor 在 P0 由 owner 执行对应操作。

| 动作 | Viewer | Analyst | Editor | Admin |
|---|---|---|---|---|
| 查看有权访问的事件、评论、覆盖与证据 | 允许 | 允许 | 允许 | 允许 |
| 创建/发布自己的 Monitor 与预算内扫描 | 禁止 | 自有范围 | 已授权范围 | 允许 |
| 增加评论预算/深入展开 | 禁止 | 自有范围且不超 Admin 上限 | 已授权范围且不超上限 | 配置上限 |
| 事件合并/拆分与摘要治理 | 禁止 | 提交反馈 | 允许并审计 | 允许并审计 |
| 配置凭据、会话、来源权利/保留 | 禁止 | 禁止 | 禁止 | 允许 |
| 读取明文凭据/任意对象 Key | 禁止 | 禁止 | 禁止 | 禁止 |

正常：显示来源、窗口、最后成功、样本与可用动作。空：分别显示未配置、正常零条、过滤后零条。加载：显示运行身份和已保存成果，可离开页面。错误：分清未获能力、会话到期、额度耗尽、评论关闭、结构变化，保留输入。权限不足：API 与页面一致，不能泄露不属于该账号范围的帖子、评论或会话。
