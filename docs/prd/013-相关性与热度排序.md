# 相关性与热度排序 PRD

日期：2026-09-17。状态：详细需求草案；承接既定范围 FR-001-011，保持 P0 优先级。本文是独立评审和验收依据，不代表功能已实现。对应 [执行计划](../plans/013-相关性与热度排序计划.md) 已建立且为 planned；同编号 Design 与真实 Acceptance 尚未建立。

入口：[逐项 PRD 索引](README.md) · [平台需求总纲](001-热点事件监控平台功能与非功能需求.md) · [鱼皮项目功能研究](../research/001-热点事件监控平台调研.md)。

## 1. 背景、问题与用户价值

用户需要分清“已有高互动”与“现在增长快”。跨平台直接相加指标或让页面分数与排序不一致，会误导关注优先级。

总纲原始要求：先判断与主题相关性，再提供最新、热门、升温、相关性排序；作品分数与事件分数分开；展示指标、比较范围、算法版本和低置信状态。

研究者比较一个互动总量很高的旧事件与一个快速增加讨论的新事件，并追问为什么它排在前面。

## 2. 目标与成功指标

**BR-013-001：**提供相关性、热门、升温和最新四种可解释选择，能够复算排序且不伪造缺失信号。

| 指标 | 统计口径 | 目标或判定 |
|---|---|---|
| 解释覆盖率|展示分数对应输入、窗口和版本的比例|100% |
| 排序有效性|Q0 Top-10 相关率及与基线比较|候选目标 ≥80%，同时报告实际提升/退化 |
| 复算一致性|固定输入与版本重算排序|一致，稳定并列规则可核查 |

指标用于评审和后续测量，尚未取得运行结果。涉及新增数量、时长和默认值的建议须在实施前冻结；不据此扩大既定平台范围或付费权限。质量目标不以“页面有按钮”替代。

## 3. 范围、优先级与边界

- **本期范围（P0）：**相关性准入、平台内指标规范、作品和事件分数、增长快照、时间衰减、排序解释与版本。
- **明确不包括：**把热度当事实可信度、拿认证标识证明真实、未校准的跨平台总指数或预测保证。
- **与相邻能力的边界：**本模块排序已发现资料，不负责提高来源召回；来源排名仅为观察信号，不作为官方真实热度公式。
- **发布条件：**本文件全部适用验收通过，并满足关联质量要求；缺失该能力不能用演示或其他功能替代 P0 完成。

## 4. 用户流程与关键结果

1. 按主题规则判断相关性，边界内容待复核。
2. 选择同平台、内容类型和可比较时间范围的样本。
3. 读取有效指标快照，分别计算现有互动和增长信号。
4. 生成作品排序与基于代表作品的事件排序，保存版本。
5. 用户切换排序并打开解释，看到缺失指标及置信提示。

完成后用户获得：可切换排序、可解释分数、原始快照与明确比较范围。取消、失败或权限拒绝时，不显示与实际不符的成功结果。

## 5. 输入、配置与信息展示

| 信息项 | 规则与校验 | 默认或展示要求 |
|---|---|---|
| 排序模式|最新/热门/升温/相关性|建议默认热门，用户选择可保留 |
| 指标口径|点赞/转发/回复/播放等保持平台定义|缺失为未知并显示可用项 |
| 增长窗口|至少两个有效快照、实际时间间隔|建议间隔至少 30 分钟，来源单独校准 |
| 比较样本|平台、类型、时间窗、样本数、版本|少于 30 条时分数标暂定 |

配置变更记录操作者、时间和版本；正在执行的操作绑定启动时的业务规则版本。当前权限、连接停用、删除要求与更严格预算始终优先，不能以旧版本继续越权或超额执行。冲突的输入必须明确拒绝或延期，不能静默修改用户意图。

## 6. 详细需求与业务规则

| 需求 ID | 规则 | 详细行为 | 对应验收 |
|---|---|---|---|
| FR-013-001 | 相关性优先 | 明确无关作品不靠高互动进入主题榜；人工纠正应影响下一次排序。 | AC-013-006 |
| FR-013-002 | 口径与缺失 | 平台内归一化，缺失项不补零，不能直接累加不同平台指标；口径变化切换版本。 | AC-013-002 |
| FR-013-003 | 增长有效性 | 单快照不算增速；计数回落保留原观察并标异常，长间断不能伪装分钟爆发。 | AC-013-002、AC-013-003 |
| FR-013-004 | 时间与证据 | 新鲜度用发布或有证据的实质进展时间，补采旧闻不加新鲜奖励。 | AC-013-006 |
| FR-013-005 | 展示一致 | 同名热度在卡片、列表和报告中一致；不同指数另命名解释，固定并列时以稳定标识兜底。 | AC-013-004 |
| FR-013-006 | 事件聚合 | 作品分与事件分分开；控制单作者/重复转载贡献，解释代表作品选择和覆盖平台。 | AC-013-005 |

**DEC-013-001：**使用版本化、可复算指标解释排序；具体权重在标注集比较后冻结，002 的 X 公式仅作候选。

以上规则解释 FR-001-011，不重编号或替换总纲条目。后续发现冲突应显式更新总纲及受影响文档，不由某一页面或适配器单独改变语义。

## 7. 状态、异常与权限

| 状态或场景 | 展示与处理 |
|---|---|
| 充分样本|显示分数、范围、时间及解释入口。 |
| 增长待观察/样本不足|显示原始值与暂定排序，不生成虚假增速。 |
| 分数过期/口径变化|展示旧版本标识或暂不比较，等待重算。 |
| 加载或执行中 | 展示已知阶段和可用操作；未知进度不用虚假百分比，已持久化历史结果可以继续查看。 |
| 无权访问 | 显示稳定的权限提示，不通过错误内容泄露其他使用者的数据或凭据。 |

所有者可选择排序和申请重算；评分配置更改须有版本及影响记录，不允许页面临时算法悄悄改义。

| 身份 | 访问与操作边界 |
|---|---|
| 资料或配置所有者 | 在本文件范围内处理自己的业务资料与配置；维护职责的动作仍须相应授权。 |
| 获授权维护者 | 仅诊断或维护明确授权的范围，不自动获得业务正文、规则修改或秘密回读权限。 |
| 其他身份 | 默认拒绝；仅在 026 团队协作正式启用且被显式授权后，按实际角色开放对应操作。 |

本项专门权限规则优先约束上述通用边界，后续角色设计不能扩大已有秘密或数据访问权限。

重复点击、刷新页面或网络重试不得重复产生同一业务结果；若本操作是有意新建的一次业务行为，必须有独立标识和清晰的版本/时间范围。

## 9. 验收标准

AC-001-011 是父级验收，本文件第一项完整保留其场景，其余补充边界、异常和业务细节。以下全部是待执行标准，不是已通过记录。

| 验收 ID | 场景 | Given：前提 | When：操作 | Then：可核查结果 |
|---|---|---|---|---|
| AC-013-001 | 总纲场景继承 | 一个高互动无关帖和一个相关新帖被返回，部分作品仅有一次快照 | 查看列表顺序与页面分数解释 | 无关帖不因热度优先；单快照不伪造增长，不直接相加不同平台互动值；同名分数与排序口径一致，其他指标另行命名。 |
| AC-013-002 | 低样本与不同口径 | 同组仅 8 条且各有一次观察，部分指标缺失，另有其他平台指标 | 选择升温并检查评分输入 | 显示增长待观察与暂定比较；缺失不填零，不直接累加跨平台指标，不输出稳定百分位承诺 |
| AC-013-003 | 计数回落 | 平台修正点赞导致下降 | 计算增长 | 保留原始变化并标异常，不伪造负增长结论 |
| AC-013-004 | 展示一致 | 同一版本在列表卡片与报告出现 | 比较顺序与分数 | 同名指数一致，并列顺序可重复 |
| AC-013-005 | 转载集中 | 同作者或同稿占多数作品 | 计算事件分 | 控制重复贡献并可解释，不按采集频次直接加分 |
| AC-013-006 | 旧闻与无关 | 旧闻今天补采且无关帖互动很高 | 排序 | 不增加旧闻新鲜度，无关帖被排除 |

交付证据应包含输入/规则版本、执行记录、实际结果和人工核对结论。界面能力须有真实浏览器证据；运行、恢复与来源能力按相应环境验证，纯文档检查不计作产品验收。
