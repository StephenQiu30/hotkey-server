# 讨论分析与趋势 PRD

日期：2026-09-17。状态：详细需求草案；承接既定范围 FR-001-013，保持 P0 优先级。本文是独立评审和验收依据，不代表功能已实现。对应 [执行计划](../plans/015-讨论分析与趋势计划.md) 已建立且为 planned；同编号 Design 与真实 Acceptance 尚未建立。

入口：[逐项 PRD 索引](README.md) · [平台需求总纲](001-热点事件监控平台功能与非功能需求.md) · [鱼皮项目功能研究](../research/001-热点事件监控平台调研.md)。

## 1. 背景、问题与用户价值

用户需要理解讨论焦点、诉求和分歧，单纯词云或负面比例不能回答这些问题。采样方式变化也容易被误解为真实舆论变化。

总纲原始要求：提供已采集作品/评论数量、时间变化、讨论焦点、主要问题/诉求、代表观点；情绪与对特定对象的立场分别记录，允许混合/不确定与人工标注。

用户研究召回事件，想区分质量担忧、退款诉求和品牌支持，并逐条核对各观点的评论依据。

## 2. 目标与成功指标

**BR-015-001：**将明确范围的讨论样本转化为有证据、可修订的焦点和变化分析，允许不确定而不推断全网民意。

| 指标 | 统计口径 | 目标或判定 |
|---|---|---|
| 结论证据覆盖率|有依据的焦点/代表观点占全部此类结论|100% |
| 分母标注率|比例及趋势显示样本量、窗口和口径|100% |
| 人工有效性|研究者能用结果定位主要问题与不同意见|Q0 逐项评估，不用文本长度代替价值 |

指标用于评审和后续测量，尚未取得运行结果。涉及新增数量、时长和默认值的建议须在实施前冻结；不据此扩大既定平台范围或付费权限。质量目标不以“页面有按钮”替代。

## 3. 范围、优先级与边界

- **本期范围（P0）：**样本选择、基础统计、讨论主题、问题诉求、代表观点、情绪/对象立场的人工或规则标注及同口径趋势。
- **明确不包括：**默认付费 LLM、真实身份画像、总体民意比例、情绪等同立场、预测事件结果。
- **与相邻能力的边界：**本模块定义分析产物；自动模型增强归 022，证据与版本归 016，统计只描述采到的样本。
- **发布条件：**本文件全部适用验收通过，并满足关联质量要求；缺失该能力不能用演示或其他功能替代 P0 完成。

## 4. 用户流程与关键结果

1. 选择事件、作品、平台、时间与采样版本。
2. 检查样本量、上下文和来源缺口，确认分析范围。
3. 生成统计和候选主题/观点，区分原话与系统归纳。
4. 研究者核对代表评论，修订主题、情绪和立场对象。
5. 保存带证据的分析版本，对可比较时间窗展示变化。

完成后用户获得：焦点、诉求、代表观点及趋势，同时附样本清单和证据引用。取消、失败或权限拒绝时，不显示与实际不符的成功结果。

## 5. 输入、配置与信息展示

| 信息项 | 规则与校验 | 默认或展示要求 |
|---|---|---|
| 分析范围|事件/作品及数据快照、窗口、平台必须明确|默认当前事件已采样讨论 |
| 标签|主题、情绪、立场对象和态度分别记录|允许多标签、混合和未知 |
| 重复处理|同 ID 去重；相同文本另记录重复比例|不直接删除所有不同作者的相同表达 |
| 对比窗口|长度、采样模式与平台集合可比|不同口径必须提示，不默认比较 |

配置变更记录操作者、时间和版本；正在执行的操作绑定启动时的业务规则版本。当前权限、连接停用、删除要求与更严格预算始终优先，不能以旧版本继续越权或超额执行。冲突的输入必须明确拒绝或延期，不能静默修改用户意图。

## 6. 详细需求与业务规则

| 需求 ID | 规则 | 详细行为 | 对应验收 |
|---|---|---|---|
| FR-015-001 | 样本先行 | 分析绑定固定样本 ID 集合，输入不足可给基础统计并说明不适合概括。 | AC-015-002 |
| FR-015-002 | 观点有据 | 每个焦点/诉求至少有可核对评论；代表观点兼顾差异，热门观点不代表多数人观点。 | AC-015-002、AC-015-005 |
| FR-015-003 | 语义区分 | 情绪标表达感受，立场须有对象；反讽、引用和缺上下文允许未知，不强行二分类。 | AC-015-003 |
| FR-015-004 | 统计诚实 | 展示纳入/排除数量与原因，比例分母明确；热门样本不称随机抽样，缺来源不得当零声量。 | AC-015-004、AC-015-005 |
| FR-015-005 | 趋势可比 | 只对同窗口/同采样口径比较；规则改变或断采期间用断点/注释，不解释为真实升降。 | AC-015-004 |
| FR-015-006 | 人工与失败 | 修订保存原结果和理由；自动处理失败时原文、统计与人工整理仍可用，不将真实性默认标真。 | AC-015-006 |

**DEC-015-001：**基础分析以证据和可比较口径为核心，自动化手段可替换且不成为付费前置条件。

以上规则解释 FR-001-013，不重编号或替换总纲条目。后续发现冲突应显式更新总纲及受影响文档，不由某一页面或适配器单独改变语义。

## 7. 状态、异常与权限

| 状态或场景 | 展示与处理 |
|---|---|
| 可分析|显示已冻结样本及任务范围。 |
| 低样本/上下文不足|保留统计和原文，限制概括并允许继续补采。 |
| 分析失败/人工修订|显示原因和已保留成果，修订有独立版本。 |
| 加载或执行中 | 展示已知阶段和可用操作；未知进度不用虚假百分比，已持久化历史结果可以继续查看。 |
| 无权访问 | 显示稳定的权限提示，不通过错误内容泄露其他使用者的数据或凭据。 |

仅分析当前有权访问的数据；样本失去访问权或删除后，相关结论必须标失效或重算。

| 身份 | 访问与操作边界 |
|---|---|
| 资料或配置所有者 | 在本文件范围内处理自己的业务资料与配置；维护职责的动作仍须相应授权。 |
| 获授权维护者 | 仅诊断或维护明确授权的范围，不自动获得业务正文、规则修改或秘密回读权限。 |
| 其他身份 | 默认拒绝；仅在 026 团队协作正式启用且被显式授权后，按实际角色开放对应操作。 |

本项专门权限规则优先约束上述通用边界，后续角色设计不能扩大已有秘密或数据访问权限。

重复点击、刷新页面或网络重试不得重复产生同一业务结果；若本操作是有意新建的一次业务行为，必须有独立标识和清晰的版本/时间范围。

## 9. 验收标准

AC-001-013 是父级验收，本文件第一项完整保留其场景，其余补充边界、异常和业务细节。以下全部是待执行标准，不是已通过记录。

| 验收 ID | 场景 | Given：前提 | When：操作 | Then：可核查结果 |
|---|---|---|---|---|
| AC-015-001 | 总纲场景继承 | 同一事件含支持、反对、提问和讽刺的讨论样本 | 生成分析并人工复核 | 至少给出有证据的焦点和代表观点；表达不清允许弃判；比例明确分母和样本范围。 |
| AC-015-002 | 观点依据 | 一个焦点只有模型文本没有引用 | 请求发布分析 | 不能作为已证实观点发布，需补证据或标待核实 |
| AC-015-003 | 情绪与立场 | 评论愤怒但对象是虚假传闻 | 标注并查看 | 不自动记为反对品牌，对象与态度独立 |
| AC-015-004 | 采样改变 | 第二窗口只采热门评论 | 比较两窗情绪比例 | 显示口径变化，不输出直接总体上升结论 |
| AC-015-005 | 少量分歧 | 少数评论提出不同诉求 | 选择代表观点 | 保留差异观点且不称多数观点 |
| AC-015-006 | 处理失败 | 分析模型失败但原文已保存 | 打开分析页并人工整理 | 原文和统计可用，修订记录独立且不默认标真 |

交付证据应包含输入/规则版本、执行记录、实际结果和人工核对结论。界面能力须有真实浏览器证据；运行、恢复与来源能力按相应环境验证，纯文档检查不计作产品验收。
