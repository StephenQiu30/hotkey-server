# 事件与热度需求

本文从 [总需求 001 v5.0](001-热点舆情监控平台需求.md) 保留的 PRD 001 v3.0 基线按 M3 拆出，现与 [Design 004](../design/004-事件与热度设计.md) 对齐；[Plan 004](../plan/004-事件与热度计划.md) 已按同号里程碑迁入 `docs/plan/`。需求状态 `approved` 不表示产品验收通过。

## 1. 目标与范围

**目标**：研究者从已验收的跨平台内容查看同一事件及热度变化，必要时人工合并或拆分。

**不包含**：把单条热榜命中直接当事件；未通过 M2 的 B 站内容；报告、知识库写入与渠道送达。

## 2. 用户场景与状态

- 从已验收的不同平台帖子查看同一事件的代表内容、来源分布及热度口径。
- 发现自动归并不准时人工合并或拆分，再核对事件成员及升温标注；单条热榜命中仍只是输入。

权限沿用总需求的单 owner 登录；加载及权限不足沿用现有界面和权限契约。以上场景按本里程碑 FR/AC 与总需求 NFR 核对。

## 3. 业务需求

| ID | 业务需求 | 成功判断 |
|---|---|---|
| BR-004-001 | 判断内容是否相关并逐步整理观点、事件 | 跨平台相似内容归并为事件，人工合并/拆分与升温可核对。 |

## 4. 功能需求

| ID | 功能 | 要求 |
|---|---|---|
| FR-004-001 | 事件归并 | 跨平台相似内容归并为事件，保存标题、摘要、首次出现时间、平台分布、热度、情感分布和代表帖子与评论；支持人工合并/拆分 |
| FR-004-002 | 事件热度与升温 | 程序综合互动量、帖子数和来源权重计算热度并记录口径版本，标出新出现、快速升温；报告引用事件时附计算口径，不得把热榜条目自动视为事件 |

## 6. 验收标准与退出条件

**证据门槛**：表中列出的等级须分别具备。受控测试验证状态机、边界与故障；真实运行验证实际来源、外部依赖和持久结果；产品验收按本条样本、连续窗口或用户核对口径作结论。低一级证据不能替代高一级；“代码已合入”本身不属于通过证据。

**退出条件**：真实三平台同事件、人工合并/拆分和升温口径可核对。受控测试、真实运行与产品验收分层记录；一项结果不替代另一项。

| ID | Given（前提） | When（操作） | Then（期望与退出条件） | 证据等级与用途（所列均必需） |
|---|---|---|---|---|
| AC-004-001 | M1 来源有已验收的真实跨平台样本；B 站只在 M2 通过后纳入。 | 用真实三平台同事件样本归并、人工合并或拆分 | 同一事件在 3 个平台的内容归并为一项，人工合并/拆分与升温标注可核对；热榜快照及事件笔记不作为本项的替代证据 | 真实运行（三平台同事件样本与热度记录）；产品验收（人工合并/拆分和升温可复核） |

- **决策/未决项**：沿用总需求 DEC-001-114/215；暂无本里程碑新增产品决策。本文不新建 DEC/OPEN。
