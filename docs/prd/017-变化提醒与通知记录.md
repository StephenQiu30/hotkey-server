# 变化提醒与通知记录 PRD

日期：2026-09-17。状态：详细需求草案；承接既定范围 FR-001-015，保持 P0 优先级。本文是独立评审和验收依据，不代表功能已实现。对应 [执行计划](../plans/017-变化提醒与通知记录计划.md) 已建立且为 planned；同编号 Design 与真实 Acceptance 尚未建立。

入口：[逐项 PRD 索引](README.md) · [平台需求总纲](001-热点事件监控平台功能与非功能需求.md) · [鱼皮项目功能研究](../research/001-热点事件监控平台调研.md)。

## 1. 背景、问题与用户价值

不断重复提醒同一高热事件会让用户忽略真正变化；另一方面，没有运行故障提醒会让用户误以为监控仍然正常。

总纲原始要求：站内提供新作品、新事件、显著升温及持续采集故障提醒；可配置规则、静默、冷却、已读；提醒附触发原因和证据，防重复及反复越线抖动。

用户只希望首次发现相关事件、作者新作或再次明显升温时收到站内提醒，也希望连续采集失败能被及时发现。

## 2. 目标与成功指标

**BR-017-001：**把可解释的新变化转换为少量有用的站内通知，并保持完整记录而不反复打扰。

| 指标 | 统计口径 | 目标或判定 |
|---|---|---|
| 重复通知率|同一业务变化重复生成通知的比例|受控重放测试为 0 |
| 通知解释率|通知附规则、变化、证据和触发时间|100% |
| 规则有效性|人工判断有价值通知/已评审通知|首轮建立基线，不以通知总量为成功 |

指标用于评审和后续测量，尚未取得运行结果。涉及新增数量、时长和默认值的建议须在实施前冻结；不据此扩大既定平台范围或付费权限。质量目标不以“页面有按钮”替代。

## 3. 范围、优先级与边界

- **本期范围（P0）：**新作/新事件/升温/故障规则、站内通知、静默与冷却、已读、变化归并和通知历史。
- **明确不包括：**自动发送未经配置的外部消息、保证用户一定阅读、每次指标刷新都提醒。
- **与相邻能力的边界：**本模块产生业务通知记录；离线送达由 024 处理，传输成功不等于用户已读。
- **发布条件：**本文件全部适用验收通过，并满足关联质量要求；缺失该能力不能用演示或其他功能替代 P0 完成。

## 4. 用户流程与关键结果

1. 用户在主题/账号/事件设置需提醒的变化与范围。
2. 采集和分析完成后评估规则及数据充分性。
3. 对同一业务变化去重，应用冷却、静默和归档条件。
4. 生成带原因与证据的站内通知，可标已读或查看详情。
5. 故障恢复或再次合格变化产生新的关联记录，保留历史。

完成后用户获得：有理由和证据的站内通知流及已读状态。取消、失败或权限拒绝时，不显示与实际不符的成功结果。

## 5. 输入、配置与信息展示

| 信息项 | 规则与校验 | 默认或展示要求 |
|---|---|---|
| 规则类型|新作品、新事件、升温、连续失败独立启停|建议新作品/事件开启 |
| 阈值与证据|升温需有效快照与比较窗口|不足时不触发虚假升温 |
| 冷却与静默|建议同事件冷却 6 小时；支持静默时段|重要性不能绕过用户停用 |
| 故障提醒|按连接/能力聚合|建议连续 3 轮失败提醒一次，恢复一次 |

配置变更记录操作者、时间和版本；正在执行的操作绑定启动时的业务规则版本。当前权限、连接停用、删除要求与更严格预算始终优先，不能以旧版本继续越权或超额执行。冲突的输入必须明确拒绝或延期，不能静默修改用户意图。

## 6. 详细需求与业务规则

| 需求 ID | 规则 | 详细行为 | 对应验收 |
|---|---|---|---|
| FR-017-001 | 触发清晰 | 保存规则版本、触发前后指标、时间和证据；无有效增长数据不能触发升温。 | AC-017-003 |
| FR-017-002 | 去重键 | 同一作者作品或事件变化只产生一条业务通知；任务重试、消息重投不制造新通知。 | AC-017-002 |
| FR-017-003 | 冷却与抖动 | 阈值附近波动不反复提示；冷却后仍需新的实质变化才能再发，持续高值不是新变化。 | AC-017-003 |
| FR-017-004 | 静默与停用 | 区分不产生新提醒、静默期间汇总和未读状态；归档/取消关注停止相应额外通知。 | AC-017-004 |
| FR-017-005 | 故障聚合 | 同一连接连续错误聚合为一条活动问题，恢复后更新或产生一次恢复记录，不为每个主题轰炸。 | AC-017-005 |
| FR-017-006 | 阅读状态 | 已读只改变个人阅读状态，删除通知不删除原始证据；历史回填默认不冒充实时新事件提醒。 | AC-017-006 |

**DEC-017-001：**以业务变化而非任务次数触发提醒，站内记录和外部传输各自可追踪。

以上规则解释 FR-001-015，不重编号或替换总纲条目。后续发现冲突应显式更新总纲及受影响文档，不由某一页面或适配器单独改变语义。

## 7. 状态、异常与权限

| 状态或场景 | 展示与处理 |
|---|---|
| 无通知|解释尚无满足条件的变化，而非来源一定正常。 |
| 未读/已读|状态独立于事件真假、任务成功和外部投递。 |
| 冷却/静默/故障聚合|在规则或活动问题页说明抑制原因，可查看历史。 |
| 加载或执行中 | 展示已知阶段和可用操作；未知进度不用虚假百分比，已持久化历史结果可以继续查看。 |
| 无权访问 | 显示稳定的权限提示，不通过错误内容泄露其他使用者的数据或凭据。 |

所有者管理自己的规则和阅读状态；任何外部渠道发送必须另经用户配置启用，本轮不发送。

| 身份 | 访问与操作边界 |
|---|---|
| 资料或配置所有者 | 在本文件范围内处理自己的业务资料与配置；维护职责的动作仍须相应授权。 |
| 获授权维护者 | 仅诊断或维护明确授权的范围，不自动获得业务正文、规则修改或秘密回读权限。 |
| 其他身份 | 默认拒绝；仅在 026 团队协作正式启用且被显式授权后，按实际角色开放对应操作。 |

本项专门权限规则优先约束上述通用边界，后续角色设计不能扩大已有秘密或数据访问权限。

重复点击、刷新页面或网络重试不得重复产生同一业务结果；若本操作是有意新建的一次业务行为，必须有独立标识和清晰的版本/时间范围。

## 9. 验收标准

AC-001-015 是父级验收，本文件第一项完整保留其场景，其余补充边界、异常和业务细节。以下全部是待执行标准，不是已通过记录。

| 验收 ID | 场景 | Given：前提 | When：操作 | Then：可核查结果 |
|---|---|---|---|---|
| AC-017-001 | 总纲场景继承 | 同一事件多轮超过阈值，随后再次实质升温 | 运行提醒规则 | 重复轮次不重复提醒，新的合格变化产生独立记录；恢复后不重复轰炸旧通知。 |
| AC-017-002 | 重复重放 | 同一作品结果投递三次 | 运行通知规则 | 只生成一条业务通知 |
| AC-017-003 | 阈值抖动 | 分数反复在阈值两侧小幅变化 | 多轮检查 | 按抖动/冷却规则抑制并说明，不重复刷屏 |
| AC-017-004 | 静默与归档 | 事件归档且进入静默时段 | 出现符合阈值变化 | 遵守停用/静默配置，历史仍可检查 |
| AC-017-005 | 故障聚合 | 一个连接影响十个主题三轮失败 | 产生问题记录后恢复 | 聚合一次问题和一次恢复，不逐主题轰炸 |
| AC-017-006 | 历史回填 | 旧作品今天补采且用户将通知标已读 | 刷新页面 | 不冒充新发生，已读不修改原始证据 |

交付证据应包含输入/规则版本、执行记录、实际结果和人工核对结论。界面能力须有真实浏览器证据；运行、恢复与来源能力按相应环境验证，纯文档检查不计作产品验收。
