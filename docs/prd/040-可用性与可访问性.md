# 可用性与可访问性 PRD

日期：2026-09-17。状态：详细需求草案；承接既定范围 NFR-001-014，保持 P0 优先级。本文是独立评审和验收依据，不代表功能已实现。对应 [执行计划](../plans/040-可用性与可访问性计划.md) 已建立且为 planned；同编号 Design 与真实 Acceptance 尚未建立。

入口：[逐项 PRD 索引](README.md) · [平台需求总纲](001-热点事件监控平台功能与非功能需求.md) · [鱼皮项目功能研究](../research/001-热点事件监控平台调研.md)。

## 1. 背景、问题与用户价值

监控产品的用户首先需要判断发生了什么、数据是否新鲜和可以采取什么行动。来源限制、空结果、执行失败若表达不清，即使功能齐全也无法形成可信决策。

总纲原始要求：核心流程用业务语言；支持桌面和窄屏，键盘操作与清晰焦点；状态不只靠颜色；错误提供下一步动作，正常空结果与故障明显不同。

首次使用者通过桌面或窄屏创建关键词监控、打开事件并找到一条原文证据；遇到来源失效时能判断需要更新连接，而不是误以为没有相关事件。

## 2. 目标与成功指标

**BR-040-001：**让目标用户在无现场指导下完成核心闭环，并在键盘、窄屏和状态异常场景下理解并操作。

| 指标 | 统计口径 | 目标或判定 |
|---|---|---|
| 核心任务完成率|至少 5 名目标或明确标注的代理用户，无现场指导完成全部指定步骤者占比|候选 ≥80%，即至少 4 人；不足 5 人或缺少受试者不判通过 |
| 键盘可完成性|核心流程必须操作中可仅用键盘完成的比例|100%，无焦点陷阱且焦点清楚 |
| 状态可理解性|受试者对正常空结果、来源失败、部分数据的判断和下一步选择|记录逐项结果与误解；关键误导问题修复后复验 |

指标用于评审和后续测量，尚未取得运行结果。涉及新增数量、时长和默认值的建议须在实施前冻结；不据此扩大既定平台范围或付费权限。质量目标不以“页面有按钮”替代。

## 3. 范围、优先级与边界

- **本期范围（P0）：**中文核心任务流程、业务用语、反馈与错误、键盘与语义、窄屏布局和首次使用验证。
- **明确不包括：**在未专项测试时声称达到完整可访问性认证、首版承诺全部语言本地化、通过培训替代可理解界面、仅凭截图判断功能可用。
- **与相邻能力的边界：**本文件约束所有 P0 页面交互；030 定义响应时长，004 和 009 提供状态事实。后续高级功能纳入发布时适用相同基础要求。
- **发布条件：**本文件全部适用验收通过，并满足关联质量要求；缺失该能力不能用演示或其他功能替代 P0 完成。

## 4. 用户流程与关键结果

1. 用户进入后看见建立监控所需的最少步骤和当前连接状态。
2. 使用清楚的标签填写主题、关键词及来源，错误显示在相关字段并保留输入。
3. 保存后获得可信受理反馈，了解何时有结果及限制。
4. 在列表和事件详情中识别新鲜度、部分数据与原文证据。
5. 遭遇空结果或故障时理解原因并完成适用修正，全程可用键盘及窄屏操作。

完成后用户获得：可独立完成的监控到证据流程及清楚的异常下一步。取消、失败或权限拒绝时，不显示与实际不符的成功结果。

## 5. 输入、配置与信息展示

| 信息项 | 规则与校验 | 默认或展示要求 |
|---|---|---|
| 主要用语|主题、作品、事件、评论、回复、采集时间保持一致|对用户不展示队列内部名、异常类名等无助决策的信息 |
| 状态表达|文字、图标和可读说明共同表达|颜色不能作为唯一信号，部分数据必须有文字说明 |
| 测试设备|记录桌面/窄屏尺寸、浏览器、缩放和辅助操作条件|建议覆盖桌面及 375 CSS 像素窄屏，320 CSS 像素作为最窄核验场景 |
| 用户任务脚本|统一自然语言任务、开始条件、成功定义和观察记录|不现场提示按钮位置；代理用户与真实目标用户分开报告 |

配置变更记录操作者、时间和版本；正在执行的操作绑定启动时的业务规则版本。当前权限、连接停用、删除要求与更严格预算始终优先，不能以旧版本继续越权或超额执行。冲突的输入必须明确拒绝或延期，不能静默修改用户意图。

## 6. 详细需求与业务规则

| 需求 ID | 规则 | 详细行为 | 对应验收 |
|---|---|---|---|
| NFR-040-001 | 任务与信息层级 | 新建监控到查看事件证据的主路径清晰，核心输入有可理解标签和必要示例；可选高级项不遮挡必填步骤，专业状态提供业务解释。 | AC-040-002 |
| NFR-040-002 | 状态与错误反馈 | 空结果、未运行、部分结果、连接失效和系统失败各自表达；保存、取消、删除和重试反馈符合实际结果，错误保留可修正输入并给出适用下一步。 | AC-040-003 |
| NFR-040-003 | 键盘与焦点 | 核心控件可按合理顺序聚焦和触发，弹窗打开/关闭焦点正确管理；操作后焦点可定位，无键盘陷阱，不能依赖悬停才能发现必要动作。 | AC-040-004 |
| NFR-040-004 | 语义与感知 | 表单有程序化标签，错误与对应字段关联；关键状态变化可被辅助技术感知，文本/图标不只靠颜色区别，链接说明目的，图表有可读数据摘要。 | AC-040-005 |
| NFR-040-005 | 窄屏与长内容 | 核心输入和操作在窄屏可用，不发生遮挡或页面级无意横向溢出；必要宽表可局部滚动并保留上下文。长中文、英文、URL、用户名和缺失内容不破坏主流程，缩放不丢失关键操作。 | AC-040-006 |
| NFR-040-006 | 真实可用性验证 | 按统一任务让至少 5 名目标或代理用户独立完成创建监控、查看事件和找到原文，记录完成、耗时、误解及帮助次数；只有浏览器自动化不替代受试者验证，缺人则标未验证。 | AC-040-002、AC-040-003 |

**DEC-040-001：**以用户能否独立完成核心任务及正确理解数据状态为准；视觉整齐、控件存在或自动化通过都不是完整可用性验收。

以上规则解释 NFR-001-014，不重编号或替换总纲条目。后续发现冲突应显式更新总纲及受影响文档，不由某一页面或适配器单独改变语义。

## 7. 状态、异常与权限

| 状态或场景 | 展示与处理 |
|---|---|
| 首次使用或未运行|说明尚未取得数据，提供明确下一步，不伪造演示为真实结果 |
| 空结果与故障|分别描述搜索范围无匹配、来源不可用及可能修正动作 |
| 输入错误或操作失败|保留输入、明确定位错误和结果，不把重复提交作为唯一恢复方法 |
| 加载或执行中 | 展示已知阶段和可用操作；未知进度不用虚假百分比，已持久化历史结果可以继续查看。 |
| 无权访问 | 显示稳定的权限提示，不通过错误内容泄露其他使用者的数据或凭据。 |

无权限状态不泄漏他人资料，隐藏无用操作时仍提供可理解原因；普通使用者不需理解或操作维护者秘密设置。测试受试者使用合法脱敏样本。

| 身份 | 访问与操作边界 |
|---|---|
| 资料或配置所有者 | 在本文件范围内处理自己的业务资料与配置；维护职责的动作仍须相应授权。 |
| 获授权维护者 | 仅诊断或维护明确授权的范围，不自动获得业务正文、规则修改或秘密回读权限。 |
| 其他身份 | 默认拒绝；仅在 026 团队协作正式启用且被显式授权后，按实际角色开放对应操作。 |

本项专门权限规则优先约束上述通用边界，后续角色设计不能扩大已有秘密或数据访问权限。

重复点击、刷新页面或网络重试不得重复产生同一业务结果；若本操作是有意新建的一次业务行为，必须有独立标识和清晰的版本/时间范围。

- **适用质量要求：**本文件即质量要求的细化，受总纲免费、数据边界和真实验收约束。
- **验证口径：**固定浏览器与设备条件验证键盘、焦点、缩放及窄屏核心流程；人工检查程序化标签和状态可感知性。可用性研究记录受试者类型、统一任务和实际完成，不把设计者自测计入 5 名用户结果。

总纲质量目标：首轮建议 5 名目标或代理用户中至少 4 名可在无现场指导下完成新建监控、查看事件与找到原文；如没有受试者，记录未验证。核心流程同时做键盘/窄屏浏览器验证。
来源访问条件未满足时，使用受控样本验证内部规则，并单独记录真实来源验证未完成；不能用模拟成功冒充真实平台接入。涉及性能沿用总纲 B0，分析质量沿用 Q0；未采用相关基线时需注明适用样本和环境。

## 9. 验收标准

AC-001-038 是父级验收，本文件第一项完整保留其场景，其余补充边界、异常和业务细节。以下全部是待执行标准，不是已通过记录。

| 验收 ID | 场景 | Given：前提 | When：操作 | Then：可核查结果 |
|---|---|---|---|---|
| AC-040-001 | 总纲场景继承 | 用户首次使用且遇到空结果或来源失效 | 完成核心流程 | 能找到规则、状态和下一步；不把错误误认成无相关事件。 |
| AC-040-002 | 无指导任务 | 至少 5 名目标或明确标注代理用户获得统一任务 | 独立创建监控、查看事件并定位原文 | 至少 4 人完成全部步骤；帮助次数、失败原因和样本类型可核查 |
| AC-040-003 | 空与错的理解 | 提供无匹配、未运行、来源失效及部分结果场景 | 用户判断状态并选择动作 | 文字解释不同，用户误解有记录，关键误导需修复后复验 |
| AC-040-004 | 键盘完整路径 | 用户不使用鼠标 | 完成输入、弹窗确认、结果查看和返回 | 焦点顺序合理且可见，无陷阱，关闭弹窗后焦点回到合理位置 |
| AC-040-005 | 语义与颜色 | 隐藏颜色差异并检查辅助技术信息 | 识别错误、状态及图表结论 | 标签和错误关联可读，状态文字或摘要足以理解，不依赖颜色 |
| AC-040-006 | 窄屏和长内容 | 375 与 320 CSS 像素场景包含长标题、URL 和多语言评论 | 操作核心页面并缩放查看 | 关键输入和按钮可用，长内容不遮挡，宽表仅局部可控滚动 |

交付证据应包含输入/规则版本、执行记录、实际结果和人工核对结论。界面能力须有真实浏览器证据；运行、恢复与来源能力按相应环境验证，纯文档检查不计作产品验收。
