# 关键词主动发现 PRD

日期：2026-09-17。状态：详细需求草案；承接既定范围 FR-001-003，保持 P0 优先级。本文是独立评审和验收依据，不代表功能已实现。对应 [执行计划](../plans/005-关键词主动发现计划.md) 已建立且为 planned；同编号 Design 与真实 Acceptance 尚未建立。

入口：[逐项 PRD 索引](README.md) · [平台需求总纲](001-热点事件监控平台功能与非功能需求.md) · [鱼皮项目功能研究](../research/001-热点事件监控平台调研.md)。

## 1. 背景、问题与用户价值

只在热榜里找关键词会漏掉尚未上榜的事件；只采热门又会漏掉正在发生的新内容。用户需要知道检索方式和结果范围。

总纲原始要求：在已接入平台执行关键词检索；同时支持最新与热门发现意图，保留原生排序与本地排序区别；支持时间/语言过滤、手动检索和定时检索。

研究者关注一款产品，既想看最近的新故障反馈，也想看互动最高的公开讨论。

## 2. 目标与成功指标

**BR-005-001：**在同一主题下提供可解释的最新与热门发现，保留查询范围、来源排序和采样边界。

| 指标 | 统计口径 | 目标或判定 |
|---|---|---|
| 查询执行一致性|实际请求与已保存查询版本的比对|全部验收请求一致 |
| 样本相关率|按总纲 Q0 对前十条人工评估|候选目标 ≥80%，分来源报告 |
| 来源说明完整率|结果含平台、排序、查询时间和范围|100% |

指标用于评审和后续测量，尚未取得运行结果。涉及新增数量、时长和默认值的建议须在实施前冻结；不据此扩大既定平台范围或付费权限。质量目标不以“页面有按钮”替代。

## 3. 范围、优先级与边界

- **本期范围（P0）：**关键词主动搜索、最新/热门意图、别名与排除规则、时间语言筛选、结果预览与监控结果关联。
- **明确不包括：**保证全部搜索命中、任意平台原生热门接口、自动扩成所有社交平台。
- **与相邻能力的边界：**热榜归 021，作者列表归 006；这里负责发现作品而非证明事件事实或完整评论。
- **发布条件：**本文件全部适用验收通过，并满足关联质量要求；缺失该能力不能用演示或其他功能替代 P0 完成。

## 4. 用户流程与关键结果

1. 从主题或独立搜索页输入关键词并选来源。
2. 展示来源支持的排序与限制，编译实际检索条件。
3. 按最新和热门两个通道分别执行有界检索。
4. 保存作品与多条发现依据，去重后应用相关性规则。
5. 展示分通道结果、失败来源与进入事件研究的入口。

完成后用户获得：有来源和查询依据的作品候选集及可复查采样记录。取消、失败或权限拒绝时，不显示与实际不符的成功结果。

## 5. 输入、配置与信息展示

| 信息项 | 规则与校验 | 默认或展示要求 |
|---|---|---|
| 查询词与别名|复用主题规则；独立查询也须有可保存版本|不自动扩词 |
| 排序意图|最新、热门分别执行；本地排序另标|不支持的原生排序不可冒充 |
| 时间与语言|验证来源操作符；无法原生过滤时标本地过滤|首次窗口建议 7 天 |
| 分页与条数|应用、连接和来源上限取更严格值|建议每通道最多 50 条，预算可提前截断 |

配置变更记录操作者、时间和版本；正在执行的操作绑定启动时的业务规则版本。当前权限、连接停用、删除要求与更严格预算始终优先，不能以旧版本继续越权或超额执行。冲突的输入必须明确拒绝或延期，不能静默修改用户意图。

## 6. 详细需求与业务规则

| 需求 ID | 规则 | 详细行为 | 对应验收 |
|---|---|---|---|
| FR-005-001 | 双通道 | 两类通道分别保存进度和结果出处，热门不能挤占全部新增发现预算。 | AC-005-002 |
| FR-005-002 | 查询可见 | 保留实际提交词、查询版本及时间条件；扩展词是否真正送至上游可核对。 | AC-005-003 |
| FR-005-003 | 顺序与截断 | 上游顺序不可靠时不得遇到一条旧帖就结束；达到页数/时间/预算必须标部分结果。 | AC-005-004 |
| FR-005-004 | 相关性过滤 | 字面和别名匹配附理由，排除优先；高互动不豁免相关性，也不以缺少互动直接排除新帖。 | AC-005-005 |
| FR-005-005 | 多主题归属 | 作品实体复用，主题命中和通道发现关系分别保存；不得覆盖先前的主题关联。 | AC-005-002 |
| FR-005-006 | 空与错 | 有效空结果、无权限、限流和解析失败分开；未接入平台不计为已成功搜索。 | AC-005-006 |

**DEC-005-001：**分别保留最新与热门证据，使用有界采样而不提供虚假的全网覆盖数量。

以上规则解释 FR-001-003，不重编号或替换总纲条目。后续发现冲突应显式更新总纲及受影响文档，不由某一页面或适配器单独改变语义。

## 7. 状态、异常与权限

| 状态或场景 | 展示与处理 |
|---|---|
| 搜索中|展示进行中的来源和已返回数量，不编造总体完成率。 |
| 正常/部分|列出结果与缺失来源、范围、排序和停止原因。 |
| 有效空/失败|空结果可以调整条件；失败按原因处理，不能自动放宽规则。 |
| 加载或执行中 | 展示已知阶段和可用操作；未知进度不用虚假百分比，已持久化历史结果可以继续查看。 |
| 无权访问 | 显示稳定的权限提示，不通过错误内容泄露其他使用者的数据或凭据。 |

仅所有者可执行使用其连接和预算的查询；保存结果仍受资料访问范围约束。

| 身份 | 访问与操作边界 |
|---|---|
| 资料或配置所有者 | 在本文件范围内处理自己的业务资料与配置；维护职责的动作仍须相应授权。 |
| 获授权维护者 | 仅诊断或维护明确授权的范围，不自动获得业务正文、规则修改或秘密回读权限。 |
| 其他身份 | 默认拒绝；仅在 026 团队协作正式启用且被显式授权后，按实际角色开放对应操作。 |

本项专门权限规则优先约束上述通用边界，后续角色设计不能扩大已有秘密或数据访问权限。

重复点击、刷新页面或网络重试不得重复产生同一业务结果；若本操作是有意新建的一次业务行为，必须有独立标识和清晰的版本/时间范围。

## 9. 验收标准

AC-001-003 是父级验收，本文件第一项完整保留其场景，其余补充边界、异常和业务细节。以下全部是待执行标准，不是已通过记录。

| 验收 ID | 场景 | Given：前提 | When：操作 | Then：可核查结果 |
|---|---|---|---|---|
| AC-005-001 | 总纲场景继承 | 关键词存在已知可访问的相关新帖和热门帖，配置了别名 | 分别运行两种发现任务并查看实际查询记录 | 保存返回作品、搜索条件和时间；明确别名仅本地匹配还是参与上游查询，扩展请求计入预算；未支持的原生排序明确标记。 |
| AC-005-002 | 热门与最新 | 两个通道命中同帖且各有独有作品 | 合并结果 | 作品不重复，保留全部通道和主题依据 |
| AC-005-003 | 上游扩词 | 规则含一个本地别名和一个检索别名 | 查看查询记录 | 仅明确启用的检索别名参与上游且计预算 |
| AC-005-004 | 非时间顺序 | 一页含旧帖后又含符合窗口的新帖 | 继续扫描 | 不因旧帖提前漏掉新帖，预算终止有记录 |
| AC-005-005 | 低互动新帖 | 新帖相关但互动为零 | 发现并排序 | 可以进入最新候选，高互动无关帖仍被排除 |
| AC-005-006 | 部分失败 | 一来源成功、一来源超时 | 查看结果 | 保留成功样本并明确失败，不把总计当全网总数 |

交付证据应包含输入/规则版本、执行记录、实际结果和人工核对结论。界面能力须有真实浏览器证据；运行、恢复与来源能力按相应环境验证，纯文档检查不计作产品验收。
