# 事件识别与归并 PRD

日期：2026-09-17。状态：详细需求草案；承接既定范围 FR-001-009，保持 P0 优先级。本文是独立评审和验收依据，不代表功能已实现。对应 [执行计划](../plans/011-事件识别与归并计划.md) 已建立且为 planned；同编号 Design 与真实 Acceptance 尚未建立。

入口：[逐项 PRD 索引](README.md) · [平台需求总纲](001-热点事件监控平台功能与非功能需求.md) · [鱼皮项目功能研究](../research/001-热点事件监控平台调研.md)。

## 1. 背景、问题与用户价值

用户关注的是一件具体发生的事情。将所有含同一品牌的内容混为一组，会把新品、召回和营销活动的评论与分数混在一起。

总纲原始要求：主题、事件、作品分层；按主体、发生事项和时间形成事件候选；支持跨平台归并、人工合并/拆分/移出及修改记录。

某品牌同一天发布新品并宣布旧产品召回，研究者需要分别分析，又希望把不同平台关于同一召回的内容合在一起。

## 2. 目标与成功指标

**BR-011-001：**形成可解释、可纠正的事件身份，使作品和讨论围绕同一具体事项组织。

| 指标 | 统计口径 | 目标或判定 |
|---|---|---|
| 自动归并精确率|Q0 中被判同事件的作品对经人工确认|候选目标 ≥90%，同时报告漏归并 |
| 人工修正可追溯率|合并/拆分/移出操作具备前后状态与原因|100% |
| 错误统计残留|移出作品仍贡献原事件当前指标的次数|0 |

指标用于评审和后续测量，尚未取得运行结果。涉及新增数量、时长和默认值的建议须在实施前冻结；不据此扩大既定平台范围或付费权限。质量目标不以“页面有按钮”替代。

## 3. 范围、优先级与边界

- **本期范围（P0）：**事件候选、事件名称和主体、跨平台关联、人工合并拆分/移出、关系历史和派生结果更新。
- **明确不包括：**把相似度直接当同事件、自动裁决事实真伪、永久删除被移出原始作品。
- **与相邻能力的边界：**一个主题包含多个事件，一件事件可被多个主题关注；去重作品不等于事件归并。
- **发布条件：**本文件全部适用验收通过，并满足关联质量要求；缺失该能力不能用演示或其他功能替代 P0 完成。

## 4. 用户流程与关键结果

1. 从相关作品提取主体、具体事项、时间与地点等已有信息。
2. 形成候选事件，显示建议关联及依据，模糊情况待复核。
3. 研究者确认、移入或移出作品，必要时创建独立事件。
4. 合并或拆分时预览作品、讨论、分数和报告影响。
5. 保留旧关系及操作记录，重算当前事件派生结果。

完成后用户获得：稳定事件身份、作品归属和有历史记录的人工纠正。取消、失败或权限拒绝时，不显示与实际不符的成功结果。

## 5. 输入、配置与信息展示

| 信息项 | 规则与校验 | 默认或展示要求 |
|---|---|---|
| 事件名称|概括具体事项，建议 1–120 字|自动建议可编辑，不用关键词直接代替 |
| 身份要素|主体、行为、对象、时间、地点可空|未知不编造 |
| 作品集合|只允许有权访问的作品；保留关联理由|一作品涉及多事项可多事件关联 |
| 纠正理由|合并、拆分和移出记录操作者与说明|高影响修改展示影响预览 |

配置变更记录操作者、时间和版本；正在执行的操作绑定启动时的业务规则版本。当前权限、连接停用、删除要求与更严格预算始终优先，不能以旧版本继续越权或超额执行。冲突的输入必须明确拒绝或延期，不能静默修改用户意图。

## 6. 详细需求与业务规则

| 需求 ID | 规则 | 详细行为 | 对应验收 |
|---|---|---|---|
| FR-011-001 | 身份原则 | 同主体不自动同事件；主体、具体事项和时空关系共同判断，模糊候选不得强行合并。 | AC-011-002 |
| FR-011-002 | 跨平台关系 | 各平台原作品保留独立身份；同稿转载可标关系，不能按平台条数虚增独立证据。 | AC-011-003 |
| FR-011-003 | 人工优先 | 已确认的排除/拆分约束在后续相似匹配中保留，自动任务不得静默撤销。 | AC-011-004 |
| FR-011-004 | 合并语义 | 确认目标事件及来源事件，保留可追踪别名/转向；统一当前关联但不删除原作品。 | AC-011-005 |
| FR-011-005 | 拆分与移出 | 明确每个作品的去向，允许暂不归属；相关评论随作品证据关联，不复制评论实体。 | AC-011-006 |
| FR-011-006 | 派生失效 | 修正后分数、时间线和报告标重算/过期；保留旧版引用，新的变化通知不得重复播报旧事件。 | AC-011-006 |

**DEC-011-001：**事件归并允许不确定和人工纠错，身份规则优先于单一语义相似度分数。

以上规则解释 FR-001-009，不重编号或替换总纲条目。后续发现冲突应显式更新总纲及受影响文档，不由某一页面或适配器单独改变语义。

## 7. 状态、异常与权限

| 状态或场景 | 展示与处理 |
|---|---|
| 候选/待确认|展示建议关系和不确定要素，允许保持未归类。 |
| 已确认/已合并|展示当前身份与来源，旧入口可找到变更说明。 |
| 重算中/冲突|保留可读旧版但标过期，冲突解决前不发布新分数。 |
| 加载或执行中 | 展示已知阶段和可用操作；未知进度不用虚假百分比，已持久化历史结果可以继续查看。 |
| 无权访问 | 显示稳定的权限提示，不通过错误内容泄露其他使用者的数据或凭据。 |

所有者可修正自己有权研究的事件；涉及他人未分享作品的批量合并不得执行；未来协作另按角色授权。

| 身份 | 访问与操作边界 |
|---|---|
| 资料或配置所有者 | 在本文件范围内处理自己的业务资料与配置；维护职责的动作仍须相应授权。 |
| 获授权维护者 | 仅诊断或维护明确授权的范围，不自动获得业务正文、规则修改或秘密回读权限。 |
| 其他身份 | 默认拒绝；仅在 026 团队协作正式启用且被显式授权后，按实际角色开放对应操作。 |

本项专门权限规则优先约束上述通用边界，后续角色设计不能扩大已有秘密或数据访问权限。

重复点击、刷新页面或网络重试不得重复产生同一业务结果；若本操作是有意新建的一次业务行为，必须有独立标识和清晰的版本/时间范围。

## 9. 验收标准

AC-001-009 是父级验收，本文件第一项完整保留其场景，其余补充边界、异常和业务细节。以下全部是待执行标准，不是已通过记录。

| 验收 ID | 场景 | Given：前提 | When：操作 | Then：可核查结果 |
|---|---|---|---|---|
| AC-011-001 | 总纲场景继承 | 同品牌同时有新品发布和召回，另有跨平台重复报道 | 归并并人工修正 | 保留两个事件；同事件关联多平台作品，修改可追溯且重新计算关联统计。 |
| AC-011-002 | 同主体分开 | 新品和召回含同一品牌词 | 自动生成事件候选 | 保留两个事件或待复核，不因品牌相同合并 |
| AC-011-003 | 转载去重 | 三平台发布同一通稿 | 关联同一事件 | 保留三个原帖但独立证据统计说明转载关系 |
| AC-011-004 | 人工约束 | 用户已把无关作品移出 | 下轮自动归并 | 不会静默加回，保留排除理由 |
| AC-011-005 | 合并保留 | 两个事件确认属于同一事项 | 合并并打开旧链接 | 新事件可见、旧入口有转向和操作记录 |
| AC-011-006 | 拆分重算 | 事件含两种事项且已有报告 | 拆分作品 | 评论不复制，旧报告标过期，当前指标重算 |

交付证据应包含输入/规则版本、执行记录、实际结果和人工核对结论。界面能力须有真实浏览器证据；运行、恢复与来源能力按相应环境验证，纯文档检查不计作产品验收。
