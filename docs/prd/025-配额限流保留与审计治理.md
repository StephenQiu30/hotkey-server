# 配额限流保留与审计治理

## 用户问题

来源速率、AI 预算账本、保留策略、审计日志和运行概览已有基础，但缺少面向用户的统一监控数、手动搜索数和模型用量配额。

## 产品目标

控制用户、监控、来源和模型成本，提供明确剩余额度、重置时间和管理员治理能力。

## 范围

- 配额策略和用量账本
- 限流、预留、结算与超限反馈
- 数据保留和清理任务
- 管理员治理总览与审计查询

## 用户故事

- 作为阅读者，我能快速看到重要变化、依据、可信程度和更新时间。
- 作为编辑者，我能从发现、研判到处理和交付完成闭环。
- 作为管理员，我能查看成本、失败、权限和审计并安全恢复。

## 功能要求

- FR-025-1：配额维度至少包含 active monitors、manual searches/day、source calls、AI tokens/cost 和通知投递；按用户/工作区和时间窗记账。
- FR-025-2：先在事务中 reservation，再执行外部调用，完成后 settle；失败按规则释放或记实际成本，避免并发超卖。
- FR-025-3：来源 429 与产品配额分开表达；响应包含稳定错误码、limit、remaining、reset_at。
- FR-025-4：内容、指标、会话、任务和审计采用独立保留策略；核心事件、发布报告与审计不得被普通清理静默删除。

## 非功能要求

- 写操作具备认证授权、审计、幂等或乐观锁；异步操作可追踪和重试。
- 列表使用稳定分页，慢任务不阻塞 HTTP；错误使用统一业务码。
- 前端使用 shadcn/ui/Radix 组合，覆盖响应式、键盘、焦点、对比度与减弱动效。

## 非目标

不以静态 Mock、不可追溯模型文本或仅桌面可用页面通过验收。

## 验收标准

- AC-025-1：并发请求不会突破硬配额
- AC-025-2：用户能在触发前看到剩余手动搜索/AI 额度
- AC-025-3：保留任务具有 dry-run、批量上限和不可删事实保护
