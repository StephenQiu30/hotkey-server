# 采集批次原子重试

## 范围

- 保持现有管理员重试 API，在同一事务中重置业务批次并重新激活原 `collect_source` 任务。
- 保持稳定唯一键和小型 ID/version/window envelope，不创建重复任务；以 source/query claim lock 与 checkpoint CAS 恢复原窗口。
- 覆盖成功、任意较新窗口冲突、较新 checkpoint 冲突、目标失效、任务缺失、非法任务状态、事务回滚、重复请求和 Worker 后续领取。

## 非目标

- 不改变 API DTO、Schema、OpenAPI、自动重试次数或 Connector 行为。
- 不重试成功、运行中或已排队批次，不从 HTTP 同步采集。

## 验收条件

1. failed/cancelled 批次、其 targets、仍未被较新成功推进的 checkpoints 与对应 discarded/cancelled/available 任务在同一事务变为 queued/queued/原窗口/available。
2. 原任务 ID 与唯一键不变；历史 attempt/error 保留，终态任务只增加一个 max attempt，Worker 可重新解析 target 并执行该 run。
3. 存在任意较新窗口 run、checkpoint 已被较新事实推进、目标不再 eligible、任务缺失、completed/running 状态或队列写失败时，批次、targets 与 checkpoints 不发生任何变化。
4. 两个并发重试最多一个成功，第二个得到稳定冲突。
5. Retry 与较新窗口 Worker 并发时只能有一个窗口完成 claim；不得产生额外 queued/failed run，也不得让旧、新窗口并行 Fetch。
6. HTTP 权限、业务码、安全 DTO、Schema 与 OpenAPI 均无漂移；完整质量门禁通过。
