# 可观测性部署与质量门禁

## 用户问题

项目已有 health/readiness/metrics、结构化日志、OpenTelemetry 基础、运行概览、单二进制角色、双环境 Compose、后端 CI 和前端构建测试入口。

## 产品目标

让 MVP 在本地和生产可重复部署、诊断、升级和回滚，并以端到端质量门禁约束所有 001–027 实现。

## 范围

- 健康、指标、日志、追踪和运行总览
- 开发/生产容器部署
- CI、契约、浏览器和安全门禁
- 备份恢复、发布回滚和容量基线

## 用户故事

- 作为阅读者，我能快速看到重要变化、依据、可信程度和更新时间。
- 作为编辑者，我能从发现、研判到处理和交付完成闭环。
- 作为管理员，我能查看成本、失败、权限和审计并安全恢复。

## 功能要求

- FR-028-1：保持 all/api/worker 三种角色和 PostgreSQL、Redis、MinIO 基础设施；开发与生产只通过根 Compose 覆盖环境差异。
- FR-028-2：每个外部来源、任务种类和 API 暴露 latency、success/failure、retry、queue lag、quota 和 cost 指标，标签不得含用户内容或高基数字段。
- FR-028-3：CI 顺序包含架构门禁、Schema 验证、OpenAPI 漂移、后端测试、前端类型/单测/构建和 Compose 配置。
- FR-028-4：备份恢复、密钥轮换、来源授权和故障处置在对应功能验收后形成 Operations；发布使用向前兼容和能力开关。

## 非功能要求

- 写操作具备认证授权、审计、幂等或乐观锁；异步操作可追踪和重试。
- 列表使用稳定分页，慢任务不阻塞 HTTP；错误使用统一业务码。
- 前端使用 shadcn/ui/Radix 组合，覆盖响应式、键盘、焦点、对比度与减弱动效。

## 非目标

不以静态 Mock、不可追溯模型文本或仅桌面可用页面通过验收。

## 验收标准

- AC-028-1：全新环境按 README 可启动并通过 readiness
- AC-028-2：任一流水线失败能定位到来源、运行和任务而不泄露内容
- AC-028-3：main 分支不能合入 Schema/OpenAPI/生成客户端漂移
