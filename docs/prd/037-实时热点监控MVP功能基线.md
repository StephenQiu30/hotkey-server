# 实时热点监控 MVP 功能基线

## 用户问题

需要持续关注产品、公司、人物或技术主题的用户，不想反复打开多个平台手工搜索。他们希望只配置监控词，就能持续看到新出现且与主题相关的内容，在重要信息出现时立即收到页面或邮件提醒，也能随时发起一次临时多源搜索。

此前的范围把热点监控扩展成了事件情报、证据图谱和知识管理平台，增加了首版交付成本。本 PRD 以 [`liyupi/yupi-hot-monitor@cd48b08`](https://github.com/liyupi/yupi-hot-monitor/tree/cd48b0885bfa8ae9c8043cf78ef6cfd045530bdb) 的真实可用闭环为最低线，并修复它已经确认的断链，不复制其未接线声明。

## 产品目标

用户能在一个响应式工作台内完成以下闭环：

```text
添加监控词
→ 等待自动扫描或点击立即扫描
→ 从多个来源发现新内容
→ 查看 AI 摘要、相关性、重要性与热度
→ 筛选、排序并访问原文
→ 在铃铛和邮件中收到重要热点
```

同一套多源搜索还要通过 Web 即时搜索页面使用。

## 成功定义

- 用户无需理解来源连接、任务或事件模型，即可创建监控并看到第一批结果。
- 自动扫描真实覆盖文档声明的来源；任何来源不可用时明确展示，不静默返回空。
- 新热点提交后 2 秒内出现在在线页面，重要热点按规则发送邮件。
- 列表卡片、筛选、排序和即时搜索使用同一热点字段与判断结果。
- 产品不把一次 LLM 判断宣传为已完成事实核验。

## MVP 范围

### 监控词

- FR-037-1：用户可以创建、编辑、暂停、恢复和删除 Monitor；名称/查询去除首尾空白，同一用户下的等价查询不得重复创建。
- FR-037-2：Monitor 卡片展示启用状态、累计命中数和最近一次扫描状态；新增后提供“立即扫描”。
- FR-037-3：暂停或删除后不再进入后续扫描；历史热点保留。删除必须二次确认。

### 扫描

- FR-037-4：启用 Monitor 默认每 30 分钟自动扫描；手动扫描立即排队，并展示排队、运行、部分成功、成功或失败状态。
- FR-037-5：同一 Monitor 同一时刻只允许一轮扫描；重复点击复用已有任务，不产生重叠采集。
- FR-037-6：单来源失败不阻塞其他来源；扫描结果必须逐一返回来源的成功、空、失败或不可用状态。

### 来源

- FR-037-7：Web 自动监控主链至少提供以下六类实际能力：X/Twitter 内容、Bing 类网页搜索、Hacker News 最新内容、搜狗类中文网页发现、Bilibili 视频/账号更新、微博热榜/关键词内容。
- FR-037-8：Web 即时搜索复用当前已配置的合规来源；可额外使用 Google 授权搜索、DuckDuckGo Instant Answer 和 RSS/Atom，但必须如实展示能力限制。
- FR-037-9：所有来源只能通过官方 API、RSS/Atom 或明确授权 Feed；来源未授权或未配置时显示实际状态，禁止隐藏 HTML 抓取、Cookie 伪造或反爬绕过。

### 发现与 AI

- FR-037-10：系统对每个 Monitor 生成原词和 3–8 个受控查询变体；具备搜索能力的来源必须真实使用变体进行检索。
- FR-037-11：来源结果统一为标题、内容摘要、原文 URL、来源、外部 ID、发布时间、发现时间、作者和可用互动指标；缺失字段保持未知。
- FR-037-12：有明确发布时间且早于 7 天的候选默认不进入首轮热点；无法取得发布时间的结果可以保留并标记未知。
- FR-037-13：优先按 `source + external_id` 去重，没有外部 ID 时按规范 URL 去重；去除已知跟踪参数和 fragment。
- FR-037-14：同一 Hotspot 可同时命中多个 Monitor，并为每个 Monitor 保存独立相关性和通知；同一 Monitor 不重复通知。
- FR-037-15：AI 为每个候选返回质量状态、0–100 相关性、理由、是否直接提词、`low/medium/high/urgent` 重要性和一句话摘要。
- FR-037-16：默认拒绝相关性低于 50 的内容；未直接提词且相关性低于 65 时也拒绝。可疑内容默认不出现在普通热点流，但可通过质量筛选查看。
- FR-037-17：AI 不可用时结果显示“未分析”，不得自动标为可信，也不得触发高/紧急邮件。

### 热点雷达

- FR-037-18：热点雷达展示总热点、今日新增、紧急热点和启用 Monitor 数。
- FR-037-19：热点卡片展示重要性、来源、命中 Monitor、AI 质量状态、热度、标题、摘要、作者、可用互动指标、发布时间、发现时间、判断理由、原始摘要/片段和原文链接。
- FR-037-20：热点列表支持分页，以及来源、重要性、Monitor、时间范围、AI 质量状态的组合筛选。
- FR-037-21：列表支持最新发现、最新发布、重要性、相关性和热度排序；服务端返回的同一个 `heat_score` 同时用于排序和卡片展示。
- FR-037-22：重复发现已有 Hotspot 时更新最后发现时间和最新互动指标，不新增重复卡片或重复通知；MVP 不要求保存完整指标历史曲线。

### 即时搜索

- FR-037-23：用户可以用临时 query 搜索全部当前可用来源或指定来源，并看到各来源成功/失败状态。
- FR-037-24：即时搜索返回与热点雷达相同的卡片 DTO，AI 字段不得藏在前端不读取的子对象中。
- FR-037-25：即时结果默认不持久化、不创建 Monitor、不生成站内通知或邮件；结果集支持来源、重要性、时间和质量筛选及五种排序。

### 通知与邮件

- FR-037-26：每个新接受的 MonitorMatch 在同一事务中创建持久站内通知，事务提交后再发送 WebSocket 事件。
- FR-037-27：在线页面在事件提交后 2 秒内更新热点流、Toast、铃铛未读数和最近通知；重连后重新订阅并补拉断线缺口。
- FR-037-28：通知只通过顶栏右侧铃铛进入，不作为一级菜单项；铃铛支持未读数、最近 5 条通知、跳转热点和全部已读。
- FR-037-29：`high` 和 `urgent` 热点发送即时邮件，包含标题、摘要、来源、相关性、Monitor 和原文链接；`low/medium` 不发。
- FR-037-30：SMTP 未配置或暂时失败不影响热点和站内通知，邮件独立重试并保留投递结果。

### 响应式界面

- FR-037-31：桌面与 390px 移动端都能完成创建监控、立即扫描、筛选、查看卡片、打开铃铛和访问原文；移动端不能依赖 hover 才显示关键操作。

## 来源能力验收矩阵

| 来源能力 | 自动扫描 | Web 即时搜索 | 发布前要求 |
|---|---:|---:|---|
| X/Twitter | 是 | 是 | 官方 API fixture、限流和真实授权冒烟 |
| Bing 类网页搜索 | 是 | 是 | 授权搜索 API fixture 和真实冒烟 |
| Hacker News | 是 | 是 | 官方 API fixture 和公开端点冒烟 |
| 授权中文网页发现 | 是 | 是 | 授权 Feed/API；无授权时不得以搜狗名义发布 |
| Bilibili | 是 | 是 | 开放平台/授权 webhook fixture 与授权冒烟 |
| 微博 | 是 | 是 | 开放平台/授权 Feed，并标明热榜或全文能力 |
| Google | 非必需 | 可选 | Google Agent Search/授权 API |
| DuckDuckGo | 非必需 | 可选 | 官方 Instant Answer，并标明能力限制 |
| RSS/Atom | 可选增强 | 可选增强 | 标准 Feed 与权利策略 |

来源未通过真实授权冒烟前，只能标记为“适配已实现、连接未验证”，不能计入对外可用来源数。

## 核心用户故事与验收

### AC-037-1：创建、暂停、恢复和删除

```gherkin
Given 当前用户不存在名为 "Claude" 的 Monitor
When 用户输入 " Claude " 并创建
Then 页面显示已启用的 "Claude" Monitor
And 刷新后仍然存在
And 用户可以立即扫描

When 用户暂停并触发扫描
Then 本轮不处理 "Claude"
And 历史热点仍可查看

When 用户恢复后再次扫描
Then "Claude" 重新参与扫描
And 当前页面恢复它的实时订阅
```

### AC-037-2：六类来源与部分成功

```gherkin
Given 一个启用 Monitor 选择了六类 Web 来源
And 其中一个来源超时，另一个来源返回空，其余来源返回候选
When 自动或手动扫描完成
Then 扫描状态为 partial
And 页面分别显示失败、空和成功来源
And 成功来源的合格热点仍然入库并通知
```

### AC-037-3：去重与多 Monitor 命中

```gherkin
Given 同一 X 帖子同时匹配 "Claude" 和 "Anthropic"
When 两个 Monitor 完成扫描
Then 系统只保存一个 Hotspot
And 保存两个 MonitorMatch
And 两个 Monitor 分别产生一次通知

When 下一轮再次发现该帖子
Then 更新最后发现时间和最新指标
And 不产生重复通知
```

### AC-037-4：AI 判断与降级

```gherkin
Given 候选包含高相关、低相关、可疑和 AI 超时四种结果
When 扫描完成
Then 高相关结果进入默认热点流
And 低相关结果按 50/65 阈值拒绝
And 可疑结果只在质量筛选下可见
And AI 超时结果显示未分析且不发高优先级邮件
```

### AC-037-5：热点雷达与排序

```gherkin
Given 数据库有超过一页、来自不同来源和 Monitor 的热点
When 用户组合筛选来源、重要性、Monitor、时间和质量状态
Then 所有结果同时满足条件
And 翻页无重复或跳项

When 用户依次选择五种排序
Then 服务端稳定返回正确顺序
And 热度排序值与卡片展示值完全一致
```

### AC-037-6：即时搜索

```gherkin
Given 至少三个来源可用且一个来源失败
When 用户执行临时多源搜索
Then 页面展示成功来源的统一热点卡片
And 展示失败来源及原因
And 每条卡片正确显示 AI 字段和原文链接
And 结果不会写入监控历史或创建通知
```

### AC-037-7：实时、断线与铃铛

```gherkin
Given 页面在线并订阅 "Claude"
When 后端提交一个新的 "Claude" 热点和通知
Then 2 秒内热点出现在列表顶部
And Toast、铃铛未读数及最近通知同步更新

When WebSocket 断线后重连
Then 客户端重新订阅所有启用 Monitor
And 补拉断线期间的通知
And 同一热点不重复显示
```

### AC-037-8：邮件

```gherkin
Given SMTP 配置有效
When 新热点重要性为 high 或 urgent
Then 收件人收到包含摘要、来源、相关性、Monitor 和原文链接的邮件

When 重要性为 low 或 medium
Then 不发送即时邮件

Given SMTP 暂时失败
When 扫描发现新热点
Then 热点与站内通知仍成功
And 邮件进入有界重试并记录结果
```

### AC-037-9：移动端

```gherkin
Given 视口宽度为 390px
When 用户完成创建监控、立即扫描、筛选、打开铃铛和访问原文
Then 页面无横向滚动
And 关键按钮无需 hover 即可见
And 通知面板不超出视口
And 交互目标至少为 44x44 CSS 像素
```

## 非功能要求

- NFR-037-1：普通已缓存页面首屏在目标环境 3 秒内可交互；热点/通知读 API 在正常数据量下 P95 小于 1 秒。
- NFR-037-2：筛选、排序和分页在 PostgreSQL 完成，不把全量热点加载到应用内存。
- NFR-037-3：扫描、热点、Match 和通知具备确定性幂等键；服务重启或任务重试不得重复通知。
- NFR-037-4：来源、AI 和 SMTP 调用均有超时、限流和安全错误；密钥不得出现在日志、前端或响应中。
- NFR-037-5：来源名称、可用状态和产品宣传必须由实际能力矩阵驱动，不能保留未接线筛选项。
- NFR-037-6：WebSocket 不是事实源；页面刷新和重连后可以从 PostgreSQL 恢复一致状态。
- NFR-037-7：所有跨端 DTO 来自发布 OpenAPI 和生成客户端，不允许前端手写第二套分析结构。

## 非目标

- 语义事件聚类、跨来源事件生命周期、Claim/Evidence 图谱和事实概率。
- 评论/回复正文、评论树、浏览器自动化和通用网页爬虫。
- 日报/周报 Web 产品、知识库、自动发帖、主题换肤和通用设置中心。
- 来源级流式采集、Web Push、系统通知和指标历史趋势图。
- 新建微服务、Kafka、图数据库、向量数据库或第二套热点事实。

已有用户认证、权限、来源权利和审计继续生效，但不属于本 PRD 的新增产品功能。
