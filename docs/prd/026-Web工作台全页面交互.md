# Web工作台全页面交互

## 用户问题

已有首页、认证、Radar、监控、来源、内容列表/详情、事件、告警、订阅、资料和设置页面；reports 与 users 管理页缺失，topics/favorites 为旧重定向，部分复杂页状态与移动体验不完整。

## 产品目标

用 Next.js+TypeScript+shadcn/ui+Radix+Tailwind 全面完成所有页面，使用户从创建监控到阅读证据、处理告警和发布报告无需离开工作台。

## 范围

- 公共首页与完整认证流
- Overview、监控、来源、内容、事件和告警
- 报告、订阅、用户管理、资料与系统设置
- 响应式导航、全状态、可访问性和错误恢复

## 用户故事

- 作为阅读者，我能快速看到重要变化、依据、可信程度和更新时间。
- 作为编辑者，我能从发现、研判到处理和交付完成闭环。
- 作为管理员，我能查看成本、失败、权限和审计并安全恢复。

## 功能要求

- FR-026-1：信息架构固定为 Overview、Monitors、Sources、Contents、Events、Alerts、Reports、Subscriptions、Administration、Profile；移除无业务意义旧入口。
- FR-026-2：Overview 采用 Vercel 式密集但克制的网格：关键指标、趋势事件、运行状态和快捷动作，不使用装饰性大卡片堆叠。
- FR-026-3：列表页统一 Search/Filter/Sort/Table-or-Card/Pagination；详情页统一 Header/Summary/Tabs-or-Sections/Timeline/Actions。
- FR-026-4：服务端组件负责壳和可静态内容，交互数据区使用客户端组件；复杂编辑使用 React Hook Form+Zod（引入前先确认现有依赖），基础控件只用 shadcn/ui。

## 非功能要求

- 写操作具备认证授权、审计、幂等或乐观锁；异步操作可追踪和重试。
- 列表使用稳定分页，慢任务不阻塞 HTTP；错误使用统一业务码。
- 前端使用 shadcn/ui/Radix 组合，覆盖响应式、键盘、焦点、对比度与减弱动效。

## 非目标

不以静态 Mock、不可追溯模型文本或仅桌面可用页面通过验收。

## 验收标准

- AC-026-1：导航没有死链或只重定向的遗留主入口
- AC-026-2：全部页面覆盖 loading/empty/error/forbidden 并可键盘操作
- AC-026-3：360px、768px、1280px 关键视口完成浏览器端到端验证
