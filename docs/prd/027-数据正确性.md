# 数据正确性 PRD

日期：2026-09-17。状态：详细需求草案；承接既定范围 NFR-001-001，保持 P0 优先级。本文是独立评审和验收依据，不代表功能已实现。对应 [执行计划](../plans/027-数据正确性计划.md) 已进入 `in_progress`，[Design](../design/027-数据正确性设计.md) v1.0 已接受 S00；真实 Acceptance 尚未建立。

入口：[逐项 PRD 索引](README.md) · [平台需求总纲](001-热点事件监控平台功能与非功能需求.md) · [鱼皮项目功能研究](../research/001-热点事件监控平台调研.md)。

## 1. 背景、问题与用户价值

错误的身份、关系或计数会直接影响事件排序与分析，即使页面显示正常也不能接受。正确性必须有可重放样本和明确的不变量。

总纲原始要求：已验收输入中，原生 ID、作者归属、父子关系和时间不得因系统处理发生错误；同平台同 ID 唯一；缺失值与零区分；记录与提醒幂等。

研究者多次抓取同一讨论，运维重放失败消息后，仍应看到相同实体数、正确作者和完整父子关系。

## 2. 目标与成功指标

**BR-027-001：**确保系统在规范化、重复处理和更新过程中不制造错误数据，未知项与真实零有明确差异。

| 指标 | 统计口径 | 目标或判定 |
|---|---|---|
| 重复实体率|相同来源原生身份被重复建立的额外实体/有效身份|测试为 0 |
| 关系错误率|错误作者/父子/引用关联数/已标注关联数|测试为 0 |
| 缺失误填率|未知指标或时间被自动补成有意义值的次数|0 |

指标用于评审和后续测量，尚未取得运行结果。涉及新增数量、时长和默认值的建议须在实施前冻结；不据此扩大既定平台范围或付费权限。质量目标不以“页面有按钮”替代。

## 3. 范围、优先级与边界

- **本期范围（P0）：**身份唯一、字段语义、关系、时间、内容版本、重复重放与异常数据隔离。
- **明确不包括：**承诺上游全部真实或完整、以本地正确性证明平台召回、强行修复未知原文。
- **与相邻能力的边界：**正确性针对已接受输入的处理；来源完整度由能力和采样状态表达，分析效果由 041 验证。
- **发布条件：**本文件全部适用验收通过，并满足关联质量要求；缺失该能力不能用演示或其他功能替代 P0 完成。

## 4. 用户流程与关键结果

1. 建立含原始来源与人工预期的冻结样本。
2. 对输入进行身份、字段和关系校验，异常项保留原因。
3. 处理正常、重复、乱序与冲突更新。
4. 对实体、关系、快照、统计和提醒逐层对账。
5. 记录发现的错误和修复复测结果，未通过不发布依赖功能。

完成后用户获得：数据不变量清单、逐字段对账结果和可复现异常样本。取消、失败或权限拒绝时，不显示与实际不符的成功结果。

## 5. 输入、配置与信息展示

| 信息项 | 规则与校验 | 默认或展示要求 |
|---|---|---|
| 身份键|来源、对象类型、原生 ID 及来源必要作用域|ID 以字符串输出 |
| 字段字典|零/未知、指标含义、时间精度、作者关系|逐来源登记 |
| 样本集|重复、乱序、重名、缺父帖、引用、编辑和删除|覆盖所有启用来源 |
| 异常记录|保留错误类别与可复核输入引用|脱敏且遵守保留期 |

配置变更记录操作者、时间和版本；正在执行的操作绑定启动时的业务规则版本。当前权限、连接停用、删除要求与更严格预算始终优先，不能以旧版本继续越权或超额执行。冲突的输入必须明确拒绝或延期，不能静默修改用户意图。

## 6. 详细需求与业务规则

| 需求 ID | 规则 | 详细行为 | 对应验收 |
|---|---|---|---|
| NFR-027-001 | 身份唯一 | 同一有效原生身份只有一个实体；重复发现可增加关系但不重复实体或新作通知。 | AC-027-002 |
| NFR-027-002 | 关系校验 | 作者、父评论、根作品、引用与转帖分别有语义；父数据未获取保留明确缺失状态而非猜测。 | AC-027-003 |
| NFR-027-003 | 缺失与单位 | 0、null、未知、未支持分别表达；不同来源的评论/回复/弹幕/浏览单位不得混加。 | AC-027-004 |
| NFR-027-004 | 时间与版本 | 发布、发生、观察时间及精度分别保留；内容更新有版本，乱序旧结果不能静默覆盖新事实。 | AC-027-005 |
| NFR-027-005 | 冲突隔离 | 身份或关键字段冲突的输入进入待核对，不用默认值掩盖；总体任务标部分或数据异常。 | AC-027-006 |
| NFR-027-006 | 可重放对账 | 固定数据重放 3 次后实体与业务通知不变，允许新观察形成新快照但需有明确观察身份。 | AC-027-002 |

**DEC-027-001：**将身份、关系和口径作为发布不变量，异常输入可部分隔离而不能静默变成正常数据。

以上规则解释 NFR-001-001，不重编号或替换总纲条目。后续发现冲突应显式更新总纲及受影响文档，不由某一页面或适配器单独改变语义。

## 7. 状态、异常与权限

| 状态或场景 | 展示与处理 |
|---|---|
| 校验通过|资料可参与当前规则的统计与分析。 |
| 字段不完整|能安全使用的范围可用，缺失明确显示。 |
| 关键冲突/隔离|不进入会产生误导的分析，保留核对与修正路径。 |
| 加载或执行中 | 展示已知阶段和可用操作；未知进度不用虚假百分比，已持久化历史结果可以继续查看。 |
| 无权访问 | 显示稳定的权限提示，不通过错误内容泄露其他使用者的数据或凭据。 |

维护者查看脱敏质量记录；原始正文的人工核对仍须资料读取权限，不能借诊断导出越权数据。

| 身份 | 访问与操作边界 |
|---|---|
| 资料或配置所有者 | 在本文件范围内处理自己的业务资料与配置；维护职责的动作仍须相应授权。 |
| 获授权维护者 | 仅诊断或维护明确授权的范围，不自动获得业务正文、规则修改或秘密回读权限。 |
| 其他身份 | 默认拒绝；仅在 026 团队协作正式启用且被显式授权后，按实际角色开放对应操作。 |

本项专门权限规则优先约束上述通用边界，后续角色设计不能扩大已有秘密或数据访问权限。

重复点击、刷新页面或网络重试不得重复产生同一业务结果；若本操作是有意新建的一次业务行为，必须有独立标识和清晰的版本/时间范围。

## 8. 依赖、质量与验证环境

- **依赖或关联 PRD：**[007 作品资料与上下文](007-作品资料与上下文.md)、[008 评论与回复采集](008-评论与回复采集.md)、[010 增量更新与历史回补](010-增量更新与历史回补.md)、[013 相关性与热度排序](013-相关性与热度排序.md)。
- **适用质量要求：**本文件即质量要求的细化，受总纲免费、数据边界和真实验收约束。
- **验证口径：**每个启用来源至少包含一组身份与字段样本；冻结预期表，重放 3 次，并执行重复消息/乱序/缺失故障验证。真实上游完整性不在该通过结论中。

总纲质量目标：固定含重复、引用、重名、缺父帖、缺指标的样本，重跑 3 次：重复实体和重复提醒为 0，关系断言全部通过。真实平台召回率另报。
来源访问条件未满足时，使用受控样本验证内部规则，并单独记录真实来源验证未完成；不能用模拟成功冒充真实平台接入。涉及性能沿用总纲 B0，分析质量沿用 Q0；未采用相关基线时需注明适用样本和环境。

## 9. 验收标准

AC-001-025 是父级验收，本文件第一项完整保留其场景，其余补充边界、异常和业务细节。以下全部是待执行标准，不是已通过记录。

| 验收 ID | 场景 | Given：前提 | When：操作 | Then：可核查结果 |
|---|---|---|---|---|
| AC-027-001 | 总纲场景继承 | 输入含重复作品和两层回复 | 重跑并对照冻结样本 | 实体唯一、作者和父子关系正确；不把缺失指标补成 0。 |
| AC-027-002 | 重复身份 | 同一页及消息各重放三次 | 归一化并统计 | 实体和新作通知不增加，发现关系保持合法 |
| AC-027-003 | 缺失父链 | 子回复可见但父帖缺失 | 建立关系 | 保留父标识和缺失提示，不错接其他根帖 |
| AC-027-004 | 零与单位 | 0 点赞、未知播放、弹幕 100 | 展示与计算 | 保留不同语义，弹幕不冒充评论 |
| AC-027-005 | 乱序更新 | 新正文后收到旧观察 | 应用更新 | 不静默覆盖新版本，仍可追溯旧观察 |
| AC-027-006 | 关键冲突 | 相同身份对应不一致作者 | 导入 | 隔离或待核对，任务不虚报完整正确 |

交付证据应包含输入/规则版本、执行记录、实际结果和人工核对结论。界面能力须有真实浏览器证据；运行、恢复与来源能力按相应环境验证，纯文档检查不计作产品验收。
