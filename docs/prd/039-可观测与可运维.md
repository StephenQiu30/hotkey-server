# 可观测与可运维 PRD

日期：2026-09-17。状态：详细需求草案；承接既定范围 NFR-001-013，保持 P0 优先级。本文是独立评审和验收依据，不代表功能已实现。对应 [执行计划](../plans/039-可观测与可运维计划.md) 已建立且为 planned；同编号 Design 与真实 Acceptance 尚未建立。

入口：[逐项 PRD 索引](README.md) · [平台需求总纲](001-热点事件监控平台功能与非功能需求.md) · [鱼皮项目功能研究](../research/001-热点事件监控平台调研.md)。

## 1. 背景、问题与用户价值

持续监控失败时，使用者需要知道影响了哪个主题、哪个来源和哪个阶段。仅展示累计采集条数既不能发现陈旧资料，也不能解释关键词配置修改后的变化。

总纲原始要求：能定位哪个主题、来源、阶段失败；统计成功/部分/失败、限流、排队、请求量、解析异常和数据新鲜度；关键配置变更留痕。

某个来源连续三轮失败后用户修改监控词，排查页面应能关联每轮任务、当时的配置版本与稳定错误原因，同时不把敏感关键词或秘密写进一般日志。

## 2. 目标与成功指标

**BR-039-001：**让用户理解当前覆盖和缺口，让维护者用最少必要信息定位失败、采取动作并验证恢复。

| 指标 | 统计口径 | 目标或判定 |
|---|---|---|
| 失败可定位率|具有来源/能力/阶段、关联 ID、稳定原因及下一步的失败任务占比|100% |
| 状态统计一致性|任务明细与成功、部分、失败、延期、取消等聚合统计差异|0；同一口径和时间窗口可核对 |
| 数据陈旧可见性|存在连续失败或超过有效新鲜度目标时是否有明确提示|全部受测场景可见，恢复不能删除历史故障 |

指标用于评审和后续测量，尚未取得运行结果。涉及新增数量、时长和默认值的建议须在实施前冻结；不据此扩大既定平台范围或付费权限。质量目标不以“页面有按钮”替代。

## 3. 范围、优先级与边界

- **本期范围（P0）：**任务与阶段记录、结构化状态统计、预算及新鲜度展示、配置审计、问题提示和运维排查入口。
- **明确不包括：**首版建设昂贵外部观测平台、永久保存所有正文日志、把请求成功率当作全网覆盖率、把没有错误日志当作采集完成。
- **与相邻能力的边界：**017 管业务提醒与问题去重，024 管外部投递；本文件提供可信运行事实。029 定义新鲜度，031 定义内部执行率，二者口径不混用。
- **发布条件：**本文件全部适用验收通过，并满足关联质量要求；缺失该能力不能用演示或其他功能替代 P0 完成。

## 4. 用户流程与关键结果

1. 调度或用户操作生成可贯穿阶段的关联标识和配置版本。
2. 执行记录排队、请求、解析、保存、分析等实际发生阶段。
3. 汇总可相互核对的状态、消耗、新鲜度与失败范围。
4. 用户从受限提示进入任务详情，看到原因和适用处理动作。
5. 维护者修复并验证恢复，保留原故障、处理及恢复时间线。

完成后用户获得：能从平台状态追溯到具体任务和配置的排查记录。取消、失败或权限拒绝时，不显示与实际不符的成功结果。

## 5. 输入、配置与信息展示

| 信息项 | 规则与校验 | 默认或展示要求 |
|---|---|---|
| 关联标识|主题、来源、连接引用、能力、任务及阶段 ID|不将秘密或完整关键词拼入 ID |
| 状态口径|成功、部分、失败、延期、取消、执行中分别统计|同一任务重试为执行尝试，不重复当新业务任务 |
| 新鲜度与消耗|计划、开始、最后成功、最后尝试、请求量、保存量和限额|未知显示未知，不填零或伪造更新时间 |
| 配置审计|记录修改者、时间、版本和脱敏变更摘要|一般日志不包含正文、敏感搜索词及秘密 |

配置变更记录操作者、时间和版本；正在执行的操作绑定启动时的业务规则版本。当前权限、连接停用、删除要求与更严格预算始终优先，不能以旧版本继续越权或超额执行。冲突的输入必须明确拒绝或延期，不能静默修改用户意图。

## 6. 详细需求与业务规则

| 需求 ID | 规则 | 详细行为 | 对应验收 |
|---|---|---|---|
| NFR-039-001 | 可串联记录 | 同一业务任务的请求、重试、保存和分析可按关联 ID 追踪，并绑定来源能力与配置版本；跨进程恢复不丢失关联，记录时钟与时区一致。 | AC-039-002 |
| NFR-039-002 | 统计真实互斥 | 业务任务状态按统一规则聚合，部分结果、延期和取消不合并为成功；尝试次数另算，失败重试不能放大成功任务数，聚合可回到明细核对。 | AC-039-003 |
| NFR-039-003 | 错误分类与动作 | 区分来源拒绝、授权失效、限流、网络、解析、内部执行、预算和权限错误；每个失败有稳定类别、实际影响与下一步，不只输出异常堆栈。 | AC-039-004 |
| NFR-039-004 | 新鲜度与问题提示 | 分别显示最后成功与最后尝试；连续失败和陈旧提示按影响范围去重，恢复后关闭当前问题但保留历史。单次空结果成功不能被当作有新内容。 | AC-039-005 |
| NFR-039-005 | 脱敏与最小留存 | 一般日志和指标不收秘密、完整正文或敏感关键词；必要排障详情按权限单独控制且有保留期，不能因调试开启全量永久记录。 | AC-039-006 |
| NFR-039-006 | 审计与运维闭环 | 配置变更、暂停/恢复、重试、删除和预算调整有操作者与版本记录；维护者能按提示找到受影响任务、采取适用动作并核查恢复，不能直接改状态伪造成功。 | AC-039-002、AC-039-006 |

**DEC-039-001：**以业务任务及来源能力为观察单位，保留部分完成与数据缺口；诊断信息足够定位，但不扩张正文和秘密的留存范围。

以上规则解释 NFR-001-013，不重编号或替换总纲条目。后续发现冲突应显式更新总纲及受影响文档，不由某一页面或适配器单独改变语义。

## 7. 状态、异常与权限

| 状态或场景 | 展示与处理 |
|---|---|
| 健康但无新结果|保留最后成功及本轮零新增，区别于失败 |
| 连续失败或陈旧|指明范围、持续时间、原因与下一步，避免每轮重复制造新问题 |
| 已恢复|展示恢复验证时间及仍待回补缺口，原故障记录继续可查 |
| 加载或执行中 | 展示已知阶段和可用操作；未知进度不用虚假百分比，已持久化历史结果可以继续查看。 |
| 无权访问 | 显示稳定的权限提示，不通过错误内容泄露其他使用者的数据或凭据。 |

用户只查看自己有权限的任务和配置；维护诊断默认脱敏，额外正文访问需原有授权。一般运行日志不成为绕过业务权限的数据入口。

| 身份 | 访问与操作边界 |
|---|---|
| 资料或配置所有者 | 在本文件范围内处理自己的业务资料与配置；维护职责的动作仍须相应授权。 |
| 获授权维护者 | 仅诊断或维护明确授权的范围，不自动获得业务正文、规则修改或秘密回读权限。 |
| 其他身份 | 默认拒绝；仅在 026 团队协作正式启用且被显式授权后，按实际角色开放对应操作。 |

本项专门权限规则优先约束上述通用边界，后续角色设计不能扩大已有秘密或数据访问权限。

重复点击、刷新页面或网络重试不得重复产生同一业务结果；若本操作是有意新建的一次业务行为，必须有独立标识和清晰的版本/时间范围。

- **适用质量要求：**本文件即质量要求的细化，受总纲免费、数据边界和真实验收约束。
- **验证口径：**构造同一主题跨配置版本、三轮连续失败、部分成功、预算延期及恢复的完整记录，核对明细与聚合；检查一般日志与错误响应是否泄漏受控秘密和关键词。测试使用固定时钟或记录偏差，避免时间窗口不一致。

总纲质量目标：每个失败任务有稳定错误类别、关联 ID 和可操作提示；数据陈旧与连续失败可见；统计包含部分完成，不能只报成功总数。
来源访问条件未满足时，使用受控样本验证内部规则，并单独记录真实来源验证未完成；不能用模拟成功冒充真实平台接入。涉及性能沿用总纲 B0，分析质量沿用 Q0；未采用相关基线时需注明适用样本和环境。

## 9. 验收标准

AC-001-037 是父级验收，本文件第一项完整保留其场景，其余补充边界、异常和业务细节。以下全部是待执行标准，不是已通过记录。

| 验收 ID | 场景 | Given：前提 | When：操作 | Then：可核查结果 |
|---|---|---|---|---|
| AC-039-001 | 总纲场景继承 | 来源连续失败三轮且用户修改规则 | 查看运行记录和统计 | 能关联失败范围与规则版本，敏感搜索词与秘密不进入一般日志。 |
| AC-039-002 | 版本追踪 | 主题在失败后发生关键词修改 | 查看修改前后两轮任务 | 每轮关联自身配置版本和阶段，能区分规则影响与来源故障 |
| AC-039-003 | 明细与聚合 | 存在成功、部分、失败、延期及多次重试 | 按同一窗口汇总 | 各状态与明细一致，重试不被当新成功任务 |
| AC-039-004 | 错误可行动 | 分别注入限流、凭据失效和解析错误 | 查看任务原因和处理入口 | 错误类别稳定、影响明确，动作对应原因而非统一要求重试 |
| AC-039-005 | 连续失败恢复 | 同一能力连续失败三轮后恢复但欠账未补齐 | 查看平台与问题记录 | 提示去重，最后成功和尝试分开；恢复保留故障及缺口 |
| AC-039-006 | 脱敏审计 | 关键词、连接与正文包含受控敏感值 | 检查日志并执行暂停/恢复 | 一般日志没有敏感值；操作身份、版本和恢复证据可核对 |

交付证据应包含输入/规则版本、执行记录、实际结果和人工核对结论。界面能力须有真实浏览器证据；运行、恢复与来源能力按相应环境验证，纯文档检查不计作产品验收。
