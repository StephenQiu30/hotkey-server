# 实时事件流与站内通知

## 用户问题

参考项目使用 Socket.io 推送新热点；当前 HotKey 有持久告警事实和通知页面，但主要依赖请求刷新，没有统一实时传输通道。

## 产品目标

当采集运行、事件更新、告警或报告状态变化时，已登录用户无需刷新即可收到可恢复的站内更新。

## 范围

- 认证 SSE 端点
- 事件类型与持久游标
- 客户端重连、补拉和 Toast/徽标
- 采集、事件、告警、报告通知

## 用户故事

- 作为阅读者，我能快速看到重要变化、依据、可信程度和更新时间。
- 作为编辑者，我能从发现、研判到处理和交付完成闭环。
- 作为管理员，我能查看成本、失败、权限和审计并安全恢复。

## 功能要求

- FR-022-1：MVP 使用单向 authenticated SSE，而非引入 Socket.io/双向 WebSocket；所有业务动作仍走普通 HTTP API。
- FR-022-2：事件从持久 outbox/audit fact 投影，包含 event_id、type、resource_id、occurred_at 和最小展示 payload。
- FR-022-3：客户端保存 Last-Event-ID，断线指数退避并补拉缺口；实时消息只提示变化，详情仍从正式 API 获取。
- FR-022-4：按用户角色和资源范围过滤；心跳不包含业务数据，代理缓冲和连接上限可配置。

## 非功能要求

- 写操作具备认证授权、审计、幂等或乐观锁；异步操作可追踪和重试。
- 列表使用稳定分页，慢任务不阻塞 HTTP；错误使用统一业务码。
- 前端使用 shadcn/ui/Radix 组合，覆盖响应式、键盘、焦点、对比度与减弱动效。

## 非目标

不以静态 Mock、不可追溯模型文本或仅桌面可用页面通过验收。

## 验收标准

- AC-022-1：断线重连后不漏关键通知且允许幂等重复
- AC-022-2：viewer 收不到管理员运行诊断
- AC-022-3：SSE 不可用时轮询降级保持功能可用
